# Phase 1 性能実測記録(Windows x64)

実装計画 §4 Done 条件の実測エビデンス。計測日: 2026-08-02。

- 対象: `JetBrains/kotlin` full clone(`git rev-list --count --all` = 225,818。
  デフォルト表示セット `HEAD --branches --remotes` で 224,401 行)
- ビルド: `cargo build --release`、計測はウォームファイルキャッシュ
- 自動計測ハーネス: `PG_AUTO_OPEN` / `PG_AUTO_SCROLL` / `PG_AUTO_SELECT` /
  `PG_LOG=info`(数値は tracing 出力と WorkingSet サンプリング)

| 予算(要望.md) | 実測 | 判定 |
|---|---|---|
| 起動→グラフ初回表示 3s | **534–654ms**(first chunk 512行) | ✅ |
| 操作応答 100ms | **88ms**(行選択→コミット詳細+ファイル一覧表示) | ✅ |
| スクロール 60fps | **99.3fps**(3,000行連続スクロール、100Hz環境) | ✅ |
| メモリ 300MB(提案値) | **peak 324MB / 静定 318MB**(224k行時) | ⚠ 下記 |

補足:

- 全 224,401 行のストリーム完了は 2.2s(初回表示後もバックグラウンド追記)。
- **タグを graph の walk から除外する設計判断**をこの計測で確定
  (`platitude-core::session::LOG_REVS` のコメント参照)。kotlin の 44,710 タグを
  walk に含めると `--topo-order` のフロンティア初期化だけで git の first-byte が
  0.42s → 2.14s に悪化し、コールドキャッシュでは初回表示が 7.8s まで落ちた。
  タグの**ラベル表示**は refs join で維持される(タグからしか到達できない
  コミットの行だけが非表示。将来設定でオプトイン可能な構造)。
- メモリ内訳: ベースライン(Qt ランタイム+QML+ペイン一式)≈160MB、
  行データ ≈73MB/10万行。要望の基準(kotlin の 138,915 コミット)に換算すると
  ≈262MB で予算内。324MB は基準の 1.6 倍(リモートブランチ 7,767 本を含む
  デフォルト表示セット)での値。「※提案値、フレームワーク検証時に見直し」の
  見直し対象として、行ストレージのパック化を将来最適化候補にする。
- コールドキャッシュ初回はディスク I/O が支配的(タグ除外前の実測で +5s 程度)。
  予算は「快適に扱える」趣旨のウォーム前提で判定した。
