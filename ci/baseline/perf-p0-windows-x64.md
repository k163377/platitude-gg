## ここまでに言えること

1. 詳細のメタデータ表示だけと、diffを開いた状態には大きな差がある。旧来の「選択あり」は両者を混ぜていた。
2. diffを一度も開かない未選択スクロールでも300MiBを超え、100ms超のフレームが出る。詳細の古い応答だけを直しても、スクロール問題全体は解消しない。
3. 100ms超のフレーム間隔は記録されているが、表示環境を固定していないため、その原因やrun間の差は断定しない。平均fpsだけでは操作応答の判定にならない。
4. 最大Rust liveを報告した時点と、Working Setの最大時点は同じとは限らない。起動中にはrefsの読み取りバッファ等も存在する。`Working Set - Rust live` をそのままQtの未解放ヒープと呼ばない。
5. 自動fetch、表示順序、対象refs、選択対象の条件が旧測定と異なる。旧406–418MiBとの差を、この変更による削減量として扱わない。
6. 次の比較ではディスプレイ名・報告Hz・DPI・ウィンドウ位置と寸法を保存し、同じ画面とHzに固定する。途中で画面条件が変わったrunは比較から外す。報告Hzと物理走査完了は別である。

次の計測は、長いフレームの時刻とUI drain・行変換・レイアウト・描画を対応させること、
およびdiff表示／新しい行へのスクロールで増えるネイティブ割り当ての所有者を追うこと。
メモリ300MiBと応答100msの達成はまだ確認できていない。

## 要求順の修正（計画P2の一部を先行）

P0採取後、A→B選択に対してB→Aの順に結果が届くとBがキューから消える不具合を、旧実装で失敗するテストとして再現した。
詳細要求にはプロセス内で一意に増える番号を付け、coreの結果、feed、UIの照合まで保持する。
前の要求はキャンセルし、feedは要求番号が最大の結果を1件だけ残す。読み終わった古い結果や古い失敗も、新しい結果を上書きできない。
番号はセッション再作成で巻き戻さない。エラーの表示も、現在の要求に対応する詳細モデルが判断する。

実gitを使うテストは、A→B→Aをworker実行前に送った場合のgit起動1回、
executorに入った旧要求のキャンセル、最新要求の失敗、セッション再作成を確認する。
完了通知・要求番号・barrierで待ち、sleepによる順序合わせはしていない。
この変更だけで単発操作の時間やメモリが上表から改善したとは主張しない。

## 検証と計測の限界

実装と検証は `worktree-b` に隔離し、mainへは反映していない。
ホストのstructure / waits / fmt / clippy / 全テストと、Linuxのcoreテスト / clippy / 同じUI動詞 / bare起動を検証する。
UIは未選択・詳細・diff・diff後スクロール・未選択スクロール・空リポジトリ・詳細失敗の7ケース。

画像点検でLinuxの初回identityダイアログを確認したため、検証用の子プロセスだけにGit identityを固定した。
実計測はidentity未設定なら失敗とする。スクロールは、アニメーション終了後のフレームと表示行も確認してから完了する。
未選択は詳細を読まないだけでなく、ListViewが自動で付ける先頭行の選択色も解除する。
これらの追加ガードは上表の `b3872a1e` での採取後に入っている。追加後の実スクロール再計測は、main追従と画面条件の記録を整えてから別の証拠として採取する。

途中でグラフが空白に見えた画像は、保存PNGの欠落ではなかった。
同じSHA-256の4画像が表示ツール上では異なって見え、ファイルの画素を読むと4枚とも同じ文字領域を保持していた。
この所見をアプリ／Qt／カメラの不具合として扱わず、一時的に入れた連続撮影・ミラー変更・描画設定変更は全て撤去した。
`visible=true` とログのPASSだけに頼らず画像も点検するが、画像表示で異常に見えた時は保存ファイル自体の画素と照合する。

未着手なのは計画P1のネイティブ割り当ての帰属・長いフレームの処理内訳、
P2のdiffキャンセル・ハイライト・UI仕事の分割、P3の支配的メモリ削減、P4の長時間／多タブの予算判定。
この着手単位を終えても、計画全体の完了や性能予算の達成とは扱わない。

## 再実行例

専用worktreeで実ウィンドウの計測が許可された場合に実行する。出力ディレクトリは毎回新しい名前にする。

```text
cargo xtask perf --repo C:/Users/wrongwrong/IdeaProjects/kotlin --selection first --no-diff --no-scroll --runs 3 --breakdown --settle-ms 1000 --output target/perf/details-new
cargo xtask perf --repo C:/Users/wrongwrong/IdeaProjects/kotlin --selection first --runs 3 --breakdown --settle-ms 1000 --output target/perf/scroll-new
cargo xtask perf --repo C:/Users/wrongwrong/IdeaProjects/kotlin --no-select --runs 3 --breakdown --settle-ms 1000 --output target/perf/unselected-scroll-new
```

同一対象に固定する再測定は `--select-oid` と `--file` を指定する。
指定OIDが読み込み範囲に無い、指定ファイルが無い、表示グラフが動かなかった、メモリが採れなかった場合は失敗扱いとなる。
