## 計測条件

**判定 4 行を撃ち直す 2 行**:

```
cargo xtask corpus
PGG_ALLOW_GUI=1 cargo xtask perf --at <測る commit> --repo <上の 1 行が印刷した path> --runs 5
```

段ごとの表は 2 行目にフラグを足しただけで、**撃ち方は各節が持つ**。この記録を撃ち直すなら
`--at` は冒頭の 2 つの木を持つ commit で、**全節が同じ commit**。既定で最初に較正 run
(`run-font-walk`)が走り、report の `font walk` / `net` 行になる(rules-refs/app-ui.md
「perf の判定行は net で読む」)。

- 対象: **`cargo xtask corpus` が生成する合成リポジトリ**。**corpus token
  `23da9ebd03a156a5937d265abb0a353fc60e7b75`**(`show-ref` 全体の blob id)—
  HEAD `e512482ebce1b16fd3a7908a4000c229896fcf7e`、コミット 200,000、
  refs 50,004 本(タグ 42,800 / リモートブランチ 7,200 / `main` / 追跡 `main` /
  リモート 2 本の `HEAD`)、追跡ファイル 109,652、pack 5 本 + multi-pack-index、
  commit-graph chain あり、作業ツリーは clean
- **形は `JetBrains/kotlin` の実測に寄せてある**が、**寄っていない軸がある** —
  §コーパスと kotlin の距離(そこが正本)
- ハーネスが選ぶ行(`--selection first` = ref から届く最新)は HEAD と同じ
  `e512482e`(**76 ファイル変更**)。既定で開く diff はその 1 件目
  `…/checker_codegen38182.java`(**34,059 バイト**の中の **+47 −3**)。
  **操作応答と diff frame の数字はこのコミットのもの**で、**大きいファイルの中の
  小さい diff = 文法ハイライトの最も高い経路**
- 表示は既定設定(`HEAD --branches --remotes --tags` を `--max-count=2000` の
  ウィンドウ、2,001 行)
- **窓は `\\.\DISPLAY2`(180Hz、1920x1080、原点 (0,0))に 1440x900 で固定**。**fps は出た画面で

  **窓の復元はカーソルのある画面を基準に出る**ので、撃つ前にカーソルをその画面に置く

- ビルドは `cargo build --release --features automation`(ハーネス込み)
- **実ウィンドウ**(offscreen ではメモリも fps も表示性能にならない)、ウォーム
  キャッシュ、WorkingSet と private bytes の 100ms サンプリング
  最大値。1 回目は捨てて以降を採る

  グラフィックス構成でなければ通らない**(違ったら報告ごと落ちる)
- 数値は **min–中央–max**(kept run の全数)。**判定は max、比較は中央**を読む
- 撃った時の機械: 判定の invocation で全体 10.3–11.1–12.2% busy、うち対象プロセス以外
  5.4–6.0–7.4%(最悪の 1 tick で 23.0–63.5%)。
  **他の仕事が載る台**(ブラウザ・IDE・コンテナランタイム・他席のセッションが動いている
  24 スレッド機)

## 操作 1 点の内訳 — 読み / 適用 / 描画

**別の座り** — **`corpus --copies 8` の作業コピーが立ったコーパス**
(token `fb3d090c4261f4500bd61c8db7389485d515feab`、refs 50,012)に `--allow-noisy` で撃った
3 run。開幕の巡回がグラフと機械を取り合う条件なので、
**読むのは割り方**。

3 段に割る 3 つの印は、要求した時刻からの経過として全部 app が言う —— `… request round trip`
(答えが drain された = report の `details data` / `diff data`)、`… rows applied`(行がモデルに
入り、変更通知も出た = `details rows` / `diff rows`)、そしてハーネスが見たフレーム
(`details frame` / `diff frame`)。

| | 読み(`data`) | モデルに入るまで(`rows`) | フレーム(`frame`) |
|---|---|---|---|
| 詳細 | 57–129–181 | 83–177–227 | 98.8–205.5–252.9 |
| diff | 61–111–220 | 97–155–283 | 110.2–168.4–301.4 |

機械は全体 32.6–42.4–98.0% busy、対象以外 16.5–27.1–84.1% —— 散りの大半は機械の側。
**静かな座り(§判定 の 5 run)の同じ 3 印**は 詳細 49–55–62 / 75–83–95 / 84.3–95.5–109.0、
diff 61–61–71 / 93–97–103 / 94.4–109.5–115.1。

- **読みは座りで大きく散る**(57–220ms)が、**適用(rows − data)は中央どうしで 詳細 28〜48ms・
  diff 36〜44ms、描画(frame − rows)は 詳細 12〜29ms・diff 13ms** —— 待ちの本体は読みで、
  残り 2 段のうち**重いのはモデルの側**
- **一覧のデリゲートの作り直しが乗るのは「モデルに入ってからフレームまで」の小さい側**
  —— `reset()` を `dataChanged` に替える案(P3-確認事項 §性能)が狙えるのは小さい方の半分で、
  適用はモデルを組む側の代金
- **読みの中は全部プロセス**:
  `diff-tree -r -p` / `config --get-regexp core.autocrlf` / `rev-parse --verify <oid>:<path>` /
  `check-attr -z text eol` / `cat-file blob` の 5 本で、**3 本は同時に起き、答えは最後の 1 本が
  返った 0.3ms 後に届く** —— **diff の組み立ては前の待ちの陰に隠れていて、測れる残りを持たない**。
  1 本ごとの起動と実行は
  [git-slots-windows-x64.md](git-slots-windows-x64.md) §操作 1 回の内訳 が正で、長い鎖も同じ
  2 本(`rev-parse` → `cat-file`)

## 表示に依らない計測(`--software`)

棚の exe のまま software scene graph で撮った 1 座り(較正 run +
捨て 1 + **2 run**、`--settle-ms 4000`、表示は点いたまま)。
**software scene graph の値**なので、読むのは同じ commit の D3D 値との差:

| | D3D(§判定 の 5 run) | software(2 run) |
|---|---|---|
| WorkingSet gross | 337.4–343.2–344.8 | 291.0–291.4 |
| net(較正 run の歩きを引く) | 287.4–293.3–294.9 | 241.2–241.7 |
| font walk(較正 run) | +49.9 / private +21.3 | +49.7 / private +21.5 |

- **差は renderer の差**(net で約 52MB)。software は D3D の床(§Qt の床の +25MB)も
  描いた行のグリフ texture も持たない — その分だけ軽く出る。**歩き(font walk)は同じ大きさ**で、
  フォント DB の populate は scene graph に依らない
- **表示を消した座りはこの木では撮っていない**。software の経路は表示の状態で変わらない
  (rules-refs/app-ui.md「表示に依らず測るのは `perf --software`」)
- **使い道は 2 つ**: 同じ renderer どうしで A/B を撮る(表示は付け消ししてよい —
  `--software --at <対照>` と `--software --at <変更>`)、歩きの帰属を撮る。**§判定 の撮り直しは
  できない** — 予算行は点灯した D3D の値で、それには表示が要る

### 旧フォント backend との A/B

**別の木(Qt 6.10.3)**。旧 backend は QPA 引数 `fontengine=gdi` で今も選べる。その `populateFamily` はファイルを
写像しないので、**歩きの代金がどこまで落ちるか**を同じ座りで背中合わせに
撃った(各 2 run + 較正 run):

| | 既定(DirectWrite) | `windows:fontengine=gdi` |
|---|---|---|
| 較正 run の歩き | +49.9MB / private +21.3 | **+2.3MB / private +0.7** |
| net(歩きを引く) | 252.7–257.5 | 250.2–255.3 |
| 16.7ms を跨いだフレーム | 1–2 本 / frame max 142.2–285.2ms | **0 本 / frame max 13.4–14.9ms** |
| startup(見えるグラフまで) | 1158–1183ms | 1343–1378ms |

- **絵は変わらない**(画素で確認。色絵文字も CJK も同じ字形で出る)
- **代金は startup の +約 200ms**。予算 3s の内側
- **出荷は既定のまま**(ユーザー決定)。**この記録の数字は全部 DirectWrite 側**。
  理由は数字の外に在る: **Qt が既定から降ろした backend に予算を預ける**
  ことになる
- **撃ち方**: perf は実窓を建てるため `QT_QPA_PLATFORM` を消してから起動する
  (`perf::measure`)ので、この A/B は**その 1 行を使い捨てで開けて**撃った。
  `verify-ui` は offscreen 固定 = 機械のフォントを 1 本も持たないため、両 backend の絵は
  実窓でしか並べられない

- **ただし Rust 全体は 19MB** — 300MB の主役は C++ / Qt 側と
  フォント(§常駐の内訳)

## 出荷ビルドとの差(5 run)

`--shipped` を足す。出荷ビルドはタブを開くだけで、駆動も報告もしないので、
**比べる相手は同じことしかしていない「開くだけ」の段**:

| | 出荷(feature 無し) | ハーネス込み(開くだけ) |
|---|---|---|
| WorkingSet | 228.6–243.6–247.5 | 241.6–244.5–246.2 |
| グラフまで | 1125–1144–1263ms | 1238–1254–1319ms |

**中央値でメモリ −0.9MB / グラフまで −110ms(どちらも出荷のほうが軽い)** —
**メモリはこの採取数では差が出ず、時間は出荷のほうが速い側に出る**。**判定 4 行をハーネス込みで
読んでよい根拠がこれ**(ハーネス込みの値は出荷より重い側に立つ)。
どちらの段もフォントの歩きは払っていない(§常駐の内訳 の「開くだけ」= フォント 9 ファイル)
ので、この 2 列は歩きの前の量どうしを比べている。

## Qt の床

**Qt 6.10.3 の値**。Qt そのものの値なので、アプリ側の変更では動かない(Qt の版では動く):

| 積み上げ | WorkingSet | 差分の中身 |
|---|---|---|
| Qt の `qml.exe` + 素の `Window` | 75.5MB | Qt Quick + D3D + GPU ドライバの床 |
| 同 + Controls(Fusion)+ `ListView` | 83.9MB | +8.4 = このアプリも使う部品 |

描画経路の寄与は同条件の差で取った: リポジトリ無しが software 描画 90.9–91.3MB に
対し D3D(既定)115.7–116.3MB = **+25MB が D3D / GPU ドライバ経路**。
**60fps を満たすのは D3D 側** — software 描画は同条件で 56.4–57.8fps。

**exe のサイズとメモリは別の量**。tree-sitter 37 文法の
静的テーブルで exe は 61.1MB あるが、**`ENTRIES` を空にして exe を 10.5MB にしても
`--no-open` の WorkingSet は動かない** — 触られない
読み取り専用ページは常駐しない。メモリは常駐で測ること。

## アロケータと確保の個数

**バイト数より個数が効く帯がある。** Windows ヒープは確保 1 個ずつに管理領域を持ち、
管理領域とサイズ級の丸めは**計数アロケータには見えない** — 確保の個数を減らす変更
(`crate::Name` + `SmallVec<[Name; 1]>` で 305,213 個)は、計数側 −3.1MB が
WorkingSet では −12MB に出た。

**アロケータは既定のまま**。同一コミット・同一コーパスでの A/B:

| | 既定(Windows heap) | mimalloc | mimalloc + 即時 purge |
|---|---|---|---|
| WorkingSet | 288.8–296.3MB | 326.4–351.0MB | 289.4–299.5MB |
| private | 305.9–311.1MB | 388.3–397.3MB | 348.8–354.2MB |

遅延解放を切って WorkingSet でようやく並ぶが private は +43MB のままで、しかも
配布時に環境変数を撃つ前提になる。起動・操作応答にも差は出なかった。
**この 3 列は 1 回の座りの中の A/B なので、読むのは列どうしの差。**

## この記録の読み方

1. **機械が見る**: 窓の出た画面と Hz / 掴んだ GPU アダプタと描画バックエンド /
   コーパスの token(run の前後で 2 回)。**並ぶのは同じ画面・同じアダプタ・同じコーパスの数字だけ**
2. **コーパス**。生成器が固定なので**もう勝手には動かない** — token が違う時に
   起きたことは 2 つに 1 つで、**生成器を変えた**(なら記録ごと取り直す)か、
   **`--repo` が生成物ではない別のリポジトリを指している**(なら指し直す)。
   `--corpus <token>` を足すと、違った時に refuse する。
   操作応答だけを跨いで比べたいなら `--select-oid` でコミットを名指しする
   (その oid が 2,000 行の窓に残っている間だけ効く)
3. **スクロールベンチの有無**。判定の 300MB はベンチ込みの行に対して読む。ベンチの代金は
   §メモリの段 の +64MB で、中身は §常駐の内訳 のとおり **見えた行が呼んだフォールバックの
   歩き**(フォント +30 とヒープ外 +34)— 窓に絵文字の行が無いリポジトリでは出ない
4. **座り(計測の機会)は残っている**。**同じコミットの対照は同じ座りで撃つ**
   (`cargo xtask perf --at <対照> …`)
5. **採取数**。スクロールまで撃つと 1 つの invocation の中で WorkingSet は 2〜10MB 散る。
   **数 MB の差は 5 回採りでは分離できない**。中央値どうしで読み、範囲は「どこまで散ったか」
   としてだけ読む。窓だけの段は 1.9MB しか散らないので、そこは違う読み方でよい
6. **net の絶対値は、その invocation の較正 run が量った charge に依る**。同じ
   commit の 11 invocation で charge は **WorkingSet +49.7〜+50.8MB** に散り(判定の座りは
   +49.9)、net はその差だけ動く。**net で数 MB を比べるなら charge も並べて読む**
   (report の `font walk` 行)。**歩きの停止時間はもっと散る** — その日最初の invocation だけ
   775ms で、以降は 116–155ms(フォントのファイルが OS のキャッシュに乗るまでの差)
7. **操作の裾は変種の差を読めない**。`--cases` の run が 1 ケースにつき採るのは 36 操作で、
   **その p95 と max は同じ設定を背中合わせに撃っても動く**(git-slots-windows-x64.md §条件)。
   **変種を比べる時に読むのは p50 と
   「100ms を越えた操作の割合」**、裾を読みたいなら A/B(`--compare`、ABBA)で
   同じ条件を交互に撃って両変種のサンプルを束ねる
8. **途中で Hz を変えて戻した run は見分けられない** — 画面の Hz を読むのは run の前後
   (`display-before.txt` / `display-after.txt`)だけで、前後 snapshot の一致では途中の変更を
   検出できない。計測中は画面の設定を触らない

**機械の忙しさの閾(対象以外 35%)が数字を動かすかどうかは測っていない** —
静かな機械との背中合わせを、閾を動かす前に撮る。

**判定は予算に対する絶対値** — 上のどれかが動いていれば、同じコミットでも
数十 MB 違う。
