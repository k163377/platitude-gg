# 確認の段と gate を撃つ時機

**Claudeクラウド(`CLAUDE_CODE_REMOTE=true`)ではここの何も撃たない** — 撃つはずだった確認は報告で「未実行の検証」として名
指す([クラウドセッション.md](../../../internal-docs/クラウドセッション.md))。仕組み(依存木・スタンプ・登録表・land)の正
本は [反映前テストの機械化.md](../../../internal-docs/反映前テストの機械化.md)、ここは使う側の手順。

前提: 日常のビルド・テストは debug。起動・UI 検証・性能計測は各 xtask コマンドの手順に従う。以下 `cargo` / `cargo xtask`
を省略。

## 確認は 3 段

- **1 日常・報告前** = <!--call:gate.daily-->`gate --related`(変更箇所に直接関係するテスト: 差分で選んだステップの host
  側、動詞は変更した QML 部品を示す行だけ — singleton はそれを読む部品を示す行、Rust・ハーネスだけの変更なら 0 行なの
  で、ハーネスの変更は効く動詞を `--verb` で名指す。commit にはスタンプを書かず、通ったステップの緑は段 2 がそのまま使
  う)
- **2 反映前** = `gate`(差分の依存木と `verb-tiers.txt` の段で選んだテストを回し、緑を commit にスタンプ = `land` と git
  hook が要求)
- **3 全体** = <!--call:gate.whole-->`gate --whole`(差分を見ず登録表(`verb-lines.txt`)の全行と `periodic`、全件 1 プロセ
  スの QtTest(<!--call:qmltest.together-->`qmltest --together`)を両 OS で回す。それ以外で回すのはユーザーがテストを指示
  した時だけ)+ <!--call:linux.bare-->`linux bare --discover` + CI の Whole test + 性能実
  測([性能.md](../../../internal-docs/性能.md) §計測)。リリース前と依存・環境を触った時。**版(crate・toolchain・Qt・最低
  git)を動かす差分は `gate` 自身が段 3 の計画へ上がる**、残りは手で(出荷ビルドの版を動かした land の Whole test はその
  land が push するタグで走る)

段の中身と「いつ何が走るか」の表は 反映前テストの機械化.md §段 1 / 段 2 / 段 3。

## gate を撃つ時機

**席で何を撃つかは、差分とターンの種類で決める**。段 2 は `/land` の中で回る。ユーザーがその作業に gate を回す・省くと明
示した時はそれに従う。

- **新しい表現・画面の追加と、見た目だけの修正** — 直した直後は撃たない。意匠は「直す → ユーザーが見て確かめる」の往復で
  詰めるので、その 1 往復を gate で待たせない。見せ方は verify-ui スキル(単発の `verify-ui` と board)。報告には「gate 未
  実行」と書き、「マージ可」とは言わない。段 2 は `land` の中で回り、ユーザーが検証・反映を指示した時は手でも撃つ
- **内部の挙動・テストの実装・既存の内部制御の変更** — ユーザーが試す時点でなるべく動くよう、報告の前に段 1 を撃って緑に
  する。報告には「段 1 PASS・段 2 は `/land`」と書き、段 2 が緑になるまで「マージ可」とは言わない。見た目の修正と同じ差
  分に混ざっていれば、こちらに倒す。Rust のソース・テスト・xtask の変更はこちら。QML でも、既存のハンドラ・状態の遷
  移・タイマーの書き換えはこちら
- **起動だけの要求(「rebase して起動」等)では撃たない** — 起動して即報告し、段 2 が未実行であることを 1 行添え
  る(verify-ui スキル §起動 fast path)
- **文書・コメントだけの直しと、撮るだけのターンでは撃たない** — `.md` はテストを選ばず、コメントは動詞を回し直させな
  い。それでも走る数百の動詞は、下に残る未 gate の変更・前の赤で止まった残り・rebase で変わった木の分で、その段 2 は
  `/land` の中で回る。報告には「gate 未実行」。文書の上限・書式は post-write hook が書いた時に言う
- **追従の rebase(衝突なし)では撃たない** — 乗せ直しただけの木の段 2 は `/land` が自分の rebase の後に回す(land スキル
  §先頭 4)ので、手で撃った緑は main の変更がそのステップの読む物に届けば捨てられる。衝突を解いたら、解いた所の変更として
  上の 2 つで決める。**撃つ理由がある時に rebase も控えていれば(ユーザーが「キリのいい所で」等の時機ごと指示した
  等)、rebase してから 1 本** — 古い土台の緑は rebase で捨てられる

撃ったら現在の commit の結果を使う — 撃ち直すのは変更か未解決の失敗がある時だけ(反映前テストの機械化.md §段 1 / 段 2 /
段 3)。
