# 確認の段と gate を撃つ時機

**Claudeクラウド(`CLAUDE_CODE_REMOTE=true`)ではここの何も撃たない** — 撃つはずだった確認は報告で「未実行の検証」として名指す([クラウドセッション.md](../../../internal-docs/クラウドセッション.md))。仕組み(依存木・スタンプ・census・land)の正本は [反映前テストの機械化.md](../../../internal-docs/反映前テストの機械化.md)、ここは使う側の手順。

前提: 日常のビルド・テストは debug。起動・UI 検証・性能計測は各 xtask コマンドの手順に従う。以下 `cargo` / `cargo xtask` を省略。

## 確認は 3 段

- **1 日常** = <!--call:gate.daily-->`gate --host-only`(コンテナ無し)
- **2 反映前** = `gate`(差分の依存木と `verb-tiers.txt` の段で選んだテストを回し、緑を commit にスタンプ = `land` と git hook が要求)
- **3 全体** = <!--call:gate.whole-->`gate --whole`(差分を見ず census の全行と `periodic` を両 OS で回す。それ以外で回すのはユーザーがテストを指示した時だけ)+ <!--call:linux.bare-->`linux bare --discover` + CI の Whole test + 性能実測([性能.md](../../../internal-docs/性能.md) §計測)。リリース前と依存・環境を触った時。**版(crate・toolchain・Qt・最低 git)を動かす差分は `gate` 自身が段 3 の計画へ上がる**、残りは手で

段の中身と「いつ何が走るか」の表は 反映前テストの機械化.md §段 1 / 段 2 / 段 3。

## gate を撃つ時機

**席で段 2 を手で撃つかどうかは、差分の種類で決める**。ユーザーがその作業に gate を回す・省くと明示した時はそれに従う。

- **新しい表現・画面の追加と、見た目だけの修正** — 直した直後は撃たない。意匠は「直す → ユーザーが見て確かめる」の往復で詰めるので、その 1 往復を gate で待たせない。見せ方は verify-ui スキル(単発の `verify-ui` と board)。報告には「gate 未実行」と書き、「マージ可」とは言わない。段 2 は `land` の中で回り、ユーザーが検証・反映を指示した時は手でも撃つ
- **内部の挙動・テストの実装・既存の内部制御の変更** — ユーザーが試す時点でなるべく動くよう、報告の前に撃って緑にする。見た目の修正と同じ差分に混ざっていれば、こちらに倒す。Rust のソース・テスト・xtask の変更はこちら。QML でも、既存のハンドラ・状態の遷移・タイマーの書き換えはこちら
- **起動だけの要求(「rebase して起動」等)では撃たない** — 起動して即報告し、段 2 が未実行であることを 1 行添える(verify-ui スキル §起動 fast path)

撃ったら現在の commit の結果を使う — 撃ち直すのは変更か未解決の失敗がある時だけ(反映前テストの機械化.md §段 1 / 段 2 / 段 3)。

## Linux での確認

**`linux <コマンド>`**([ci/linux/Dockerfile](../../../ci/linux/Dockerfile) のコンテナ = 最低 git バージョンを積んだ唯一の環境。Windows では WSL 3 の `wslc` が回す)。**`bare` は宣言した依存だけの Ubuntu で動くかだけを見る**。UI の動確をコンテナで撃つ手順は verify-ui スキル linux.md。
