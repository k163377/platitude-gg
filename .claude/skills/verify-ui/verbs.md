# PG_AUTO_ACT 動詞表(正本)

[SKILL.md](SKILL.md) の参照資料 — **1 動詞 1 行**(近縁動詞は束ねる・段落側だけの動詞は §動詞ごとの読み方・仕込み)、使う動詞名で Grep して該当行と続く節の該当段落だけを読み(全読みしない)、追記も 1 動詞 1 行(段落で書く仕込みは下の節へ)。

**負荷の下では、正しい run でも稀に watchdog まで行く** — 途中の報告行を 1 本も出さないまま 120.5s(2026-08-18 実測: `push-retry` をコンテナで 3 回・`eol-commit` をホストで 1 回。どれも `check` の並列・直前のビルド・連続 run と重なった時だけで、静かな時は `push-retry` が 20 run 連続 PASS)。**FAIL を見たらまずその動詞を単独で回す** — 単独で通るなら見ているのは負荷であってコードではない(逆に単独でも落ちるなら本物)。**判定を緩めない**(`--watchdog-ms` を伸ばして隠さない)。

## 動詞一覧

- `details-failure --preset perf`: 実在しないOIDの詳細を要求し、`details_failure loading=false error=true` とPNGで確認する。詳細失敗は要求世代に属し、現要求だけがスピナーを下ろして既存エラー面へ渡す。

- `perf none|details|diff|scroll|scroll-none|font-walk --preset perf`: 性能ドライバーの表示契約。未選択、詳細、diff、diffを閉じて表示グラフをスクロール、未選択スクロールの5通りと、較正 run の形 `font-walk`。全て `perf_complete` の状態とPNGで判定する。offscreenのfps・メモリは性能値に使わず、実測は `cargo xtask perf`。空コミットを持つ `deep` はdiff要求を失敗させるため、変更ファイル付きの専用presetを使う。 `font-walk` は `cargo xtask perf` の較正 run の形(未選択・スクロール無し、`perf_done` の前に `WindowPerfDriver` が一族に無いグリフを 1 つ組んで `perf_font_walk_begin` / `done` / `settled` の 3 行を言う)で、判定は `settled` の行。offscreen の FreeType DB にはフォントが無いので歩きの代金はここでは出ず、実測は `perf` の `font walk` 行(rules-refs/app-ui.md)。

## 動詞ごとの読み方・仕込み

**先端に答えが立つ 3 つ(`merge-branch` / `cherry-pick` / `revert-commit`)は 1 本の報告行を共有する** — `tip_landed follows= onscreen= op= head= selected= row=` で、**合格条件は `follows=` / `onscreen=` に `op=` を足した 3 つ**(`Outcome::must_say` は動詞ごとに 1 行 = `op=merge` / `op=cherry-pick` / `op=revert`)。**完了の門は 4 つ** — ① この動詞自身の書き込みが答えたこと(`writeSeq` の notify が運んだ答えの列から `at_tip` の 1 本を latch = `writeAnswerAtTip(i)`。**答えの group は次の答えが丸ごと上書きし、同じ drain バッチに合流した答えも読めない**ので、着地を待つ間に fetch が着けば名前は消える = `op=` は latch した名前で、報告時に読み直さない)② その答えが arm した着地の解け(`pendingHeadSelect`。答えの直後は refs がまだ古く、`selected === headOid` はそこで初めて意味を持つ)③ 行が画面に在ること ④ **右ペインがその行に追いついたこと**(`detailsModel.shaHex`)。**選択が元から先端に居る形(ref 行からの merge・HEAD の revert)は、待たないと git が動く前に他の全条件が揃い、手つかずのリポジトリを緑で撮る**。④ が抜けると右ペインは前に選ばれていたコミットを描いたまま写る — merge ではそれが書き込み前の先端 = **右半分が「何も起きていない」絵になる**(2026-08-23 実測: ペインの往復は `screenshot saved=true` の後に着いていた)。**3 動詞とも完了は `tipLandedTimer` の単独所有**(defersCompletion — writeBarrier が答えの直後に先勝ちすると、報告行の無い書き込み境界の絵で終わる)。選択が新しい先端のコミットへ移り、その行が画面に在ることを言う(規約 §履歴を合流させる)。**merge / cherry-pick は `--preset diverged` の `origin/main`** — 木がきれいで、取り込むものが向こうにあり、着地が非早送りの本物のコミットになる(**`--preset basic` は木が汚れていて `git cherry-pick` が `your local changes would be overwritten` で落ちる**)。**選択は撃つ前に先端から動かす**(グラフ行から入る 2 つは `jumpToRow` してから撃つ)— 動かさないと「元から先端に居た」だけで `follows=true` になる。`merge-branch` は ref 行から入るので選択は起動時の先端のまま = **書き込みが先端を動かすことがそのまま試験になる**。**取り込み済みの merge も先端に着くのが正**(`merge-branch v0.1 --preset basic` = `Already up to date` でも `follows=true`)。

**「止まった側」の 4 動詞は 1 本の報告行を共有する** — `cherry-pick-stops` / `revert-stops` / `rebase-stops` / `drop-stops`(merge だけは `merge-stops` = 出口の形が違うので報告行も別)。共有する 1 本は `write_stopped wip= conflicts= error= log= cont= stashes= op= files=` で、**合格条件は `wip=true conflicts=true error=false log=false cont=true`**(`Outcome::must_say`。`drop-stops` だけ `stashes=1` まで含む)。**`error=` / `log=` が「正常な conflict を失敗として出さない」側で、写真では答えられない**(帯もログも出ていない絵は、出ていない絵と同じ)。**`cont=` は merge 側と裏返る** — step する 4 つは出口カードに `--continue` の行を残す(規約 §進行中の操作から出る。行が無いカードと行が下りているカードは同じ絵)。**`stashes=` は carry を伴う着地だけの主張** — 作業を落とした画面と stash に持っている画面はほとんど同じ絵になる(規約 §未コミット変更がある状態で履歴を書き換える)。**preset は「まだ止まっていない木」でなければならない** — 止まった状態で建つ preset(`cherry-pick-conflict` / `rebase-conflict` 等)は、押した操作が何を答えるかを撮れない。**失敗した run の木は捨てる**(止まった操作が残り、次の run が別の理由で落ちる)。

**タブの幅と `✕` は `tab-widths` / `tab-mark`** — どちらも**xtask が長さの違う名前でリポジトリを建てる**(デモの作業ツリーは全部 `repo` なので、同名の並びでは「どのタブが譲ったか」を言えない。最後の 1 つだけ `basic` = 絵の中でページを持つのは前に出るそれ)。`tab-widths` の引数はタブ数(1..=16・既定 8)で、報告行 `tab_widths tabs= run= cap= floor= ease= max= content= view= scrolls= widths=`(`cap=` の隣に `room=`)の **`widths=` が本体**(**`ease=` は短い名前の縮みを緩める基準幅** = 8 文字ぶん。これに足りない名前は差の半分を空きとして貰うので、**短いタブの幅は名前の幅そのものではない** — 規約 レイアウト初期値)。**`room=` が「帯が今どちらの段を食っているか」**(規約 §ウィンドウの縁 の譲る順 = `markRoomFull` 17 から `markRoomMin` 4 まで先に畳み、それから `cap`)(実測 Windows `run≈912-938`: **6 タブ** = `room=17 cap=180` どちらも満額 / **8 タブ** = `room=11 cap=180` = 印の余白だけが減った段 / **9 タブ** = `room=4 cap=180` = 1 段目の底で、名前はまだ 1 文字も切れていない / **12 タブ** = `room=4 cap=88` / **16 タブ** = `room=4 cap=floor` 56。**`room` が減ると名前が印の下に入る**ので、`✕` の出ているタブは末尾がフェードで消える)。**何タブで縮み始めるかは OS で違う**ので、両 OS で同じ数字を期待しない — Linux は merged chrome を持たない = 掴み代 48 も窓ボタンも要らないぶん run が広く(実測 `run≈1079-1099` 対 912)、**9 タブまで `room=17 cap=180` = 1 段目にすら入らず**、12 タブで `room=4 cap=122`、16 タブで `cap=71`(floor 56 には届かない)。**読むのは数字の一致ではなく形**(短い側が据え置き / 譲った側が同じ幅 / `content` ≤ `view`)。`tab-mark` の引数は手を置くタブ(既定 1)で、報告行 `tab_marks tabs= current= pointed= marks=` の `marks=` は**印自身の opacity**(前に居るタブと手の下のタブだけ 1)。**`✕` の hover 半分はこの動詞にしか無い**(hover は注入できないので `TopBar.pointAtTab` が実 hover と同じ `pointed` へ書く)。

**同名リポジトリのタブ名と hover は `tab-name`** — xtask が**同じ根の下に 5 つ**建てる(`foo/repo` / `bar/repo` / `1/deep/repo` / `2/deep/repo` / `solo`。最後の `solo` だけ `basic` = 絵の中でページを持つ前のタブ)。根を共有させるのは、各々が別々のディレクトリに居ると「たまたま違う」だけで通ってしまうため。引数は手を置くタブ(既定 0)。報告行 `tab_names tabs= pointed= unique= tip= titles= said=` で、**`must_say` は `unique=true tip=true`** — **名前そのものは判定に使えない**(区切りが OS の綴りなので `foo\repo` と `foo/repo` の両方が正)ので、判定は「2 つのタブが同じ名前で並んでいない」の側。**`titles=` は目視の答え合わせ用**(`foo\repo,bar\repo,1\deep\repo,2\deep\repo,solo` = 親を 1 段だけ足した組と、2 段まで上がった組と、動かない名前が 1 枚の絵に揃う)。**`tip=` はツールチップの `visible` で、絵は overlay.png 側** — hover が出なかった run は普通の帯として撮れてしまう。**`said=` は行末に置く**(パスに空白が入りうる唯一の値)。

**タブの並べ替えは `tab-drag` / `tab-hold` の対** — どちらも xtask が同じ名前のはしごから **4 つ**建てる(`tab-widths` と同じ理由で、同名のタブが並んだ帯では順が読めない。最後の 1 つだけ `basic`)。`tab-drag` の引数は `<from>:<to>`(既定 `3:1`)で、報告行 `tab_drag moved= from= to= tabs= active= open=` の **`moved=` が本体** = 掴んだタブのパスが頼んだ席に居ること(`must_say`)。**`active=` は `to` と同じになるのが正** — 手は運ぶ前にそのタブへ移るので、運ばれた先が前に出る。**両向き撃つ**(既定の `3:1` が左へ・`0:3` が右へ)= 判定は 1 つでも縁と中央の比べ方が向きで別々に書かれている。`tab-hold` の引数は掴むタブ(既定 0)で、報告行 `tab_hold lifted= at= shift= active= open=` の **`shift=` はタブ自身の `Translate.x`**(頼んだ側 = `heldX` を報告するとバインディングが切れていても緑になる)。**この 2 つは対でしか意味を成さない** — `tab-drag` の絵は「並び替わった帯」で、席が飛ぶだけの実装(タブが手の下に描かれない)と区別が付かない。**`tab-hold` の絵ではページが空**なのが正 — 掴む前にそのタブへ移るので、既定の 0 番は履歴を持たないリポジトリ(主題は帯の側)。**末尾のタブは右へ運べない**(運べる先は `contentWidth - width` で止まる)ので、フックは端のタブだけ内側へ運ぶ。

**タブ切替が何を連れて行き何を捨てるかは `tab-carry`** — **タブが 2 つ要る**(`--preset basic --preset stashes`)。前に出ているタブに人が作らない形の跡を残し(一覧を畳む・ログを開く・コミット欄に文を打つ)、もう一方へ移って読み、戻ってもう一度読む、の 3 着地。**待つのは行ではなくタブ**(`tabsModel.currentTabId`)で、**各着地のページは別のオブジェクト**(前に出ているタブの分しか作られない)なので、着地を跨いで持ち越せるのは読み取った値だけ。報告行 `tab_carry tabs= sessions= folded= log= empty= back= wip=` で `must_say` は **`sessions=1 folded=true log=true empty=true back=true wip=true`** — **`sessions=` が解放そのもの**(`Harness.openSessionCount()`。タブ 2 本でリポジトリ 1 つ = **写真では絶対に答えられない側**)、`folded=` / `log=` が「レイアウトは付いて行った」、`empty=` が「言葉は付いて行かなかった」、`back=` / `wip=` が「言葉は打った所に残り、欄ごと戻って来た」。**再読み込みの証拠は `finishCount > 0`** — 切替の後に建ったページのモデルは 0 から始まるので、これが上がっていること自体がグラフを読み直した証。**汚れた作業ツリーで撮ると絵が一番読める**(`--preset basic --preset rebase-conflict` = 戻り先が作業ツリー行に立ち、`REBASING` の帯も読み直しで戻る)。

**帯が横スクロールしている時の並べ替えは `tab-edge`** — タブ **8 枚**を建て、**窓を床に落としてから**掴む(何枚で溢れるかはフォントと帯の持ち物次第 = `tab-widths` が OS で違う答えを出す所なので、溢れることを窓の幅の側で作る)。引数は掴むタブ(既定 0)。報告行 `tab_edge landed= from= run= tabs= active= open=` の **`landed=` が本体** = 押し当て続けた結果、列が端まで流れて掴んだタブが最後尾に着いたこと(`must_say`)。**絵では判定しない** — 流れて着いた帯と、最初からそこに居た帯は同じ絵。**この動詞だけは窓の幅を書き換える**ので、他の帯の動詞と同じ絵を期待しない。

**今居るタブの張り付きタブは `tab-pin` / `tab-pin-go` の対** — どちらも xtask が同じはしごから **12 枚**建て(`tab-edge` と同じ理由で窓を床に落とすが、**8 枚では Linux の run が 3px** = 流れていない帯と区別が付かない絵になる。実測 Windows `run=369` / Linux `run=202`)、引数は**どのタブを前に出すか**(既定 0)。フックは前に出したタブから**遠い方の端**へ帯を送るので、**既定 0 なら張り付きタブは左の縁・末尾のタブ(`11`)なら右の縁**に立つ。`tab-pin` の報告行 `tab_pin stood= onScreen= left= at= run= tabs= active=` の **`must_say` は先頭 2 つ**(`stood=true onScreen=false` = 立っていて、かつ本物の席は見えていない —— **どちらか片方だけでは規則が逆でも通る**)で、**`left=` は既定の引数の時だけ判定する**(どの縁かは引数が決めるので)。`tab-pin-go` は同じ staging の後に張り付きタブを押し、報告行 `tab_pin_go gone= onScreen= travelled= at= from= run= tabs=` の **`must_say` は `gone=true onScreen=true travelled=true`** —— **絵では判定できない**(流れて着いた帯と、最初からそこに居た帯は同じ絵)ので `travelled=` が本体。**押した後に staging を読み直さない**こと(staging の最後は「張り付きタブが立っている」で、この動詞はそれを消しに行く = 読み直すと watchdog に落ちる。2026-08-29 実測)。**判定する所は報告行に隣り合わせで並べる** — `must_say` は 1 本の文字列の**部分一致**なので、間に別の読みが挟まると同じ run が落ちる(同日実測)。

**新しい window 側の動詞を足したら `AutoActDriver.defersCompletion` の一覧にも足す** — 足さないとページ側が即完了し、**動詞が働く前に撮って `screenshot saved=true` のまま `must_say` で落ちる**(1 tick で終わる動詞は偶然通ってしまうので、通ったことは足りている証拠にならない — 2026-08-18 実測)。**入れ忘れは「たまに落ちる」として出る**(2026-08-27: `tab-carry` が一覧に無く 10 run に 1 回 FAIL。**失敗した run のログは `auto_act ran=` と `auto_act complete=` が同じマイクロ秒に並び、報告行が 1 本も無い** — 落ちる頻度は同居する動詞や無関係な通知の増減で動くので、緑が続いても入れ忘れていないことにはならない)。

**右下の git バージョンが隅を譲るかは `corner`** — 引数はペイン(`wip` = 作業ツリー / 行番号 = そのコミットの詳細。省略は `wip`)。**`--preset basic`(一覧が隅まで届かない)と `--preset long`(一覧がペインを超える)を対で読む** — 片側だけでは「常に出る」「常に出ない」と見分けが付かない。報告行 `git_corner pane= shown= room= needs=` の **`shown=` はラベル自身の可視性**(頼んだ側 = 空き寸法を報告するとバインディングが切れていても緑になる)。**PNG でも読める** — 隅の淡い文字が在るか無いかがそのまま答え。**`wip` はどの preset でも `shown=false room=0`** — 底には commit ボタンが張り付いていて隅そのものが無い(規約 §コミットメッセージの 2 つの枠)ので、譲る / 譲らないの対が読めるのは**詳細ペイン側だけ**。実測 Windows: `1 basic room=547` = 出る、`1 long` は `room=0` = 退く(`needs=21` = ラベルの箱そのもの)。must_say は **`wip`(引数省略を含む)が `git_corner pane=wip shown=false room=0`**・**行番号が `git_corner pane=details`**(詳細側の `shown=` は preset で割れるので、引数だけでは claim できない)。**この行が無い間、隅を貸さないはずの WIP ペインに版が出て commit ボタンに重なる形が緑で通っていた**(使う側が `visible:` を書いて部品自身の判定ごと置き換えた形。対照を取ってある)。

**既に開いているリポジトリを開き直す形は `open-again`**(引数はパス、省略で先頭タブ自身の綴り。報告行 `open_again tabs= active= asked= open=`)。**2 通りを対で読む**: `--preset basic --preset stashes` に**引数なし**で「移る」側(起動直後は `active=1`、頼んだ後に `tabs=2 active=0`)、**git の綴りを引数で渡す**方が「綴りが違っても同じフォルダ」側(`--repo` にはシェルの綴り = `C:\Users\WRONGW~1\…` を渡し、引数に `git worktree list` が出す `C:/Users/wrongwrong/…` を渡す → `tabs=1`)。**後者だけが本題** — 素の文字列比較でも前者は通る。WORKTREES の行から入る形は `nav-dbl worktree:<git の綴り>` で、判定は `opened repository tab` のログが 1 本きりであること。**引数なしの側は `active=0` を待って完了する** — 帯の item はモデルが行を得た次のレイアウトで生まれるので、綴りを訊く `tabPathAt(0)` は先に `""` を返しうる。それで頼むと何も開かず、「タブが増えていない」= 完了条件を即座に満たして **`asked=` 空のまま緑で通る**(2026-08-17 実測・修正済み。今は綴りが来るまで頼まない)。**復元側は仕込みが要る**(`--config-dir` に重複入りの `[tabs] paths` を書いた `state.toml` を置き `state --restore`)— `restored tab dropped: already open` が落ちた件数を、`state tabs= active=` が残った形を言う。

**identity の画面は `identity` / `identity-half` の対**(引数は打ち込む値 `<name>|<email>`、既定 `Ada Lovelace|ada@example.com`)。**この 2 つだけ書き込みが demo リポジトリの外 = 人の git 設定へ出る**が、隔離自体は全動詞共通(SKILL.md §Linux)——**この 2 つは共通の gitconfig に自分の種を書く側**で、他の動詞はそこに fixture identity が入っているために画面が出ない。`identity` = 画面を埋めるだけ(全フラグが下りているのが正)/ `identity-half` = **多値の `user.email` を仕込んだ設定へ保存する** = git が `cannot overwrite multiple values` で exit 5 に落とすので **name だけ着地**(ロック競合と同じ形を決定的に作る唯一の手)。報告行 `identity state= dialog= nameSaved= emailSaved= unsaved= badge= said=` で、**両方 `must_say` を持つ** — 「save が通らずに残っているダイアログ」と「まだ誰も答えていないダイアログ」は同じ絵なので、写真では答えられない。**`dialog=` が本体**。**半端 save の印は `identity-tip`** — 同じ隔離・同じ半端 save の後にダイアログを閉じ(印は半端の間しか立たない)、`badges-hover` と同じ帯の状態カードを開く(`TopBar.statePointedAt` = 実 hover と同じ 1 つのプロパティ)。報告行 `identity_tip unsaved= badge= tip= rows=` の **`tip=` はカードの `opened`**(unsaved / badge / tip の 3 つが must_say)。カードは overlay.png の側に写る。

**最大化した窓の中身が四隅まで届いているかは `window-fill`**(最大化 → 申告 → 撮影のために windowed へ戻す。報告行 `window_fill fills= maximized= at= size= window=` で、**合格条件は `fills=true`**(`Outcome::must_say`)。読むのは**中身の scene 座標と窓の寸法**で、頼んだ margin ではなく着地の方。**両 OS が同じ答えを返す**(窓は frameless = 窓とクライアントが同一で、埋める相手は `merged` に関係ない)。**絵では読めない** — 最大化した窓は画面いっぱいなので、端が足りないことを見せる相手のデスクトップが隣に無い。**offscreen の最大化は 800×800** — 正は `at=0,0 size=800x800`(FAIL でも `screenshot saved=true` は出る)。**窓の縁が画面の外へ出るかはヘッドレスでは判定できない**(実モニタが無い)ので、縁の規則は実窓の画素実測が正本 = rules-refs/app-ui.md)

**窓がこれ以上小さくならないことは `window-floor` の 4 形**(引数なし / `fold` / `log` / `wip`。規約 §窓の床)。**引数なしは xtask が `--config-dir` に 320×240 の `state.toml` を仕込んでから起動する** — 床より小さい形はアプリ自身には作れない(アプリは自分が取れない形を書き留めないため)ので、「床が無かった頃のファイル」は外から置くしかない。`fold` は畳んだ床へ窓を降ろしてから一覧を戻し、`log` は panes だけの床へ降ろしてからログを開く = **どちらも「立っている窓の下で床が上がる」**側を見る。報告行 `window_floor fits= floorW= floorH= bandW= pageW= w= h= from= folded= log=` で、**合格条件は `fits=true`**(`Outcome::must_say`。床に立った窓と床を割った窓は**同じ絵に収まる** — 割った側は写真の外にペインがあるだけなので、写真では答えられない)。**`from=` が「一度は降ろした」の証拠**で、これが無いと `fold` は最初から広かった run と区別が付かない。`wip` は右ペインを WIP に切り替えてから床へ降ろし、**`wipScrolls=true`**(= 出口カードは下にあるが**届く**)を見る — `--preset rebase-conflict` を当てる。**`bandW=` / `pageW=` は `floorW` がその max である 2 つ**(規約 §窓の床)で、**どちらが床を決めたかを引き算で戻さずに読むためのもの**。実測: `floorW=821 floorH=245`、ログを開くと `floorH=369`、**畳んだ床は両 OS とも 677**(`from=`。2026-08-25 に帯が 3 つのボタンを畳んだ姿で数えるようになり、Windows の帯は 696 → 506 = どちらの OS でもページ側が勝つ)。**`bandW=` はその run で帯が実際に抱えていたものの床** — 状態バッジは worktree の走査が届いてから立つので、**`fold` / `wip` の報告時点ではまだ載っていないことがある**(identity は run が必ず仕込むので `SET IDENTITY` は立たず、`--preset rebase-conflict` でも `bandW=506` = 状態なしの値)。**印 1 つ分が乗った帯の床は `badges` の `bandW=` で読む**。**詳細ペインの側は `details-fit` の `overH=` で読む**(判定には入らない相乗り。壁は `--preset edges` の行 7 を**床の窓**で開く = `--config-dir` に床より小さい `state.toml` を仕込むと起動が床まで持ち上げる。実測: 包む前 `overH=160` / 包んだ後 `overH=0`)。

**帯の状態が 3 つ同時に立つ形は `badges` / `badges-hover` の対**(前者の引数は**窓の幅** — 省略で既定の 1440 / `floor` で床 / 数値でその幅。後者が hover でカードを開く)。**群は 3 段で譲る**(規約 §ウィンドウの縁)ので、**3 形とも撮る**。**同じ幅で同じ形になるとは限らない**のが要点 — タブ列と群が帯の不足を分け合うので、**タブの本数と名前の長さで境目が動く**(OS でも動く: Linux は帯が窓ボタンも掴み代も持たないぶん粘る)。**形は絵ではなく報告行で読む**(`words=` / `mark=` / `cap=`)。実測 2026-08-11(Windows / 長い名前 3 タブ): 1200 = 群 cap 80 / 1050 = 55 / 980 = 45(語の最後の一段)/ 930 = `…` / 880 = タブも下限。**`--preset` 1 つ**(タブ 1 枚)なら群だけが縮み、床 821 でも語が残る。**印だけの形は床より狭い所にしかない**ことがあるので、この動詞は指定された幅を床でクランプしない(`fits=false` はそこでは正 = 判定にも入れていない)。**どちらも `--preset cherry-pick-conflict` が要る** — 進行中の操作と conflict が同時に要り、素の preset ではどちらも立たないので `must_say` に届かない(引数なしで撃つと `op=false conflicts=false` で FAIL する = それが正しい振る舞い)。3 つ目の identity は xtask が**空の gitconfig を**渡し(他の動詞はここに fixture identity が入っている)、`PG_AUTO_IDENTITY=skip` がダイアログを `Not now` で閉じる = 状態だけが残る。報告行 `badges fits= op= conflicts= identity= words= mark= cap= groupW= card= rows= cardSize= bandW= floorW= w= tabsW= grabRun=` を両方が出し、**`badges` は `op=true conflicts=true identity=true`・`badges-hover` は `card=true rows=op,conflicts,identity` が合格条件**(`Outcome::must_say`)。**どの形になったかは判定に入れない** — それは渡した幅が決めることで、引数が名乗っている。**`words=` / `mark=` は行と印それぞれの側・`cap=` は縮んだ幅**(-1 = どれも縮んでいない)で、**`rows=` はカードが実際に並べた行** — 1 行のカードと 3 行のカードは帯へ寄せて切り出すと同じ絵になる。**`cardSize=` は `card=false` の run では不変量ではない** — Popup の寸法は初めて求められた時に決まるので、開いていないカードは `16x16`(padding だけ)にも実寸にも出て、**同じビルドの `badges` と `badges floor` で食い違う**(2026-08-16 実測。分割前後の差分を追う時にここを invariant として読むと偽陽性になる)。読むのは `card=true` の側だけ。**カードは overlay.png に写る**(Popup)。**`identity-tip` も同じカードを読む**(`tip=` はカードの `opened`)。**印に畳んだ後の帯の床は Windows 546 / Linux 381 で、一覧を開いた窓の床 821 の下**(実測 2026-08-25。だから状態が 3 つ立っても床は動かない — 畳んだ側は規約 §窓の床)が、**両 OS 撮るのは変わらない**(フォントが違えばカードの中の 3 行も別々に組み上がる)。

**描かれているグラフがこのリポジトリの履歴でない形は `graph-stale` / `graph-stopped` の対**(規約 §ウィンドウの縁)。**どちらも絵では答えられない** —— 全部の行が立ったまま古くなったグラフは 1 拍前の健全なグラフと画素で同じで、空になった列は開いた直後と同じ絵。**バッジはどちらの場合も同じ 1 語**(`STALE GRAPH`)なので、バッジだけでもどちらか言えない。報告行 `graph_stale badge= stopped= stale= tint= card= words= rows= cardRows=` の**前 5 つが合格条件**(`Outcome::must_say`。`graph-stale` は `stopped=false stale=true`・`graph-stopped` は `stopped=true stale=false`、両方 `tint=danger card=true`)で、**`card=true` を条件に入れているのは、2 状態を言い分けるのがカードの行だけだから**。**仕込みは失敗する git ではなく walk の入口**(`harness::fail_graph_pass` を `GraphModel.failGraphPass` から — 実体は feature `automation` の中。demo リポジトリは歩けるように建ててあるので落ちる git が無い)で、**pass は普通の報告腕から出る** = 本物の失敗と同じ経路。**preset は選ばない**(グラフが 1 本立てば足りる)。**カードは overlay.png の側**。`graph-stopped` の絵は**列が空でリングも回っていない**のが見分け方 —— 開いた直後の絵はリングが回っている。

**帯の 3 つのボタンが縮む形は `band-actions-none` / `band-actions` / `band-actions-fold` / `band-actions-alert` の 4 つ**(規約 §ウィンドウの縁。2 段で譲り、最後は `railWidth` × 帯の全高の印だけになる)。**引数は幅ではなく「形」で渡す** — どの pixel でどの形になるかは入っているフォントの問い(箱も床もそこから測る)なので、**帯自身の計算に幅を名乗らせる**: `-none` は「まだ何も譲っていない最も狭い窓」、引数なしの `band-actions` は「語が残っている最も狭いセル」= 印になる 1 つ手前(数値を渡せばその幅)、`-fold` / `-alert` は**一覧を開いた窓の床**(= 縮み切っていることを約束した幅)。報告行 `band_actions fits= folded= cut= alert= cap= natural= foldAt= cutAt= want= cellW= cellH= wordW= inkW= mark= openW= floorW= bandW= w=` で、**判定に入る 4 つが先頭に並んでいる**(隣り合っていないと 1 つの部分文字列で捕まえられない)。合格条件は `-none` が `fits=true folded=false cut=false`・`band-actions` が `fits=true folded=false`・`-fold` が `fits=true folded=true`・`-alert` が `fits=true folded=true cut=true alert=true`。**`folded=` は絵では答えられない** — 早く畳んだ帯とただ狭い帯は同じ写真で、1 つの幅で撮った帯は「どの幅で形が変わるはずだったか」を何も言わない。**`cut=` は判定に入れない**(`-none` / `-alert` を除く)— **省略の段がどれだけ続くかは入っているフォント次第で、4 文字のコマンドでは 0 になりうる**(実測 2026-08-25 Linux: `push` と `…` + 2 文字がどちらも 27px = `push -f` は丸ごとから印へ 1 段で飛ぶ。Windows は 11px 分だけ段がある)。**`push -f` を見るので `--preset diverged`** を当てる(枠・長押しの印・`-f` が畳んだ姿でも残っているかがここで見える)。**`-alert` だけは仕込みが要る** — `!` は git が撥ね返した go の上に立つので、`push-retry` と同じく **`--preset diverged` の非早送り拒否を受けさせ、`--allow-write-failure` を付ける**(force ではなく素の push を送る = 落ちる方の go)。実測 2026-08-25: `natural=93 foldAt=81`(Windows)/ `92` `84`(Linux)で、天井は窓 992 → 821 の間に降りる。

**アバターは `avatar-*`**(**引数は取り込む画像の `file:` URL** — 保管庫は実行ごとに空なので、見るものはまず入れる。**この一族は `check --verb` に乗らない**(1 本の引数行を両 OS へそのまま渡す仕組みなのに、URL は OS ごとに別物 — ホストは Windows パス、コンテナは `file:///work/…`)。段 2 は `check`(--verb 無し)+ `verify-ui` / `linux verify-ui` を各 OS の URL で個別に走らせる): `avatar-rest`(顔が identicon のまま)/ `avatar-hover`(ペンのバッジを出す — hover は注入できないので `DetailsPane.avatarPointedAt` を立てる)/ `avatar-assign`(選んだコミットの著者へ引数の画像を取り込み、**報告行 `avatar email= details= rows= error=`**。`rows=` は **Rust 側が数える**グラフ行の枚数 = 顔がグラフまで届いたかを言う。QML から数えると**画面に出ていても 0 になる**)/ `avatar-badge`(バッジを押して設定カードを開く = 入力欄にその人が入り `Choose avatar…` に焦点)/ `avatar-settings` / `avatar-row-lit`(一覧の 1 行目の `Remove` にポインタを置いた形 = そのボタンだけが明るい側。置かない側が `avatar-settings`)/ `avatar-remove`(その行の長押しを走らせ、**消えた後**の一覧を撮る — 赤が写るのは `avatar-row-lit` の方)/ `avatar-combo`(候補の一覧を開く。カードは overlay.png 側で `popups=3` = 影 + カード + 一覧)。**この 4 つの絵は overlay.png 側**(カードはモーダル = app.png には写らない)。**完了は `WindowAutoActDriver`** — 設定カードはウィンドウ側の持ち物で、page は画像を入れてカードを頼むだけ、**報告行は 4 つ共通で `avatar_card rows= painted= lit= combo= removed=`** — `painted=` は 1 行目の顔が canvas に載ったか(ファイルは非同期に読まれる)、`removed=` は長押しで保管庫から行が消えたか。**行が要る 3 つ(`avatar-row-lit` / `avatar-remove`、および顔を見る `avatar-settings`)は引数必須** — 入れないと待つ相手が生まれず watchdog まで行く(`avatar-combo` と往復読みの `avatar-settings` は引数無しで動く)。**往復は 2 回の実行で読む** — `--config-dir` を共有し、1 回目に `avatar-assign`、2 回目は**何も割り当てない `avatar-settings`** で顔が出ていれば `settings.toml` の `[[avatar]]` と `avatars/` から戻っている。**画像の実体は中身のハッシュ名**(`avatar` モジュール)なので、ファイル名は毎回同じ = 絵は再現する。


## 通信中(リング)と起動直後の狙い方

**通信中は millisecond の窓を探さない**。`file://` の subprocess は 50〜150ms で終わり、
並行 build・別セッション・ウイルススキャン等でその幅は桁ごと動く。撮りたい出力ごとに
専用動詞を作り、`RepoTab.busyOp` / `mergeToolsLoading` 等の**実 edge**を signal で観測して
automation latch を上げ、app / overlay の `grabToImage` callback が終わるまで表示を保つ。
既存の決定的な中間状態は次の 2 つ:

| 撮りたい状態 | 動詞 | 因果的な証拠 |
|---|---|---|
| force push 通信中(枠あり) | `force-push-hold --preset diverged` | `busyOp == "push"` を latch。`push_hold mode=diverged busy=true` |
| fetch 通信中(枠なし) | `fetch-busy` | `busyOp == "fetch"` を latch。`fetch_busy busy=true fails=0 framed=false` |
| merge tool 候補 loading | `settings-tools-loading` | `mergeToolsLoading == true` を latch。`settled=false loading=true open=true` |

fetch の黄 / 赤、通常 push、起動直後の loading を撮る必要があるなら、同じ型の専用 latch
動詞を先に追加する。`--watchdog-ms` を短くしても画像は保存されず FAIL になるため代用に
ならない。`ActionButton.still` は latch された busy のリング回転を止めるだけで、busy を
作った証拠にはならない。

**起動直後の 0 / false は状態ではない**。グラフ・worktree・sidebar 等を撮る動詞は
`loaded` / first chunk / request generation 等の answer edge 後に値を読む。ロード途中そのもの
が主題なら、実 loading edge を latch する専用動詞を作る。ゲート(git 不在 / 二重起動)は
元から出力状態なので、その `visible` を待ち `gate.visible ? gate : mainUi` の出ている側を掴む。

**ヘッドレスで色を確かめる時はデモリモートの URL を疑う** — 届かないリモートを使う
検証(`fetch-fail` / `fetch-resume` / 黄の `push`)で通信が成功してしまうと失敗の記録が
消え、黄も赤も出ない(逆に `fetch-recover` は**回復側が届く origin に乗っている** —
塞いだままだと成功が来ず、退く絵が撮れない)。実験で `remote set-url` を触ったら戻すこと。**URL は demo repo の
`.git/config` を直接書き換えるのが早い**(`git -C` が通らない worktree セッションでも
届く)。`--preset diverged` は `push -f` の形をそのまま出すので、**枠のある状態と
`!` の同居**はこれで撮る。

## 面の掃き

**掃きの報告文は 1 本**(`SweepPad.sweepAir`)— 7 面が同じ 4 つを訊いていたので、`all=` / `caret=` / `hand=` / `reach=` / `miss=` / `text=` は部品側が書く。動詞ごとの主張だけが `hand=` の後ろに挟まる(`card_sweep` の `open=` が並ぶ席はそこ)。**`all=` が判定・`reach=` は診断** — 面の余白の箇所数はフォントと機械で変わる。**`hand=` を必ず並べる**(run はポインタでなく関数を叩くので `MouseArea` を消しても掃きは緑になる)。

- `gate-sweep`(**起動ゲートの掃き** = `solo` と同じ仕込み。**xtask が `--config-dir` の `lock` を握ってから**アプリを起こすので、パスの行が出るのは本物の 2 つ目のプロセスだから。**この面だけコマンドログが存在しない** — リポジトリを開く前の画面なので、git の答えと相手の exe のパスがそこにある全部。報告行 `gate_sweep all= caret= hand= held= reach= miss= text=`、must_say は `all=true caret=true hand=true held=true`。**`held=` は仕込みの側** — 空のゲートは余白だけ持って欄を持たず、その掃きは読者が見ない画面の話になる。**git が無い側のゲートには動詞が無い**(PATH から git を外した起動が要る = §Windows での実行・デバッグの罠))
- `open-dialog-sweep`(**開けなかったフォルダのダイアログの掃き** = `open-not-a-repo` と同じ仕込み(引数なしで xtask がフォルダを作る)。**モーダルなのでログへの出口も無い**。報告行 `open_dialog_sweep all= caret= hand= kind= reach= miss= text=`、must_say は `all=true caret=true hand=true kind=plain`。**`kind=` は掃いた画面の種別** — `plain` には git の行が無いので、3 行のうち 2 行を掃いた主張であることが 1 行で読める)
- `open-fail-sweep`(**同じ失敗のタブ側画面の掃き** = `open-fail-tab` と同じ仕込み。**こちらは足下に `>_` があるので git の言葉はログで取れる**が、フォルダはどこにも書かれていない側。報告行と must_say は `open_dialog_sweep` と同じ形(`open_fail_sweep …`))
- `ask-sweep`(**質問バーの掃き** = `move-ask` と同じ仕込み。引数はリモート ref(既定 `origin/main`)、**`--preset diverged` が要る**。**`AskBar.settled` を待つ** — バーは 200ms かけて降りるので、途中の絵の余白を標本化しても意味が無い。報告行 `ask_sweep all= caret= hand= words= reach= miss= text=`、must_say は `all=true caret=true hand=true words=true`。**`words=` は仕込みの側**(言葉の無いバーは欄を持たない))
- `diff-band-sweep`(**DIFF 帯のパスの掃き**。引数は `diff-file` と同じ `<パス>` か `<bucket>:<パス>`(**必須** — 帯は渡されたファイルしか名乗らない)。**xtask が `--config-dir` に `details_width = 1100` を撒く** — 1440 の窓で帯に 200px 台しか残らないので、**帯は必ず切る**。報告行 `diff_band_sweep all= caret= hand= cut= reach= miss= text=`、must_say は `all=true caret=true hand=true cut=true`。**`cut=true` が主題** — 帯は `LineText.cutAt: "middle"` で**中央を切る**(規約 §右のペインの字は掴める)。**欄自身は頭切りと同じく far edge へ寄ったまま**で、頭は `…` と一緒に印の地の上に描かれる印の一部なので、`text=` は掃けた尾の分だけ = `es/refs_join_snapshot.rs`(Linux は `res/…`)になるのが正(切れた値は見えている分までしか掃けない)。全文は `Ctrl+A` と一覧の行の hover が持つ。撮るのは `--preset longpaths` の `unstaged:crates/platitude-core/src/session/integration/support/fixtures/refs_join_snapshot.rs`)
- `plan-amend-kept`(**プラン以前から枠に在った素の amend 文**。HEAD の行に降りて打鍵し、**HEAD 自身の行から**プランを開いて `Discard` する — この順だけが「プランが閉じたこと」を唯一の容疑にできる(1 行下を右クリックする道は選択が動き、書きかけの文は矢印でもクリックでも落ちる = `graph-step-dirty`)。報告行 `plan_amend_kept kept= restored= dirty= editable= guard=`、must_say は `kept=true restored=true dirty=true editable=true guard=false`。**どれも写真では答えられない** — 枠は残った文でも原文でも同じ 2 つの箱で、違うのは文言だけ。`kept=` が枠の中身そのもの(`DetailsPane.boxSubject`)/ `restored=` は base がコミット原文であること(= 立っている文が未保存だということ)/ **`guard=` は `Discard` が黄色の長押しを着ていたか**(`RepoPage.planDiscards`)—— 読者自身の amend 文はプランの持ち物ではないので `false` が正で、**着ている側の絵は `plan-fold-carry`**(動詞を置いたプラン = `dirty=true`)が撮る。preset は `plan`)
