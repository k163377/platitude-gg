# PG_AUTO_ACT 動詞表(正本)

[SKILL.md](SKILL.md) の参照資料 — **1 動詞 1 行**(近縁動詞は束ねる・段落側だけの動詞は §索引)、使う動詞名で Grep して該当行と続く節の該当段落だけを読み(全読みしない)、追記も 1 動詞 1 行(段落で書く仕込みは下の節へ)。

**負荷の下では、正しい run でも稀に watchdog まで行く** — 途中の報告行を 1 本も出さないまま 120.5s(2026-08-18 実測: `push-retry` をコンテナで 3 回・`eol-commit` をホストで 1 回。どれも `check` の並列・直前のビルド・連続 run と重なった時だけで、静かな時は `push-retry` が 20 run 連続 PASS)。**FAIL を見たらまずその動詞を単独で回す** — 単独で通るなら見ているのは負荷であってコードではない(逆に単独でも落ちるなら本物)。**判定を緩めない**(`--watchdog-ms` を伸ばして隠さない)。

## 動詞一覧

書き込み操作の headless 検証は **`PG_AUTO_ACT` = 動詞 / `PG_AUTO_ACT_ARG`**:

- `commit`(引数はメッセージ。**省略時は `chore: commit from the headless run`** — 空のまま撃つと git が拒み、コミットの積まれていない絵が撮れる)
- `amend`(同じく引数はメッセージだが、**省略時は `--no-edit`** = HEAD の文言をそのまま持ち上げるので既定でも書き込みは成立する)
- `amend-reset-author`(HEAD の author を identity で取り上げる amend。引数は `amend` と同じで、省略時は `--no-edit`。**書き込み境界では足りない** — amend は自分が呼ぶ再構築より先に答えるので(core `AfterWrite::Graph`)、そこで撮ると**取り上げる前の著者を着たコミット**が写る(2026-08-21: `--preset authorship` が緑のまま `Yuki Tanaka` を撮った)。**refs も再構築より先に答える**ので新しい先端が名乗ったことも境界にならない — 待つのは「グラフが新しい先端を持ったこと」と「詳細ペインが選択に追いついたこと」の 2 つ。報告行 `reset_author was= head= shown= author= committer=` の **`shown=` が、絵の著者行はどのコミットのものかを言う**。**取り上げが絵に出るのは `--preset authorship` だけ**(HEAD の author が identity と違う唯一の preset)で、`head_author differs=true name=Yuki Tanaka` → `author=Demo User` の**対で読む**。**素の `basic` は `shown=` が amend される前のコミットを指すのが正** — その上に積まれた stash が親として描き続けるので amend 後もグラフに残り(行は 1 本**増える**)、選択はそこに留まる)
- `stash-file` / `switch` / `switch-remote` / `squash` / `edit-message` / `edit-message-leave`
- `stash`(木ごと退避する = 作業ツリーの行がグラフから消え、出来た stash が先頭に立つ。**完了はその行が消えたこと + STASHES の本数が動いたこと**で、書き込みの答えでは止まらない — **書き込みは自分が呼ぶ再構築より先に答える**ので(core `AfterWrite::Graph`)、書き込み境界で撮ると**再構築前のグラフ**が写り、行が着ける印の誤りが緑のまま通る(2026-08-21 の 2 件がこれ)。報告行 `graph_settled gone= top= named= back= rows= stashes=` の **`gone=true top=stash named=false` が must_say**。**引数 `named` で対の片割れ**になる = コミット箱に summary を置いてから押す形で、`named=true`(出来たエントリが `On <branch>: feat: write the summary` を名乗る)が must_say。**文言は driver が持つ**(`check --verb` は行を空白で割るので引数に文は渡せない)。**2 本で 1 組** — 片方だけでは「全部同じ名前を着せる帯」も「名前を一切渡さない帯」も緑で通る。**入るのはツールバーの `stash` ボタンそのもの**(`TopBar.stashNow()` — カードは無い。押した瞬間に走る = 規約 §変更を退避する)。**WIP ペインは開かない** — ボタンは帯に常設なので、開いてから押すと「もう要らないペインからの到達」を検証することになる。半分だけ退避する `stash-file` は作業ツリーの行が残るので素の書き込み境界のまま)
- `stash-state`(**ツールバーの `stash` ボタンが作業ツリーをどう読んだか**。引数が期待する答えを名乗り、帯がそれを言うまで待つ = **4 本で 1 組**: `ready`(既定 preset = 汚れた木)/ `clean`(**`--preset tags` 等の綺麗な木が要る**)/ `conflicts`(**`--preset conflict-kinds` 必須**)/ `unborn`(**`--preset empty` 必須** = `git init` だけのリポジトリ)。報告行 `stash_state mode= enabled= tip=`、`must_say` は `ready` が `enabled=true`・残り 3 本が `enabled=false tip=true`。**1 本では何も証明しない** — 下りたボタンはどの理由でも同じ絵なので、「全部同じ答えを返す帯」が緑で通る。**`tip=` はボタンが出す文字列の有無**で、開いた ToolTip ではない(`fetch-tip` と同じ理由)。**`unborn` は木が汚れていても `unborn`** が正 = git が拒む側が先に立つ)
- `reword`(**引数(新しい subject)が要る** — `commit` / `amend` と違って既定を持たないので、省くと空の subject を書き込もうとして何も起きず、**書き込み待ちのまま 120s の watchdog で落ちる**。`check --verb` は空白で割るので、そこへ渡す subject は 1 語にする)
- `edit-message-focus`(description 枠に caret を入れる = 打っている間の色。**何も打たない**ので **body を持つコミットが要る** — `--preset co-authors` の行 0 = HEAD。**休息側は同じ preset・同じ行の `co-authors 0`** で、対で読む。報告行は `message_focus pane= focused= color=` で、読むのは **`color=`**(`textPrimary` `#e2e8f0` / `textSecondary` `#94a3b8`)。`forceActiveFocus()` は offscreen でも効く = フォーカスは hover と違って注入できる)
- `cherry-pick`(引数は ref 名 / 完全な oid / `row:<n>`。グラフ行にある commit なら先にそこへスクロールして選ぶ。下の `tip_landed` を読む)
- `stage-hunk` / `stage-line` / `push` / `force-push` / `force-push-hold`
- `push-retry`(**ボタンが黄 + `!` になる形は push を届かないリモートへ撃つ** — `fetch-fail` と同じ仕込み。push-retry は `--preset diverged` で実際の非早送り拒否を受けてから force で着地させ、報告行 `push_retry refused= branch=` が印の立った側を言う。**印が消えた側は最後の絵で見る**)
- `reset-soft` / `reset-mixed` / `reset-hard`(引数は完全な oid か `row:<n>`。**省略時は HEAD の 1 つ下の行** — 先端への reset は何も動かず絵にならない)
- `reset-hard-confirm`(hard はサブメニューの長押し行 — -confirm はメニューと行を出した所で止まり、reset-hard が長押しを完走させて実行。引数の解決は reset-soft と同じ)
- `commit-menu` / `reset-menu`(**判定は overlay.png 側の報告行**。must_say は `overlay saved=true popups=1` / サブメニューを開く `reset-menu` は `popups=2` — カードの写っていない絵は緑にならない)/ `fetch` / `settings`
- `open-picker`(**ダイアログはプラットフォームの窓なのでどちらの PNG にも写らない** — 判定は報告行 `picker folder=` = 開いているリポジトリの親フォルダの `file:` URL)
- `open-not-a-repo` / `open-bare` / `open-not-a-repo-retry` / `open-not-a-repo-cancel` / `open-fail-tab` / `open-fail-tab-bare`
- `open-fail-tab-log`(**開けないフォルダの 6 通り**。規約 §リポジトリを開く = 置き場所は「どの道で来たか」・文言は種別。**引数を渡さなければ xtask がそのフォルダを作る** — 素のディレクトリか `git init --bare` した先で、**リポジトリになれないものが主題なので `--preset` で名指しできない**。前半 4 つがピッカー経由 = ダイアログ(報告行 `open_failed kind= dialog= tabs= active= near=`。**`tabs=` が「開けなかったフォルダはタブにならない」の答え**で、`-retry` は既存の `picker folder=` が**失敗フォルダの親**を名乗るか・`-cancel` は `tabs=` と `active=` が入る前と同じかを見る)、後半 3 つがそれ以外の道 = タブの中の画面(報告行 `open_fail_tab tabs= state= kind= commands=`。`-log` は `>_` を押して**その画面からログが届く**ことを見る = パネルは空でよい、届くことが答え)。**`dialog=` / `commands=` はどちらもその窓自身の可視性**。**3 つ目の種別(`other` = git が答えられなかった)はアプリから作れない** — 起こせるのは実質 10 秒のタイムアウトだけなので、撮る時は `repo::open` が `TimedOut` を返す**使い捨てパッチ**を当てる(コミットしない))
- `preview` / `preview-unstaged` / `preview-staged`(**引数はパス。素で撃つと空の絵を撮って PASS する** — `toggleDiff` が空パスを受け取り diff ペインは黒いまま、`screenshot saved=true` は出る。**どの preset も画像も binary も持たない**ので、プレビューの絵が要るなら自分でリポジトリを建てて `--repo` で渡す(素の `git init` で足りる — `demo-repo --at` は origin を建てる分だけ MSYS のパス変換に当たる)。`preview-staged` に**まだ commit していない追加**を渡した形が「HEAD 側が無い」= `preview::blob_is_there` の的で、`After` の 1 枚だけが出るのが正)
- `dbl-local` / `dbl-remote` / `move-branch` / `commands` / `commands-fail`
- `name-branch`(**引数は付ける名前、`--preset deep` が要る**。driver は行を選ばず `graphModel.oidAt(0)` = **一番上の行**に名前を付けるので、作業ツリーの行を持つ preset(`basic` 等)では oid がゼロのまま `git switch --create <名前> 0000…` が `unable to read tree` で拒まれる。`deep` は行 0 が HEAD のコミット。**引数を省くと拒否にすら届かない** — 空文字は「申し出の取り消し」として `GraphPane.onNamingSubmitted` で捨てられるので書き込みが起きず、watchdog まで無言(120 秒))
- `commands-clear`(**ヘッダの `Clear` が空にするのは行だけではない** — 帯の `>_` は行と**ヘッダの 1 行**の両方で赤くなるので、行だけ消すと空のパネルの上に赤が残る。`commands-fail` と同じ拒否から始め、着いてから `Clear` を押す。**`--allow-write-failure` が要る**。報告行 `commands_clear was= wrong= open= mark=` は**同じ 1 つの印を押す前と後に読む** — `was=true` が無いと、拒否が着かなかった run の休息状態が修正に化ける(`must_say` は `was=` / `wrong=` / `open=` の 3 つで、この並び順のまま部分一致する)。**`Clear` はパネルも畳む**ので `open=false` が正で、印は誰も開いていない休息の `textMuted`(`#64748b`)へ戻る。**絵は畳んだ後の窓** — パネルの中身は写らない)
- `fetch-fail`(引数は連続で失敗させる回数 — 1〜2 で警告の形、3 で auto fetch が止まった形。**リモートが届かないリポジトリが要る**: demo repo の origin を存在しないパスへ向けておく。報告行 `fetch_fail stopped= fails= wanted=`、`must_say` は引数 1〜2 が `stopped=false` / それ以外が `stopped=true` —— **数は判定しない**(開いた瞬間の fetch が自分の失敗を run の中へ落とすので、どこで落ちるかは機械で動く)。届くリモートで撃つと `fetch_fail reachable=true` を 1 行出して watchdog で落ちる = 仕込みが効いていない印)
- `fetch-busy`(**通信中のボタンそのもの** — 素の fetch を撃ち、`busyOp === "fetch"` の実 edge を帯が latch してから撮る(`force-push-hold` と同じ型)。撮れるのは**枠を持たない側**の待ち = 席でリングが回り語は `textMuted` で残る形。報告行 `fetch_busy busy= fails= framed=`、`must_say` は `busy=true fails=0 framed=false` — **`framed=false` が「一度も枠を着ていないボタンは待っても枠を出さない」の判定**で、無い線は写真では判定できない。枠のある側の待ちは `force-push-hold`)
- `open-fetches`(**開いただけで fetch が走る側** — 何も押さない。引数は fetch が着いた後にグラフが持つ行数で、**`--preset behind 3` が仕込み**(リモートだけが持つコミットが 1 本ある = 開く前は 2 行)。報告行 `open_fetch fails= rows= wanted=`、`must_say` は `open_fetch fails=0` —— 行数に届かない run は報告行を 1 本も出さないまま watchdog で落ちるので、**行が来たことは報告行の存在そのもの**が言う。**通信中のリングはこの動詞では撮れない**(fetch は QML より先に始まりうる = §通信中(リング)と起動直後の狙い方))
- `fetch-tip`(**押せない fetch ボタンが hover に何も出さない側**。引数が対のどちらかを名乗る — `off` が **`--preset noremote` 必須**(リモート 0 本 = 帯の fetch が暗い)、`on` はリモートを持つ既定 preset。報告行 `fetch_tip enabled= tip= remotes=`、`must_say` は `off` が `enabled=false tip=false remotes=0` / `on` が `enabled=true tip=true`。**`tip=` はボタンが出す文字列の有無**で、開いた ToolTip ではない — ポインタは注入できず、しかも**無効なコントロールも hover を受けて添付 ToolTip を開く**(実測 = rules-refs/app-ui.md §hover)ので、判定できるのは「出すものを持っているか」の側。**対で読む** — 出ない側だけでは、文言ごと消えていても緑になる。絵は REMOTES の件数(0 / 3)と fetch の明暗が対になる)
- `fetch-resume`(3 回失敗させてから、止まったボタンの長押しを完走させる。**最後の絵は `fetch-fail 1` と同じ黄**(再開した fetch がまた失敗する)= 赤い `Resume` に届いたことは絵では言えないので、報告行 `fetch_resume stopped= fetched= fails= suspended=` の前 2 つが `must_say`)
- `fetch-recover`(失敗 → 成功の遷移: fetch の失敗がヘッダの 1 行と赤い `>_` を立て、**後続の fetch 成功がその両方を自動で下ろす**側を見る — 意匠の正本は rules-refs/app-ui.md の同名の項。**仕込み不要 = 既定 preset で自己完結** — 失敗側は**存在しないリモート名**への fetch(`git fetch --prune pg-no-such-remote` が exit 128)、回復側は届く file:// origin への fetch。**`--allow-write-failure` が要る**(前半の拒否がこの動詞の見せ物)。報告行 `fetch_recover was= hadline= wrong= line= failures= open=` は**成功の前(`was=` / `hadline=`)と後(残り)を対で読む** — 絵は退いた後しか持てない。ログ本体の失敗行は残るのが正 = 履歴は読者のもの)
- `nav-dbl`(引数 `<section>:<name>`。**タグ行だけは書き込みでは無い** — 開くのは `Create branch here?` の欄なので、`AutoActDriver.isWriteAct` が `nav-dbl tag:` を除いている。除かないと来ない答えを write barrier が待って watchdog まで無言(2026-08-18 実測))
- `nav-reclick` / `nav-reclick-away`(引数 `<section>[:<row>]`、行は既定 0。**畳んだレールが開いたセクションの行を 2 回クリックする** = 改名の所作(規約 §左メニューの所作「間を空けた 2 回目」)。素の形は覗いたまま 2 回 = **箱が開き、一覧が戻る**。`-away` は 1 回目の後にポインタをセルから退かせ、セクションが消えてからもう一度覗いて 1 回 = **何も起きない**のが正(hover で出入りする覗きの「次の 1 回目」が 2 回目に化けると、覗くだけのつもりのクリックが一覧を戻して diff を閉じる — 2026-08-18 ユーザー報告)。**対で読む** — `armed=false` だけでは所作ごと死んでいても緑になる。**箱は畳みを戻さない** — 開いているセクションの中に出て、そのセクションを開いたまま留める(規約 §左メニューを畳む)ので、素の形も `collapsed=true` のまま。報告行 `nav_reclick section= row= marked= away= armed= collapsed= box= focused= peek= editing=` の **`armed=` は行自身の答え**(`NavItemDelegate.renameArmed`)、**`focused=` は箱がキーボードを取れたか**(Popup は自分からは取らないので、ここが false なら箱は打てない見せかけ)。クリックは注入できないので `NavItemDelegate.leftClick` を名前で叩く — **フォルダに畳まれるセクションは先頭行が改名できない**ので行を渡す(`--preset basic` の BRANCHES は `branch:1` = `feature/topic-a`))
- `nav-rename-far`(**`--preset manytags` を当てる** — 一覧より行数が多いセクションでないと何も起きない)。畳んだレールの TAGS を開き、**先頭の行が見えなくなるまでスクロールしてから**その行に箱を開く = 押した行と箱の出る行が別になる経路(現在ブランチの張り付き行と同じ形)。報告行 `nav_far row= shown= box= collapsed= editing=` の **`shown=` は `contentY` から出す**(デリゲートを見ない — 流れ去った行にはデリゲートが無く、「まだ組み立てていない」と区別が付かない)。`must_say` は `shown=true box=true`
- `nav-branch-box` / `nav-rename-box`(**左メニューの行の名前の箱を開いたまま止める** — 前者が新しいブランチの名前(グラフのチップ列と同じ `Create branch here?`)、後者が改名。**同じ欄の 2 つのモード**(`NavNameBox`)なので**対で読む**。引数はどちらも `<section>:<ref>[:<幅>][:away]`(section は `branch` / `remote` / `tag`、ref は git が知っている名前)。**幅はサイドバーの仕切りを引いた先**で、床(180)より狭く頼んでも splitter が床で受ける — 省略すると開いた時の幅(既定 260)のまま。`remote` は根のフォルダが畳まれて始まるので動詞が先に開く。branch の箱は**行メニュー経由**で開く(`RepoPage.refMenuInSidebar` = 左メニュー側とグラフ側のどちらが開くかを決める口)。報告行 `nav_name_box mode= ref= row= pane= seat= box= whole= cut= open= focused= shown= at=` の **`seat=` が行が箱に渡せる幅(= ペインの中で切れていた頃の幅)・`box=` が実際に描かれた幅・`whole=` が中身を切らずに置くのに要る幅**(branch は placeholder、rename は開いた時の名前。**開いた時に latch する**ので打ち込んでも動かない)。**`shown=` は箱が画面に在るか** — ペインの外へ出る箱は「層に切られた」「行がスクロールで消えた」という**行の中の箱には無い消え方**を 2 つ持つので、`must_say` は `open=true focused=true shown=true`。**`:away` を付けると箱を立ててから一覧を 4 行送る** = 行と一緒に箱が消える側で、`must_say` が `shown=false` に割れる(**ビューのキャッシュの内側で送る** — 端まで送るとデリゲートごと消えて、消えたのが箱なのか行なのか言えない。**溢れているセクションが要る**ので `--preset manytags` の TAGS)。実測 2026-08-21 `--preset basic`: `whole=147`(Linux 146)に対し seat は `branch:main` = pane−92 / `branch:feature/topic-a` = pane−68 / `remote:origin/feature/topic-a` = pane−64 なので、**床 180 では 3 行ともペインの外へ出て `box=147`**、既定 260 では 3 行とも seat のまま。rename 側の壁は **`--preset worktrees` の `release/2026-08-candidate-with-a-very-long-name`**(`whole=350` / Linux 345 = どの幅でも外へ出る))

- `graph-bar-away`(レーンの横スクロールバー。**対で読む** — 出る側だけでは何も証明しない。報告行 `graph_bar shown= overflow=`)
- `middle-scroll`(引数 `message` で subject 列から中クリックする。既定はレーン列。報告行 `middle_scroll lanes= x= max=` の `x` が 0 か max か = 横へ流れたかどうか。**`must_say` は引数で割れる** — 既定は `lanes=true`・`message` は `lanes=false x=0`。**完了は `graphX` が自分の max へ着くこと**で、`autoPanning` が下りるのを待たない(あれは身振りの間ずっと立ったままなので、レーン列側だけが必ず watchdog に落ちていた — 2026-08-16 実測・修正))。**この 3 つはレーンが列に溢れている必要があり、どのデモリポジトリも既定の列幅では溢れない**ので、フックが先にレーン列を 2 本ぶんまで詰める(人が仕切りでやることと同じ)。**`--preset stashes` が 3 レーン**で摘みが 6 割になり絵として読める
- `middle-close`(引数はタブの index、省略で先頭。タブを中クリックで閉じる。**タブが 2 つ以上要る**ので `--preset` を 2 回渡す(`--preset basic --preset stashes` = 2 タブ。`--repo` も同じく繰り返せる)—— 1 タブでは「タブが閉じた」しか言えず「隣は残った」が言えない。報告行 `middle_close gone= tabs= active= open=` の **`open=` は残っているリポジトリのパス**で、**タイトルでは閉じた側を言えない**(デモの作業ツリーはどれも `repo` という名前)。`must_say` は先頭の `gone=true` = **押した index のタブのパスが帯から消えた**こと(残り本数は判定しない — 渡されたリポジトリの数だけ開く)。**active より左を閉じたら `active` が 1 つ左へ寄るのが正**)。クリックと同じ経路を通る。**完了は「2 タブ以上」を押す前だけの前提として読む** — 押した後に読み直すと、閉じて 1 本になった状態が前提を割って永久に待つ(2026-08-17 実測・修正)。押下自体も帯の item が出来るまでは空振りするので、`middleClickTab` の戻り値で着地を確かめてから latch する。

## 動詞ごとの読み方・仕込み

**先端に答えが立つ 3 つ(`merge-branch` / `cherry-pick` / `revert-commit`)は 1 本の報告行を共有する** — `tip_landed follows= onscreen= op= head= selected= row=` で、**`follows=` / `onscreen=` の対が合格条件**(`Outcome::must_say`)。選択が新しい先端のコミットへ移り、その行が画面に在ることを言う(規約 §履歴を合流させる)。**merge / cherry-pick は `--preset diverged` の `origin/main`** — 木がきれいで、取り込むものが向こうにあり、着地が非早送りの本物のコミットになる(**`--preset basic` は木が汚れていて `git cherry-pick` が `your local changes would be overwritten` で落ちる**)。**選択は撃つ前に先端から動かす**(グラフ行から入る 2 つは `jumpToRow` してから撃つ)— 動かさないと「元から先端に居た」だけで `follows=true` になる。`merge-branch` は ref 行から入るので選択は起動時の先端のまま = **書き込みが先端を動かすことがそのまま試験になる**。**取り込み済みの merge も先端に着くのが正**(`merge-branch v0.1 --preset basic` = `Already up to date` でも `follows=true`)。

**「止まった側」の 4 動詞は 1 本の報告行を共有する** — `cherry-pick-stops` / `revert-stops` / `rebase-stops` / `drop-stops`(merge だけは `merge-stops` = 出口の形が違うので報告行も別)。共有する 1 本は `write_stopped wip= conflicts= error= log= cont= stashes= op= files=` で、**合格条件は `wip=true conflicts=true error=false log=false cont=true`**(`Outcome::must_say`。`drop-stops` だけ `stashes=1` まで含む)。**`error=` / `log=` が「正常な conflict を失敗として出さない」側で、写真では答えられない**(帯もログも出ていない絵は、出ていない絵と同じ)。**`cont=` は merge 側と裏返る** — step する 4 つは出口カードに `--continue` の行を残す(規約 §進行中の操作から出る。行が無いカードと行が下りているカードは同じ絵)。**`stashes=` は carry を伴う着地だけの主張** — 作業を落とした画面と stash に持っている画面はほとんど同じ絵になる(規約 §未コミット変更がある状態で履歴を書き換える)。**preset は「まだ止まっていない木」でなければならない** — 止まった状態で建つ preset(`cherry-pick-conflict` / `rebase-conflict` 等)は、押した操作が何を答えるかを撮れない。**失敗した run の木は捨てる**(止まった操作が残り、次の run が別の理由で落ちる)。

**タブの幅と `✕` は `tab-widths` / `tab-mark`** — どちらも**xtask が長さの違う名前でリポジトリを建てる**(デモの作業ツリーは全部 `repo` なので、同名の並びでは「どのタブが譲ったか」を言えない。最後の 1 つだけ `basic` = 絵の中でページを持つのは前に出るそれ)。`tab-widths` の引数はタブ数(1..=16・既定 8)で、報告行 `tab_widths tabs= run= cap= floor= max= content= view= scrolls= widths=` の **`widths=` が本体**(実測 Windows: **8 タブ** = 長い 2 枚だけ cap 167 で揃い短い側は自然幅 / **12 タブ** = cap が下限の 1 つ上 / **16 タブ** = `cap=floor` で `scrolls=true`)。**何タブで縮み始めるかは OS で違う**ので、両 OS で同じ数字を期待しない — Linux は merged chrome を持たない = 掴み代 88 も窓ボタンも要らないぶん run が広く(実測 1133 対 896)、8 タブでは 1 枚も縮まず 16 タブでもまだ収まる。**読むのは数字の一致ではなく形**(短い側が据え置き / 譲った側が同じ幅 / `content` ≤ `view`)。`tab-mark` の引数は手を置くタブ(既定 1)で、報告行 `tab_marks tabs= current= pointed= marks=` の `marks=` は**印自身の opacity**(前に居るタブと手の下のタブだけ 1)。**`✕` の hover 半分はこの動詞にしか無い**(hover は注入できないので `TopBar.pointAtTab` が実 hover と同じ `pointed` へ書く)。

**タブの並べ替えは `tab-drag` / `tab-hold` の対** — どちらも xtask が同じ名前のはしごから **4 つ**建てる(`tab-widths` と同じ理由で、同名のタブが並んだ帯では順が読めない。最後の 1 つだけ `basic`)。`tab-drag` の引数は `<from>:<to>`(既定 `3:1`)で、報告行 `tab_drag moved= from= to= tabs= active= open=` の **`moved=` が本体** = 掴んだタブのパスが頼んだ席に居ること(`must_say`)。**`active=` は `to` と同じになるのが正** — 手は運ぶ前にそのタブへ移るので、運ばれた先が前に出る。**両向き撃つ**(既定の `3:1` が左へ・`0:3` が右へ)= 判定は 1 つでも縁と中央の比べ方が向きで別々に書かれている。`tab-hold` の引数は掴むタブ(既定 0)で、報告行 `tab_hold lifted= at= shift= active= open=` の **`shift=` はタブ自身の `Translate.x`**(頼んだ側 = `heldX` を報告するとバインディングが切れていても緑になる)。**この 2 つは対でしか意味を成さない** — `tab-drag` の絵は「並び替わった帯」で、席が飛ぶだけの実装(タブが手の下に描かれない)と区別が付かない。**`tab-hold` の絵ではページが空**なのが正 — 掴む前にそのタブへ移るので、既定の 0 番は履歴を持たないリポジトリ(主題は帯の側)。**末尾のタブは右へ運べない**(運べる先は `contentWidth - width` で止まる)ので、フックは端のタブだけ内側へ運ぶ。

**帯が横スクロールしている時の並べ替えは `tab-edge`** — タブ **8 枚**を建て、**窓を床に落としてから**掴む(何枚で溢れるかはフォントと帯の持ち物次第 = `tab-widths` が OS で違う答えを出す所なので、溢れることを窓の幅の側で作る)。引数は掴むタブ(既定 0)。報告行 `tab_edge landed= from= run= tabs= active= open=` の **`landed=` が本体** = 押し当て続けた結果、列が端まで流れて掴んだタブが最後尾に着いたこと(`must_say`)。**絵では判定しない** — 流れて着いた帯と、最初からそこに居た帯は同じ絵。**この動詞だけは窓の幅を書き換える**ので、他の帯の動詞と同じ絵を期待しない。

**新しい window 側の動詞を足したら `AutoActDriver.defersCompletion` の一覧にも足す** — 足さないとページ側が即完了し、**動詞が働く前に撮って `screenshot saved=true` のまま `must_say` で落ちる**(1 tick で終わる動詞は偶然通ってしまうので、通ったことは足りている証拠にならない — 2026-08-18 実測)。

**右下の git バージョンが隅を譲るかは `corner`** — 引数はペイン(`wip` = 作業ツリー / 行番号 = そのコミットの詳細。省略は `wip`)。**`--preset basic`(一覧が隅まで届かない)と `--preset long`(一覧がペインを超える)を対で読む** — 片側だけでは「常に出る」「常に出ない」と見分けが付かない。報告行 `git_corner pane= shown= room= needs=` の **`shown=` はラベル自身の可視性**(頼んだ側 = 空き寸法を報告するとバインディングが切れていても緑になる)。**PNG でも読める** — 隅の淡い文字が在るか無いかがそのまま答え。**`wip` はどの preset でも `shown=false room=0`** — 底には commit ボタンが張り付いていて隅そのものが無い(規約 §コミットメッセージの 2 つの枠)ので、譲る / 譲らないの対が読めるのは**詳細ペイン側だけ**。実測 Windows: `1 basic room=547` = 出る、`1 long` は `room=0` = 退く(`needs=21` = ラベルの箱そのもの)。

**既に開いているリポジトリを開き直す形は `open-again`**(引数はパス、省略で先頭タブ自身の綴り。報告行 `open_again tabs= active= asked= open=`)。**2 通りを対で読む**: `--preset basic --preset stashes` に**引数なし**で「移る」側(起動直後は `active=1`、頼んだ後に `tabs=2 active=0`)、**git の綴りを引数で渡す**方が「綴りが違っても同じフォルダ」側(`--repo` にはシェルの綴り = `C:\Users\WRONGW~1\…` を渡し、引数に `git worktree list` が出す `C:/Users/wrongwrong/…` を渡す → `tabs=1`)。**後者だけが本題** — 素の文字列比較でも前者は通る。WORKTREES の行から入る形は `nav-dbl worktree:<git の綴り>` で、判定は `opened repository tab` のログが 1 本きりであること。**引数なしの側は `active=0` を待って完了する** — 帯の item はモデルが行を得た次のレイアウトで生まれるので、綴りを訊く `tabPathAt(0)` は先に `""` を返しうる。それで頼むと何も開かず、「タブが増えていない」= 完了条件を即座に満たして **`asked=` 空のまま緑で通る**(2026-08-17 実測・修正済み。今は綴りが来るまで頼まない)。**復元側は仕込みが要る**(`--config-dir` に重複入りの `[tabs] paths` を書いた `state.toml` を置き `state --restore`)— `restored tab dropped: already open` が落ちた件数を、`state tabs= active=` が残った形を言う。

**identity の画面は `identity` / `identity-half` の対**(引数は打ち込む値 `<name>|<email>`、既定 `Ada Lovelace|ada@example.com`)。**この 2 つだけ書き込みが demo リポジトリの外 = 人の git 設定へ出る**ので、xtask が `GIT_CONFIG_GLOBAL`(+ `GIT_CONFIG_NOSYSTEM=1`)と**作業ディレクトリごと**隔離した上で起動する(隔離しないとこの機械の identity を読み書きする)。`identity` = 画面を埋めるだけ(全フラグが下りているのが正)/ `identity-half` = **多値の `user.email` を仕込んだ設定へ保存する** = git が `cannot overwrite multiple values` で exit 5 に落とすので **name だけ着地**(ロック競合と同じ形を決定的に作る唯一の手)。報告行 `identity state= dialog= nameSaved= emailSaved= unsaved= badge= said=` で、**両方 `must_say` を持つ** — 「save が通らずに残っているダイアログ」と「まだ誰も答えていないダイアログ」は同じ絵なので、写真では答えられない。**`dialog=` が本体**。**半端 save の印は `identity-tip`** — 同じ隔離・同じ半端 save の後にダイアログを閉じ(印は半端の間しか立たない)、`badges-hover` と同じ帯の状態カードを開く(`TopBar.statePointedAt` = 実 hover と同じ 1 つのプロパティ)。報告行 `identity_tip unsaved= badge= tip= rows=` の **`tip=` はカードの `opened`**(unsaved / badge / tip の 3 つが must_say)。カードは overlay.png の側に写る。

**2 つ目のプロセスが出す窓は `solo`** — **xtask 自身が `--config-dir` の `lock` を握ってから**アプリを起動するので、起動するのは本物の 2 つ目(状態を真似るフラグは無い)。報告行 `solo blocked= held= gate= main=` で、**`blocked=true` を言わなかった run は FAIL**(仕込みが効かないと絵は普通の窓になり、普通の窓は普通に撮れてしまう)。`--config-dir` を渡さない既定でよい。

## 通信中(リング)と起動直後の狙い方

**通信中は millisecond の窓を探さない**。`file://` の subprocess は 50〜150ms で終わり、
並行 build・別セッション・ウイルススキャン等でその幅は桁ごと動く。撮りたい出力ごとに
専用動詞を作り、`RepoTab.busyOp` / `mergeToolsLoading` 等の**実 edge**を signal で観測して
automation latch を上げ、app / overlay の `grabToImage` callback が終わるまで表示を保つ。
既存の決定的な中間状態は次の 2 つ:

| 撮りたい状態 | 動詞 | 因果的な証拠 |
|---|---|---|
| force push 通信中(枠あり) | `force-push-hold --preset diverged` | `busyOp == "push"` を latch。`push_hold mode=diverged busy=true` |
| fetch 通信中(枠なし) | `fetch-busy` | `busyOp == "fetch"` を latch。`fetch_busy busy=true fails=0 framed=false` |
| merge tool 候補 loading | `settings-tools-loading` | `mergeToolsLoading == true` を latch。`settled=false loading=true open=true` |

fetch の黄 / 赤、通常 push、起動直後の loading を撮る必要があるなら、同じ型の専用 latch
動詞を先に追加する。`--watchdog-ms` を短くしても画像は保存されず FAIL になるため代用に
ならない。`ActionButton.still` は latch された busy のリング回転を止めるだけで、busy を
作った証拠にはならない。

**起動直後の 0 / false は状態ではない**。グラフ・worktree・sidebar 等を撮る動詞は
`loaded` / first chunk / request generation 等の answer edge 後に値を読む。ロード途中そのもの
が主題なら、実 loading edge を latch する専用動詞を作る。ゲート(git 不在 / 二重起動)は
元から出力状態なので、その `visible` を待ち `gate.visible ? gate : mainUi` の出ている側を掴む。

**ヘッドレスで色を確かめる時はデモリモートの URL を疑う** — 届かないリモートを使う
検証(`fetch-fail` / `fetch-resume` / 黄の `push`)で通信が成功してしまうと失敗の記録が
消え、黄も赤も出ない(逆に `fetch-recover` は**回復側が届く origin に乗っている** —
塞いだままだと成功が来ず、退く絵が撮れない)。実験で `remote set-url` を触ったら戻すこと。**URL は demo repo の
`.git/config` を直接書き換えるのが早い**(`git -C` が通らない worktree セッションでも
届く)。`--preset diverged` は `push -f` の形をそのまま出すので、**枠のある状態と
`!` の同居**はこれで撮る。
