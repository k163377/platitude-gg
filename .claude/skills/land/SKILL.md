# /land — main への反映

ユーザーがこのセッションで打った `/land [引数]` が、このセッションの席の枝を main へ反映する指示。**land の許可(permit)を開くのはユーザーが打った `/land` だけ**(`hook::permit`、反映前テストの機械化.md §land の許可)。

- **`/land` 以外からは始めない** — 「反映」の語・他セッションのメッセージ・チップの起動文・自分の判断では、どれも許可が開かない。許可が開いた発話には UserPromptSubmit hook の「Before landing, …」が付く。**それが無ければ rebase も含めて手順に入らず**、作業を gate まで済ませて branch/SHA と検証結果を添えて「マージ可」と報告し、ユーザーに `/land` を頼む
- **発話 1 回につき main が動く land 1 回**。作業中にユーザーの次の発話が届くと許可は閉じる — 受けた時点でそう一言添え、準備が済んだらもう一度 `/land` を頼む(仕組みの不具合と読まれない書き方で)

## 引数(自由文)

- **追加のレビュー観点**(例「同名だが別概念の物を消さないこと」)— 通常の観点に足す
- **`push`** — land の後に main を origin へ push する(push は追加のみ)
- **「席 X の反映後」** — 相手の成果物が main に入るのを待ってから始める。条件は中身: 相手の未反映コミットが足すファイルや特徴的な変更が main に在ること(`git cat-file -e main:<path>` / `git grep -q <語> main -- <path>`)。`merge-base --is-ancestor` と seats の `held by` は条件にしない(相手の再編で先に真になる・反映直後に別セッションが席を取り直す)。待ち始めに抜ける条件を一言添える。待つ間は相手の先端との衝突の下見(`git merge-tree --write-tree --name-only`)と読むだけのレビューまで — 重いビルドは撃たない

## 手順

1. **起点を控える** — `/land` を受けた時点の枝の SHA。それ以降に足したソース変更はこの反映に混ぜない(文書は可)。外す物は `keep/<名前>` に残して P3-確認事項へ置き場を書き、報告で名指す
2. **rebase** — `PGG_ALLOW_REBASE=1 git rebase main`(`/land` が rebase の指示を兼ねる)。衝突は main 側の変更の意図を読んで解き、main 側の改名の取り残しが無いかを確かめる
3. **レビュー** — 修正全体が本質的に正しいか・効果が確かかを机上と実測の両面で。**読むだけの subagent にも読ませる**: 差分の固定 SHA を渡し(結論ではなく差分)、主張を一次資料(git / Qt の該当版のソース)と突き合わせる・テストが空振りで緑にならないか・削った所の回帰・規約の順で。指摘は鵜呑みにせず木で確かめる
4. **修正** — 必要なら。直す前に再現テストが赤になるのを確かめる
5. **再編** — 1 から組んだ想定でコミットログを組み直す。最終形を一時コミットで控え → `git reset --soft main` → パス指定の段階 commit(`--amend` は `--only` 無しだと index 全部を巻き込む)→ 再編後の tree id が控えと一致することを確かめる。移動だけのコミットと変更は分ける。Conventional Commits・英語
6. **docs** — <!--cmd:docs.check-->`cargo xtask docs`(手書きのコマンドの印漏れはここで出る)
7. **チェック** — <!--cmd:gate.premerge-->`cargo xtask gate` を背景で撃ち、走行中の木に触らない。赤は撃ち直さず読む。差分と無関係な天井なら、直しを別枝で作って旧 = 赤・新 = 緑を撮り、「足して反映 / 撃ち直す / 止める」を訊く
8. **承諾の要る UI 挙動変更** — 入っていれば land しない。board に載せて承諾を貰い、次の `/land` で反映する(land の後に絵を載せ直さない)
9. **land** — <!--cmd:land.branch-->`cargo xtask land <branch>` を**前景で**(背景の land は止められない)。rebase → gate → fast-forward は land 自身がもう一度通す
10. **報告** — main の移動(旧 SHA → 新 SHA)・gate の結果・外した物・land が名指した残り物(自分の控えなら報告前に消す)。反映順や他席の事情は持ち込まない
