# /land — main への反映

ユーザーがこのセッションで打った `/land [引数]` が、このセッションの席の枝を main へ反映する指示。**land の許可(permit)を開くのはユーザーが打った `/land` だけ**(`hook::permit`、反映前テストの機械化.md §land の許可)。同じ発話がこの席を**反映の列**に入れる(§land の列)。列の順は `/land` を打った順で、追い越しは無く、先頭の席だけが land する。

- **`/land` 以外からは始めない** — 「反映」の語・他セッションのメッセージ・チップの起動文・自分の判断では、どれも許可が開かない。許可が開いた発話には UserPromptSubmit hook の「Before landing, …」が付く。**それが無ければ列にも手順にも入らず**、[gate スキル](../gate/SKILL.md)の実行時機に従って branch/SHA と検証結果を報告する。見た目の確認待ちは「gate 未実行」、現在の commit の gate が PASS した時だけ「マージ可」とする
- **発話 1 回につき main が動く land 1 回**。作業中にユーザーの次の発話が届くと許可が閉じ、席は列から消える — 受けた時点でそう一言添え、準備が済んだらもう一度 `/land` を頼む(仕組みの不具合と読まれない書き方で)
- **待つ時はトークンを使わない** — 待ちは背景のコマンドの終了で起こす。他席の枝は読まない(読むのは下の read の差分だけ)。先に反映された物を正とし、rebase は「次」で 1 回・「先頭」で 1 回まで

## 引数(自由文)

- **追加のレビュー観点**(例「同名だが別概念の物を消さないこと」)— review-points スキルの観点に足す
- **`push`** — land の後に main を origin へ push する(push は追加のみ)

## 手順 — 列の位置で 3 段

位置は <!--cmd:land.line-->`cargo xtask land line` が言う。**起点を控える**のはどの位置でも最初: `/land` を受けた時点の枝の SHA。それ以降に足したソース変更はこの反映に混ぜない(文書は可)。外す物は `keep/<名前>` に残して P3-確認事項へ置き場を書き、報告で名指す。

### 待機(3 番目以降)

何もしない。<!--cmd:land.wait-next-->`cargo xtask land wait next` を背景で撃ってターンを終える。終了の通知で起きたら、その行の位置に従う(次 → 下の段、先頭 → その下の段)。

### 次(2 番目)

終了の行(または <!--call:land.line-->`land line`)が、先頭の反映に含まれる規約・設計の変更をパスで言う:

- **stop**(CLAUDE.md、land / review-points / verify-ui / gate の SKILL.md)— 何もしない
- **read**(それ以外の `.claude/` と `internal-docs/`)— そのパスの差分だけを先頭の枝から読み(`git diff main...<先頭の枝> -- <path>`)、自分の作業に全体適用される規約・設計の変更なら何もしない
- どちらでもなければ、今の main へ `PGG_ALLOW_REBASE=1 git rebase main` し、**自分の書いたコードだけを読んでバグ・テスト漏れなど明確な不備だけ直す**。規約との照合・再編・gate はしない(本番のレビューは先頭で)。**明確な不備を超える直しが要ると分かったら** <!--cmd:land.leave-->`cargo xtask land leave <why>` で列から外れ、残作業を続けて §外れた後 へ

済んだら <!--cmd:land.wait-head-->`cargo xtask land wait head` を背景で撃ってターンを終える。先頭の反映が済むと通知で起きる。

### 先頭(反映中)

ここが本番。**どの段でも、ユーザーの判断が要ると分かった時点で <!--cmd:land.leave-->`cargo xtask land leave <why>` で列から外れ、それから訊く**(答えを待ってから外れない — 後ろの席を待たせる)。レビューで出た設計の要判断、4 の差分と無関係な天井、7 の承諾待ちがそれ。順に:

1. **rebase** — `PGG_ALLOW_REBASE=1 git rebase main`。衝突は main 側(反映済み)の変更の意図を読んで解き、main 側の改名の取り残しが無いかを確かめる
2. **レビュー** — main からの差分全体を review-points スキルで(引数の追加観点を足す)
3. **修正** — 必要なら。直す前に再現テストが赤になるのを確かめる
4. **確認** — <!--cmd:gate.premerge-->`cargo xtask gate` を背景で撃ち、走行中の木に触らない。赤は撃ち直さず読む。差分と無関係な天井なら、列から外れ、直しを別枝で作って旧 = 赤・新 = 緑を撮り、「足して反映 / 撃ち直す / 止める」を訊く
5. **再編** — 1 から組んだ想定でコミットログを組み直す。最終形を一時コミットで控え → `git reset --soft main` → パス指定の段階 commit(`--amend` は `--only` 無しだと index 全部を巻き込む)→ 再編後の tree id が控えと一致することを確かめる。移動だけのコミットと変更は分ける。Conventional Commits・英語。木は変わらないので land の gate はキャッシュで済む
6. **docs** — <!--cmd:docs.check-->`cargo xtask docs`(手書きのコマンドの印漏れはここで出る)
7. **承諾の要る UI 挙動変更** — 入っていれば land しない。列から外れ、board に載せて承諾を貰い、次の `/land` で反映する(land の後に絵を載せ直さない)
8. **land** — <!--cmd:land.branch-->`cargo xtask land <branch>` を背景で撃ってターンを終える。land は rebase → gate → fast-forward をもう一度通し、fast-forward の直前に permit を読み直す(ユーザーの発話で閉じていれば main を動かさずに止まる)。終了の通知で起きる
9. **報告** — main の移動(旧 SHA → 新 SHA)・gate の結果・外した物・land が名指した残り物(自分の控えなら報告前に消す)。反映順や他席の事情は持ち込まない

## 外れた後

land が rebase の衝突・赤い gate・承諾待ち・閉じた permit で止まると、その席は**自動で列から外れる**(先頭で 2 時間、awake と同じ判定で何も起きなかった席も、反映する物が無かった席も)。順番を取る前の拒否(汚れた席など)は外れないので、直して撃ち直す。ユーザーの判断が要ると分かった席は、どの段でも訊く前に自分で外れる(上)。外れた席は残作業を続ける — 自分の不備なら直し、差分と無関係な天井なら上の 4 のとおり別枝で直して訊く。済んだら branch と SHA を添えて「マージ可」と報告し、ユーザーの次の `/land` を待つ(最後尾に並び直す)。自分で並び直す経路は無い。
