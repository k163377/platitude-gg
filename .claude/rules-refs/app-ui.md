# platitude-app 各論(複数の部品に効く罠・型と配線済みの索引)

[.claude/rules/app-ui.md](../rules/app-ui.md) の参照資料 — **1 項目 1 行**。置くのは**複数の部品に効く物**(共有部品の使い分け・Qt / QML の罠・自動化の共通の型)と配線済み操作の索引だけ。**1 つの部品の意匠決定・実装対応・罠はその部品のコメントが正本** — ここへ足さず、部品名で Grep して部品を読む。

- **配線済み**: ステージング(ファイル / hunk / 行)・commit / amend・switch(ローカル / リモート)・fetch(手動 + auto + 開いた時)・pull(右クリックの 1 行 —— 今立っていないブランチは早送り)・push / force push・単体 cherry-pick・単体 squash・merge / rebase / revert の起動・単体 drop・止まった操作の出口・conflict の種別・片側採用・外部ツール連携・conflict の一括解決(バケツの帯)・コミットメッセージ編集・amend での著者引き継ぎ・reset(soft / mixed / hard)・stash push(全体 / 1 パス)・discard / clean・identity・署名の表示・設定の画面(規約 §設定の画面)・diff プレビュー(`platitude_core::preview`)・コマンドログ・初回 push・Ctrl+F のコミット検索(アドバンス検索は未着手)・上下矢印でのコミット送り・diff の上下送り・diff のファイル一覧の送り(PageUp/Down・Home/End は未配線)・読んでいるファイルの光・stash の Apply / Pop・ブランチ / タグ / stash の改名と削除・リモートブランチの差し替えと削除(左メニューの行・グラフ行・チップの一覧の 3 経路)・upstream の解除(BRANCH カードの白の 2 回押し・`Set upstream…` の名前を空にした質問)・手元の改名の後のリモート・タグのリモート状態バッジ・リモート / PR のバッジと色の札の扇(`RefChipStack`)と `+N`・チップの一覧のスクロール・タグの作成(軽量)とリモートへの push・co-author の表示・著者のアバター・設定 / 画面状態の永続化・改行コードの警告・git の版(無ければ全画面のゲート / `OLD GIT` バッジ)・diff のシンタックスハイライト・コミットの複数選択(Ctrl / Shift)・サイドバーの各ブランチの upstream との距離(ahead / behind)・タブ名の中央切りと字数の床 / 取り分の天井・帯のタブへの移動(開く・既に在るタブへ・復元)・別の worktree へ立ち位置を移す(WORKTREES 行 / 別の worktree のピル / その worktree のパスを開く)・タブが立ち位置を名乗る・立てない worktree からリポジトリ自身の worktree への立ち直し・worktree の削除(WORKTREES 行・グラフ行・別の worktree が持つブランチの右クリックの WORKTREE カード)・worktree の作成(右クリックの `Create worktree here…` / `worktree add` —— グラフ行・左メニューの ref 行)・worktree の改名(間を空けた 2 回目 —— WORKTREES の行・フォルダのチップ。ブランチの無い worktree はフォルダ名 = `worktree move`、このタブが立つ worktree はタブが追う)・破棄記録(記録・一覧・グラフの仮表示・帯からの復元 = `platitude_core::discards`。方針は 破棄記録仕様.md)・ブランチの作成(`Create branch here…` —— グラフ行・左メニューの ref 行)・クローン(☰ `Clone repository…` = `CloneDialog`)・リモートの追加 / URL の訂正 / origin の印(`RemoteDialog` / `RemoteRowMenu`)・upstream の指定(`Set upstream…` = `UpstreamFlow`)・フル interactive rebase のプラン(`RebasePlanPane`)・diff の中の Ctrl+F(`DiffFindBar`)・GitHub のページへのリンク(`GitHubMenu`)・別の worktree の変更をこの木へ当てる(`Apply changes to this worktree`)。この一覧が配線済み操作の正本(配線したらこの行へ足す)

- チェックボックスは `AppCheckBox` の 1 か所(規約 §QML 実装ルール。Fusion の indicator が消える理由・高さの既定・動詞は `AppCheckBox.qml` のコメント)
- 改行コードの警告は 3 席・判定は core の `eol` の 1 か所(規約 §改行コードの警告。席ごとの実装は `WipPane.qml` / `WipCommitBlock.qml` / `RepoSession::publish_diff` のコメント)
- 実窓の絵は UIA では代われない — `ValuePattern` の欄の値は追従するが、`Text` の `Name` は古いまま返る。実窓の判定は `PrintWindow(hwnd, hdc, 2)` の画素で
- コンポーネント本体に書いた素の `onX` は、使用側が同じ `onX` を書くと丸ごと置き換えられて黙って死ぬ — 本体の側は `Connections` で繋ぐ(例: `IdentityFields.touched`)
- `Canvas` の印はオーバーレイのミラーの grab に間に合わないことがある — 印は `overlay.png` でなく `scene.png` で見る(例: 設定画面の帯 = `SettingsHeader`)
- **床のある数値欄は空欄を `onEditingFinished` で拾えない** — `IntValidator` に `bottom` があると空文字は Intermediate = `acceptableInput` が false で、Qt は Enter でもフォーカス離脱でも `editingFinished` を出さない。空欄が意味を持つ欄は画面の出口が書く(例: `SettingsAppPane.applyFields`)
- ツールチップの中の行き先は `HoverToolButton.tipPlace` / `tipHref`(頼む側は `TipAsk.place` / `href`。規約 §hover のツールチップ)。文は `tip` に素のまま 1 か所に綴る(組み立てと色の罠は `CardText.qml`、押下の行き先は `RepoPage.tipLinkAsked` のコメント)
- **ツールチップの文中に立てる印**(規約 §ref の種別「ツールチップと見出し(報せ・質問・ダイアログ)は字の中」)は、的の `tipMarks`(`CardText.marks` の 4 つ組)か `tipMarkWord` / `tipMarkKind`、頼む側なら `TipAsk.marks` / `markWord` に書く。`tipPlace` と同じ文に並べてよく、文は分割しない(席の探し方は `Words.tipNameSeat`、部屋と描き方は `CardText.qml` のコメント)
- **ヘッドレスの窓には手が乗っている** — offscreen の platform は画面の原点にカーソルを置いたまま動かさず、窓はその点に立つので、**窓の左上のセルが run 中ずっと `hovered`** になる。**取り返しは効かない**: `hovered` は QML からは読み取り専用・カーソルが動かないので leave も来ない・窓は完了ハンドラより前に上がっているので後から場所を変えても enter は決まった後。**だから製品側が「手は無い」を読む** = `Hand.away` を `WindowHarness` が `Harness.automated` で立て、実ポインタを読む所(`HoverToolButton.lit`・`AppMenuButton` の地・`BandStateGroup.asking` — 読まないと何が起きるかはそのコメント)がそれを見る。run が点けるのは stand-in(`pointedAt`)だけ

- **カードの行は `onTriggered` に繋ぐ** — 普通の行のクリックは `triggered` だけを出して閉じる(回数押しの行は `held` で、閉じるのは `closeMenu()`。自動化の押し方は `AppMenuItem.held` のコメント)
- **worktree の名前を言う連(木 / 家 + フォルダ名)は `NameRun`**(規約 §ref の種別「文の中の名前」)—— 印の色・等幅の字・地の直しが全部の使い手へ届く。使い手と幅の天井は `NameRun.qml` のコメント
- **字のインクの端は大きく測る**(`WordFace.codeLarge`)—— 描く大きさの `tightBoundingRect` は FreeType(offscreen と Linux)では整数の画素へ外向きに丸めた箱で、offscreen の絵は地の端も外向きに丸めて描く。テストは地の端を item の幾何で、字のインクを絵で読む(罠の詳細は `WordFace.qml`)
- 枠の中の先頭に立つ字の隣の印は、枠の側の席の空気(`MarkSeat.airAt(字の px)`)を席の幅と印の x から引く(規約 §余白「枠の中の先頭に立つ印」。呼び手と余りの割り方は `MarkSeat.airAt` / `ActionButton.headInk` のコメント)
- **ヘッドレス(offscreen)の絵の等幅の字は、名前の大きさではヒンティングで設計の外形より高く描かれる** —— 地と字の空きを絵で読むテストは半画素の揺れを見込み、地の位置は外形(`WordFace.codeInk`)から出す(実測は `tst_codeground.qml` のコメント)
- **コードの地は `CodeGround` 1 つ**(規約 §git 用語のコード表記。高さ・縦・角・色はそこだけが決める — 仕様と使い手は `CodeGround.qml` のコメント)。**等幅 `Label` の行箱の高さは OS ごとに違う** —— 同じ罠はその高さを読む所すべてに在る

- **modal な popup はポインタも窓の `Shortcut` も封じる**(Qt 6.10.3)。modeless はポインタを通すが、`CloseOnEscape` を持てば窓の `Shortcut` は封じる(「hover のカードは窓の `Shortcut` を塞がない」)。だからその下の `Shortcut` や Escape を**手で落とす配線は要らない** — 書けば死んだコードになる(例は `QuitWaitDialog.qml`。アプリ終了の close ゲートは `WindowQuitGate.qml` の冒頭コメント)
- **走っている git は右クリックのメニューの行を落とさない — 開いた時に走っていれば全行を灰にして待ち、終われば読み直した状態で形を保って立て直す**(規約 §メニュー)。新しいメニューもページの `runningWhy` を受け、`AppMenu.waitEnded` で開き手の `standAgain` を呼ぶ(実装と罠は `AppMenu.qml` の `runningWhy` / `holdShape`、`RepoPage.runningWhy` / `treeAtAsk`、各開き手の `standAgain` のコメント)
- **1 回の drain は queue を全部吸って `changed()` は 1 回**なので、**1 つの notify が答えを複数運ぶ**。**特定の答えを待つ側は `RepoTab::write_answers` を読む** — group の `write*` が説明するのは「名前で待たれていなかった最後の 1 本」だけ(詳細は `models/repo_tab/mod.rs` の `write_answers` と `ops/mod.rs`)
- **行番号で「最新のコミット」を指す所は `GraphModel.newestCommitRow()` を撃つ** — 規則は `models::graph::item::newest_commit_row` の 1 か所
- **コミットの詳細を読む動詞は自分でその行を開く** — 汚れた preset ではページが WIP 行に着地するので、`AutoActDriver.cardSettled` を待つ sampler は**誰も選んでいない**まま watchdog へ行く(例は `AutoActHistoryVerbs.readCommit`)。**逆に「HEAD が選択でない」ことが前提の動詞もある** — 自分で最新のコミットを選んでから始める(`graph-head-below` の driver)
- `qproperty!` の doc コメントはビルドを落とす(`//` で書く)。`#[derive(QModelItem)]` は 16 個目のフィールドを拒む(15 が上限 — 例は `GraphRowItem`)
- **Qt のキーとフォーカスの罠**(適用は `GraphList.qml` / `GraphRowWalk.stepRow`): `ListView` の既定のキーナビは `currentIndex` を黙って動かす(`keyNavigationEnabled: false`)/ 単行 `TextInput` は上下を消費しない(デリゲート内の `TextField` にフォーカスがあってもリストの `Keys.onDownPressed` が発火。Left/Right は箱が消費)— `ListView` は focus scope で、子が持っていても `activeFocus` は true なのでフォーカスでは判別できない / 画面から退いたアイテムはフォーカスとキーを持ち続ける(`StackLayout` の裏の子が `visible=false activeFocus=true` で `keyClick` がまだ発火。手放させるのは `focus = false`)

- 幅の上限は外から — 子の `Layout.maximumWidth` に親の `width` を入れるとループし、Qt は黙って最小幅で落ち着かせる。`Layout` は不可視の子を spacing ごと飛ばす — 席を保つ子の字は `text` で消し、`visible` では消さない(実例と罠は `FindBar` のコメント)
- **メニューが立っている間、裏の hover は伏せる**(規約 §メニュー): ページの物の判定は `RepoPage.menuDoor` 1 つ(どの面のどの的から出したメニューかを `area` / `key` の対で持つ戸口)— **読む側は戸口 1 本から導く**(戸口と別のプロパティを 2 本読む式は、片方だけ更新された瞬間に評価されて自分の行のメニューでも閉じる)。**窓の物は窓に立つメニューを読む**(`OutsidePress.standsOver`)— ページの戸口と混ぜない。**例外は自分の行から出したメニューだけ** —— 「どれかのメニュー」を保持の理由にすると、グラフのメニューの下で手が離れても閉じない。メニューの `showing` は素のプロパティ — 他ファイルから `visible` を読むと stale(席ごとの実装と動詞は `RepoPage.menuDoor` / `RowHoverHost` / `OpenRowSeat` / `SidebarPane` / `OutsidePress.standsOver` のコメント)
- **帯末の道具は段を `padding` で落とす** — `Control` は `contentItem` を padding の残り全部に伸ばすので、中身に書いた `width` は次のレイアウトで消える(実例は `NavHeader` / `ViewMarkButton`)。**`Popup` では消えずに回る** — 窓より広い箱は位置決めが窓に合わせて切り、中身の `width` と書き手が 2 つになって幅の binding loop。上限は箱の `implicitWidth` に置く(`TipSeat.box`)
- `Layout.verticalStretchFactor` は両端に付ける — Qt は未設定を 0 と読み、片方だけだと相手の取り分が丸ごと消える(実例は `NavSections` の地)
- `SplitView` の min / max / preferred は代入で固定(バインディングはドラッグに壊される — `SidebarPane.applyFold`)。QML のシグナル引数漏れは黙って `undefined` になる。`Popup` は中身を面の全面に敷く — 不透過の中身は枠を塗り潰すので `padding` に枠幅を入れる(`SectionPeekPopup`)
- **席を帯の縦いっぱいに広げても重ね色は印の箱に留める**(規約 §QML 実装ルール「広げるのは判定だけ」)— 差は `topInset` / `bottomInset` で書く(`Control` は `background` を inset の分だけ縮めて置く。`padding` は `contentItem` にしか効かないので、両方書かないと印だけが縮む)。`background` に `anchors.centerIn` + 明示幅で書いても同じ絵になるが、`Control` の `resizeBackground` は「幅が明示されているか」で分岐するので、片方だけ書くと黙って伸びる。手本は `ViewMarkButton`(`TreeViewToggle` の 2 つ)。**この差は写真では判定できない** — 塗りが席より小さいので、席が広がっていない実装と同じ絵になる。使い捨ての qmltestrunner シーンで測る: `mouseMove` を帯の最上行と最下行へ配って `hovered` が両方 true・帯の外は false
- ボタンのフォーカスリングは `visualFocus` — `activeFocus` はクリックでも出て居座る(QQC2 のボタンは `StrongFocus`)。リングを出せるのはタブ順のボタンだけ(どのボタンを入れるかは `ActionButton.activeFocusOnTab`)
- hover の検証は使い捨ての qmltestrunner シーン(hover はアプリへ注入できない)。`platitude.ui` はディレクトリ名が URI と食い違う — `-import` の先に `<tmp>/imports/platitude/ui` のジャンクションを張ってから渡す。シーンには `font.family: Theme.uiFamily` を書く — 既定フォントの `/` は太くて広く、分数の印が `⫽` に化ける
- `hoverEnabled: true` は手に応える `Control` が名乗る — `Control` の既定 hint(theme の `useHoverEffects`)は offscreen で false。行やセルの `HoverHandler` は hint を訊かないので、名乗らないと同じ帯で片方だけが手に応える(`HoverToolButton` は名乗る)
- **`hoverEnabled: true` を名乗った `Control` は、無効(`enabled: false`)でも hover を受け、`hovered` で頼む tip が出る** — **押せないボタンを黙らせるには `tip` を空にする**(規約 §無効「ボタンや入力欄の無効はツールチップを持たない」。`HoverToolButton` での形はそのコメント)
- 画素の検証は qmltestrunner シーンの `mouseMove` → `grabImage`。Fusion の面を測るには palette が要る(`Item` に palette は無いので `Pane` で包んで `Main.qml` の値を写す — 無いと style 既定の白いボタンを測る)。qmltestrunner の出力は `QT_FORCE_STDERR_LOGGING=1` が無いと 1 行も出ない(OutputDebugString 行き)
- **リモートへ届く削除は画面の oid を運ぶ**(lease — `remote::delete_remote_branch` / `delete_remote_tag` のコメント)。出所は入口ごとに 1 つ(各入口のコメント)。**メニューの oid は開いた時に凍る**(`standOn`)ので、開いている間に背景の fetch が進めても押下は見ていた先端へ掛かる

- **1 行の文に名前を code で並べる部品は `CodeLine`**(折り返さない)— 切り方(`cutAt: "end"` / `"middle"`)・印・名前の色は `CodeLine.qml` の冒頭
- **子の入札から自分の幅を決める入れ物は `Math.ceil` で受ける**(`AppMenu.widestRow`)。入札は測った数なので端数を持つ — `property int` は**切り捨てる**ので、入れ物はその行に切り捨てた幅しか配らず、行の `RowLayout` が予算超過になる。超過分は伸縮する item から取られ、しかも端数ぶんでは済まないので、幅を決めた当の行だけが省略される。**Windows は同じ語のメトリクスが整数で出るので何も起きない**。測った幅を `int` にする式は他は全部 `Math.ceil`(`BandStateMetrics` / `DiffTextMetrics`)か `real`(`ActionButtonLabel.wantWidth`)で、`TopBar` の `Math.round` は報告値(`band-actions` の数)— 新しく `int` で受ける時にどちら側か決める。**入札を足し合わせる側も部品ごとに切り上げる**(`AppMenuItem.implicitWidth` のチップと印付きの名前)—— `RowLayout` は子の幅を 1 つずつ整数へ上げるので、端数のまま合計して最後に 1 回上げると部品の数だけ 1px 弱ずつ足りず、最後に並ぶ名前だけが省略される(例は `AppMenuItem.besideWords`)
- **基底型に在る名前で property を宣言しない**(基底の property でもメソッドでも。`enabled` なら `Item.enabled` をそのまま使う)—— 同じ名前が 2 つになり、外からの読み書き・呼び出しは新しい方へ届くが、基底型自身は C++ の仕組みも基底の QML の binding も元の方を読み続ける。`enabled` を覆うと、祖先の無効化も、無効化で落ちるフォーカスと pointer の grab も元の方にしか効かず、新しい方を読んだ入口だけが止まる(覆うとフォーカスが残り、Enter で行が走る = `tst_opexitrow`)。`HoverToolButton.lit`(手が乗っている)を覆うと、外から読んだ `lit` だけが別の物を答える(`tst_viewtoggle`)。Qt 6.12 は素の宣言を型を建てるたびに警告する(`qt.qml.propertyCache.append`「overrides a member of the base object」)。**model の role 名も同じ**(delegate の `required property` になるので、`Item.state` と重なる名前を欄に付けない)。**QML で書いた関数を書き直すのは別** —— 基底の中からの呼び出しも新しい方へ振り分けられる上書き(`DiffPane.clampY`)。**`enabled` とは別に「今は押せない」が要るなら別の名前で**(`ActionButton.busy` / `AppMenuItem.blocked`)、押下・キー・自動化の入口を全部止め、進行中の回数押しは `HoldDriver.blank()` で消す(`tst_menurowblocked`)
- **ツールチップは `TipSeat` の `ToolTip` 1 つ**(`Main` が窓に 1 つ置き、`Tips` singleton が席を登録する。添付の `ToolTip` は使わない = `ToolTip.policy` も `ToolTip.delay` も書く所が無い)。的は **`TipAsk`** で頼む。待ち・手渡し・手の下で動く的・機械の判定の限界は `TipSeat.qml` / `TipAsk.qml` の冒頭、`rowsMoved` を言う面の一覧は `HandWatch.rowsMoved`
- **ペインの内寸は `spaceXs`(規約 §QML 実装ルール)** — 書いてある所は 8 つ: `PaneHeader.x` / `NavHeader` / `NavItemDelegate` / `WipBucketHeader` / `StashActionsBand` / `FileRowDelegate` / `DetailsMessageBlock`・`WipCommitBlock` の `Layout.margins`。**中央ペイン(`DiffPaneHeader` / `DiffFileNotices` / グラフ行の中の刻み)は `spaceSm` のまま**。**左メニューの「行」は名前を見出しの印の列に揃える**(規約 §余白 の左メニューの行の項)。値は `NavList.rowInset` / `nestStep` の 1 箇所(読む側と STASHES / TAGS の席の有無は `NavList.qml` / `NavRowBody.seated`)

- **`Awaited.claim("<名>", () => <述語>[, ["app", "scene"]])` は絵の主張** — 完了と絵の間に別の物(読みの着地・休止の満了)が入りうる動詞が完了で置き、各成果物(`app` / `overlay` / `scene`)が保存されたターンに `pictured run= artifact= name= holds=<true|false|error>` が出る(`Awaited.pictured`、`AutoShotDriver.pictured` → `WindowHarness`)。xtask は `true` 以外と、判定表 `verify::verbs::CLAIMS` が要求する主張の欠落を FAIL にする(`verify::contract`)。全 run は `name=window` の主張(完了時に立っていた部品の集合が絵でも同じ、`WindowCensus.markCompletion` / `reportAt` — 完了の歩きは動かさず、swap 1 フレーム後に撮って比べる)と、**完了のターンに page が settled だという主張**(`complete … page=settled`。完了の経路が待つので、残るのは complete に名指した届く前の項だけ)を自動で持つ。置くのは「完了の後にページへ届く物が主題を変える」動詞(`card-latch back` / `rebase-plan-run`。反映前テストの機械化 §検証時点)
- **観測・遷移・完了は分ける**(`Awaited` / `StageTimer`、反映前テストの機械化 §検証時点) — **観測** `Awaited.all(名, 項)` は今揃っているかだけを答え、何度読んでも段を動かさない。**sampler は全部 op**(page 側 `PageStage` / 窓側 `WindowStage`、`name:` 必須)で、起動ごとが世代。**遷移** は op だけが動かす: `op.advance("段"[, () => 報告])`(その拍の最後の観測が真の時だけ)/ `op.input("段", () => 押す[, 答え => 報告])`(入力は段ごと世代に 1 回、押す関数が false なら動かない = 効果を待つ要求の撃ち直しはこの形)/ `op.complete({ when, report[, arriving][, lost][, name] })`。段は `op.at("段")` で読み、`order:` に順を宣言する(飛ばし・戻り・二重・最後の段の前の完了は breach)。別の driver の段が要る時だけ `after: ["page/act/dispatched"]` と項 `"joined": op.joined()`。**証拠は 3 つ**: 入力前・押下中・入力直後の事実は `op.witness(名, 値)`(op・世代・段に結ぶ、`witness` 行)と `op.witnessed(名)`、完了時にも要る条件は `when`(移る拍と保留の各回に読む。崩れたら待ち直し、`lost: "fail"` で breach。入力は撃ち直さない)、完了時の状態は `report`(確定の読みのターンに読み、同じターンの読み直しと一致した時だけ言う)。行は `begin` / `stage` / `witness` / `said …: <行>`(段の報告と `op.note` = 履歴)/ `report … text=<行>`(完了の報告 — 動詞の must_say はこの行だけで照合する。perf は `measurement … text=`、絵の主張は撮影の `… saved=` 行)/ `complete … page= [expected=] [witnesses=]`。dispatch は `act` の入力で、完了しない — 報告は `driver.reportAtCompletion(…)`、障壁への引数は `driver.awaitTreeGone` などの受け口。**辿る検査** (`cargo xtask waits` の `reach`): beat は入力も状態も持たず、press は入力と起動だけ、read は読むだけで前の値を持ち込まない — 補助関数・別ファイルの関数も呼び元として読み、機構の関数は `// reach(…)` で呼べる文脈を宣言する(書き方は verify-ui スキル implement.md §操作の書き方)。**`Harness.report` と完了の口・`Awaited` の内部は機構のファイルだけ**(`sampler` / `owner` / `report` / `completion` / `awaited` / `reach` / `stage` / `input` / `stale` / `unread`、どれも marker で通らない)。予約名: op の `owner` / `name` / `order` / `after` と関数 `at` / `generation` / `joined` / `advance` / `input` / `say` / `note` / `witness` / `witnessed` / `kept` / `complete` / `again` / `still` / `laidOutSince`(同名の property を足すと型ごと読めない)。天井の行 `awaited` / `stages` が止まった段と揃わなかった条件を名指す
- **レイアウトを待つなら `op.still(名, 値)`(読んだ値が、読んだ後に始まった polish をまたいで同じ)か `op.laidOutSince(名)`(初めて訊いた後に polish が 1 回始まった)** — 根拠は `Awaited` の 1 つの契約(`layoutMark` / `layoutPassedSince` / `askLayout`、完了経路の `sized:` も同じ)で、窓の `afterAnimating` = polish の回数を数える。**`frameSwapped` は根拠にしない**(threaded loop では render thread から、GUI thread が先へ進んだ後に届く — 読みより前に始まったフレームの通知で解ける)。描画できない窓は polish しないので待ちは解けず、守っている入力・証人も保留される。寸法 0 で置かれた値も polish の後は立つ。**レイアウト以外の仕事(読みの到着・色付け・答え)は、その仕事自身の条件で先に待つ** — polish 1 回をすべての完了と読まない。記録は op の段と世代に属し、前の段・前の世代で成り立った記録は次の待ちを満たさない。動詞ごとにフレームや polish を数えない(`waits` の `frames`)・「同じ値が 2 拍」を settle にしない(拍は壁時計で、1 回のレイアウトの前に 2 拍とも落ちる)。**一覧の行を読む(`itemAtIndex`)・一覧の上で完了するなら先に `Awaited.built(view)`** — モデルの行は着いた瞬間に在り、delegate は次の polish で建つ(`QQuickItemView::refill` は viewport を 1 回で埋める)ので、着いた拍に読むと空。`PageSettled.missing` も見える一覧ごとに `rows:<持ち主/型>` の項で同じことを待つ(一覧を足しても登録は要らない — 拾い方は `PageSettled.lists` のコメント)
- **`Awaited.all` の名は診断の接頭辞** — 変わった時だけ `Harness.report` で 1 行(`<接頭辞> waiting=<揃わない名前,…>`)、watchdog が最後の行と経過を `awaited … for Nms`、op ごとの世代と段を `stages <owner/op>@<世代>:<段> …` で出す(`AutoShotDriver`)。**置き換えで判定を変えない** —— 渡すのは今までの述語そのままで、何が揃えば進むかは動かさない。経過は run の時計(`PerfProbe.clockMs`)で測る = `Date.now()` は `cargo xtask waits` が咎める。天井は同じ所で `page missing=<項>` も出す —— **`PageSettled.missing` が `settled` の規則そのもの**(`settled` は「missing が空」)なので、項を足す時は `missing` に 1 行足せば両方に効く
- **worktree の行は全部 git の all-zero id を着ている**(`GraphModel.carried_row_of`)ので、**「番号で取った行の id が all-zero か」は「この窓のworktree 行が在るか」の答えにならない**。窓自身の行は walk が**歩く前に先頭へ積む**(`session::walk`。積むのは最初の status が「何か在る」と言った pass だけ)ので、**行 0 が他の worktree の行 = この pass には窓自身の行が無い**。訊く形は 1 つ(`GraphModel.wipRow` = 先頭が all-zero **かつ** carried でない)で、既定の着地(`RepoPage.trySelectDefault`)・止まった操作の着地(`tryPendingWipSelect`)・ハーネスの分類(`AutoActDriver.graphTopKind`)が全部それを読む。実コミットを指す番号が要る所は `GraphModel.newestCommitRow`(`rememberAnchor` の錨)。**素の id で訊くと**、status に負けた walk の pass で着地が他の worktree の行に乗り、`openWipFor` がその worktree の上にページを立てて読む。**機械化済み: `cargo xtask structure`**(`ui/` と `auto/` の QML で、**番号で取った行**に `GitFacts.wipOid` を訊くのを拒む。手渡された行に訊くのは対象外)
- **「答えで完了する動詞」は、その書き込みの status まで待つと宣言する**(`AutoActCompletion.owesStatus` → `AutoActDriver.statusOwedFrom`)— core は答えを、その書き込みが無効化した status より先に出すので、答えの瞬間と status の後はどちらも `PageSettled` が立つ別の画面。待ち方(番号で測る・自分の答えから引く)と、fetch を含む動詞に付けない理由は同 2 ファイルのコメント
- **ドライバの root は `Item`** — `QtObject` は default property を持たず、匿名の子(`Timer`)を 1 つも書けない(`Cannot assign to non-existent default property` で窓ごとロードに失敗する)
- **インスタンス化の場所の `prop: <同名の id>` は id に解決される**(自己バインドしない)— ドライバの property 名を渡す id と揃えられるのはこれが理由で、逆なら全部 null になる。同じ名前でも**部品の内側**では property が id をシャドウする(帯の幅式が NaN になった形は `WindowBandActs.qml` の `bandActTimer` のコメント)

- **Rust に文言を置かない** — 画面に出る文は QML の `Words`(`qsTr()`)だけが持つ。core / app の Rust が橋へ渡すのは種別(kind)・名前・数と、引用として出す git の言葉まで。Rust で組んだ文は `qsTr()` を通らない(CLAUDE.md 絶対制約)
- **`Shortcut` の既定 `context: Qt.WindowShortcut` は窓がアクティブになるまでキーを渡さない** — Windows のフォアグラウンド・ロックで前面にならずに起動した窓は、中を 1 回クリックするまで Ctrl+F 等が効かない。常に届かせたい入口は常設のボタンかメニューの行にも置く
- **動詞の run が「注入した条件だけが違う」形になったら、その条件表は QML 部品テストへ移し、窓を建てる run は door を 1 本だけ残す**(先例 = `report-tone` + `tests/qml/tst_reportdress.qml`)。**判断は「run ごとに何が違うか」** —— 違いが引数だけ(`showReport(arg,…)` のように動詞が条件そのものを渡す)なら移せる / 違いが repo の状態・窓の寸法・OS のフォントなら移せない(`delete-blocked-tip` の 3 つは、どの理由が当たるかを実リポジトリの状態が決める)。**残す run は「その kind だけが持つ側」を選ぶ** —— 既定値の arm を残すと、door が答えを 1 つ落としても既定のまま緑になる
- **「窓の寸法・OS のフォントが決める」run でも、決めている当の値を引数にすれば移せる**(`tab-widths` + `tests/qml/tst_tabwidths.qml`、同じ形で帯の状態群 `badges` + `tests/qml/tst_bandshare.qml`)。**ただし数だけを割った単体は、割った先が製品に繋がっている証拠にならない** — 単体は自分で入力を作るので、**製品側の配線を切っても緑のまま**。**数を割ったら、実部品を建てて配線を撃つ QtTest を対にする**(`tst_bandgroup.qml` = 実 `BandStateGroup` + 証人の実 `BandStateMetrics`。境界は計算せず**掃いて見つけ**、入れ替わりが部品自身の報せる床の上に載ることを要求する)。**手順は 2 つ** —— ① 測る側と配る側を別オブジェクトへ割る(`TabMetrics` = フォント・アイテム / `TabShare` = 数だけ)。**測った値を引数に取れば run は数になる**ので、境界の直前・一致・直後まで 1 プロセスで撃てる。② 残す run は**枚数ではなく状態を名乗らせ、その状態へ着いたことを assert する**(`tab_widths cut= folded=` / `TabStrip.tabNamesCut`)—— 枚数は OS が答えを変える側なので、枚数を名乗る run は確かめていない状態を主張する
- **Esc は窓に 1 本しか生きられない**(規約 §立っている質問は 1 か所で聞く / §答えの要らない報せ): **有効な `StandardKey.Cancel` の `Shortcut` が窓に 2 本あると Qt はどちらも撃たない**(`tests/qml/tst_escape.qml` の `test_two_at_once` が固定)。質問バーと報せバーは**同時に立ちうる**ので、**順序は `RepoPage` の `NoticeBar { yieldsEscape: graphPane.asking }` の 1 行だけ**に書く。**新しく Esc を欲しがるものは キーハンドラで受ける**(3 本目の `Shortcut` は窓の Esc を全部殺す)。バー側の所作とヘッドレスは `NoticeBar` / `RepoPage` のコメント

- **`contentY` を手で書く所は `originY` と両端の margin で丸める**(`AppListView.clampY` = 一覧全部が持つ 1 本。diff だけは `[0, maxY]` の自前を上書きで持つ)— 高さの違う行を持つ一覧で `positionViewAtEnd` / `positionViewAtIndex` を撃つと ListView が自分の原点を動かすので、`[0, contentHeight - height]` は可動域ではない。**絵は正しいまま端だけが届かなくなる**ので目視では出ない

- **その隣の secondary は枠を持たない**(`Cancel` / `Not now` 等)— 対の形はアプリ全体で 1 種類、枠を落とせるのは肯定側の隣に並んだ時だけ。Fusion の素のボタンは平らな枠版の隣では肯定側より重く見える

- **ボタンは `ActionButton` か `HoverToolButton` の 2 つだけ**。数えるなら型で数える — リテラル `highlighted: true` の列挙は式で書かれたものと highlighted でないものを落とす
- **字の隣の印は `NavIcon.set` で描く**(規約 §アイコンの席)—— `"name"` / `"lead"` / `"head"` / `"sign"` に `size`(字の px)と `wordBase`(その項目の y で字のベースライン)を渡すと、大きさ・線・置く高さを印が自分で出す。**項目の高さは字の項目と同じにして同じ揃え方で並べる**(`wordBase: words.baselineOffset`)—— レイアウトとアンカーは半 px を別々に丸めるので、混ざる所は字の y を読む(`AppMenuItem.wordsTop`)。**`rotation` で回さない**(置く高さごと回る)—— `turn` を使う。**`baseline` という名の property は置けない**(`Item` の FINAL と衝突して型ごとロードに失敗する)。**部品に足す property は置かれる側の id と同じ名にしない** —— インスタンスが自分の component(`Loader` の `sourceComponent`・delegate)の中にあり、id がその外のファイルの物の時、束縛は部品の property を id より先に引き、警告 1 行のまま既定値で描く(実例は `NavIcon.pen` のコメント)。同じ component の中の id は property より先に引かれる。ツールバー(積んだボタン)と操作パネルは対象外。大きさ・席の幅・置く中央・コードの地の始まりの各論は `NavIcon` / `WordFace` / `MarkSeat` のコメント

- **欠けた前提は言って止まる**(rules/app-ui.md §UI 自動化)— readiness(`viewLaidOut` 等)の後でも動詞の前提が無い fixture は、待っても来ないので watchdog まで無言になる。欠けを報告行の値で言ってその場で完了する(`code-send` の `max=0`・`code-grow` の枠に収まる diff・`keep-place` の `room=`)— must_say が落ちるので run は赤のまま、原因が行に出る。欠けを読むのは readiness の後だけ(前の 0 は「まだ」と「無い」を区別しない)。例外の `diff-bar` は同動詞のドライバのコメント
- **書き込みの答え(`WriteFinished`)は、その書き込みが無効化した読み直しより先に来る**(`session::write::run_write`)ので、答えで撮った絵は実行前の画面 — ハーネスの write barrier は answered と settled を id で待つ(`wroteAndSettled`)。動詞の見せ物が「書き込みの後の画面」なら、さらにその書き込みが動かす当の行を待つ(グラフは `graphGoneOid`、作業ツリーの一覧は `treeGoneRow`)— settled は断られた write にも読み直しが失敗した write(`WriteSettled.failed` は tab に届かない)にも来るので、行が動いたことだけがこの write が着地した証拠。status / refs の seq は誰も頼んでいない読み直しでも進むので証拠にならない
- **左メニューの一覧(stash / worktree)は書き込みの後の読み直しのうち status・refs と別の読みで、順不同に着く**(3 つが並走し、walk はその後 = `session::write::settle_after`)—— status で撮る動詞は書き込みの前の一覧を写しうる。**HEAD を detached にする書き込み(replay の停止)と下ろす書き込みでは、WORKTREES のリポジトリ自身の行の名前(ブランチ ⇔ フォルダ)がそこで入れ替わる**ので、止まった・下ろした着地は全境界の後に撮り、名前を報告行 `home=` で言う(`NavProbe.homeWorktreeName`)。**tab の口を通らない書き込み(`RebasePlanModel::run_plan` が session へ直に出す)は id が無く `wroteAndSettled` が開かない** —— 答えを名前で拾って `writeAnswerReadsFrom(i)` を控え、その一覧の `NavSectionModel.listingLooked()` がそれ以上になるまで待つ(core の `Fence::reads_from` と同じ比較)。**そういう書き込みを `pressWrite` に通さない** —— watch は押下済みのまま閉じず、後の press の arm が違反になる
- **「まだ答えが無い」と値 0 / false を分ける** — 非同期モデルは `loaded` / request generation / sequence 等の readiness を公開し、自動化は readiness の後で値を読む
- **一瞬だけ立つ状態は signal で観測して latch する** — error / busy / loading が polling 1 周より短くても、その実 edge を見た証拠を保持し、非同期 `grabToImage` が終わるまで意図した中間表示を保つ。証拠は実 edge を見た時か、edge を見せない書き込みの答えを見た時だけ(`write_answers` の行)
- **報告行が主張する到着は、前提条件でも全部待つ** — 失敗した書き込みの帯の印(`commandsWrong` = コマンドの行)とその下の 1 行(`lastError` = 書き込みの答え)は別の道を順不同で来る。どちらか一方で先へ進むと、遅れた側を `false` と読む(`fetch-recover-held`。`WindowAutoActDriver.fetchRecoverActTimer` は両方の latch を待つ)
- **描画境界は画像 callback が答える** — completion 後に `requestUpdate()` と event-loop turn を通し、app / overlay 両方の `grabToImage` callback が返ってから終了する
- **`frameSwapped` を待つなら頼むのは `window.update()`** — verify の offscreen run は software ループで、software / basic ループは `updatePending`(`QQuickWindow::update()` が立てる)が無いと swap も `frameSwapped` もしない。素の `requestUpdate()` は静止した scene では描くだけで何も送らない(threaded ループは毎回 present するので実窓の perf では差が出ない)
- **効果を待つ要求は拍ごとに撃ち直す**(rules/app-ui.md §UI 自動化)— `update()` でも、窓が見えていない時に取られた要求は swap せずに消える(上の行)/ `RepoSession::restart_log` は後から来た ask に取って代わられ、取られた pass は cancel される(`take_log_run`)/ 故障の注入(`failGraphPass`)は立ったままなので、撃ち直しても同じ故障にしかならない。撃ち直さずに待てるのは完了境界を持つ要求だけ(書き込みの答え・`grabToImage` の callback)
- **QML テストの待ちも `cargo xtask waits` が見る** — 待ちは `tryCompare` / `tryVerify` の既定 timeout(`wait(ms)` は赤。message だけなら timeout の席は `undefined`)・`waitForRendering` / `waitForItemPolished` の戻り値は `verify()` で読む
- **見出しの名前の天井は `CardText.holdsNames`**(報せ・質問・リモートのダイアログ・破棄記録の帯とカードの見出し。2 行目とツールチップは切らない。切り方・全文の出し方・コピーは同 property のコメント)
- **名前の色は `Words.nameInk(地の文の色, 居場所の色)` の 1 か所**(規約 §ref の種別「文の中の名前」。色の優先順は同関数のコメント)。**印の色は `NavIcon.inkBeside(名前の色)`**
- **`TextMetrics` は 1 つの変更通知で全部を言う** — 書いた `elideWidth` の答えを同じ定規の `advanceWidth` で読むと binding loop(全幅と切った幅は別の `TextMetrics` に置く)。**字の大きさは定規の `font` から読み返さない** —— 自分の `pixelSize` を読む(定規の `font.pixelSize` を読む席は Linux の qmltest でだけ binding loop になる)。例は `AppMenuItem.refCuts` / `seatRoom`・`CardText.seatRoom`
