# platitude-app 各論(意匠決定・実装対応・罠)

[.claude/rules/app-ui.md](../rules/app-ui.md) の参照資料。全文を読む必要はない — **1 項目 1 行**なので、触る部品名(QML ファイル名)・操作名・動詞名・規約 §名で Grep して**該当行と前後**を読む(罠は塊で並ぶ)。**追記も 1 項目 1 行で**(並行セッションの追記を同じ行で衝突させないための形)。コード・docs の「app-ui.md §…」という参照は、このファイルへ移った行も指す。

- **配線済み**: ステージング(ファイル / hunk / 行)・commit / amend・switch(ローカル / リモート。**行き先は必ずブランチで、detach する導線を UI のどこにも置かない** — `CheckoutTarget` に detach する行き先自体が無い。ブランチの無いコミット・タグを指した時は `Create branch here?` の入力欄になる。**ただし git が置いていった detached HEAD からは表示も操作も普通に働く**(抜ける道は switch とその入力欄の 2 つ。ブランチが要る操作だけ無効)。未コミット変更は**必ず持っていき、何も尋ねない** — git が拒否したら core が stash → switch → `stash pop --index` で回り直す(`session::carry_across`)。conflict しても専用の表示は無く、conflict の付いたファイル行になるだけ)・fetch(手動 + auto)・push / force push・単体 cherry-pick・単体 squash・merge / rebase / revert の起動・単体 drop・止まった操作の出口(commit ボタン直下のカード)・conflict の種別・片側採用・外部ツール連携・コミットメッセージ編集・amend での著者引き継ぎ(HEAD の author が現在の identity と違う時だけ出す)・reset(soft / mixed / hard。ブランチがある時だけ・進行中操作なしの時だけ出す。サブメニューの親行が `reset` \<branch\> here を名乗り、各行はフラグ(`--soft` 等)のチップ + 説明文 — チップ列は幅を共有して文の頭を揃える。**hard はバーではなくサブメニュー行そのものの長押し** = stash 削除と同じ意匠)・stash push(作業ツリー全体は WIP ペインのオプションカード / ファイル行の右クリックで 1 パスだけ)・discard / clean(ファイル行の右クリック。下記)・identity・署名の表示(詳細ペインは検証結果を 3 つに畳んだ 1 語 + 無署名は無表示、コミット欄は `commit.gpgsign` が効いている時だけ `will be signed`。規約 §署名の表示)・設定(auto fetch 間隔)・diff プレビュー(画像は Before/After 描画、非画像バイナリはサイズ表示 — `platitude-core::preview`)・コマンドログ・初回 push・Ctrl+F のコミット検索(基本 — アドバンス検索は未着手)・上下矢印でのコミット送り(グラフをクリックしてから)と **diff の上下送り**(diff は画面に出た時に自分でキーボードを取り、1 打 1 行で視界を送る。どちらも PageUp/Down・Home/End は未配線)・stash の Apply / Pop・ブランチ / タグ / stash / リモートブランチの改名と削除・タグのリモート状態バッジ・co-author の表示・著者のアバター・設定 / 画面状態の永続化・改行コードの警告(**個々の意匠・実装対応は下の各項**)。**この一覧が配線済み操作の正本**(CLAUDE.md は未配線だけを持つ。機能を配線したらこの行へ足す)

- **グラフの未コミット行の集計は status から数える**(規約 §未コミット行が名乗るもの)。`status::Kinds::of` が **`Counts::of` と同じ 1 パス**で種別ごとの**行数**を出し(`models::worktree` の `drain`)、`WorkTreeModel.wip*` → `GraphPane` の view → `GraphRowDelegate.Tally` と渡る。**git のコマンドは 1 本も増えない** — 行数(`+N -M`)を出すなら `diff --numstat HEAD` が 1 本要るが、ファイル数は既に手元にある status の文字そのもの。**印は `ChangeIcon` の再利用**で、色の規則は 1 か所のまま(数字は `tallyMark.tint` を借りる)。**`conflictCount` を種別の 1 つとして混ぜる**(`Kinds::conflicted` と同じ値 = 一覧の CONFLICTS バケツの行数)
- **印の席は `NavIcon.inkWidth`**(規約 §余白)。`NavIcon` は 16 グリッドに描くが**インクの幅は kind ごとに違う**(`plus` / `minus` / `copyicon` 9・`arrow` 8・`pen` 10・`bang` **2**)ので、箱で席を取ると `!` だけ 5px の空気を抱えて数字から離れる。**`inkGrid` は NavIcon が持つ**(描き方を知っているのはそこだけ)。**列挙に無い kind は箱いっぱい**を返す = 既存の呼び出しは 1px も動かない
- **`pen` の補正は 0.67 グリッド**(旧 0.25)。回転後のインクは本体の角が 5.23・先端が 3.89 で**原点より 0.67 上**に座る(ストロークの 1/4 は別に足す)。**`iconMd` で語の隣に立っている間は隠れていた** — 数字と組で立たせた瞬間に「ペンだけ浮く」として報告された(2026-08-10)。直すと `iconMd` の側も 0.42px 下がるが、ファイル行の見え方は変わらない
- **段は `iconXs`(10)** — この印は語ではなく**数字と並ぶ**ので `iconSm` では大きい(実測: インク 8px 対 数字 6px)。**10px にしてもインクは 1px しか縮まない**(アンチエイリアス込み 8 → 7)ので、効いているのは**席の引き方の方**。字で組む案(`+2` / `~2` / `→1`)は不採用 — 和文 UI フォントで記号の幅が揃わない(実測 em: `+` 0.724 / `-` 0.435 / `→` **1.000 = 全角**)
- **ヘッドレスは `wip-tally`** — 報告行 `wip_tally added= modified= deleted= renamed= copied= conflicted= rows=` の **`rows=` と種別の和が一致するのが答え**(`rows` は一覧の行数)。**絵では答えられない** — 4 つの数字と 6 行を目で足し合わせることは求められない。数字そのものは PNG に写るので `must_say` は付けない
- **改行コードの警告は 3 つの席に出るが、判定は 1 か所**(規約 §改行コードの警告)。core の `eol` が patch の bytes から 4 ケースを読み、(c)(d) だけ近傍ファイルの標本を基準に付き合わせる。**diff ペインの 1 行は `git diff` と並列に解決する**(`session::load_diff` の `tokio::join!`)— 後から現れる警告は既に読み進めた人には届かない。**基準は (ディレクトリ, 拡張子) でキャッシュ**し、書き込みと refs の移動で捨てる。**WIP の印は status が変わった時だけ読み直す**(`status_key`)— index は status を動かさずに変わりようがないので、**窓の外の git が `git add` した分も次のポーリングで拾う**。ポーリングそのものには乗せない(読むのは pending の diff で、静止状態が 10 秒ごとに払う値ではない)
- **コミットボタンが警告するのは index に乗っている時だけ**(`WorkTreeModel.eolStagedCount`)。commit が積むのは index なので、ワークツリー側だけの印は「次の `git add` の話」。**語は変えず、押し方も変えない** — 枠と `!` と hover だけが動く。長押しにしない理由は規約 §可否・警告の出し場所(日常操作は尋ねない)
- **警告の hover はカード**(`EolHoverCard`)。`ToolTip` は**文字列 1 つ・色 1 つ**で、ここは 2 行のうち 1 行だけが警告色(`CommitHoverCard` と同じ判断)。**地はもう理由ではない** — ツールチップも同じカードに載る(下記 `Main.dressToolTip`)。**カードはペインが 1 枚持ち、行とコミットボタンが共有する** — ポインタは 1 本で、行に持たせるとスクロールで行ごと消える。ヘッドレスは `eol-hover <パス>` / `eol-commit [amend]`(報告行の **`card=` はカード自身の `opened`**)、diff ペイン側は `diff-file` が `line_endings kind= scope= lines= text=` を出す。**`--preset eol` が 4 ケース + 印の付かない普通の変更を 1 つ持つ**(「印が付く」と「このコミットが印の付いたファイルを積む」を 1 枚の絵で分けるため)
- **identity のダイアログは「git が今どう答えるか」で閉じる**(`AppBackend.identityNameSaved && identityEmailSaved`。`identityError === ""` ではない)。**2 連書きは原子的にできない**(理由と実測は core.md)ので、**半端を消すのではなく見えるようにする**のがこの画面の役目 — 揃えば閉じ、揃わなければ**欄ごとのチェック印**(`NavIcon kind: "check"` + `Theme.success`)が landed した側だけに出て、下に git の文言が残る。**判定は Rust 側**(`identity::IdentityWrite` → 2 つの `qproperty!`)で、trim の規則の写しを QML に作らない。**印は `identityUnsaved` の時だけ出す** — 揃った save はダイアログを閉じるので、印は成功の飾りではなく**失敗の説明そのもの**。**`visible` ではなく `opacity`**(タブの `✕` と同じ理由 = 印の出入りで入力欄の幅を動かさない)
- **半端のまま `Cancel` / `Not now` で閉じられたら、ツールバーの identity バッジが引き受ける**(`AppBackend.identityUnsaved`)。**文言は `SET IDENTITY` のまま**で、分けるのは tooltip だけ — 押した先の操作は同じなので、語彙を 1 つ増やす理由が無い。**セッション内に閉じる**(次回起動へ持ち越さない)— 持ち越すには「頼んだ値」をファイルに残すことになり、**アプリは identity のコピーを持たない**(ダイアログ本文が `Platitude GG keeps no copy of them.` と名乗り、`settings.rs` の `Settings` にもキーが無い)方針と両立しない
- **git が何も言っていないのに揃わない時の 1 文は QML が持つ**(repo-local が global 書き込みの上に座った場合)。**Rust に文言を置かない** — git のメッセージは素通しでよいが、こちらが書く文は `qsTr()` の側に在る必要がある(CLAUDE.md 文言規約)
- **ヘッドレスは `identity` / `identity-half` の対**で、**identity 系だけは書き込みが demo リポジトリの外へ出る**ので xtask が `GIT_CONFIG_GLOBAL` と作業ディレクトリごと隔離する(`verify::identity_seed`)。半端は**多値の `user.email`** で決定的に作る(core.md)。**両方 `must_say` を持つ** — 「save が通らなくて残っているダイアログ」と「まだ誰も答えていないダイアログ」は同じ絵になる
- **`Open repository` のピッカーは開いているリポジトリの隣から始まる**。放っておくと `FolderDialog` は前回受理したフォルダ = そのリポジトリ自身の中から開き、そこは**開くものが 1 つも無い唯一の場所**(次のリポジトリは必ず 1 つ上に居る)。`RepoTab.pickerFolderUrl` が workdir の親を `file:` URL にして持ち(`urlpath::picker_folder_url`。`#` / `?` を含む名前で URL が切れないよう percent encode する。**ルートに在るリポジトリはそのルート自身**を返す — 上が無い時に空を返すと「前回どこかで置き去りにされたフォルダ」へ落ちる)、**入口 3 つ**(メニュー行 / `+` ボタン / 空ページのボタン)は全て `Main.openRepositoryPicker()` を通って `currentFolder` へ入れてから開く。**バインディングにしない** — ダイアログは人が移動する度に自分で `currentFolder` を書くので、押した瞬間に 1 度だけ入れる。タブが 1 つも無い時は入れない(比べる相手が居ないので Qt の既定に任せる)。ヘッドレスは `PG_AUTO_ACT=open-picker`
- **ピッカーが受理したフォルダは、開けると分かってからタブになる**(規約 §リポジトリを開く)。`TabsModel.openPickedPath` → `Hub::probe_repo` が `repo::open` を撃ち、答えを `Feed<PickMsg>` で戻してから `open_tab` する。**開けなかったフォルダはタブを作らない** = グラフを描かないことが構造で保証され、`state.toml` の tabs にも入らない。**タブを先に作って消す形にしない**(答えは 30〜36ms で返るので、タブが 1〜2 フレーム点滅する)
- **開けなかった時の置き場所は「どの道で来たか」、文言は種別が決める**(規約 §リポジトリを開く。3 × 2 = 6 通り)。ダイアログ(`OpenFailedDialog`)はピッカー経由の 1 経路だけが開き、**復元タブ / worktree 行 / `PG_AUTO_OPEN` は今まで通りページの中の画面**(人が今選んだ結果ではないものに、起動直後のモーダルを出さない)。**文言は `Words.openFailure(kind)` の 1 か所**を両方の画面が読む
- **種別は core が返す**(`GitError::NotARepository { bare }` → `plain` / `bare`、それ以外は `other`)。**git の文言を読んで分岐しない**。`bare` の判定は**失敗した時だけ** `rev-parse --is-bare-repository` を 1 本足す(実測 33ms。成功したフォルダには 1 本も増えない)
- **失敗した時のパスは `SessionEvent::OpenFailed` が運ぶ**(`GitError` から取らない)。パスを持つエラー型と持たない型があり、`TimedOut` で空になって**3 つ目の画面だけフォルダを名乗れなかった**実績がある。セッションは「何を開けと言われたか」を知っているので、git が何を答えても埋まる
- **失敗の画面はペインの席に置く**(`RepoPage` の縦 `SplitView` の中)。ページ全体を覆う形だと**コマンドログがその覆いの内側**に居て、`>_` を押しても何も起きなかった(実測)。**ログは自分から開かない** — 開く時の `rev-parse` は背景読みなので、空のパネルが立つ(実測)
- ヘッドレスは 7 動詞: `open-not-a-repo` / `open-bare`(ダイアログの 2 種)/ `open-not-a-repo-retry` / `open-not-a-repo-cancel`(出口 2 つ。前者は既存の `picker folder=` が**失敗フォルダの親**を名乗るかで読む)/ `open-fail-tab` / `open-fail-tab-bare` / `open-fail-tab-log`(タブ側の 2 種と、`>_` が届くこと)。報告行は `open_failed kind= dialog= tabs= active= near=` と `open_fail_tab tabs= state= kind= commands=` で、**`dialog=` / `commands=` はどちらもその窓自身の可視性**(頼んだ側を報告するとバインディングが切れていても緑になる)。**`tabs=` が「開けなかったフォルダはタブにならない」の答え**。**3 つ目(`other`)はアプリから作れない** — 起こせるのは実質 10 秒のタイムアウトだけなので、撮る時は `repo::open` が `TimedOut` を返す**使い捨てパッチ**(コミットしない)を当てる
- **fetch の調子は fetch ボタンだけが語る**(規約 §リモートから取り込む)。ツールバーに別のインジケータを置かない(`↻` は削除済み)。`RepoTab.fetchFailures` が**連続して失敗した fetch**を数え(手動・タイマーの区別なし。`fetch_settled`)、1〜2 回で `warning` の枠 + 語の後ろに `!`(`ActionButton.alert`)、3 回で `RepoSession::suspend_auto_fetch()` がタイマーを止めて `danger` + `Resume` の長押しボタンになる。**止めるタイマーが無ければ赤へ行かない**(`suspend_auto_fetch` の戻り値がその判定 — 設定で off のリポジトリは黄のまま)。長押しは `resume_auto_fetch()` = 覚えている間隔でタイマーを戻し、即 1 回 fetch。**成功はどちらの経路でも数を 0 に戻す**。**コマンドログを開くのは連続の 1 回目だけ**(`fetchFirstFailed` シグナル)
- **push が拒まれたら push ボタンも黄 + `!` になる**(規約 §リモートへ送る)。fetch の 1〜2 回失敗と同じ形(`warned` → `tone` / `toneDim` / `frameColor`、`alert`)で、**赤に当たる段は無い**(止められる自動の仕掛けが無い)。**憶えるのは `RepoPage` で、押したブランチ単位**(`pushSentBranch` → `pushFailBranch` / `pushFailReason` → `pushFailed` が `workTree.branch` と突き合わせる)。**送る時に埋める枠が「この答えは自分のものか」の判定を兼ねる** — 答えの `lastWriteOp` は `push` としか言わず、**リモートブランチの改名と削除も同じ名前で返る**(`session` の `write("push", …)` が 4 か所)。消えるのは**同じブランチへの push が通った時だけ**。ヘッドレスは `push`(届かないリモートへ)と `push-retry`(実際の非早送り拒否 → force で着地。報告行 `push_retry refused=` が消える側を言う — 消えた後の絵には写らないため)
- **fetch と push は 1 つの箱を共有する**(`TopBar.widestAction` + `widestActionCode`)。隣り合っていて互いに関係なく語が変わるので、共有しないと片方の状態変化がもう片方を横へずらす。**バインディングにせず `Component.onCompleted` で 1 度だけ決める** — 4 つの計測を読んで 2 つのボタン幅へ入る式はエンジンにはループに見える(実測)。**候補は `TextMetrics` でなく非表示の `Label` で測る**(`TopBar.Widest`)— 幅を決める箱は `ActionButton` 側の Label で、TextMetrics はそれより数 px 詰まる。等幅と通常表記が混ざる今、「片方の物差しで勝った候補が、もう片方の物差しでは負ける」が起こりうる
- **コマンドログの `>_` は箱を隣から借りる**(規約 §ウィンドウの縁「その 3 つは 1 つの箱の高さに揃える」)。`commandsToggle` は `Rectangle` なので自分では padding を持たず、**トークンで組むと `spaceXl` × `iconLg` = 24×20** = 両隣(92×32)より一段低い的が 2 つの間に挟まった(2026-08-10 に「他より小さい」として報告)。高さは **`fetchButton.implicitHeight` をそのまま**取り、幅は **`commandsMark.implicitWidth` + `fetchButton.leftPadding` / `rightPadding`** = 28×32。**近い値を書き写さない** — 帯のボタンの高さは Fusion の `padding: 6` が決めていて表に無く、写した数は隣が動いた時に黙って 1px ずれる。**高さは「借りる」・幅は「同じ padding を払う」**と非対称なのが正: 3 つが同じ線に乗るには高さが**一致**していなければならないが、幅は語を持たない印に合わせる方で、**印の席(`ActionButton` の `seat` = 24)は借りない** — あれは印と長押しの印を並べるための席で padding ではない(`besideWord` が同じ理由でそれを返している)。**`Layout.alignment` を書いていない子は帯の高さへ伸びない**(実測: `RowLayout` は cross 軸で implicit の高さのまま置く)ので、箱の高さがそのまま的の高さ
- **その `>_` が赤くなる元は 2 つあり、`Clear` は両方を空にする**(`CommandsPane.clearPanel()` = `commandsModel.clear()` + `errorCleared()`)。`commandsToggle.wrong` は `log.failed`(行)**か** `pageTab.lastError !== ""`(ヘッダの 1 行)で、**後者は次の成功では下りない**(例外は fetch が書いた行 — 次の fetch-recover の項)— 規約 §git が言ったことを読む場所「次の成功で閉じない = 読む前に消える」の裏返しで、**下ろせるのは読んだ人だけ**(その道が 2 つ = 行をクリック / `Clear`)。行だけ消していた頃は**空のパネルの上に赤い `>_` が残り**、画面にそれを説明するものが 1 つも無かった(2026-08-10 報告)。**押す道は `clearPanel()` の 1 つ**にまとめ、ボタンとヘッドレスが同じ所を通る。ヘッドレスは **`commands-clear`**(`--allow-write-failure` が要る = 見せ物は拒否そのもの)で、**この動詞だけ `Main` に居る** — 答えは帯の印で、ページからは帯が見えないため(`TopBar.commandsWrong` / `commandsMarkColor` と `RepoPage.clearCommandLog()` がその両端)。報告行 `commands_clear was= wrong= mark= open=` は**同じ印を押す前と後で読む**(`was=true` が無いと、拒否が着かなかった run の休息状態がそのまま緑になる)
- **fetch の失敗がヘッダに立てた 1 行(とその赤)は、後続の fetch 成功が自動で下ろす**(手動・タイマーの別なし。`RepoTab.last_error_from_fetch` — `fetch_settled` の成功枝と `resume_auto_fetch` は**この印が立っている時だけ** `lastError` を空にし、背景読み(`OpError`)が書いた行は印が無いので残る = 「下ろせるのは読んだ人だけ」はそちらに残る)。fetch のエラー行は履歴ではなく**状態** — 規約 §リモートから取り込む「成功が 1 回入れば数は 0 に戻る(でなければ押して通ったボタンが前回失敗を出し続ける)」の帯側で、回復後も赤い `>_` が残るのは同じ誤報(2026-08-11 報告: スリープでネットワークが落ちた auto fetch の赤が、回復後も Clear まで残った — この時ログ本体は 0 件で、赤を説明するものはヘッダの古い 1 行だけ)。**連続失敗の 1 回目が行を立ててパネルを 1 度だけ開くのは従来どおり**(fetch ボタンは調子の 3 状態を語り、ログは git の言葉を読ませる場所 — 二重の語りではない)。**ログ本体の失敗行は退かせない**(履歴は読者のもの)。ヘッドレスは **`fetch-recover`**(仕込み不要・`--allow-write-failure`。報告行 `fetch_recover was= hadline= wrong= line= failures=` を成功の前後で対で読む — 絵は退いた後しか持てないため)
- **箱の余りはボタン自身の余白へ分ける**(`ActionButton.slack` → `leftPadding` / `rightPadding`。規約 §リモートから取り込む)。**ラベルの席は自分の幅に戻す**(`Layout.preferredWidth: btnLabel.implicitWidth`)— 余りを席が抱えていると全部が語の後ろに落ち、ホバーの重ね色・警告の枠・長押しの塗りが最後の字よりずっと右まで届く(実測 Windows: 印の手前 10px 対 語の後ろ 29px。Ubuntu は 10 対 33)。**幅は 1px も動かない**(片端が取った分をもう片端が出す)ので、`widestAction` の共有も右端の据わりもそのまま。**後ろ側は「残り」で取る**(`slack - headAir`。`floor` と `ceil` を並べると端数の語で対が 1px 太る)= 端数は `!` が枠から離れる側へ行く。**チップと `!` は席の座標のままでよい**(どちらも `btnLabel.implicitWidth` から測っており、席が語の幅になったので語に付いて動く)。**語だけを箱の中で中央寄せにする案は不採用** — 印が置き去りになって語との間が 18px = 隣のボタンまでの距離とほぼ同じになり、印と語が 1 つの句に見えなくなる(実測して差し替え)。`widestText` を渡さないボタン(`box === 0`)には余りが無いので当たらない
- **割るのはインクの前後**(`ActionButton.headInk` / `tailInk` を引いてから半分)。印は席の中で中央に立ち(席は印と長押しの印を並べる幅なので `(implicitWidth − step) / 2` が余る)、コードのチップは地が語より半ギャップ張り出す。引かずに行を中央へ置くと**印の手前 22px 対 語の後ろ 17px** で、引くと **17 対 18**(実測 Windows)。**`box === 0` のボタンには当たらない** — 分ける余りが無い上、そこで引くとアプリ中の全ボタンの余白が 2px 動く。**分数の印(`seat.paired`)だけは印が席の左端から始まる**ので `headInk` の 4px が余分に効き、`push -f` は 5 対 10 になる(実測。対の他 3 状態が正しい側なので現状維持)
- **`box` は最長のインク幅そのもの**(`widest.implicitWidth`。通常表記の時だけ足していた末尾 1 ギャップは廃止)。**足していた頃は 1px の勝敗が 5px の幅差**になり、UI フォントが `Yu Gothic UI` へ変わって(`671b30d`)`Resume`(53)が `push -f`(52)を抜いた瞬間、対が黙って **92px → 97px** に育っていた(2026-08-10 に一時パッチで実測。`36424f7` が「92px」と書いたまま誰も測り直していなかった)。**今は両 OS とも 93px**(Windows は箱 53、Ubuntu は 52.2 で 92.2 → 整数化して 93)。額縁までの空きは padding 側が持つ
- **ツールバーの fetch / push はコード表記**(`ActionButton.code` = 等幅 + `bgHover` の地。規約 §git 用語のコード表記)。`AppMenuItem.code` は文の頭に付くチップだが、こちらは**ラベル自体がコマンド**なので `text` がそのままチップになる(`qsTr()` を通さない — 翻訳しないため)。**チップの地は語の実幅だけ**(`btnLabel.implicitWidth` に張り出し半ギャップ)で、共有の箱いっぱいには広げない。**チップの語間は `font.wordSpacing: -Theme.spaceXs`**(`AppMenuItem` 側も同じ — `push --delete` が 2 語に割れる)。**測る側の Label にも同じ wordSpacing を付ける**(`TopBar.Widest` / `ActionButton` の隠し Label)— 付け忘れると箱だけ 4px 広いままになる。**共有の箱に末尾のギャップは足さない**(`ActionButton.box` = 最長のインク幅。かつては通常表記の時だけ 1 ギャップ足していた — 上の項が経緯と実測)。額縁までの余白として目が測るのはチップの端で、その地は既に半ギャップ張り出しているので、必要な空きは padding 側が両端で持つ。**フラグのダッシュは `Rectangle` で引く**(`ActionButton` が `text` を最初の ` -` で割り、`splitFlag` / `head` / `dashCount` / `flagRest`。規約 §git 用語のコード表記)— **字の差し替えでは 1px も縮まない**(U+002D / 2010 / 2011 / 2212 が全部同じ 7px。Cascadia Mono 実測)ので、`push -f` + `!` が枠に乗る(実測 1px)問題はこれで解く。**箱を広げて席を空ける手は不採用**(全状態ぶん要るので対で 16px 太る)。**測る側の隠し Label は font のまま** = 箱は動かず、縮むのはインクだけ(56px → 53px)。**`!` の位置は語の送り幅の末尾**(チップの地の端から 3px)で、**`splitFlag` の時だけさらに半ギャップ内側**(同 1px)
- **止まった操作の出口は commit ボタンの直下のカード**(規約 §進行中の操作から出る)。**押して出すのではなく居座り**、ファイル一覧はその分だけ下へ寄る。行は `OpExitRow` = `AppMenuItem` の写し(`MenuItem` は Menu の中でしかレイアウトされない)で、チップ列と印の席をカードが揃える。**ツールバーのバッジは状態だけを言い押せない**。**バッジが名乗るのは 1 つ** — フラグを並べると rebase が pick で止まった時(`CHERRY_PICK_HEAD` が残る)に `REBASING · CHERRY-PICKING` になる。どれが今の操作かは `integrate::InProgress::from_state`(continue / abort が効く先と同じ答え)。**`--skip` / `--quit` を出すかも同じ答えから**(`WorkTreeModel.op_stepping`)で、**進捗の件数で代用しない**(件数を書くのは rebase だけ = step する cherry-pick が merge に見える)。**`--skip` の長押しは状態で出入りする** — 空になって停止した時(conflict 0 + staged 0 + unstaged 0)は失うものが無いのでクリック + `nothing in it`、それ以外は長押し。**`edit` 停止も木がきれいなので、フル interactive rebase を入れる時に判定を作り直す**(P3-確認事項)
- **コミット単体の drop はグラフ行メニューの行で、印は状態で出入りする**(規約 §履歴を合流させる)。行は `drop` のチップだけ(規約 §メニュー「行がコマンドだけで終わることがある」)で、**squash の隣**(どちらもそのコミットの居場所を書き換える)。core は `sequencer::Edit::Drop` で、**プランはその行から始まる**(親は upstream = 書き換えられない)。**`plan_edit` は object name を取る**(`HEAD` のような symbolic name は履歴に見つからず弾かれる)
- **未コミット変更があっても履歴の書き換えは止まらず、何も尋ねない**(規約 §未コミット変更がある状態で履歴を書き換える)。**`squash` / drop も `rebase` onto も同じ 1 本**を通る — app 側に判定は無く、core が素のまま撃ち、git が拒んだら stash → rebase → `pop --index` で回り直す(`session::carry_across_rewrite`。入口の別は `session::Rewrite` の 2 枝だけ)。**専用の表示を持たない**のは switch と同じで、着地は 3 つとも既存の絵になる: きれいに戻る / conflict の付いたファイル行 / **途中で止まったら進行中のバッジと出口カード + 作業は STASHES とグラフの stash 行に残る**。**拒否ではコマンドログが開かない**(core が `answers_by_code()` を付けている)が、**止まった時は開く** — 開けるのは書き込みの答え(`lastWriteError`)の側だから。ヘッドレスは `--preset drop-collides`(戻す時に conflict)/ `--preset drop-stops`(replay が止まる。`drop-commit-go row:2` + `--allow-write-failure`)
- **drop が長押しかクリックかは `repoTab.headReachedElsewhere` の 1 つで決まる**(規約 §履歴を合流させる)。**行ではなくブランチの先端の性質**なので、`RepoPage` は訊かない — session が**refs が動いた refresh と書き込みの後**に答えを押し出し(`session::settle_head_reach`)、メニューが開く時には手元にある。**メニューを開いてから訊く形にしない**(`checkPublish` と違い、答えが `holdMs` を動かすと `AppMenu.holdIndent` が全行を字下げし直す = 手が降りている最中に的が動く)。**行の入口は `page.dropCommit()` の 1 つ**に集め、`onTriggered`(クリック時)と `onHeld`(長押し時)の両方から呼ぶ — `holdMs > 0` の間 `AppMenuItem` はクリックを一切報告しないので、どちらか片方しか走らない。ヘッドレスは `drop-commit` / `drop-commit-go` で、報告行の `hold=` / `reached=` が形を言う(`-go` は出ている方の所作を取る)。**`--preset basic` がクリック側・`--preset diverged` が長押し側**(前者は stash と `v0.3-local` タグが先端に乗っている)
- **判定は core の `reachable` で 2 段**: (1) `a_ref_sits_on_head` = refs の一覧を 1 周する**プロセス 0 個**の判定(`publish_refs` が持っている listing をそのまま使う。タグはここでしか数えない)、(2) 落ちたら `reached_without_branch` の walk(`rev-list --max-count=1 <tip> --not --exclude=<branch> --branches --remotes --glob=refs/stash*`)。**先端とブランチ名は `publish_refs` が `head_hold` に置いた値を読む**ので、walk のために refs や HEAD を読み直さない。コストと不採用の形は [ci/baseline/head-reach-windows-x64.md](../../ci/baseline/head-reach-windows-x64.md)
- **merge / rebase / revert は現在のブランチを文の主語にする**(規約 §履歴を合流させる)。`merge` into \<current\> / `rebase` \<current\> onto it / `revert`、いずれも git 用語のコード表記。**入口が変わっても文は同じ** — ref 行でもクリックした側は言い直さない(規約 §メニュー「行がコマンドだけで終わることがある」)ので、`page.menuRefId` は文に出ない。**入口は左メニューのブランチ行・リモートブランチ行・グラフ行の 3 つ**(merge はタグ行にも、rebase は出さない)。**revert は cherry-pick の隣**。**どれもクリック**(merge / revert は足すだけ・rebase は switch / reset で戻せるローカルの書き換え)。**rebase だけ `<row>..HEAD` の publish を訊いて `rewrites pushed commits` を添える** — `publishRange` は 1 枠の共有なので**自分が訊いた範囲の答えだけを読む**(`RepoPage.rebaseRange`)。**出す条件は reset と同じ形**(ブランチの上・進行中操作なし・行き先が現在地でない)。**rebase が足すフラグは `--update-refs` だけ**で、`RepoTab.rebase` に autostash の引数は無い — 未コミット変更は core の carry が運ぶ(下の項)
- **merge / cherry-pick / revert が着いたら選択と視界がその新しいコミットへ移る**(規約 §履歴を合流させる)。**既にある `pendingHeadSelect` の 3 人目**として `absorbWriteResult` が**3 つまとめて**立てる — 着地は「refs と walk が揃った後の HEAD」で、**書き込みの答えの中で解決しない**(status / refs / walk は別々に届き、先の 2 つはまだ書き込み前の履歴を語る)。**conflict で止まった側には効かない** — `lastWriteError` の早期 return より後ろに置いてあり、そこは commit が 1 つも生まれていないので移る先が無い(着地は今までどおり conflict の付いたファイル行と出口カード)。**何も書かなかった書き込みも着く**(`Already up to date` の merge と、写す先が既に同じ内容を持っている cherry-pick / revert = core.md)。**そこで armed を解くのは `NavSectionModel.refsSettled`** — `publish_refs` は refs が動かなくても `RefsLoaded` を出すが、**モデルの `changed` は同じ行では黙る**(4 万タグのセクションを同じ絵のために建て直さないための最適化)ので、届いたことだけを言う口が別に要る。**残ると armed のまま次に refs が動いた背景更新が視界を動かす**(実測: 空の cherry-pick が `follows=false selected=<写した元> row=1`。**`merge-branch v0.1 --preset basic` はこの穴を通り抜けていた** — 選択が元から先端なので、解決していなくても `follows=true` になる)。**空の cherry-pick の検証はリポジトリを建てる** — `demo-repo diverged --at <dir>` の木に「同じ内容のコミットを両ブランチに 1 つずつ」積み、その oid を `cherry-pick <oid> --repo <dir>` へ渡す(Linux は worktree の中に建てて `--repo /work/<名前>`)。**rebase / `squash` / drop / reword はこの枠に入れない** — あちらは「読んでいたコミットが何になったか」を追う側(`rewordRow` / `followVanishedCommit`)で、先端へ飛ばすと読んでいた場所を失う
- **視界まで動くのは `pendingHeadAsked` が立っている時だけ** — 同じ枠を使う他の 2 つ(端末で誰かがコミットした / poll 中に選択中のコミットが書き換えられた)は**窓に起きたこと**で、背景の更新が読んでいる人の視界を動かしてはならない(§`ListView.highlightFollowsCurrentItem`)。**移す先が画面に在れば動かさない**のは検索の `goToMatch` と同じ規則
- **視界の移動は `GraphPane.showRowSoon()` = `shiftRows` と同じ 1 本のタイマに載る**。2 つは同じ `contentY` を逆の理由で書き(片方は読んでいた行を留める・片方は新しい行へ連れて行く)、**「その行が画面に在るか」は shift が置いた後の位置についてしか真でない** — 別のタイマにすると同じ `anchorDelayMs` で発火順に賭けることになる。**`activateRow` の後に頼む**(未保存メッセージの質問が移動を留めた時 = `pendingMove !== null` は、質問が選択を元へ戻しているので視界に行き先が無い)
- **ヘッドレスは 3 動詞が 1 本の報告行を共有する**(`revert-commit` / `cherry-pick` / `merge-branch` → `tip_landed follows= onscreen= op= head= selected= row=`。**`follows=` / `onscreen=` の対が `must_say`**)。**グラフ行から入る 2 つは先にその行へ `jumpToRow` する** = 人が「スクロールして見つけて右クリックする」経路そのもの。**判定が空回りしていないことは実測で確かめてある**(条件を revert だけに戻すと `merge-branch` / `cherry-pick` が `follows=false selected=<元の先端> row=1` で落ち、`showRowSoon` を殺すと `onscreen=false` で落ちる)。**merge / cherry-pick は木がきれいで取り込むものがある `--preset diverged` の `origin/main`**(`basic` は木が汚れていて git が cherry-pick を拒む)。**視界の側は背の高い履歴でしか試験にならない**(ペインに収まる履歴では最初から `onscreen=true`)ので、`demo-repo co-authors --at <dir>` に 40 件ほど積んだ木を `--repo` で渡す(**コンテナへ渡す木は `commit.gpgsign` を落とす** — co-authors の preset は Windows の絶対パスで署名鍵を指しており、`/work` から読めない)

- **`WM_NCCALCSIZE` を横取りして非クライアントを消す手は採れない**(実測)。サブクラスは **Qt のウィンドウプロシージャの手前**に座るので Qt がそのメッセージを見ず、窓を作った時のフレーム余白を持ち続ける = クライアントだけ広がってシーンが追わない(右と下が黒くなる)。**採れないのは「Qt が答えから状態を組み立てるメッセージ」**で、純粋な問い合わせ(下の `WM_NCHITTEST`)は横取りしてよい — 区別はそこに引く
- **merged chrome では `WM_NCHITTEST` をサブクラスが全点で答える**(`winframe::take_frame_hit_test` / `hit_test`。リサイズ縁 → HT 各種、掴み代の矩形 → `HTCAPTION`、残り全部 → `HTCLIENT`)。**Qt 6.10 に任せてはならない**: `ExpandedClientAreaHint` + `CustomizeWindowHint`(タイトル要素なし)の `handleNonClientHitTest` は、**NCHITTEST のたびに `GetAsyncKeyState` をポーリングし、`static` 1 個とのエッジ検出で合成 press / release をシーンへ同期配信**し、accept されなければ帯の高さ以内を `HTCAPTION` と答える(qwindowswindow.cpp)。press と release の片方を別の窓が受けるとその static が脱調し、**幽霊 press がシーンに残る** — 次の実クリックが caption 扱いで飲まれ(実測ログ: 死んだクリックの `WM_MOUSEACTIVATE` が hit=HTCAPTION)、幽霊 grab が hover を 1 つの item に固定する(= 「タブの 1 回目が効かない」「hover の色が残る・追わなくなる」の正体)。**`PostMessage` の合成クリックは `GetAsyncKeyState` を動かさない**ので、この病気はヘッドレス・自動化では一切再現しない — 実マウスだけが踏む
- **右端はクライアント領域の端に密着させない**(`spaceXs`)。クライアントは可視ウィンドウより外へ出ており(実測 4.5px)、密着させると窓ボタンの hover が切れて見える
- **窓 = クライアント = 描画領域**(frameless。実測 2026-08-09: 最大化で窓・クライアント・作業領域が揃って `0,0..1920,1032`)。**中身を内側へ寄せない** — `mainUi` は `anchors.margins` を持たず `anchors.topMargin: -root.contentItem.y` だけ。**寄せた実績がある**: 枠のあった頃「最大化した窓は画面より大きいから帯が画面外に出る」という推測から `maximizedInset` = 8 を入れ、**中身が左から 8px 寄り右が 8px 足りない**とその場で報告された。**その推測自体も誤りだった** — 枠付きでもフレーム(1936×1048)だけが大きく、**クライアントは作業領域と 1px も違わなかった**。**QML 側からはこの数を出せない**: `Screen.desktopAvailableWidth` は仮想デスクトップ全体(実測: 1920×3 台で 5760)、`Screen.width` は縦置きタスクバーで負に転び、`root.width` はフレーム幅を名乗らない(`widthSlop`)。metrics(`SM_CXSIZEFRAME + SM_CXPADDEDBORDER`)から採っても誤りで、**正しい数は最初から 0** だった。ヘッドレスは **`window-fill`**(最大化 → 申告 → windowed に戻して撮影。報告行 `window_fill fills= maximized= at= size= window=` の **`fills=true` が合格条件**(`Outcome::must_say`)で、**中身の scene 座標と窓の寸法を突き合わせる** — 頼んだ margin ではなく着地を読む。両 OS 同じ答え。**絵では読めない**(最大化した窓は画面いっぱいで、端の不足を見せる相手が隣に無い)。実測: 8px 寄せた版は `at=8,8 size=780x780 window=796x796` で FAIL / frameless は `at=0,0 size=800x800` = 枠が無いぶん offscreen の 796 が 800 になった)
- **最大化の矩形はサブクラスが作業領域に固定する**(`winframe::clamp_maximized` = `WM_GETMINMAXINFO` の `ptMaxSize` / `ptMaxPosition`。**先に `DefSubclassProc` へ通してから**その 2 つだけ書き換える)。放っておくと Windows は frameless の窓を**モニタ全体**に最大化する。**`IsZoomed` はもう判定に使えない** — Qt が frameless の窓を最大化サイズに置いても zoomed にはならない(実測)ので、リサイズ縁を出すかは `fills_work_area`(窓矩形が作業領域を覆っているか)で決める。**これを使わないと最大化中の上端 8px = タブ行と窓ボタンがリサイズ縁に化ける**
- **最小化中の窓は何も申告しない**(`Main.reportState` の `visibility !== Window.Minimized`)。実測 2026-08-09(Windows / 実窓): 下りている間の窓は**窓の姿でも最大化の姿でもない数字**を名乗り(1920×1032 の作業領域で最大化していた窓が `1926×1032 at -3,3`)、`visibility` は Maximized ではなくなる。**2 秒のタイマは下りている窓にも回る**ので、これを書き込むと**画面より広い窓が「最大化していない前回の形」としてファイルに残り**、最大化フラグも降りる = 次回起動が画面外へはみ出す(報告 2026-08-09。実際に `dev-graph-cursor/state.toml` が `1926×1032 maximized=false` を持っていた)。ヘッドレスは **`state minimize`**(最大化 → 申告 → 最小化 → 申告 の順に走り、報告行の `windowMax=` / `windowW=` が**ファイルの側**を言う。**最大化を先に 1 度書き込むのが要**で、書き込まないと 2 度目の申告に「守るもの」が無く、修正の有無に関わらず緑になる)
- **窓が名乗る寸法は、窓に渡した寸法と一致しない**(`Main.widthSlop` / `heightSlop`)。実測 2026-08-09: merged chrome で 1200 を渡すと**クライアントは 1200・フレームは 1216** になるのに窓は自分を **1206** と呼ぶ(縦は一致)。読みと書きで Qt の使うフレーム余白が違うためで、**そのまま書き戻すと起動のたびに 6px ずつ広がる**(実測: 1200 → 1206 → 1212 → 1218 → 1224。ユーザーの実ファイルも 1926 → 1950 まで育っていた)。**差は窓自身から測って引く** — `applySavedWindow` が渡した寸法を憶え、`Metrics.anchorDelayMs` 後に読み直した差が slop(**答えは代入の中ではなくキュー越しに返る**ので 1 拍要る)。**測るのは起動直後の windowed だけ**: 最大化で上がった run は画面の寸法を名乗るので測らず、後から下ろした瞬間も測らない(半画面スナップは寸法ごと変える = そこで読んだ差はフレーム余白ではない)。その run は終わり方次第で 6px 1 回ぶん広く残るが、**次の起動が windowed で測って止める**
- **寸法を収めるだけでは足りない — 最後にフレームごと作業領域へ入れ直す**(`AppBackend.fitWindowToScreen` → `winframe::fit_to_work_area`。`applySavedWindow` の末尾で 1 回・**最大化中の窓は触らない**)。**QML では判定できない**: 収まるべきは窓が名乗る寸法ではなく**フレーム**(1920 を渡すとフレームは 1936)で、作業領域は QML がどの画面についても出さない。実測 2026-08-09: 汚染された `1920×1009 at 0,23` が **frame -5..1931**(0..1920 のモニタ)になり、**右ペインのスクロールバーが画面外**・左端が隣のモニタ = 報告 2 件の正体。修正後は `window = 0,15..1920,1032`(frame inside work area)で、**書き戻しで `state.toml` 自身も治る**(`width 1910 x 5 y 18`)。**縮めるのは作業領域までで、あとは動かして収める**(右へずれているだけの窓に要るのは角を戻すことで、小さくすることではない)。**動かした run では frame slop を測らない** — `settleTimer` は「渡した寸法と名乗る寸法の差」を読むので、間に再配置が入るとその差ではなくなる(次の起動が測る)。**汚染の出所**は「最大化中の窓の数字が windowed の形として書かれる」経路で、`applySavedWindow` がそれを maximize の前に窓へ入れるため **Windows の復元先矩形になって自己増殖する**
- **前回の形は画面の中へ収めてから戻す**(`Main.insideScreen`。上の入れ直しの手前で効く粗い方 = 3OS 共通の歯止め)。**比べる相手は `Screen.width` / `Screen.height`**(その窓が居る画面)で、`desktopAvailableWidth` ではない(上記のとおり仮想デスクトップ全体)。**畳むのは人が見ている窓だけ** — `AppBackend.automated`(= core の `Env::automated`。`PG_CONFIG_DIR` / `PG_LOG` / `PG_ALLOW_GUI` 以外の `PG_*` が 1 つでも立っていれば真)が立っている run は**渡された寸法のまま**にする。**`verify-ui` は必ず `PG_CONFIG_DIR` を渡す**ので「ファイルを持っているか」では分けられず、**offscreen の画面は 800×800**(実測)なので分け損ねると**全スクリーンショットが 800 幅に化ける**。この 1 本で、既に壊れた値を持つ `state.toml` も**次の起動で自分で直る**(実測: 1950 → 1920 = フレーム 1936 が画面の端にちょうど収まる)
- **窓は自分の床を名乗り、床を割る大きさを自分で撥ね返す**(規約 §窓の床)。**Qt Quick は床を上へ渡さない** — widget の窓なら子の `minimumSizeHint` が窓の下限になるが、`SplitView` と `Layout` は下限で縮むのをやめて**残りを自分の右端の外へ並べる**(実測: 窓幅 640 で右ペインは 32px しか画面に無く、900 でも 8px 欠ける)。**`minimumWidth` / `minimumHeight` は半分にしかならない** — 人が縁をドラッグする経路しか通らず、**`QWindow::resize` はサイズヒントを一切見ない**(実測: 床より小さい 200×150 を代入したら窓はそれを取った)。だから**アプリが自分で置く大きさは全部 `Main.holdFloor()` を通す**(復元した形 = `applySavedWindow` の `Math.max` と、動く床 = `onFloorWidthChanged` / `onFloorHeightChanged`)
- **床は 2 か所が計算して `Main` が大きい方を取る**: `TopBar.floorWidth` = **`bandRow.implicitWidth` + 右余白**(足し算を書かない = 帯にコントロールが 1 つ増えても数え漏らさない。そのために `tabStrip` に `implicitWidth` を持たせる — `fillWidth` なので**レイアウトの挙動は 1px も変わらず**、帯が「自分はいくら要るか」を言えるようになるだけ)/ `RepoPage.floorWidth` = 左(畳みで `railWidth` か 180)+ 仕切り + `centreMinWidth` + 仕切り + 300。**実測 824×245**(畳むと 688)。どちらが勝つかは中身次第なので、片方だけ見ていると足りない
- **床を読む相手は `curPage` ではなく `Main.floorPage`**(タブが 0 枚の時は空ページの `Loader.item`)。`curPage` は「タブのページ」なので**タブが無い窓では null** だが、窓は空ではなく**同じ 3 ペインの空ページ**を出しており、そのままだと**空ページの窓だけ帯の床まで縮められる**。ヘッドレスは `window-floor --restore`(空の `--config-dir`)で、報告行の **`tabs=0` でも `floorW=824`** が答え
- **`holdFloor` が窓を広げたら `askedWidth` / `askedHeight` も更新する** — しないと**その成長が frame slop として測られ**(`settleTimer` は「渡した寸法と名乗る寸法の差」を読む)、`reportState` がその分だけ小さい形をファイルへ書く(実測: 床に立った窓が 510 と記録された)
- **中央ペインの下限は数ではなく式**(`RepoPage.centreMinWidth` = `max(GraphPane.contentMinW, sidebarPane.minOpenWidth)` = 実測 336)。**詰むのはレーン列だけ**(`graphColWMax`。元からある挙動)で、**チップ列は窓に合わせて詰めない** — 一度そうして 3 つの症状で取り消した(規約 §窓の床): チップより狭い列は**チップを潰して描く**・**左メニューの畳みだけで列幅が動く**・そもそも床がこの列の幅を確保している。**`labelWManual`(手がドラッグした列)だけは `labelColWMax` で抑える** — そこは幅を決めた人が居る列で、抑えないと窓を狭めた時に message 列が消える
- **コマンドログの高さは `preferredHeight` を書き留める**(`RepoPage.reportLayout`)。laid-out の `height` を書くと、**短い窓で開いた 1 回が憶えている高さを食う**(実測: 窓 420 で開いたら 280 → 168 になり、以後の起動が全部その 168 から始まった)。ドラッグは `SplitView` が同じ `preferredHeight` を書き換えるので、手が置いた値はこちらに在る
- **メッセージの枠はホイールを自分で取り、端で外へ渡す**(規約 §窓の床)。`DescriptionBox.rollBy` が自分の本文を動かし、動かせなければ `wheelPastEnd(pixels)` をペインへ上げて `rollBlock` がブロックを動かす(summary は枠がコンポーネントでないのでペイン側の `rollSummary` が同じ 2 段を書く)。**渡す量は「本文が進みたかった距離」= px** で、受け側は `contentY - pixels` — **足すと逆へ動く**(上へ回すと下がる。2026-08-09 報告の半分がこれ)。**`ScrollView` の中の `Flickable` は `interactive: false` にする** — handler と flickable が**同じホイールを 2 回処理**し、handler の跳びの後に flickable 自身のアニメーションが別の場所へ落ち着くので「一瞬上へ行って引き戻される」に見える(残り半分)。`event.accepted = false` で Qt に流させる形は採らない(**ホイールは注入できない = ヘッドレスで証明できない**ので、伝播規則に賭けない)
- **右ペインの 2 つの姿は、帯と一覧の間を `Flickable` で包む**(規約 §窓の床)。`WipPane` / `DetailsPane` とも `blockScroll` + `blockCol` の対で、**`Layout.preferredHeight` は `Math.min(blockCol.implicitHeight, blockRoom)`**(`blockRoom` = ペイン高 − 上の帯 − (`CHANGES` の帯) − 2 行)。**`descOwed` / `blockScrolls` は `blockRoom` と比べる** — **並べ終わった `blockScroll.height` と比べると輪になる**(枠が伸びる → `implicitHeight` が伸びる → まだ前フレームの高さと比べて「その差を返せ」→ 取った分を全部返す。実測: `wip-grow` が `cap=120 rows=25` = 掴みが 1px も効かない状態で緑になった。正しい形は `cap=667 rows=2`)。**`descKeeps` は `!blockScrolls`** に畳んである(枠が返し切ったか = 下に隠れたものが無いか、は同じ問い)
- **ヘッドレスは `window-floor` の 4 形**(`wip` が加わる)。`window-floor wip` は右ペインを WIP に切り替えて床へ降ろし、報告行の **`wipScrolls=true`** が「出口カードは下にあるが届く」を言う(スクロールバーは PNG に写るが、写ったバーがどの面のものかは絵では言えない)。**`details_fit` には `overH=` / `paneH=` が乗っている**(判定には入れない = `window_fill` の `edge=` と同じ扱い。窓の高さ次第の値なので、この動詞の合否にはできない)。**詳細ペイン側の壁は `--preset edges` の行 7 を床の窓で開く**(`--config-dir` に床より小さい形を仕込む — 起動が床まで持ち上げる。実測 `overH=160` → 包んだ後 `overH=0`)
- **`window-floor` の形**(引数なし / `fold` / `log` / `wip`)。**引数なしは xtask が `state.toml` に 320×240 を仕込んでから起動する** — 「床が無かった頃のファイル」はアプリ自身には作れない(アプリは自分が取れない形を書かないため)。`fold` は畳んだ床へ降ろしてから一覧を戻し、`log` は panes だけの床へ降ろしてからログを開く = **どちらも「立っている窓の下で床が上がる」**。報告行 `window_floor fits= floorW= floorH= w= h= from= folded= log=` で、**`fits=true` が合格条件**(`Outcome::must_say`)・**`from=` が「一度は降ろした」の証拠**(無いと `fold` は最初から広かった run と見分けが付かない)
- **帯の状態バッジは 3 つまで同時に立ち、その分だけ窓の床が上がる**(規約 §窓の床)。進行中の操作(`opBadge`)/ `CONFLICTS` / `SET IDENTITY` はどれも `Layout.fillWidth` を書いていない = 縮まない箱なので、`TopBar.floorWidth`(= `bandRow.implicitWidth` + 右余白)がそのまま伸び、`onFloorWidthChanged` → `holdFloor()` が窓を押し戻す。**足し算を書いていないので、この 3 つは誰も数え直さずに床へ入る**(帯にコントロールが 1 つ増えた時と同じ)。**当たるのは Windows だけ** — 掴み代 `railWidth` × 2 と窓ボタン 3 つを払う帯は **824 → 900** になるが、merged chrome を持たない Linux / mac は帯の床が **662** 止まりでページの床 824 が勝つ(実測 2026-08-11)。**タブは先に縮むので床を動かさない**(3 タブでも 900)。**バッジ側に省略や畳みを入れない** — 読めない帯になるか、押せる 3 つ(`>_` / fetch / push)を押し出すかのどちらかにしかならない
- **ヘッドレスは `badges`**(引数なし = 普通の窓 / `floor` = そこから床へ降ろす。**`--preset cherry-pick-conflict` が要る**)。**3 つ目は identity なので隔離が要る** — xtask の `identity_seed` が空の設定を渡し、`identity_answer` が `PG_AUTO_IDENTITY=skip` を渡してダイアログを `Not now` で閉じる(`identity` 系と同じ隔離 = この機械の設定を読まない。**引数は窓の形なので、打ち込む名前と席を分けてある**)。報告行 `badges fits= op= conflicts= identity= bandW= floorW= w=` の **`fits=` と 3 つの `true` が揃って合格条件**(`Outcome::must_say`)— **1 つ立たなかった run の絵は、3 つを捌いた絵と同じに見える**。`op=` / `conflicts=` は `TopBar` が**バッジ自身の `visible`** を読む(頼んだ側を報告するとバインディングが切れていても緑になる)
- **掴む所作はプラットフォームの正規経路**: QML はハンドラを持たず、**掴み代の位置を報告するだけ**(`TopBar.captionStripMoved` → `Main.reportCaptionStrip` → `AppBackend.setCaptionStrip`。scene 座標の論理 px で渡し、DPI はサブクラスが hit test ごとに掛ける)。その矩形を hit test が `HTCAPTION` と答えるので、ドラッグ・スナップ・ダブルクリック最大化・右クリックの窓メニュー(サブクラスの `WM_NCRBUTTONUP` → `open_system_menu`)は全部 OS の title bar そのもの。**押下はシーンに一切届かない** = QML 側に DragHandler / TapHandler を書き戻さない(`startSystemMove` 方式は Qt の hit test を生かしたまま = 上の病気ごと生かすことになる)。報告の再送は 3 つ: 掴み代自身の x / width、`Main` の width、`maximizedInset`。**掴める空きは `railWidth` × 2 を必ず残す**(`tabs.grabRun`)— タブが伸びて消える空きは掴もうと思える場所ではない
- **兼ねるかはプラットフォームの名指し**(`Main.captionMerged`)。窓の生成時に読まれる設定なので「効いたか見てから決める」ができない。**`PG_PLAIN_CHROME=1` で兼ねない側の形をこちらから出せる** — mac / Linux を動かせないこの機械では、これが無いと**その形は報告できない人にしか踏まれない**(実際、常設 Search 箱の消し忘れはこの動詞で見つけた)
- **Windows だけのウィンドウ装飾は `winframe.rs` の 1 か所**(規約 §アプリアイコン)。Qt に口が無いものだけを Win32 で直接叩く — **角を丸めない**(`DWMWA_WINDOW_CORNER_PREFERENCE` = `DWMWCP_DONOTROUND`。Windows 11 は既定で丸めて角の外を透過にするので、後ろのウィンドウが透ける)と、**アイコンを着せる**(`WM_SETICON` を small / big の両方へ = タイトルバーとタスクバーのボタンは別の口)。**依存は足さない** — `dwmapi` / `user32` / `kernel32` のシグネチャを `#[link]` + `unsafe extern` で書き、workspace の `unsafe_code = "warn"` はモジュールの `#![expect(…, reason = …)]` で抑える(`undocumented_unsafe_blocks` があるので各ブロックに `// SAFETY:` が要る)。**対象は `EnumThreadWindows` で拾う** — Qt は人が見る 1 枚以外にもウィンドウを持ち、QML から hwnd を取る口が無い。**呼ぶのは `Main.qml` の `Component.onCompleted`**(`visible: true` が既に効いた後。それより早いと着せる相手がまだ居ない)
- **アイコンの PNG は SVG から事前ラスタライズしてコミットする**(`assets/icon-<size>.png` = 16 / 20 / 24 / 32 / 48 / 64。16 と 20 は小サイズ版、24 以上はマスターから — 規約 §アプリアイコン)。**`CreateIconFromResourceEx` は PNG を直接読む**ので `.ico` コンテナもデコーダも要らない。渡す 1 枚は `GetSystemMetrics(SM_CXSMICON / SM_CXICON)` に最も近いものを選ぶ(100% でない画面に引き伸ばさせない)。**exe 自身のリソースアイコン**(エクスプローラ・ピン留め・ショートカットが読む絵 = ファイルから読まれるので、窓が着る方とは別の口)は `build.rs` が渡す。`assets/platitude.rc` が id 1 の `ICON` を宣言し、**コンパイル済みの `platitude.res` をコミットして** `build.rs` が `cargo:rustc-link-arg-bins` で渡す(bins 限定 — テストのバイナリはリソース無しでリンクする)。**リソースコンパイラをビルドの前提にしない** — SDK の `rc.exe` は Windows にしか無く、他 2 OS には使い道が無いので、21KB のファイルを木に置く方を採る。焼き直す手順は `platitude.rc` のコメント。**id 1 は動かさない**(Windows は数値が最小の `ICON` をファイルの絵に使う)。`.ico` は 16〜256 の 8 サイズで、中身は PNG(Vista 以降が読む形式 — BMP へ展開しない)
- **同じ `.res` が exe の表示名も運ぶ**(`VERSIONINFO` の `FileDescription` = `Platitude GG`。規約 §アプリ名 の表示名 = `.desktop` の `Name=` / `Info.plist` の `CFBundleName` と同じ席)。**これが無いとシェルは名前を持たず、ファイル名へ落ちる** — タスクバーの窓メニューが `platitude-gg.exe` と名乗ったのがそれ(2026-08-10 報告)。**`InternalName` / `OriginalFilename` にはスラッグを入れる**(`Exec=` / `CFBundleExecutable` と同じ = 機械が読む側。表示名を入れない)。**版番号は書かない**(Cargo.toml が正本。`.res` はコミット済みなので `Info.plist` の `@VERSION@` に当たる手が使えない — 埋めるのは配布手続き = P5-確認事項 §11)
- **表示名が入ったかを `FileVersionInfo` で確かめない**(PowerShell の `Get-Item .VersionInfo` がそれ)。**このリソースの文字列を全部空で返す**(固定ブロックは読めている = 非ゼロの `FILEVERSION` を焼くと `FileVersionRaw` だけが動く)ので、**入っているものを「入っていない」と読む** — 一度その誤診で「未解決」として棚上げされた。読むのは **Win32 の `VerQueryValue`** と、シェルの 2 つ(`AssocQueryString` / `ASSOCSTR_FRIENDLYAPPNAME` = ジャンプリストが名前を引く経路そのもの、エクスプローラの「ファイルの説明」列)。**`.rc` は ASCII のまま保つ** — `rc.exe` は指示が無ければシステムのコードページで読むので、コメントの非 ASCII 1 バイトが焼く機械によって別物になる
- **2 つ目のプロセスは窓を出して「もう開いている」と言い、それ以外は何もしない**(規約 §アプリ名)。判定は `main` で終わっており(`claim_store`)、UI が読むのは `AppBackend.alreadyRunning` と `heldElsewhere`(= 取れなかったディレクトリ。**2 つのビルドは画面上で他に見分けが付かず**、ジャンプリストの起動エントリはどちらを起動したか言わない)。**追い返された run には空の store を渡す**ので、出て行く前に 1 バイトも書けない。**`Component.onCompleted` は `decorateWindow()` だけ通す** — git も訊かず・タブも開かず・前回の形も戻さない(その形は本物の窓が今着ている)。`stateTimer` と `onClosing` の申告も止める
- **その窓には `Close` ボタンが要る**。帯がタイトルバーを兼ねる形では閉じる手が `mainUi` の中にしかなく、ゲートが出ている間 `mainUi` は不可視。**accent を着せない**(アクセントは押しに来た人のためのもので、ここへは誰も来ていない — 空ページの 1 個ボタンと同じ `borderDefault` の枠)
- **ゲートは自分の地を持ち、`shotTimer` は出ている方を掴む**(`gate.visible ? gate : mainUi`)。ゲートは `mainUi` の**兄弟**なので、これが無いと**ゲートで終わった run が「なれなかったアプリ」を撮る**。ついでに git ゲート(`gitState !== "ok"`)も撮れるようになった(以前は使い捨てパッチが要ると verify-ui スキルに書いてあった側)。ヘッドレスは **`solo`** で、**xtask が本物のロックを握ってからアプリを起動する**(状態を真似るフラグを作らない)。仕込みが効かないと絵は普通の窓になるので、`verify-ui` は `solo blocked=true` を**言ったかどうかも判定に入れる**(`Outcome::must_say`)
- **worktree で建てたビルドは、右下の git バージョンの隣に自分のツリー名を出す**(`git 2.55.0 · labels`。並行セッションはそれぞれ自分の exe を建てるので、窓は他に見分ける手掛かりを持たない)。値は `AppBackend.buildTree` = `env!("CARGO_MANIFEST_DIR")` から `.claude/worktrees/<名前>` を読む**ビルド時の**もの(`models::app_backend::tree_of`)。**環境変数から採らない** — exe は建てたツリーの中に居るので、ビルドパスから採れば印はファイルと一緒に動き、どう起動されても正しい。**素の checkout から建てたビルドには最初から付かない**(= 外の人が作る全ての配布ビルドと本体 checkout)ので、出荷物に開発用の文字列が残らない。**窓のタイトルには出さない — 左上のアプリ名は将来消えるので基準にしない**(2026-08-09 ユーザー指示)。起動時に `build tree tree=` を 1 行ログするので、窓が出ない run でも stderr で判る
- **その隅の文字は、ファイル一覧が届いた時点で退く**(2026-08-10 ユーザー報告 = 一覧と重なっていた)。**ペインで最も淡い文字と、人が今読んでいる行**なので、どちらが譲るかは問いにならない。判定は席が空いているかの 1 つで、**各ペインが自分の一覧を測って `bottomRoom`**(ペイン下端 − 一覧のコンテンツ下端。スクロールした一覧は 0)を出し、ラベルは `roomNeeded`(自分の行 + ぶら下がっている `spaceXs` = **自分の箱そのもの**)と比べるだけ。**上に自前の空気を足さない**(足した版を出したら「余白は要らない」= 2026-08-10 ユーザー報告)— この隅に乗るのは一覧で、行は自分の高さで既に空いている。**worktree のツリー名も同じ 1 つのラベル**なので一緒に退く。**ここは `opacity` ではなく `visible` でよい**(タブの `✕` / identity の印とは違う)— **隠れた `Label` も implicitHeight を保つ**(隠れている間に届いた text も込み。qmltestrunner 実測 2026-08-10)ので、**自分の高さが判定の半分**でも答えが自分の読んだ値を食わない。**`z: 1` は残すが意味が変わった** — 前に出て一覧を上書きするためではなく、退いた後の並び順をこの隅の次の住人に対して保つため。ヘッドレスは **`corner`**(引数はペイン = `wip` か行番号)で、**`--preset basic`(隅まで届かない一覧)と `--preset long`(ペインを超える一覧)を対で読む** — 片側だけでは「常に出る」「常に出ない」と見分けが付かない。**両ペインぶん要る**(WIP と詳細は別々に自分の一覧を測る)ので計 4 run。報告行 `git_corner pane= shown= room= needs=` の **`shown=` はラベル自身の `visible`**(動詞の使い方・引数は verbs.md の `corner` が正)
- **アプリメニュー(ハンバーガー)は `offer()` ではなく `open()` で開く** — 固定行で空になり得ず、`offer()` の中の引数なし `popup()` はポインタ位置に出すため、`y` を決めているメニューの座席が失われる(`TopBar.menuButton`。行の可否で増減する右クリック系は従来どおり `offer()`)
