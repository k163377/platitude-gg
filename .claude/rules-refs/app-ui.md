# platitude-app 各論(意匠決定・実装対応・罠)

[.claude/rules/app-ui.md](../rules/app-ui.md) の参照資料 — **1 項目 1 行**、触る部品名・操作名・動詞名・規約 §名で Grep して該当行と前後だけを読み(全読みしない)、追記も 1 行(「app-ui.md §…」の参照はここへ移った行も指す)。

- **配線済み**: ステージング(ファイル / hunk / 行)・commit / amend・switch(ローカル / リモート。detach する導線を UI に置かない決定 — git が置いた detached HEAD からは普通に動く。未コミット変更は尋ねず持っていく = `session::carry_across`。conflict でも専用表示なし)・fetch(手動 + auto + 開いた時)・push / force push・単体 cherry-pick・単体 squash・merge / rebase / revert の起動・単体 drop・止まった操作の出口・conflict の種別・片側採用・外部ツール連携・conflict の一括解決(バケツの帯)・コミットメッセージ編集・amend での著者引き継ぎ・reset(soft / mixed / hard。hard はサブメニュー行の長押し = stash 削除と同じ意匠)・stash push(全体 / 1 パス)・discard / clean・identity・署名の表示(規約 §署名の表示)・設定(auto fetch 間隔)・diff プレビュー(`platitude-core::preview`)・コマンドログ・初回 push・Ctrl+F のコミット検索(アドバンス検索は未着手)・上下矢印でのコミット送り・diff の上下送り・diff のファイル一覧の送り(PageUp/Down・Home/End は未配線)・読んでいるファイルの光・stash の Apply / Pop・ブランチ / タグ / stash / リモートブランチの改名と削除・タグのリモート状態バッジ・co-author の表示・著者のアバター・設定 / 画面状態の永続化・改行コードの警告・git の版(無ければ全画面のゲート / 最低バージョン未満は `OLD GIT` バッジ)・diff のシンタックスハイライト(個々の意匠・実装対応は下の各項)。**この一覧が配線済み操作の正本**(CLAUDE.md は未配線だけを持つ。配線したらこの行へ足す)

- グラフの未コミット行の集計(`Tally`)は status から数える(規約 §未コミット行が名乗るもの)。決定: 行数でなくファイル数 — 行数(`+N -M`)は `diff --numstat HEAD` が 1 本増えるが、ファイル数は手元の status の文字で足りる
- チェックボックスは `AppCheckBox` の 1 か所(素の `CheckBox` を使わない。規約 §QML 実装ルール)— Fusion の indicator は面が `palette.base` = 後ろのペインと同じ色・枠がその地をさらに暗くした色で、この地では箱が消える(未チェックは語の前が空白・チェック時は印が宙に浮く)。`implicitHeight` は `controlHeight` を既定に持つので呼び出し側で書かない(band に乗る `Background reads` だけが `iconLg` に落とす)。ヘッドレスは `amend-author`(2 つ並ぶ唯一の席)/ `remote-url origin:marked` / `commands`
- 印の席は `NavIcon.inkWidth`(規約 §余白)— インク幅は kind ごとに違うので、箱で席を取ると `!` だけ 5px の空気を抱えて数字から離れる(実測)
- `pen` の補正 0.67 グリッドの根拠: 回転後のインクは角 5.23・先端 3.89 で原点より 0.67 上に座る(実測。ストロークの 1/4 は別に足す)
- Tally の段は `iconXs` — 数字と並ぶには `iconSm` は大きい(実測: インク 8px 対 数字 6px。10px に落としてもインクは 1px しか縮まず、効くのは席の引き方)。不採用: 字で組む案(`+2` / `~2` / `→1`)— 和文 UI フォントで記号幅が揃わない(実測 em: `+` 0.724 / `→` 1.000 = 全角)
- ヘッドレスは `wip-tally`
- 改行コードの警告は 3 席・判定は core の `eol` の 1 か所(規約 §改行コードの警告)。diff ペインの警告行は `git diff` と並列に解決する決定 — 後出しの警告は読み進めた人に届かない。WIP の印の読み直しはポーリングに乗せない(静止状態が 10 秒ごとに払う値ではない)— `status_key` 起点で足りる(index は status を動かさず変わりようがなく、窓の外の `git add` も拾える)
- コミットボタンの警告は index に乗っている時だけ(`eolStagedCount`)— ワークツリー側だけの印は「次の `git add` の話」。長押しにしない理由は規約 §可否・警告の出し場所
- 警告の hover は `EolHoverCard` — `ToolTip` は文字列 1 つ・色 1 つで、1 行だけ警告色にできない。カードはペインが 1 枚持ち行とボタンで共有(行に持たせるとスクロールで行ごと消える)。ヘッドレスは `eol-hover` / `eol-commit` / `diff-file`(`--preset eol`)
- **カードは関数で置くので、ポインタの縁だけで呼ぶと動かないポインタの下で古びる**(上に出すカードは採寸済みの高さが要る = バインディングにできない)。ファイル行は status 到着ごとにデリゲートごと建て直されるので hover の縁が勝手に張り直る(2026-08-18 実測)が、**コミットボタンは建て直されない** — `settleCommitCard` は `eolWarned` と `eolStagedCount` の側からも呼ぶ(`Stage all` を押して手をボタンへ運ぶと、押せない = 警告しない間に縁が済む)
- **commit ボタンのカードはボタンの上に開く**(ボタンがペインの底に張り付いたため。下に開くと窓の外 — 実測でカードの上端ヘアラインが写真の最終行だった)。**`y` は代入でなくバインディング**(`anchorY` / `above`)— Popup は文字を渡されたフレームでは最終の高さではなく(規約 §hover のツールチップ「出す前に採寸する」)、上に開くカードはその高さが無いと置けない = 代入だとカード 1 枚分下にずれる
- identity のダイアログは「git が今どう答えるか」で閉じる(`identityError === ""` ではない)。2 連書きは原子的にできない(core.md)ので、半端は消さず欄ごとのチェック印で見せる — 印は成功の飾りではなく失敗の説明。trim 規則の写しを QML に作らない(判定は Rust 側)。印は `visible` でなく `opacity`(入力欄の幅を動かさない)
- 半端のまま閉じたらツールバーの identity バッジが引き受ける(`identityUnsaved`)。文言は `SET IDENTITY` のまま・分けるのは tooltip だけ(操作が同じなら語彙を増やさない)。セッション内に閉じる — 持ち越すと「アプリは identity のコピーを持たない」方針と両立しない
- git が何も言わないのに揃わない時(repo-local が global の上に座る)の 1 文は QML が持つ — 自前の文は `qsTr()` の側に要る(CLAUDE.md 文言規約)
- ヘッドレスは `identity` / `identity-half` の対
- `Open repository` のピッカーは開いているリポジトリの隣から始める(`RepoTab.pickerFolderUrl`)— 既定は前回受理したフォルダ = リポジトリ自身の中で、そこだけ開くものが無い。`urlpath::picker_folder_url` はルート直下のリポジトリでルート自身を返す(空だと置き去りフォルダへ落ちる)。`currentFolder` はバインディングにしない — ダイアログは移動の度に自分で書くので、押した瞬間に 1 度だけ入れる。ヘッドレスは `open-picker`
- ピッカーのフォルダは開けると分かってからタブにする(規約 §リポジトリを開く)。不採用: タブを先に作って失敗で消す(答えは 30〜36ms で返り、タブが 1〜2 フレーム点滅する)
- 開けなかった時の置き場所は経路、文言は種別(規約 §リポジトリを開く)。ダイアログ(`OpenFailedDialog`)はピッカー経由だけ — 人が今選んでいないもの(復元タブ / worktree 行 / `PG_AUTO_OPEN`)に起動直後のモーダルを出さない。文言は `Words.openFailure` の 1 か所
- 種別は core が返す(`GitError::NotARepository { bare }`)— git の文言を読んで分岐しない。`bare` 判定の `rev-parse --is-bare-repository` は失敗時だけ 1 本(実測 33ms)
- 失敗時のパスは `SessionEvent::OpenFailed` が運ぶ — `GitError` にはパスを持たない型があり、`TimedOut` で空になって画面がフォルダを名乗れなかった実績
- 失敗の画面(`OpenFailedScreen`)と `OpenFailedDialog` は 1 部品にしない — 席が違い(規約 §可否・警告の出し場所)、字も揃えも出口も違う(席の中央揃え + `fontLg` + Close tab / 窓の左揃え + `fontXl` + Choose again…)。共有するのは文言だけで、それは `Words.openFailure` が既に持っている
- 失敗の画面はペインの席(`RepoPage` の縦 `SplitView` 内)— ページ全体を覆うとコマンドログが覆いの内側に居て `>_` が効かない(実測)。ログは自分から開かない(背景読みだけで空のパネルが立つ・実測)
- ヘッドレスは 7 動詞: `open-not-a-repo` / `open-bare` / `open-not-a-repo-retry` / `open-not-a-repo-cancel` / `open-fail-tab` / `open-fail-tab-bare` / `open-fail-tab-log`
- fetch の調子は fetch ボタンだけが語る — ツールバーに別のインジケータを置かない(規約 §リモートから取り込む)。止めるタイマーが無ければ赤へ行かない(auto fetch off のリポジトリは黄のまま)
- タブを開いた(= 復元タブへ切り替えた)瞬間の fetch は `Hub::ensure_open` が `apply_repo_settings` の直後に頼む(`session::fetch_on_open`。設定 = 許可なので順番が意味を持つ)。ボタンは `autoFetchRunning` で回る = タイマーの fetch と同じ経路。**失敗してもコマンドログを開かない**のはこの 1 回だけで、`TabMsg::AutoFetch.announce` が運ぶ(数は数える)。「最初の失敗」は `fetch_log_raised` が持つ — 数で数えると、黙った開き際の失敗が run の 1 回きりの発言を食う
- push が拒まれたら push ボタンも黄 + `!`(規約 §リモートへ送る)。赤の段は無い(止められる自動の仕掛けが無い)。答えの分類 `writePushed` は「push だった」としか言わず、リモートブランチの改名・削除も同じ答えで返る — 送る時に埋める枠(ブランチ単位)が「自分の答えか」の判定を兼ねる(`PublishFlow.noteWriteAnswer` は引数なしで tab の `writePushed` / `writeRefused` / `lastWriteError` を読む)。ヘッドレスは `push` / `push-retry`
- fetch と push は 1 つの箱を共有(`TopBar.widestAction`)— しないと片方の語の変化が他方を横へずらす。バインディングにしない: 4 計測 → 2 ボタン幅の式はエンジンにループに見える(実測)ので `Component.onCompleted` で 1 度だけ。候補は `TextMetrics` でなく非表示の Label(`TopBar.Widest`)で測る — 数 px 詰まり、等幅と通常表記が混ざると物差し次第で勝敗が入れ替わる
- コマンドログの `>_`(`commandsToggle`)は高さを `fetchButton.implicitHeight` から借りる — トークンで組むと 24×20 で両隣より一段低く、帯のボタン高は Fusion の `padding: 6` が決めていて表に無い(写した数は隣が動くと黙って 1px ずれる)。`ActionButton` の `seat`(24)は padding ではないので借りない。`RowLayout` は `Layout.alignment` の無い子を帯の高さへ伸ばさない(実測)
- `>_` は手組みの `Rectangle` + `MouseArea` のまま — `HoverToolButton` に席が無い(2026-08-16 判断)。畳めない理由は 3 つ: 地が open / hover / 素の 3 値で `washColor` の 1 枚では出せない・`wrong` の赤枠は `ActionButton.frameColor` と違って印と同時に色が変わる・印の色が wrong / running / open / 素の 4 値。トグルの見た目は `ActionButton` の「押して離す」意匠ではないので、寄せるなら台座側に 4 値の口を開けることになる
- `>_` が赤くなる元は 2 つ(行の `log.failed` / ヘッダの `lastError`)で、`Clear` = `clearPanel()` が両方を空にし、そのまま `closeRequested()` でパネルを畳む(規約 §git が言ったことを読む場所)。ヘッダの 1 行は次の成功では下りない — 下ろせるのは読んだ人だけ(例外は fetch の行 = 次項)。ヘッドレスは `commands-clear` — **パネルが立っていることは press する枝でだけ読む**(毎 tick 読むと、この動詞自身の答え = 畳んだパネルが完了を塞ぐ。規約 §UI 自動化の因果性)
- fetch がヘッダに立てた 1 行と赤は、後続の fetch 成功が自動で下ろす(`last_error_from_fetch` の印がある時だけ — 背景読みが書いた行は残る)。fetch のエラー行は履歴ではなく状態。ログ本体の失敗行は退かせない(履歴は読者のもの)。ヘッドレスは `fetch-recover`
- 箱の余りはボタン自身の余白へ(`ActionButton.slack`)— ラベルの席は自分の幅に戻す。余りを席が抱えると hover の重ね色・警告の枠が最後の字よりずっと右まで届く(実測 Windows: 印の手前 10px 対 語の後ろ 29px)。後ろ側は「残り」で取る — `floor` と `ceil` を並べると端数の語で対が 1px 太る。不採用: 語だけ中央寄せ(印が置き去りで語との間 18px = 隣のボタンまでの距離並み。実測して差し替え)
- 割るのはインクの前後(`ActionButton.headInk` / `tailInk`)— 引かず中央だと印の手前 22 対 語の後ろ 17、引くと 17 対 18(実測 Windows)。`box === 0` には当てない(そこで引くと全ボタンの余白が 2px 動く)。`seat.paired` の `push -f` だけ 5 対 10 になるが、対の他 3 状態が正しい側なので現状維持(実測)
- `box` は最長のインク幅そのもの — 末尾ギャップを足すと 1px の勝敗が 5px の幅差になり、フォントが変わると対が黙って育つ。今は両 OS とも 93px(実測)
- ツールバーの fetch / push はコード表記(`ActionButton.code`。規約 §git 用語のコード表記。`qsTr()` を通さない)。チップの `wordSpacing` は測る側の隠し Label にも付ける — 忘れると箱だけ 4px 広い。フラグのダッシュは `Rectangle` で引く — 字の差し替えでは 1px も縮まない(U+002D / 2010 / 2011 / 2212 が全部同じ 7px。Cascadia Mono 実測)。不採用: 箱を広げて席を空ける(全状態ぶんで対が 16px 太る)
- **止まった merge の出口は `OpExitRow` ではなく `ActionButton` 1 個で、カードごと消える**(規約 §進行中の操作から出る)。`OpExitCard.bare` が枠・地・見出し・内側のマージンを全部落とすので、ボタンは真上の commit ボタンと同じ幅・同じ列に立つ。`centred` + `frameColor: danger` + `tone: danger`(`holdTone` の既定が `frameColor` なので塗りは枠の中を満たす)+ `phraseHead: "merge --abort"`。**句の長押しの印は `ActionButtonLabel.phraseHoldMs` で句の中に置く** — `ActionButtonSeat` は行の左端に立つので、中央に寄せた句と離れて座る(2026-08-22 実測)。`ActionButton` 側は `btnLabel.phrased` の時だけ席から hold を外す(素の held ボタン = `force-push-hold` / `discard-hunk-go` は席のまま)。自動化の `completeOpExit` / `offersOpExit` は `--abort` をこのボタンへ先に振る(`ActionButton.code` は「ラベルがコマンドか」の bool で、行の `code` とは別物なので走査に載らない)
- 止まった操作の出口は commit ボタン直下の居座りカード(規約 §進行中の操作から出る)。`OpExitRow` は `AppMenuItem` の写し — `MenuItem` は Menu の中でしかレイアウトされない。バッジが名乗るのは 1 つ — rebase が pick で止まると `CHERRY_PICK_HEAD` が残り `REBASING · CHERRY-PICKING` になる。`--skip` の判定を進捗の件数で代用しない(件数を書くのは rebase だけ = step する cherry-pick が merge に見える)。`edit` 停止の判定はフル interactive rebase の時に作り直す(P3-確認事項)
- **止まった操作の上で switch すると質問バーが降りる**(規約 §進行中の操作から出る)。門は `RepoPage.standsInTheWay(leaving)` で、`switchToRef`(手が来る道)と `switchTo`(自動化と force 経路)の**両方**に置く — 前者だけだと `checkoutMovingBranch` の「何を失うか」の read が操作の立ったまま走り、後者だけだと `Move here?` と abort の質問が 2 つ続けて立つ。**同意は `leaving` 引数で運ぶ**(ページのプロパティにしない — 再入で門が自分の答えを見て無限に立つ)。core は `checkout_leaving_operation` / `checkout_moving_branch(.., leaving)` の 2 本で、どちらも `session::build::leave_operation` を通し、後者は**check の後**に通す(Move を取り下げた人が pick を失わない)。**バーの形は操作で 2 通り**(`RepoPage.leavingUndoes`)— rebase だけ `--abort` の danger + 長押し(`rebase --quit` は HEAD を detached にして作り直したコミットを参照無しで置いていく実測 2.55)、他の 3 つは `--quit` → conflict を `git add` → `stash push -u` の warning + クリック。**`git add` を挟むのは必須** — unmerged な index に `stash push` は `could not write index` で落ちる(実測 2.55)。**`InProgress::supports` は merge の `--quit` を通す**(出口カードが行を出さないのは UI の判断で、git の側は取る)。**門は 3 つとも同じバーへ落とす**(`standsInTheWay` = 操作 or conflict(`offers::moves_blocked` → `workTree.movesBlocked`)/ 保持は `offers::switch_action` の `holder`)— 操作が無く conflict だけ残る形(`--quit` の着地)は文が 1 節短いだけで同じ質問、別の作業コピーが持っている形は `askOpenHolder` = ピル `Open` + `askAlert` の `!` でその作業コピーをタブで開く(`openRepositoryPathRequested`)。**`RefRowMenu` の `switch` 行はもう暗くならない**(`blockedReason: ""`。暗い行は hover でしか理由を言わない = 2026-08-22 ユーザー判断で撤回。delete の行は据え置き)。代わりに **`AppMenuItem.asks` が長押しの印と同じ席へ黄の `!` を置く**(`NavIcon` kind `bang` / `iconSm` / `Theme.warning` — `HoldIcon` と同寸・同アンカーなので席がずれない)。**`AppMenu.holdIndent` は `asks` でも開く** — 開かないと `!` がカードの縁へはみ出す。条件はメニューを開く時に 1 度だけ決める(`RefRowMenu.switchAsks`)。ヘッドレスは `switch-mark <branch>:asks|plain`(**16px の印は全景の写真では判定しない**)。**`standsInTheWay` の門は 2 か所要る**: `Move here?` の答えと自動化は `switchToRef` を通らず `switchTo` へ直に着くので、片方だけだと**git が拒んでコマンドログが赤く開く**。報告行の `log=false` がその半分を持つ(閉じたパネルと一度も開かなかったパネルは同じ絵)。ヘッドレスは `switch-stopped[-go]` / `switch-conflicted[-go]` / `switch-held`
- **メニューの可否・移動の 3 択・出口の形の規則は core の `offers.rs` が正**(実測つきの doc もそこ): `RefRowMenu.offerOn` / `CommitMenuState.openRowMenu` は `GitFacts.refMenuOffers` / `commitMenuOffers`(packed words を `split(" ")` して can* へ凍結 — 開く時 1 度だけの現設計のまま)、`RepoPage.switchToRef` は `GitFacts.switchAction`(`holder` / `switch` / `materialize` / `move`、L・R 以外は `""`)、状態から導く側は `WorkTreeModel` の drain 派生 qproperty(`movesBlocked` / `leaveUndoes` / `leaveCode` / `opSkipFree`)。QML に残るのは lookup の配線(`worktreeHolding` / `localNameFor` / `upstreamOf` / `oidOfName`)と qsTr の文言・行ごとの kind 条件だけ

- **帯は 0 でも立ち、スクロールしない**(規約 §その他の操作)。バケツごとに一覧を分けた今は帯が枠の一部なので、空バケツの帯を手で戻す仕掛け(section delegate / footer の 2 段重ね)は要らない。**バケツ同士は `borderWidth` 1px 空ける**(どちらも `bgElevated` なので、空のバケツで帯が隣り合った時に 1 本の帯に見える)。`conflicts` のバケツだけ `conflictCount > 0` で出入りする
- **帯のボタンは 3 本とも同じ 1 個**(`WipBucketHeader.moveAllButton`。conflicts は `Mark all resolved` = 規約 §その他の操作)。**conflicts だけ `repoTab.stageConflicted()`** で、`stageAll()` ではない(`git add --all` は隣の unstaged を道連れにする)。**パスの束は QML で集めない** — `RepoSession::stage_conflicted` が書き込みロックの中で status を読み直す(デリゲートは realize された行しか答えず、集めた一覧は前に並んだ書き込みより古い)。**mergetool の待ちが立っている間はボタンが退く**(同じ席・キューが塞がっている)。動詞は `resolve-all`

- 行末の `+` / `−` は光っている行すべてに効く(規約 §その他の操作。`stageTargets` / `stagePeerOf`、動詞 `stage-many`)
- **行の `+` は押した所で書く。diff の行はそれ以外のクリックを取らない**(規約 §diff の中のステージ。`DiffRowDelegate.lineStageRequested` → `DiffPane.stageLine` → `stageSelectionRequested`)。行選択の機構(`DiffLineChoice` / `beginLines`+`addLine`+`stageLines` / `encode::line_selection`)は**持たない・再導入しない** — 本文をいずれ選択・コピーさせるので、行に当たり判定を持たせない
- **「どの行にポインタが在るか」は行に訊かず、ペインが座標から引く**(`DiffPane.settlePointedRow` → `hoverHunk` / `hoverLine`。規約 §diff の中のステージ)。**行を作り直すと、新しい item は次のマウス移動まで hover しない**(Qt は hover を動きで配る)= 1 行ステージ直後に `+` が出ず連続操作が死ぬ。引き金は 3 つ: `HoverHandler.onPointChanged` / `onContentYChanged` / 行が届いた後の `Metrics.anchorDelayMs` タイマ(届いたフレームではまだレイアウト前で `itemAt` が空)。**`settlePointedRow` は hover していない時は何もしない** — headless では 1 度も hover しないので、自動化が名指しした行を消してはならない(消すのは `onHoveredChanged` の離脱側だけ)
- **行の hover を `MouseArea` で取らない**(2026-08-17 実測・qmltestrunner)。子の hoverEnabled な `MouseArea`(行の `+`)へポインタが入ると親 `MouseArea` の `containsMouse` が落ちる = 印へ手を伸ばすと印が消える。`HoverHandler` は passive なので落ちない
- その棚卸しは済み(2026-08-21: `ui/` の `containsMouse` 15 箇所)— 該当は `NavItemDelegate` だけで、行の `+`(`stageButton` = `HoverToolButton`)へ手を伸ばすと行の地と `hoverText` が落ち、`eolPointed(false)` が改行コードのカードまで閉じていた(qmltestrunner 実測 `containsMouse=false lit=false eolOn=false` → `HoverHandler` の `navRow.pointed` へ移して 3 つとも true。`itemMouse` は `hoverEnabled` を名乗らない・handler の `enabled: !editing` が旧 `visible: !editing` の門を引き継ぐ)。**奪うのは覆う `MouseArea` の子孫でない hover 持ちだけ** — 上に重なる兄弟(`stageButton` / タブの `✕`)は奪うが、**`Control` の中へ入れた子の `MouseArea` は奪わない**(同実測: 子の `containsMouse` と親の `HoverToolButton.hovered` が同時に true = `WipPane.commitHover` は無事)。残り 13 箇所は覆う先が Label / `NavIcon` だけなので触らない
- **行の上に重ねるオーバーレイに `HoverHandler` を置かない**(同実測)。**置いた瞬間、下の行は `MouseArea` も `HoverHandler` も hover を受け取らなくなる**(素の `MouseArea` を重ねる分には落ちない)。「ポインタがペインに居るか」は**ペイン自身(祖先)のハンドラ**で取る — 祖先なら行の hover は残る
- **書き込みが行に届くまで印は無効**(`RepoPage.diffSettling` = `diffAwaits || busyCount>0 || diffModel.loading` → `DiffPane.busy`)。押下は「その時の行 index + 指紋」を宛先にするので、入れ替わり前後で撃つと core が `Rejected` を返しログが赤くなる(連打で再現。2026-08-17 ユーザー報告)。**3 項とも自分で下りるものだけで組む** — 「ツリーをまだ読んでいない」を条件に入れると、行が動かない書き込み(両側に居るファイルの 2 行目)で**永久に無効のまま**になり、以後どのファイルでも `+` が死ぬ(同日ユーザー報告)。**`busyCount` だけでも足りない** — 立つのはキューが書き込みを始めた時で、押下の瞬間ではない(連続 2 押下は両方出て行く)。`diffAwaits` は `stageSelection` / `discardSelection` の**「積めたか」の答え**で立てる(スロットは bool を返す — 指紋なし・空選択で門前払いされた押下に答えは来ないので、先に立てると同型の永久無効)、下ろすのは書き込みの答え
- **`NavSectionModel.changed()` は行が変わった時しか出ない**(`drain` の `arrived`)。「status を読んだ」を待つなら `WorkTreeModel.changed()`(StatusMsg 毎に無条件)。行の部分ステージは行を動かさないので、前者で待つと来ない
- **diff の読み直しは書き込みの答えの所で撃つ**(`absorbWriteResult`。`WriteFinished` は status の publish より先に届く — `session::write` は write → publish_status の順)。git は答える時点で index を動かし終えているので、ファイルの diff は既に新しい。status を待つ必要があるのは**ファイル一覧**の側だけ(`followEmptySide` が status で訊く)。二重読みは `diffReadAt`(その書き込みの writeSeq)で抑え、外の変更は `WorkTreeModel.changed()` + 件数の指紋で拾う。**拒否(エラー)の答えでも読み直す** — 拒否の原因は表示の古さで、件数を動かさない外部変更は指紋では拾えない(読み直さないと同じ押下が拒まれ続ける)。`holdScroll()` は**行を入れ替える直前**に `DiffModel.rowsReplacing` から取る — 読み直しを頼む側(`reloadDiff` / `pollDiff`)には置けない(下の tick の項)
- **件数の指紋では「同じ状態のまま中身だけ動いたファイル」を拾えない**(2026-08-22 ユーザー報告)。conflict がその形 — 別窓で解決してもマーカーが消えるだけで、`git add` するまで status の 2 文字も 4 つの件数も動かず、ペインは開いた時の conflict を描き続けた。ページの tick が `RepoPage.pollDiff` → `DiffModel.refreshWorkTree` → `RepoSession::refresh_diff` で**開いているファイルだけ**を訊き直す(commit の diff は訊かない・`diffSettling` の間も訊かない)。**核は fingerprint 比較で黙る** — 動いていなければイベントを出さないので、静止したファイルの 10 秒は `git diff` 1 本で、行も読んでいた位置も動かない。**tick は `loading` を立てない**(立てるとポーリングのたびにペインが白む)。窓がフォーカスを取り戻した時も同じ 1 本を撃つ。動詞 `diff-tick`(訊けたこと自体が唯一の edge — 外からファイルを書く側は core の統合テストが持つ)
- **側が空になった diff は閉じずに移る**(規約 §diff の中のステージ。`RepoPage.followEmptySide`)。次のファイル → 同じファイルの向こう側 → 閉じる、の順。**隣は「まだ在る間」に控える**(`noteDiffNeighbour` を `worktreeModel.onChanged` で呼び、`holdsPath` が真の時だけ更新)— 書き込みが着いた時にはファイルは移動済みで、`besidePath` は答えを持たない。隣の探索は**モデル側**(`NavSectionModel.besidePath` / `holdsPath` / `bucketOf`)= ListView は画面外の行を持たないので、ビューを歩くと隣が null になる。動詞 `diff-follow`(引数 `<パス>` / `staged:<パス>`)
- **ファイル一覧の上下矢印は `FileRowWalk` の 1 本**(規約 §diff のファイル一覧)。両ペインが同じ部品を持ち、**「今どこに居るか」はペインが `readBucket` / `readPath` で渡す**(walk 自身が書く `at*` にバインドを掛けない — 1 歩目で切れる)。**次の行はモデルが答える**(`stepFile` → `<row>\u{1e}<bucket>\u{1e}<path>`。ビューを歩くと画面外の行が null = P3 の `chosenRows` と同じ穴)。**視界は `positionViewAtIndex(row, ListView.Contain)`** — WIP の一覧は行の間にバケツの帯が挟まるので、`GraphRowWalk` の「行高 × row」算術はそこで別の画素に落ちる。**diff の読みは `keyStepSettleMs` で間引く**(1 歩 = `git diff` 1 本)ので、光は打鍵ごと・中央は止まってから。**クリックとは別のシグナル**(`fileWalked` → `openDiff`)— `fileActivated` は `toggleDiff` なので、同じ経路だと settle の 2 通目が diff を閉じうる
- **diff はもうキーボードを取らない**(規約 §diff を上下に送る「手が着いた時」)。取る扉は `DiffPane.handArrived()` の 1 本で、押す物は**ペイン自身の `PointHandler`**(passive grab = 下のボタン・バー・行の印が生きる。overlay に置くと行の hover が死ぬ — 下の項)と `WheelHandler`。一覧側は行のクリックハンドラで `forceActiveFocus()`。退く時に手放すのは両 walk が持つ(`onVisibleChanged`)
- **読んでいるファイルの行は光る**(規約 §diff のファイル一覧)。CHANGES は `DetailsPane.readPath` の 1 本を行へ配る(行ごとに「読んでいる path」を持たせない)。WIP は**既に在る `chosen` の光を使い回す** — 足りないのは逆向きだけで、ペインが自分で diff を動かした時に `RepoPage.openDiff` → `WipPane.readOne` が選択を連れて行く(素のクリックでは既に 1 件なので `rowIndexOf` の走査は走らない)。報告は行の `litKey` = **矩形が出ている時だけその行の名前を返す**(`chosen` / `readPath` を読み直すと矩形の配線を切っても緑になる)。ペイン自身が動かす経路は status 起点(上の `followEmptySide` の項)なので、光は「一覧がその側で持たなくなった」と同じ 1 本に乗る
- **diff は横へ送る・溝は動かない**(規約 §diff を横へ送る。`DiffCodeScroll` / `DiffRowDelegate.codeX`)。動かすのは `codeRoom`(`clip: true`)の中の Label の `x` だけで、**ListView の `contentX` は使わない** — ListView は自分で `contentWidth` を持つので取り合いになる。バーは `Flickable` に付けない素の `ScrollBar`(`size` / `position` を束ね、`pressed` の時だけ書き戻す = `GraphPane` のレーンバーと同じ形)で、**リストの中ではなくペインの側に置く**(掴みが Flickable の取り立てに持って行かれない)。中クリックは `MiddleAutoScroll` を共有(グラフと違い `panFrom`/`panTo` はペイン全幅)。幅は `diffModel.widestColumns` × **測った 1 文字**(`charMeasure` の 10 文字 ÷ 10)— メトリクスをメソッドで取ると初回の既定フォントで固まる。動詞 `code-send`(`--preset widelines`)
- **`elide` を外した Label は `width: implicitWidth`**(`DiffRowDelegate` の code Label)。hunk 見出しだけは `codeRoom.width` + `ElideRight` = ペイン自身の言葉なので右端の 2 語に席を譲る
- **移る・閉じるの引き金は `worktreeModel.changed()` で `holdsPath` が偽になった時**(規約 §diff の中のステージ。`followEmptySide` 冒頭のガードが正、旧 `closeWhenEmpty` は廃止)。**空の読みを引き金にしない** — `load_diff` は `publish_status` と並走して空の答えが一覧より先に着きうる(書き込み前の一覧に「次」を訊き、空になった側を開き直して止まる)し、未追跡(全追加として描く)・画像は空にならないので引き金が来ない。`clear()`(ユーザーの閉じ)を「空になった」と誤読して開き直す穴も同根
- **diff の作り直しで画面を飛ばさない**(規約 §diff の中のステージ。`begin_request` は同じファイルなら行を消さない)。`holdScroll()` は `onCountChanged` の 0 を無視する(reset が先に来る)。**戻した位置は `DiffScrollPlace.landedY`(復元前は -1)**= 自動化が待つ出力で、書き込みが片側を空にした diff では行が戻らないので永久に -1 のまま。動詞 `keep-place`(`--preset manyhunks`)
- **`DiffScrollPlace` の位置は別のファイルへ移る時に捨てる**(`openDiff` 冒頭の `dropScroll()`)— 空にした側から移った先(追従・次に開いたファイル)が旧ファイルの位置に着地する。`hold()` は復元待ちの位置を上書きしない(行が戻った直後の押下は、ビューが reset の先頭に立つ瞬間と重なる — 先頭を「読んでいた位置」として掴む)+ 保留中の復元タイマも止める
- **diff の色は行の後から届く**(`SessionEvent::DiffColoured`。規約 §シンタックスハイライト)。syntect は行数に比例して重い — 6001 行の `.rs` で 951ms・同内容の `.txt` は 3ms(2026-08-13 実測)、UI スレッドは無実(`flatten_patches` は 2ms)。色を乗せる時に行を作り直さない — `ListView` は新しいリストで先頭へ戻る(`repaint_rows` が `text` / `rich` だけ書き換える。実測 `at=400`)。追い越された読みは色を付けない(`diff_epoch` — 無いと、ファイルを次々クリックした時に離れた行の色付けが 1 件ずつ後ろに残る)。動詞 `colour-place`
- **diff の feed だけ `push_replace` ではなく `push`**(`hub.rs`)— 1 つの diff が行と色の 2 通を出し、置き換えると片割れが消える。応答は要求順に返らない(色付き 951ms / プレーン 3ms)ので、遅れて着いた古い応答が新しい方を上書き → stale として捨てられ、開いているファイルの diff が二度と来なかった(2026-08-13 実測。「diff が出たり出なかったりする」の正体)
- **diff の行を触る自動化フックは待ち時間で計らない**(`AutoActDriver.stageRowTimer`)。固定の待ちは、読みが間に合わない run と dirty でない run を「空のペインを撮って PASS」に潰す(2026-08-13 実測: 1 行も名指しできないまま緑)。行が着くまで訊き続け、着いた瞬間に実行して報告する — 上限は持たず、届かない run は報告行を 1 本も出さないまま watchdog で終わる(報告行と must_say は verbs.md)
- **PG_AUTO_ACT の一式は `AutoActDriver`(ページ)と `WindowAutoActDriver`(窓)**。`RepoPage` / `Main` が `Loader { active: AppBackend.autoAct !== "" }` で持ち、通常起動では 1 つも建たない。別ファイルからは持ち主の id が見えないので、**動詞が触る相手(ペイン・モデル・メニュー行・カード)はインスタンス化の場所で property として渡す** — 渡す先が部品の内側なので `GraphPane.view` と同じ**自動化フック専用の露出**として扱う(相手を増やす時はこの意味で 1 行足す)。持ち主から叩く口は `begin()` の 1 本(`autoActLoader.item` の null を見てから呼ぶ)
- **ドライバの root は `Item`** — `QtObject` は default property を持たず、匿名の子(`Timer`)を 1 つも書けない(`Cannot assign to non-existent default property` で窓ごとロードに失敗する)。描かず寸法も持たないので `Loader` の中では 0x0
- **インスタンス化の場所の `prop: <同名の id>` は id に解決される**(自己バインドしない。2026-08-16 qmltestrunner 実測)— ドライバの property 名を渡す id と揃えられるのはこれが理由で、逆なら全部 null になる。同じ名前でも**部品の内側**では property が id をシャドウする(帯の幅式が NaN になった形は verbs.md `band`)
- **diff の一覧のホイールも 1 ノッチ = `wheelRows` 行**(規約 §グラフ・インタラクション定数)— 素の Flickable ホイールは疑似フリックで他の面より鈍い。ホイールは注入できないので動確は絵ではなく回帰(`diff-file` / `keep-place` が PASS のまま)で言う
- **リモートブランチの改名**(規約 §リモートブランチの改名): git に無いので push + `push --delete` + `--set-upstream-to` の合成(`remote::rename_remote_branch`)。押すのは追跡 ref — 先へ進んだローカルのコミットを一緒に publish しない。同意は長押し(forge から見れば作成 + 削除で PR は付いてこない)。既にリモートに在る名前は入力欄で弾く — 存在する名前への push は早送りできると成功し、git が拒まない
- **リモートブランチの削除**(規約 §リモートブランチを消す): メニュー行そのものを長押し(stash 削除と同じ所作・同じ文言、この行だけ warning)。git は何も拒まない(`-d` の「そこにしか無いコミット」を数える材料が手元に無い)ので長押しがその代わり。upstream でも既定ブランチでも行は出す

- **stash の名前を決めるのは `WipPane.stashName` 1 か所**(規約 §変更を退避する。2026-08-22 ユーザー指示 = コミット箱の summary をそのまま名前にする)— 帯のボタンは `RepoPage.pageStashName` 越しに、ファイル行の `stash` は `wipPane` を直に読む。**`outgoingSubject` を使わない**(中断した merge の文が混ざる)・**amend 中は空**(箱に在るのは HEAD のメッセージ)。可否は core の `stash::is_valid_message`(改名の箱と同じ純関数)。**一覧に出る綴りは `On <branch>: <summary>`** — `push -m` に git が前置きを足す(実測)ので、改名で作ったエントリ(`stash store -m` = 前置き無し)とは形が違う。ヘッドレスは `stash` と `stash named` を**対で読む**(報告行 `graph_settled … named=` は `stashesModel.nameAt(0)` の末尾一致 = git まで届いたかどうかで、箱に残った文では立たない)
- **保存フラグの復元は 1 書き手**: `wip_tree` は `PageLayout.applySavedLayout` → `setTreeView` だけが書く — `NavSectionModel::attach_*` が触ると復元を上書きし、その値が保存へ書き戻る(平置きを選んでも毎起動ツリーへ戻る形を一度作った)。`tags_shown` は同じ理由で **session 側は `Hub::ensure_open` が保存値を渡す**(復元の `setTagsShown` は session 誕生前に走り届かない — 目は隠すのにグラフはタグを描く形)
- **HEAD の oid の正は `WorkTreeModel.headOid`**(status 由来 — detached でも答える)。`NavSectionModel.headOid` は「HEAD が乗っているブランチ」の答えで detached では空 — 着地(`tryPendingHeadSelect`)はブランチ側が空なら status 側へ倒す
- **packed record の区切りは 1 対**(`encode::RECORD_SEP` U+001F / `FIELD_SEP` U+001E)— avatar 便も同じ(逆順の別対を持たない)。QML の `fromCharCode(31/30)` はこの対の読み
- **タブの feed 一覧は `for_every_feed!` の 1 本**(hub/feed.rs)— release / clear / `feed_depths` は全部そこから展開する。手書きの写しは memory report がまさに捕まえたい queue を数え漏らす
- xtask の automation env 隔離は **prefix 方式**(`PG_*` から pass-through 3 名を引く — core の `AUTOMATION_PREFIX` / `NOT_AUTOMATION` と手動対、変えるなら両方)。ノブ追加でリストを触り忘れても親 shell の値は漏れない
- **`pop` はエントリの名前をコミット箱へ返す**(規約 §変更を退避する。2026-08-22 ユーザー指示)— 入口は `RepoPage.popStash` 1 つ(グラフ行のメニューと詳細ペインの帯が両方これを通る)。**名前は押した時に読む**(答えが返る頃にはエントリは一覧に無い = `NavSectionModel::name_of_full` が selector から行の表示名を引く。filter を無視して全エントリを見る)、**入れるのは書き込みが landed した後**(`absorbWriteResult` の成功側。失敗側で `pendingPopLabel` を捨てる = 拒まれた pop は名前も戻さない)。git が書いた `WIP on …` は返さない・箱が空の時だけ入れる(`subjectText` と `bodyText` の両方)。前置きの剥がしは core の `stash::label_in` —— **`On <branch>: ` の branch には空白が入る**(detached は `(no branch)`)ので、切るのは最初の `": "`(実測)。`apply` は返さない(エントリが残る)。ヘッドレスは `stash-pop-row` の報告行 `graph_settled … back=`(箱の `subjectText` を読む = 入れた側の property ではない)
