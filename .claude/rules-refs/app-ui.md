# platitude-app 各論(意匠決定・実装対応・罠)

[.claude/rules/app-ui.md](../rules/app-ui.md) の参照資料 — **1 項目 1 行**、触る部品名・操作名・動詞名・規約 §名で Grep して該当行と前後だけを読み(全読みしない)、追記も 1 行(「app-ui.md §…」の参照はここへ移った行も指す)。

- **配線済み**: ステージング(ファイル / hunk / 行)・commit / amend・switch(ローカル / リモート。detach する導線を UI に置かない決定 — git が置いた detached HEAD からは普通に動く。未コミット変更は尋ねず持っていく = `session::carry_across`。conflict でも専用表示なし)・fetch(手動 + auto)・push / force push・単体 cherry-pick・単体 squash・merge / rebase / revert の起動・単体 drop・止まった操作の出口・conflict の種別・片側採用・外部ツール連携・コミットメッセージ編集・amend での著者引き継ぎ・reset(soft / mixed / hard。hard はサブメニュー行の長押し = stash 削除と同じ意匠)・stash push(全体 / 1 パス)・discard / clean・identity・署名の表示(規約 §署名の表示)・設定(auto fetch 間隔)・diff プレビュー(`platitude-core::preview`)・コマンドログ・初回 push・Ctrl+F のコミット検索(アドバンス検索は未着手)・上下矢印でのコミット送りと diff の上下送り(PageUp/Down・Home/End は未配線)・stash の Apply / Pop・ブランチ / タグ / stash / リモートブランチの改名と削除・タグのリモート状態バッジ・co-author の表示・著者のアバター・設定 / 画面状態の永続化・改行コードの警告・git の版(無ければ全画面のゲート / 最低バージョン未満は `OLD GIT` バッジ)・diff のシンタックスハイライト(個々の意匠・実装対応は下の各項)。**この一覧が配線済み操作の正本**(CLAUDE.md は未配線だけを持つ。配線したらこの行へ足す)

- グラフの未コミット行の集計(`Tally`)は status から数える(規約 §未コミット行が名乗るもの)。決定: 行数でなくファイル数 — 行数(`+N -M`)は `diff --numstat HEAD` が 1 本増えるが、ファイル数は手元の status の文字で足りる
- 印の席は `NavIcon.inkWidth`(規約 §余白)— インク幅は kind ごとに違うので、箱で席を取ると `!` だけ 5px の空気を抱えて数字から離れる(実測)
- `pen` の補正 0.67 グリッドの根拠: 回転後のインクは角 5.23・先端 3.89 で原点より 0.67 上に座る(実測。ストロークの 1/4 は別に足す)
- Tally の段は `iconXs` — 数字と並ぶには `iconSm` は大きい(実測: インク 8px 対 数字 6px。10px に落としてもインクは 1px しか縮まず、効くのは席の引き方)。不採用: 字で組む案(`+2` / `~2` / `→1`)— 和文 UI フォントで記号幅が揃わない(実測 em: `+` 0.724 / `→` 1.000 = 全角)
- ヘッドレスは `wip-tally`
- 改行コードの警告は 3 席・判定は core の `eol` の 1 か所(規約 §改行コードの警告)。diff ペインの警告行は `git diff` と並列に解決する決定 — 後出しの警告は読み進めた人に届かない。WIP の印の読み直しはポーリングに乗せない(静止状態が 10 秒ごとに払う値ではない)— `status_key` 起点で足りる(index は status を動かさず変わりようがなく、窓の外の `git add` も拾える)
- コミットボタンの警告は index に乗っている時だけ(`eolStagedCount`)— ワークツリー側だけの印は「次の `git add` の話」。長押しにしない理由は規約 §可否・警告の出し場所
- 警告の hover は `EolHoverCard` — `ToolTip` は文字列 1 つ・色 1 つで、1 行だけ警告色にできない。カードはペインが 1 枚持ち行とボタンで共有(行に持たせるとスクロールで行ごと消える)。ヘッドレスは `eol-hover` / `eol-commit` / `diff-file`(`--preset eol`)
- identity のダイアログは「git が今どう答えるか」で閉じる(`identityError === ""` ではない)。2 連書きは原子的にできない(core.md)ので、半端は消さず欄ごとのチェック印で見せる — 印は成功の飾りではなく失敗の説明。trim 規則の写しを QML に作らない(判定は Rust 側)。印は `visible` でなく `opacity`(入力欄の幅を動かさない)
- 半端のまま閉じたらツールバーの identity バッジが引き受ける(`identityUnsaved`)。文言は `SET IDENTITY` のまま・分けるのは tooltip だけ(操作が同じなら語彙を増やさない)。セッション内に閉じる — 持ち越すと「アプリは identity のコピーを持たない」方針と両立しない
- git が何も言わないのに揃わない時(repo-local が global の上に座る)の 1 文は QML が持つ — 自前の文は `qsTr()` の側に要る(CLAUDE.md 文言規約)
- ヘッドレスは `identity` / `identity-half` の対
- `Open repository` のピッカーは開いているリポジトリの隣から始める(`RepoTab.pickerFolderUrl`)— 既定は前回受理したフォルダ = リポジトリ自身の中で、そこだけ開くものが無い。`urlpath::picker_folder_url` はルート直下のリポジトリでルート自身を返す(空だと置き去りフォルダへ落ちる)。`currentFolder` はバインディングにしない — ダイアログは移動の度に自分で書くので、押した瞬間に 1 度だけ入れる。ヘッドレスは `open-picker`
- ピッカーのフォルダは開けると分かってからタブにする(規約 §リポジトリを開く)。不採用: タブを先に作って失敗で消す(答えは 30〜36ms で返り、タブが 1〜2 フレーム点滅する)
- 開けなかった時の置き場所は経路、文言は種別(規約 §リポジトリを開く)。ダイアログ(`OpenFailedDialog`)はピッカー経由だけ — 人が今選んでいないもの(復元タブ / worktree 行 / `PG_AUTO_OPEN`)に起動直後のモーダルを出さない。文言は `Words.openFailure` の 1 か所
- 種別は core が返す(`GitError::NotARepository { bare }`)— git の文言を読んで分岐しない。`bare` 判定の `rev-parse --is-bare-repository` は失敗時だけ 1 本(実測 33ms)
- 失敗時のパスは `SessionEvent::OpenFailed` が運ぶ — `GitError` にはパスを持たない型があり、`TimedOut` で空になって画面がフォルダを名乗れなかった実績
- 失敗の画面(`OpenFailedScreen`)と `OpenFailedDialog` は 1 部品にしない — 席が違い(規約 §可否・警告の出し場所)、字も揃えも出口も違う(席の中央揃え + `fontLg` + Close tab / 窓の左揃え + `fontXl` + Choose again…)。共有するのは文言だけで、それは `Words.openFailure` が既に持っている
- 失敗の画面はペインの席(`RepoPage` の縦 `SplitView` 内)— ページ全体を覆うとコマンドログが覆いの内側に居て `>_` が効かない(実測)。ログは自分から開かない(背景読みだけで空のパネルが立つ・実測)
- ヘッドレスは 7 動詞: `open-not-a-repo` / `open-bare` / `open-not-a-repo-retry` / `open-not-a-repo-cancel` / `open-fail-tab` / `open-fail-tab-bare` / `open-fail-tab-log`
- fetch の調子は fetch ボタンだけが語る — ツールバーに別のインジケータを置かない(規約 §リモートから取り込む)。止めるタイマーが無ければ赤へ行かない(auto fetch off のリポジトリは黄のまま)
- push が拒まれたら push ボタンも黄 + `!`(規約 §リモートへ送る)。赤の段は無い(止められる自動の仕掛けが無い)。答えの `lastWriteOp` は `push` としか言わず、リモートブランチの改名・削除も同じ名前で返る — 送る時に埋める枠(ブランチ単位)が「自分の答えか」の判定を兼ねる。ヘッドレスは `push` / `push-retry`
- fetch と push は 1 つの箱を共有(`TopBar.widestAction`)— しないと片方の語の変化が他方を横へずらす。バインディングにしない: 4 計測 → 2 ボタン幅の式はエンジンにループに見える(実測)ので `Component.onCompleted` で 1 度だけ。候補は `TextMetrics` でなく非表示の Label(`TopBar.Widest`)で測る — 数 px 詰まり、等幅と通常表記が混ざると物差し次第で勝敗が入れ替わる
- コマンドログの `>_`(`commandsToggle`)は高さを `fetchButton.implicitHeight` から借りる — トークンで組むと 24×20 で両隣より一段低く、帯のボタン高は Fusion の `padding: 6` が決めていて表に無い(写した数は隣が動くと黙って 1px ずれる)。`ActionButton` の `seat`(24)は padding ではないので借りない。`RowLayout` は `Layout.alignment` の無い子を帯の高さへ伸ばさない(実測)
- `>_` が赤くなる元は 2 つ(行の `log.failed` / ヘッダの `lastError`)で、`Clear` = `clearPanel()` が両方を空にする。ヘッダの 1 行は次の成功では下りない — 下ろせるのは読んだ人だけ(規約 §git が言ったことを読む場所。例外は fetch の行 = 次項)。ヘッドレスは `commands-clear`
- fetch がヘッダに立てた 1 行と赤は、後続の fetch 成功が自動で下ろす(`last_error_from_fetch` の印がある時だけ — 背景読みが書いた行は残る)。fetch のエラー行は履歴ではなく状態。ログ本体の失敗行は退かせない(履歴は読者のもの)。ヘッドレスは `fetch-recover`
- 箱の余りはボタン自身の余白へ(`ActionButton.slack`)— ラベルの席は自分の幅に戻す。余りを席が抱えると hover の重ね色・警告の枠が最後の字よりずっと右まで届く(実測 Windows: 印の手前 10px 対 語の後ろ 29px)。後ろ側は「残り」で取る — `floor` と `ceil` を並べると端数の語で対が 1px 太る。不採用: 語だけ中央寄せ(印が置き去りで語との間 18px = 隣のボタンまでの距離並み。実測して差し替え)
- 割るのはインクの前後(`ActionButton.headInk` / `tailInk`)— 引かず中央だと印の手前 22 対 語の後ろ 17、引くと 17 対 18(実測 Windows)。`box === 0` には当てない(そこで引くと全ボタンの余白が 2px 動く)。`seat.paired` の `push -f` だけ 5 対 10 になるが、対の他 3 状態が正しい側なので現状維持(実測)
- `box` は最長のインク幅そのもの — 末尾ギャップを足すと 1px の勝敗が 5px の幅差になり、フォントが変わると対が黙って育つ。今は両 OS とも 93px(実測)
- ツールバーの fetch / push はコード表記(`ActionButton.code`。規約 §git 用語のコード表記。`qsTr()` を通さない)。チップの `wordSpacing` は測る側の隠し Label にも付ける — 忘れると箱だけ 4px 広い。フラグのダッシュは `Rectangle` で引く — 字の差し替えでは 1px も縮まない(U+002D / 2010 / 2011 / 2212 が全部同じ 7px。Cascadia Mono 実測)。不採用: 箱を広げて席を空ける(全状態ぶんで対が 16px 太る)
- 止まった操作の出口は commit ボタン直下の居座りカード(規約 §進行中の操作から出る)。`OpExitRow` は `AppMenuItem` の写し — `MenuItem` は Menu の中でしかレイアウトされない。バッジが名乗るのは 1 つ — rebase が pick で止まると `CHERRY_PICK_HEAD` が残り `REBASING · CHERRY-PICKING` になる。`--skip` の判定を進捗の件数で代用しない(件数を書くのは rebase だけ = step する cherry-pick が merge に見える)。`edit` 停止の判定はフル interactive rebase の時に作り直す(P3-確認事項)
- 単体 drop はグラフ行メニューの行で squash の隣(規約 §履歴を合流させる・§メニュー)。`plan_edit` は object name を取る — `HEAD` 等の symbolic name は履歴に見つからず弾かれる
- 未コミット変更があっても履歴の書き換えは止まらず、何も尋ねない(規約 §未コミット変更がある状態で履歴を書き換える)。squash / drop / rebase onto は同じ 1 本(`session::carry_across_rewrite`)で専用の表示を持たない — 着地は 3 つとも既存の絵。拒否ではコマンドログが開かず、止まった時は開く。ヘッドレスは `--preset drop-collides` / `drop-stops`
- drop が長押しかクリックかは `repoTab.headReachedElsewhere` の 1 つで決まり、session が先に押し出す — メニューを開いてから訊くと答えが `holdMs` を動かし、`AppMenu.holdIndent` が全行を字下げし直す(手が降りている最中に的が動く)。ヘッドレスは `drop-commit` / `drop-commit-go`
- 判定は core の `reachable` の 2 段(refs 一覧 1 周 → 落ちたら `rev-list` の walk)。コストと不採用の形は [ci/baseline/head-reach-windows-x64.md](../../ci/baseline/head-reach-windows-x64.md)
- merge / rebase / revert は現在のブランチを文の主語にする(規約 §履歴を合流させる)。入口が変わっても文は同じ — `RefRowMenu.refId` は文に出ない(規約 §メニュー)。`publishRange` は 1 枠の共有なので自分が訊いた範囲の答えだけを読む(範囲は `RefRowMenu.rebaseRange`・答えを配るのは `RepoPage` の 1 か所)。rebase に autostash の引数は無い — 未コミット変更は core の carry が運ぶ(上の項)
- merge / cherry-pick / revert の着地で選択と視界が新しいコミットへ移る(規約 §履歴を合流させる。`pendingHeadSelect` の 3 人目)。書き込みの答えの中では解決しない — status / refs / walk は別々に届き、先の 2 つはまだ書き込み前の履歴を語る。armed を解くのは `NavSectionModel.refsSettled` — モデルの `changed` は同じ行では黙る(4 万タグの最適化)ので、届いたことを言う口が別に要る。残ると次に refs が動いた背景更新が視界を動かす(実測: 空の cherry-pick。`merge-branch v0.1 --preset basic` は選択が元から先端でこの穴を素通りしていた)。rebase / squash / drop / reword はこの枠に入れない — あちらは読んでいたコミットの行方を追う側(`followVanishedCommit`)で、先端へ飛ばすと読んでいた場所を失う。空の cherry-pick の検証は `demo-repo diverged` の木に同じ内容のコミットを両ブランチへ積んで建てる
- 視界まで動くのは `pendingHeadAsked` が立っている時だけ — 同じ枠の他 2 つは窓に起きたことで、背景の更新が読んでいる人の視界を動かしてはならない(§`ListView.highlightFollowsCurrentItem`)。移す先が画面に在れば動かさない(`goToMatch` と同じ規則)
- 視界の移動は `GraphPane.showRowSoon()` = `shiftRows` と同じ 1 本のタイマ — 別のタイマだと同じ `anchorDelayMs` で発火順に賭ける(「その行が画面に在るか」は shift が置いた後の位置についてしか真でない)。`activateRow` の後に頼む — 未保存メッセージの質問が移動を留めた時は選択が元へ戻され、視界に行き先が無い
- ヘッドレスの `revert-commit` / `cherry-pick` / `merge-branch` は `tip_landed` の 1 行を共有(フィールドは verbs.md)。判定の空回りは実測で否定済み(条件を revert だけに戻すと後 2 者が `follows=false`、`showRowSoon` を殺すと `onscreen=false` で落ちる)。merge / cherry-pick は `--preset diverged` の `origin/main`(`basic` は木が汚れて git が cherry-pick を拒む)。視界の試験は背の高い履歴だけ — `demo-repo co-authors --at` に 40 件積んで `--repo` で渡す(コンテナへ渡す木は `commit.gpgsign` を落とす — preset の署名鍵は Windows 絶対パスで `/work` から読めない)
- conflict の片側採用は規約 §conflict の ours / theirs が正。`NavItemDelegate.conflictWords` はヘッドレスの `conflict_kind` 報告だけが呼ぶ — ファイル行アイコンの hover は届いていなかったので外した(下の「行を覆う MouseArea」)
- conflict を外部ツールへ渡す(規約 §同名): 書くのは `merge.guitool` — 起動が `--gui` で guitool が先に効き、`merge.tool` へ書くと guitool 設定済みの人に無反応。ターミナルの `git mergetool` を巻き添えにしない(端末があるので `vimdiff` でよい)。`mergeTool` は conflict がある時だけ読む(2 spawn を毎ポーリングに乗せない)。ヘッドレスは `open-mergetool`
- マージツール候補の `AppCombo`(規約 §conflict を外部ツールへ渡す): ComboBox は model 差し替えで `currentIndex` を先頭へ寄せ `editText` を道連れにする — 値は `wanted` に別で持ち、人の操作だけが動かす(`editText` の変化・`activeFocus`・`popup.opened` は判別に使えない。内部リセットは `onModelChanged` より先に走る)。Popup の `implicitHeight` に padding を足す(行の高さだけだと最終行が切れる)。ヘッドレスは `settings-tools`
- `WorkTreeModel.mergeTool` は読まなかった refresh でも前回値を繰り返す(`merge_tool_seen`)— 空で上書きすると開いたままの設定ダイアログの値が次の tick で蒸発する
- Ctrl+F の照合の正本は `platitude-core::find` — QML に判定を書かない(規約 §コミットを探す)。`setFind` は `splice_notified` を通さない(行を丸ごと clone した `Vec` を取る = 毎打鍵で全行の String 複製)。`GraphRowItem` は 15 フィールドが上限(`#[derive(QModelItem)]` が 16 個目を拒む)— 席は `row_width` を落として空けた。`matchCount` はプロパティ(スロット戻り値だと背景 refresh の marking し直しでバーが古い数を握る)。`qproperty!` に doc コメントを付けない(ビルドが落ちる)
- marking は splice の前に(`mark_incoming`)— 後から marking すると誰も描いていない行に変更通知が飛び、検索中に届いたチャンクが 1 フレーム暗く出る
- 暗く落とす対象は規約 §暗く落とした段が正。レーンは落とさない — ノードと同じ Canvas なので `onPaint` 内で手前だけ `ctx.globalAlpha` を落とす(co-author バッジの `destination-out` は必ず 1 に戻してから — 暗い消しゴムは author の顔を透かす)。`dimmed` が動いたら `requestPaint()`(ロールが動かず他経路では再描画されない)
- 暗くする条件は件数でなく「探しているか」(`findOn` / `searching`)— 0 件なら全行が落ちるのが正(規約 §コミットを探す)。判定はモデル = `platitude-core::find` の 1 つ、QML に 2 つ目を書かない
- `findClears`(規約 §コミットを探す)の判定は `firstMatched` の 1 つ — 「木が汚れているか」を別に訊かない(WIP 行は `find::Query::matches` が必ず false)。ヘッドレスは `clears=`(意図)と 300ms 後の `find_settled shift=`(実測)の 2 行 — 同じ行に `shift=` を出さない(アニメ前で必ず 0 = 意図を実測に見せかける行になる)
- 検索の選択移動(`findLanded`)は一致行が変わった時だけ — `selectRow` は 3 spawn を連れてくるので打鍵ごとに撃たない
- 上下矢印は `GraphPane.stepRow()` の 1 本。`Keys` は `graphList` に置く(検索バーはリストの兄弟で、そこへ打つ矢印はペインに届かない)。`keyNavigationEnabled: false` — Qt 既定のキーナビは `currentIndex` を黙って動かし、`highlightFollowsCurrentItem: false` と組むとハイライトだけが画面外へ歩く

- ゲートは `mainUi` の兄弟で、`AutoShotDriver` は出ている方を掴む(`gate.visible ? gate : mainUi`)— 無いとゲートで終わった run が「なれなかったアプリ」を撮る。ヘッドレスは `solo`(仕込み・`blocked=true` の判定は verbs.md)
- worktree ビルドは右下の git バージョンの隣に自分のツリー名を出す(`AppBackend.buildTree`)。環境変数でなくビルドパス(`CARGO_MANIFEST_DIR`)から採る — 印がファイルと一緒に動き、素の checkout / 配布ビルドには最初から付かない。起動時に `build tree tree=` を 1 行ログ(窓の出ない run でも stderr で判る)
- その隅の文字はファイル一覧が届いたら退く(判定は `bottomRoom` と `roomNeeded` の比較 1 つ)。上に自前の空気を足さない(ユーザー判断 — 行は自分の高さで既に空いている)。ここは `visible` でよい — 隠れた `Label` も implicitHeight を保つ(隠れている間に届いた text も込み。qmltestrunner 実測 2026-08-10)。`z: 1` は退いた後の並び順を次の住人へ保つため。ヘッドレスは `corner`(使い方は verbs.md)
- アプリメニュー(ハンバーガー)は `offer()` でなく `open()` で開く — 固定行で空になり得ず、`offer()` の引数なし `popup()` はポインタ位置に出して `y` の座席が失われる(右クリック系は `offer()` のまま)
- サイドバーの行は持たずに射影する(`NavSectionModel` = `QAbstractItemModel`。`QListModel` は `get` が実体への参照を返すので `Vec<NavItem>` の実体化が必須だった)。実測(`JetBrains/kotlin`): `nav-tags-all` 12,315,139 B / `nav-remotes-all` 2,263,852 B → どちらも 0。罠 3 つ: ① ロール名を 1 つ間違えるとデリゲートは黙って空を描く(警告なし)— `Role` の綴りと番号はテストで突き合わせる ② `Arranged::At` の `from` は refs と worktree のツリーで答えが違う(置いた側が書く) ③ WIP の `MM` は 2 行(バケツ + エントリ)なので並び順は到着時に 1 度だけ作る(`Source::files`)
- 同じ内容の再公開では行を建て直さない(`NavSectionModel::take` がエントリ同士を比較 — poll は動かなくても再公開する)。比較は届いた側の型で(行を建ててから比べると捨てるためだけに 12MB 確保)。新しいハンドルは動いていなくても受け取る — 古い `Arc` を握ると同内容のスナップショットが 2 つ生きる
- モデルのメモリは `crate::memprobe::note()` を drain の末尾に(`PG_MEM_REPORT=1` の時だけ O(行数))。1 行にまとめるのは `AppBackend.noteMemory()` — そこでしか同時に読めない(Hub は thread_local・モデルは QML 所有)。内訳の読み方は rules-refs/core.md の同項
- qmlcachegen はメモリ対策にならない — 測って見送り(2026-08-11): qrc の QML はディスクキャッシュに載らない(タイムスタンプ無し = 60 ファイル毎起動コンパイル)が、AOT で動かせるコンパイル単位は計 1.34MB = 予算の 0.4%。窓の 32MB は実体化したオブジェクト木。起動 883–1,171ms / 予算 3s で build.rs 導入の理由にならない
- `Qt6Network` / `Qt6Svg` は見送り済み(2026-08-11)。`Qt6Network` は `Qt6Qml` / `Qt6Quick` の静的インポート(dumpbin 確認)で外せば起動不能 — 通信禁止には「載っているが使っていない」が正。`Qt6Svg` は imageformats が引き、天井 0.65MB = 予算の 0.2%。`QT_PLUGIN_PATH` で外す A/B は成立しない — 既定の探索パスへ追加するだけ(実測で踏んだ)。外すなら exe の隣の `qt.conf` の `[Paths] Plugins=`(一式が欠けると窓が上がらず app-side watchdog も起動しないため、parent kill guard が最後の境界)
- ロードされない同梱物を除いてもメモリに効かない(2026-08-11 実測: `qmltooling` / `tls` / `networkinformation` / `opengl32sw` / `d3dcompiler_47` / `dxcompiler` / `dxil` / `qtuiotouch` / `qsvgicon` / `Qt6QuickShapes` はどれもロードされず計 24.9MB)— 配布物のサイズと攻撃面の話で `windeployqt` の採否は P5(候補は windows-x64.md §3)。`opengl32sw` と shader compiler の除外は robustness を削る — この開発機でロードされない ≠ 不要
- 長押しの状態機械は `HoldDriver` 1 部品(`ActionButton` / `AppMenuItem` / `AskBar` / `OpExitRow` は身振りと絵だけ・`holdProgress` は readonly alias)— 塗りを直す時にファイルを 4 つ回らない
- diff の行の色は Rust の markup を `Text.StyledText` で出す(`encode::styled` / `DiffRow.rich`)。素の StyledText は HTML と同じ空白処理で先頭の字下げを全部捨てる(2026-08-12 実測: 0 空白と 4 空白が同じ x に着く)— 空白は `&nbsp;`・タブは 4 桁のタブストップまで展開(`encode::push_escaped` が `&` `<` `>` も実体参照に)
- `<pre>` で包まない(A/B で確認)— Qt は `<pre>` の中身を別フォントに差し替え、同じ色指定でも diff の文字だけくすんで見える。「色が薄い」はまず色でなく描画経路(`<pre>` / リッチテキスト)を疑う
- 行は plain と markup の 2 本を持たない(`DiffRow.rich` がどちらかを名乗る)— 長い diff のメモリが倍になり、plain を読む者は居ない
- コンフリクトのマーカ行は `textMuted` に落とし背景は追加行のまま(`DiffRow.fence`)— git の足場を追加行の緑で塗ると誰も読まない部分が一番大きな声になる。背景を残すのは実際に作業ツリーへ入っている行だから。`markers`(combined の列)とは別物 — あちらは「どちらの側から来たか」
- hunk 見出しの Label は `hunkTools.visible` の時だけ右端の `Discard hunk` / `Stage hunk` へ幅を明け渡す(`@@` 行は signature ぶん長く、明け渡さないと重なる。フォントの段は規約 §タイポグラフィ)
- hunk 見出しは行の左端から・行番号列は数字に合わせて切る(規約 §diff の中のステージ / §レイアウト初期値。2026-08-13 ユーザー指示)。列幅(`DiffPane.numberColW`)の measure は隠し Label — `TextMetrics` は数 px 狭く出る(`ActionButton` / `TopBar` と同じ)。行の印(`+` / `−`)の席は空の `Item` で幅だけ確保し、印自身は Row の外に置いて `x` で座らせる — Row の中へ入れると後から宣言の `lineHover` にクリックを取られる
- verify-ui の固定 shot clock 廃止(2026-08-16): page current の claim が無いと新規 tab が同じ動詞を再実行し、page / window の完了競合は中間状態を撮った。全動詞を 1 owner の causal completion にし、window-level 動詞は page を defer、`AutoShotDriver` だけが最終撮影を所有する
- offscreen の描画完了は `frameSwapped` 単独で待たない(2026-08-16 並行実測: `signature-tip` が状態完成後も 2 回無発火)。`requestUpdate` → event-loop turn → app / overlay の `grabToImage` callback を最終境界にする
- readiness の初期値は出力ではない(2026-08-16 実測: `wip` が一覧ロード前の 0 件を clean と誤認して PASS、PNG は変更 0 なのに graph は +1/-2)。`WorkTreeModel.loaded` のような answer edge の後だけ 0 / false を判定する
- polling より短い状態は edge を latch する(2026-08-16 実測: command/fetch の error と force-push の busy が 25ms sampler の間に立って消えた)。error 回復は「立った証拠」と最終 quiet の対、通信中の絵は実 busy/loading edge でだけ latch し、画像 callback 完了まで表示を保持する
- verify-ui の明示リソースは排他(2026-08-16): 同じ `--repo` / `--config-dir` / `--shot-dir` の並行利用は Git 書換え・state・PNG を混線させるため、target 外の atomic lock で fail fast。既定 path は pid + time + serial の名前だけでなく `create_dir` 成功を ownership edge にする
- cross-harness 回帰(2026-08-16): app 側の固定 quit 依存を verify-ui から外した際、`perf` / offline smoke の非因果終了経路まで失われた。offline は `PG_AUTO_ACT=band` + app watchdog + 親 `timeout`、perf は `perf_done` + 親 watchdog とし、因果撮影の完了判定へ戻さない
- 性能測定の 12 秒窓は入力サンプルの範囲として保持するが、起動からの固定 quit は成功条件にしない。`perf_done` と親 watchdog がプロセス寿命を判定し、raw worktree app 起動は offscreen 環境変数だけでは許可しない
- harness 間の環境汚染(2026-08-16 review): `perf` / verify-ui / offline smoke は親 shell の別 `PG_AUTO_*` を継承すると二つの完了 protocol が同居する。automation env を一度全除去して所有分だけ設定し、offline の config も `mktemp` 配下に分離する
