# platitude-core 各論(複数の操作に効く git の実測挙動・実装の型)

[.claude/rules/core.md](../rules/core.md) の参照資料 — **1 項目 1 行**。置くのは複数のモジュール・呼び出しに効く git の挙動と実装の型だけ。**1 つのモジュール・関数・コマンドの決定と罠はそのコードのコメントが正本** — ここへ足さず、名前で Grep してコードを読む。
最低版に対する互換性の確認記録と更新手順は [gitの扱い.md](../../internal-docs/gitの扱い.md) の参照先に集約する。

## git サブプロセス規約(各論)

- **stdin を渡すのは、読む物として stdin を名指すコマンドと、git が渡す stdin を子が読むコマンドだけ**(`GitCommand::input` → `process::Input`。今は `commit --file=-`(`commit::commit`)と `apply … -`(`stage::partial` の部分ステージ・部分破棄、`discards::restore`)。最低版 v2.43.0 の Documentation に `-F -` / `<patch>` の `-` あり。子が読むのは interactive rebase のプランで、sequence editor は rebase の stdin をそのまま渡される — `sequencer::run` のコメント)— 他は閉じた stdin(対話の問いは即 EOF)。**ファイルで渡す物**(`scratch::ScratchFile`)は一時の index だけ。送り方・止め方(送信は stdout / stderr の読みと並行、送信の失敗・キャンセル・時間切れでは stdin を開けたまま git を終える)と Linux のパイプ幅は `process::child` のコメント、入力付きを背景で共有しないのは `GitExecutor::run_shared`。**`child::ending` は中身の無い観測点で、「テストの差し替えは mry」(本体には属性まで)の例外** — 停止の順序の網のためだけに置く
- **コマンドログは executor の observer 1 本**(`process::CommandObserver` + `process::Kept` の 3 ハンドル)— 分類は `session::write::run_write` の 1 箇所: 利用者用 `Asked` / 背景の読み `Unasked` / 頼まれていない fetch `UnaskedUnlessItFails`(行になるのは git が断った時だけ)
- **設定ファイルを開けなかった読みは executor が 1 回だけ撃ち直す**(`process::config_unread`)— **読みのサブコマンドを新しく撃つなら `reads_only` に足す**(足し忘れは撃ち直しが効かないだけ。枠・ログの行・`GitError::ConfigUnreadable` はそのコメント)
- **`&str` をバイト長で切らない** — キーの前方一致は `as_bytes().get(..KEY.len())` + `eq_ignore_ascii_case`。`l[..KEY.len()]` は多バイト文字を跨いだ瞬間に落ち、walk のワーカで落ちるとグラフはリングのまま無言で止まる(「サイドバーは出るのにグラフだけ空」はまず stderr のパニック)
- **パスは `:(literal)` で包む**(`process::literal_pathspec`。`GIT_LITERAL_PATHSPECS` を使わない理由と `--no-index` の例外はそのコメント)
- **`git stash pop` の非ゼロは「無処理」を意味しない** — 作業ツリー conflict はマージ済み+stash 残置、staged 衝突は丸ごと拒否(`conflicts in index. Try without --index.` → `--index` 無しで再試行)。判定は unmerged の有無 — ただし元の木に unmerged が在れば pop は丸ごと拒否(`needs merge`)で残る conflict は元のものなので、前後で見る(`RepoSession::stash_pop`)
- **退避の可否は `stash::standing` 1 本で決める** — `git stash push` は unmerged が 1 本でも在れば、パスを名指しても丸ごと拒む(実測と文言は `StashStanding::Conflicts`)
- **終了コードを自分で読むコマンドには `answers_by_code(<答えのコード>)` を付ける** — config の読み取りは `--get` / `--get-regexp` とも全部(未設定 = exit 1 = 答え。網は `tests/it/config_reads.rs`)。各コマンドの答えのコードは付けた箇所のコメント、網は `tests/it/answer_reads.rs`。**`cat-file` は読む前に `rev-parse --verify -q <spec>` で訊く — 無い側は exit 128 で 0/1 の枠外、しかも「リポジトリが無い」も 128 なので枠を広げると本物の失敗が消える**(実例と `--batch-check` を採らない理由は `preview::blob_is_there`)
- **答えのコードは 1 とは限らない** — `config --unset <key>` は「元から無い」を exit 5 で言う(ファイルが無い時・キーが無い時・multivalue で消せない時が全部 5、実測 2.55)。枠はそのコマンドの 5 だけ — コードの意味はコマンドごと(1 で印を付けた時の害は `conflict::set_merge_tool`)
- **`stash` の断りの終了コードは 2.55 まで 1、2.56 から 128**(`786fc39046 stash: reserve exit status 1 for conflicts` —— 1 は衝突だけ)。呼び手はどれも終了コードの値を見ず 0 以外を一様に扱うので、着地は版で変わらず、変わるのはコマンドログの行だけ(呼び手ごとの扱いは `stash::pop`)。テストは終了コードを言い当てず「0 以外の `Exited`」を主張する(`carried_apply::a_failed_row`)
- **`stash apply` / `pop` には `--no-index` を必ず渡す**(2.52 からの `stash.index=true` が apply / pop を `--index` にする — `stash::pop`)。**`stash apply` は追跡分を当ててから untracked を戻し、untracked の置き場が埋まっていると追跡分を当てたまま断る**(断りとロックの見分け・untracked を後から戻す形は `session::carried_apply` と `report::carried_refused`)
- **git を撃つ前にこちらが断る書き込みは `GitError::Withheld`、UI が先に止める残りは `GitError::Rejected`**(使い分けの理由はその型のコメント。個別の箇所は Grep が正)
- **`rev-list --exclude` は名前空間を外して書く** — `--branches` に `refs/heads/` を付けると何も除外されず「他の誰かが掴んでいる」が常に真(エラーも警告も無し)。`--tags` / `--remotes` も同様。`--glob` / `--all` だけ `refs/` 始まり
- **`--glob=<pattern>` は階層にしか当たらない** — `--glob=refs/stash` は 0 件(`refs/stash*` なら拾う)。素の rev `refs/stash` は stash 無しで `fatal: ambiguous argument`、`--ignore-missing` は間違った oid も黙って捨てる = 安全側と逆。`reachable::command` は `--glob` を採る
- **`--all` で HEAD は外せない** — `--exclude=<現在のブランチ> --all` でも先端が negative に残る。外したい walk は `--branches --remotes` を並べる
- `git config <key> <value>` はダッシュ始まりの値もそのまま(`--` は値として保存される)
- **`config --get-regexp` は低いレベル順・実効値は最後の行** — 1 件目で判定すると system が常に勝つ(Git for Windows は system に `core.autocrlf=true` を書く)。単一キーは `--get`、複数キーは最後の出現で上書き読み。TestRepo が隔離するのは撃つ git だけで、コード側は開発機の system / global を見る

- **「そのリポジトリ自身が何を書いているか」は `--local` でしか読めない**(`config::get_regexp_at`)— 実効レベルの `--get-regexp` はどのファイルの record かを言わないので、継承しているだけの値と自分で書いた値が同じ姿で届く。書き戻しの読み直しも `--local` 側で読む
- **`--local` の書き込みは「今の値を先に読んで、違うキーだけ撃つ」**(`identity::write_local_pair`)— 空欄 = `--unset` だが、`--unset` の「元から無い」と「多値なので触れない」は同じ exit 5(実測 git 2.55。git の doc は 5 と 6 に分かれると書いてあるが分かれない)ので、先に読まないと本物の失敗が無害な答えに化ける。**`--local` は set 側にも明示する** — 素の `git config <key> <value>` / `--unset` も既定でローカルに書くが、読む側と書く側が同じ語を名乗る形にしておく
- **`ls-files --eol` は作業ツリーの実ファイルを読む** — グロブ渡しは基準リポジトリ級で数十秒。候補列挙(索引のみ)と `--eol`(確定した数パスだけ)を必ず別コマンドに分ける。未チェックアウトは `w/` が空
- **作業ツリーの diff は index 空間で出る** — `autocrlf=true` でも patch に CR は現れず `apply --cached` / `apply -R` が通る。index blob に CR があるファイルは変換されない = 設定切替で全ファイルが modified にはならない
- **`git apply` の exit 1 は「点検で断った・何も書いていない」**(`--reject` / `--3way` を付けない時。`check_patch_list` の失敗 = `patch does not apply` / `does not exist in index` / `No such file or directory`)、128 は patch が壊れている・書き込みの失敗・lock。**動いたからとは限らない** —— 文脈の無い hunk はファイルの途中には当たらない(何も動いていないのに exit 1)。部分ステージ・破棄がそれをどう読み分けるか(読み直し・動詞ごとのロックの報せ・untracked の照合)は `stage::partial::apply_partial` / `apply_built` と `stage::refusal::locked_out` のコメント

- **実行枠 `process::Slots`** — spawn 直前に `acquire` して reap で Drop が返す(`GitExecutor::execute` の中だけ。上の層は枠を持たない = 複合操作が枠を跨いで待つ形が作れない)。プールは 1 つ・click の予約付き(`Limits::of(n)`): 予約は interactive かつ `Pace::Here` だけが取れ、`Pace::Elsewhere`(fetch / push / ls-remote / clone / mergetool / 署名検証の gpg)と `Priority::Background` は残り `max(1, n/4)` を分け合う。**優先度はハンドル側**(`GitExecutor::background()` = セッションの `exec_background`。poll 自身の読みは interactive のまま)、**ペースはコマンド側**(`GitCommand::paced_elsewhere()`)。待ちは token で終わる。数の根拠・却下した別プール案・aging・同一の背景読みの相乗り・既定値と床は `process::slots` のコメント。網は `process::slots` の単体 + `tests/it/slots.rs`
- **`CommandStarted` は「訊かれた」であって「並んだ」ではない** — observer へ告げるのは `Slots::acquire` の前(位置は仕様。`GitExecutor::execute` のコメント)。並びを待つ時の観測口は `Slots::settled`(取りこぼさない取り方と順序の網はそのコメント)
- **書き込みの失敗の分類を足す・変える前に、読む文を形(`Words`)として `platitude-core/src/relied_messages.rs` に足して <!--cmd:relied-messages.audit-->`cargo xtask relied-messages audit` で全リリースの行を記録する**(出所の `- git:` と証人の `- witness:`。同じことを言う別の形はメッセージ(`Relied`)の束に並べる —— 版で分岐しない。分類器は表の判定を呼び、自前の文字列を書かない = 機械化済み `cargo xtask structure`。見るのは `said` / `stderr` / `stderr_utf8` / `failure_message` を名指す関数なので、git の文を受ける引数・変数はこの名で受ける。git の文でない文字列は `// not git's words: <何か>`。最低版と最新版の両端だけでは途中の保守版・Git for Windows の変化を見落とす —— 文・終了コード・どの stream かは記録の時代の境目で確かめる。手順は `internal-docs/gitの扱い.md` §git の文言に依存する判定)。使い捨てリポジトリで再現して `tests/it` に固定してから分類器を書く。類型は分類器のコメントに場面・頻度と出し先を書く(置き場は `internal-docs/gitの扱い.md` §類型 の索引)。**分類器が読むのは `LC_ALL=C` の固定の語・終了コード・push の ref 行だけ** —— 向こうの `remote:` 行は向こうの locale なので、サイズとロックの見分けの補助にしか使わない(他の言語で来たら分類の無い側へ落ちる)。**分類は 2 行目を選ぶためだけ**で、誰の文も報せへ運ばない(`WriteReport::fact` はロックの理由と残ったブランチだけ)
- **報せが名指す原因は git の文か git 自身の記録が言うことだけ**(ユーザー決定 2026-10-11)。git が語を足さない断り(commit・push・駆動 rebase・worktree add のフック、ssh の署名プログラム)は **trace2 で読む**(`GitCommand::traced` → `GitOutput::trace`。受け口の作り・記録をディスクに置かない / 記録付きの git から fsmonitor を外さない(どちらもユーザー決定)・数える git の範囲は `process::trace_sink` / `process::trace` のコメント)。**フックの終わりは git の語より先に見る** —— フックの出力は git の stderr に混ざり、フックが走らせた git のロック・署名の語も載る。git はフックが断ったコミットをそれ以上作らず(commit は index のロックをフックの前に、署名と ref のロックを全フックの後に取る)、push は pre-push を署名と送信の前に走らせる。**フック・ロックファイルの在処で推さない**(在っても断った理由とは限らない)。名指せない断りは `git turned it down — see GIT COMMANDS`

- **ロックと言うのは git がロックを名指した時だけ**(判定は `report::lock_taken` の 1 か所。語・`core.lockfilePid`・名指さない場面と網はそのコメント)
- **`cat-file --batch` の常駐は保留・設計済み**(設計は P3-確認事項 §core)
- **Windows のテストの一時フォルダは 8.3 の短い名前で来る**(`tempfile` → `C:\Users\XXXXXX~1\…`)—— git の一覧(`worktree list`)は長い名前で、`same_path_key` は同じと見ない。画面がパスを git の一覧から取る操作は、テストも一覧のパスで撃つ(短い名前で撃つと記録の経路を通らずに緑になる)

## セッション・実装の決定事項(各論)

- **破壊的な書き込みを足したら、破棄記録に載せるかを決めて書く**(`discards` の冒頭の Listed / Not listed に 1 句、載せる物は `session::discard_record` が書き込みの前後に記録を置く)— 一覧は手で保ち、機械は確かめない
- **git を撃つ前に答えが出る分岐は `#[cfg(test)]` の単体テストへ**。**証人を 2 つ置く** —— `CommandObserver` の `started` を数えて 0 と、在りもしないプログラム名 + 在りもしない木(すり抜けた分岐は spawn で落ちる)。先例は `stage::partial`。**統合テストに残すのは git が答えてから断る側**(fingerprint のズレ・combined diff・実際の patch 適用と復旧)
- **読みの並びの後の判断は純関数に割る**。先例は `remote::push::decide_push`。**統合テストに残すのは「読みが git の持ち物を持って返るか」**(scope・正規表現になる名前・実 push の代表例)と、`config_reads::planning_a_push_answers_by_code`
- **同じ割り方の 2 例目・3 例目**: `identity::local::keys_to_write`(組合せ全件が単体、実 git に残すのは**発行されたコマンドがその判断どおりであること**)/ `sequencer::plan::decide_edit`(**拒否の順**は単体。実 git に残すのは shallow clone の縁が縁として返ること)。**割る前に測る対象は「その判断 1 通りあたり何プロセス・何リポジトリか」** —— 純関数を足しただけで元の統合テストを全部残すのは未完了

- **メモリの内訳は `cargo xtask perf --breakdown` で出す**。撃ち方と記録の置き方は [internal-docs/性能.md](../../internal-docs/性能.md)、実測記録は [ci/baseline/perf-windows-x64.md](../../ci/baseline/perf-windows-x64.md)
- **refs に比例する名前は `crate::Name`(`compact_str`)で持つ** — 24 バイトまで inline(`Footprint` の `SmallVec` の罠は `mem.rs` のコメント)
- **バイト数より確保の個数が効く帯がある** — 個数の削減は計数より WorkingSet に大きく出る(差はヒープ管理領域。計数アロケータには見えない)。`classes=` の**件数**を必ず見る
- **mimalloc は不採用** — WorkingSet が増え(環境変数で抑えても private が増える)、起動・応答に差なし。数字は [perf-windows-x64.md](../../ci/baseline/perf-windows-x64.md) §アロケータと確保の個数
- **refs に比例する常駐データは平らな索引 1 本で持つ**: `BTreeMap` は 1 件でも 11 スロットのノード(→ `RemoteTagIndex`)/ `HashMap<K, Vec<V>>` は push 1 回で 4 スロット(→ `LabelIndex`)/ hex 40 字の `String` は 1 行 1 確保。`String` → `Vec<u8>` では 1 バイトも減らない — 減るのは表現を変えた時だけ
- **メモリ予算の半分は空リポジトリで既に埋まっている**(`--no-open` — ci/baseline/perf-windows-x64.md。Rust ヒープは 1.2MB)。software 描画は fps が予算割れ(GPU −25MB でも)

- interactive rebase は `GIT_SEQUENCE_EDITOR` に別実行ファイル `pgg-todo-editor` を差す。**配布物に同梱必須**(本体と同じディレクトリ)
- **rebase・merge・pull は全部 `--no-autostash`、push は全部 `--no-follow-tags`** — 利用者の `rebase.autoStash` / `merge.autoStash` / `push.followTags` を釘付けで外す(理由と網は `integrate::rebase_command` / `integrate::merge` / `remote::pull` / `remote::push::porcelain_push` のコメント)
- **テストが差し込む実行ファイルは rename で置く** — Linux は write fd の下の exec が `ETXTBSY`(Windows では出ない — `cargo xtask linux` でしか観測できない)。手順と罠は `tests/it/support/session.rs` の `install_todo_editor` / `publish_helper` のコメント
  - **fork が継承した write fd は rename では防げない** — exec 側で `ETXTBSY` をリトライする(core のテストは `support::busy::run_once_it_is_not_busy`、xtask のテストは `output_past_a_busy_image`)
  - **Windows は走らせた直後の複製への書きの open を稀に拒む** — 握り手は未特定。書きで開く側は `open_past_another_holder`(`tests/gate/stamps.rs`。観測はそのコメント)を通す
  - **lock は unlock で離す** — `flock` は fork が複製する open file description に付くので、close だけで離すと隣のスレッドが fork した子の `execve` まで残る。**離す型は `xtask::locks::Locked`**、core は `settings::lock::Lock` の Drop(順序・待ち・網は `xtask::locks` のコメント)
  - **lock ファイルは握ったまま消し、取る側は名前が残っているか確かめる**(理由と OS 差の無さは `still::lock_beside` のコメント)。**名前が共有の lock ファイルは残す**(`still::Name::Shared` / `verify::ownership`)

- **integration test の Git 環境は executor ごとに隔離する**(rules/core.md §非同期・並行テストの実装方針)— 入口は `support::exec::isolated`(`GitExecutor::with_env`)、`TestRepo` の setup Git も XDG を自身の temp 配下へ向ける。共有の executor は設定ファイルを持たないので、`--global` へ書くテストは `TestRepo::global_config` を `isolated_global` で(漏れた時の症状と中身は `support::exec` のコメント)
- **core と app のテストの一時フォルダは `target/tmp`**(core の結合 `support::temp::dir`・core の単体 `crate::temp::dir`・app の単体 `crate::temp::root`。ユーザー方針「書き込みはプロジェクトの下」= Defender の除外の内)。テストが起こす git は `support::temp::ceiling()` を持つ: `isolated_env` / `isolated_global` / `TestRepo::run`。git を起こす口を足したらそこにも渡す。単体テストのフォルダでは git を撃たない。**フォルダはテストの終わりに消える物だけ** —— session は support の `opened` 系が返す `TestSession` で持ち、終わりに `close_and_wait().await`(**待たずに drop すると赤**)。close の後を見る主張は `close()` のまま書き、終わりに改めて待つ。**テストが頼んだ push / fetch は答えを待ってから閉じる**。子プロセスに使わせる置き場は親が原子的に作り、子の終了後に親が消す(先例 app の `encode::wire_qml`)。理由は `support::temp` / `TestSession` のコメント
- **テスト用の窓口はセッション構築時の seam で渡す**(先例 `PassHooks` を `RepoSession::open` の引数で)— `RepoSession` に置いた test-only のスロットは Mutex として全セッションに常駐する(app 側で qslot が feature 無しでは何もしない形は `GraphModel.failGraphPass` のコメント)
- **表示更新はポーリング**(watcher 不採用: WSL / ネットワークで通知が来ない)。契機・間隔・他の worktree の読み方は `session::pace`(規則)/ `session::pacer`(駆動)のモジュール文書
- **git を撃つ頼みは種類を名乗り、種類が門を、待つ人が優先度を決める**(`session::asks` の module doc に表)— 実行(書き込みの列)/ 追従・畳む(`Coalesce`・`ReadFlight`)/ 追従・乗っ取る(`Takeover`、連続で止めるのは `TAKEOVER_STREAK` まで)/ 最新(`Latest`・`DiffEpoch`、失敗は待ちを見せている画面にだけ答える)/ 一度(`Derived`)/ 機会(`Coalesce::try_turn`・素の `try_acquire`)。**捨ててよいのは次の拍が必ず来る機会だけ**、追従は最後の状態を必ず読む。新しい読みは門をこの中から選ぶ(素の semaphore を足さない)
- **同じ答えは git に 1 度だけ訊く** — HEAD は `for-each-ref` の `%(HEAD)`(`refs::head_in`)、リポジトリ全体の答え(`core.autocrlf`・remotes)は `Derived` の single-flight、walk の HEAD は `refs::head_tip` の oid 1 つ(破棄の時機と罠は各型・関数のコメント)

- **完了 ack は single-flight permit を返した後に送る** — `refresh_poll_tracked` / `refresh_remote_tags_tracked` の `outcome()` から即座に次を要求しても `Busy` へ落ちないことが契約。`WriteFinished` は Git command の終了通知で、後続の読み直しは含まない。**後続更新完了の境界は `WriteSettled { id, kind, failed }`** — queue idle が必要ならこれを待つ(`support::session::write_settled` が `failed` を返す)。含む読み・`failed`・各読みが失敗を返す型は `SessionEvent::WriteSettled` / `FollowUp` のコメント
- **tokio の時計は runtime の task の中で作る** — `Interval` / `Sleep` は作られた runtime の time driver を掴むので、runtime の外(UI スレッド)で建てると `there is no reactor running` で panic する(統合テストは全部 `#[tokio::test]` の中から呼ぶので気付かない)。clock は spawn した future の中で建てる(先例は `session::auto_fetch` の `IntervalClock`)
- **製品の clock の時間仕様は仮想時計で両端を固定する** — `#[tokio::test(start_paused = true)]` + `tokio::time::advance` で「間隔の 1 instant 手前で `poll_once` が Pending・間隔が出たら Ready」を 3 周見る(`session::auto_fetch` の `a_due_falls_at_the_end_of_each_interval_and_the_first_is_a_whole_one_out`)。実時間の下限判定では上側が見えない。`test-util` は core の `[dev-dependencies]` の tokio に足した feature で、crate は増えず製品ビルドには届かない
- **「開き終わりより前」を読むテストは current_thread ランタイムで縁を作る** — 既定 flavor の `#[tokio::test]` は spawn したタスクをテスト側が await するまで poll しないので、spawn 直後の問いは負荷によらず「まだ」を読む。multi_thread だと開き全体が次の 2 行の間に収まり得て、別の側を読む(先例は `session_integration::auto_fetch` の `an_ask_that_beats_the_opening_is_kept_for_it`)
- **flaky の反復 campaign は test binary を直接起動する** — Cargo 自体の build lock を並列性と取り違えないため
- **cleanup campaign の回数は対象 suite だけに払う** — 率を観測できた時は最低 10 回かつ概ね逆数の 3 倍以上、未知なら 10 回を入口にする

- **`periodic` = 日常の段に見合わないテスト** — めったに変えない約束を、OS の制約で時間のかかる読みで確かめるもの。実 git の結合テストのうち git の挙動そのもの(固定のコマンド行の後ろで git が書く物・断る文言・設定の効き方・製品が立てないオプション)を確かめる物もここ(ユーザー決定)。自前のコードの経路を反映前に通す唯一のテストは反映前の段に残し、兄弟か単体が同じ主張をしている物は削除、git に届く前に返る判断は単体へ(`platitude_core::refusing` — 何も起こせない executor と無いリポジトリ)。`mod periodic` に置いて `#[ignore = "<日常に見合わない理由>"]`。gate は段 3(`--whole`)でだけ `-- --ignored ::periodic::` の段を足す(`gate::plan::periodic_steps`)。手で回す時は `cargo test -p platitude-core --test it -- --ignored ::periodic::`(コンテナは `cargo xtask linux test …`)。**道具の `#[ignore]`**(fixture の再生成 `capture`・性能計測・子プロセスの入口)は `periodic` に入れない — 拾われて fixture を書き換える。実物の長い無言の 1 手を待つ所は沈黙予算でなく全体予算で待つ(`CaptureSink::wait_through_silence`)
- **テストの差し替えは mry**(`#[mry::mry]`。依存は platitude-core、ユーザー決定)— 本体に置くのは属性まで。テストのための trait・setter・引数を本体に作らず、属性で済まない時だけ例外として本体に口を足す。mock が入るのは debug ビルドだけなので、統合テストから呼ぶ `mock_<fn>` は `#[cfg(debug_assertions)] pub use` で外へ出す。**free 関数の mock も lock もスレッドごと**(mry の `static_mocks.rs` は両方 `thread_local!`。版は `Cargo.lock`)— mock を立てるテストは `#[mry::lock(<fn>)]` を持つ(無いと mry が panic する)が、lock は他のスレッドのテストを待たせない。mock の無いスレッドは実物を呼ぶので、実物を読むテストは何も立てなくてよい(`mock_<fn>().calls_real_impl()` は同じスレッドで両方要る時だけ)。**session に mock を見せるテストは既定の `#[tokio::test]`(current_thread)で撃つ** —— `multi_thread` だと worker が実物を呼び、mock は 0 回と言う(`lfs::runs` で実測)。mry は照合する引数を複製して持つので、借用で複製できない引数は `skip_args(<型>)` で外す
- **xtask の待ちは `crate::wait` 1 本から取る**(`Wait` / `Budget::SUITE` / `receive` / `stood`)— 天井の値は呼び手が理由付きで持つ(`still::SWEEP` / `watched::QUIET_CEILING` 等)。期限切れは `Expired` で失敗させる。例外は `stood` だけ(製品が立っている下限を見る `shipped` / `gui::launch` / Linux sampler の窓)。gate の統合テストは `#[path]` で同じファイルを読む(`tests/gate/main.rs`)ので、`wait.rs` の参照は `crate::` 抜き。**scanner は xtask の `src` ではツール本体も読む** — `crate::wait` の外の sleep(スクリプト文字列の `Start-Sleep` 含む)/ `Instant::now()` / `recv_timeout`(予算の名前に依らず)を名指し、`Wait` / `receive` / `stood` を通る文と `Duration` の宣言は通す。残す時のマーカーは本体も同じ 4 語 — 表示・記録用の時計は `measured`、sampler スクリプトの間隔は `paced`
- **シナリオの一部として天井を使う試験は、天井の起点を因果の駅に置く** — 起動から数える天井は、機械の速さが結果を決める。`wedge-check` の deadline スレッドは、止まれと注文した駅に着いた時点から猶予を数える(`harness::deadline::first_look`)。起動から数える天井は、駅に着かない run を刈る backstop だけ(`verify::faults::BACKSTOP_MS`)
- **イベントを出さない完了の await は `bounded` 必須**(`cargo xtask waits` が機械化)— tracked `outcome()` / `wait_for_graph_passes` / `wait_for_snapshot_reads` / ticker `tick()` は sink を通らず `Patience` が数えない。QML は 2 種類 — QtTest の `tst_*.qml` は `wait(ms)` / 独自 timeout / 裸の `waitForRendering`、アプリのハーネス `src/auto` は自分で綴った時間(`Timer` オブジェクト・`duration:`・`Date.now()`)と溜めた ms(`+= …interval`)を見る。天井の実装 `support/wait.rs` / `src/wait.rs` と scanner 自身の fixture は読まない
  - **ハーネスの Rust 半分 `src/harness` も本体まで読む**(xtask 本体と同じ規則 = sleep・単調時計・予算付き receive)。`Instant::now` は `()` 無しでも時計読み(`get_or_init(Instant::now)` の形)。PowerShell の `Start-Sleep` を文字列から拾うのは xtask だけ — ハーネスの文字列にあるそれは待ちではない。**どちらの半分も 1 ファイルも読めなかったら赤**(規則が何かを名指している証拠)
  - **製品本文に `// waits(` を書くと「何も覆わないマーカー」で赤** — 書けるのは試験装置の中だけ
- **イベント列は基準位置で切る** — `sink.events.clear()` は reader と競る(clear と次の待ちの間に届いた分ごと消える)。件数で待つ時は先に `len()` を控えて `evs[from..]` を読み、スナップショット数も base を控えて `settle(base + 1)` を待つ(`session_integration::query` の形)
- **C の build script は解禁(ユーザー決定)** — tree-sitter の文法 crate 群のため。画像経路が純 Rust である条件は platitude-core/Cargo.toml のコメントが正
- **baseline は開始条件を列挙して待つ** — `Opened` は path を受理しただけで、その後の refs / status / log は未完了。要求は前の pass を cancel するだけで、cancel は止まった証拠ではない(閉じる順と理由は `CaptureSink::opened_graph` のコメント)
- **完了境界を足した先例**(rules/core.md §正しさは因果で待つ): `RefreshTask` / `RefreshOutcome` / `RemoteTagRefreshTask`、タイマは `RepoSession::auto_fetch_ticker`。**複合操作の失敗後に走ってよい読み取り**の先例は `catch_up_after` の fetch(§複合操作は 1 手目が失敗したら止める)
- **`poll_once` で門に止める先例**(rules/core.md「競合の相手は手で目的の地点まで進める」): `state_tests` / `read_flight` の tests、`session_integration` の diff の読み。spawn した相手に到着を言わせる境界は `ReadFlight::wait_for_askers`
- **時間の仕様を固定する先例**(rules/core.md §時間の仕様は機能テストから外す): タイマの「間隔が来たら 1 回・停止が overdue の tick に勝つ・最初の tick は間隔 1 つ先」は `session::auto_fetch::drive_auto_fetch` / `AutoFetchClock` の単体テスト。統合テストは全 tick を `RepoSession::auto_fetch_ticker` で手で進める
- **`cargo xtask waits` が読む範囲**(rules/core.md §waits。名指す形の例: 答えを捨てた待ちは `let _ =`): 統合スイート + support・各クレートの `#[cfg(test)]` 区画(`mod` / `fn` / `impl`、`all(test, …)` / `any(test, …)` も。`mod x;` は `#[path]` まで追う)/ `*_tests.rs`・`tst_*.qml`。試験装置 = xtask の `src` と app のハーネス両半分(動詞の QML `src/auto` と、run を運転・観測する Rust `src/harness`)で、どれも本体まで読む。**製品本文は対象外**
- **偶発的な赤は再現条件と失敗を残して、当該変更で直すか専用 cleanup task に切り出す**。本格的な flaky cleanup task だけ反復 campaign を行う — 対象を再現に必要な最小 suite に絞り、観測された OS・runner の並走・負荷形態を含める。修正した実装ごとに 0 から数え、最低 10 回連続 OK。全 workspace / 段 2 は最後に 1 回
