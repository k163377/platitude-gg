# platitude-app 規約(Qt Bridges・QML 配線・意匠の実装対応)

app / QML のファイルを読み書きすると自動ロードされる。UI の色・寸法・用語の正本は [デザイン規約.md](../../internal-docs/デザイン規約.md)(QML を書く前に必ず読み、値は表から選ぶ)。core 側は `.claude/rules/core.md`、ヘッドレス検証の手順と `PG_AUTO_ACT` 動詞表は verify-ui スキル。

## Qt Bridges の要点(罠)

- main は `QApp::new().register::<Backend>().load_qml(include_bytes!("qml/Main.qml")).run();` の形。QML はバイナリに埋め込む
- `#[qobject]` は `impl` ブロックに付ける。struct は `Default` 実装必須。プロパティは `qproperty!("name", Member = field, Notify = signal)`、メソッドは `#[qslot]` / `#[qsignal]`。`ConvertToCamelCase` で QML 側を camelCase に
- QML モジュール名は Cargo パッケージ名になる
- 全 QObject は `Rc<RefCell<_>>`(メインスレッド専有)。**QML からの呼び出し中に再入 borrow すると panic** — 借用は短く保つ
- バックグラウンド → UI は `QObjectHolder::get_qml_method_invoker()` で得た `QmlMethodInvoker` をスレッドへ移動し `invoke_method*`(queued 実行)する。それ以外の経路で UI を触らない
- `#[derive(QModelItem)]` は非衛生的展開 — 使用側ファイルに `use std::collections::HashMap;` が必須。ロール名はフィールド名そのまま(snake_case)。`display` という名前のフィールドは Qt の display ロールに割り当てられる
- `QListModelBase` にバッチ挿入は無い(push/insert は 1 行ずつ)。大量追記は `try_get_rust_proxy_ptr()` + `base_begin_insert_rows(first, last)` + `Vec::extend` + `base_end_insert_rows` のレンジ挿入で行う(P0 スパイク `spike/src/main.rs` の `extend_notified` 参照)
- `ConvertToCamelCase` はスロット/シグナルのメタ名を camel 化する — そのオブジェクトへの `invoke_method!` も camel 名で呼ぶこと(混在事故を防ぐため、invoker で呼ぶ対象には付けないのが安全)
- QML モジュール名は既定で Cargo パッケージ名(ハイフン不可)だが、`#[qobject(NoQmlElement)]` + 手動 `impl QmlRegister`(URI 定数)で任意にできる
- Qt Widgets 不可・C++ 混在不可。必要になった時点で CXX-Qt 移行を検討
- 参照実装は公式 examples(`hello_world` / `minimal_app` / `host_monitor` = tokio 連携 / `color_palette`)。ドキュメント https://doc-snapshots.qt.io/qtbridge-rust/qtbridge/index.html / リポジトリ https://github.com/qt/qtbridge-rust / フォールバックの CXX-Qt book https://kdab.github.io/cxx-qt/book/
- **QML にビジネスロジックを書かない**(表示とインタラクションのみ。JS でのデータ加工禁止)— ブリッジ差し替え(Qt Bridges → CXX-Qt)を可能に保つための条件でもある
- `include_bytes_qml!("dir/file", "prefix")` は **prefix にファイルの相対パス全体を連結**する(qrc:/prefix/dir/file)。ソースのディレクトリ構造 = qrc 構造として設計する。qmldir も埋め込めるので QML singleton(`platitude.ui` の `Theme` / `Metrics`)はこの方式で成立する
- QML は `ui/` 直下フラットに 1 ファイル 1 コンポーネント(`platitude.ui` モジュール)。**新規 QML は qmldir と main.rs の `include_bytes_qml!` の両方へ登録**(qmldir があるディレクトリでは列挙された型しか見えない)
- コンポーネント配線規約: データは親→子へ property、操作・状態変更は子→親へ signal。タブのモデル群は `RepoPage` が所有しペインへ渡す(ペインはモデルのスロットを呼んでよいが、ページ状態は signal で上げて page が変更する)。ウィンドウ横断(タブを開く・settings・identity)は Main まで signal で上げる。`GraphPane.view` は自動化フック専用の露出
- QML の font 値型に `families`(配列)は無い — フォールバックは `Qt.fontFamilies()` と照合して Theme 側で 1 家族に解決する
- `grabToImage` は `Window.contentItem` には使えない("no QML engine")— QML 宣言したアイテムを対象にする
- **画面全体の入力観測は最前面オーバーレイ + `PointHandler`**(passive grab のみが仕様保証)。TapHandler は DragThreshold でも press を消費して下のコントロールへ届かなくし、contentItem 直付けでは手前の MouseArea が accept した press が届かない(2026-08-04 実測)
- **Flickable(ListView 含む)に宣言した子は contentItem に養子入りする** — そのままではコンテンツと一緒にスクロールして流れ去る。ビュー枠に固定するオーバーレイ(スクロール位置で出入りする現在ブランチ行など)は `parent:` でビュー自身を指し、描画も入力もデリゲートより手前に来る(2026-08-04 実測)
- **QML バインディングはプロパティにしか反応しない** — `#[qslot]` は呼び出し用。`enabled:` 等が値の変化を追う必要があるものは `qproperty!` にする(スロットのままだと初期値のまま固まる)
- **`palette` へのグループ無し代入は全グループを塗り、しかも後から上書きする** — disabled グループまで同じ色になり `enabled: false` が見た目に出ない。`disabled { … }` を足しても、グループ無し側がバインディングだと**そちらが後に確定して勝つ**(リテラル代入なら勝たない — この差で「単体 QML では再現しない」事故になる。2026-08-05 実測)。状態で変わる役割は `active` / `inactive` / `disabled` の 3 つ全てに書く(`Main.qml` の `palette`)。`contentItem` 自作のコントロール(`ActionButton`)は palette を通らないので自分で `enabled ? … : textMuted` を書く
- **メニューは `AppMenu` / `AppMenuItem` / `AppMenuSeparator` で書く**(素の `Menu` を使わない)。Fusion の素のメニューは**幅が中身によらず 200px 固定**(背景 Rectangle の implicitWidth。contentItem の ListView は implicitWidth を持たない)で長い文言が無言で省略され、**地は `palette.base` = グラフと同色**で枠も見えない。`AppMenu` は最も広い行に幅を合わせ(上限はウィンドウ幅)、溢れた行だけ省略して hover で全文を出す
- **右クリックのメニューで行の可否を書くのは `AppMenuItem.offered`(`enabled:` ではない)**(規約 §メニュー = 選べない行は消す)。**`visible` を判定に使わない** — 閉じているメニューの ListView は行を release して visible を落とすので、**開く前に読むと全行が非表示に見える**(`offer()` が「1 行も無い」と判断して永久に開かない = 実測で踏んだ)。`offered` は誰も触らないので閉じていても正しい。幅・チップ列・長押しの字下げも `offered` で数える。サブメニューは `AppMenu.applies`(Menu の `visible` は「カードが画面に出ている」の意味なので使えない)
- **メニューは `popup()` ではなく `offer()` で開く** — 出す行が 0 なら開かない(空のカードを出さない)。**行の可否はメニューを開く関数で 1 度だけ決めて `page` のプロパティに置く**(`menuCanSwitch` / `menuFileCanWrite` 等)。生の条件を `offered:` に直接書くと、タイマの fetch が `busyCount` を動かした瞬間にポインタの下で行が出入りする
- **区切りは `AppMenuSeparator` が自分で決める**(使う側に `visible:` を書かない)。`AppMenu` が `Component.onCompleted` で自分自身を各区切りの `inMenu` に入れる(MenuSeparator には `MenuItem.menu` に当たるものが無い)ので、**AppMenu のインスタンス側で `Component.onCompleted` を書かない**(奪うと区切りが親を見失う)。判定は「すぐ上の group に行が残っている」+「下にまだ行がある」= 端の線も、group が空になった時の二重線も出ない。**引かない時は `implicitHeight` を 0 にする**(ListView は高さで並べるので、消えても高さを持つと穴が残る — `AppMenuItem` と同じ)
- **`ListView.highlightFollowsCurrentItem` は false にする** — 既定の true では `currentIndex` を動かすだけでビューが追いかけ、背景更新で選択行が 1 つずれただけでも履歴を読んでいる人の視界を選択位置まで飛ばす。行の入れ替えでコンテンツが N 行ずれる分は `GraphPane.shiftRows()` で contentY を戻す(**レイアウト前なので 1 拍遅らせる** — 直後は contentHeight が旧値で clamp に食われる)
- ブリッジは **Qt Bridges 採用で確定**(Phase 0 スパイク合格)。CXX-Qt へ差し替え可能な構成を維持。スパイクコードは `spike/` に残置
- UI は [internal-docs/デザイン規約.md](../../internal-docs/デザイン規約.md) が正本(Theme.qml と Main.qml 冒頭定数ブロックはその写し)。グラフ・インタラクション定数とレイアウト初期値は **2026-08-02 の UI 基準確定で規約へ昇格済み**

## 配線済み操作の意匠と実装対応

- **配線済み**: ステージング(ファイル / hunk / 行)・commit / amend・switch(ローカル / リモート。**行き先は必ずブランチで、detach する導線を UI のどこにも置かない** — `CheckoutTarget` に detach する行き先自体が無い。ブランチの無いコミット・タグを指した時は `Create branch here?` の入力欄になる。**ただし git が置いていった detached HEAD からは表示も操作も普通に働く**(抜ける道は switch とその入力欄の 2 つ。ブランチが要る操作だけ無効)。未コミット変更は**必ず持っていき、何も尋ねない** — git が拒否したら core が stash → switch → `stash pop --index` で回り直す(`session::carry_across`)。conflict しても専用の表示は無く、conflict の付いたファイル行になるだけ)・fetch(手動 + auto)・push / force push・単体 cherry-pick・単体 squash・コミットメッセージ編集・amend での著者引き継ぎ(HEAD の author が現在の identity と違う時だけ出す)・reset(soft / mixed / hard。ブランチがある時だけ・進行中操作なしの時だけ出す。サブメニューの親行が `reset` \<branch\> here を名乗り、各行はフラグ(`--soft` 等)のチップ + 説明文 — チップ列は幅を共有して文の頭を揃える。**hard はバーではなくサブメニュー行そのものの長押し** = stash 削除と同じ意匠)・stash push(作業ツリー全体は WIP ペインのオプションカード / ファイル行の右クリックで 1 パスだけ)・discard / clean(ファイル行の右クリック。下記)・identity・署名の表示(詳細ペインは検証結果を 3 つに畳んだ 1 語 + 無署名は無表示、コミット欄は `commit.gpgsign` が効いている時だけ `will be signed`。規約 §署名の表示)・設定(auto fetch 間隔)・diff プレビュー(画像は Before/After 描画、非画像バイナリはサイズ表示 — `platitude-core::preview`)・コマンドログ・初回 push・stash の Apply / Pop・ブランチ / タグ / stash / リモートブランチの改名と削除・タグのリモート状態バッジ・co-author の表示・著者のアバター・設定 / 画面状態の永続化(**この 7 つは下の各項が意匠と実装対応を持つ**)。**この一覧が配線済み操作の正本**(CLAUDE.md は未配線だけを持つ)
- **`Open repository` のピッカーは開いているリポジトリの隣から始まる**。放っておくと `FolderDialog` は前回受理したフォルダ = そのリポジトリ自身の中から開き、そこは**開くものが 1 つも無い唯一の場所**(次のリポジトリは必ず 1 つ上に居る)。`RepoTab.pickerFolderUrl` が workdir の親を `file:` URL にして持ち(`urlpath::picker_folder_url`。`#` / `?` を含む名前で URL が切れないよう percent encode する。**ルートに在るリポジトリはそのルート自身**を返す — 上が無い時に空を返すと「前回どこかで置き去りにされたフォルダ」へ落ちる)、**入口 3 つ**(メニュー行 / `+` ボタン / 空ページのボタン)は全て `Main.openRepositoryPicker()` を通って `currentFolder` へ入れてから開く。**バインディングにしない** — ダイアログは人が移動する度に自分で `currentFolder` を書くので、押した瞬間に 1 度だけ入れる。タブが 1 つも無い時は入れない(比べる相手が居ないので Qt の既定に任せる)。ヘッドレスは `PG_AUTO_ACT=open-picker`
- **ピッカーが受理したフォルダは、開けると分かってからタブになる**(規約 §リポジトリを開く)。`TabsModel.openPickedPath` → `Hub::probe_repo` が `repo::open` を撃ち、答えを `Feed<PickMsg>` で戻してから `open_tab` する。**開けなかったフォルダはタブを作らない** = グラフを描かないことが構造で保証され、`state.toml` の tabs にも入らない。**タブを先に作って消す形にしない**(答えは 30〜36ms で返るので、タブが 1〜2 フレーム点滅する)
- **開けなかった時の置き場所は「どの道で来たか」、文言は種別が決める**(規約 §リポジトリを開く。3 × 2 = 6 通り)。ダイアログ(`OpenFailedDialog`)はピッカー経由の 1 経路だけが開き、**復元タブ / worktree 行 / `PG_AUTO_OPEN` は今まで通りページの中の画面**(人が今選んだ結果ではないものに、起動直後のモーダルを出さない)。**文言は `Words.openFailure(kind)` の 1 か所**を両方の画面が読む
- **種別は core が返す**(`GitError::NotARepository { bare }` → `plain` / `bare`、それ以外は `other`)。**git の文言を読んで分岐しない**。`bare` の判定は**失敗した時だけ** `rev-parse --is-bare-repository` を 1 本足す(実測 33ms。成功したフォルダには 1 本も増えない)
- **失敗した時のパスは `SessionEvent::OpenFailed` が運ぶ**(`GitError` から取らない)。パスを持つエラー型と持たない型があり、`TimedOut` で空になって**3 つ目の画面だけフォルダを名乗れなかった**実績がある。セッションは「何を開けと言われたか」を知っているので、git が何を答えても埋まる
- **失敗の画面はペインの席に置く**(`RepoPage` の縦 `SplitView` の中)。ページ全体を覆う形だと**コマンドログがその覆いの内側**に居て、`>_` を押しても何も起きなかった(実測)。**ログは自分から開かない** — 開く時の `rev-parse` は背景読みなので、空のパネルが立つ(実測)
- ヘッドレスは 7 動詞: `open-not-a-repo` / `open-bare`(ダイアログの 2 種)/ `open-not-a-repo-retry` / `open-not-a-repo-cancel`(出口 2 つ。前者は既存の `picker folder=` が**失敗フォルダの親**を名乗るかで読む)/ `open-fail-tab` / `open-fail-tab-bare` / `open-fail-tab-log`(タブ側の 2 種と、`>_` が届くこと)。報告行は `open_failed kind= dialog= tabs= active= near=` と `open_fail_tab tabs= state= kind= commands=` で、**`dialog=` / `commands=` はどちらもその窓自身の可視性**(頼んだ側を報告するとバインディングが切れていても緑になる)。**`tabs=` が「開けなかったフォルダはタブにならない」の答え**。**3 つ目(`other`)はアプリから作れない** — 起こせるのは実質 10 秒のタイムアウトだけなので、撮る時は `repo::open` が `TimedOut` を返す**使い捨てパッチ**(コミットしない)を当てる
- **fetch の調子は fetch ボタンだけが語る**(規約 §リモートから取り込む)。ツールバーに別のインジケータを置かない(`↻` は削除済み)。`RepoTab.fetchFailures` が**連続して失敗した fetch**を数え(手動・タイマーの区別なし。`fetch_settled`)、1〜2 回で `warning` の枠 + 語の後ろに `!`(`ActionButton.alert`)、3 回で `RepoSession::suspend_auto_fetch()` がタイマーを止めて `danger` + `Resume` の長押しボタンになる。**止めるタイマーが無ければ赤へ行かない**(`suspend_auto_fetch` の戻り値がその判定 — 設定で off のリポジトリは黄のまま)。長押しは `resume_auto_fetch()` = 覚えている間隔でタイマーを戻し、即 1 回 fetch。**成功はどちらの経路でも数を 0 に戻す**。**コマンドログを開くのは連続の 1 回目だけ**(`fetchFirstFailed` シグナル)
- **push が拒まれたら push ボタンも黄 + `!` になる**(規約 §リモートへ送る)。fetch の 1〜2 回失敗と同じ形(`warned` → `tone` / `toneDim` / `frameColor`、`alert`)で、**赤に当たる段は無い**(止められる自動の仕掛けが無い)。**憶えるのは `RepoPage` で、押したブランチ単位**(`pushSentBranch` → `pushFailBranch` / `pushFailReason` → `pushFailed` が `workTree.branch` と突き合わせる)。**送る時に埋める枠が「この答えは自分のものか」の判定を兼ねる** — 答えの `lastWriteOp` は `push` としか言わず、**リモートブランチの改名と削除も同じ名前で返る**(`session` の `write("push", …)` が 4 か所)。消えるのは**同じブランチへの push が通った時だけ**。ヘッドレスは `push`(届かないリモートへ)と `push-retry`(実際の非早送り拒否 → force で着地。報告行 `push_retry refused=` が消える側を言う — 消えた後の絵には写らないため)
- **fetch と push は 1 つの箱を共有する**(`TopBar.widestAction` + `widestActionCode`)。隣り合っていて互いに関係なく語が変わるので、共有しないと片方の状態変化がもう片方を横へずらす。**バインディングにせず `Component.onCompleted` で 1 度だけ決める** — 4 つの計測を読んで 2 つのボタン幅へ入る式はエンジンにはループに見える(実測)。**候補は `TextMetrics` でなく非表示の `Label` で測る**(`TopBar.Widest`)— 幅を決める箱は `ActionButton` 側の Label で、TextMetrics はそれより数 px 詰まる。等幅と通常表記が混ざる今、「片方の物差しで勝った候補が、もう片方の物差しでは負ける」が起こりうる
- **ツールバーの fetch / push はコード表記**(`ActionButton.code` = 等幅 + `bgHover` の地。規約 §git 用語のコード表記)。`AppMenuItem.code` は文の頭に付くチップだが、こちらは**ラベル自体がコマンド**なので `text` がそのままチップになる(`qsTr()` を通さない — 翻訳しないため)。**チップの地は語の実幅だけ**(`btnLabel.implicitWidth` に張り出し半ギャップ)で、共有の箱いっぱいには広げない。**チップの語間は `font.wordSpacing: -Theme.spaceXs`**(`AppMenuItem` 側も同じ — `push --delete` が 2 語に割れる)。**測る側の Label にも同じ wordSpacing を付ける**(`TopBar.Widest` / `ActionButton` の隠し Label)— 付け忘れると箱だけ 4px 広いままになる。**共有の箱の末尾のギャップは、最長がコマンドの時だけ落とす**(`ActionButton.box`)— チップの地が既に半ギャップ張り出しており、額縁までの余白として目が測るのは字の端でなくチップの端。足すと右が緩み、左はチップがアイコンにほぼ触れる(実測 7px 対 2px)。**この 2 つで 92px** = 素の語だけだった頃と同じ幅で、コード表記は幅を 1px も足していない。**フラグのダッシュは `Rectangle` で引く**(`ActionButton` が `text` を最初の ` -` で割り、`splitFlag` / `head` / `dashCount` / `flagRest`。規約 §git 用語のコード表記)— **字の差し替えでは 1px も縮まない**(U+002D / 2010 / 2011 / 2212 が全部同じ 7px。Cascadia Mono 実測)ので、`push -f` + `!` が枠に乗る(実測 1px)問題はこれで解く。**箱を広げて席を空ける手は不採用**(全状態ぶん要るので対で 16px 太る)。**測る側の隠し Label は font のまま** = 箱は動かず、縮むのはインクだけ(56px → 53px)。**`!` の位置は語の送り幅の末尾**(チップの地の端から 3px)で、**`splitFlag` の時だけさらに半ギャップ内側**(同 1px)
- **止まった操作の出口は commit ボタンの直下のカード**(規約 §進行中の操作から出る)。**押して出すのではなく居座り**、ファイル一覧はその分だけ下へ寄る。行は `OpExitRow` = `AppMenuItem` の写し(`MenuItem` は Menu の中でしかレイアウトされない)で、チップ列と印の席をカードが揃える。**ツールバーのバッジは状態だけを言い押せない**。**バッジが名乗るのは 1 つ** — フラグを並べると rebase が pick で止まった時(`CHERRY_PICK_HEAD` が残る)に `REBASING · CHERRY-PICKING` になる。どれが今の操作かは `integrate::InProgress::from_state`(continue / abort が効く先と同じ答え)。**`--skip` / `--quit` を出すかも同じ答えから**(`WorkTreeModel.op_stepping`)で、**進捗の件数で代用しない**(件数を書くのは rebase だけ = step する cherry-pick が merge に見える)。**`--skip` の長押しは状態で出入りする** — 空になって停止した時(conflict 0 + staged 0 + unstaged 0)は失うものが無いのでクリック + `nothing in it`、それ以外は長押し。**`edit` 停止も木がきれいなので、フル interactive rebase を入れる時に判定を作り直す**(P3-確認事項)
- **コミット単体の drop はグラフ行メニューの行で、印は状態で出入りする**(規約 §履歴を合流させる)。行は `drop` のチップだけ(規約 §メニュー「行がコマンドだけで終わることがある」)で、**squash の隣**(どちらもそのコミットの居場所を書き換える)。core は `sequencer::Edit::Drop` で、**プランは親まで含める**(depth 2)— 最新コミットを落とすと全行 drop のプランになり `rebase_interactive` が拒むため。その親は素の `pick` で**元の object name のまま出てくる**(実測)。**`plan_edit` は object name を取る**(`HEAD` のような symbolic name は履歴に見つからず弾かれる)
- **未コミット変更があっても `squash` / drop は止まらず、何も尋ねない**(規約 §未コミット変更がある状態で履歴を書き換える)。app 側に判定は無い — core が素のまま撃ち、git が拒んだら stash → replay → `pop --index` で回り直す(`session::carry_across_replay`)。**専用の表示を持たない**のは switch と同じで、着地は 3 つとも既存の絵になる: きれいに戻る / conflict の付いたファイル行 / **replay が途中で止まったら進行中のバッジと出口カード + 作業は STASHES とグラフの stash 行に残る**。**拒否ではコマンドログが開かない**(core が `answers_by_code()` を付けている)が、**止まった時は開く** — 開けるのは書き込みの答え(`lastWriteError`)の側だから。ヘッドレスは `--preset drop-collides`(戻す時に conflict)/ `--preset drop-stops`(replay が止まる。`drop-commit-go row:2` + `--allow-write-failure`)
- **drop が長押しかクリックかは `repoTab.headReachedElsewhere` の 1 つで決まる**(規約 §履歴を合流させる)。**行ではなくブランチの先端の性質**なので、`RepoPage` は訊かない — session が**refs が動いた refresh と書き込みの後**に答えを押し出し(`session::settle_head_reach`)、メニューが開く時には手元にある。**メニューを開いてから訊く形にしない**(`checkPublish` と違い、答えが `holdMs` を動かすと `AppMenu.holdColW` が全行を字下げし直す = 手が降りている最中に的が動く)。**行の入口は `page.dropCommit()` の 1 つ**に集め、`onTriggered`(クリック時)と `onHeld`(長押し時)の両方から呼ぶ — `holdMs > 0` の間 `AppMenuItem` はクリックを一切報告しないので、どちらか片方しか走らない。ヘッドレスは `drop-commit` / `drop-commit-go` で、報告行の `hold=` / `reached=` が形を言う(`-go` は出ている方の所作を取る)。**`--preset basic` がクリック側・`--preset diverged` が長押し側**(前者は stash と `v0.3-local` タグが先端に乗っている)
- **判定は core の `reachable` で 2 段**: (1) `a_ref_sits_on_head` = refs の一覧を 1 周する**プロセス 0 個**の判定(`publish_refs` が持っている listing をそのまま使う。タグはここでしか数えない)、(2) 落ちたら `reached_without_branch` の walk(`rev-list --max-count=1 <tip> --not --exclude=<branch> --branches --remotes --glob=refs/stash*`)。**先端とブランチ名は `publish_refs` が `head_hold` に置いた値を読む**ので、walk のために refs や HEAD を読み直さない。コストと不採用の形は [ci/baseline/head-reach-windows-x64.md](../../ci/baseline/head-reach-windows-x64.md)
- **merge / rebase / revert は現在のブランチを文の主語にする**(規約 §履歴を合流させる)。`merge` into \<current\> / `rebase` \<current\> onto it / `revert`、いずれも git 用語のコード表記。**入口が変わっても文は同じ** — ref 行でもクリックした側は言い直さない(規約 §メニュー「行がコマンドだけで終わることがある」)ので、`page.menuRefId` は文に出ない。**入口は左メニューのブランチ行・リモートブランチ行・グラフ行の 3 つ**(merge はタグ行にも、rebase は出さない)。**revert は cherry-pick の隣**。**どれもクリック**(merge / revert は足すだけ・rebase は switch / reset で戻せるローカルの書き換え)。**rebase だけ `<row>..HEAD` の publish を訊いて `rewrites pushed commits` を添える** — `publishRange` は 1 枠の共有なので**自分が訊いた範囲の答えだけを読む**(`RepoPage.rebaseRange`)。**出す条件は reset と同じ形**(ブランチの上・進行中操作なし・行き先が現在地でない)。rebase の既定は **`--autostash` + `--update-refs` の両 ON**
- **conflict の片側採用はファイル行の右クリックの 2 行で、両側をブランチ名で呼ぶ**(規約 §conflict の ours / theirs)。**rebase の反転は core が吸収する** — `conflict::sides()` が操作ごとに正しい名前を返すので UI も読む人も反転を知らなくてよい(`WorkTreeModel.sideOurs` / `sideTheirs`)。名前が取れない側は言葉で埋める。**どちらもクリック**(conflict 中のファイルにはまだ失う版が無く、もう片方は continue まで 1 クリック先)。**光っている conflict 行すべてに効き**、パスはバケツ集合経由で git 実行は 1 回(`takeSidePaths`)。**両側が何をしたかの文言は diff ペインだけが出す**(2 文字コード → 規約 §conflict の種別 の表)。`NavItemDelegate.conflictWords` は残っているが**ヘッドレスの `conflict_kind` 報告だけが呼ぶ** — ファイル行のアイコンに付いていた hover は届いていなかったので外した(下の「行を覆う MouseArea」)
- **conflict を外部ツールへ渡す行は、未設定なら設定への入口に化ける**(規約 §conflict を外部ツールへ渡す)。名前は `WorkTreeModel.mergeTool` = **conflict がある時だけ**読む(`session::refresh_status`。2 spawn を全タブの毎ポーリングに乗せない)ので、**設定ダイアログは `askMergeTool()` で 1 回だけ頼む**(`merge_tool_wanted` を立てて refresh)。答えは遅れて来るので、**入力欄は `onTextEdited` が立つまでだけ追従する**(`toolTouched`)。**書くのは `merge.guitool`** — 起動が `--gui` なので guitool が先に効き、`merge.tool` へ書くと guitool 設定済みの人に無反応になる。ついでにターミナルの `git mergetool` を巻き添えにしない(そちらは端末があるので `vimdiff` でよい)。**表示名は起動に使わない** — `conflict::mergetool` が実行時に引き直すので古い名前で撃てない。待ちの判定は `repoTab.busyOp === "mergetool"`(設定の書き込みは `"config"` に分けてある)。ヘッドレスは `PG_AUTO_ACT=open-mergetool`
- **マージツールの候補は `AppCombo`(自由入力 + 一覧)で出す**(規約 §conflict を外部ツールへ渡す)。印は **`NavIcon kind: "chevron"` = 山 1 つ**(`chevrons` = 2 つは `FoldBlock` 専用 = ペインの端を動かす。規約 §QML 実装ルール)。**ComboBox は model 差し替えで `currentIndex` を先頭へ寄せて `editText` を道連れにする**ので、値は `wanted` に別で持ち、**人の操作だけがそれを動かす**(`onActivated` と contentItem の `textEdited` — **`editText` の変化・`activeFocus`・`popup.opened` はどれも判別に使えない**。ポップアップが開いている間 combo は焦点を持ち続け、内部リセットは QML の `onModelChanged` より**先に**走る)。差し替え後は `Qt.callLater` で `editText` を `wanted` へ戻す。Popup の `implicitHeight` には **padding を足す**(行の高さだけだと最終行が切れる)。ヘッドレスは `PG_AUTO_ACT=settings-tools`(`merge_editor wanted= shown= configured=` を報告)
- **`WorkTreeModel.mergeTool` は読まなかった refresh でも前回値を繰り返す**(`session::merge_tool_seen`)。空で上書きすると、**開いたままの設定ダイアログの値が次の tick で蒸発**し、ツールが解決して conflict が消えた瞬間にも名前が消える。`set_merge_tool` は自分の refresh が読み直すよう `merge_tool_wanted` を立てる
- **グラフ行のダブルクリックはその行のチップへ移動する**(規約 §グラフ行のダブルクリック)。行き先はチップの先頭レコード = 画面に出ている名前。リモートのみの行は同名ローカルが無ければ黙って作って移動、**在れば git に訊いてから**(`merge-base --is-ancestor` = 遅れているだけなら黙って `switch -C`、ローカルにしか無いコミットがある時だけ `Move <branch> here?` を尋ねる。`session::checkout_moving_branch`。**何も捨てない switch に長押しを出さない**)。タグのみ / ref 無しの行はチップ列が `Create branch here?` の入力欄になる — **タグで detach しない**(チップ列に出るのはこの入力欄だけ。質問は上のバーへ移した)。重なったチップは hover で下に展開(`RefListPopup`、ページ所有・スクロールで閉じる)
- **左メニューの所作**(規約 §左メニューの所作): ダブルクリック = 行き先(ブランチ / リモート = switch、worktree = 別タブ、タグ = `Create branch here?` の入力欄)、**間を空けた 2 回目のクリック = 改名**(ブランチ / タグ / stash / リモート。判定はダブルクリック間隔だけで上限なし、2 回目も普通のクリックとして飛ぶ)。直前にクリックした行は `bgSelected`。名前の可否は core の純関数(`tag::is_valid_name` = `check-ref-format` の写し / `stash::is_valid_message`)で、独自の禁止を足さない。**タグの改名は `tag <new> <old>` + `tag -d`、stash は書き直したコミットを `stash store` + drop**(stash は一覧の先頭へ移動する)

- **conflict 中のファイルの diff は combined**(規約 §conflict の diff)。core が読む(`parse::diff` が `diff --cc` / `@@@` / N 列マーカー / `* Unmerged path`)ので、app は `DiffModel.isCombined` / `unmerged` と行の `markers` を受け取るだけ。**`DiffPane.partial` に `!combined` が入る** — combined patch は `git apply` が拒むので分ける道具が当たらない(core 側の floor は `stage::refuse_combined`)。**どちら側の行かは `sideOf(markers)`** = 列が空白なその側にある、を 1 か所で判定する(色は言えない — git は両側を同じ緑で塗る)。**側の色はグラフから借りる**(`GraphModel.colorOfRef` が chip 記録を `encode::label_names` で読んで `node_color` を返す → `conflictColorOurs` / `conflictColorTheirs` → `RepoPage.sideColorOurs` / `sideColorTheirs` → `Theme.graphLane`)。**バインディングにする** — チップはグラフの 2 波目で載るので、開いた時に 1 度読むだけでは色が付かない(依存を作るために `graphModel.finishCount` を読む。グラフのプロパティは notify を共有している)。**2 色を決めるのは `encode::conflict_side_colors` の 1 か所**(スロットが対を返せないので QML 側は半分ずつ取る)で、借りられない側は**ブランチ名の FNV-1a**から引き、衝突したら **ours を保護して theirs をずらす**。**乱数にしない** — 開き直すたびに色が変わり、verify-ui の PNG も毎回変わって目視判定が成立しない。**`* Unmerged path` の 1 行だけが返る種別(`DU` / `UD` / `AU` / `UA`)は行が 0** で、ペインは種別の 1 文を出す — 文言は **`Words.conflict` singleton**(`NavItemDelegate.conflictWords` もそこへ委譲する)。種別の 2 文字は `NavSectionModel.changeOf(path)` でパスから引く(ペインは行ではなくパスしか持たない)
- **新規ファイルの diff からは分ける道具を外す**(規約 §diff の中のステージ)。`DiffPane.partial` = `fromWorkTree && !diffModel.isNewFile` の 1 つに集め、hunk 見出しの 2 語・行の `+`・行の `MouseArea`(= hover の照明と行選択)を全部そこへ繋ぐ。ヘッダの `Stage file` だけ `fromWorkTree` のまま。**判定は Rust 側**(`encode::is_new_file` → `DiffModel.isNewFile`)で、**「新しい側があって古い側が無い」**を見る — 古い側が無いだけを条件にすると、`diff --git` ヘッダの無い patch(`parse_patch` が両側 None で合成する)まで新規に化ける。**削除は当たらない**(古い側に行が在るので一部ステージに意味がある)。**未追跡と staged 済みの新規は git の出力がバイト単位で同一**(`--no-index /dev/null <path>` でもヘッダは `a/<path>` を名乗り、`--- /dev/null` だけが真を言う。git 2.55 実測)。`begin_request` での取り下げは**行を消す時だけ**(`!same_file`)— 残っている行と食い違わせない。ヘッドレスは diff 系の動詞の引数が `<bucket>:<path>` を取れる(`untracked:untracked.txt`)
- **staged のバケツの帯は 0 でも立つ**(規約 §その他の操作)。**帯は `WipBucketHeader` の 1 つ**で、`ListView.section.delegate`(行のあるバケツ)と `ListView.footer`(staged が空の時)の両方がそれを建てる — **行の無いセクションに見出しは無い**(section delegate は行が 1 つ以上ある group にしか作られない)ので、**空の staged が座る席 = 一覧の末尾 = footer** になる(staged は最後のバケツなので位置がそのまま合う)。**隠す時は高さも 0 にする**(`height: visible ? - **行末の `+` / `−` は光っている行すべてに効く**(規約 §その他の操作)。対象は `WipPane.stageTargets`(押した印と**同じ側**の chosen 行。選択外の行は自分だけ)、まとめる時は `beginPaths` / `addPath` → `stagePaths` / `unstagePaths` で **git 実行 1 回**。一緒に出る印は `stageHotKey`(`<bucket>:<path>`)+ `stagePeerOf` で、**ポインタが乗っている行自身にも true を返す** — 実 hover では既に出ているし、headless はこれが唯一の経路(`PG_AUTO_ACT=stage-many`)
- **行選択は `DiffPane` が持つ**(規約 §diff の中のステージ)。`chosenLines` = `<hunk>:<line>` をキーにした素の object(**毎回新しい object を代入する** — 同じものを返すと行が追えない。WIP の `chosenKeys` と同じ形)で、デリゲートは `picked` / `pickedInHunk` を読む。**書き込みは `beginLines` / `addLine` → `stageLines` の集合渡し**(パス集合と同じ形)で、core は `encode::line_selection` が hunk ごとに 1 つへ畳む(**負の index は捨てる** — `hunk_selection` と違い「hunk 全部」の意味を持たせない)。選択は書き込みと `reloadDiff` で下ろす(index が指す diff が入れ替わるため)
- **hunk 全体の照明は `hoverHunk` + `hoverLine < 0`**(規約 §diff の中のステージ)。見出しの `MouseArea.onContainsMouseChanged` が自動化フックと**同じ 2 つのプロパティ**へ書くので、実 hover と `PG_AUTO_ACT` が 1 つの答えに集まる。`hoverLine` を見るのは「行に乗っているだけの時は照らさない」ため
- **側が空になった diff は閉じる**(規約 §diff の中のステージ)。判定は `DiffModel` の `changed()`(`drain` が reset + extend の**後**に出すので、そこでの `diffList.count` が新しい方)で、`closeWhenEmpty` は `reloadDiff` = 書き込み後の読み直しだけが立てる。**`count` の 0 を直接見ない** — reset で一度 0 を通るため。画像・バイナリは行 0 でも中身なので `isBinary` / `previewKind` で除く
- **diff の作り直しで画面を飛ばさない**(規約 §diff の中のステージ)。`DiffModel::begin_request` は**同じファイルなら行を消さない**(`drain` が reset + extend を 1 呼び出しで済ませるので入れ替えは一瞬)。位置は `DiffPane.holdScroll()` → `placeTimer`(`Metrics.anchorDelayMs`)で戻す — **`onCountChanged` の 0 は無視する**(reset が先に来る)。実測: 20 hunk の diff で contentY 400 のまま partial stage して 400(`PG_AUTO_ACT=keep-place` の `diff_place`)

- **リモート 0 本は、質問を立てた直後に `RemoteDialog` が自分で開く**(規約 §リモートが 1 つも無い時)。判定は `startPublishAsk` の末尾 1 か所で `publishRemotes.length === 0` を見て、**最終行を押したのと同じ `choosePublishRemote(publishRemotes.length)` を呼ぶ** — 2 つ目の開き方を作らない。**バーを立てた後に呼ぶ**(`startRowAsk` は `form` / `answerable` / `neutral` を既定へ戻すので、先に開くと質問の側が組み上がっていない)。取り下げても行き止まりにならないのは、空の一覧でも最終行だけは常に在るから。ヘッドレスは **`--preset noremote`**(コミットだけでリモート 0 本)で、報告行に `dialog=` / `name=` が足してある(ダイアログが立ったか・名前欄に何が入っているかは、それ以外に headless から読む手段が無い)。**確定直後の絵は `publish-new-go` + `--quit-ms 3600`** — 確定(約 2.1s)と答え(約 3.3s)の間に撮影(`quit-ms − 800`)が入る窓で、そこだけが「新しいリモートが選ばれた状態のバー」を写せる
- **名前の prefill `origin` はリモート 0 本の追加時だけ**(規約 §リモートを書き留める)。**`origin` としての特別扱いは prefill ではなく名前が配る** — 既定の行き先は `RepoTab` が `names.iter().find(|r| *r == "origin").or_else(first)` で引くので、prefill を書き換えれば特別扱いは付いてこない。**焦点は「この dialog が名前を当てられなかった時」だけ名前欄へ**(`onOpened` の三項)。**placeholder は `origin` が取られていれば出さない** — prefill が埋める間は一度も描画されず、埋めない場合を作った時にはじめて画面に出た文字列なので、`Add` が必ず拒む名前を薄く提案する状態のまま残さない

- **co-author は詳細ペインの日付行に出す**(規約 §co-author の表示)。**署名の 1 語は名前の行へ上げてある** — 日付行の左カラムは実寸 ~230px で、日付 + 署名 + co-author の 3 つは入らず**後から入った co-author が切れる**(実測 `with Cla…`)。データは **core が git に訊く**(`details.rs` の `DETAILS_FORMAT_ARG` に `%(trailers:key=Co-authored-by,valueonly,unfold,separator=%x1F)` = **プロセスは 1 本も増えない**)。**メッセージを自分で走査しない** — trailer の規則(最後の段落・`key: value` の形・折り返しの継続行)は git のもので、複製すると本文中の `Co-authored-by:` まで拾う(統合テスト `details_of_a_commit_without_the_trailer_credit_nobody` がその形)。`key=` は**大文字小文字を区別しない**ので `Co-Authored-By`(ツールが書く綴り)も `Co-authored-by`(慣習の綴り)も同じ所へ落ちる。**区切りは U+001F**(NUL レコードを壊さない・名前にもアドレスにも出ない。git 2.55 実測)。app へは `encode::encode_co_authors` が**名前 / アドレス / identicon の 3 フィールド**を `\u{1e}` で、レコード間を `\u{1f}` で詰めて渡し、QML は `labelRecords` と同じ流儀で split する。**identicon は Rust で計算する**(`avatar_code` が顔を決める唯一の場所)。**アドレスが無い trailer も 3 フィールド**にする = 読む側は数えずに index できる。**カードは `CoAuthorCard`**(`RefListPopup` と同じ地・枠・行高。DetailsPane は delegate ではないので自分で所有できる)。**開閉は `matesLit` = `matesPointed || mateCard.pointerInside`** の 1 つで決まり、実 hover と `PG_AUTO_ACT` は**同じ `showCoAuthors()`** を通る。閉じ判定は `Metrics.hoverKeepMs` の Timer で待つ(下線とカードの hover は**別のフレームで**順不同に変わり `Qt.callLater` はその間に走る — `settleRefList` と同じ形。下の罠 (3))。**報告するのは `matesCardOpen` = カードの `opened`**(入力側を報告するとバインディングが切れていても緑になる)。ヘッドレスは `co-authors` / `co-authors-open` の**対**で、`--preset co-authors`

- **credit 行はカードの幅の計算に入らない**(規約 §co-author の表示)。`Layout.preferredWidth: 0` + `Layout.fillWidth` で「メッセージが決めた幅の残り」を取り、`Layout.minimumWidth: Math.min(Metrics.messageMinW, 名前の自然幅)` だけが床。**素直に `maximumWidth` で刈らない** — それだと人数の多いコミットでカードが横に伸び、preview が中身で形を変える。**床を `messageMinW` 一定にしない** — 1 人(実測 97.6%)の短い名前のカードに空白が残る

- **hover で開くものの 5 つの罠**(すべて 2026-08-09 に踏んだ。規約 §hover のツールチップ): (1) **カードはポインタの x に開く** — 行はペイン幅なので左端は手から最も遠い。(2) **`HoverHandler` は `background` に置く** — `contentItem` は padding の内側で終わり、カードの縁を通る手はどちらの hover にも入らない。(3) **閉じ待ちは `Qt.callLater` では足りない**(`Metrics.hoverKeepMs` = 150ms)— 線とカードの hover は別フレームで変わり、callLater はその間に走る。(4) **hover で出すものが、hover されている当のものをリサイズしない** — 行の高さ / 幅が変わると手から逃げる。アドレスは最初から席を持たせ、**開く位置から右に残っている幅**で elide する(ペイン幅で測ると Popup が位置だけ収めて端に張り付く)。(5) **hover で開くものを 2 つ同時に出さない**(下記)
- **(2) は「`background` に置く」では足りない — `background` と `contentItem` は兄弟**(qmltestrunner + `mouseMove` で実測)。「handler は passive」が効くのは**親と子の間**で、行は `contentItem` の子だが `background` はその親ではなく**隣**。実測は padding の帯で `background=true / content=false`、行の上で **`background=false` / `content=true`** — つまり `background` だけに置くと、**手が行に届いた瞬間に「誰も乗っていない」に化ける**。`RefListPopup` はこれで、**行がハイライトした直後に自分を閉じた**(2026-08-09 報告「一瞬一覧側の背景色が変化した後閉じる」)。**hover で開くカードは全部、2 つ置いて OR する**(`pointerInside: insideHover.hovered || contentHover.hovered` — `RefListPopup` / `CommitHoverCard` / `CoAuthorCard` / `AuthorCard` の 4 つとも)。**中身がまだ hover を受けないカードにも置く** — 「1 つで足りている」は行を光らせる 1 手で黙って壊れる均衡で、対の 3 行を惜しむ理由が無い(`CommitHoverCard` は今どの子も hover を受けないが、受ける子が 1 つ増えた瞬間に `background` だけの実装は「手が中に居るのに誰も乗っていない」に化ける)
- **hover で開くものは、出す前に採寸する**(規約 §hover のツールチップ)。`Column` は polish で並ぶので、記録を渡したその場で `open()` すると**渡す前の寸法で表示される**(実測 8x8 = padding だけ → 1 フレーム後に 111x80)。**Qt は「今どこが hover されているか」をポインタのイベントから決め、図形の変化では決め直さない**ので、**後から伸びたものは既に上に居る手を認識できない**。`RefListPopup.layOutRows()`(`Positioner.forceLayout()`)を `open()` の前に通す。幅だけは 1 フレーム遅れて確定するが(97 → 111)、**増える方向にしか動かないので既に中に居る手から地面を奪わない**
- **(2) と (3) は同じ 1 つの穴の両側**(qmltestrunner + `mouseMove` で実測): **`Popup` は下の item から hover を奪う**(下の `MouseArea` は popup の上のどの点でも `containsMouse=false`)が、**handler が `contentItem` に在ると padding の帯は popup 自身も拾わない**。つまり帯の上では**開いた側・開かれた側・下の行の 3 つ全部が「自分の上には居ない」と答える**。チップの下に flush で開く `RefListPopup` はその帯が入口なので、`Qt.callLater` で閉じる実装は**降りる手を毎回弾いた**(2026-08-09 報告)。**hover で開くものは `background` の handler と `hoverKeepMs` の 2 つを必ず対で持つ**。**下の行を疑わなくてよい**のはこの実測の裏返し — popup が hover を奪うので、一覧の下に隠れた行が自分のチップを展開し直すことも、その行のカードが一覧の前に出ることも起きない
- **グラフ行のカードとチップの一覧は同時に出ない**(規約 §hover のツールチップ「1 つのポインタが開けるものは 1 つ」)。**残るのはチップの一覧** — カードはどの行にも在るが一覧はそのチップにしか無く、しかも**カードは手の下 = 一覧が開くその場所**に出るので、放っておくと一覧への道をカードが塞ぐ(2026-08-09 報告のスクリーンショットがその形)。判定は `RepoPage.refListUp`(`refListWanted || refList.opened`)1 つで、**`openRowCard` はそれを見て何もしない**・**`openRefList` は `closeRowCard()` で待たずに引っ込める**(閉じ待ちに乗せると 150ms 重なって見える)。行の側は `GraphRowDelegate.noteChipHover` が**チップに乗った時に `hoverDelay` を止めて `rowHoverRequested(false)` を上げ**、**チップから行へ降りた時に `hoverDelay` を restart する**(= 外から行へ入り直したのと同じ扱い。`tipDelayMs` 600 > `hoverKeepMs` 150 なので一覧が閉じてからカードが出る)。ヘッドレスは **`ref-list-card`**(`row-card` と**対で読む** — 同じ行・同じ preset で `row_card open=` が割れるのが答え)
- **チップの一覧は一呼吸置いて開き、出た後はチップ列全体が保持する**(規約 §hover のツールチップ)。**着地で開かない** — チップ列を横切るポインタは**途中の重なったチップ全部の上を通る**ので、乗った瞬間に開く実装は触れた分だけ出しては引っ込め、それが「点滅」として報告された(2026-08-09)。待ちは行のカードと同じ `Metrics.tipDelayMs`(チップ列に他に hover で答えるものが無いので、狙った手が払うのは待ち時間だけ)。**保持は `GraphRowDelegate.chipHeld` + `chipUnder` が `labelColumn` まで広げる** — チップは `fontSmLine` = 16px、行は `graphRowHeight` = 26px で、**着いたばかりの手はまだ止まっていない**(実測: 行 y 17 に着地 → 8ms 後に y 2)。**開けるのはチップ・保つのは列**という非対称がその答え。**出ている一覧のチップへ戻った手は待たせない**(規約 §hover のツールチップ「出ているものの的へ戻る手は待たせない」)— 一覧へ降りた時点で `refListWanted` は下りているので、戻りを `chipDelay` に乗せると**閉じ待ち 150ms で消えて開き待ち 600ms で出直す点滅**になる。`GraphRowDelegate.noteChipHover` は乗ったチップが `view.chipListAnchor`(`RepoPage.refListAnchor` が open で立て closed で下ろし、`GraphPane` が view へ写す)と同一なら `chipDelay` を飛ばして即 re-hold する
- 確定意匠: 状態バッジ = 無表示(ここにしか無い)/ 雲(リモートにも在る)/ **緑の PR アイコン**(PR中・ブランチのみ)。**タグにも同じバッジを出す**(要望「ローカルのみのタグを区別したい」の答え)。ブランチの PR 判定(`ls-remote refs/pull`)は P4 のままで `PG_FAKE_PR=名前` がプレビュー(タグ側のデータ配線は `.claude/rules/core.md`)
