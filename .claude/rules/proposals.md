# UX を変える提案は board の絵で出す

- **UX(画面の見え方・文言・操作・挙動)を変える修正を提案する時は、問題点と修正案を board に載せ、そのラベルで指して出
  す** — 文だけで提案しない。案を出して訊く・推す・残りとして挙げる・「直すなら」と書く、のどれも提案で、締めの
  文・wrap_up の問い・AskUserQuestion のどこで言っても同じ
- **1 件 = 横並びの 1 run**: 問題点(今の画面 — main か今の枝)を before、修正案(**席に実装した有るべき形**)を after に
  `shots add --before … --after …`。after の案が複数なら `--part 今 … --part A … --part B …` で今と各案を並べ、案は A,
  B, … と呼ぶ。動きの話は film スキルの before / after。作れない場面(競合の瞬間など)は形だけ示す絵で代用し、代用であるこ
  とをラベルと本文に書く
- **本文は board のラベルの綴りで件を指し、案は A, B で指す** — 件が複数ならラベルの頭に `1.` `2.` を付ける。書くのは
  「どの絵のどこで、何をすると、何が起きるか」。撮り方・載せる順は verify-ui スキル
- **`/land` の後に UX に影響する課題が見つかったら、反映する変更と関係が無くても反映を止めて訊き直す** —
  <!--cmd:land.leave-->`cargo xtask land leave <why>` で列から外れてから、問題点と修正案を載せて訊く(載せた絵は land を
  ユーザーの次の発言まで止める。止まるのが正しい)。**land の報告で UX の課題を新しく出さない** — 見つけた物は land の前
  に止めて訊いている。反映の後の確かめで初めて見つかった物は新しい提案として、`cargo xtask seat` で席を取り直して載せる
- **UX の課題を P<n>-確認事項 に積んで終えない** — 考えて、絵で示して、訊く。確認事項に書くのは、訊いた上でユーザーが保
  留と決めた物だけ
- 出口の網は `hook::proposal`
  ([反映前テストの機械化.md](../../internal-docs/反映前テストの機械化.md#ux-の提案は絵でhookproposal))。語で読む網なので
  掛からない提案もある — 掛からなくても規則は同じ
