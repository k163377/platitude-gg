# 分割・共通化基準(Rust / QML 共通)

既存の超過はラチェット式 — 触った時に寄せる。一斉整形だけのコミットを作らない。

## 上限(物理行)

- **src 1 ファイル 500 行 / fn 100 行**(clippy `too_many_lines` 相当)**/ tests 1 ファイル 1000 行**
- **上限超過ファイルへ追記しない** — 先にその責務を切り出す。切り出しが今の変更を膨らませすぎる時だけ追記し、分割タスクを積んで報告する(黙認しない)
- 分割しない判断をした超過ファイルは [rules-refs/structure.md](../rules-refs/structure.md) へ理由 1 行(記載の無い超過は違反)

## 分割

- 挙動不変・**移動だけのコミット**(変更・リネームを混ぜない)。公開名は `pub use` / qmldir で不変に保つ
- Rust: ディレクトリ化は **mod.rs 方式(既存踏襲)**。mod.rs は mod 宣言・re-export・共有型のみ(実装を置かない)。`#[cfg(test)]` は対象と同じファイルへ付いて行く(テストだけ巨大なら `<mod>/tests.rs` へ)
- 統合テストは tests/it/ 内のモジュール分割(1 バイナリ規約は core.md)
- QML: 子コンポーネント切り出し(ui/ フラット・登録 2 箇所は app-ui.md)。inline `component` は 2 ファイル目が使う時か親の超過時に独立ファイル化

## 共通化

- 同じロジックは **3 箇所目が出た時に共通化**(2 箇所は静観)。挙動が半端に違う実装を無理に束ねない
- 置き場は**使う全員から到達できる最深のモジュール**。util / misc / helpers という名のモジュールを作らない(名前は責務)
- xtask は依存 std のみ — core / app と共通化せず重複を許容
- QML の繰り返す意匠は既存部品を先に探す(一覧は ui/qmldir)

## QML 整理

- 属性順は Qt 規約: id → property → signal → JS 関数 → オブジェクトプロパティ → 子要素(触る箇所だけ揃える)
- 数行を超えるスクリプトは名前付き関数へ(ロジックを QML に書かない規約は app-ui.md)
