# 性能 — 予算・設計規則・計測・記録

**性能に影響を与える変更**(UI 操作の経路・読み込み・常駐データ・描画・起動・画面表示中の読み込み)**の前に読む**。予算と
設計規則はここが正本、予算に対する数字の正本は記録 [perf-windows-x64.md](../ci/baseline/perf-windows-x64.md)(本書は撃ち
方と記録の置き方)。**Claudeクラウドでは計測しない**([クラウドセッション.md](クラウドセッション.md))。

## 予算

`JetBrains/kotlin` 級(10万コミット超・refs 5 万本、うちタグ 4.5 万)で: 起動→グラフ初回表示 3 秒以内 / 操作応答 100ms /
スクロール 60fps / メモリ 300MB 以下。

- 指標ごとに何を測って何で判定するか(操作フィードバック・重い diff と git の書き込み・子の git・長時間使
  用)は [メモリと操作応答の改善計画.md](メモリと操作応答の改善計画.md) §2
- **メモリは net で読む**(§計測の各論「perf の判定行は net で読む」)。report の MB は実質 MiB(同 改善計画)

## 計測

**いつ**: 段 3(リリース前と依存・環境を触った時 — gate スキル)で記録 §判定 を撃ち直す。それ以外は変更の効果を確かめる時
に A/B で撃つ(§cacheとA/B)。**実窓を使うので、席から撃つのはユーザーが明示した時だけ**(`PGGDEV_ALLOW_GUI=1` — CLAUDE.md
§ビルド・テスト)。

**判定の 4 行を撃ち直す 2 行**(コーパスの形・座り・画面の条件は記録 §計測条件):

```
cargo xtask corpus
PGGDEV_ALLOW_GUI=1 cargo xtask perf --at <測る commit> --repo <上の 1 行が印刷した path> --runs 5
```

### 測るフレームと操作の開始条件

待ち方と罠は `PagePerfDriver.qml` の冒頭と `PerfFrameWait.qml`、読む側は `perf::reading` の `Reading::method`。

- **1 つの入力に 2 つのフレームを測る** — **フィードバック**(入力が取られたことを最初に見せるフレーム: 行が選ばれた =
  `perf_details_feedback`、diff のペインが立った = `perf_diff_feedback`)と**完了**(答えが入ったフレーム:
  `perf_details_frame` / `perf_diff_frame`、最終色付けは `perf_colour_frame`)。操作応答 100ms はフィードバックに対して読
  み、完了は別の指標([改善計画](メモリと操作応答の改善計画.md) §2)。入力はハンドラの呼び出しで、OS の入力配送は含まない
- **測るフレームは、変更の後に scene graph が同期した最初の 1 枚** — 頼んだ後に最初に届いた 1 枚ではない。各行の
  `passed_over=` が、待つ間に見送った(変更の入っていない)フレームの数。**時刻は swap の報せが GUI thread に届いた時点**
  — 画面へ出す投入の後(走査線が出た時刻ではない)で、GUI thread が次にイベントループへ戻るまで遅れうる。画面の vsync の刻
  み(180Hz で 5.6ms、60Hz で 16.7ms)も含む。どちらも足す向きなので、数字は上界
- **操作は何も借りていないページから始める** — ページの読みが全部届き(`PageSettled`)、アプリの git が 1 本も走っていない
  時。起動からそこまでが report の `to idle`。**`--back-to-back` は待たずに続けて撃つ** — 前の操作の後始末と重なった時の
  値で、アイドルの値とは別の軸
- **製品が色を付けるファイルは `coloured` で測る** — `raw` は色付けの終わりを待たずに次へ進むので、閉じた diff の色付け
  が次の操作に重なる
- **report の `method` 行が、そのビルドの測り方を言う**。言わないビルドは「頼んだ後に最初に届いたフレーム」「続けて撃
  つ」で測っていて、**フレームの時間はこの行が同じ値どうしでしか並べない**(起動の行も同じ。メモリと fps は並ぶ)

### ケース

連続するケースは周回境界も含めて異なるOIDにする。同じ行の再クリックは改名などの別ジェスチャーになる。

`--cases <file.tsv>` はヘッダー無しの4列: `name<TAB>full-oid<TAB>path<TAB>completion`。空行と `#` 行は無視する。nameは英
数字・`-`・`_`、OIDは完全長、pathはそのコミットの変更ファイル一覧に載るパス。completionは `raw` または `coloured`。一覧
の順に選択・diffを開き、 `--cycles N` でN周する。反復には異なるOIDが2つ以上必要。

```
cargo xtask perf --repo <corpus> --cases <cases.tsv> --cycles 50 --runs 5
cargo xtask perf --repo <corpus> --cases <scroll-cases.tsv> --diff-scroll --runs 5
cargo xtask perf --repo <corpus> --select-oid <full-oid> --file <path> --completion coloured --runs 5
```

合否はケースごとに判断する。プロセス内反復と別プロセスのrunは別の軸。ケースの行は kept run を束ねた分布で、p95 は 20 操
作から、p99 は 100 操作から出す(それ未満の標本では最大値の言い換えにしかならないので出さない)。run が 2 本以上あれば run
ごとの中央(`p50 by run`)が隣に並ぶ — run が丸ごとずれた時に、束ねた分位が run の中の散りに見えるのを防ぐ。

通常の変更、多数ファイル変更、小さい変更を含む大きなソース、長いdiffを固定ケースにする。画像・非対応言語は `raw` として
別ケースにする。`coloured` は最終 `DiffModel.coloured` が立つ対象専用。時間切れは失敗のまま記録する。rawが測るのは画像デ
コード前まで。

`perf_diff_frame` は対象diffの初回表示、`perf_colour_frame` は同じfingerprintの最終色付けが反映されたフレーム。
`--diff-scroll` は各操作で可視diffを2秒スクロールし、正の移動量と終了後の可視行を要求する。短くoverflowのないdiffは失敗
なのでスクロール用一覧は分ける。グラフの12秒計測とは別系列。反復と併用する時は、全操作の計測時間を含む `--watchdog-ms`
を指定する。

### cacheとA/B

- `--cache warm` が既定。同じ経路の捨てrunで温める。
- `--cache first --runs 1` は、このinvocationの最初のプロセス。OS cacheの状態は別に確かめる。
- `--cache cold --cold-prepare <executable>` は利用者指定のOS固有プログラムを各run直前に実行する。repositoryと測
  定binaryの2引数を渡し、成功終了を準備完了とする。準備失敗・期限超過は測定失敗。プログラムがどのcacheをどう冷却したかを
  記録に併記する。成功終了が示すのは準備が走ったことだけ。

```
cargo xtask perf --repo <corpus> --at <A> --compare <B> --runs 3 --cases <cases.tsv>
```

A/Bの `--runs` はABBAブロック数。3なら各6回。画面・Hz・renderer・features・corpus・GPUの記録が変われば比較を中止する。古
いcommitが新しい計測口を持たない場合、要求したケースや色付けの証跡欠落を失敗とする。

### 短いメモリ峰

100msのWorkingSet最大とは別にWindowsの `PeakWorkingSet64`、Linuxの `VmHWM` を `memory.csv` の
`os_peak_working_set_bytes` に記録する。OSが保持するプロセス寿命中の最大常駐量で、サンプル間の短い峰を検出する。
**子の git 込みの量は report の `with its git`** — アプリとその子が同時に確保していたコミット量の峰 (job object の
`PeakJobMemoryUsed`、`memory.csv` の `job_peak_commit_bytes`)。WorkingSet と private の行はアプリ単体で、読みが起こす
git は入らない。 private commitの峰・割当回数・発生時刻は分からないので、差が問題になる場合は別の診断runでOSの割当トレー
スを採る。帰属取得の計測負荷は別runへ置き、OS最大は素の値で記録する。

### workload別の比較

`cargo xtask corpus --against <reference>` は以下を別profileとして出力する。プロファイルは軸ごとに独立して読む。

| profile | 入力 | 対応する性能 |
|---|---|---|
| startup/status | 追跡数・directory・index・無視ファイル・git設定 | 起動・status完了 |
| refs | refs数・注釈タグ比・remote階層 | refs読込・ナビゲーション |
| graph/scroll | lane幅・chip数・文字量・フォールバック | frame分布・停止・常駐量 |
| diff | 変更数・ソースサイズ各分位・言語・変更量 | raw/coloured完了・diff scroll |

### 計測の各論

撃つ人・記録を読む人が知っておくことだけ。仕組みと罠は各モジュールのコメント(`perf::sampler` / `perf::measure` /
`perf::display` / `perf::corpus` / `perf::rig` / `perf::fonts` / `xtask::still`)。画面の名前(Qt の `ScreenInfo.name` は
OS の `DISPLAYn` と一致しない)は `perf::sampler` の `Sample::display`、詳細フレーム列の時刻(到着時刻でなく各行の
`clock_ms` を読む)は `harness::perf_probe` の `end_scroll`、画面を invocation の間ずっと起こしておく仕組み(`away_ms` が
答えるもの)は `perf::sampler::keep_awake`。

- **性能計測は機械の状態も測って、駄目な run は落として撮り直す**: 落とす条件(ロック / セキュアデスクトップ・最小化・落
  ち着いた後の画面移動・配信フレームが画面の Hz の半分未満・ベンチが 30 秒で終わらない・対象以外が機械の 35% 超)・撮り直
  し(`--retries` 既定 3、被さりは 2 度で諦める)・捨て run の省略は
  `perf::sampler`(`Conditions::complaint`)・`perf::measure`(`Spoiled`)・`perf::warmth`。対象プロセスの CPU は job object
  で子孫の git まで込み。`--allow-noisy` は全部の関門を開く。CPU の閾は「並行ビルドが居る」を捕るためで、ブラウザや IDE
  が開いている程度(24 スレッドで 11〜32%)では落とさない
- **表示に依らず測るのは `perf --software`**: software scene graph は画面の点灯・消灯に依らず完走する(点灯前提の D3D run
  は 1 tick の消灯で落ちる)。**読めるのはメモリだけ**: software の WorkingSet は D3D の床が無い別の量なので、同じ commit
  の D3D 値と並べて読む。frame gate は効かせず、ロック・被さり・CPU の閾は効く(仕組みは `perf::options` の
  `software`・`perf::measure`)
- **窓は名前の付いた画面へ固定する**(`--screen`): **どの画面に出たかが fps をそのまま決める**ので、fps は画面の Hz に対
  する割合で読み、`over_16_ms` を「どの Hz でも同じ問い」として読む(置き方は `perf::artifacts` / `perf::display`)
- **ベンチマークリポジトリは `HEAD` では固定できない** — 測るのは `cargo xtask corpus` が生成する合成リポジトリで、**本
  体 checkout 直下の gitignore 済み `.pgg-perf-corpus/` に 1 つ**(理由と token の取り方は `xtask::corpus` /
  `perf::corpus`)。記録を取り直す時は記録の token を `--corpus` へ渡す。**kotlin との距離は `cargo xtask corpus` と
  `cargo xtask corpus --against <repo>` が同じ実装で両列を出す** — 正本は
  [perf-windows-x64.md](../ci/baseline/perf-windows-x64.md) §コーパスと kotlin の距離。**形を変えると token が変わり判定
  表ごと撮り直し**になる
- **計測したビルドを名乗らせる**: manifest の `features=` が何を頼んだかを持つ。`perf --shipped` は出荷ビルド(feature 無
  し)を測る — 答えられるのは**メモリと `graph stream finished` までの時間だけ**で、リポジトリは `state.toml` の `[tabs]`
  から開く(出荷ビルドに引数の口は無い)
- **計測は計測台(rig)で撃つ — `cargo xtask perf --at <rev>`**: roster 外の worktree
  `.claude/worktrees/rig`(`seats::RIG`)に名指しの commit を載せて release ビルドし、exe を commit 単位で置
  く(`perf::rig`。同じ commit の 2 度目はビルド無し)。**測られるのは commit だけ**(席の編集を測るなら commit してから
  `--at HEAD`。`--at` 無しは席の exe = 編集込み)。**触るのは機械だけ** — EnterWorktree(名前でも path でも)と Write /
  Edit は hook が deny、rig が dirty なら perf は reset せず拒む。証跡は撃った席の `target/perf/` に落ちる。**CPU の並行
  は増えない** — 実窓の計測は他席のビルドと同時に撃てば foreign 35% で落ちる(隣で続けてよいのは編集・思考・git だけ)—
  **その順序付けは `still` がやる**
- **perf の判定行は net で読む(`--no-font-walk` で素の gross)**: 一族(`Yu Gothic UI`)に無いグリフを 1 つ組むと Qt がフォ
  ント DB の全 family を populate する(`QPlatformFontDatabase::fallbacksForFamily` が writing system で絞る前に全 family
  へ `ensurePopulated()` を当てる = プロセスに 1 回。絵文字でも JIS 外の簡体字でも同じ、日本語は一族が持つので呼ばな
  い)。`QFontDatabase` の fallback / emoji API も `QFont::families` も一覧の順を変えるだけで populate は止まらない。止ま
  るのは色フォントを primary にした時だけで、それは run 分割 = 却下。なので `cargo xtask perf` は較正 run
  `run-font-walk` を毎回先に撃ち、歩きの差を report の `font walk` 行に出して、`net` = working set − 差 を判定行にす
  る(較正の組み方は `perf::fonts` と `WindowPerfDriver.qml`)。**offscreen では歩きは出ない**(FreeType DB にフォントが無
  い)ので、歩きの代金は `cargo xtask perf` でだけ読む
- **計測は機械を止めて撃つ(`xtask::still`)**: 仕組みは `crates/xtask/src/still.rs` の `//!`(要約は 反映前テストの機械
  化.md §計測との直列化)。hold 中にセッションが撃つ compile する cargo は pre-shell hook が deny する — 通るのは
  `cargo xtask …` / `cargo run -p xtask …` と compile しない sub-command(fmt / tree / metadata 等)だけ(判定は
  `hook::still`)

## 記録の管理

- **予算に対する答え(§判定)の正本は [perf-windows-x64.md](../ci/baseline/perf-windows-x64.md)**。冒頭に測った
  木(`git rev-parse <commit>:crates/platitude-core` / `…:crates/platitude-app`)・Qt・corpus token を名乗らせ、**同じ
  木・同じ Qt で撮った節だけを並べる**。別の木の表はそう名乗らせ、読むのは表の中の差だけ
