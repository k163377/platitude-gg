# 性能 — 予算・設計規則・計測・記録

**性能に影響を与える変更**(UI 操作の経路・読み込み・常駐データ・描画・起動・画面表示中の読み込み)**の前に読む**。予算と設計規則はここが正本、予算に対する数字の正本は記録 [perf-windows-x64.md](../ci/baseline/perf-windows-x64.md)(本書は撃ち方と記録の置き方)。**Claudeクラウドでは計測しない**([クラウドセッション.md](クラウドセッション.md))。

## 予算

`JetBrains/kotlin` 級(10万コミット超・refs 5 万本、うちタグ 4.5 万)で: 起動→グラフ初回表示 3 秒以内 / 操作応答 100ms / スクロール 60fps / メモリ 300MB 以下。

- 指標ごとに何を測って何で判定するか(操作フィードバック・重い diff と git の書き込み・子の git・長時間使用)は [メモリと操作応答の改善計画.md](メモリと操作応答の改善計画.md) §2
- **メモリは net で読む**(§計測の各論「perf の判定行は net で読む」)。report の MB は実質 MiB(同 改善計画)

- 常駐データの持ち方(`crate::Name`・平らな索引・確保の個数・mimalloc 不採用)は [rules-refs/core.md](../.claude/rules-refs/core.md) §セッション・実装の決定事項
- 形を選ぶ前に支配項を読む — プロセス起動ほかの代金は [code-costs](../ci/baseline/code-costs-windows-x64.md)
- 未着手の非同期化の候補は [非同期化の候補.md](非同期化の候補.md)

## 計測

**いつ**: 段 3(リリース前と依存・環境を触った時 — gate スキル)で §判定 を撃ち直す。それ以外は変更の効果を確かめる時に A/B で撃つ(§cacheとA/B)。**実窓を使うので、席から撃つのはユーザーが明示した時だけ**(`PGG_ALLOW_GUI=1` — CLAUDE.md §ビルド・テスト)。

**判定の 4 行を撃ち直す 2 行**(コーパスの形・座り・画面の条件は記録 §計測条件):

```
cargo xtask corpus
PGG_ALLOW_GUI=1 cargo xtask perf --at <測る commit> --repo <上の 1 行が印刷した path> --runs 5
```

### ケース

連続するケースは周回境界も含めて異なるOIDにする。同じ行の再クリックは改名などの
別ジェスチャーになる。

`--cases <file.tsv>` はヘッダー無しの4列: `name<TAB>full-oid<TAB>path<TAB>completion`。
空行と `#` 行は無視する。nameは英数字・`-`・`_`、OIDは完全長、pathはそのコミットの変更
ファイル一覧に載るパス。completionは `raw` または `coloured`。一覧の順に選択・diffを開き、
`--cycles N` でN周する。反復には異なるOIDが2つ以上必要。

```
cargo xtask perf --repo <corpus> --cases <cases.tsv> --cycles 50 --runs 5
cargo xtask perf --repo <corpus> --cases <scroll-cases.tsv> --diff-scroll --runs 5
cargo xtask perf --repo <corpus> --select-oid <full-oid> --file <path> --completion coloured --runs 5
```

合否はケースごとに判断する。プロセス内反復と別プロセスのrunは別の軸。

通常の変更、多数ファイル変更、小さい変更を含む大きなソース、長いdiffを固定ケースにする。
画像・非対応言語は `raw` として別ケースにする。`coloured` は最終 `DiffModel.coloured` が
立つ対象専用。時間切れは失敗のまま記録する。rawが測るのは画像デコード前まで。

`perf_diff_frame` は対象diffの初回表示、`perf_colour_frame` は同じfingerprintの最終色付けが
反映されたフレーム。
`--diff-scroll` は各操作で可視diffを2秒スクロールし、正の移動量と終了後の可視行を要求する。
短くoverflowのないdiffは失敗なのでスクロール用一覧は分ける。グラフの12秒計測とは別系列。
反復と併用する時は、全操作の計測時間を含む `--watchdog-ms` を指定する。

### cacheとA/B

- `--cache warm` が既定。同じ経路の捨てrunで温める。
- `--cache first --runs 1` は、このinvocationの最初のプロセス。OS cacheの状態は
  別に確かめる。
- `--cache cold --cold-prepare <executable>` は利用者指定のOS固有プログラムを各run直前に
  実行する。repositoryと測定binaryの2引数を渡し、成功終了を準備完了とする。
  準備失敗・期限超過は測定失敗。
  プログラムがどのcacheをどう冷却したかを記録に併記する。成功終了が示すのは準備が
  走ったことだけ。

```
cargo xtask perf --repo <corpus> --at <A> --compare <B> --runs 3 --cases <cases.tsv>
```

A/Bの `--runs` はABBAブロック数。3なら各6回。
画面・Hz・renderer・features・corpus・GPUの記録が変われば比較を中止する。古いcommitが新しい
計測口を持たない場合、要求したケースや色付けの証跡欠落を失敗とする。

### 短いメモリ峰

100msのWorkingSet最大とは別にWindowsの `PeakWorkingSet64`、Linuxの `VmHWM` を
`memory.csv` の `os_peak_working_set_bytes` に記録する。OSが保持するプロセス寿命中の
最大常駐量で、サンプル間の短い峰を検出する。
private commitの峰・割当回数・発生時刻は分からないので、
差が問題になる場合は別の診断runでOSの割当トレースを採る。帰属取得の計測負荷は別runへ
置き、OS最大は素の値で記録する。

### workload別の比較

`cargo xtask corpus --against <reference>` は以下を別profileとして出力する。
プロファイルは軸ごとに独立して読む。

| profile | 入力 | 対応する性能 |
|---|---|---|
| startup/status | 追跡数・directory・index・無視ファイル・git設定 | 起動・status完了 |
| refs | refs数・注釈タグ比・remote階層 | refs読込・ナビゲーション |
| graph/scroll | lane幅・chip数・文字量・フォールバック | frame分布・停止・常駐量 |
| diff | 変更数・ソースサイズ各分位・言語・変更量 | raw/coloured完了・diff scroll |

### OS別の証跡

既定の出力先は `target/perf/<os>-<arch>/<run>/`。
Windowsの正本は [perf-windows-x64.md](../ci/baseline/perf-windows-x64.md)。Linux と macOS arm64 は実機待ちで、取る物と残す物は
[P5-確認事項.md](P5-確認事項.md) §23。

### 計測の各論

- 性能計測の画面対応: Qtの `ScreenInfo.name` は実機でfriendly nameとなりWindowsの `DISPLAYn` と一致しない。HzはPIDの `MainWindowHandle` から採取した画面IDをOS設定へ結合する。詳細フレーム列のログ到着時刻はflush時刻なので、各行のアプリ共通 `clock_ms` を読む。
- **性能計測は機械の状態も測って、駄目な run は落として撮り直す**: `perf::sampler` が 100ms ごとに WorkingSet / private に加えて機械の状態を採る。**対象プロセスの CPU は job object で子孫の git まで込み**(**アプリは `CREATE_SUSPENDED` で起動して join 後に sampler が resume する**ので、最初の命令から job の中 — 計時の起点はその `resumed`。nested job は Claude Code の job 配下からでも通る)。**ロックの判定は「最前面の窓を持つ pid が `LockApp` / `LogonUI` か」**(ロック中も 0 でないハンドルが返り、`LockApp` は解除後も常駐するので存在も根拠にならない)— ただし**0 は 3 つ目のケース**でロック相当に落とす(セキュアデスクトップ = UAC・Ctrl+Alt+Del・ロックの前後)。**落とす条件は「窓が描かれていたか」** — このアプリは起動元シェルからフォーカスを奪わない事があり、前面でなくても合成も表示もされる。落とすのは **ロック / セキュアデスクトップ(どちらも連続 3 tick から — 単発の 0 はフォーカス移動で出る)/ 最小化 / 落ち着いた後の画面移動 / 画面の Hz に対して配信フレームが半分未満 / ベンチが始まってから 30 秒で終わらない / 対象以外が機械の 35% 超**。**ベンチの 30 秒はレートの言い換え**(12 秒のアニメーションは画面のフル レートでだけ 12 秒で終わり、frame gate が通す下限の半レートで 24 秒)なので、`--allow-noisy` では他の関門と一緒に開く。落ちた run は `wait_for_quiet` で機械が静まるのを待ってから撮り直す(`--retries` 既定 3)。**被さり(`Spoiled::Covered`)だけは 2 度で諦める** — 被せた物は通り過ぎるか居座るかの二択。**捨て run は、数分内に同じ exe・corpus・path・シナリオを温めた invocation の直後で、その後に他プロセスのビルドが終わっていなければ省く**(`perf::warmth` が `target/perf/warm.txt` に note を残し、判定は hold を取った後)。CPU の閾は「並行ビルドが居る」を捕るためで、ブラウザや IDE が開いている程度(24 スレッドで 11〜32%)では落とさない
- **表示に依らず測るのは `perf --software`**: 表示が消えている間、D3D11 の swap chain は 1 枚も present しない。software scene graph(`QT_QUICK_BACKEND=software`)は点灯でも消灯でも同じ経路で描き、完走する。だから `--software` は**表示の状態から独立**: wake helper は入力注入なしの `ES_SYSTEM_REQUIRED` だけ、窓を前面へ上げ直さない(在席中の人の目の前に出さない)、sampler の `dark=`(`PerfDisplay`)は証跡。**点灯前提の D3D run のほうは 1 tick の消灯で落とす**。**読めるのはメモリだけ**: software の WorkingSet は D3D の床が無い別の量なので、同じ commit の D3D 値と並べて読む。frame gate(画面 Hz の半分)は software では効かせない。ロック・被さり・CPU の閾は効く
- **画面は invocation の間ずっと起こしておく**(`perf::sampler::keep_awake` — 親の生存と**起動時刻**を毎周確認する子 PowerShell。pid は再利用されるので番号だけでは足りない)。**run の間だけ `ES_DISPLAY_REQUIRED` を立てるのでは足りない** — 既に暗い画面は起こせないので、ビルドと run 間の待ちで暗くなると 2 本目以降が毎回暗い画面から始まる。起こすのは入力なので **0 ピクセルのマウス移動を注入する**。**その副作用で `away_ms` は「人が居たか」を答えなくなる** — 答えるのは「起こす側が動いているか」だけ。PowerShell は `0x80000003` を負の `Int32` と読んで `uint` に渡せないので、**10 進で書く**
- **窓は名前の付いた画面へ固定する**: run ごとの `PGG_CONFIG_DIR` に `state.toml` を書いて `[window] x/y/width/height` を渡す(`PGG_CONFIG_DIR` は `Build::driven` に勝つので、ハーネス有無どちらのビルドでも効く)。**どの画面に出たかが fps をそのまま決める**。fps は画面の Hz に対する割合も併記し、`over_16_ms` を「どの Hz でも同じ問い」として読む。窓は最初の 1 秒だけ別画面に居てよい(platform が置いた所から `applySavedWindow` が動かすため)
- **ベンチマークリポジトリは `HEAD` では固定できない**: 既定 `--selection first` が選ぶのは `HEAD --branches --remotes --tags` の最新 = リモート ref 由来の行で、`git fetch` はローカルブランチを動かさずにそれを変える。`perf::corpus` が `show-ref` 全体の blob id を token にして印刷し、**run の前後で突き合わせる**。記録を取り直す時は記録の token を `--corpus` へ渡す。**なので測るのは `cargo xtask corpus` が生成する合成リポジトリ**(`xtask::corpus`)— 生成器が固定なので消して作り直しても同じ id が出る。**本体 checkout 直下の gitignore 済み `.pgg-perf-corpus/` に 1 つ**(席の中や `target/` は 6 個になる上 `cargo clean` で消える)。**kotlin との距離は `cargo xtask corpus` と `cargo xtask corpus --against <repo>` が同じ実装で両列を出す** — 正本は [perf-windows-x64.md](../ci/baseline/perf-windows-x64.md) §コーパスと kotlin の距離。**形を変えると token が変わり判定表ごと撮り直し**になる
- **計測したビルドを名乗らせる**: manifest の `features=` が何を頼んだかを持つ。`perf --shipped` は出荷ビルド(feature 無し)を測る — 答えられるのは**メモリと `graph stream finished` までの時間だけ**で、リポジトリは `state.toml` の `[tabs]` から開く(出荷ビルドに引数の口は無い)
- **計測は計測台(rig)で撃つ — `cargo xtask perf --at <rev>`**: roster 外の worktree `.claude/worktrees/rig`(`seats::RIG`)に名指しの commit を載せ、release ビルドし、exe を commit 単位で置く(`perf::rig`)。**同じ commit の 2 度目はビルド無し**。**測られるのは commit だけ**(席の編集を測るなら commit してから `--at HEAD`。`--at` 無しは席の exe = 編集込み)。**触るのは機械だけ** — EnterWorktree(名前でも path でも)と Write / Edit は hook が deny、rig が dirty なら perf は reset せず拒む。証跡は撃った席の `target/perf/` に落ちる。**CPU の並行は増えない** — 実窓の計測は他席のビルドと同時に撃てば foreign 35% で落ちる(隣で続けてよいのは編集・思考・git だけ)— **その順序付けは `still` がやる**
- **perf の判定行は net で読む(`--no-font-walk` で素の gross)**: 一族(`Yu Gothic UI`)に無いグリフを 1 つ組むと Qt がフォント DB の全 family を populate する(`QPlatformFontDatabase::fallbacksForFamily` が writing system で絞る前に全 family へ `ensurePopulated()` を当てる = プロセスに 1 回。絵文字でも JIS 外の簡体字でも同じ、日本語は一族が持つので呼ばない)。`QFontDatabase` の fallback / emoji API も `QFont::families` も一覧の順を変えるだけで populate は止まらない。止まるのは色フォントを primary にした時だけで、それは run 分割 = 却下。なので `cargo xtask perf` は較正 run `run-font-walk`(`perf_done` の前に `WindowPerfDriver` が U+1F352 を 1 つ組み、`perf_font_walk_begin` / `done` / `settled` を言う)を毎回先に撃ち、begin の直前と settled の直前の tick の差を report の `font walk` 行に出して、`net` = working set − 差 を判定行にする(`perf::fonts`)。**offscreen では歩きは出ない**(FreeType DB にフォントが無い)ので `verify-ui perf font-walk` は 3 行の順序だけを見る
- **計測は機械を止めて撃つ(`xtask::still`)**: 仕組みは 反映前テストの機械化.md §計測との直列化。`PGG_STILL_UNDER=1` は `still::step` を `watched::run_step` とコンテナの run が付ける。announce の終わりは `pgg-built/<pid>` に時刻を残す(`perf::warmth` が読む)。セッションが撃つ cargo は pre-shell hook が **`cargo xtask …` と `cargo run -p xtask …`、compile しない sub-command(fmt / tree / metadata 等)だけ通し、他は hold 中 deny**(コマンド位置の cargo だけ — `git commit -m "… cargo test …"` は対象外。`cargo +stable build` / `cargo.exe build` / `cargo test -p xtask` / `echo x | cargo build` / `env X=1 cargo test` / `bash -c "cargo build"` は止める)

## 記録の管理

- **予算に対する答え(§判定)の正本は [perf-windows-x64.md](../ci/baseline/perf-windows-x64.md)**。冒頭に測った木(`git rev-parse <commit>:crates/platitude-core` / `…:crates/platitude-app`)・Qt・corpus token を名乗らせ、**同じ木・同じ Qt で撮った節だけを並べる**。別の木の表はそう名乗らせ、読むのは表の中の差だけ
- **比べてよいのは条件を揃えた値だけ** — 揃える軸は §cacheとA/B(画面・Hz・renderer・features・corpus・GPU)
- run の生データは `target/perf/<os>-<arch>/<run>/`(§OS別の証跡)。記録へ写すのは判定と読み
- **1 つの問いに答えた実測は `ci/baseline/<主題>-<os>-<arch>.md`** — 今あるもの: コードの判断の代金 [code-costs](../ci/baseline/code-costs-windows-x64.md) / 画面表示中の読み込み [poll-cost](../ci/baseline/poll-cost-windows-x64.md) / refs の join [refs-join](../ci/baseline/refs-join-windows-x64.md) / 先端を他が掴んでいるか [head-reach](../ci/baseline/head-reach-windows-x64.md) / git の実行枠 [git-slots](../ci/baseline/git-slots-windows-x64.md) / アバター [avatar-log](../ci/baseline/avatar-log-windows-x64.md)・[avatar-shrink](../ci/baseline/avatar-shrink-windows-x64.md) / 依存更新の前後(段 3 の性能実測を撃った最後の 1 本)[deps-update](../ci/baseline/deps-update-windows-x64.md)
- **コメントに時間・メモリ・機材構成の実測値を書かない**(rules/code.md)— 数字が要るなら code-costs へ 1 行足してそこを指す
- 判断・却下・要調査は確認事項へ(下の §現状と残件)
