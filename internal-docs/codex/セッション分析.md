## 対象と数え方

2026-10-17 の調査。対象はローカルの `.codex/sessions/2026/10/` にある platitude-gg の記録で、
今回の会話より前の **20 セッション・65 ユーザー発話レコード**。実際の発話日は 10 月 4 日〜17 日(JST)。
全 `.codex/sessions/` の metadata も照合し、インポート・子agent・今回の会話を除いた対象プロジェクトの
保存セッションが同じ 20 件であることを確認した。

最初に見つかった 119 ファイルから、`external_agent_session_imports.json` の `imported_thread_id` と
照合した Claude のインポート 74 件、guardian・子agent 24 件、今回の会話 1 件を除いた。
Codex の `session_meta.originator` だけでは Claude のインポートを区別できない。

`response_item` の user message を抽出し、付属メタデータがある場合は `user.text` だけを採った。
AGENTS・環境情報・open-page の注入や tool output は含めない。同じ発話の重複表現は二重に数えない。
継続・再開・添付の発話も分母に含む。引用された指示は、それを採用して依頼している発話の 1 件として数え、
引用内の各文を別件にはしない。

下表はキーワード出現数ではなく、全 65 発話を読んで当該指示が含まれる発話を分類した件数。
分類は重なる。**指示の反復数であり、違反や不具合が起きた回数ではない**。
集計期間外の傾向や、過去の指示が現在も有効かまでは、この頻度からは判断しない。

## skill とハーネスへの対応

Codex が探索する `.agents/skills/` に skill を置き、`AGENTS.md` は適用条件とパスを持つ。
`platitude-claude-review` は引き継ぎの根拠・出力を扱い、レビュー観点の本体は共有 skill から読む。
`platitude-policy-edit` は規約編集の範囲と最小差分を扱い、文書の配置基準は `CLAUDE.md` を参照する。
`platitude-seat` は現在のタスク ID と Git 管理領域への書き込み権限を確認し、席を取得する。

文書中のコマンド参照を正本へ照合する `docs/commands.rs` の対象に `.agents/skills` を含める。
skill 本体と参照文書を同じ検査へ通す。一時的な分析結果は `target/` へ保存する。
自然言語の意味は代表的な依頼との照合で評価し、実運用での改善はその後の応答で確かめる。

適用範囲は実際の依頼にも照合する。「レビューして」は引き継ぎ skill、
「レビューし、必要なら修正して」は実装を含む依頼として共有レビュー観点へ進む。
費用の質問・指示書の再出力停止中は質問へ答え、`gate` の語句訂正では規約編集 skill を使う。
通常の UI 修正・起動は既存の verify-ui skill を使う。

Codex 向けの改善はプロジェクト内で管理する。
skill 一覧への自動探索は新しいセッションで確認する。現セッションではパスから直接読み込める。
