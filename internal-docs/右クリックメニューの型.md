# 右クリックメニューの型

右クリックのメニューを要素の型から組み立てる設計。**正本は型** —— core の `menu` モジュールで、規則はモジュールの冒頭、
分類・部品・席・理由はそれぞれの型の説明が言う。規約(デザイン規約 §メニュー・app-ui.md)は型を指す数行の補足で、個々の当
てはめを書かない。本書が持つのは型と描く部品の分担だけ —— 当てはめで決まった事は型の説明と規約が、残る問いは
[P3-確認事項.md](P3-確認事項.md) が持つ。左クリックで開く選ぶ一覧(ツールバーの REPOSITORY / WORKTREE のカード、操作パネ
ルの枝のカード)は行き先を選ぶ物で、ここの対象ではない。

## 慣習か独自か

- **Apple**([HIG の Context menus](https://developer.apple.com/design/human-interface-guidelines/context-menus)): 使えな
  い行は灰にせず隠す。例外は macOS の Cut / Copy / Paste。
- **Microsoft**([Win32 の UX ガイドの Menus](https://learn.microsoft.com/en-us/windows/win32/uxguide/cmd-menus)): 今の文
  脈に当てはまらない行は外す。あると期待される行(標準の行、組で揃う行)は無効で並べる。メニューバーは逆で、並びを安定させ
  るために無効にする。
- **この製品**: 分類に無い行を並べないのは慣習と同じ。分類に在って今押せない行を灰で並べるのは §メニュー のユーザー決定
  で、Microsoft の「あると期待される行」の側(同じ分類の物はいつも同じ行を持つ)、Apple とは逆。

## 型が受け持つ範囲

- **範囲**: リポジトリに働く行の有無と押せるかと席 —— 左メニューの ref 行(BRANCHES / WORKTREES / REMOTES の枝 / TAGS /
  STASHES)、グラフの行(コミット・stash・別の worktree の未コミット)、作業ツリーのファイル行、プランの段、REMOTES のリ
  モート自身の行。入口は 1 つ(`menu::lines` が右クリックした物 `menu::On` を受ける)で、`GitFacts.menuOn` / `carriedMenu`
  / `filesMenu` / `remoteMenu` と `RebasePlanModel.stepMenu` が答える。行の文(`switch` と `Open` の言い分
  け、`-D`、`push` の形)は型に無い。
- **型の外 —— 事実を持つ部品の固定の表**: 画面を読むだけの行(`Copy path`、diff の `Copy` 2 行、GITHUB のカードと、それだ
  けを持つ 2 つのコミットの選択のメニュー・コミットの変更ファイルのメニュー)、文字の欄の編集の表(`FieldMenu` —— OS の欄
  と同じ表)、☰(`AppMenuButton`)。事実(選択・欄の取り消しの履歴・ページの有無・向こうの持ち物)が部品の中にしか無く、core
  に渡しても型は真偽を写すだけになる。規則は同じ —— 対象の種類が行を決め、状態は押せるかだけを決める。
- **型の入力は今の事実** —— ref とグラフの行は `menu::Subject`(右クリックした行 `menu::Seen` と、`GitFacts.menuOn` と
  `RefMenuFacts.stand` が持っている入力)から分類と状態を組む(`Facts::of_subject`)。ファイル行は選択の区画、プランの段は
  下の段、リモートは印の設定。
- **行ごとの試験は型の上で書く** —— どの分類に在り、どの理由で灰になるか(`menu/tests/`)。
- **表は型が書く** —— 分類ごとの行の
  表(`table`)は、[`menu/tests/snapshots/`](../crates/platitude-core/src/menu/tests/snapshots/) のスナップショット。本書
  へ写さない。

## 描く部品(`MenuLines`)

- **型の答え(`encode::MenuAnswer`)を描くのは `MenuLines`** —— 行の宣言と種類の名乗り・並び・灰・群の区切り・立て直す時機
  は、その冒頭と `standAgain` の説明が言う。行が持つ物(押せるか・キーの止まり方・開いた時の相手へのリース)は
  `AppMenuItem`(`ownBlocked` / `enabled` / `leaseMoved`)、メニュー全体に掛かる待ちと保留は `AppMenu`(`rowsHeldWhy` /
  `waiting`。タブが開く前は型の `Why::Opening`)。
- **開いている間は開いた時の行のまま**(§メニュー の既存の決定)。
- **右クリックした物の同一性と、開いている間に届く git の答えは開く側が持つ**(`RefRowMenu.standAgain` /
  `CommitMenuState.standAgain`、BRANCH カードの `RefBranchMenu.refused`)—— 分類ではなく、開いた物が何かの話。WORKTREES
  の行はその worktree が出している枝のメニューで、開いたままその worktree が枝を離れる(外で消える・別の枝へ移る)と、押せ
  る行は worktree そのものに掛かる行(型の `Row::on_worktree`。消えた worktree には無い)だけになり、他の行は灰で席に残
  る(`RefRowMenu.standOn`、`GitFacts.worktreeLeft`)。
- **機械が守る** —— `cargo xtask structure` の `structure::menu_words`(何を見るかはその冒頭)。開いたメニューが答えの行の
  部品を持たなければ、描く部品が言い(`MenuLines.undrawn`)、verify-ui と qmltest の赤になる(`verify::gaps`)。QML テストが
  手で組む答えの席は代役の表(`tests/qml/stubs/GitFacts.qml` の `seats`)で、`encode::menu` の試験が core の席と照らす。
