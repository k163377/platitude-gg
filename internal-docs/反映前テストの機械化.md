# 反映前テストの機械化(gate)

入口は `cargo xtask gate`(USAGE が正)。

**gate と check が撃つ cargo は全部 `--locked`**(`cargo xtask` の alias 自身も)。`Cargo.lock` を書き換えたい cargo は「lock file needs to be updated」の赤で止まる(依存の変更は人の許可が要る = CLAUDE.md 絶対制約。ロックを本当に更新する時は人が `cargo update -p <crate>` を撃って commit する)。`cargo fmt` だけは素のまま(依存を解決しない)。CI(`.github/workflows/ci.yml`)の cargo も同じ綴り。

**手で撃つコンテナ行にも `linux` が付ける**。`/work` はホストの checkout そのものなので、コンテナの中で解決する cargo はホストの `Cargo.lock` を書く cargo でもある。**既定が locked で、リストは例外の側**(`linux::UNLOCKED_VERBS`)— 解決する動詞を数え上げるリストは取りこぼすと**黙って**ホストのロックを書き換えるが、要らない動詞に付けた場合は撃った人の前で赤く止まるだけ。`--locked` を受けない third-party サブコマンドは後者なので、`--shell` で回すか例外へ足す。

**赤いステップのログは実行単位で残る**(`gate::evidence`)。ログ名はステップ番号なので同じ木の次の gate が上書きする — 赤は `target/gate-logs/failed/<run>/` に写しが残る(新しい 10 run 分)。**cargo がロックファイルで止まった赤だけは**、ホスト側の答え(解決が読む全ファイルのバイト数と sha256・こちらの cargo・イメージ ID)を写しの隣に書き、コンテナ側の同じファイルの見え方は、動かすコマンドの前後で挟んだ look がログに残す(`linux::watched_from_inside`)。

**この証拠が言えること**: 前の端が `bytes=0` なら、その run に空が渡っていたという事実。両端とも無事なら「前後には立っていなかった」まで — **cargo 自身が読んだ瞬間は挟めていない**。コンテナの PID 1 は `sh` — 中のプロセスを覗く時、動かしたいコマンドはその子。

## 依存木(`gate::graph`)

ノードはファイル(workspace 相対、末尾 `/` はディレクトリ)。辺 `a → b` は「a が b を読む」。逆閉包(reach)= 変更ファイルを読む全ファイル。**QML ノードは QML の読み手とディレクトリノードにだけ伝播**(QML 変更が届くのは QML をディスクから読む xtask のテストだけ)。

**Markdown(`.md`、拡張子の大小文字を問わない)の変更はテスト選択の外** — 依存の辺・テスト選択の起点・ステップのキャッシュ入力から除く(コードや assets・ハーネスのディレクトリ内でも同じ)。`structure` / `waits` / `docs` / `fmt` の常時チェックは残る。

- **`mod x;` 宣言は辺ではない**(辺にすると宣言する root / mod.rs が全体へのハブになる)
- 文字列リテラルが workspace のファイル / ディレクトリを名指ししていれば辺(xtask の structure が `ui/` を読む等)。**パスの形をした文字列が読み取りとは限らない** — バイト文字列・自分を含むディレクトリ・`crates/xtask/verb-census.txt` は辺の外。そして**ステップの鍵が名指すパスは、そのファイルの読みとは別** — `plan.rs` の `core()` / `app()` / `harness()` / `qml_dirs()` が**パスを分割して綴る**のはこのため(丸ごと綴ると core の 1 ファイルの変更が plan.rs を読み手にし、そこから runner の全テストへ届く)
- **製品のファイルを「読む」到達は、統合バイナリの手前で止まる**(`graph::Carried`)— 統合バイナリは自分で建てたサンドボックスへ向けて撃つ。**reach は各ファイルに「どこまで渡されたか」を添える**: `Whole`(変更そのものと、それを組み込むコード)/ `AsProductFile`(製品外のファイルがディスクから読む製品データ)。製品の変更は app / core のディレクトリノードを通って xtask のほぼ全体へ `AsProductFile` で届く(`gate deps --why` は `(as a product file the tool reads)` と添える)が、そう届いた製品外のファイルのコードは変わっていない — **ファイルの名指しで選ぶステップ(動詞 = `verify` / `demo`、`qmltest` = `qmltest.rs`、wedge = 記録の経路)と、コードしか読まない clippy は `Whole` でだけ選ばれ**(`plan::steps::Sorted::rust_moved`)、そのコードのテスト(単体・統合)はどちらでも選ばれ、鍵の入力も変えない(ツールのテストがそのデータを読み得る。**分割するだけでは「読まない」の証明にならない** — 読んだファイルをテスト自身に言わせる保証が要る。候補は §残る候補の棚卸し)
- **鍵の入力は同じ止まり方を逆向きに読む**(`Graph::inputs`): 統合バイナリのモジュールから前方へ辿る時、製品外のファイルがデータとして読む製品ファイルは入力に入らない(そこを変えてもバイナリへ届かない)。ツールのコードと、実ツリーから読む製品外のファイル(hook スクリプト)は入る。QML の規則は逆向きには読まない — QML を名指す Rust は鍵にそれを持つ

**木そのものへの苦情は毎回の gate が読む**(`graph::complaints`)—「全パス解決」と「root に読み手なし」の 2 つで、赤ければ**入口で拒む**。どちらも今の変更の落ち度ではないが、**解決しないパスは引かれなかった辺**で、その辺が運ぶはずだった選択が丸ごと欠ける。root の規則は rules/structure.md §分割。

診断: `cargo xtask gate deps --file <path> --why <path> --show` / `--history <n>`(診断はキャッシュを使わず毎回ソースから読む)。

## ステップの抽出(`gate::plan`)

| ステップ | 条件 | 側 | キャッシュキー(読むもの) |
|---|---|---|---|
| structure / waits / docs / verbs / fmt | 常時(秒。キャッシュしない) | host | — |
| `deny`(= `cargo deny check bans sources licenses`) | `deny.toml` の変更、またはビルド入力の変更 | host | `deny.toml` + Cargo.toml / Cargo.lock + `crates/*/Cargo.toml` |
| `clippy -p <crate>` / `linux clippy -p <crate>` | reach にそのクレートの .rs が **`Whole` で**ある(製品データとして届いただけのクレートは選ばない — §依存木。全体の時は全クレート) | host / linux | クレート dir + Cargo.* + toolchain(+ Dockerfile) |
| `test -p <crate> --lib\|--bin -- <module::>…` | reach の中でテストを**定義する**ファイル(`#[test]` かインライン `mod tests {`。`#[cfg(test)] mod x;` の宣言は違う)。root が含まれれば全部 | host(core / xtask は linux も) | 選んだテストファイルの**前方閉包**(それらが読む全部)+ Cargo.* |
| `test -p <crate> --test <binary> -- <module::>…` | reach の統合バイナリ(`tests/it/main.rs` と `tests/*.rs` は各々が crate root)。`main.rs` / `support/` が含まれれば全部 | host(core / xtask は linux も) | 同上。統合バイナリでは、ツールがデータとして読む製品ファイルは鍵に入らない(§依存木) |
| `test -p <crate> <target> -- --ignored ::periodic::` | **段 3(`--all`)だけ**。そのテストターゲットのファイルが `mod periodic` を持つ時(日常の段に見合わないテスト — rules-refs/core.md `periodic`) | host(core / xtask は linux も) | 同上 |
| `qmltest` / `linux qmltest` | reach に製品の QML(`ui/`)か `tests/qml/tst_*.qml`、または `qmltest.rs` のコード変更(全体の時も。QML が届いただけの `qmltest.rs` は選ばない — §依存木) | host / linux | `ui/` + `tests/qml/` + `qmltest.rs` |
| `shipped`(`target/shipped` に組む — §hook は自前の build directory で動く) | reach に QML か app の main.rs | host | app + core + Cargo.* |
| `verify-ui <行>` / `linux verify-ui …` | reach の部品を census に持つ行(+ `--verb`)。ハーネス(verify / demo)のコードに変更が届く時と全体検証は census の全行(製品データとして届いただけでは選ばない — §依存木)。**選んだ行のうち段分け表(`crates/xtask/verb-tiers.txt`)が `full` / `twin` とする行は反映前は回らず、コンテナが回すのは `linux` 行だけ**(§段ごとに何を回すか。`--verb` の行は両側)。**board には載せない**(board に載るのは明示的に撃った run だけ) | host / linux | app + core + xtask の verify / demo + Cargo.*(+ Dockerfile) |
| `linux bare` | reach に app / core の .rs か QML、または Dockerfile の変更 | linux | app + core + xtask/src/linux + Dockerfile + Cargo.* |

`deny` が回すのは `bans` / `sources` / `licenses` の 3 つだけ — `advisories` は RustSec DB を github.com から取るので**段 2 はオフラインで完結させ、4 つ目は CI(`.github/workflows/ci.yml` の `deny` job)に残す**。cargo-deny 未導入は**赤**(スキップすると policy 未検査のまま commit にスタンプが付く)。

**ビルド入力の変更(`Cargo.toml` / `Cargo.lock` / `rust-toolchain.toml` / `clippy.toml` / `.cargo/` / `crates/*/Cargo.toml` / `crates/*/build.rs` / `crates/platitude-app/assets/` / Dockerfile)は reach を全ファイルにし、テストは filter 無しで全部回す**(ソースのグラフには依存の更新が映らない)。**消えたソース(`.rs` / `.qml` / `qmldir`。改名の旧名も)も同じ** — 消えたファイルには読み手の辺が立たず、reach がそのファイル 1 つで閉じて何も回らない(`plan::gone_source`。消えたテストは例外 = `plan::gone_test`)。**reach の QML 部品を census のどの行も出していなければ gate は赤**(名指し。singleton / `QtObject` root は item tree に立たないので対象外)。

## 動詞の絞り込みは比較表示に留める(`plan::verbs_in_snapshot`)

**実行するのは reach が名指す行**。変更部品を終了時の census に持つ行は **shadow 候補として数えるだけ**で、実行数と候補数を別々に印字する(`verbs: 353 selected; shadow candidate: 15 ...`)。census は終了時点の表示で、途中で使った部品は載らない — `settings-escape` は `SettingsDialog.escapeOut()` を呼んで閉じるため終了時の census に `SettingsDialog` が無く、この不在を根拠に除外すると終了処理を壊してもその検証が実行されず gate が PASS する。実選択への適用には、途中で閉じる popup・破棄される Loader 等も含む依存の記録と、候補外の検証を落とさない故障注入の比較が必要。

## キャッシュとスタンプ(`gate::stamp`)

ディレクトリを入力に持つステップは、Markdown を除いた配下から指紋を作る(`gate::inputs`)— Git のディレクトリ tree id をそのまま鍵にすると、Markdown を追加・編集・削除しただけでテストが再実行される。

**アプリをビルドして走らせるステップ(`shipped` / `verify-ui` / `bare`)は、製品 2 クレートを丸ごと読む**(配下の `tests/` も指紋に入る)。**テスト専用の配下を指紋から落とす案は採らない**: 落としてよいかは否定の証明で、ソースの走査では「見つからなかった」までしか言えず、外れた時の答えは「緑を使い回す」。回帰条件は `stamps::a_file_the_product_opens_is_owed_though_no_scan_could_find_it`。代金: 製品変更を含むブランチへテストを足すと、そのブランチの `shipped` / 動詞 / `bare` が 1 度ずつ回り直す。**この代金を外すなら、必要なのは走査ではなく保証**(ビルドが読んだファイルをビルド自身に言わせる等)。

ステップの緑は `(id, コマンド, 読むパスごとの object id)` の鍵で `<git-common-dir>/pgg-gate/steps/<key>` に記録(**木全体を `git ls-tree -r -t` 1 回で引く** — ステップ × 入力ごとに `rev-parse` を spawn すると計画だけで分の桁になる)。同 commit の 2 度目は何も回らず、rebase で SHA が変わっても読む tree が同じなら緑のまま。`--host-only` は host 側だけ回して commit に `full=false` で記録し、フルの gate はコンテナ側だけ追加で回す(**フルのスタンプが既に在る commit へ `--host-only` を撃っても `full=false` に格下げしない**)。`--fresh` はスタンプを無視。環境(ホストの Qt 等)はキーに入らない。

**依存木そのものも棚に載る**(`gate::reuse`): 鍵は **commit の root tree の object id + 読んだ実行ファイルの全バイト**、置き場は `<git-common-dir>/pgg-gate/graphs/`(席をまたいで共有)。**棚に載せるのも読むのも clean な木だけ**(グラフは作業ツリーから読むので、commit の tree はそれを説明していない)。`graph cache` 行は端末と `target/gate-runs/` の両方へ残る。

run の残骸は gate が掃く: 動詞は `%TEMP%` の `pgg-verify` / `pgg-demo` / `pgg-linux`(と xtask のテストの `pgg-census`)へ run 固有のディレクトリを置き去りにするので、**gate は入口で 1 日より古い物を背景スレッドで消す**(`verify::sweep_yesterdays_runs`。絵の正本は board で、run の直下に残る PNG は 1 日で捨ててよい物)。preset の雛形も同じ掃除に乗り(掃かれた雛形は次の run が組み直す)、コンテナの中には gate が居ないので、雛形を組む時にも同じ掃除を撃つ(`demo::template`)。**雛形の指紋は preset を組むソース・git の版・UTC の日**で、席と gate を跨いで 1 組を使う。**実行ファイルのバイト列を鍵にしない** —— リンクのたびに PE の時刻と PDB の GUID が変わるので、relink ごと・席ごとに全 preset の雛形が組み直しになる(代金は code-costs §テストとハーネス の雛形の行)。

**掃くのは run が置き去りにした物だけ**: `cargo xtask demo-repo` は人が見るために木を建てる口なので、根に `.pgg-keep` を置き、掃除はこれを持つエントリを日付に関わらず飛ばす(`verify::keep`)。**印に寿命は無いので、印の付いた木を消すのは人の仕事**。

**docker 側は `linux` が入口で掃く**(`linux::housekeeping`)。`git worktree list` が挙げる checkout 全部の名前と tag の集合に無い `pgg-linux-{target,demo}-<名前>` のボリュームと `pgg-linux:<stage>-<指紋>` のイメージを消して印字する(`pgg-linux-registry` は機械のもの)。**遅れた席の世代を守るのは build cache の上限ではなく、この keep 集合**(席が main より遅れているのは正常なので、Dockerfile / ci.yml / rust-toolchain.toml が動いた日は世代が 2 つ同時に生きる)。罠と vhdx の話は P3-確認事項 §開発環境(Linux コンテナ)。

**共有 registry への展開は錠ごと共有する** —— イメージが cargo の 2 つの錠(`.package-cache` / `.package-cache-mutate`)を registry(`linux::REGISTRY_MOUNT`)へリンクしている(ci/linux/Dockerfile。形は `linux::tests::the_package_cache_locks_live_in_the_shared_registry` が見張る)。錠がコンテナごとだと、同じ新しいクレートを 2 つのコンテナが同時に展開し、後の側が `.cargo-ok` の `File exists` で落ちる(`failed to unpack package`)。世代が 2 つ生きている間は、リンクの無い古い世代のコンテナとの間にだけ衝突が残る。

commit スタンプ `<git-common-dir>/pgg-gate/commits/<sha>`: `main=` `base=` `onto_main=`(base == main)`full=` `step=…`。必要ステップが全部緑の時だけ書く。`run` は clean な tree。

## 群の並走と動詞の並列(`gate::sides` / `gate::sides::verbs`)

側の中のステップは **build directory を共有しない 2 群に分けて並走させる**。**checks 群**(clippy・test・deny・qmltest・shipped — `target/debug` と `target/shipped`)は計画の順に直列で、**最初の赤で群が止まる**(ビルドが落ちた群の後続は雑音)。**built-app 群**(verify-ui の動詞と linux の `bare` — 動詞の 1 本目がビルドする `target/release` を読む側。`plan::Step::release`)はその隣で走る。先頭の always ステップ(structure / waits / docs / verbs / fmt — host の物)だけは**両側より前に**単独で回す(`gate::sides::run_sides`)— そこの赤は人がまず直す物で、隣で動詞を回しても直しがアプリを変えて緑を無効にする。代金は同居だが、直列より 16〜22% 短い(§実測)。

動詞同士が共有するのは最初の 1 本がビルドする release だけ。なので側の動詞は 1 ブロック: **最初の未キャッシュの 1 本が単独で走ってビルドし、残りは `--no-build` で `--jobs` 本ずつ並列**。**赤が出れば run 全体が止まる**(§最初の赤で止まる)。`--keep-going`(と `--all`)の時だけ赤があってもブロックは進み、緑は個別に stamp される。**例外はアプリ自体がビルドできなかった赤**(その動詞の log に `could not compile` / `cargo build --release failed`): 次の 1 本も同じソースを同じエラーまで組むだけなので、ブロックをそこで止めて回さなかった本数を名指す。

**xtask のステップは runner の複製から起動する**(`gate::runner`)。計画は `cargo run --locked -p xtask -- <verb>` と綴ったまま(stamp の鍵がどの機械でも同じ 1 行を名指すため)、実行時に `gate::runner::launched` が先頭を複製(`target/gate-logs/xtask-runner-<pid>`)のパスに差し替える — cargo は `target/debug` をビルドの間ロックするので、`cargo run` の launcher 同士と隣の群の `cargo test` が待ち合う。

`--jobs` の既定は**論理 CPU の 1/3、1〜8**(`gate::default_jobs`)。値の根拠は §実測。

## 最初の赤で止まる(`gate::halt`)

**赤が 1 つ出た run の判定はもう決まっている**。残りを走らせて得られるのは、通ったステップの stamp だけ —— そして **動詞は app と core の木を丸ごと読む**ので、赤への直しはその stamp をほぼ必ず全部無効にする。

- **最初の赤で両側が止まる**: 新しいステップは始めない・予算の順番待ちは(計測の hold 待ちも含めて)席を譲る(`budget::Pool::admit_unless`)・走っているステップは子ごと終わらせる(`check::run_step` の `stop`、gate のコンテナの中は `linux::container::stop_step`)。**自前のコンテナを立てる `linux` のステップ(clippy・test・`bare`・runner の準備)は止めずに終わりまで走らせる** —— launcher を刈ってもコンテナは走り続けるので、止めると予算の ticket だけが先に返り、動いている仕事の分だけ他席が過剰に入る(`gate::runner::execute_step`)。止めたステップと始めなかったステップは ledger に **`halted`** の行(stamp は無く、次の run が払う)。終わりに `stopped at the first red (<id>)` と言う
- **`--keep-going` は残りを走らせる**: 動詞の赤は他の動詞を止めず、checks の赤はその群だけを止め、通った物は stamp される。**`--all`(段 3)はこれが既定**。**always-step の赤は `--keep-going` でも止まる**
- 代金: 赤が直しの要らない物(負荷の揺れ等)だった時、止まった分は次の run が払う。負荷でだけ出る赤は規約違反として直す物(CLAUDE.md Rust 規約)なので、そちらに合わせて最適化はしない

## 機械の予算と優先キュー(`budget`)

**gate 1 本の負荷はプロセスの束**で、席が同時に gate を回せばその全部が足し算になる。**数えるのは全部のステップ**: ステップ 1 個 = 1 単位で、走る前に機械共通の予算から **ticket** を取り、終わったら返す(`gate::step::run_one`)。両側は同じ予算から引く。

**重みは 2 つだけ**(`budget::weight_of`): **LIGHT=1** = コンパイラを起こさない 1 プロセス / **COMPILE=4** = コンパイラかテストバイナリを起こす物。**重みは投入制御**(cargo は中で並列に動く)。

**予算 = gate 1 本ぶん**(`budget::demand`)。**単独 gate が自分自身を待たない値**であり、2 本目の gate はその中を分け合う。`--jobs` を既定より大きく撃った gate は ticket にその値を書き、生きている ticket の最大値がプールになる。

**優先度は 3 段**(ユーザー決定): **main 反映(`Rank::Landing`)> 起動(`Rank::Launch`)> 他のテスト(`Rank::Normal`)**。起動(`cargo xtask launch`)で**数えるのはビルドと起動まで**で、立った窓自体はユーザーの物で予算の外(verb を headless で撃つのはテストなので `Normal`)。

**規則は 1 文**: *待っている単位は、順序付けたキューの「空きに収まる先頭部分」に居れば走ってよい。収まらない 1 本でその先頭部分は終わる*(`budget::queue::admits`)。ここから全部出る —

- **上の段の待ちが空きを塞ぐ**(= 補充停止): 空きが足りない単位の所で歩きが止まるので、終わった単位が返した分はその単位のために溜まる。予約という別の機構は要らない
- **重い単位にも番が回る**: 収まらない 1 本を飛び越す(backfill)と、ある席の動詞 1 本 × 無限が後ろの `cargo test`(重み 4)を永久に追い越す

**同順位は席の持ち回り**: 待ち行列は「rank → **その席が配られた重みの累計** → 到着順」で並ぶ(`queue::order`)。**小さい答えは 2 つとも間違う** —

- **「キューの中で何番目か」**: a が着席した次の瞬間、a の 2 本目も b の 1 本目も「自分のキューの先頭」なので**また a が出る**
- **「その席が今走らせている重み」**: a の 1 本目が**終わった瞬間に両方 0 になり**、古い方(= a)がまた出る

なので累計は **台帳(`pgg-budget/served`)に置く** — 配った単位より長生きしないと意味がないから。後から来た席の高さは「今ここに居る席の最小値」(貸しも借りも無い)。巡目は rank の中で数える(ある席の landing がその席の通常仕事を 1 巡下げない)。

**保証しないこと**: 上の段を優先したまま preempt しない以上、**land や起動が連続する間の下の段の待ち時間は保証できない**。割り込みの速さは走っている単位の長さで決まる(→ §割り込みを妨げる単位)。**起動の fast path も機械が満杯なら待つ** — 待った分はその場で 1 行言う(`waited … for room on the machine`)。

**台帳**は `<git-common-dir>/pgg-budget/`。**生死は lock**: 誰も握っていない ticket は死んだプロセスの物。**管理者は台帳** — 参加者全員がそれを保つ。

**ただし lock が空いても仕事は残りうる**。gate をステップの途中で殺すと、その cargo・rustc・コンテナ・アプリは走ったまま残る。そこで room を配ると、**誰も気付かないまま投入制限が破れる**。なので単位は**自分が起こしたプロセスの番号を ticket に書き**、掃除する側が room を返すのはその番号が**消えてから**。

**書く場所は spawn する所すべて**。gate のステップは渡された ticket に書く(`check::run_step`)。単体コマンドはプロセス全体で 1 つの置き場(`budget::MINE`)へ書く(`budget::child_started` / `watched`)。**見えるのは docker CLI まで**で、その CLI も殺されたコンテナはプロセス表の外(`docker ps` の領分)。`cargo xtask budget` はそれを `LEFTOVER: this unit's process is gone and pid N is not` と名指す。**止めるのは人の仕事** — 残るのは cargo・コンテナ・アプリで、`cargo xtask kill` が刈るのは最後の 1 つだけ。

- **zombie は「居ない」**(`subprocess::behind` が `ps` の state を読む)。**親を殺された子は誰も wait しない** — コンテナの中では PID 1 が cargo なので永久に残る。生きていると読むと room がコンテナの寿命ぶん塞がる
- **「訊けなかった」は「生きている」扱い**(`subprocess::listed_by_tasklist`)。`tasklist` が拒否されたり、ポリシーで制限されていたりすると一致する行が返らず、**居ないのと同じ形に見える**ので、非ゼロ終了かエラー出力があれば第 3 の答え(訊けなかった = 生きている扱い)にする
- **番号は使い回される**ので、判断は番号と名前で(`Ticket::child_name` / `subprocess::image_still_at`)。名前は**起こした側の綴りをそのまま**書く — 名前を読むのはプロセス 1 つぶんの費用で、gate の全ステップで払うことになる。書く時にプローブの語彙へ寄せる(`subprocess::as_probed`。**Linux はプロセス名を先頭 15 文字しか持たない**ので、全文で記録すると全ステップが他人に見える)
- **`LEFTOVER_CEILING`(ステップが走ってよい最長)は報告**。判断はプローブだけ —— 遅れていようが**その負荷は機械に在る**。天井を超えた居残りは `LEFTOVER OVERDUE` として名乗り、room は握ったまま。**訊けなかったプローブも同じ扱い** —— 配れるのは「居ない」と答えた時だけ
- **代金は「人が手で終わらせる room が有り得る」こと**: 番号も名前も継いだ他人と、プローブが恒久的に拒否される機械では、そのプロセスが終わるか ticket を消すまで room は空かない。**この向きを選ぶのは、逆向き(自動返却)が「予算の 2 倍で静かに走る機械」を作り、下流の誰にも検出できないから**。そして**待ちには天井がある** —— 動かないキューは `QUIET_CEILING`(30 分の完全静止)で赤くなり、その行が `LEFTOVER OVERDUE` と番号を名指す

**land 同士は受付順に 1 件ずつ**(`Pool::turn`): `land` は入口で turn を取り、rebase → gate → census → ff の全部を握ったまま進む。

**ロック順序**: 木の gate(`lanes::sole` — 即拒む)→ land の turn → **計測の hold が空くのを待つ**(`still::until_free_in` — 黙って待つ)→ ticket → 計測へ announce(`still::busy`、`check::run_step` の中)。**単位は ticket を 1 個だけ、丸ごと取る**ので部分的に握って待ち合う形が無く、`still::hold` 側は ticket を取らないので循環しない。**hold を待つのを ticket より先にするのは診断のため** — 先に ticket を取ると、動けない単位が台帳では「running」に見えて、**キュー待ちと起動後の無進捗が区別できなくなる**。**admit した単位の子は親の ticket の下**(`PGG_BUDGET_HELD`)。

**「組んだ」は実際に走った 1 本だけ**(`gate::step::Ran`)。動詞ブロックは最初の 1 本が release を組んでから残りを `--no-build` で回すので、**stamp で省略された 1 本を「組んだ」と読むと、残り全部が古いバイナリに対して緑を出す**。

**予算は機械を余らせていない**: 単独 gate で効く旋回は `--jobs` の側で、**倍にしても縮まない** —— 投入を増やすと**競合**(ディスク・docker デーモン・WSL 側)で機械の稼働は下がる。既定の「論理 CPU の 1/3」を上げてよいのは、32 本同時でも CPU が落ちない機械を測った時だけ(CPU の数字は診断で、判定は壁時計)。

**ticket を取る場所は 2 種類だけ**: (1) **runner がステップを回す所**(`gate::step::run_one` / `gate::runner` / `check::run_side`)、(2) **それ自体が 1 単位である単体コマンドの入口**(`verify-ui` / `linux` / `shipped` / `launch` = `budget::standalone`)。**runner は (1) だけ**: (2) は「このプロセスの ticket は 1 個」を前提に置き場(`budget::MINE`)を持つので、多数の ticket を持つ runner が通ると 1 本目だけが記録され、以降の子は既に降りた ticket へ書きに行く。**カウント外**は `perf`(機械を止める側なので ticket を取らない)と、コンパイルしない軽い verb。

**数えるのは host 側の `linux` コマンド**。`docker run` に `PGG_BUDGET_HELD=1` を渡す(`PGG_STILL_UNDER` と同じ形)ので、中の xtask は親の ticket の下に居る。**これは必須**: 席の `.git` はマウントの外を指すファイルなので、**コンテナの中から台帳へ道が無い**。

**到着は unit が自分で言う**(`budget hold --queued <file>` / `Pool::admit_arriving`)。**テストが待つのはその通知** — `cargo xtask budget` の見出しは空の台帳でも `0 landing(s) in line` と言うので、そこに語を探す待ちは**その unit が並ぶ前に真になる**(→ rules/core.md §非同期・並行テスト)。

**印は 2 つで、付ける場所は 1 つ**(`linux::marked`)。片方だけ付いた道は**機械を二重に数える道**で、`linux verify-ui` なら host 側が重み 4 を握ったまま中の動詞が自分の重みを待つ形になり、その対が並ぶと**どちらの半分も動けない機械**になる。**構築子を 1 つにして「組み立てたが印を忘れた」を書けなくしてある**。Linux ホストでコンテナを挟まずに走る道(`linux::here`)は子へ `budget::under` を付ける。gate 所有のコンテナ自身(`docker run --detach`)にも同じ印が付く —— **exec が受け継ぐ環境に印が無い瞬間を作らないため**。

**tree に gate は 1 本**: `<tree>/target/gate-running`(note)と `.lock` を握り、2 本目は 1 本目の pid と経過を名指しして拒む — 同じ build directory の同じステップを 2 度回し、互いの cargo を待ち合う(ツール呼び出しの timeout で背景へ回った gate を、終わったと思って撃ち直す形で起きる)。`land` の gate も同じ lock。

host の run は census を書き直すので、並列の 2 本が互いの行を失わないよう **`target/verb-census.lock` を 1 writer で握る**(`census::one_writer`。tree の中に置くと gate が拒む「未コミットの変更」になる)。**読めない census は書き戻さない** — 空として読むのはファイルが無い時(初回)だけで、読めない・UTF-8 でない・`<行> TAB <部品>` の形でない行・同じ行の 2 度目はファイル名:行番号付きのエラーになり、gate の計画・`verbs`・run の記録がそこで止まる。**記録を負う run が行を書けなければ(`census=` を言わない・lock・保存の失敗)、その run は FAIL**(負わない run = `--no-census` / コンテナ / `--repo` 等 / `twin` は PASS のまま)。

## 割り込みを妨げる単位(`gate::record`)

**preempt しないので、land が待たされる上限は「その瞬間走っている単位の長さ」**。だから gate の記録は**長い単位を上位 5 本、両側まとめて**言う(`longest <id> <時間> (weight N) / …`)。**次に割るならこの行が名指す物**。

分割の代金と制約(先に読む): 起動と fixture の費用が単位ごとに増える。**統合テストは 1 バイナリ**(core.md)なので `tests/it` はそのまま — 割るなら実行集合・cwd・環境・成果物・終了コードが同一であることを機械で確かめてからにする。

**`tests/it` は割らない** — 最長の単位は `test it (all)` で、その半分はバイナリ 1 本のコンパイル = モジュールで割っても最初の単位に残り、上限は次に長い単位(`test xtask (all) linux`)までしか下がらない。`test it` は host のサイドの末尾にも居ないので、割っても gate は縮まない(数字は [gate の負荷の内訳](../ci/baseline/gate-load-windows-x64.md) §割り込みを妨げる単位)。

## 動詞の天井(`verify::options::WATCHDOG_MS` = 600s)

**天井は失敗検出の backstop**(.claude/rules/core.md §非同期・並行テスト)。

**120s は負荷で破れる**: 別セッションの gate と同居した run で `identity-tip` が 122.0s で落ちた(単独なら PASS)。core 側は同じ問いを既にこの向きで解いてある(`tests/it/support/wait::OVERALL_BUDGET` = 900s)。

**ただし高さは core より下** — こちら側は赤の代金が壁時計そのもので、しかも `--keep-going` の run では**全滅の赤で天井が動詞の本数だけ直列に積まれる**(`gate::sides::verbs` は緑が 1 本返るまで単独で回す)。

**代金**

- **実際に人が払うのは「最初の赤が出るまで」= 天井 1 本**(gate は動詞が終わるたびに赤を印字する)。
- 緑の run は 1 秒も払わない(`Timer` は鳴らない)。

122s を起こした機構は未再現なので、**「実測した伸びの数倍」で高さを決めると測っていない機構に対して決めることになる**。

**却下: 赤の撃ち直し**(watchdog 赤は 1 度撃ち直して両方赤なら赤)—— 時計で出た赤を時計で薄める形で、「正しさは因果で待つ」に逆行する。

**赤の読み方は 2 つに分かれる**(`verify::outcome` / `verify::wedge`)

| 赤 | 何が起きた | 報告 |
|---|---|---|
| `auto-act watchdog expired` | **イベントループは回っていた**(この watchdog は QML の `Timer` なので、鳴ったこと自体が証拠)。動詞の完了述語に届かなかっただけ | `the loop answered its watchdog … lanes:` —— その瞬間に機械が何本回していたかを添える |
| 天井で刈られた / exit 97 | プロセスが答えなくなった(ループが回っていないか、既に出た後) | `the app's own account:`(駅・沈黙・写真・`lanes:`) |

2 つは排他で、`lanes:` はどちらか一方にしか出ない。**「動詞が間違っている」と「機械に食われた」を分けるのは `lanes:` の数字と、その動詞を単独で 1 回撃った結果**。

## land

land の結果と時間内訳は席の `target/land-runs/` に残る。失敗時の未完了区間は `unfinished` と結果の理由で読む。gate 内部の内訳は `target/gate-runs/`。

1. branch を checkout している worktree(席)を探す。無ければ拒む(gate はそこで回す)/ 席が汚れていれば拒む — **ただし census 1 ファイルだけの汚れ(席で回した gate や動詞の書き直し)は 5 と同じ commit で land が積む** / main を持つ席があれば拒む
2. 走っている xtask が席の build slot(`<seat>/target/debug/xtask`)なら、その名前から退く(rename)。実行中の image は置き換えられない(Windows は `failed to remove file … (os error 5)`)ので、退かないと 5 の gate が撃つ `cargo build -p xtask` が同じ slot を書きに行って落ちる。**退く名前は 2 つ** — cargo は image を `deps/xtask-<hash>` に書いて slot をそこへハードリンクするので、片方だけ空けると `LNK1104` で落ちる(rebase が済んでいて引き返せない所で止まる)。網は `gate::landing::land_steps_out_of_the_build_slot_the_gate_builds_into`
3. <!--call:gate.install-->`gate install`(冪等)
4. main が branch の祖先でなければ席で `git rebase main`。止まれば `--abort` して報告
5. 席で gate(full)。赤なら止まる(branch は rebase 済みのまま、main は動かない)。**動詞が census を書き直して緑なら、land がその 1 ファイルを `chore(xtask): the verb census as the land's gate rewrote it` で席に commit してもう一度 gate する**。2 度目も書き直したら止まる — 機械のタイミングで動いている census なので、人が 2 つの diff を読む
6. primary が main を checkout していれば `merge --ff-only`、どこにも無ければ `fetch . branch:main` → hook がスタンプを確かめる。動いたらこの land が走った permit を spent にする(§land の許可)
7. board の掃除と**席の claim の解放**。誰の claim でも外す(land はユーザーの「この作業は終わり」の言葉。手書きの lock だけ残す)。そのまま作業を続ける側は claim が戻る — 次の編集(post-write hook)・撮影(`seats::held_by_this_run`)・入席・セッション開始のどれでも、そして `cargo xtask seat` は座っている木を、その中身ごと返す(`seats::claim_where_it_stands`)。間に他セッションが取っていたら別の席が来る。land しない終わり方で返すのは <!--cmd:seat.release-->`cargo xtask seat release`。他人の claim が乗った席だけ、ユーザーの指示による <!--cmd:seat.takeover-->`PGG_ALLOW_TAKEOVER=1 cargo xtask seat takeover <letter>` で動く(`crates/xtask/src/seats/claim.rs`)。**session id は会話を通して不変ではない** — 再起動・再開は同じ id だが、セッションの再配置は子セッション(別 id)として続くので、再配置後の自分の旧 claim も乗っ取りの対象になる

履歴は線形。反映後の席は main の先端に居る。

### land の許可(permit)

main を書くのは `cargo xtask land` だけ — セッションの git による `merge` / `push … :main` / `branch -f main` / `update-ref` は pre-shell hook が**常に deny**(前に何を付けても通らない。`PGG_ALLOW_MAIN=1` は land と無関係で、残る用途は primary checkout で直接 commit する例外 `hook/commit.rs` だけ)。land が通るかは UserPromptSubmit hook がユーザー発話そのものから読む permit が決める(`crates/xtask/src/hook/permit.rs`): 発話に「反映」があれば open、無ければ closed。pre-shell hook は land を open の時だけ通す。

- **発話 1 回 = main が動く land 1 回**。open を spent にするのは main を fast-forward した land 自身。止まった land(汚れた席・赤い gate・止まった rebase)は何も消費しない — 直して同じ発話のうちに撃ち直せる。spent の後の 2 本目は deny。permit の対象は land だけ
- **次の発話で消える**(spent でも open でも)。訂正・質問への答え(「1で」「OK」)・別件の承認は許可を持ち越さない。もう一度「反映」と言えばまた開く
- **触るのはユーザーの発話だけ**: 要約で持ち込まれる文脈(`This session is being continued …`)と、`<task-notification>` / `<ci-monitor-event>` のようなタグで始まる機械のメッセージは素通り
- 差し引く形(容器): 反映され / 反映済 / 反映前 / 未反映 / 反映漏れ / 反映するな / 反映しな / 反映せず
- Stop hook は現在のツリーの未反映 commit と未コミットファイルを数え、open なら反映未達、spent なら反映後の未反映作業を `systemMessage` で告げる。未着手の修正や他のツリーまでは検出しない

判定語が「反映」1 語なのは実測: 全 transcript の land 592 本のうち、直前のユーザー発話が容器差し引き後に「反映」を含むのは 518 本。含まない 74 本の発話は「起動」「1で」等 — この仕組みが止めるべきもの。land / merge / マージ は対象外(製品語 — merge editor・マージン・tipLanded — として大半の発話に出る)。

## git hook

`reference-transaction` は `prepared` で非 0 終了すると更新を中止する(git ≥ 2.28)。

**gate が答えるのはセッションの git にだけ**。環境に `CLAUDECODE`(Claude Code が自分の起動する全プロセスに置く印)が無ければ素通し — ユーザー自身の端末・IDE・アプリの窓の git は、main への直 commit も巻き戻しも自由。判定はスクリプトが cargo を呼ぶ前に置く(IDE の git には cargo が PATH に無く、verdict まで行けば fail closed に当たるだけだから)。`cargo xtask launch` の窓は印を落として起動する(ユーザーが操作する窓なので)。headless の verify-ui は印を残す(操作しているのはセッション)。

**印が消えたら gate は黙って誰も止めなくなる**ので、SessionStart が印の不在を報せる。

セッションの git に対する verdict の規則: `old == new` は通す(`reset --hard HEAD` も transaction を回す)/ 削除・スタンプ無し・`full=false`・`onto_main=false`・ff でない(巻き戻し・force)は拒む / `PGG_GATE_SKIP=1` は通す(セッションは pre-shell hook が deny。`CLAUDECODE` を綴るコマンドも deny — 印の削除も検証を省略する設定変更に当たる)。

install(<!--cmd:gate.install-->`cargo xtask gate install`。SessionStart と `land` が毎回撃つ): `.githooks/reference-transaction` を `<git-common-dir>/pgg-gate/hooks/` に複製し(worktree からは編集できず、席の reset / 削除で消えない)、`core.hooksPath` を複製の絶対パスにする。**答えるのは install した tree の xtask**(隣の `tree` ファイル。席の xtask が壊れていても main が止まらない)。複製元は primary の `.githooks`、無ければ今の tree の。`core.hooksPath` に他人の値が入っていれば残してエラー。

罠: `fetch . x:main` と `branch -f main` は main が checkout 済みだと git 自身のガードが先に答える(`update-ref` だけが素の書き込みで、hook が唯一の守り)/ hook の実行ビットは index で `100755`、unix では install が複製に付け直す(git は実行できない hook を**黙って**無視する)/ セッションの git で cargo が PATH に無ければ fail closed。

## hook は自前の build directory で動く(`--profile hooks`)

Claude Code の hook(`.claude/settings.json` の全 event)と git の `reference-transaction` は `cargo run --quiet -p xtask --profile hooks -- …` で xtask を起動する。cargo は **profile の directory(`target/<profile>/`)をビルドの間ずっとロックする**ので、`target/debug` で動く hook は、同じ tree で gate が回す `cargo test` / `clippy` のコンパイルが終わるまで待つ。代金は xtask のソースが変わった tree で次の hook が 1 度 xtask を組み直すこと。手で撃つ <!--cmd:hook.event-->`cargo xtask hook <event>` は `target/debug` の xtask(alias)で、答えは同じ。

**shipped も自前の build directory**(`--profile shipped` = `target/shipped/`、Cargo.toml): `shipped` はハーネス無しの release で、動詞はハーネス付きの release。同じ directory だと互いの binary を置き換え合うので、gate は `shipped` を checks 群で動詞の隣に回す(§群の並走)。代金は tree ごとに release の複製 1 つと、CI の `cargo xtask shipped` が deps をもう 1 度組むこと(P5-確認事項 §3.5)。

## census(`gate::census`)

`WindowCensus.qml`(`platitude.auto`)が run 自身が持つ 2 つの縁で窓のオブジェクト木を歩き、両方の和を `census page=<settled|arriving> …` と `census=A,B,…` で報告。**答えの隣の項は、行が動いた時にその run 自身に理由を名乗らせるためだけに在る**(機械が読むのは答えの 1 語目と `census=` の行だけ)。verify-ui は PASS した run だけを `crates/xtask/verb-census.txt`(commit する生成物)に「打ち直せる行 → 部品名の集合」で記録する(消えたファイルの名前は次の書き込みで全行から落ちる。`--repo` / `--restore` / `--config-dir` / `--no-census` とコンテナの中の run は記録しない)。**`--preset` は run を変える時だけ行に入る** —— 既定と同じ物を名指した `--preset basic` は書かない(`repos::preset_is_the_default`)。これが無いと同じ run が 2 つの綴りで 2 行になり、その動詞へ届く変更は両側で 2 倍計画される。**基底型は派生名の下に隠れる**(item tree が答えるのは一番外側の型だけ)ので、gate は根の型でソースを引いて基底 → 派生 → census と辿る(`census::worn_by` / `through_wearers`)。**動詞の選択と「誰も出していない」の判定は同じこの辿りを通す** —— 片方だけだと、基底を触った変更が動詞を 1 つも選ばないか、逆に絶対に緑にならない名指しで止まる。

**時計で歩かない**。記録されるのが「tick が当たった物」になると、commit 済みの生成物がアプリに触っていない作業の最中に動き、dirty な木では gate が走らないので無関係な作業まで止まる。**gate 自身が census を書き直す**(手で撃った run に任せると、QML を変えた直後に gate が撃つ行がまさに stale なまま捨てられ、後から誰かが手で撃った時に木が汚れる)。

**run が持つ縁は 2 つで、census はその和**。どちらか一方だけで記録すると、その 2 つの間に流れる壁時計が答えに入る — そこは run が握っていない時間で、動詞が仕掛けたまま待たなかった拍が全部そこで鳴る。

- **絵の縁** — run が撮った窓 = 人が判定する窓。絵が保存されたのと同じターンで歩く(`AutoShotDriver.appPictured` → `WindowCensus.report`)。フレームを頼んで待つとその待ちがまさに上の隙間になるので、ここでは頼まない。
- **settled の縁** — 読みが全部着いた後の窓(`PageSettled`)を、磨かれたフレームで歩く(`WindowCensus.arm` — `requestUpdate()` で 1 フレーム頼み、その `afterAnimating`)。動詞は自分が触った物が答えた時点で完了し、その裏でリポジトリはまだ読まれている — 作業ツリーの行(と行の上のタリー)は status が頼み直したパスで届く。フレームで歩くのは、木に立つ delegate を view が建てるのが窓が item を polish する時だから: settled が立つ縁自体はデータの縁で、refs が届いた同じ呼び出しの中では nav の一覧がまだ行を建てていない(`tab-hold 0` が refs を最後に受けた run で `NameCell NavItemDelegate NavRowBody` を落とした)。

歩きが遅れる分は run の終わりが待つ(`AutoShotDriver.waitsForCensus`)。窓が一生落ち着かない run は watchdog の担当(`shot state … census=waiting`)で、ここに通してしまう時計は無い。

**`lost=` は run が「仕掛けた物を待たずに終わった」と自分で名乗る語** — 絵の縁に居て settled の縁に居なかった部品の名前(無ければ `none`)。`lost=` を出した動詞の完了条件はまだ自分の主題を名指していない(rules/app-ui.md §UI 自動化(`PGG_AUTO_ACT` 動詞)の不変条件)。読むのは人で、判定には入らない。

**動詞は自分が仕掛けた物が届いてから完了する**(開いた diff = `DiffPane.diffSettled` / 書いた後の読み直し = `RepoPage.diffSettling` / 長押しは `AutoActDriver.holdToEnd`。規則は verify-ui スキル §壊れない動詞の実装と反復)。

**行を書き直すのは「行がもう届かないページ」を撮った run だけ**。`arriving` の run は和集合で足すだけにする(言わなかった run も `arriving` 扱い — 名前を保つ側に倒す)。これが無いと commit 済みの生成物が機械のタイミングで動き、gate を回すたびに中身の無い census コミットが要求される。settled の規則(`PageSettled`)が待つ読みの一覧は rules-refs/app-ui.md の `WindowCensus` の行。

**書き換えた側が集合差を名乗る**(`census::Shift`)。生成物は部品 1 つの増減で全行が書き換わるので、diff からは「新部品が全行に入った」と「1 行だけが揺れた」を見分けられない。なので run と gate / land の記録が、語ごとに「どの動詞の行が得た / 失った」を要約行で言う: 全行が動いた語は 1 行に畳み、`NAMED_AT_MOST` 本以下しか動かなかった語は動詞名を並べる(揺れはそこに出る)。**読ませるための行** —— 判定は「木が動いたか」だけ。

## どの層が何を持つか(検証の割り当て)

**名前ではなく「何を壊すと落ちるか」で決める**。gate が回すのは選ばれたテストだけなので、同じ主張を 2 つの層に置くと高い方の代金だけが増える。

| 壊れると落ちる物 | 担当 | 実体 |
|---|---|---|
| 値から結果を決める規則(判断・分類・拒否条件・表示変換) | Rust 単体 / QML のデータ駆動テスト | 対象と同じ `.rs` の `#[cfg(test)]` / `tests/qml/tst_*.qml` |
| QML 部品の描画・入力・シグナル | 実部品を使う QtTest | `tests/qml/tst_*.qml`(**全ファイルを 1 プロセス**。緑でなければ 1 ファイル 1 プロセスで撃ち直す — §QtTest のプロセス代) |
| git のコマンド・設定スコープ・終了コード・ファイルの更新 | 実 git 統合テスト | `crates/platitude-core/tests/it/` |
| Rust モデル → QML の接続・実ウィンドウ・OS 固有挙動 | verify-ui | `PGG_AUTO_ACT` の動詞 |

**同じ画面を出すだけは重複ではない**。違う境界を見ている run は残す。**削る前に移行先を足し、代表的な規則を一時的に壊して担当が赤くなることを確かめる**(確かめていない移行は、単体が製品実装を呼んでいない・部品テストが製品の binding を通っていない・残した run が実モデルを見ていない、のどれかで空振りする)。**census は実行記録で、同等性の証明ではない** — 動詞を統廃合したら判定表(`verify::verbs`)・docs・census を揃える。

## 残る候補の棚卸し

残りは主張の形で分類する。1 本の run はたいてい複数の主張を抱えているので、**主張ごとに層を割り当ててから、割り当て先の無い主張が残った run だけを残す**。「must_say の見出しが違う」「実 git を書く」「hover や描画を扱う」は、どれも単独では残す理由にならない。

| 形 | どんな主張か | 例(**候補であって調査結果ではない**) |
|---|---|---|
| **A 拒否条件の表** | 読んだ値から「断る / 断らない」を決め、1 つの報せに出す | 書き込みの報せ(`push-outdated` / `stale-part` / `rename-taken` / `remote-refused` / `tag-refused`) |
| **B 同じ部品の状態表** | 1 つの部品へ違う状態を入れて姿を見る | `window-floor` / `nav-tip` / `carried-read`・`carried-stand` / `path-tip` / `fetch-hover` / `publish-taken` |
| **C 実 git の書き込みを伴う** | 押した所から git が書くまで | `delete-branch-go` / `push` / `stash-pop-row` |
| **D 実ウィンドウ・OS 固有を含む** | 窓の形・フォント・hover・実描画 | `window-fill` / `*-hover` / `*-tip` |

**C は「実 git の検証が要る」と「その verify-ui ケースが要る」を分ける**。割ると: 文言差 → 単体・QtTest / git の結果 → 統合 / 操作と画面の接続 → 代表 UI 1 本。D も同じ —— 残るのは hover そのものだけ。

B を削る条件は A と違う —— 状態を注入できるかではなく、**その状態を決めているものを引数にできるか**(`tab-widths` は「窓の持ち物とフォント」を測定値として引数に落とした)。

### 履歴書き換えの拒否

UI run は door ごとに 1 本: fold の door(行メニュー = `plan_edit`)は `fold-first-commit --preset one-commit`、plan の door(プレビュー = `rebase_plan::preview`)は `plan-off-branch row:0 --preset one-commit`。拒否の形ごとの run は**同じ 1 本道**で、違うのは preset が建てるリポジトリだけなので、接続について全部が言うことと 1 本が言うことは同じ。残すのは preset が最も小さい `one-commit`。

| 層 | 何を担うか | どこに在るか |
|---|---|---|
| 拒否条件と**優先順位** | 4 つの拒否 × 3 つの編集、merge が off-branch と fold-first より先 | `sequencer::plan::decide_edit` の単体 |
| `ReportKind` → 画面用の種別 | `across-merge` / `off-branch` / `fold-first` / `unfetched-base` / `drop-all` の 5 arm | `repo_tab::drain_report_tests::every_withheld_rewrite_reaches_the_page_under_its_own_name` |
| `PlanRefusal` → 画面用の種別 | plan の door の 3 arm、と**プランが開かないこと** | `rebase_plan::drain_tests::every_refused_preview_reaches_the_page_under_its_own_name` |
| **両 door が同じ名前で呼ぶこと** | `PlanRefusal` の 3 つと `ReportKind` の同じ 3 形 | `repo_tab::drain_report_tests::the_plan_door_names_the_same_refused_history_the_same_way` |
| 文言・表示・入力 | 見出し・2 行目・色・Esc・ピル | `tests/qml/tst_reportdress.qml`(実 `Words` + 実 `NoticeBar`) |
| git 履歴から条件を読む | `base_of` の 3 択と `read_rows` の `merges` | fold 側 = `integrate_integration/edits.rs`、plan 側 = `integrate_integration/plan.rs` |
| 操作 → 報せの接続 | 押した所から bar が降りるまで | 上の UI run 各 1 本 |

### QtTest のプロセス代

全ファイルを 1 プロセスで走らせるので、**ファイルを 1 枚足す代金は 0**。緑でない run は 1 ファイル 1 プロセスで撃ち直すが、**判定は常に 1 本目**(`qmltest::verdict` —— 単独では全部緑・まとめると赤も赤)。**全ファイルの全 `TestCase` が「終わった」形でログに在ることを要求する**(`qmltest::unfinished_in`)。

### タグのカード(`tag-menu`)

**`GitFacts` について、2 つを分ける**:

- **「今の `qmltestrunner` に直接登録できない」= 真**。アプリの Rust 側モジュールは空の stub で、`qmltestrunner` にプラグインを渡す口は在っても qtbridge に出口が無い(P3-確認事項)。
- **「部品テストへ移行できない」= 偽**。読む位置を**親へ上げれば**、部品自身は `GitFacts` に触れなくなる。判断を複製するのではなく、**core が出した答えを値として受ける**だけなので、判断は core に 1 つのまま。引くのは入口の側で、**型付きモデルの接続は入口に残る**。

| 層 | どこへ | 実体 |
|---|---|---|
| **純粋な判断** | core | `offers::ref_menu` の tag の表(`offers::tests::each_delete_row_needs_the_side_it_names` ほか) |
| **表示**(どの行に席が在る / 灰色になる / push の行がどちらの形か) | **実部品の QtTest** | `tests/qml/tst_tagcard.qml`。実 `RefTagMenu` を平の値で立てる |
| **入力要求**(押した所が何を頼むか) | 同上 | signal を受けて言葉ごと突き合わせる |
| **実モデルとの接続** | **窓に残す** | `tagSides` と `remoteTagDrift` の 2 つの引き = `tag-menu v1.0:remote` と `v1.5:drift` |

### グラフ行のメニュー(`chip-menu`)

**`chip-menu` / `chip-menu-current` の 2 行は消せない** —— `CommitMenuState.askRefRows` の引き(チップが描いた名前と木のブランチ)を**両側から読む**ので、片方だけでは「常に同じ名前を渡す」実装が通る。行がその答えから描かれるかは QtTest が持つ。引数無しの `chip-menu` は落とした —— **空の名前へ向いた行**で、census の部品集合も must_say も `chip-menu feature/topic-a` と 1 字違わない。

### 実 git 結合テストの側(`eol::sample`)

**この線引きは全ファイルで宣言されている**。`tests/it` の各モジュールの `//!` が自分で言う。`eol::sample` の近所の選び方と票の数え方は値の上の判断なので `nearby` / `widen` / `settle` の単体。残した境界は 2 本 —— 一覧が本当に index か・ endings が本当に `ls-files --eol` の出力か、そして**単一の行末を持たないファイルが票を投じないのは git の答え**。**移す理由は検証の置き場所であって時間ではない**。

**費用の読み方**: **スイート全体の時間をリポジトリ生成の時間として読まないこと**(何割かは測っていない)。テストの数はバイナリが報告する数が正(grep で数えると誤る)。**モジュールの平均からの割り戻しは使わない** —— 多くコミットを積むテストの費用が実際より小さく出る。

### 1 行を消すと何が減るのか

**①実行数 → ②単独の仕事 → ③壁時計 は、間に「混雑の倍率」と「どの上限が効く区間か」の 2 つを挟まないと繋がらない**。**②を並列数で割るだけの見積もりは外す**。

- **① 実行数** —— 数えた値で、推定は入らない。
- **② 過去ログ上の実行時間合計は混雑込みの経過時間であって、取り除ける仕事ではない**。同じ仕事が gate の中では単独の 3〜4 倍に伸び、雛形を組んだ run や側の build を背負う run の秒は**その行の費用ですらない**。**census から消した行を名指しで撃つ時は `--no-census` 必須** —— 付けないと消した行が census に戻る。
- **③ 壁時計 — A/B で測った**。同じ木・同じ選択で census だけを 531 → 399 行に落とし、`gate --fresh` を複数回ずつ: **1 census 行 = 壁時計 0.49s**。尾では host の動詞の待ち行列が host の枠で飽和しているので、行を消せば待ち行列は短くなる。**ただし host の checks の鎖が床**で、動詞側がそこまで落ちれば止まる。

**上限は 2 つ在り、別のもの**。**片側の枠 = `jobs` 本**(`gate::default_jobs`)は**その側の動詞が同時に何本走れるか**、**機械の予算**(`budget::unit::demand`)は**両側と、同じ機械の他の gate が分け合う**もの。台帳から同時実行数を数える時は、1 秒ごとの時刻 `t` について **開始 ≦ t < 終了** の run を数える —— 区間をまたぐ run を「その秒に居た」と数えると、続けて走った 2 本が同じ秒に二重に乗る。**区間の平均同時実行数 = 各 run とその区間の重なり時間の合計 ÷ 区間長**(run の所要時間をまるごと足す数え方は、区間にはみ出した分まで数える)。

### 1 run の中身

**`chip-menu feature/topic-a` を静かな機械で `--no-build` で回し、`PGG_LOG=info` の時刻から段を読んだ**。`whole=1491ms` のうち、動詞の報告行までの**この census 行が在る理由の、実際の仕事**は 33ms。最初のログ行 → `opened repository tab` の 655ms は engine + 窓 + QML のロード + 設定の読み + タブを開くまでの複合。

## 世代の掃除(`xtask::sweep`)

cargo は置き換えた成果物を消さない。`Cargo.lock` / rustc / profile 設定が動くと全 unit が別 hash で作り直され、前の artifact・build script のディレクトリ・incremental セッションは**名前を持たないまま残る**。`target/` を 1 世代に有界にするのが `sweep`。

**いつ走るか** — gate と land の末尾。**世代キー**が前回 sweep 時と違う時だけ走る。`gate --all` は無条件に走る(段 3 は木に全部を訊いた後なので)。

**段 1(`--host-only`)はこの木だけを掃く** — コンテナを 1 つも立てない段が、掃除のためにコンテナを立てることはしない。ボリュームは次に Linux 側を持つ run が訊く。

**ボリュームの判断はボリューム自身のスタンプで** — Linux 側を持つ末尾は、**host の鍵に関わらず**コンテナで <!--cmd:sweep.if-the-generation-moved-->`cargo xtask sweep --if-the-generation-moved` を撃つ(host の鍵で決めると、<!--call:gate.daily-->`gate --host-only` と手打ちの `sweep` が先に host のスタンプを書いた後の gate / land が `generation unchanged` で返って Linux 側へ行かない)。ボリュームの掃除は**イメージを建てない** — 無いタグは Linux 側を一度も走らせていない印なので、その先のボリュームにも掃く物は無い。

**生きている集合は cargo に訊く**。fresh なビルドは `.fingerprint/*/invoked.timestamp` に触らないので、**古さは証拠にならない**。**正規集合**(`sweep::CANONICAL`)に無い行は**次に使う時に組み直す**。

**hash 無しの bin は 1 ファイル** — workspace member の bin は uplift されるので、feature の解決が違っても 1 つの名前に落ちる。同じ bin を書く行を 2 つ並べると listing 1 回につき互いに relink し合い、木には**最後に走った行の設定**が残る。なので**道具が読む設定の行を最後に置く**。素の `cargo build --release` を正規集合に持たないのもこれ — 製品を建てるのは `cargo xtask shipped` で、素の release を打つのは設計に反する型なので守らない。

**消す物** — `debug` / `release` / `shipped` の `deps/` `build/` `incremental/` のうち、集合にも下の floor にも無い物。

**recency floor** — 集合に無くても、**前回 sweep 以降に書かれた物は消さない**。その週に誰かが使った設定を毎回消して組み直す往復を防ぐ。

**ビルド中は触らない** — profile ディレクトリの `.cargo-*lock` を全部 exclusive で取ってから歩く。取れなければその profile を `left alone` と言って飛ばす。消えなかった物も印字する — Windows ではそれが「誰かが立っている」の合図。

単独で撃つ: <!--cmd:sweep.now-->`cargo xtask sweep` / <!--cmd:sweep.dry-run-->`cargo xtask sweep --dry-run`(どちらも鍵を見ずに走る。書くのは自分が居る木のスタンプだけなので、ボリュームの判断は動かない)。Linux 側は同じ verb をコンテナで撃つ(`cargo xtask linux sweep` — 対象はボリューム)。

## 計測との直列化(`xtask::still`)

`cargo xtask perf` は run の間だけ `<git-common-dir>/pgg-still` に hold を置く。ビルドは
compile の chokepoint(`tree::app_exe` / `shipped_exe`、`check::run_step` の各 step)で
announce され、始める前に hold が消えるのを待ち(最大 60 分)、逆に hold はその時点の
announce(`<git-common-dir>/pgg-busy/<pid>-<n>`)が終わるのを待つ(最大 30 分)。gate の
step は `run_step` が 1 つずつ announce し、step の子は `PGG_STILL_UNDER=1` で親の下に居て
待つのは親だけ(gate の verify-ui が「gate を待つ perf」を待つ deadlock の回避)。生死は
note の隣の `.lock` を開き続けているかで判定する(殺された xtask のロックは OS が
離す)。セッションが撃つ cargo は pre-shell hook が `cargo xtask` と compile しない
sub-command だけ通し、他は hold 中 deny する。`cargo xtask still` が今の状態を印刷する。
compile しないが重い verb だけ自分で announce する(`verify-ui` / `linux` のコンテナ / `corpus` の生成)。
CPU 閾(foreign 35%)はそのまま — ブラウザ等、自分たちのビルド以外の分を見る。

- 予算は 3 段: **規則**は純関数の単体(`budget::queue`)。**台帳**はスレッド間(`budget::tests`)。**OS が持つ部分**は実プロセス間(`tests/gate/budget.rs`)。**待ちは全部、到着通知(台帳に名前が出る)か明示の解放(`--until` のファイル)で駆動する** — 時計は 1 つも無い
- Linux: `cargo xtask linux test -p xtask`(実プロセスのテストは `flock` 側の答え。Windows は `LockFileEx` 側)
