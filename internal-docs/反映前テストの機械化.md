# 反映前テストの機械化(gate)

**何をするか**: 変更ファイルからその依存木(逆方向の閉包 = 変更を読む全ファイル)を機械で抽出し、その範囲の**テストだけ**を両 OS で回し、緑を commit にスタンプする。`land` と git hook がそのスタンプを要求するので、**テストの選び忘れも実行漏れも main に届かない**。入口は `cargo xtask gate`(USAGE が正)。

## 全体像(4 層)

| 層 | 役割 | 実体 |
|---|---|---|
| gate | 差分 → 依存木 → ステップ抽出 → 実行 → スタンプ | `crates/xtask/src/gate/`(`graph` / `plan` / `census` / `stamp` / `hooks`) |
| land | 席で rebase(遅れていれば)→ gate → fast-forward | `crates/xtask/src/land.rs` |
| git hook | **セッションの git** による `refs/heads/main` の更新は**フル・on-main スタンプ**への ff だけ | `.githooks/reference-transaction`(`core.hooksPath` は絶対パス。SessionStart と `land` が `gate install`) |
| Claude hook | `PG_GATE_SKIP` / `CLAUDECODE` を含むコマンドの deny / Stop で席の gate 状態を `systemMessage` | `crates/xtask/src/hook/` |

## 依存木(`gate::graph`)

ノードはファイル(workspace 相対、末尾 `/` はディレクトリ)。辺 `a → b` は「a が b を読む」:

- Rust: `use` / インラインの `crate::` `super::` `self::` `platitude_core::` / **素の名で始まるパス**(`mod x;` した子 = `self::x`、`use super::*` 等の glob import が持ち込む親の子と再エクスポート = `super::x`)がモジュールへ解決される(`pub use` 再エクスポートを辿る。glob 再エクスポートは候補全部)。**`mod x;` 宣言は辺ではない**(宣言は依存ではなく、宣言する root / mod.rs が全体へのハブになる)。**インライン `mod tests {}` の中の `super` は自分自身**。テストは `#[test]` / `#[tokio::test(…)]` / インライン `mod tests {` を持つファイルが定義する(`#[cfg(test)] mod x;` の宣言は違う)
- 文字列リテラル(コメント・文字・エスケープを正しく読んだ上で)が workspace のファイル / ディレクトリを名指ししていれば辺(xtask の structure が `ui/` を読む等)。ディレクトリノードは配下の全ファイルを読む。**統合バイナリ(`tests/*.rs`)のリテラルは辺にしない**(サンドボックスの fixture が実木を名指すだけ)
- `CARGO_BIN_EXE_<name>` を綴るファイルは、その名の bin root への辺(同じパッケージの `src/main.rs` / `src/bin/<name>.rs`。**`src/bin/*.rs` も各々 crate root**)。**統合バイナリのリテラルでもこれだけは辺**(バイナリを撃つテストの依存はここにしか書かれていない — `use` する先が無い)。解決しない名は unresolved
- insta snapshot は名前が言うモジュールの辺
- QML: 大文字の語が他の QML ファイル名なら型参照の辺、`#[qobject]` の型名なら app のモデルファイルへの辺
- **コメントと文字列の中身は読む前に落とす**(コメントの `Main.qml` は依存ではない)

逆閉包(reach)= 変更ファイルを読む全ファイル。**QML ノードは QML の読み手とディレクトリノードにだけ伝播**(QML 変更は Rust の単体テストに届かない。届くのは QML をディスクから読む xtask のテストだけ)。

**クレート root は宣言と再エクスポートだけ**(structure.md §上限 の下の項。`the_crate_roots_have_no_readers` が守る)— root にヘルパがあると全モジュールが root を読み、root は全モジュールへ dispatch するので、どの変更も全体に届く。xtask の `git_query` 等は `tree` / `subprocess` へ、core の `type Name` は `model` へ移した理由。

診断: `cargo xtask gate deps --file <path> --why <path> --show` / `--history <n>`。

## ステップの抽出(`gate::plan`)

| ステップ | 条件 | 側 | キャッシュキー(読むもの) |
|---|---|---|---|
| structure / waits / fmt | 常時(秒。キャッシュしない) | host | — |
| `deny`(= `cargo deny check bans sources licenses`) | `deny.toml` の変更、またはビルド入力の変更(= reach 全ファイル。閉包が動くのはマニフェスト経由だけ) | host | `deny.toml` + Cargo.toml / Cargo.lock + `crates/*/Cargo.toml` |
| `clippy -p <crate>` / `linux clippy -p <crate>` | reach にそのクレートの .rs | host / linux | クレート dir + Cargo.* + toolchain(+ Dockerfile) |
| `test -p <crate> --lib\|--bin -- <module::>…` | reach の中でテストを**定義する**ファイル(`#[test]` かインライン `mod tests {`。`#[cfg(test)] mod x;` の宣言は違う)。root が含まれれば全部 | host(core / xtask は linux も) | 選んだテストファイルの**前方閉包**(それらが読む全部)+ Cargo.* |
| `test -p <crate> --test <binary> -- <module::>…` | reach の統合バイナリ(`tests/it/main.rs` と `tests/*.rs` は各々が crate root)。`main.rs` / `support/` が含まれれば全部 | host(core / xtask は linux も) | 同上 |
| `shipped` | reach に QML か app の main.rs | host | app + core + Cargo.* |
| `verify-ui <行>` / `linux verify-ui …` | census がその行で reach の部品を出したと記録している行(+ `--verb`)。**側ごとに 1 ブロックで、最初の未キャッシュの 1 本が単独でビルドし、残りはそのビルドを `--no-build` で `--jobs` 本ずつ並列に使う**(§動詞の並列。キャッシュ済みの動詞のビルドは別の tree のものかもしれないので、この実行でビルドした時だけ)。**board には載せない**(`verify::suite_words` が `--no-board` を行に入れる — 撮影も判定も census もそのままで、載せる側だけを止める。board に載るのは明示的に撃った run だけ) | host / linux | app + core + xtask の verify / demo + Cargo.*(+ Dockerfile) |
| `linux bare` | reach に app / core の .rs か QML、または Dockerfile の変更 | linux | app + core + xtask/src/linux + Dockerfile + Cargo.* |

`deny` が回すのは `bans` / `sources` / `licenses` の 3 つだけ — `advisories` は RustSec DB を github.com から取るので**段 2 はオフラインで完結させ、4 つ目は CI(`.github/workflows/ci.yml` の `deny` job)に残す**。cargo-deny 未導入は**赤**(docker / qmake と同じ扱い。スキップすると policy 未検査のまま commit にスタンプが付く)。

**ビルド入力の変更(`Cargo.toml` / `Cargo.lock` / `rust-toolchain.toml` / `clippy.toml` / `.cargo/` / `crates/*/Cargo.toml` / Dockerfile)は reach を全ファイルにし、テストは filter 無しで全部回す**(`--all` と同じ。ソースのグラフには依存の更新が映らない)。どのステップも読まない変更(docs 等)は「no step reads these」で名指し。**reach の QML 部品を census のどの行も出していなければ gate は赤**(名指し。singleton / `QtObject` root は item tree に立たないので対象外)。

## キャッシュとスタンプ(`gate::stamp`)

ステップの緑は `(id, コマンド, 読むパスごとの `git rev-parse HEAD:<path>`)` の FNV-64 で `<git-common-dir>/pg-gate/steps/<key>` に記録。同 commit の 2 度目は何も回らず、rebase で SHA が変わっても読む tree が同じなら緑のまま。`--host-only` は host 側だけ回して commit に `full=false` で記録し、フルの gate はコンテナ側だけ追加で回す。`--fresh` はスタンプを無視。環境(ホストの Qt 等)はキーに入らない。

commit スタンプ `<git-common-dir>/pg-gate/commits/<sha>`: `main=` `base=` `onto_main=`(base == main)`full=` `step=…`。必要ステップが全部緑の時だけ書く。汚れた tree では `run` しない。

## 動詞の並列(`gate::verbs`)

側の中のステップは直列で、**最初の赤で側が止まる**(ビルドが落ちた側の後続は雑音)。例外が verify-ui の動詞で、動詞同士が共有するのは最初の 1 本がビルドする release だけ(repo / config / shot は run ごとに一意で atomic に claim される = verify-ui スキル)。なので側の動詞は 1 ブロック: **最初の未キャッシュの 1 本が単独で走ってビルドし(赤なら次の 1 本が単独で — 赤い 1 本目がビルドを残したとは限らない)、残りは `--no-build` で `--jobs` 本ずつ並列**。**赤い動詞はブロックを止めない** — 動詞は次の動詞が読む物を壊さず、緑は個別に stamp されるので、直した後の撃ち直しが負うのは赤だけ。ブロックに赤があれば側はブロックの後で止まる(linux の `bare` は走らない)。

`--jobs` の既定は**論理 CPU の 1/3、1〜8**(`gate::default_jobs`)。動詞 1 本 = アプリ 1 個(QML エンジン + offscreen ラスタ)+ それが起こす git で、両側が同時に走る。値の根拠は §実測。

host の run は census を書き直す(load → 自分の行 → save)ので、並列の 2 本が互いの行を失わないよう **`target/verb-census.lock` を 1 writer で握る**(`census::one_writer`。tree の中に置くと gate が拒む「未コミットの変更」になる)。

`check --verb` の動詞は従来どおり直列(`check.rs`)。

## land

1. branch を checkout している worktree(席)を探す。無ければ拒む(gate はそこで回す)/ 席が汚れていれば拒む / main を持つ席があれば拒む
2. 走っている xtask が席か primary の build slot(`<tree>/target/<profile>/xtask`)なら、その名前から退く(rename)。**実行中の image は置き換えられない**(Windows は `failed to remove file … (os error 5)`)ので、退かないと 5 の step も 6 の verdict も同じ slot へ `cargo run -p xtask` を撃って落ちる。退いた複製は普通そのまま消える(**Windows でも消える** — cargo の slot は `deps/` のバイナリへのハードリンクで、走っている image でも別リンクが残っていればそのリンクは unlink できる)。消せない形(cargo がリンクでなくコピーした slot)で残った分は次の land が掃く
3. `gate install`(冪等)
4. main が branch の祖先でなければ席で `git rebase main`。止まれば `--abort` して報告
5. 席で gate(full)。赤なら止まる(branch は rebase 済みのまま、main は動かない)
6. primary が main を checkout していれば `merge --ff-only`、どこにも無ければ `fetch . branch:main` → hook がスタンプを確かめる
7. 席の claim 解放・board の掃除(従来どおり)

履歴は線形。反映後の席は main の先端に居る(`reset --hard main` 不要)。

## git hook(実測)

`reference-transaction` は `prepared` で非 0 終了すると更新を中止する(git ≥ 2.28。Windows の git 2.55 とコンテナの最低 git で確認)。

**gate が答えるのはセッションの git にだけ**。環境に `CLAUDECODE`(Claude Code が自分の起動する全プロセスに置く印)が無ければ**何も見ずに通す** — ユーザー自身の端末・IDE・アプリの窓の git は、main への直 commit も巻き戻しも自由。判定は**スクリプトが cargo を呼ぶ前**に置く(IDE の git には cargo が PATH に無く、verdict まで行けば fail closed に当たるだけだから)。verdict 側も同じ印を読む(`gate verdict` を手で撃った時とテストのため。同じ名前を綴っているかは xtask の単体テストが見る)。`cargo xtask launch` の窓は印を落として起動する(ユーザーが操作する窓なので)— 同時に自動化ノブも落とすので「何かが操っている窓の git だけ素通し」にはならない。headless の verify-ui は印を残す(操作しているのはセッション)。

**印が消えたら gate は黙って誰も止めなくなる**ので、SessionStart が印の不在を報せる(session-start は定義上セッションの中で走るので、そこに無ければ壊れている)。

セッションの git に対する verdict の規則: `old == new` は通す(**`reset --hard HEAD` も transaction を回す**)/ 削除・スタンプ無し・`full=false`・`onto_main=false`・ff でない(巻き戻し・force)は拒む / `PG_GATE_SKIP=1` は通す(セッションは pre-shell hook が deny。`CLAUDECODE` を綴るコマンドも同じ理由で deny — 印を消すのは escape を綴るのと同じ)。

install(`cargo xtask gate install`。SessionStart と `land` が毎回撃つ): `.githooks/reference-transaction` を **`<git-common-dir>/pg-gate/hooks/` に複製**し(worktree からは編集できず、席の reset / 削除で消えない)、隣の `tree` ファイルに「verdict を答える checkout」を書き、`core.hooksPath` を複製の絶対パスにする。スクリプトは `tree` へ `cd` し git の hook 環境変数を捨ててから `cargo run -p xtask -- gate verdict` を撃つ — **git を打った tree の xtask ではなく、install した tree の xtask が答える**(primary の main が gate 以前なら primary の xtask には `gate` が無い。席の xtask が壊れていても main が止まらない)。複製元は primary の `.githooks`、無ければ今の tree の(= 初回反映)。`core.hooksPath` に他人の値が入っていれば上書きせずエラー。

罠: `fetch . x:main` と `branch -f main` は main が checkout 済みだと git 自身のガードが先に答える(`update-ref` だけが素の書き込みで、hook が唯一の守り)/ hook の実行ビットは index で `100755`、unix では install が複製に付け直す(git は実行できない hook を**黙って**無視する)/ **セッションの git** で cargo が PATH に無ければ **fail closed**(ユーザーの git は verdict へ行かないので当たらない)/ gate が撃つ動詞は census を書き直すので、**動いたら stamp せずに赤**(生成物を commit して撃ち直す。stamp は commit を名指すので、通った木がその commit でなくなる)。

## census(`gate::census`)

`WindowCensus.qml`(`platitude.auto`)が **run の PNG が保存された縁**(`AutoShotDriver.appPictured`)で窓の**オブジェクト木**を 1 度だけ歩き、`census page=<open|opening>` と `census=A,B,…` を報告。verify-ui は PASS した run だけを `crates/xtask/verb-census.txt`(commit する生成物)に「打ち直せる行(verb・引数・`--preset`・`--select`・`--allow-write-failure`・`--old-git`)→ 部品名の集合」で記録する(消えたファイルの名前は次の書き込みで全行から落ちる。`--repo` / `--restore` / `--config-dir` と**コンテナの中**の run は記録しない)。**基底型は派生名の下に隠れる** —— item tree が答えるのは一番外側の型だけで、`GraphFind` として置かれた物は `FindBar` とは名乗らない。なので gate は**根の型でソースを引いて基底 → 派生 → census と辿る**(`census::worn_by` / `through_wearers`)。**動詞の選択と「誰も出していない」の判定は同じこの辿りを通す** —— 片方だけだと、基底を触った変更が動詞を 1 つも選ばないか、逆に絶対に緑にならない名指しで止まる(2026-09-03 実測: `CloseToolButton` を触ると `FindBar` が名指しされ、`FindBar` は誰の census にも入りようがない)。

**歩くのは 1 回、時計では歩かない**。時計で歩くと、記録されるのは「run が見せた物」ではなく「tick が当たった物」になる — run が出して引っ込めた行は、tick が間に合った機械の census には入り、間に合わなかった機械の census には入らない(実測: `avatar-remove` の `AvatarAssignRow` は 100ms tick でしか入らず、tick を遅らせると消える)。そうなると commit 済みの生成物がアプリに触っていない作業の最中に動き、**dirty な木では gate が走らない**ので無関係な作業まで止まる。**census が言うのは「その動詞が最後に立たせている物」**で、それはその run の PNG が写している物と同じ。だから **gate 自身が census を書き直す**(手で撃った run に任せると、QML を変えた直後に gate が撃つ行がまさに stale なまま捨てられ、後から誰かが手で撃った時に木が汚れる)。

**縁は完了ではなく PNG**。完了の縁がその場面を組むことがある(`AutoShotDriver.grabApp` の項) — status で完了する動詞は作業ツリーのバケツが立つその turn で完了するので、行のデリゲートは grab が果たされるフレームで生まれる。`finishAutoAct()` で歩くと 1 turn 差で名前が入ったり入らなかったりする(実測: `commit-menu --preset tags` が 10 回に 1 回 `FileRowDelegate` を落とす)。

**行を書き直すのは「行がもう届かないページ」を撮った run だけ**。窓が主題の動詞は自分の主題で完了するので、リポジトリを読んでいる最中のページを撮る — その run の一覧は届いていた分しか持たず、**歩いた結果は「見た物」は言えても「残りが無い」ことは言えない**。なので `WindowCensus.pageSettled` が `settled` と答えた run だけが行を書き直し、`arriving` の run は**和集合で足すだけ**にする。**言わなかった run は `arriving` 扱い**(名前を黙って失わない側に倒す)。これが無いと commit 済みの生成物が機械のタイミングで動き、gate を回すたびに中身の無い census コミットが要求される(実測 2026-09-04、この開発機・idle: `band --system-title-bar` は 20 run 中 13 が status 未着のページを撮り、うち 6 が `FileRowDelegate` を落とした。基底が揃った 18 run は全て保持。揺れる行は `band --system-title-bar` / `commit-menu --preset tags` / `identity` / `tab-widths 6` / `tag-card --preset tags`)。

**問いは「開いたか」ではなく「まだ届く途中か」**。パスを渡されていないタブ(`open-picker`)と**開くのを断られたタブ**(`open-not-a-repo`)はどちらも届き終わっているので、その run は見せ物の全部を撮っている = 行を書き直してよい(`state` が `""` / `"error"`)。ここを「開いていない」で括ると、この 2 つの行が**足せるだけで一生減らない**行になる。パスが通った(`"open"`)側だけが、ページ動詞の基底(`workTree.loaded` / `refsLoaded` / `finishCount > 0`)を待つ。**主題がまさに届く途中の動詞**(`graph-stale`)はいつでも `arriving` で、その行が減らないのは正しい側の答え。

歩き方(実測で決めた規則): 窓そのものは item でないので別に記す(`Main`)/ `children` でなく `data`(子 item + リソース)を辿る — Popup(全ダイアログ・全メニュー)は item でない / **閉じた popup とその中身は数えない**(宣言済みの全ダイアログが全動詞に付いて区別が消える)が、**閉じた popup の中も歩く**(chip のカードは閉じたメニューの中に宣言された開いたメニュー)/ Loader の中身は `item` で(popup を load すると `data` に出ない)/ **サブメニューは親の `contentData` に「行」としてしか出ない**ので `menuAt(i)` で取り、親が見えていれば見えている扱い(親の行がサブメニューの顔)/ **Control の `background` は content でも data でもない**ので名前で辿る(`AppCardFace` は全カード・全メニューの地で、この道が無いとどの動詞も出さない)/ `pragma Singleton` と `QtObject` root は木に立たないので coverage の対象外。avatar 系の 4 動詞は写真のパスが要るので verify-ui が 2×2 の PNG を合成して既定引数にする(機械パス入りの行は再現できない)。

## 計測との直列化(`xtask::still`)

`cargo xtask perf` は run の間だけ `<git-common-dir>/pg-still` に hold を置く。ビルドは
compile の chokepoint(`tree::app_exe` / `shipped_exe`、`check::run_step` の各 step)で
announce され、始める前に hold が消えるのを待ち(最大 60 分)、逆に hold はその時点の
announce(`<git-common-dir>/pg-busy/<pid>-<n>`)が終わるのを待つ(最大 30 分)。gate の
step は `run_step` が 1 つずつ announce し、step の子は `PG_STILL_UNDER=1` で親の下に居て
自分では待たない(gate の verify-ui が「gate を待つ perf」を待つ deadlock の回避)。生死は
pid でなく note の隣の `.lock` を開き続けているかで判定する(殺された xtask のロックは OS が
離す)。セッションが撃つ cargo は pre-shell hook が `cargo xtask` と compile しない
sub-command だけ通し、他は hold 中 deny する。`cargo xtask still` が今の状態を印刷する。
理由は [rules-refs/app-ui.md](../.claude/rules-refs/app-ui.md) の「計測は機械を止めて撃つ」。
