黄・赤が**現に着いている所の全一覧**と、その割り当ての決まったこと。値と使い分けの正本は [デザイン規約.md](デザイン規約.md)
§状態 / §長押し(長押しの色の表)/ §暗く落とした段 で、本書はその規則が実際に届いた先を数えたもの。戻せる範囲の正本は
[破棄記録仕様.md](破棄記録仕様.md)。長押し以外の配り方の未決は [P3-確認事項.md](P3-確認事項.md) §要判断(小さいもの)の
「警告色の配り方」。

- 対象: 製品の QML(`crates/platitude-app/src/ui`。検証ハーネスの `auto/` は外)の `Theme.warning`(92)/
  `Theme.danger`(39)/ `Theme.warningDim`(3)/ `Theme.dangerDim`(1)= **参照 135・128 行・55 ファイル**
- 絵: <!--cmd:shots.open-->`cargo xtask shots open` の board(**Windows の run のみ**)。表の `#` は全行を上から順に撮った時の並び
- 撮り直し: 表の「動詞」列をそのまま `cargo xtask verify-ui <動詞> --label "<ラベル>"` に渡す。**変わる所が写る状態で撮る** ——
  `Discard hunk` はポインタが見出しに乗った時だけ色を着る(`hunk-tools`。`discard-hunk` の絵では灰色)、`drop` は先端に他の
  ref が届く木では長押しにならず色を着ない(`drop-commit --preset plan` が色を着る形)

## 規則(正本からの要約)

| token | 値 | いつ使うか |
|---|---|---|
| `warning` | `#D97706` | **自分の外へ波及する** / **進行中で対処が要る** / **答えを待っている** / **戻せる破棄**(破棄記録が持つ) |
| `danger` | `#EF4444` | **今止まっている・失敗した** / **戻せない形で手元の成果を捨てる**(進行中の操作の途中の作業・記録が残らない discard・リポジトリの外の物) |

色を持つのは**枠・印・語**。**長押しの行は、メニューを開いただけで語・コマンドのチップ・長押しの印が `holdTone` を着る**
(`AppMenuItem.wordColor`)。塗りが同じ色で満ちるのは押している間だけで、塗りまで写るのは #23(帯の `push -f`)だけ。
長押しの色は**押し切った時に失う物を戻せるなら `warning`、戻せないなら `danger`** の 1 つの規則で決まる(行ごとの表は
デザイン規約 §長押しの色)。

## 決まったこと(ユーザー決定)

1. **破棄記録で戻せる破棄は `warning`** —— ファイルの `Discard`・hunk の `Discard hunk`・`reset --hard`・コミットの `drop`・
   stash の `drop`・`branch -D` と `-D` に落ちる `Delete both`・ローカルの `tag --delete`・プランの実行ボタンの長押し
   (#1〜#4・#6〜#9)。戻る経路: 未コミットの変更は記録の写し(破棄記録仕様 §2.1)、先端・entry・名前は記録と枝の reflog。
   **長押しかクリックかは色の規則と別に決まる**([P3-確認事項.md](P3-確認事項.md) §破棄記録と復元「長押しは今のまま」)。
   トークンは足さない
2. **記録が残らない discard は `danger`** —— discard の入口(ファイル・hunk・untracked の削除・`reset --hard` の未コミットの分)は
   普段は `warning`、次の時だけ `danger`。**色は行が出る前に status から決まる**(`GitFacts.discardUnrecorded` /
   `WorktreeModel.hardResetNotCopied`)。`reset --hard` の行き先が持つパスに立つ untracked は status から見えないので、
   写せなくても `warning`(エッジケース。P3-確認事項 §触らないと決めたもの)
   - **最初のコミットの前** —— 記録しない(破棄記録仕様 §2.1)
   - **`filter.lfs.required` が立ち、Git LFS が動かないパス**(`WorktreeModel.notCopied`)—— `git add` が断るので写しに
     入らない。`NO LFS` が数える形のうち、こちらだけが戻せない:

     | 形 | `git add` | 戻せるか |
     |---|---|---|
     | `filter=lfs` だが `filter.lfs.*` が未定義、または `required` が立っていない | 丸ごと取り込む(必須でないフィルタの失敗は素通し = gitattributes(5)) | 戻せる(`warning`) |
     | `filter.lfs.required = true`(`git lfs install` が書く)で Git LFS が動かない | 断る(破棄記録仕様 §2.1・§5) | 戻せない(`danger`) |

     この形の木では、git がファイルをクリーンしないと読めない時(rename・racy なエントリ)に **`git status` 自体が
     `fatal: <path>: clean filter 'lfs' failed` で止まる**。LFS 以外の必須フィルタと `working-tree-encoding` の失敗は事前に
     分からない(稀)ので `warning` で、一覧の `not copied` が言う
3. **アバターの `Remove`(#22)は `danger`** —— リポジトリの外の物で、破棄記録では戻らない
4. **窓の `✕` の赤(`WindowButton.danger`)は状態色の規則の外** —— OS の閉じるボタンの慣習
5. **プランの verb チップ(`pick` / `edit` / `squash` / `drop` …)の色は長押しの色の規則の外** —— 警告ではなく種類を見分ける色
6. **長押しの既定値は `warning`**(`AppMenuItem` / `OpExitRow` の `holdTone`)—— `danger` は戻せない行が自分で名乗る。
   **既定を理由に見える色を変えない**: 見える色は規則で行ごとに決める
7. **改行無しの印は `danger`**(GitHub の慣例 = デザイン規約 §行末の改行が無いこと の例外)。横棒は輪の内側に収める(同 §)

## 表に無いもの

**同じ規則で色を着るが、別の行・別の状態でしか出ない長押し**:

| 色 | 行 | 置き場所 |
|---|---|---|
| 黄 | `push --force`(ずれたタグ)・`push --delete`(ブランチ)・`Delete both`(タグ / ブランチ —— 手元が `-d` でも `-D` でも)・左メニューの stash の `drop` | `RefTagMenu` / `RefBranchMenu` / `RefRowMenu` |
| 黄(既定) | `AppMenuItem.holdTone` / `OpExitRow.holdTone` の既定 | `AppMenuItem` / `OpExitRow` |

**動詞が無い / 今の preset では作れない状態**:

- **署名が壊れている(赤)** —— `SignatureMark.broken` は git の `B`(署名後に内容が変わった)。`signed` は `G` / `U` / `N`、
  `errsig` は `E` で、**`B` を建てる preset が無い**
- **`no newline at end of file` の印(赤 = 決まったこと 7)** —— `DiffLineCell` の `no-entry`。それを出す preset が無い ——
  `cargo xtask demo-repo dirty` の木で `b.txt` の末尾の改行を落とし、`diff-file b.txt --repo <その木>`
- **破棄記録の一覧が読めない(赤)** —— `RecoverPane` の `What was thrown away could not be read`。失敗させる動詞が無い
- **`already pushed`(黄)** —— amend にチェックが入り、かつ HEAD が公開済みの組。動詞が無い(同じ文言のプラン側は #9)
- **`This commit is on a remote…`(黄)** —— 詳細ペインのメッセージ編集。公開済み HEAD の preset が要る
- **窓の `✕` の赤(決まったこと 4)** —— `WindowButton.danger` は実ポインタの `containsMouse` だけを読む。**注入不能**
- **`RemoteDialog` の「同じ名前のリモートが既にある」(黄)** —— 打った名前が衝突する動詞が無い
- **`LineEndingField` / `IdentityFields` / アバターのエラー行(赤)** —— 失敗させる動詞が無い
