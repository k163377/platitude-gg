# Phase 5(配布準備)確認事項

## 積み(未検証)

### 1. diff プレビューの画像デコーダ範囲

プレビュー(`platitude-core::preview`)が画像扱いする拡張子のうち描画できるかは
実行環境の Qt imageformats プラグイン次第。デコーダが無い形式は
「Preview unavailable」+ サイズ表示に劣化する(壊れない)。
**webp / tif / tiff / avif は劣化表示**。

検証・判断:

- **qtimageformats を配布物に同梱するか(本命)**。プラグイン DLL を置くだけで
  コード変更なしに描画可能。ライセンス確認(libwebp = BSD-3 /
  libtiff = MIT 系)と 3OS の deploy 手順への追加が必要
- **avif**: Qt 標準プラグインが無い。(a) 劣化表示のまま /(b) kimageformats 系の同梱
  (LGPL — 依存ライセンス方針の確認要)/(c) Rust 側デコードして PNG に変換
  (依存が大きく軽量方針と要相談)
- **WebView(Qt WebEngine)フォールバックは非推奨の見込み** — 実体は Chromium 同梱で、
  ネットワークスタック同梱が「ネットワーク非通信」の主張
  ([実装計画.md](実装計画.md) §11)に抵触する

### 2. forge との距離(`gh` を呼ぶか) — **かなり後の判断**

PR バッジの実データ(P4)とリモートブランチの差し替え・削除まわりで「`gh` CLI があれば
済む」場面が出る。決まるまでは git だけ。

- `gh` は外部 CLI なので絶対制約の条文には触れないが、アプリが
  forge へ通信させる点で制約の趣旨としては同じ側
- 判断時に同時に決めること: 未インストール環境での degrade(バッジが出ないだけ)/
  認証(`gh auth` に委譲)/
  「ネットワーク非通信」の主張([実装計画.md](実装計画.md) §11)の書き換え
- 当面の代替: PR バッジは `ls-remote refs/pull`(git 経由)で足りる見込み。残る判断は
  「forge の rename(PR が付いてくる = 本物の改名)まで要るか」だけ

### 3. 配布物への同梱一覧(既知分の集約)

**表示の置き場は About**(ユーザー案 2026-10-05)。LGPL-3.0 は、実行中に著作権表示を出すならそこに Qt /
qtbridge の表示とライセンス本文への案内を含めることを求める(§4(c))ので About が合う。GPL と LGPL の本文は
binary と一緒にファイルでも渡す(§4(b))— About はそのファイルを読んで見せる。中身(crate・Qt とその第三者部品・
tree-sitter の文法・構文定義)は依存を上げるたびに変わるので、`cargo xtask` で生成して CI で照合する。
qtbridge の上流の修正で `vendor/qtbridge-interfaces` を消しても、消えるのは改変版のソースと改変告知を
示す 1 項だけ(LGPL の表示と再リンクの道は残る)。

- `pgg-todo-editor.exe` を本体と同じディレクトリへ(rules-refs/core.md の pgg-todo-editor
  項)。**これは `platitude-core` の bin ターゲット**なので、配布物を組む手順は必ずワークスペース全体をビルドする
  (`crates/xtask/src/package/run.rs` の `HELPER`)
- **既定ビルドの Qt では Qt6Network は Qt6Qml / Qt6Quick のロード時依存として同梱が必須**(外せるのは Qt の
  カスタムビルドだけ —— 非通信の証明の前提。[実装計画.md](実装計画.md) §11.2)
- **mac の bundle に入れる Qt は `crates/xtask/src/package/contents.rs` の許可リストが正本**(ユーザー決定
  2026-10-05: 必要最低限だけを入れ、Qt の更新で余計な物が入らないようにする)。中身・外した物の理由・package が
  赤にする条件・`qt.conf` はそのファイルのコメント — **Qt を上げた時はこの赤でリストを見直す**
- **アプリのスタイルが Fusion に決まっているのは `Main.qml` の import の順による**(bundle は macOS のスタイルを
  積まない。罠はその import のコメント)
- imageformats プラグインの選定(§1 の結論)
- **配布物の import 検査**(実装計画 §11.2)は Qt のカスタムビルド(§14)の 3OS の配布物で組む —— Windows の
  [windows-x64.md](../ci/baseline/windows-x64.md) の import は既定ビルドの Qt の実測で、検査の元にはならない
- **syntect / two-face が埋め込む構文定義の著作権表示**。定義は 100 本超で
  それぞれ別ライセンス。two-face の `acknowledgement` モジュールが全文をプログラムから返すので、
  **`cargo xtask` で deny.toml の allow リストと突き合わせて落とす**。Apache-2.0 の定義は
  NOTICE と改変告知が要る(§15 も参照)
- **Octicons(MIT)から描き直した印**([デザイン規約.md](デザイン規約.md) §出典とライセンス):
  ファイルは同梱しないが、MIT の表示を第三者表示に載せるかを決める
- **同梱クレートのうち MIT を選べないものの表示**。SPDX 式が OR なら許可枝に MIT を
  選べるが、AND と単独綴りは選び直せないので、表示と義務の要否をここで決める:
  - `foldhash` = Zlib 単独 / `tree-sitter-elixir` = Apache-2.0 単独(§15-3)。
    **全文同梱・NOTICE・改変告知の要否はライセンスごとに違う**ので個別に決める
  - qtbridge 一族 = `LicenseRef-Qt-Commercial OR LGPL-3.0-only`(LGPL 側。静的リンクの扱いは §14)。
    **`qtbridge-interfaces` は改変版を同梱している**(`vendor/qtbridge-interfaces`):
    改変したソース・改変告知と日付(`PLATITUDE-MODIFIED.md`)・LGPL 本文はリポジトリに在る。
    配布物からそのソースへ辿れる形にする
  - **対象の絞り込みは `cargo tree -e normal,no-proc-macro --target all`** — proc-macro とその依存
    (`proc-macro2` → `unicode-ident` 等)はコンパイラの中で走るだけで本体に入らない。
    `cargo deny list` は build 依存も含み(`codespan-reporting` = Apache-2.0 単独は build 専用で
    再配布しない)、dev 依存は含まない
- **Qt は組んだ版と同じものを同梱する**: qtbridge-runtime 0.3 は Qt の private ヘッダ
  (`QtQml/private/qqmldata_p.h` の `QQmlData`)を読んで組まれるので、private の ABI が
  変わる別のマイナー版の Qt では動く保証が無い(システムの Qt を使う配布形は取れない)。
  qtbridge-runtime はビルド時に `Qt6QuickTest` もリンクするが、本体の import には残らない
  (release の本体が直に読む Qt は Windows も Linux も `Qt6Core` / `Qt6Gui` / `Qt6Qml` だけ —
  exe の dependents / ELF の `NEEDED` で確認)。mac の本体は残す(`contents.rs` の `FRAMEWORKS`)

### 3.5 CI の構成(push は mac だけ・全部は版が動いた時と週 1)

**入口は用途ごとに分け、中身は呼ばれる側の workflow(`workflow_call`)で共有する**(正本はファイル。各ファイルの
冒頭と step のコメントが理由を持つ):

| workflow(Actions の一覧の名前) | 起動 | 中身 |
|---|---|---|
| `push.yml`(Push check (macOS)) | main への push(`**.md` だけなら起きない)。走っている run は次の push が取り消す | macOS の clippy・test(`ci.yml`)、mac の撮影の `fonts` 段(`shots.yml`) |
| `whole.yml`(Whole test (3 OS)) | `deps/*/after` タグの push・PR・週 1(金曜 19:00 JST)・手動 | 3OS の fmt・clippy・test・`periodic` のテスト・`shipped`、deny(`ci.yml` の全部)、mac の撮影の全行(`shots.yml` の `whole`) |
| `snapshot.yml`(Snapshot build (macOS, not a release)) | 手動 | Whole test と、それを待たずに並ぶ mac の `cargo xtask package`(§8)。**中で Whole test が回るので、Whole test を別に撃たない**(同じ commit の 3OS と mac の全行が 2 重になる)— パスワード付きの DMG を run の artifact に残す(保持 30 日。理由・secret・開け方は `snapshot.yml` の冒頭) |
| `shots.yml`(Shots (macOS)) | 手動(既定は登録表 `verb-lines.txt` の全行。段で絞り、名指した行は段の行に足す — §3.6) | push / whole からも段を渡して呼ばれる |
| `relied-messages.yml`(Relied messages (weekly)) | 週 1(金曜 19:00 JST)・手動 | Ubuntu の runner で <!--cmd:relied-messages.watch-->`cargo xtask relied-messages watch`(git の各系列の先端と新しいリリースを照合の記録と比べる)と <!--call:relied-messages.master-->`relied-messages master`(本家 `master` を組み、語の表の証人をその git で回す)。**赤は「git の文言が変わった」で、この木が壊れたのではない**(gitの扱い.md §git の文言に依存する判定) |

- 段との対応: Push check は机の無い OS の段 2 相当(テストと `fonts` 段の撮影)、Whole test は段 3 の CI の部分。段 3 の残り(<!--cmd:linux.bare-->`cargo xtask linux bare --discover`・性能実測)は机で回す

**各ジョブの手順は 3OS とも通る**(fmt・clippy・テスト・`shipped`・deny・mac の撮影)。構文・キー・
`${{ }}` の式・呼ぶ側と呼ばれる側の入力の突き合わせは actionlint で検査する(v1.7.12。composite action の
中身と `run:` のシェルは対象外 — shellcheck を積んでいない)。
**リポジトリの Actions 設定は、外部の action を許可していることが前提**(Settings → Actions → General。
「自分のリポジトリの action だけ」だと、workflow は 1 行も実行されずに `startup_failure` で終わる)。
**xtask が macOS 向けに組めることは机で確かめられる**: `rustup target add aarch64-apple-darwin` の後
`cargo clippy --locked -p xtask --all-targets --target aarch64-apple-darwin -- -D warnings`(check だけなので
リンカも SDK も要らない。xtask の OS 分岐を触ったら撃つ)。core / app は tree-sitter の C と Qt を mac 向けに
組めないので、机では確かめられない。

runner の上で分かっている事(workflow・action の組み方の理由と罠は各ファイルのコメント):

- **macOS で xtask・core・app が組めて、`cargo test --workspace` が通る**(xtask の単体と gate のスイートを
  含む。一時ディレクトリが `/var` → `/private/var` の symlink の下に在ることで割れるテストは無い)。`shipped` と
  `replay` → `verify-ui` も通る
- **offscreen の macOS は起動のたびに `Populating font family aliases took … ms … "Sans Serif"` を出す**
  (65〜88ms)。Qt の offscreen プラグインの既定フォントが `Sans Serif` 9pt(`qoffscreenintegration.cpp` の
  `OffscreenTheme`)で、CoreText にその名前が無いため。アプリは窓に `Theme.uiFamily` を名指すので絵には
  出ない。Cocoa の窓では既定がシステムフォントなので、この探索は起きない
- **キャッシュは 4GB 弱**(`rust-cache` 5 本と Qt 3 本。リポジトリの上限は 10GB)。同じ鍵を並走の job が先に
  予約した時は `Unable to reserve cache` の警告で済む(PR の run は PR のスコープへ書く)
- **所要**(cache の無い run): Linux 13 分・macOS 16 分・Windows 33 分・deny 1 分。
  `shipped` のビルドは Linux 3 分半・macOS 4 分・Windows 8 分
- **`cargo xtask package` の署名と DMG は runner で通る**: `PlugIns` の下の dylib と `Resources/qml` からそれへの
  link という bundle の形で、`codesign --deep` が `PlugIns` の下まで署名して `--verify --deep --strict` が通り、
  `hdiutil` の暗号化と開け直しも通る(Snapshot の run 37238446842 — 中身は許可リストより多い bundle)
- **`periodic` のテストは runner の 3OS で通る**(各 70 本。Whole test の run 37331246562: Windows 32 秒・macOS 7 秒・
  Ubuntu 2 秒)

まだ見ていない事:

- **許可リスト(§3)で組んだ bundle が runner の上で通ること**(机では Mac の手順を撃てない)— リストは Snapshot の
  run 37238446842 の package の job のログと、机の Qt 6.12 で撃った trace から組んだ: フレームワーク 24 本はその run で
  macdeployqt が辿った依存と Qt の CMake のリンク先から、qmlimportscanner が辿る 32 本はその run の import の一覧から、
  QML モジュール 13 本は机の `shipped` の起動と動詞 6 本(設定・コンボ・メニュー・カード・ツールチップ・アバター)の
  `QML_IMPORT_TRACE` から(場所を引かれたのはどれもちょうど 13 本)。mac で読み違えていれば package がその名前を挙げて
  赤になる。この bundle で起動の判定(dyld が bundle の外から読んだ image が 0 本)と署名が通るかもそこで見る。
  `hdiutil create` は runner で `Resource busy` の断続的な失敗が知られている(actions/runner-images#7522)— 出たら
  job を撃ち直し、繰り返すなら手を考える
- **呼ばれる側の workflow の上で、Push check の取り消しが呼ばれた job まで止めること**と、`deps/*/after` の push で
  Whole test が立つこと(入口 3 つから `ci.yml` / `shots.yml` を呼ぶ形と、`rust-cache` の鍵が
  入口ごとに分かれることは run 37331182896 / 37331246562 / 37331306019 で走った)
- **Dependabot の PR が `.github/actions/qt` の中の action(`actions/cache/restore` / `save`)も拾い、SHA の隣の
  版コメントも書き換えること**(更新の確認は走っている。PR は action に新しい版が出た時に立つ)

### 3.6 macOS の撮影(`shots.yml`)— 実機の代わりに CI の runner で撃つ

撃ち方と読み方は verify-ui スキルの mac.md。runner の上で `cargo xtask replay` が verify-ui の行を 1 本ずつ撃ち、
判定は手で撃った run と同じ・絵とログは artifact に残る。

- **写るのは CoreText のフォントと macOS の経路まで**。offscreen の QPA は Apple では CoreText のフォント DB を
  使い(`qoffscreenintegration.cpp`、Qt 6.12)、描画は software scene graph(`RhiBasedRendering` が false)。
  **Cocoa の窓(タイトルバー・ネイティブメニュー・Metal の描画・Dock)は写らない**
- **代金**: リポジトリが public の間、標準 runner(`macos-26` = arm64)は分の課金が無く、artifact と cache の
  保管も無料(cache はリポジトリごと 10GB まで)。**private にすると分で課金され、macOS の分単価は Linux の
  約 10 倍**($0.062 対 $0.006)なので、その時は Push check と Whole test の自動の起動を外して手動だけにする。
  larger runner(`-large` / `-xlarge`)は public でも有料 — ラベルは標準のまま

runner の上で分かっている事:

- **offscreen の run は macOS で絵を出す**(`screenshot saved=true`。Windows と同じ software の経路)。
  `fonts` 行の判定(幅・切れ・段)は Hiragino Sans / Menlo で通る。所要は 1 行 1〜8 秒で、最初の
  1 行に release ビルドが乗る(cache の無い run で 5 分半、`fonts` 行だけの job 全体で 10 分)
- **登録表の全行(700 本前後)は job 全体で 40 分前後**(Replay の天井 270 分の内)。判定は Windows / Linux と同じ行が
  通り、mac でだけ落ちるのは下の「行の高さ」が効く行
- **`defaults write -g AppleLanguages` / `AppleLocale` は runner で通る**(`ja-JP` / `ja_JP` が読み返せる)。
  日本語の run の絵では、省略の `…` が中央寄りの和文字形で出る(§20)
- **和文は UI フォントで崩れずに出る**(コミット件名・長い和文の折り返し・和欧混植・名前の中抜き省略)
- **Hiragino Sans は Yu Gothic UI / Noto Sans JP と字の箱が違う** — 行の箱が低く(`FontMetrics.height` が小さい)、
  その下に leading を持ち(`fontMd` で 7px)、数字の幅が広い。フォントから寸法を出す所は mac でだけ別の答えになる。
  その差が効く所の組み方と判定の動詞は、その部品のコメント: 操作パネルの枠(`TopBar.actionDepth`)・欄と同じ行の
  ラベル(`LineText` / `DiffPaneHeader`)・hunk 見出しの 2 語(`DiffRowDelegate`)・畳んだレールの数字(`NavRail`)・
  `CardText` を語と同じ行に置く所(`CardText` と各呼び手)・右パネルの最小幅の日付(`CommitAuthorRow`)。
  1 行の入力欄(Commit summary)は低くなるだけで、字は収まる

  mac の絵は main に載せてから `shots.yml` でしか撮れない。runner の絵で見た形: 操作パネルの枠は `cellH=40`・
  `boxed=true` で語と印を包む / hunk の 2 語は同じ行(`level=true`)/ 作者行は名前の下線が字のすぐ下・日付は
  `date=day`(`2026-10-04…`)・切れた co-author 名は字の境目・親ハッシュは 3 桁 / パスの中央切りは `crate…hot.rs`
  と字が欠けない / 断られた push の報せバーは降りきって写る / diff の帯の語は 1 本のベースラインに立つ
  (`DIFF` とパスは `hunk_tools caption=true`・0px。パスの中央切りの頭と尾、`—` と worktree 名は判定行が無く、
  `diff-band-sweep` と `carried-read` の絵で見る)

まだ見ていない事:

- 英語の run(`locale=en`)と並べた字形の差 — `—` `…` と、等幅の中の和文フォールバック(§5 / §20)。
  等幅の中の和文(diff 本文・コマンドログ)を撮る行は `fonts` 段に無いので、行を名指して撃つ
- Replay が天井(270 分。job は 300 分)で切れた時の残り方 — そこまでの絵とログは artifact に残る
  (`summary.md` は replay が最後に書くので出ない — 行ごとの `ok` / `FAIL` は step のログ)。
  切れた時に撃っていた 1 行の絵とログは書きかけでありうる(step の天井が止めるのは起点のシェルで、
  その子は job の終わりまで残りうる)

**実ウィンドウの撮影は未作成**。runner のイメージは bash からの画面収録を許可済み(`screencapture` が撃てる —
actions/runner-images の TCC 設定)で、足りないのはハーネスの側: 絵を保存した後も窓を立てたまま待つ駅と、
そこで外から撮る口。§8(Dock のアイコン)・§22(アプリメニュー)を CI で見るにはこれが要る。

### 7. 引いたフラグのダッシュが他 OS の等幅で釣り合うか

### 19. IntelliJ の Code Provenance を戻す(開発環境)

開発機の IntelliJ(2026.2 系)は Registry `code.provenance.chatter.analytics.enabled`
を **false** にしてある。既定の true では bundled プラグイン "Code Provenance by Qodana"
が `chatter.exe observe` を約 65 秒間隔で起動し、起動 1 回につき tree-sitter の native lib を
`%TEMP%` へ展開したまま残す。報告は [QD-16236](https://youtrack.jetbrains.com/issue/QD-16236)。

QD-16236 が解決したら:

1. IntelliJ を対象版へ上げ、`Help | Find Action` → `Registry...` で該当キーを **true** へ戻す
2. 1 時間、`%TEMP%\tree-sitter-ng-lib_*` が増えないことを確認する(直っていなければ 1 時間で数十件以上出る)
3. 出るなら false に戻し、QD-16236 に実測を添えて差し戻す

false のままで失うのは JetBrains 側へ送る chatter analytics だけ。true へ戻すと
`code-provenance\chatter\v1` のローカル記録も再び育つ(数 GiB 規模)。

### 20. 英文中の `—` `…` の字形(macOS の JP ロケール実機)

Qt は shaping の言語を `QLocale()`(= OS のロケール)から HarfBuzz へ渡す
(`qtextengine.cpp`、Qt 6.12)。日本語フォントがロケールで持ち替える字形が、英文に続く
`—` `…` に出うる —— 和文字形は全角のダッシュ・中央の三点で、`—` が両 OS で同じ長さ・
同じ位置という据え置き(デザイン規約 §寸法「字で出ていた記号は 5 種」)から外れる。

- Windows: `Yu Gothic UI` は JP ロケールでも欧文字形(実測。ヘッドレスの `Noto Sans JP`
  だけが和文字形になる — verify-ui スキル windows.md)
- Ubuntu: 言語の出所は Qt の版によらず LANG(Qt が起動時に `setlocale(LC_ALL, "")` を
  呼び、HarfBuzz の既定言語もそれを読む)。**日本語デスクトップ(`ja_JP.UTF-8`)では和文字形**
  (実測。検証のコンテナも同じ LANG で、Linux の絵は和文字形)。幅の差は 1px 前後でレイアウトは崩れない
- **直すのはレイアウトが崩れる時と、全く違う表現に見える時だけ**(ユーザー決定 2026-10-02)——
  和文字形の `…` `—` そのものはアプリが上書きしない
- **macOS が未実測** —— Finder から立てた GUI には LANG が無く、`QLocale()` は
  システム設定の言語を答える。JP ロケールの実機で設定画面の説明文の `—` と、
  グラフのチップの省略の `…` を `Hiragino Sans` で目視し、上の 2 つに当たるかだけを見る。
  実機が無い間は `shots.yml` の日本語の run の絵で読む(§3.6 — runner の言語設定が Qt に届くかは同節の確認事項)
- **CI の絵は bundle でない素のバイナリの答え** —— macOS はアプリのロケールの言語を、ユーザーの言語と
  bundle が宣言する言語の突き合わせで決める。[Info.plist](../packaging/macos/Info.plist) が宣言するのは
  `CFBundleDevelopmentRegion = en` だけ(`CFBundleLocalizations` / `CFBundleAllowMixedLocalizations` は無い)
  なので、出荷する `.app` は日本語の Mac でも英語のロケールで立ちうる = runner の日本語の run とは shaping の
  言語が違いうる。どのロケールで立ったかは `QT_LOGGING_RULES=qt.core.locale.debug=true` で起動時に出る
  (`qlocale_mac.mm` — ロケール・優先言語・bundle の宣言が並ぶ)。`.app` を組んだ時にこれで確かめ、上の
  目視はその条件で読む

### 21. macOS の `cargo xtask linux`(docker の経路)

エンジンは Windows が WSL の wslc、Linux はコンテナ無し、**macOS は docker のまま**(`linux::engine`)。

Linux 側を持つ `cargo xtask gate` を 1 回ずつ

### 26. 画面表示中の読み込みの間隔の実機での振る舞い

規則と決定(ユーザー決定)は `crates/platitude-core/src/session/pace.rs` のモジュールコメント、駆動は
`session::pacer`。定数はこの机(Windows・SSD)の実測で決めた
([poll-cost-windows-x64.md](../ci/baseline/poll-cost-windows-x64.md))。机の無い環境で見るもの:

  天井へ寄って止まらず進むか。重さは原因を区別しない(CPU の取り合い・ディスク待ち・枠待ちのどれでも伸びる)

  期限が過ぎて見えるかどうかだけが違う(どちらでも他の worktree は 1 本ずつ追いつく)

### 27. Windows・Linux 以外の OS ですり抜ける OS 分岐(全体の点検)

**未知の OS でも組めない・lint が落ちる・テストが落ちるのは基本的に不可**(ユーザー決定)。**OS を分ける所は「基本の
OS(Windows・macOS・Linux)ごとの最適な方法 + 環境を特定できなくても動くであろうフォールバック」の形にする**
(ユーザー決定 2026-11-01。実機の無い OS の枝は検証が届かなくてよい)。机とコンテナが組むのは Windows と Linux の
枝だけで、macOS の枝は main へ push した後の Push check まで組まれず、それ以外の OS の枝はどこでも組まれない。

- **範囲**: **Linux でない unix(macOS・FreeBSD など)**。**unix でも Windows でもない OS(wasm32・wasi・uefi など)は
  対象外**(ユーザー決定 2026-11-01)— そこでは子プロセスを起こせない。tokio の `process` の `imp` は `cfg(unix)` と
  `cfg(windows)` だけ(tokio 1.54。wasi・emscripten では `process` ごと無い)で、core と app は組めない
  (`process::trace_sink` の `imp` も unix と Windows だけ)。std だけの xtask も、その OS では std の子プロセスが
  起きないので git も cargo も呼べない
- **点検済み**(core・app・xtask の全体): コンテナの置き換えで workspace の clippy
  (`--all-targets --all-features`)が緑、置き換えたままのテストは下の前提と撃ち方の副作用の他は緑。xtask の macOS
  向けの clippy も緑
- **見る形**: ①使う OS で定義が抜ける(`cfg` の組が全部の OS を覆わない)②一部の OS の枝だけが使う物(定数・
  import・関数)が他の OS で未使用になる ③一部の OS の型でだけ出る lint(unit 構造体の `default()` など)
  ④テストの台本・呼ぶ道具の POSIX に無い指定(`head -c`・`sed -i`・`readlink -f`・`stat -c` など。`ps -o a=,b=` は
  POSIX では `=` の後ろが引数の残り全部の見出しになり 1 列 — FreeBSD はそう読み、Linux と macOS は 2 列に割る。
  欄ごとに `-o` を分ける)と、OS の作りに頼る前提(パイプの容量・`/proc`)。OS を問う条件は os モジュールなど
  1 か所に置き、共有のコードに写さない(写すと、その OS の枝を後で足した時に写しが食い違う)
- **撃ち方**: OS の条件を一時的に偽にして組ませる。コンテナの上で `target_os = "linux"` を `target_os = "freebsd"`
  に置き換えて clippy とテスト = Linux でない unix の代わり。条件の形は `cfg(windows)`・`not(windows)`・
  `any(windows, …)`・`all(windows, …)`・`cfg!(any(windows, …))`・`not(any(target_os = "linux", windows))` などさまざま
  なので、置き換える前にファイルの中の `windows` / `"linux"` の条件を全部数え(コメントと文字列の中は外す)、当てた数と
  照らしてから撃ち、バイト単位で戻す(戻した後に `git status` が空)。xtask の macOS 向けの clippy は §3.5
  - `cargo xtask linux` を撃つと xtask 自身も置き換えたソースで組まれて止まるので、置き換える前に組んだ
    `target/debug/xtask.exe` を写しておき、それを直に呼ぶ
  - コンテナの kernel は Linux なので、置き換えが見せるのは cfg の枝だけ。kernel と道具の違い(`ps` が名前を切る
    長さ・`lsof` の有無・`/proc` の形)はコードを読んで見る
  - 置き換えたままのテストでは `gate::graph::tests::the_window_frame_is_compiled_on_windows_alone` が赤になる —
    ソースの cfg を中身として読むテストなので、撃ち方の副作用
  - Windows の上で `windows` の条件を偽にしても `unix` は偽のままなので、それは unix でも Windows でもない OS
    (対象外)の代わりになり、Linux でない unix の代わりにはならない
- **残した前提**(落ちうるのはその前提が崩れる OS・環境だけ): `exec_input` の読み残しの網は
  OS のパイプが 1 MiB より小さいこと、止める 3 つの道の網は 3 MiB より小さいことに頼る(パイプに収まる入力は
  見分けられない — 製品の境界と同じ)/ `process::executor::tests` の Windows 以外の子は `sh`・`dd`・`cat`・
  `sleep`・`printf`(POSIX)で動く / Linux の `a_pipe_takes_the_width_it_is_asked_for` は `fs.pipe-max-size` が
  1 MiB 以上で、利用者のパイプの割り当てが尽きていないことに頼る / Linux でない unix で `land::leftovers` が
  「木で誰が働いているか」を問うのは `lsof`(macOS は標準で持ち、FreeBSD は package)— 無い機械では land が木を
  残して理由を名指し、`tests/gate/leftovers.rs` の 3 本が赤 / `subprocess::behind` の `ps -o stat=` の `stat` は
  POSIX の欄名ではない(Linux・macOS・BSD の `ps` は持つ)/ `ps` が名前を切る長さを知らない OS の名前の照合
  (`subprocess::Spelled`)は、15 バイト以上で記録した名前の頭に当たる名前を同じと読む — 15 バイトより短く切る OS
  (知られていない)では生きている子を他人と読んで枠を手放し、記録した名前と頭 15 バイト以上が同じ別のプログラムは
  同じと読む(生きている側)/ core の `support::repo::barrier_hook` は小数の `sleep`(`sleep 0.1`)に頼る(POSIX は
  整数だけ。macOS・FreeBSD・GNU・busybox の `sleep` は受ける)
- **働かずに安全側へ倒れる所**(落ちはしない): Linux でない unix で、`reap::others_in_this_group` は答えを持たず
  (§3.5 の demo リポジトリが残る)、`cargo xtask kill` のアプリ探し(`gui::app_processes`)は `/proc/<pid>/exe`
  (Linux)も実行ファイルの path を返す `ps` の `comm`(macOS)も無い OS ではこの木のアプリを見つけず何も止めない。
  `verify::look` のスレッドの一覧(`Lister`)は Windows・Linux・macOS だけで、他の OS では wedge-check もその行を
  求めない
- **机で確かめていない枝**(実機か CI で初めて通る): macOS の `verify::look::off_ps`(`ps -M -p <pid>`、1 行目を
  見出しとして落とす)— Mac の机の gate の wedge-check か、CI の macOS で止まった run の look で読む / FreeBSD
  などの `ps` の読み方(欄ごとの `-o`、名前を切る長さ)

### 28. 差分ペインの画像プロバイダの macOS

blob 側の画像は `QQuickImageProvider` の派生(`platitude-app` の `preview_images` の CXX-Qt ブリッジが生成し、
`build.rs` の cxx-qt-build が組む)が `image://pgg-preview/<id>` で出す。Windows と Linux(コンテナ)では組み・リンク・
`preview_images` のテスト・`preview*` の動詞が通る。**macOS は組みもリンクも表示も未検証**。

- **組みとリンク**: cxx-qt-build の `QtPlatformLinker` は Apple で `-fapple-link-rtlib` を足し、Qt Quick を
  framework として繋ぐ。Push check(macOS)の `cargo test` が `preview_images` のテストを撃つので、組めれば表示まで
  見る(子プロセスで `image://` を `Image` に読ませる)
- **表示**: `shots.yml` を `whole`(登録表の全行)か `lines` に `preview*` の行を名指して撃ち、mac の絵で読む

### Linux: 日本語の Ubuntu 24.04 デスクトップが積むもの

**検証のコンテナ(ci/linux/Dockerfile の app ステージ)はこれを再現する**(ユーザー決定 2026-10-02。
積む物の理由はその Dockerfile のコメント)。

- **どのデスクトップにも在る**: 既定の選択 `ubuntu-desktop-minimal` の Depends が `fonts-dejavu-core`・
  `language-selector-common`、Recommends が `fonts-noto-cjk`・`fonts-noto-core`・`fonts-noto-color-emoji`・
  `fonts-ubuntu`・`fonts-liberation`(noble の apt で読んだ)
- **日本語を選ぶと足される**: インストーラ(subiquity の `LocaleModel`)が `check-language-support -l ja` の
  答えを入れる —— ubuntu:24.04 での答えは `fonts-noto-cjk-extra`・`fonts-noto-core`・`ibus-mozc`・
  `language-pack-ja`・`mozc-utils-gui`(language-selector 0.225 の `pkg_depends` に `fn:ja::fonts-noto-cjk-extra`)。
  ISO の pool にこれらは無く、**ネットにつながずに入れた機械には入らない**。後から「言語サポート」を開くと補完を
  促され、Japanese Team の `ubuntu-defaults-ja`(24.04 では Remix の ISO に代わる配布)も `fonts-noto-cjk-extra`
  に依存する。LANG は `ja_JP.UTF-8`
- **Qt の描き方を変えるのは 2 つだけ**(qmltestrunner で styleName・幅・grab の画素を、宣言どおり / 言語セレクタ
  有り / ja_JP / 英語デスクトップ / 日本語デスクトップの構成で比べた):
  - `fonts-noto-cjk-extra` —— 太さの面が増える。UI は使わない(`Theme.fontWeightStrong`)
  - `LANG=ja_JP.UTF-8` —— 英文中の `…` `—` が和文字形になり、`'` `.` が 1px 未満ずれる(§20)
- **language-selector-common の fontconfig 規則**(Noto Sans CJK JP の 18px 以下を hintnone ほか)と
  noto-core / color-emoji / ubuntu / liberation は、UI の字の画素を 1 つも変えない —— UI の family は全部
  名指しで、届くのは名指しの family に無い字のフォールバックだけ。コンテナはフォントを積み、規則は積まない
  (Python ごと要る)。**family を名指ししない字(窓の font を継がない qmltestrunner の Controls)だけは
  noto-core で幅が変わる**(`tst_askfields` の長い remote 名が 329 → 314px)—— qmltest の幅の前提は字面に依らせない
