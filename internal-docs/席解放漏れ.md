# 席 d の解放漏れと再発防止

## 確認した事実

2026-09-12 の調査開始時、席 d は `worktree-d` の `b5340916`、
未コミット変更 0、`main..worktree-d` は 0 commit だった。
ロックはセッション ID・PID のない `claude-seat` のみ。

Codex セッション `01a08687-56e7-71c2-ac44-a0dd6ee13060` の実行ログには、
`landed worktree-d: main 0e664333 -> b5340916 (2 commit(s)).` に続いて
`is another session's and stays as it is: claude-seat` が記録されている。
main への反映成功と、席の解放成功が一致していなかった。
匿名ロックを最初に書いた呼び出しまでは特定していない。

## 原因と変更

- `Identity::current` が Claude の ID だけを読み、空のままでも席を取得できた。
  匿名ロックは本人判定もプロセス生存判定もできず、land が保守的に残す。
  hook → Claude → Codex の順で空白でない ID を読み、ID がなければ
  割当て・再取得・明示解放を Git 操作より前に拒否する。
- 既に main に入ったブランチへの land は早期 return していた。
  自分の clean な席が残ることを実 Git の回帰テストで再現し、
  この経路でも既存の所有者判定を通して解放する。
  dirty / 状態不明・他人・匿名の claim は解放しない。
- 成功した land だけを根拠に「解放済み」と報告しない。
  AGENTS.md に解放結果とロック状態の確認、および land しない終了時の
  `seat release` を明記した。

SessionEnd の一律解放は追加しない。スリープで継続中セッションにも
届く既存の制約は変わらない。古い匿名ロックの自動回収もしない。

## 今回の席 d

利用履歴・Git 状態・プロセスのコマンドライン・Claude のセッション登録を
確認し、席 d を指す稼働中の記録は見つからなかった。これは匿名ロックの
元所有者を特定できたという意味ではない。
ユーザーの席 d 解放・再利用指示に従い、匿名ロックを解放した後、
現在の Codex タスク ID を渡す通常の `cargo xtask seat` で取得した。

回帰確認は `seats::tests` と `tests/gate/landing.rs`。ID 不在と反映済み
再実行の失敗を修正前に記録し、修正後は所有者不明・他人・dirty の保持も確認する。
