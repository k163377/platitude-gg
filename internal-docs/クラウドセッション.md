# クラウドセッション(Claude Code on the web)

`CLAUDE_CODE_REMOTE=true` のセッション(以下クラウド)は **コード変更のみ・実行無し**(ユーザー決定)。検証の土台(Qt・Linux コンテナ・画面・もう一方の OS)が無く、ビルドもセッションごとに一から払うので、**検証と反映は手元が持つ**。この文書は [CLAUDE.md](../CLAUDE.md) の実行を求める規約に優先する。判定は hook と同じ環境変数 1 つ(`crates/xtask/src/hook/cloud.rs`)— Claude Code はクラウドでだけこれを `true` にする。

**hook が答えない時もこの文書が規約**(toolchain を取れない環境では hook が全部失敗する)。CLAUDE.md §ビルド・テスト の 1 文はそのための置き場。

## 適用しない規約

- **CLAUDE.md §ビルド・テスト の全部** — 確認 3 段・完了条件の `gate` PASS・UI 配線の動詞と PNG の目視・起動(fast path を含む)・`linux`・worktree 座席(席を取らない・EnterWorktree しない)
- **CLAUDE.md §Git 運用 のうち main を動かす側** — land・反映の許可・board での承諾・land の片付け。**クラウドは main を動かさない**(main への merge・push も PR の merge もしない)。「反映」と言われたら branch を push し、手元の land 待ちと報告する
- **rules・rules-refs・スキル・確認事項の中の「撃って確かめる」指示** — git の挙動の実測・insta の再生成・`structure` や `docs` の確認・perf も撃たない。要る物は §完了条件と報告 へ回す

## そのまま守る規約

- 絶対制約・コード規約(`.claude/rules/` と rules-refs)・性能予算の設計規則・文書の上限と書き方
- Git 運用の書き方 — Conventional Commits(英語)・push は追加のみ・rebase はユーザーがその場で指示した時だけ・完了報告の前に commit

## 作業の形

- **起動した checkout で、クラウドが割り当てた branch のまま働く** — 席・worktree は作らない。commit してその branch へ push する
- **撃たない**: compile する cargo 全部(`build` / `check` / `test` / `clippy` / `run`、`cargo xtask` の動詞全部 — gate・verify-ui・linux・launch・land・seat を含む)。compile しない cargo(`cargo fmt` 等)は撃ってよい。git・grep など変更を書くための道具はそのまま使う
- **ユーザーがその場で実行を指示した時だけ** `PGG_ALLOW_RUN=1` を先頭に付けて撃つ(pre-shell hook が読む escape)
- **生成物は書き直せない** — <!--cmd:docs.sync-->`cargo xtask docs --sync` の台帳・`verb-census.txt`・`structure-baseline.txt`・insta のスナップショットが動くはずの変更は、報告で名指す(手元の gate が赤で知らせる物でもある)

## 完了条件と報告

- **完了 = 依頼範囲の変更を commit し、割り当て branch へ push した時点**(手元の検証を待たない)
- **報告**: branch / SHA・変更点・**手元に残る検証**(`cargo xtask gate`、UI 配線なら触った動詞、名指した生成物)。gate を通していないので「マージ可」とは言わず、「手元の gate 待ち」と書く
- PR はユーザーが頼んだ時だけ作る(作ると 3OS の Full CI が回る — `.github/workflows/full.yml`)

## 手元での取り込み

渡された席(main の先端・clean)で `git fetch origin <branch>` → `git reset --hard FETCH_HEAD` → `gate`。反映の指示があれば land(main より遅れていれば land が rebase する)。手元に `claude/*` の branch を作らないので、land の片付けの対象も増えない。origin の branch はユーザーが消す。

## hook の振る舞い(`hook::cloud`)

`.claude/settings.json` の hook はクラウドでも同じ形で走り(`cargo run -p xtask --profile hooks`)、`hook::cloud::run` の表で答える。subagent も同じ環境なので同じ表。

- **黙るもの**: 席(本体 checkout への書き込みの確認・commit の拒否・EnterWorktree の席判定・takeover)/ gate の git hook の install と印 `CLAUDECODE` の警告 / gate の印と skip を綴るコマンドの deny / land の許可(反映の発話は permit を開かない)/ Stop の報せ(反映未達・席の gate 状態)/ 計測・起動・kill・python・チップの guard
- **足すもの**: SessionStart の案内(この文書の要約)/ compile する cargo の deny(`PGG_ALLOW_RUN=1` で通す。compile しない cargo の一覧は計測の guard と共有 — `hook::still::HARMLESS`)/ EnterWorktree の deny / 反映の発話への「クラウドは land しない」の注記
- **残すもの**: main を書く git・rebase・席の木と branch を触る git の deny / 帰属メモを足す commit の deny / 大きなファイルの全文表示と同じ行の反復の deny / 統合テストの 2 本目の binary の deny / QML の登録・フォントと文書の上限・崩れの注記 / レビューの注記
- **代金**: hook は xtask を動かすので、クラウドでも会話の始まりに `rust-toolchain.toml` の版の取得と xtask のビルドを 1 度払う(実測 2026-10-07: 取得 16 秒・ビルド 21 秒、4 コア)。以後は hook 1 回ごとに cargo の鮮度確認だけ
- **hook ごと止めない理由**: 止めるには `.claude/settings.json` の各コマンドを環境変数で分岐させることになり、Windows の hook は Git Bash(無ければ PowerShell)で走るのでシェル構文が 3OS で揃わない。分岐を xtask の中に置けば、手元の hook の起動の仕方は変わらない
