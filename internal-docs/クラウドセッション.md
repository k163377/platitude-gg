# クラウドセッション(Claude Code on the web)

**Claudeクラウド(`CLAUDE_CODE_REMOTE=true`)だけに適用する例外**。このプロジェクトでは、クラウドは plain text としての変更だけを行い、検証と反映はローカルで行う(ユーザー決定)。この文書は `CLAUDE.md`・rules・rules-refs・スキル・確認事項のうち、席の取得や実行を求める規約に優先する。ローカルのClaude・Codexには適用しない。

## 作業の形と例外の範囲

- 起動した checkout と、クラウドが割り当てた branch で作業する。**席を取得しない・EnterWorktree しない・worktree を作らない**。
- コード・文書・設定をテキストとして編集する。`.claude/settings.json` も編集対象。git・検索・差分確認など、変更を読む・書く・commit するための道具は使う。
- **プロジェクトを実行しない**。依存取得・ビルド・テスト・clippy・gate・UI 動詞・画面確認・起動・perf・生成物の再生成はローカルへ渡す。`cargo fmt` を含む Cargo と xtask も起動しない。実行が必要になったら、その内容を名指してローカルで行う。
- `CLAUDE.md` §ビルド・テスト の席・確認3段・gate PASS・両OSの動詞とPNG目視・起動 fast path、および各文書の「実行して確かめる」指示は、クラウドの完了条件から外す。
- **main を動かさない**。land・main への merge/push・PR の merge はローカルへ渡す。「反映」の依頼でも、クラウドでは作業 branch への commit/push と引き継ぎまでを行う。land 用の許可・board・片付けもクラウドでは行わない。
- **生成物は手で編集しない**。コマンド台帳・`verb-census.txt`・`structure-baseline.txt`・insta のスナップショット等が変わる作業では、必要な再生成を報告する。

## 引き続き守る規約

絶対制約・コード規約・性能予算の設計規則・文書の上限と書き方はそのまま守る。Git 運用も Conventional Commits(英語)・push は追加のみ・rebase はその場のユーザー指示がある時だけ・完了報告前の commit を守る。例外はクラウドでの席・実行・検証・反映の手順に限る。

## hook の起動

`.claude/settings.json` の全 command hook は、次の前置きで **Cargo が起動する前に成功終了**する。

```sh
test "$CLAUDE_CODE_REMOTE" = true || cargo run --quiet -p xtask --profile hooks -- hook <event>
```

- `CLAUDE_CODE_REMOTE` が厳密に `true` の時だけ右側を起動しない。未設定・空・`false` 等では従来の Cargo コマンドへ進み、stdin・stdout・終了コードをそのまま渡す。変数を手で設定してローカルへ例外を適用しない。
- `shell: "bash"` を明示し、Linux/macOS は sh、Windows は Git Bash で同じ構文を使う。Windows の hook には Git Bash が必要。
- クラウドでは、このリポジトリの席・gate・land 等を守る hook 本体を起動せず、SessionStart も xtask をビルドしない。例外の案内は常時読む `CLAUDE.md` に置く。Rust にクラウド専用の分岐や実行許可フラグは持たない。
- 回帰テストは `crates/xtask/src/hook/cloud.rs`(テスト専用)。全 hook のクラウド時の無出力・成功終了と、ローカル時の Cargo 呼び出し・入出力・失敗終了コードの維持を、実シェルと代用の Cargo 関数で確かめる。

判定とシェル仕様の根拠: [Claude Code hooks reference](https://code.claude.com/docs/en/hooks)。`CLAUDE_CODE_REMOTE` は web 環境で `true`、shell form は Linux/macOS の sh と Windows の Git Bash で実行される。

## 完了とローカルへの引き継ぎ

クラウドの完了は、依頼範囲のテキスト変更を commit し、割り当て branch へ push した時点。報告には **branch/SHA・変更点・未実行の検証・必要な生成物の再生成**を含め、「ローカルの gate 待ち」と書く。gate を通していない変更を「マージ可」と報告しない。PR はユーザーが頼んだ時だけ作る(Full CI が回る)。

ローカルは席を取得し、対象 branch を fetch する。自席の状態を確認して対象 commit を起点に作業し、生成物の再生成と必要な確認を完了して、現在の commit に対する `cargo xtask gate` を通す。UI 配線なら両OSの動詞とPNG目視も行う。main への反映は、その場のユーザー指示を得て land する。
