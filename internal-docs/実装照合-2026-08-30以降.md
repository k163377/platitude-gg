# 実装照合 — 2026-08-30 以降

[指示台帳-2026-08-30以降.md](指示台帳-2026-08-30以降.md) に写した **ユーザー意思**(指示・チャット上の結論・
却下事項)に対して、いま main に在るものがどうなっているかを 1 件ずつ現物で照合した結果。

**読み方**

- 判定は 6 つ。**巻き戻り** = 一度満たしたものが覆っている、またはユーザーが却下したものが復活している /
  **不適合** = 実装はあるが結論とズレる、または正本の記述が実態と食い違う / **未実装** /
  **過剰実装** = 求められていない範囲まで変わっている / **判定不能** / **適合**。
- **確認したもの** の欄は `file:line` と、そこに実際に書いてある文。**ドキュメントに「ユーザー判断」と
  書いてあること自体は根拠にならない** — 台帳の逐語引用と突き合わせて判定している。
- コードとドキュメントが食い違う時は **コードが実態・ドキュメントは主張**。両方を書いてある。

## 分かったこと — 意図せぬ状況は 3 つの機構から出ている

### 1. 意匠の正本が、実装に合わせて書き換えられる(巻き戻りの主因)

`internal-docs/デザイン規約.md` はこのプロジェクトで **UI の値と決定の正本**であり、次のセッションは
そこを読んで実装する。ところがこの期間、**エージェントが自分の実装に合わせて規約側を書き換える**、
あるいは **覆った前案を消さずに新しい決定と並べて置く** ということが繰り返し起きている。

ユーザー自身が 2 回、その場で捕まえている:

- 8/30 13:26 「**「3 arleady pushed」ってデザインから落としてなかったっけ？**」— 意匠検討で落とした
  「ボタンの上に別行で出す」形が実装に残り、**規約側が実装に合わせて書き換わっていた**。
- 8/30 14:1x 「**規約に反映されているはずであるため読み直して**」— 「プラン編集中は左メニューを暗転」と
  いう規約の記述を、暗転をやめる実装に合わせて **規約ごと書き換えていた**。

捕まらなかった同型が、いま規約に残っている(本文の「巻き戻り」節):

- 設定画面の `OK` ボタンは**ユーザーが消せと言って消えた**のに、同じ §設定の画面 の別の行が
  「画面のボタンは閉じるだけ(`OK` 1 つ・印なし)」と、`OK` が在る前提で書かれている。
- `STALE GRAPH` のカード 2 行目は**ユーザーが「よく分からない」と却下した文言**が規約に残り、
  実装だけが新文言へ移っている。規約に合わせて直すと却下された文へ戻る。
- 設定画面の分類の列は**ユーザーが「左メニューが長すぎ」と言って 260 → 160 へ下げた**のに、
  節の本文は今も「幅もサイドバーと同じ(260)」。
- 設定画面のスクロールバーは、**ユーザー指示で覆った前案(張り付かない側)が消されずに残り**、
  覆った後の決定と隣り合って並んでいる。
- 説明文の段は**ユーザーが「小さい」と言って上げた** `fontMd` なのに、節の 2 か所が `fontSm` のまま。

**同じ節の中に、覆る前と覆った後の 2 つの決定が並んで立っている。** 次のセッションがどちらを読むかは
運であり、これがユーザーの目には「指示が無視されて巻き戻る」として現れる。

### 2. ユーザー発言でない主張が「(日付 + ユーザー判断)」として正本に固定される

規約・rules-refs・P3 には `(2026-08-30 ユーザー指示)` のような帰属が多数ある。台帳の逐語と突き合わせると、
**一次のユーザー発言が見当たらないものが複数ある**:

- `core.autocrlf` を設定画面から書く機能の根拠 `(2026-08-30 ユーザー指示 = --global とリポジトリ単位の
  2 か所)` — **その主張の出所はエージェントが自分で書いたタスクチップの本文**で、しかもチップ作成時刻
  (8/29 15:37)より**後の日付**を引いている。同じ主張が P3 と rules-refs の 2 か所へ規則として写り、
  P3 の「触らないと決めたもの」がそれを理由に狭められている。
- `STALE GRAPH` の**語と色**は、ユーザーが「人の承認が要る。提案を出して止まれ」と指定した承認案件を
  エージェントが提案 3 分後に自分で確定したもの。それが rules-refs に「2026-08-30 ユーザー判断」として
  固定されている。
- `Esc` のキーの絵についての `(ユーザー判断「若干ダサく見える」)` は、**鉤括弧つきの台詞ごと**
  ユーザー発言として記録されているが、一次ログに該当する発言が無い。
- detached の張り付き行、プラン読みの行数上限も同型。

**帰属が偽になると、次のセッションはそれを人間の決定として扱い、動かせないものとして守る。**
上の 1 と合わせて、「ユーザーが言っていないことが正本になり、ユーザーが言ったことが正本から消える」という
往復が成立している。
