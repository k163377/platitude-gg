# 破棄記録仕様(失った物の一覧と復元)

破壊的な操作が失わせた物を**リポジトリで 1 本の一覧**に出し、そこから**復元**する機能の正本。

- **復元は追加の操作** —— 失った物に名前を付けて立て直すか、失った中身を当て直す。既存の ref は動かさない
- **Undo / Redo は持たない**(ユーザー決定。git の操作を Ctrl+Z で戻す機能は作らない)—— 復元の後の統合(枝を
  戻す・cherry-pick する・送り直す)は、利用者が普通の操作で行う
- 意匠(一覧の置き場と見せ方・帯・グラフの仮表示・語)の決定と残りは [P3-確認事項.md](P3-確認事項.md) §破棄記録と復元

## 1. 対象

PGG から行った次の操作が失わせた物を、一覧に出して復元できるようにする(遡る深さは §3、保持は §2)。

| 対象 | 破壊操作(PGG の入口) |
|---|---|
| ローカルブランチ | 削除(Delete both のローカルの分を含む)/ 先端の非早送りの移動: reset(`--soft` / `--mixed` / `--hard`)・Move here(`switch --force-create`)・履歴の書き換え(rebase・squash・drop・reword・並べ替え)・amend・rebase する pull |
| リモートブランチ | 削除(リモートの行・ローカルの行の `push --delete`・Delete both・リモートブランチの差し替え・手元の改名の後の「消して作る」)/ force push |
| worktree | 削除(`worktree remove`) |
| stash | drop / pop(当たって entry が消えた時) |
| ローカルタグ | 削除 |
| リモートタグ | 削除 / force push |
| 未コミットの変更 | discard(ファイル・hunk・行)・untracked の削除・`reset --hard` が捨てた分 |
| detached HEAD で積んだコミット | 枝へ切り替えて置き去りにした物 |

**出さない物**:

- **明示の廃棄でない物** —— fetch が起こす変化(追跡 ref の prune・他者の force push の取り込み・`fetch.pruneTags` で消えるローカルタグ)
- 進行中の操作(merge / rebase / cherry-pick / revert)の途中の作業、conflict の片側を採って捨てた手直し
- 設定 —— リモート(URL・origin の印)と upstream の変更。ブランチの削除で消えた upstream は、そのブランチの記録に含めて戻す
- stage した版(作業ツリーと違う版を stage していた時の unstage)
- PGG が撃たない操作(`branch -M` の上書き・`stash clear`・`tag -f`・`worktree remove --force` 等)

**PGG の外の操作**(端末・他ツール)は必須ではない。git 自身の reflog に残る物(§3 のブランチの動きと
detached の置き去り。消したブランチの動きは HEAD の reflog に残る分)は、誰の操作でも一覧に出る。git での
ブランチの削除は reflog ごと消えるので出ない(他ツールが HEAD の reflog に書いた削除の行は出る)。

## 2. 記録(PGG が書く)

- **置き場は共有の専用 ref `refs/pgg/discards` の reflog**(`refs/heads` の外)。作業コピーで分かれず、HEAD が
  detached / unborn の間も書ける。reflog は `update-ref --create-reflog` で作る(`core.logAllRefUpdates=true` が自動で
  作るのは refs/heads・refs/remotes・refs/notes と HEAD だけ = git-config(1))。値の変わらない更新は reflog に行を
  残さないので、行ごとに新しいコミットを値にする
- **PGG が書くのは git が持っていない物だけ**。行の値は 2 つの形のどちらか:
  - **写し**(§2.1)—— 捨てる未コミットの変更そのもの。stash と同じ形のコミット
  - **メモ** —— それ以外。**失った物を第 1 親**(ブランチの先端・stash の entry・タグや作業コピーの立っていたコミット)、
    その木をそのまま持つコミットで、戻す物を trailer に書く
- **trailer**(1 行 1 つ。`Operation:` が行の種類):

| `Operation:` | 形 | 書く物 |
|---|---|---|
| `discard` / `hunk` / `lines` / `untracked` / `reset --hard` | 写し | `Working-copy:`(場所)・`Worktree:`(主の作業コピーは `.`、他は `$GIT_DIR/worktrees/` の下の名前)・`Branch:`(detached なら無し)・`Not-copied:`(1 パス 1 行)・`Stands-on:`(土台が HEAD でない時の HEAD = §2.1)・`reset --hard` は `Moved:` |
| `delete branch` | メモ(先端) | `Branch:`・`Upstream: <remote> <branch>`・両方の削除なら `Remote:`・`Remote-branch:`・`Remote-tip:`(リモートの先端がローカルと違う時だけ) |
| `delete remote branch` / `force push` | メモ(リモートの先端 = lease の oid) | `Remote:`・`Branch:` |
| `delete tag` / `delete remote tag` / `force push tag` | メモ(タグの指すコミット。手元に無ければ親無し) | `Tag:`・`Object:`(タグの object)・`Remote:`・両方の削除でリモートの object が違えば `Remote-object:` と、その指すコミットが手元に在れば `Remote-commit:` |
| `remove worktree` | メモ(作業コピーの HEAD) | `Working-copy:`・`Branch:`(detached なら無し) |
| `stash drop` / `stash pop` | メモ(entry そのもの) | `Message:`・`Untracked:`(untracked の commit。在る時だけ) |
| `rebase` | メモ(1 本目の旧先端) | `Moved: <ref> <old> <new>`(`--update-refs` で 2 本以上動いた時。1 本ずつ) |
| `restored` | メモ(戻した行の値) | `Record:`(戻した行の値)・`Part:`(部品の番号) |

- **全部の行が `Nonce:`(行ごとに一意の値)を持つ** —— コミットは木・親・メッセージ・identity・秒単位の日時で決まるので、
  無いと、戻した後の同じ秒に同じ中身を捨て直した行が戻した行と同じコミットになり、`restored` がそれも戻したことにする
- 1 操作で複数の ref が動いた時のまとまり(`--update-refs` の rebase)と、git の行と対になる写し(`reset --hard`)には、
  対応する git の行を特定できる値(`Moved:` = 動いた ref と old / new)を書く
- 先端の移動(reset・Move here・書き換え・amend・pull)は git が枝の reflog に書くので、PGG は書かない
  (上のまとまりを除く)
- **前と後**(どれも git のエラーとして通常どおり git commands へ出す):
  - 失う物を読む段(写し・ブランチの upstream・stash の entry・作業コピーの HEAD)は本体の前。失敗したら本体を実行しない
  - リモートの物は、本体の lease が読んだ物を書く(ブランチは lease の oid、タグは lease の `ls-remote` が読んだ object と
    その指すコミット)。画面が lease に渡すのは行が見せたコミットで、annotated タグの object ではない
  - 記録の行は本体が通った後に書く —— **断られた本体の分は記録に載らない**(写しは前に作り、行にするのは本体の後)。
    行の書き込みが失敗したら、本体は済んだまま、その操作は一覧に載らない。本体の後の記録のための読み(push が上書きしたかの
    判定など)の失敗も、本体を失敗にしない。行の書き込みは close で取り消さない(ローカルの書き込み)
  - **途中で失敗した本体**: 写しは、本体の後の index と作業ツリーを読み直し、前と違えば(何かを捨ててから失敗した)
    捨てた分だけを行にする(§2.1)。全部そのままなら(断られた)載せない。作業コピーの削除は、失敗しても git が作業コピーの一覧から外していれば行にする
    (作業ツリーを消せずに失敗しても `$GIT_DIR/worktrees/<id>` は消える)
  - 両方の削除で片側だけ通った時は、通った側だけを書く
  - コミットがまだ無い作業コピーの削除は書かない(失う物が無い)
- **保持は git の制御に従う**(reflog の期限・gc)。記録は失った物を gc から守らない —— gc が消した物の
  復元は git のエラーになる。メモの第 1 親(失った物)は専用 ref の reflog の行が在る間は届くが、annotated タグの object・
  `Remote-tip:`・2 本目以降の `Moved:` の旧先端は何も届かず、次の gc が消しうる
- **記録の行の期限は `gc.reflogExpireUnreachable`(既定 30 日)** —— 行の値どうしは親子で繋がらないので、どの行も
  (最新の行も、old 値が前の行の値なので)ref の先端から届かない行として扱われ、`gc.reflogExpire`(既定 90 日)は効かない
- **記録の identity は `Platitude GG`、email は空**(写しとメモのコミットの author・committer と、専用 ref の reflog 行 =
  `GIT_AUTHOR_*` / `GIT_COMMITTER_*`)。利用者の identity は使わない —— 記録は利用者が書いた物ではなく、
  利用者の identity の設定(未設定・`user.useConfigOnly`)にも左右されない。日時は記録した時
- 専用 ref の今の値(最新の行)は、他ツールの `git log --all` に見え、`push --mirror` と `bundle --all` に乗る(写しは捨てた
  作業そのもの)

### 2.1 未コミットの変更の写し

- **写しが持つのは捨てた分だけ —— 土台は本体が残した状態**: stash と同じ形のコミットで、W(作業ツリー側。木は捨てる前の
  作業ツリー)の第 1 親が土台 B、第 2 親が I(index 側。親は B)、第 3 親が U(捨てた untracked のファイル。在る時だけ)。
  B は本体が残した作業ツリー(本体の後の index に、写すパスの作業ツリーの版を重ねた木)なので、B → W が作業ツリーから
  捨てた差、B → I が index から捨てた差になり、他は何も持たない —— hunk・行の discard の写しは捨てた hunk・行だけで、
  同じファイルに残した変更は B の側に在る
  - B は、木が HEAD の木と同じなら HEAD そのもの、違えば HEAD を親にしたコミット(メッセージ `left by: <要約>`)。
    後者の写しは `Stands-on: <HEAD>` を持ち、グラフは写しを HEAD の上に描く(B は描かない)
  - I の木は、本体が index を触らなかった時(unstaged の行・hunk・行の discard)は B と同じ(index から捨てた物は無い)、
    index も戻した時(staged の行の discard)は捨てる前の index
  - `reset --hard` の B は動く前の HEAD(捨てたのは、その HEAD の上の未コミットの作業全部)
  - conflict 中のパスの index は HEAD の版(作業は作業ツリーの側)。staged / unstaged / untracked の区分は木の差に
    表れるので、メッセージには書かない
- **捨てる前は本体の前、残した物は本体の後に読む**: 本体が通った時、残した物は本体の種類で決まる —— unstaged・untracked の
  ファイルの discard は作業ツリーが index に戻るので読み直さない。staged の行の discard は index を読み直す。途中で
  失敗した本体は index と作業ツリーを読み直す(§2)。hunk・行の discard は index を触らないので、捨てる前の作業ツリーを
  取り込んだ一時の index を本体の後まで持ち、そこへ作業ツリーを取り込み直す(通っても失敗しても同じ)
- **作るのは plumbing だけ**: 一時の index は**作業コピー自身の index ファイルの複製**から始め(バイト列の複製で、
  日時も元のファイルのまま = §5 の racy git。`read-tree` は全エントリを書き直すので、ファイル数に比例して重い = §5)、
  `add --sparse --all --force`(写すパスの作業ツリーの版)・
  `update-index --force-remove`(作業ツリーにも index にも無いパス)・`write-tree`・`commit-tree` で組む。index ファイルが
  まだ無ければ HEAD を `read-tree` する。`add` の `--sparse` は sparse checkout の定義の外のパスを通す。conflict 中の
  index は `write-tree` が断る(exit 128)ので、`ls-files --unmerged` のパスを外して HEAD の版を `update-index --cacheinfo` で
  入れる。一時の index の書き込みは `-c index.skipHash=true`(全体のハッシュを書かない。読むのはここのコマンドだけ)。
  `refs/stash`・本物の index・作業ツリーは触らない —— グラフ(`HEAD`・`--branches`・`--remotes`・`--tags` と stash の
  一覧の oid を辿る)にも、ref の一覧(`refs/heads`・`refs/remotes`・`refs/tags`)にも、stash の一覧にも出ない
- **代金は本体の上に git 7〜10 本**(index を読み書きする物は index の大きさに比例)。staged の行の discard が読む status
  (rename の元の名前)は写しと本体で 1 回、`reset --hard` の写しが読む status(変更のある tracked のパス)と合わせて
  untracked を歩かない(`-uno`)。実測は [code-costs](../ci/baseline/code-costs-windows-x64.md) の `discards::copy`
- **メッセージ**: 1 行目は操作の要約(例 `discard 3 paths on main`)。空行の後に §2 の trailer。I・U のメッセージは
  固定の短い語(`index on <branch>` / `untracked files on <branch>`)
- **作業コピーは git の名前でも書く**(`Worktree:`)—— 読む時は今の作業コピーの一覧から場所を引き直す。リポジトリごと
  移したり `git worktree move` した後も、写しは捨てた作業コピーへ戻る。名前が一覧に無ければ `Working-copy:` の場所
- **利用者の設定で写しが止まらない・断られないように**、写しと記録の git には次を付ける(一時の index を使う物は全部。
  専用 ref の更新は hook だけ):
  - `-c core.hooksPath=<git dir>/platitude/no-hooks`(在ることの無いフォルダ)—— 利用者の hook を走らせない。ref の
    更新ごとの `reference-transaction`(非ゼロで更新を断れる)と、index を書くたびの `post-index-change`(一時の index でも
    走る)が該当する。`pre-commit` などコミット系の hook は `git commit` 専用で、`commit-tree` では元から走らない
  - `-c core.fsmonitor=false` —— 一時の index の読み書きで fsmonitor の hook・daemon を呼ばない
  - `-c core.splitIndex=false` —— 一時の index が `.git` に sharedindex を残さない
  - `-c core.safecrlf=false` —— 改行の混在したファイルで写しが断られない(`true` だと取り込みで die する)。
    その代わり、そのファイルは改行を揃えた形で写り、揃った形で戻る
  - 署名はしない —— `commit-tree` は `-S` 無しでは署名せず、`commit.gpgSign` も読まない(2.43.0 / master の
    `builtin/commit-tree.c`)
- **写せないファイルは写さずに捨てる**: 必須の filter(`filter.<driver>.required`)の driver が無いファイル
  (LFS を入れていない等)と、`working-tree-encoding` で変換できないファイルは写しに入れず、本体はそのまま
  捨てる。写さなかったパスは `Not-copied:` に残し、そのファイルは復元で戻らない。全部が写せない時も記録は書く
  (中身は空で、`Not-copied:` だけ)。写せるかは終了コードだけで判定し(まとめて取り込み、断られたら 1 パスずつ)、
  git のエラー文は解析しない
- **unborn(コミットが 1 つも無い)の間の discard は記録しない**(本体は実行し、一覧に出ない)。HEAD と何も違わない
  パスだけの discard も記録しない
- **入れ子のリポジトリ**(`.git` を持つ untracked のフォルダ)は写さない —— `clean -f -d` が残す
- **`reset --hard` は、行き先が持つパスに立つ untracked も写す** —— git はそれを黙って消す(git-reset(1)。ファイル・
  行き先がフォルダを持つ所のファイル・行き先がファイルを持つ所のフォルダ)。index が追跡をやめたファイルは写しの
  tracked の側に入る
- **大きさの上限は持たない**。掃除(大きい物・n 日より前の物を指定して消す)は P5 で足す

## 3. 表示(一覧が読む物)

| 読む reflog | 持ち主 | 拾う行 |
|---|---|---|
| 専用 ref | PGG | §2 の記録 |
| 手元の各ブランチ | git | reset・amend・rebase(`--update-refs` が動かした枝の `rewritten during rebase` を含む)・手で動かした行(作成・コミット・merge・早送り・push の行は上に足すだけなので見ない) |
| 全作業コピーの HEAD | git | 同じ種類の行(消したブランチの reflog と一緒に消える分を持つ。どのブランチの動きかは、checkout の行の移動元と rebase の戻り先で読む)/ detached から離れた行 / 他ツールが書いたブランチ削除の行(JetBrains の `delete_branch: <名前> <upstream> [<先端>]`) |

- **追跡 ref の reflog は読まない**(他者の force push を出さない)
- **git の行から出すのは、どの ref も届かないコミットを残した動きだけ** —— 旧先端が HEAD・ブランチ・追跡ブランチ・タグ・
  stash・他の作業コピーの detached HEAD のどれからも辿れず、新先端の祖先でもない物。項目の中身は旧先端だけが
  届くコミット。同じ動きがブランチと HEAD の両方に在れば 1 項目(ブランチの行。同じ名前と旧先端、改名で名前が違えば
  同じ旧先端と新先端で同じ動きと読む)。別のブランチの動きは旧先端が同じでも別 —— 1 回の rebase が同じ先端の 2 本を
  動かせば、その項目の部品は 2 つ(`Moved:` の名前で引き当てる)
- **記録の項目は、届いていても出す**(名前・upstream・stash の entry・作業コピー・写しを失ったので)。中身は先端だけが
  届くコミット(届いていれば無し)
- **読むのは git のプロセス数本で、項目の数によらない** —— 作業コピーの一覧と専用 ref と名前の一覧(`for-each-ref`)を
  並べて読み、全 reflog を `log -g` 1 本、reflog と記録が名指すコミットのうち ref の届かない物を `rev-list` 1 本
  (先端 200 ごとに分ける)。非早送りと到達は、その walk の中で答える
- **遡る深さはグラフの窓と同じ件数** —— 各 reflog を新しい方から `session::LogOptions` の `limit` 件まで読む
  (窓の広がりと設定の初期件数に追従し、窓が無ければ全部)
- **1 操作 = 1 項目**。部品が複数在る操作は、項目ごとにも部品ごとにも戻せる(1 回の rebase が動かした枝はまとめてだけ —— §4):
  - `reset --hard` —— 枝の動き(git の行)と写し(`Moved:` が同じ old / new の行)を 1 項目に。動きが一覧に出ない
    (旧先端に他の ref が届く)時は写しだけの項目
  - `--update-refs` の rebase —— 記録の `Moved:` が名指す動きを 1 項目に。利用者の `rebase.updateRefs` で動いた時
    (rebase・squash・drop・reword・pull)も、途中で止まって continue / skip で終わった時も(止まった rebase の
    `rebase-merge/update-refs` が持つ始まりの値で読む)。同じ間に他から動いた枝も含みうる
  - 両方の削除 —— ローカルの分と、リモートの先端が違った時のリモートの分
- **`restored` の行が名指す部品は出さない**。部品が全部戻った行は項目ごと出さない
- 一覧の読みは背景で行い、UI 操作の経路の同期処理に置かない(CLAUDE.md §性能予算)

### 3.1 出さない物

**読むが、何も失わない種類の行**(先端の上に足すだけか、先端が動かない):

| reflog の行 | 操作 |
|---|---|
| `commit:` / `commit (initial):` / `commit (merge):` | コミット |
| `merge <x>: Fast-forward` / `pull: Fast-forward` | 早送り |
| `cherry-pick:` / `revert:` | 上に積む |
| `branch: Created from …` | ブランチの作成 |
| `update by push` | push(追跡 ref) |
| `checkout: moving from <枝> to <枝>` | 枝から枝への切り替え(HEAD だけが動く) |
| HEAD の `rebase (pick)` / `(continue)` / `(finish): returning to …` | rebase の途中と終わり(1 回の rebase は `(start)` の 1 行で数える) |
| 値の変わらない行(`reset: moving to HEAD` 等) | 何も動いていない |

**動いたが、出さない動き**:

| 条件 | 例 |
|---|---|
| 旧先端に他の ref が届く(HEAD・ブランチ・追跡ブランチ・タグ・stash・他の作業コピーの detached HEAD) | 別の枝を立ててから reset した / 写しを stash として戻した |
| 旧先端が新先端の祖先 | reset で先へ進めた(失った物は、その先を離れた後の動きの項目に入る) |
| 旧先端を gc が消した | reflog の期限を過ぎた |
| 同じ動きのもう片方 | ブランチと HEAD の両方の reflog に在る 1 回の reset(ブランチの行の 1 項目) |
| グラフの窓より古い行 | 遡る深さの外 |

**git の reflog に行が残らない物**(PGG の記録 §2 が書く物だけ出る):

| 操作 | 理由 |
|---|---|
| git でのブランチの削除 | reflog ごと消える(他ツールが HEAD の reflog に書いた削除の行は出す) |
| タグの削除 | タグは reflog を持たない |
| stash の drop / pop / clear | stash の reflog から行が消える |
| 作業コピーの削除 | 記録が無い |
| 他者の force push | 追跡 ref の reflog は読まない |
| 未コミットの変更の破棄(`restore`・`reset --hard` の未コミット分・`clean`) | 記録が無い |

## 4. 復元

- **書くのは、操作した作業コピーと、共有の ref(ブランチ・タグ・stash)と、新しい worktree だけ。
  他の作業コピーの中は書かない**(別の作業者が居る)
- **作業を戻す先の作業コピーの書き込みの順番に並ぶ** —— 別のタブから戻す時も、復元はその作業コピーの書き込みの列に、
  受理した瞬間に場所を取る(その作業コピーの git dir で引く。一覧を読む時に `rev-parse --absolute-git-dir` で引いて
  部品に持たせる)。先に受理されたコミット・reset・rebase 等が済んでから当て、後から受理された物はその後。1 つの書き込みが
  複数の列に取る場所は同じ瞬間に取る(取る順が書き込みごとに食い違うと、互いを待って止まる)
- **グラフの窓に出ない物は復元しない** —— 復元で立てる物(ブランチ・タグ・stash の entry・worktree)の先頭の
  コミットが、仮表示のグラフの窓に描かれていない時は復元できない。グラフを追加で読み込み、窓に入ってから復元する
  (帯の `Load N more commits`)。作業コピーへ当てる未コミットの変更と、その当て先として新しく作る stash の entry
  (日時は復元の時)はこの制限を受けない。先頭のコミットが手元に無い部品(取り込んでいないリモートのタグ・gc が消した
  物)も、どの窓にも描かれないので待たない —— 押せば git が断る
- **`Worktree:` の名前は git が使い回しうる** —— 消した作業コピーと同じフォルダ名の作業コピーを後で作ると、git は同じ名前を
  付ける。その時、前の写しは新しい作業コピーへ当たる
- **名前**(ref と worktree のフォルダ)は一覧を読む時に決める(1 項目の部品どうしも重ならないように):
  1. 元の名前が空いていればその名前
  2. 埋まっていれば `<元の名前>-pgg-restored`
  3. それも埋まっていれば `<元の名前>-pgg-restored-1`、`-2` … の順
  - 元の名前が無い物(detached の置き去り)は `detached-pgg-restored` から同じ順

| 失った物 | 復元の形 |
|---|---|
| ローカルブランチの削除 | 記録の先端にブランチを立て、記録の upstream を付ける |
| ブランチの先端の移動 | 旧先端にブランチを立てる(元のブランチが在れば接尾辞付き) |
| リモートブランチの削除・force push | 記録の先端に、リモート上の名前でローカルブランチを立てる。upstream は付けない |
| worktree の削除 | 記録の場所へ `worktree add`(記録のブランチ。detached なら記録の HEAD) |
| stash の drop / pop | 記録の oid を元のメッセージで一覧へ戻す(`stash store`) |
| ローカルタグの削除 | 記録の object にタグを立てる(annotated は同じタグに戻る) |
| リモートタグの削除・force push | 記録の object にローカルタグを立てる(object が手元に無ければ git のエラー) |
| 未コミットの変更 | 捨てた作業コピー(`Worktree:` で今の場所を引き直す)へ当てる(下)。作業コピーが無くなっていれば断る(その場所に作業コピーの一番上のフォルダが立っていない時 —— 消した作業コピーの残ったフォルダは、それを含むリポジトリのフォルダとして答えるので `rev-parse --show-toplevel` で見分ける) |
| detached の置き去り | 置き去りにした先端にブランチを立てる |

- **未コミットの変更の当て方 —— 戻すのは捨てた分だけ**(上から順に、当たった所で終わる):
  1. 写しの差(§2.1 —— index から捨てた差・作業ツリーから捨てた差・捨てた untracked のファイル)を、今の index と
     作業ツリーへパッチとして当てる(`diff-tree -p --binary --full-index` の出力を `git apply --cached` と `git apply`)。
     捨てる前の区分(staged / unstaged / untracked)どおりに戻る。同じファイルに捨てた後で残った・足した変更は、その横に残る
  2. index の差が当たらなければ、作業ツリーの差だけを当てる —— index の差が触る各パスで、作業ツリーの側が同じ中身を
     持つ時だけ(落ちるのは staged だった事だけで、全部が unstaged で戻る)。作業ツリーが staged の変更の一部を打ち消して
     いた時(作業ツリーの差だけでは staged の分が消える)は 3
  3. 作業ツリーの差が当たらなければ、写しを stash の entry にする(写しと同じ木・親・メッセージで、日時を復元の時にした
     コミットを、写しの 1 行目をメッセージにして `stash store`)。entry の差も写しと同じ = 捨てた分だけ
  - パッチは前後 3 行の文脈で当たる。捨てた hunk の前後 3 行が捨てた後に変わっていれば当たらず 3 へ行く
  - 当てる前に `git apply --check` で確かめ、当たらなければ何も書かずに次へ行く。`git apply` は 1 つのパッチを全部当てるか
    何も当てないかで、index の差を当てた後に作業ツリーの差が断られた時は、index の差を逆に当てて戻す
  - 新しく作るファイル(作業ツリーの差が足すファイルと untracked のファイル)は、そのパスと上のフォルダの所に何も
    立っていないことを先に確かめ、立っていれば 3 へ行く(Git for Windows の `git apply` は、フォルダの所にファイルが立つ
    パスへの作成を、何も書かずに exit 0 で通す = §5)
  - 作業コピーで merge / rebase / cherry-pick / revert が進行中なら 3(当てた index の差がその操作のコミットに入る)
  - 改行と空白は写しのまま当てる(`-c core.safecrlf=false`・`--whitespace=nowarn`)
  - 3 の entry は PGG が作る物なので、identity は記録と同じ(利用者の identity を求めない)
  - 2 と 3 で戻った時は、答えの要らない報せの帯が言う(`The changes came back unstaged` / `The changes went to the stashes`)
- 部品ごとの復元も、まとめた復元も、同じ規則で部品を 1 つずつ戻す(1 つの書き込み)。断られた部品で止まり、それより前に
  戻した部品は戻ったまま
- **1 回の rebase が動かした枝(`--update-refs`)の項目は、まとめてだけ戻す**(ユーザー決定。一緒に動いた枝は一緒に戻す)。
  コミット単位で欲しい時は、仮表示の行から cherry-pick する(`Discard::restores_by_part`)
- **記録から読んだ部品は、戻すと `restored` の行を足す**(§2)。git の行の動きは、戻した枝が旧先端に届くので一覧から外れる
- **断りは git のエラーとして通常どおり git commands へ**(ブランチを他の作業コピーが使っている・gc で消えて
  いた 等)。送り直し(push)は復元に含めない

## 5. 実測で確かめた物(`TestRepo`)

- 値の変わらない ref の更新は reflog に残らない —— 記録は行ごとに新しいコミットを値にする(§2)
- `--update-refs` の rebase が動かした枝の reflog 行は `rewritten during rebase`(統合テスト
  `the_branches_one_rebase_moved_are_one_entry` が、最低版を積んだコンテナでも見る)
- §2.1 の `-c` は効く —— `core.hooksPath` を在ることの無いフォルダへ向けると、Git for Windows でも
  `reference-transaction` が走らない。`core.safecrlf=true` + `core.autocrlf=true` の repo でも混在改行のファイルが
  断られずに写る。必須の filter の driver が無いファイルは `add` が断り、そのパスだけ `Not-copied:` になる
- `stash apply --index` は index 側を I の親から I への差で当て、W の第 1 親と I の木が同じなら index 側を当てない ——
  写しの I の親を W と同じ B にするのは、stash の entry として当てた時(§4 の 3)も index の差が捨てた分になるように。
  `stash apply` は未コミットの変更を持つファイルを書き換える時は何も書かずに断り、衝突は conflict を残して途中まで
  書く —— 復元は stash の操作を使わずパッチで当てる(§4)
- Git for Windows(2.55)の `git apply` は、作るファイルの上のフォルダの所にファイルが立っていると、何も書かずに
  exit 0 で通す(`--check` も通す)。統合テスト `a_file_where_a_folder_would_go_keeps_the_work_out`
- index ファイルの複製は元の日時を引き継ぐ —— git は index を書いた時と同じ時刻の印を持つエントリを stat で信じずに
  中身を見る(racy git)ので、複製の日時が新しいと、その時刻のうちに同じ大きさで書き換わったファイルを「変わっていない」と
  読み、写しが捨てる前の作業を持たない。Linux の `std::fs::copy` は日時を引き継がない(Windows の CopyFile は引き継ぐ)。
  統合テスト `a_change_in_the_second_the_index_was_written_is_copied` が最低版のコンテナで見る
- 一時の index を `read-tree <HEAD>` で始めると全エントリを書き直すので、index ファイルのバイト列の複製より 2 桁重い。
  一時の index を書く `add`・`write-tree` の代金は index の大きさに比例し、その一部が全体のハッシュ(`index.skipHash` で
  省ける)。数字は [code-costs](../ci/baseline/code-costs-windows-x64.md) の `discards::copy`
- 先頭が窓に入るかは、仮表示の walk(窓と同じ `--max-count`)がその行を描いたかで判定する
- 一時の index で、sparse checkout の定義の外のパスは `add` が exit 1 で断る(`--sparse` で通る)。一時の index は
  本物の index のバイト複製なので skip-worktree の印も写るが、ディスクに在るファイルの印は git が読む時に外す
- `reset --hard` は行き先が持つパスに立つ untracked のファイル・その上のファイル・ファイルの所のフォルダを黙って消し、
  `diff --cached --diff-filter=D <行き先>` がそのパスを出す。`clean -f -d` は入れ子のリポジトリを残して exit 0
- `--update-refs` の rebase が止まっている間、枝は動かず、`rebase-merge/update-refs`(1 本 3 行: 名前・始まりの値・
  終わりの値)が残る。枝は終わる continue が動かす(統合テスト `branches_moved_together_after_a_stop_are_one_entry`)。
  同じ先端に立つ 2 本は同じ旧先端から同じ新先端へ動き、記録は `Moved:` 2 行(統合テスト
  `two_branches_on_one_tip_one_rebase_moved_both_come_back`)
- 木・親・メッセージ・identity・日時(秒)が同じ `commit-tree` は同じコミットを返す(統合テスト
  `work_thrown_away_again_in_the_second_it_came_back_is_listed` が日時を 1 秒に固定して見る)
- 素の `git commit` は pre-commit hook を index の lock を外してから走らせ、hook の後に index を読み直して木を作る —— hook の
  間に別の作業コピーから index へ書いた物はそのコミットに入る(統合テスト
  `work_brought_back_into_another_copy_waits_for_its_commit` が、復元が順番に並ぶことを hook で止めて見る)
