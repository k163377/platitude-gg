## 残っている実装

フル interactive rebase はプラン編集モードとして配線済み(意匠の正本は
デザイン規約 §フル interactive rebase、実装対応は rules-refs/app-ui.md)。残る磨き:

- **reword の鏡写しは保存時**(行の subject は `setMessage` で更新)— 打鍵ごとの live
  反映にするなら `MessageEditor` に text-changed の口を切る
- **squash / fixup の「親へ畳む」を言うのは動詞チップだけ**(字下げは撤去 = 3 列を揃える
  指示)。モックにあった接続線(下の行へ肘)は未描画 — 描くなら行を跨ぐので pane 側の
  オーバーレイ
- **プランの読みに行数の上限は無い**(ユーザー判断)— `--root` プランは全履歴を
  `PlanRow` に組む。性能予算はベースライン(素で表示した時)の話で、利用者が自分で開いた
  全履歴プランの増分は最適実装の分として許容する
- **プラン行に ref チップが出ない**(`--update-refs` で連れて動くブランチの可視化)。
  行 0 = 現在ブランチ分だけでも出す価値あり
- **実行後の選択は既定挙動**(旧選択が消えて default select)— 「読んでいた行の
  書き換わった先を追う」は未接続。単体 reword の `followRewrittenCommit` は在るが、
  arm は `RepoPage.saveMessage` の 1 箇所だけで、プラン実行はそこを通らない
- **動詞チップに ▾ の描画が無い**(チップ押下と右クリックで開く)
- **捨てる物が在るプランの Esc は無言**(その側の `Discard` は長押しなので、1 度下りただけの
  鍵では撃てない)。**残る判断は手応えを足すか** —— 設定画面が持っている形(1 回目は失う物へ
  送って `✕` を armed にし、2 回目で閉じる = `SettingsDialog.escapeOut`)をプランへ移すなら、
  `Discard` を armed に見せる姿の決定が要る
- **ヘッダ / onto 行のブランチ名は開いた時点の写し** — 端末で base ブランチだけを
  動かされると名前は古くなる(挙動は oid 釘付けで正しいまま)。
  名前の生き直しは refs 更新との突き合わせが要る
- **行に掴み点(grip)の印が無い** — トークンに点サイズが無く、直書きは規約違反。
  行全体が掴み手で機能は成立。**印を戻すならトークン追加の人間承認とセット**
- **プラン行の選択は「模型の selected_row + ページの selectedOid」の二重持ち** —
  所有を模型の oid 1 本に寄せる余地あり(据え置き: 動く実害が無く、寄せると graph 選択との
  橋が別に要る)
- **クリーン停止の WIP 行は語が場面に合っていない**(`rebase-edit-stop` の絵)—
  `edit` 停止の着地はグラフ最上部の `Uncommitted changes` 行 + 右ペインの
  `UNCOMMITTED CHANGES (0)` + 空のファイル一覧で、**行は「無い物が在る」と名乗る**。
  席そのものは仕様どおり(出口カードはこの行の下に吊るので、行を消すとカードの席ごと消える)。
  **据え置き** — 停止の説明は同じペインの底の出口カードが持っている。直すなら行の語の側(席はそのまま)

### 参照していた行が消えた時の着地 — 残っているのはコミット行の側

今の着地(席 → HEAD、借りのある着地が先)は rules-refs/app-ui.md の `followVanishedCommit` の行。

**残っている要求(ユーザー)**: **コミット行を読んでいた時も、閲覧していた線に
合わせて遷移する**。今の着地は席と HEAD しか見ないので、**別ブランチのコミットを読んでいた
時は跨ぐ**。**コミットからブランチを毎回求めるのは到達可能性の walk**(性能予算「操作応答は
コミット数から独立」)なので採れない —— 安い案は **「そこへ連れて行った ref を控える」**
(左メニュー・チップ・タブからの着地でその ref を控え、チップの無い行のクリックは直前の控えを
引き継ぐ)。**着地はコピーへ翻訳して読む** —— その ref を持つコピーが在ればその未コミット行、
無ければそのコピーの HEAD、どのコピーも持っていなければ ref の tip。**定義はユーザー判断待ち**。

- **未コミット行はブランチでなく作業コピーで扱う**(ユーザー判断)—— detached のまま
  進めているコピーが在るため、鍵はコピーのパス 1 本
- **first parent で線を追う案は差し戻し済み**(ユーザー判断)—— 同じ親から分岐した 3 本目の
  兄弟が席に来ると跨ぐ(実例は `basic` の `feature/remote-only`)

**着地が 2 つ armed になる形は非決定**: `drop-commit-go` は、書き込みの答えが arm する 2 つ
(止まった = 未コミット行 / 先端が動いた = コミット)のどちらが先に着くかで絵が変わり、
並列の gate の中では census が動く(`followVanishedCommit` の側の話ではない)。

**diff のファイル一覧も同じ平仄に合わせる** —— 一覧の移り先(規約 §diff のファイル一覧)は、
上が決まってから横展開する。

### 別 worktree の未コミット行 — 残っているのは読みの代金だけ

意匠の正本は [デザイン規約.md](デザイン規約.md) §別の作業コピーを読む と §未コミット行が名乗るもの、
実装対応は rules-refs/app-ui.md。

- **開幕の巡回(`refresh_quick` → `refresh_carried`)はグラフの初回描画と同じ機械を
  取り合う**(食われるのは CPU)。
  直すなら開幕の 1 周を `LogFinished` の後へ遅らせる(focus の巡回はそのまま)。
  **予算 3s の内側なので今は据え置き**
- **要判断: ペインが立っているコピーの二重読み**(tick ごとに `status` 1 本ぶん。
  数字と条件は同記録 §ペインが立っているコピーの二重読み)。**一覧は pass の答えと同じ
  コマンドの同じ出力**なので相乗りさせられるが、**選んだ瞬間の 1 本だけは別**
  (次の tick を待たせられない)。直すなら `RepoPage.pollCarried` の側 —— 選択時は今のまま
  読み、tick では pass の答えから配る
- **作業コピーのメニューの手すり**(WORKTREE カード = 規約 §メニュー の入れ子。入口は WORKTREES の行・
  フォルダのチップを持つコミット行・別のコピーが持つブランチの行とチップ。**未コミット行はメニューを持たないまま**。
  **次に行を足す時も以下を守る**):
  - **カードは 1 つの部品を 2 つのメニューが持つ**(`RefWorktreeMenu` を `RefRowMenu` と `CommitRowMenu`)——
    入口ごとに行を書けば必ず食い違う
  - **未コミット行が持っている扉は「その作業コピーを開く」1 つだけ**。`worktree remove` / `prune` は
    破壊的で、その形を崩す
  - **フォルダのチップが扉になったのはメニューだけ** —— `encode::menu_kind_word` が `worktree` を返し、
    `ref_kind_word` は `""` のまま(改名・ダブルクリックの行き先にはならない)。**`ref_kind_word` の 1 行を
    変えるとチップが改名とダブルクリックの扉になる**ので、変える時はその 2 つの所作を同時に決める

## ウィンドウ chrome — 形は決まり、残りは中身

形の正本は [デザイン規約.md](デザイン規約.md) §ウィンドウの縁。Windows の縁に残る 2 つ
(窓メニューの移動・サイズ変更 / Snap Layouts)は [P5-確認事項.md](P5-確認事項.md) §10。
ここに残るのは中身の方:

- **アドバンス検索**(基本検索の正本は規約 §コミットを探す):
  - **項目を名指しして探す形**(`author:` / `path:` / `date:`)。素の語を全軸のまま git へ
    降ろすと `--grep` と `--author` は AND なので和集合に 3〜4 スポーン要るが、接頭辞つきなら
    1 クエリ 1 スポーンで各接頭辞が git のフラグ 1 つに対応する
    (`git log --grep=… --author=… -G… -- <path> --format=%H` が SHA を返すので、印の仕掛けは
    基本検索のものを使い回せる)
  - **最初に出せるのは `description:`** — 外した 4 つのうち Description だけは行が既に
    持っているので、git を 1 プロセスも撃たずに出せる。判断は「据え置き、実使用をもう少し重ねてから」
  - **同時に決まるもの 3 つ**:
    1. **日付で探す**。Rust 側にタイムゾーン依存を 1 つ足すか、`LOG_FORMAT_ARG` に
       `%ad --date=format-local:%Y-%m-%d %H:%M` を 1 フィールド足す(`LOG_FIELDS` 8→9・
       parser の field 分岐・`CommitMeta` / `LogRow` / fixture)かの二択。**後者で決まり** —
       git が DST 込みで正しく組み、行が画面と同じ文字列を持つ。**`format-local` が読み手の
       時計に焼き付くのは織り込み済み**(規約 §author の hover)。範囲(`date:2026-08` /
       `--since` / `--until`)もそこで一緒に決まる
    2. **窓の外を探すか**。基本検索は読み込み済みの行しか見ない。git へ降ろす検索は窓の外も
       返せるので、返った SHA がグラフに無い時に何をするか(件数だけ言う / 窓を伸ばす /
       その行まで読み込む)が要る
    3. **パスで探す**(実装計画.md §14 のフィルタ 4 軸の最後)。`-- <path>` は git 側でしか
       解けない
  - **絞り込み(行の間引き)は引き続き別物** — レーンとエッジを「隠れたコミットを跨ぐ」形で
    引き直すことになり、core に 2 つ目の walk モードが要る
- **検索の入口をメニューにも置く案(未着手)**: アプリメニューに `Find commits…` の行を足す
  (規約 §メニュー に沿う)。キーが届かない場面の逃げ道にもなる —— `Shortcut` の既定 context は
  窓がアクティブになるまでキーを渡さない(rules-refs/app-ui.md の `Shortcut` の行)
- **macOS の形は決定済み・実装は実機ゲート**(Phase 5)。入口は画面上端の
  メニューバー。`QtQuick.Controls` の `MenuBar` は Qt 6.8 以降
  macOS で既定ネイティブ。**作るのは macOS だけ**(`Loader` で分ける — 他 OS では
  非ネイティブの QML メニューバーが窓の中に 2 段目として出る)。ネイティブ MenuBar は
  delegate を使わない = `AppMenu` の意匠は効かないので、**行の定義を 1 か所に置き見せ方
  だけ OS で分ける**。traffic light が帯の中心から約 6px 上は許容(直すには AppKit が要る)。
  `About` / `Settings…` / `Exit` がアプリメニューへ自動で寄るかは実機で確認

## 要判断(小さいもの)

- **自分の的の上に開く hover カード(詳細ペインの親の `+N`)は、手を動かさずに閉じると開き直す**。カードは
  的を覆い、覆われた(隠された)的の `HoverHandler` は hover を失う。閉じると的が手の下に戻り、Qt は手が
  動かなくても hover を配り直す = 開く合図がもう一度来る。なので **Escape や行の押下で閉じても、手が
  `+N` の位置に在ればすぐ開き直す**(行の押下は親へ移った後、その親の行の同じ位置に `+N` が在ればそれを開く)。
  author / co-author のカードは的の下に開くので起きない。チップのカード(`RefListPopup`)も的の上に開く同じ
  作りで、同じ筋のはず(未実測)。実測は `tst_parentline` に置いた使い捨てのテスト(`+N` に手 → 隠す → `false`、
  手を動かさず戻す → `true`、カードで覆う → `false`、閉じる → `true`)。選べる答えは **今のまま**(手が
  離れるまで出続ける = hover の意味どおり)か、**閉じた時の手の位置を覚え、的の hover がその位置のまま
  来たら開かない**(手が一度的を出るまで)。後者なら 2 枚のカードに同じ形で入れる

- **帯の `NO LFS` は、群が縮むと `NO …` になる**(規約 §ウィンドウの縁 の譲る順 2 段目。`badges-all 1000:6` の絵で
  他は `ME…` `CO…` `SET…` `STA…` `OL…`)。先頭に残るのが否定の 2 文字で、何が無いのかは消える。選べる答えは
  **今のまま**(`OLD GIT` と同じ「形容 + 名詞」の組み。自然幅が最も短い = 群が縮み始めるのが遅い)か、
  **`LFS MISSING`**(縮んでも `LFS…` が残る。自然幅が伸びるぶん、6 つ立った帯は早く縮む)。カードは
  どちらでも全文を出す

- **Git LFS の本体は入っているが `git lfs install` をしていない機械では `NO LFS` が立たない**。`git lfs version` は
  答えるが `filter.lfs.*` が未定義なので、git はそのファイルを pointer でなく**丸ごと**履歴へ入れる = バッジが
  防ぎたい害と同じ(apt で入れた Ubuntu で起こり得る。Git for Windows は system の設定に書くので起こらない)。
  今のバッジは「インストールされていない」だけを言う。選べる答えは **今のまま** か、**`filter.lfs.clean` /
  `filter.lfs.process` が git の設定に無い時も立てる**(語とカードの文は別に要る —— 入っているのに `NO LFS` とは言えない)

- **最小窓(高さ 415)で、止まった操作の出口カードの行がスクロールの先に在る**(規約 §窓の床
  「右ペインは帯と一覧の間だけがスクロールする … 床では答えられない」の帰結)。edit 停止なら
  見出し `REBASING — 1 of 2` と停止理由の行までは見え、`--continue` / `--skip` / `--quit` / `--abort` の
  4 行は右ペインを送ると出る。選べる答えは 3 つ: **今のまま**(床は出口カードを数えない = 止まった
  拍子に窓が広がらない)/ **出口カードの最大の高さを床に常に含める**(窓の高さの床が一段上がる)/
  **カードが立っている間は右ペインの上側(編集枠)を先に詰める**。絵は `rebase-edit-stop --preset plan` を、
  320×240 の `state.toml` を置いた `--config-dir` で撃つ(起動が床まで持ち上げる)

- **最小窓で開いた左メニューの BRANCHES は、先頭行が上端で細く切れ、現在ブランチの張り付き行が下に出る**
  (`state` を上と同じ `--config-dir` で撃った basic の絵)。一覧の床は帯だけを数え、行は各セクションの
  中でスクロールする(§窓の床)ので、視界が 1 行余りしか無いセクションはこう見える。選べる答えは
  **今のまま** か、**一覧の床に「開いていて行を持つセクションごとに 1 行」を足す**(床がセクションの
  開閉と中身の有無で動く = 高さの床を一定に保つ決定と両立させるなら、全セクション 1 行ずつを常に数える)

- **消えた作業コピーの WORKTREES 行を押すと、同じリポジトリに 2 枚目のタブが建つ**(規約
  §タブの所作「同じリポジトリのタブは 1 枚」から外れている側)。
  行が名指すフォルダが無い(`prunable`)と `repo::place` が断るので、`TabsModel::land` の
  `Refused` 枝が**そのパスを自分のリポジトリとして** `open_new` する。
  - **立ち直し(同§「立てない所へは立たない」)とは別の道** —— あちらは*立っているコピーが
    開けなくなった*タブの話で、こちらは*開けないコピーを新しく指した*時の話
  - 選べる答えは 2 つ: **その行を押した時だけ今のタブの話として断る**(頼んだ行がどのタブの
    左メニューに在ったかは分かっているので、`open_repository_path` にタブを添える)か、
    **今までどおり新しいタブで断る**(道が 1 本で済む代わりに、1 リポジトリ 2 タブが 1 場面だけ
    できる)。**絵は撮れる** —— `worktrees` preset の `gone` 行がまさにこれ

- **qtbridge — 同梱した `qtbridge-interfaces` の上流報告と、外す時**(同梱の中身は
  `vendor/qtbridge-interfaces/PLATITUDE-MODIFIED.md`、罠は rules-refs/app-ui.md の
  `QListModelBase` の行): 公開版 0.3.0 は proxy の `base_*` 等を `&mut self` で受け、
  release ビルドでスロットからの最初の行通知が `rowCount` の `BorrowError` で abort する
  (qtbridge の公開 API だけの最小再現で 15/15、debug では起きない。生成 IR では呼び出し前の
  借用状態の格納が無い)。モデルの種類と入口では、QML の view を繋いだスロットからの
  `QListModel` の push、`QAbstractItemModel` の insert / reset / `setData` / `removeRows`、
  `QTableModel` の push_row が公開版の release でどれも落ち(Windows・MSVC で各 3/3、`rowCount` か
  `roleNames` の `BorrowError`。debug は全部通る)、`QParserStatus`(`componentComplete` の signal から
  `&mut` スロット)は公開版でも通る。同梱版は release で全部通る(Windows と Linux・GCC で各 3/3。
  Linux の公開版は未計測)。**手渡しの無い再入**(`&mut` スロットの中で event loop を回し、同じ
  オブジェクトの `&mut` スロットが走る)は同梱版でも `BorrowMutError` で拒む。
  **報告文は `vendor/qtbridge-interfaces/UPSTREAM-REPORT.md`**
  (行き先は bugreports.qt.io の project **QTBRIDGES**、component Rust — GitHub の
  qt/qtbridge-rust は issues を閉じている。`dev`(f7fe523)でも未修正)。
  **分類は上流の欠陥**(正常な API 利用で起きる参照契約の違反)。上流の `88105239`(0.3.0 に
  入っている「Fix aliasing of proxy references in mutable dispatch」)は `invoke_slot_mut` /
  `write_property` を同じ理由で `&mut` から外した。同梱の変更はその方針をモデルの proxy の
  残り(`base_*` ほか)に当てたもの。**判断は「票を切るか・誰が切るか」**。**外す条件**は
  シグネチャの形ではなく、公開版の release で ① 報告文の最小再現 ② モデルの種類ごとの代表経路
  (上の 7 つ)③ 手渡しの無い再入の拒否(`BorrowMutError`)の 3 つが成り立つこと —— 満たす版が
  出たら `vendor/` と `[patch.crates-io]` を消し、3 つを Windows と Linux で撃って確かめる
- **tree-sitter-nix が Windows の exe に export を残す(`linker_messages` 警告の残り 1 件)**:
  文法の export は `.cargo/config.toml` の `CFLAGS = -DTREE_SITTER_HIDE_SYMBOLS` で外れるが、
  crates.io の最新 0.3.0 の `parser.c` は `#ifdef _WIN32` で `extern` を無条件に
  `__declspec(dllexport)` へ置き換える(その define を読まない古い生成器の出力)。exe の
  export はこの `tree_sitter_nix` の 1 つだけ(release exe を dumpbin `/exports`)で、それが
  あるので link.exe が要らない `.lib` / `.exp` を書き、rustc が `linker_messages` を出す
  (Windows で platitude-core を含む exe を組むたび — テストの exe も)。**上流の master
  (nix-community/tree-sitter-nix)は define を読む形に再生成済みで、未公開**(master の版も
  0.3.0)。**抑止(`/NOIMPLIB` 等)はしない**。**判断は ① 上流に公開を頼む(誰が頼むか)/
  ② 改変した `parser.c` を `vendor/` に同梱する(依存の変更 = 許可が要る)/ ③ 公開を待つ**。

- **ページに入り切らないチップの一覧は、チップの席を明け渡す**(規約 §グラフ行のダブルクリック

  **`--preset stack` に長い名前のタグを 1 本足す**(既存動詞の絵と census が動く)
- **文法経路の巨大ファイルに独自の上限が無い**: 天井は `SOURCE_BYTE_CAP`(4MB)だけで、
  4MB 級の minified / 生成ファイルは全体パース + 全行 span 化を払う。実害が出たら行数か byte の第 2 予算を検討
- **conflict した文法言語のファイルは色が出ない**(**bounded な直しが無い**): combined diff の着色は

  マーカーの入った作業ファイルでは `tree::reads` が通らない。結果として tree-sitter だけが知る言語
  (.qml / .kt / .zig 等)は conflict の間だけ無色になる。
  **直すには 2 面を組み直して各々を parse するか、マーカー行を抜いて行番号を写し戻すかで、
  どちらも walk モードの追加**(= ハイライト設計の変更)なので、やるなら設計判断とセット
- **アプリ終了はローカル書き込みの完走を待つ**(配線は rules-refs/app-ui.md の「close ゲートは 1 本」の行、
  core 側は rules-refs/core.md の「ローカル書き込みは走り切る」の行)。残っている縁:
  - mid-write のタブを閉じて即再オープンした時、旧セッションの replay が走っている間、再オープンした

    **別のコピーへ立ち位置を移して戻った時も同じ形**(離れた時のセッションが park した
    write が、戻って建て直したセッションの前に並ぶ)

    1 回だけ譲り、`Hub::shutdown` の join が窓なしで待つ(その間 exe は生きている —
    二重起動ゲートに映る)
  - modal の間はコマンドログを開けない(何が走っているかはダイアログの 1 行だけ)。
    走行中コマンドの名前をダイアログに出すには window 層へ op 名を運ぶ配線が要る(未着手)。
    **mergetool が最長の実例** — quit はそれが閉じるまで立つが、ダイアログはそれを名指せない
- **write group に残っている読み手は「同じ drain の答え 2 本目に負ける」**(**残っているのは
  持ち主を持たない書き込み全般**): group(`writeRefused` / `writeStaleDiff` / `writeMovedHead` /
  `writeReworded` / `writeBranchOp` / `writeFetched` / `writeReport*`)は、**その notify が
  運んだ答えのうち「名前で待たれていなかった最後の 1 本」**だけを説明する
  (`drain::fold_into_group`)ので、持ち主を持たない答えが 1 つの drain に 2 本入ると先の

  頼むスロット自身が受付の id を書き留め、`settle_write` が id で配り、ページはその答えから
  報せを読む(`ops::PushOut` の 2 つが先例)
- **コマンドログは `CommandStarted.operation`(その write の id)を app へ運んでいない**
  (`hub::sink` が捨てる)— 操作単位でまとめて見せる意匠が決まったら `CommandMsg` へ乗せる。
  書き込みの 3 境界の id は `repo_tab::write_watch` まで渡してあるので、足すのは id の載せ替えだけ

- **撃つ git のパスは global だけ・広げるのは実使用感が言ってから**(正本は
  規約 §設定の画面 の `GIT EXECUTABLE` 項)。どちらも据え置きで、動かすのは要ると言われた時:
  - **リポジトリ単位の上書きが無い**(ユーザー決定)。出すなら `Application` の側の話 —— **このアプリ自身の設定**
    なので、群の分け方(規約 §設定の画面)が `Application` にも要ることになり、**1 分類 1 群の今の
    形を崩す**
  - **起動時に落ちたことを帯が言わない**。書いてある git が答えなければ `PATH` へ落として
    窓は開き(`Hub::resolve_git`)、**そう言うのは設定画面のその章だけ**。5 つ目のバッジを立てるなら
    §ウィンドウの縁 の意匠判断で、**`OLD GIT` と同じ「アプリが自分で言う」側**になる

- **窓の復元位置の実機確認が残っている**(**実機待ち**。arithmetic は `tst_windowshape` が見ている)。
  **端から端までは 2 画面の実機でしか見えない**ので、次の実機セッションで 3 つ:
  カーソルを別画面に置いて起動 → 保存位置へ戻るか(症状は `x = 240, y = 90` を渡してもカーソルが DISPLAY1 に
  在ると `x=2160, y=66` に出る形)/ 倍率の違う画面で戻るか / 保存先モニタを外して起動 → 最寄りの画面に収まるか。
  **`cargo xtask perf --screen` の pin もここに乗っている**ので、実機確認までは計測の前に
  カーソルを対象画面へ置く運用を続ける
- **戻ったカードの席が動かないことの実機確認が残っている**(**実機待ち**。点滅の側は
  `row-card-return` が `held=true` で見ている)。席は行の `pointerX`(`MouseArea.mouseX`)由来で、ヘッドレスは
  そこへ書けないので報告行の `moved=` は番人でしかない(verify-ui §hover の絵の撮り方)。実機で見るのは
  1 つ: カードの上へ降りた手を同じ行の別の x へ戻し、カードが横へ跳ばないか
- **タブを復元する road だけ、パスの綴りに網が無い**(規約 §パスの区切り): 画面に出るパスは
  `urlpath::shown_path` を通って `/` になり、入口は `TabsModel` の 3 つ
  (`open_repository_path` / `restore_tabs` / `open_rejected`)と起動ゲートの 1 つ
  (`main::claim_store`)。**判定している動詞 `tab-name` が
  通るのは 1 つ目だけ**で、復元 road を撃つには `\` を書いた `state.toml` を `--config-dir` で
  仕込むことになり、**その形の run は census に載らない = gate が選ばない手動テスト**に
  なる。今は `shown_path` の単体テストで畳み方を守り、呼び出し側 1 行は網の外。閉じるなら道は
  2 つで、**復元を撃つ動詞を足す**(選ばれない手動テストが 1 本増える)か、**忘れようのない形に
  する**(入口が各々覚えている状態をやめる)。後者の置き場は `TabItem::standing()` ——
  行を作る唯一の door は在るが、**畳むのはそこでは遅い**: `landing_for` / `title_of` は
  その手前で綴りを読むので、door で畳んでも比較は畳まれていない方を見る
- **タグの雲バッジは、撮影に間に合わないことがある**(`band` で、**PASS したまま絵だけが違う**)。
  **欠ける時はサイドバーの行とグラフのチップが同時に欠ける**ので、遅れているのはモデルの側。
  **容疑はリモート側のタグの読み**(`session::RefJoins` / `remote_tags` = 行の `has_remote`)だが未検証。
  当面、雲バッジを見せる絵は**撮った絵の中にバッジが在ることを目で確かめてから**使う。
  閉じるなら動詞の完了にその join を足す

### 開発環境(Linux コンテナ)

- **席の木が、どのセッションの transcript にも削除コマンド無しに消えることがある**(いずれも未マージ commit を
  持ち作業ツリーは clean、持ち主セッションが再起動 / 再開で本体 checkout に戻った直後)。容疑はセッション終了時の
  worktree の keep / remove 問い合わせか CCD 側の後始末で、**原因は未特定**。枝の残った letter は `seats` と
  挨拶に「no tree」で出て、`cargo xtask seat takeover <letter>` が枝の上に木を生やし直す(`seats::grow_back`)。
  原因が判ったら、ここへ書き足すのではなく消す側の経路を塞ぐ

- **コンテナのイメージ・ボリューム・build cache は `linux` が入口で掃く**(`linux::housekeeping`。規則は
  [反映前テストの機械化.md](反映前テストの機械化.md) §キャッシュとスタンプ)。残る罠は 2 つ:
  - **名前は checkout ディレクトリの最後の 1 段のテキストだけ**(`checkout_name`)なので、
    **別の場所にある同名の clone のボリュームは孤児に見え**、逆に**同じ木を別の綴りで指した
    プロセス**(8.3 短縮名・大小違い。`seats::same_tree` が在るのはこの差のため)は別名を作る。
    今は volume を作る側(`workspace_root` = ビルド時の `CARGO_MANIFEST_DIR`)も
    `git worktree list` も長い綴りを返し、席の letter は 1 文字なので短縮も起きない
  - **`git worktree list` が挙げない木は死んだ扱い**。席の木が消える事象(上の項)の最中は letter の
    枝だけが残るので、その席のボリュームは孤児として消える。`seat takeover` が木を生やし直した
    後に `linux` を 1 度撃てば作り直るが、**target は空から**になる
- **消してもホストのディスクは戻らない** —— Docker の VHDX は確保済みのブロックを削除後も抱えたままになる。
  WSL のスパース VHD は破損の可能性を理由に既定で無効で、`wsl --manage --set-sparse` は
  `--allow-unsafe` を要求し、`.wslconfig` の `sparseVhd` も同じ理由で効かない。縮めるには
  管理者権限の `Optimize-VHD` か `diskpart` の `compact vdisk` が要る

- **WSL のメモリ: gate 1 本ごとに返らない分が残る — 原因は同定済み**
  ([実測](../ci/baseline/wsl-memory-windows-x64.md) が正。観測は `cargo xtask footprint <コマンド>`)。
  - **`/initd services` の走査を起こす条件は未特定**(同記録 §読み手が何を読んでいるか・
    [gate-container-reuse](../ci/baseline/gate-container-reuse-windows-x64.md) §言えること / 言えないこと)
  - **残骸の削減とホストメモリ症状は別々に判定する** —— **残骸が減ったことをもって本件を完了扱いにしない**

### 開発環境(スリープ止め `cargo xtask awake`)

要望のうち、このリポジトリの変更だけでは満たせず、実行側(Claude Code CLI かデスクトップアプリ)の変更が要る未達。
未達のまま残っていて、完了ではない。

リポジトリ側の Windows API 実測は[実測記録](../ci/baseline/awake-control-windows-x64.md)。
デスクトップアプリのログが読め、要求を 1 本の呼び出しに結び付けられる間は、[ログ補助](awake-ログ補助.md)
(不完全を承知で確度を上げる後追い。実スリープ試験の記録もここ)が下の 2 件の許可待ちと許可後を補う。
下は補助が止まっている・使えない時の挙動。補助があっても、実行前の保持を保証する正式な通知の不足は残る。

- **人が許可した後の、子プロセスを作らない呼び出し(MCP・WebFetch・WebSearch)は、許可から終了までスリープを止めない** ——
  「作業中は眠らせない」の未達。許可の要らなかった呼び出しは PreToolUse で開くので止め、シェル系は許可の後に
  起きた子で止める。穴は、許可待ちの印が立ってからその呼び出しの結果が書かれるまで
  - **取得経路が無い**(Claude Code 2.1.281 / 2.1.284 の本体で確認): 許可はアプリが `--permission-prompt-tool` への
    stdio の制御応答で返し、許可・実行開始を知らせる hook は無い(PermissionRequest は待ちに入る時だけで、入力に
    `tool_use_id` も無い)。実行するのはアプリ内の MCP(`ccd_*` / Claude_Browser / visualize / terminal /
    scheduled-tasks / mcp-registry / claude-in-chrome)か claude.ai のコネクタ(遠隔)で、経路に割り込める点が無い
  - **保証の代替にはならないもの**: タイマー・プロセスの有無・ログの無音からの推定、自動許可、アプリの `main.log` の後追い
    (許可要求と応答の行は書かれるが、読むのは実行開始の後 = 実行前の保持を保証できない)、OpenTelemetry の
    `tool_decision`(非同期のバッチ送出で、同じく実行前に間に合わない)
- **アプリ内 MCP が自分で人に許可を求めている間は、スリープを止め続ける** —— 「人を待つ間は眠る」の未達。
  例: Claude_Browser の `navigate` はローカルファイルを開く時にアプリ独自の許可要求 `browser:open_file` を出し、
  CLI の PermissionRequest も Elicitation も発火しないので、呼び出しは許可されるまで走っているままになる
  (実測: 許可まで 43 分、その間ずっと保持)。CLI が PermissionRequest を飛ばす許可要求(`personOnly`: 他人の
  artifact を読む WebFetch 等)も同じ。app.asar に MCP の Elicitation を呼ぶ箇所は無い(SDK の定義だけ)
- **要る変更(実行側)**: ① Claude Code CLI — 許可の解決時に実行より前に同期で走る hook(`tool_use_id`・判定・
  `agent_id` を運ぶ)、`personOnly` の許可要求でも PermissionRequest を走らせる、Elicitation / ElicitationResult の
  入力に呼び出し元の `tool_use_id`・`agent_id` を載せる ② デスクトップアプリ — 呼び出しごとの開始・入力待ち
  (アプリ独自の許可要求を含む)・再開・終了を外へ出す。対象はこの環境の MCP ツール全部と WebFetch / WebSearch
  (サブエージェント内も同じ)

### 性能(メモリが予算の縁)

**性能改善の着手順**は [メモリと操作応答の改善計画.md](メモリと操作応答の改善計画.md) を参照。
**予算に対する答えは [perf-windows-x64.md](../ci/baseline/perf-windows-x64.md) が正**。

- **残る超過の正体は、一族に無いグリフ 1 つで Qt がフォント DB の全 family を populate する代金**
  (機構と効かないと分かった手は rules-refs/app-ui.md「perf の判定行は net で読む」)。**効く唯一の手は
  絵文字 run を別 Text に分けて色フォントを primary にすること**だが、簡体字には効かず、対症療法なので
  **却下**(ユーザー判断)。**決定: 代金は許容し、判定は歩きの分を引いた net で読む**。初回の停止は
  時間の判定の外に居る — 含めるなら絵文字の行を `--select-oid` で名指しする。上流(Qt)への報告は任意
- **ページを開く +64MB のうちヒープ +45MB は、Rust の 18.8 を引いた ~26MB が QML の
  オブジェクト群**(記録 §常駐の内訳)。どの部品が太いかは未計測 — 詰めるなら item tree の census を
  部品ごとの個数に変えて、`RepoPage` の何が何個建っているかを先に数える
- **`perf --software` はロック中は始まらない**: run の前に機械が静かになるのを待つ条件
  (`perf::sampler::wait_for_quiet`)に「セッションが対話中(アンロック)」が入っていて、
  `--software` でもそこで待ち、30 分で断る。ロック中に software の bench そのものが進むかは未検証
  (待ちを外して確かめるのは判定の迂回なのでしない)。表示の物理電源オフで DP モニタが
  トポロジから消えた時の `--screen` の pin も未検証
- **操作応答は縁**(数字は記録 §判定。**縁の正体は往復の揺れ**で、往復はプロセス生成が主)。
  詰めるなら描く側と往復の揺れで、残る候補は 2 つ、どちらも要判断:
  - **diff を開く 1 点(人が待つ長さとしては最長)の critical path は `source_text` の直列 2 本**
    (`rev-parse --verify` → `cat-file blob`)。commit の diff は詳細一覧が status を知っている
    (`D` 以外は新側が在る)ので、`DiffTarget::Commit` に status を運べば probe 1 本が消える —
    rules-refs/core.md「読む前に `rev-parse --verify -q <spec>` で訊く」の commit 側だけの例外 = 規約判断
  - **詳細の `drain` は `reset()` で一覧のデリゲートを作り直す**。`dataChanged` + 末尾の insert / remove に
    変えれば可視デリゲート十数個の再生成が消える。ただし**デリゲートの作り直しが乗るのは
    「モデルに入ってからフレームまで」の小さい方の半分**(記録 §操作 1 点の内訳)なので、**やるなら
    モデルを組む側と一緒に見る**
- **グラフを一度流した分は戻らないが、漏れではない** — **一度見た行の数**で頭打ちし、走った距離では
  増えない。主因は「行のデリゲートが隠したまま建てる部品」と「フォールバックフォントの常駐」
  (記録 §メモリの段 / §常駐の内訳)。窓の行数(`--max-count=2000`)は据え置きで、**読む人は
  設定で下げられる**(規約 §設定の画面 `COMMIT GRAPH`)
  - 効かなかったもの: `gc()`(V4 ヒープではない)・`QSG_ATLAS_*` を縮める(アトラスでもない)・
    `Canvas.Immediate`(描画方式でもない)
  - **却下: フル Shape 化** — バッジの punch(`destination-out` がレーンと顔をくり抜く)は Shape に無く、

  `corner` の `shown=true` は gate で判定されていない(verb-tiers は判定される前提)。census の記録か must_say の照合をコードで直す
- **must_say の行が無い**: `push-retry` / `open-not-a-repo` 系 7 動詞 / `diff-fold-by-hand`・`diff-keep-folded` / `open-again` / `graph-divider`(絵で足りるか)
- **must_say が縛らない値**: `edit-message-focus` の `color=` / `publish` の `dialog=`・`name=` / `drop-commit` の `hold=` /
  `delete-branch` の「左のカードが閉じたか」/ 設定画面の範囲の丸め(同時実行数 0 → 既定・秒 1 → 5)
- **素の `stash` run はどんな帯でも落ちない**(`stashNamed()` は `stashWanted` が空なら常に false)— 全部同じ名前を着せる帯を捕まえる run が無い
- **census に形が無い = gate が一度も回さない**: `stash-state` の ready / clean / conflicts / `perf diff`・`perf scroll-none` /
  `commands-fail-shut fold` / `remote-menu`・`remote-url` の `:marked` / `nav-add-remote` の noremote・folded /
  `nav-*-box` の `:away`・幅 / `switch-lands feature/topic-a:2` / `switch-stopped main --preset rebase-conflict`(`-go` の must_say と合わず赤のはず)/
  `code-send columns.txt --preset widechars` / `diff-follow` の staged・untracked 形 / `name-box-drop` の `box=false`

### 不具合(コードを読んで確かめた)

- **検索 `0000` が作業コピーの行に当たる**: core `find::Query::matches` は空の id だけを飛ばし(「呼び手が非コミットの id を空にする」前提)、
  app `GraphModel::hits` は作業コピーの行の id(0 が 40 個)をそのまま渡す。規約 §コミットを探す の表「`0000` でも当たらない」に反する。
  core の `a_row_that_is_not_a_commit_matches_nothing` は行を id `""` で作るので、実物の形を縛っていない
