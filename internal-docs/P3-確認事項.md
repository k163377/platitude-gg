## 改行コード(EOL)の警告 — 仕様確定・未着手

**方針: 変換しない・gitconfig を書かない。git がしていることを見えるようにするだけ。**
他 GUI で事故が集中しているのは `core.autocrlf` を書き換える系の導線(IntelliJ の
`Fix and Commit` が global を書く / Sourcetree が勝手に false にする)なので、そこへ行かない。

### 出す 4 ケース

| | ケース | 判定 |
|---|---|---|
| (a) | 既存ファイルの EOL 反転(全行 -/+) | diff の bytes のみ = **厳密** |
| (b) | 追加 / 変更行が混在を作る・増やす | diff の bytes のみ = **厳密** |
| (c) | 新規ファイルが基準と違う | 標本による**推定** |
| (d) | 無改行ファイルへの初の改行 | 標本による**推定** |

- **元から混在で、自分の変更が増やしていないものは出さない**(増やす時は (b) として出る)
- **混在は 1 行でも言う**(閾値を持つとアプリの独自基準になる)
- 除外は git が言う `-text` だけ。生成物・testData 等は `.gitattributes` 任せ
- **履歴 diff では (a)(b) だけ出す** — (c)(d) はそのコミット時点の周辺を標本にできない

### 基準の求め方

1. **`check-attr` の `text` / `eol` + `core.autocrlf` / `core.eol` の実効値**。ここで決まるなら標本は不要
   (`autocrlf=true` なら新規ファイルは必ず LF に正規化されて格納される = 比較する必要が無い)
2. 決まらない時(**attributes 無言 かつ `autocrlf=false`**)だけ標本 3 件の多数決
   - 採取は**同一拡張子**(同ディレクトリ優先)→ 不足分はランダム。**拡張子なしファイルは直接ランダムへ**
   - `-text` / `mixed` / `w/` が空(未チェックアウト)の標本は**捨てて補充**。**1MB 超は stat で外して読まない**
   - 3 件揃うまで**最大 9 件**読む。揃わない・拮抗なら「不明」→ **黙る**((c)(d) 自体を出さない)

n=3 の弱点として、同一拡張子で LF/CRLF が拮抗するリポジトリでは標本次第で結論が揺れる。
セッション内はキャッシュで安定するが、跨ぐと変わりうる — 承知のうえで採っている。

### キャッシュ

- キーは **(ディレクトリ, 拡張子)**。契機は status ポーリングの **clean→dirty 遷移**と、
  **open 時に既に dirty なもの**(遷移が観測できないため)
- 無効化: HEAD 変化 / 書き込み完了 / `.gitattributes` を含む変更 / タブを閉じる
- 1 tick で複数増えた時は 1 プロセスにまとめる(`check-attr --stdin -z`)
- **先読みは待ち時間を消す最適化**で、正しさは diff を開く側の「無ければその場で取る」が担保する。
  **警告が後から現れるのは許容しない** = diff と同時に emit する(採取と `git diff` は並列)

### 見せ方

- **ファイル単位 1 行**。席は DiffPane のバイナリ告知と同じ場所。**行単位の印は付けない**
  (CR は不可視で行内に置く場所が無く、(b) は件数で足りる)
- **WIP ペインのファイル行にも印**を出す(diff を開かずに commit 前に気づけるのが主目的)
- **warning 色・尋ねない・止めない・長押しなし**。`LF` / `CRLF` はコード表記チップにしない
  (チップの形は小文字・等幅で、全大文字の略語は載らない)
- 文言(`qsTr`。**断片連結しない** — 標本の範囲ごとに全文を用意する):
  - (a) `Line endings change · CRLF → LF`
  - (b) `Mixed line endings · 3 added lines use CRLF, this file uses LF`
  - (c) **標本の実際の範囲を名乗る** — 3 件全部が同じ拡張子なら拡張子を、3 件全部が同ディレクトリなら
    `here` を言う: `New file uses CRLF · other .kt files here look like LF` /
    `… other .kt files look like LF` / `… other files in this repo look like LF`
  - (d) (c) と同じ形に `First line ending in this file · CRLF · …` を冠する

### 実測(判断の根拠。基準リポジトリ `JetBrains/kotlin` = 106,581 ファイル)

- `ls-files --eol` 全件 **24.7s**(`w/` 列のため worktree を全読み)/ 確定した 3 パスなら **42ms** /
  120MB のファイル 1 件で **213ms**
- `ls-files -- '*.kt'`(索引のみ) **85ms**(64,012 件ヒット)/ ディレクトリ限定 59ms
- `check-attr --stdin -z` 200 パス **71ms**(1 件ずつなら 42ms/件)

### 触らないと決めたもの

- **`core.autocrlf` / `core.eol` / `.gitattributes` を書く導線**・ファイル内容の EOL 変換・
  「`.gitattributes` が無い」という指摘
- **`--ignore-cr-at-eol` の表示トグル** — その patch は `apply` できず、EOL のみの差だと
  diff が空になる(status は modified のまま)
- **成功した git の stderr をコマンドログへ出すことを、EOL を理由には決めない** —
  `autocrlf=true` では読み取りコマンドでも警告が鳴り続けてノイズになる。
  push の `remote:` 行など他の用途で欲しくなった時に別途判断する

### 付随して要る作業

- **`TestRepo` に `autocrlf=true` 版を足す** — 今は repo-local で `false` 固定のため、
  **Windows 既定の経路をテストが一度も通っていない**。実測した挙動
  (index に CR があると `autocrlf=true` でも変換しない / `--no-index` にも変換が効く)を
  先にテストへ固定する
- **`ls-files --eol` / `check-attr --stdin -z` の最低バージョン照合**([git最低バージョン整合.md](git最低バージョン整合.md))

タブ行が OS のタイトルバーを兼ねる形は**実装済み**で、決まったことは

(exe の表示名は §11)。白い 1px はそこから落ちた — 窓が自分でフレームを塗るように
して解決済み(2026-08-09)。

ここに残るのは中身の方:

- **Ctrl+F の検索バーは枠だけ**(`FindBar`。グラフの右上に浮かび、打てるが誰も読まない)。
  中身を入れる前に 2 つ決める:
  - **「印を付けて移動」か「絞り込み」か。** 推奨は印 + 移動(Chrome の Ctrl+F と同じ
    意味)。絞り込みは行を間引くのでレーンとエッジを「隠れたコミットを跨ぐ」別物として
    引き直すことになり、core に 2 つ目の walk モードが要る。印なら walk は無変更で、
    読み込み済みの行はハッシュ集合の照合だけで光る。
    `git log --grep=… --author=… -G… -- <path> --format=%H` が SHA を返すので、
    アプリ側は「その SHA が来たら光らせる」で済む。絞り込みは同じバーの中に後から足せる
  - **1 つの入力欄で message / author / sha / path をどう捌くか。** 素の語を全軸へ流すと
    `--grep` と `--author` は AND なので git を 3〜4 回撃って和集合を取ることになる。
    `author:` / `path:` の接頭辞つき・素の語 = メッセージなら 1 クエリ 1 スポーンで、
    各接頭辞が git のフラグ 1 つに対応する
- **背景タブの状態が出ない**。進行中 / CONFLICTS のバッジは**アクティブなタブの
  分しか出ない** — 3 番目のタブで rebase が止まっていても見えない。タブ自身に印を出せば
  要望「見落とさない場所に常時表示」がむしろ強くなる
- **125% / 150% の目視が未実施**。右端の間合いは実測値で組んであるので、拡大率を
  変えた画面で 1 度見ておく
- **macOS の形は決定済み・実装は実機ゲート**(Phase 5)。兼ねる場合も **☰ は持たない**
  — 画面上端のメニューバーが通常時もフルスクリーンでも届く場所に既に在るため。
  `QtQuick.Controls` の `MenuBar` は Qt 6.8 以降 macOS で既定ネイティブなので Qt Widgets
  も C++ も要らないが、**作るのは macOS だけ**(`Loader` で分ける — 他 OS では非ネイティブの
  QML メニューバーが窓の中に 2 段目として出る)。ネイティブ MenuBar は delegate を使わない
  = `AppMenu` の意匠は効かないので、**行の定義を 1 か所に置き見せ方だけ OS で分ける**。
  traffic light が 40px の帯の中心から約 6px 上に来るのは許容(直すには AppKit が要る)。

## 要判断(画面設計と一緒に決める)

### A. interactive rebase の画面

必要な要素: 対象範囲の選択（`<upstream>..HEAD`）、行の並べ替え、
アクション選択（pick/reword/edit/squash/fixup/drop）、reword のメッセージ入力。
`sequencer::plan_for()` が初期プランを返すので、UI は並べ替えとアクション付与だけ。

ブリッジのスロット形状も同時に決める必要がある(候補: プランを 1 行ずつ積む
`beginRebasePlan()` / `addRebaseStep(action, oid, message)` / `runRebasePlan(upstream)`)。

同時に決まるもの:

- **書き換え警告**(他の操作は配線済み。残るのはこの 1 つ)。範囲 `<upstream>..HEAD` を
  `publish::state_of()` へ渡すだけだが、**答えの置き場は 1 つ**(`publishRange` /
  `publishTotal` / `publishPublished`)なので、聞いた範囲の答えだけを読むこと。
  警告は**尋ねずに言う**(実行は止めない)。published = remote-tracking ref から
  到達可能 = **最後の fetch 時点の情報**でしかない
- **`edit` 停止を「失敗」と分ける**。git の正常動作だが非ゼロ終了で返るので、セッションは
  `WriteFinished{error}` を出す。UI 側で「停止しました」と「失敗しました」を区別する
  (op_state を見れば判る)。**同時に、出口カードの `--skip` の印も決まる**(上記)

### B. グラフ行に hover した時に何を出すか — 決着済み

`CommitHoverCard`(subject + body + author + 日時 + co-author)が答え。位置が
ポインタに追従しない問題も、`ToolTip` をやめて `Popup` を自分で置くことで解けた
(規約 §co-author の表示 / app-ui.md)。チップ列に在った ref 一覧の `ToolTip` は
**行を覆う `MouseArea` に hover を奪われて一度も出ていなかった**ので削除した
(重なったチップは `RefListPopup` が答える)。**WIP 行だけは何も出さない** —
カードに入れるものを 1 つも持たないため(規約 §hover のツールチップ)。

## 要判断(小さいもの)

- **同じリポジトリのサブフォルダを指した時**: 既に開いているものは 2 枚目のタブに
  ならずそのタブへ移る(規約 §タブの所作)が、判定は**フォルダが同じか**
  (`repo::open_key` = `canonicalize`)なので `repo` と `repo/src` は別と答え、2 枚開く。
  同じと答えるには `rev-parse --show-toplevel` の答えを待つ必要があり、その判定が
  居るのは同期スロット(`TabsModel::open_repository_path`)の中。**開いてから畳む**
  (タブを立て、解決できた時点で既存タブへ吸収する)か、**そのままにする**(ピッカーで
  リポジトリの中まで降りて選ぶ人は稀、が前提)かを決める。**別 worktree は別タブの
  ままが正**(作業ツリーが違う = 見るものが違う)
- **cherry-pick / revert の複数選択**: core は複数リビジョンを受ける
  (`cherry_pick(revs)` / `revert(revs)`)。ブリッジが 1 件ずつなのは複数選択 UI がまだ
  無いから。グラフでの複数行選択ができた時点で、ブリッジも複数対応に広げる
- **`rebase --onto` の branch 指定**: core にあるがブリッジ未公開
- **`merge` のオプション**(`--no-ff` / `--ff-only` / `--squash`): ブリッジは受けるが
  呼ぶ導線が無い。rebase 側が足すのは **`--update-refs` だけに決めた**
  (規約 §履歴を合流させる)。merge のこの 3 つをどう出すかは実使用感で決める
- **URL の訂正を開く入口が無い**: 直す場所は決まった(`RemoteDialog` に `editing` を
  渡せば `Where <remote> is` になる)し core とブリッジも在る
  (`session::set_remote_url` / `RepoTab::setRemoteUrl`)。無いのは**そこへ行く操作**。
  REMOTES のリモート行は今フォルダ行でメニューを持たない(`NavItemDelegate` は
  `oid_hex !== ""` の行だけメニューを開く)ので、(a) フォルダ行にメニューを許す /
  (b) 「間を空けた 2 回目のクリック」をリモート行にも与える(今は改名の所作)/
  (c) push が失敗した質問バーの続きとして出す、のどれかを決める必要がある
- **質問を立てる残り 2 経路**: グラフ行の右クリックと左メニューから
  `startPublishAsk()` を呼ぶ配線。質問側は 1 つに集約済みなので入口を足すだけ
  (ただしグラフ行から立てる場合、対象が「現在のブランチ」でよいかは要判断)
- **リポジトリ単位の identity 上書き**(仕事用メール等)の導線: core は対応済み・UI 未提供
- **リポジトリを開く `rev-parse` をコマンドログに出すか**: 今は背景読みなので、
  タブが開けなかった画面から `>_` を押しても**パネルは空**(0 件)で立つ。出すには
  セッションの**利用者用ハンドル**(`exec_user`)で撃つ 1 行で足りるが、core.md は
  「書き込みキューだけが利用者用を使う = 分類がキューの分岐 1 箇所で決まる」と
  決めているので、**規約の書き換えを伴う**。副作用はタブを開くたびにログへ
  `rev-parse` が 1 行残ること。「開くのは利用者が頼んだ操作そのもので、今はログが
  それを黙っている」と読むなら足す側(2026-08-09 保留)
- **`ToolTip` の地が 39 か所すべて Fusion 既定**(= ダークテーマの外の淡い黄色)。
  `Main.qml` の palette が `toolTipBase` / `toolTipText` を持たないため、`ToolTip` を
  使う 14 ファイル・39 か所が全部その色で出る(2026-08-09、author 名の hover を
  カードへ差し替える作業中に実写で確認 → **今は触らないと判断**)。直すなら palette へ
  2 役割を足す 1 コミットだが、**デザイン規約の色表にツールチップの地の行が無い**ので、
  トークンを足すか既存(`bgElevated` + `borderDefault` + `textPrimary`)で足りるかを
  先に決める
- **author 側のタイムゾーン**: `AuthorCard` は 2 つの時刻をローカル時刻で出す
  (規約 §author の hover)。書いた人の現地時刻で読ませるなら core が epoch ではなく
  offset 付き(`%aI` 等)を運ぶ必要がある。要否は実使用感で決める
- **ダイアログ本文幅 `640` の token 化**: git バージョン gate からの流用で、いまは
  `AppDialog` が全ダイアログに掛けている(gate 側の `Main.qml` と 2 箇所に直書き)。
  デザイン規約の表に無い値なので、token 化するかは要判断
- **コマンドログに保存が無い**: 1 タブ 500 件・件数を超えたら古いものから捨てる(1 件
  あたりの上限は無い — 途切れた出力の方が害が大きい。実質の天井は
  `process::STDERR_CAP` = 256KB)。ファイルへの保存・「全部コピー」は将来分。
  **ファイルへ出す時は `https://user:token@host` の userinfo を落とすこと**(保存もコピーも
  ユーザー操作で画面内に留まる今は害が無い)
- **エラー表示が仮置き**: 失敗するとコマンドログのパネルが自ら開き、閉じるまで開いたまま
  になる(**答えを用意してある拒否は除く** — `RepoPage.expectedRefusals` が数えて素通しし、
  質問バーが既に説明しているものでパネルを上げない)。ヘッダの 1 行
  (`repoTab.lastError`)は**行に出ない失敗**のための場所だが、書き込みの失敗では行と
  二重になる。本来のエラー表示を作る時に整理する

## 探索で見つかった残件(2026-08-07 の全動詞スモーク + 静的探索。修正済み分はコミット履歴参照)

修正より記録が適切と判断したもの。着手時は再現テストを先に書くこと(CLAUDE.md §Rust 規約)。

### core

- **合成 write のキャンセル窓**: `carry_across` で stash 後・switch 前にセッションが閉じると、stash に入ったまま通知が出ない(stash list には残る = 復元可能)。クローズ経路の best-effort 通知を検討
- **同一リポジトリ複数タブのキュー**: 書き込みキューはセッション(タブ)単位で、同一リポジトリの worktree を 2 タブ開くと `stash@{0}` 前提の合成(`carry_across` / stash rename の selector シフト)が相互レースする
- **commit 成功後の読み失敗**: `commit::commit` は成功後に head_oid を読み、セッションはその値を捨てる — 読みだけ失敗すると成功したコミットが失敗として報告される
- **open 完了前の write**: セッション open 前に届いた書き込みは debug ログだけで消える(WriteStarted / Finished が出ない)
- **Linux で interactive rebase のテストが `Text file busy` で落ちる**(2026-08-09 実測。
  **main 時点で再現するので既存**): `cargo xtask linux test -p platitude-core` の全件走行で
  `squash_and_reword_run_through_the_write_queue` /
  `a_restore_that_collides_lands_in_the_files_and_keeps_the_entry` /
  `a_replay_that_stops_part_way_leaves_the_work_in_the_stash` が落ちる。git が起動する
  `GIT_SEQUENCE_EDITOR` = `target/debug/deps/pg-todo-editor` を、**まだ書き手が掴んでいる
  うちに exec する**ため(ETXTBSY。Linux にしか無い)。**1 件ずつ走らせると通る**ので、
  並列走行と直前のビルドが揃った時だけ出る。**`stash pop` が余分に出る形は症状ではなく
  結果** — replay が起動できず、carry が正しく退避を戻しているだけ。直すなら
  `pg-todo-editor` をテスト用に一時ディレクトリへ複製してからそれを渡す
- **walk のワーカが落ちるとグラフは回り続ける**: パニックは tokio のワーカで捨てられ、UI には成功も失敗も届かないのでローディングのリングが永久に残る(`parse::log` の byte index パニックで実際にそうなった)。**エラー表示にもコマンドログにも 1 文字も出ない**のが問題で、パニック自体を無くすのとは別に、walk が答えずに終わった時の出口が要る

## 触らないと決めたもの(再検討しない)

- **`Stage file` と `Stage hunk` の右端は揃えない**: ヘッダの語は `✕` の分だけ内側に
  いて、hunk の語より 25px 左で終わる。ヘッダ帯に区切り線が入って「別の箱の中の
  右端」として読めるので、そのままにする(2026-08-08)
- **選択のある hunk でも `Discard hunk` は hunk のまま**: 捨てるのは**見た目上の
  hunk** = 今その diff に出ているもの。`--cached` を付けないので index は動かず、
  部分ステージ済みの分は残る(`stage_integration::discard_a_single_hunk` が
  「the index is untouched」で固定している)。行単位の discard は作らない
- **末尾改行が無いファイルへの行追加は部分ステージできない**: 追加行だけを選んだ patch は
  unified diff として表現できない。**前提となる行を自動で選択に足す回避策は入れない** —
  選んでいない行を黙って index に入れる方が害が大きい
- **untracked ディレクトリの空殻が残る**: 中の 1 ファイルだけを部分ステージできる代わりに、
  全ファイルを discard すると空のディレクトリがディスクに残る(git は空ディレクトリを
  追跡しないので status は clean のまま)
- **`--allow-empty` / `hunk_count` はブリッジへ出さない**: 空コミットを発行する導線を
  持たない(Commit は staged が 1 件以上ある時だけ通る。amend を除く)。hunk 数は diff 行
  モデルから UI 側で数えられる
- **octopus merge(3 親以上)は作れない**: `merge` は 1 リビジョンのみ受ける。要望に無い
