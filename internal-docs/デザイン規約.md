# platitude-gg デザイン規約

UI の色・タイポグラフィ・寸法の**正本**。QML を書く前に読み、必要な値を表から選ぶ。

本書の目的は見た目の理想を語ることではなく、**実装時に数値を考える余地を無くすこと**。
「12px と 13px のどちらが良いか」「余白をあと 2px 詰めるか」を検討してはならない。表から引いて終わりにする。

## 絶対ルール

- 値は本書の表にあるものだけを使う。**表に無い数値・色・フォント名を QML に書かない**
- 微調整目的で中間値(1px 刻み・中間色)を新設しない。ズレて見えるなら「グリッド外の値が混ざっている」のが原因なので、そちらを直す
- 見た目を詰めるためにビルド・スクリーンショットの往復をしない。表どおりに書いた時点で完了とする
- 表で表現できない要求に当たったら、その場で値を発明せず**人間に確認する**(本書へのトークン追加として扱う)
- 用途が近いトークンの流用より、正しい用途のトークンを使うことを優先する。それでも該当が無ければ上記の確認へ

### 状態

段は 3 つ。**分ける軸は「取り返しがつくか」ではなく「波及するか / 止まっているか」**。
このアプリに取り返しのつかない操作はほとんど無い(force push は常に lease 付き、
reset も switch で戻せる)ので、可否で切ると `danger` を使う操作が無くなってしまう。

| token | 値 | いつ使うか | 例 |
|---|---|---|---|
| `success` | `#16A34A` | 成功・ahead | staged・PR あり |
| `warning` | `#D97706` | 次のいずれか — **自分の外へ波及する**(他人が持っている履歴・リモートが変わる)/ **進行中で対処が要る** / **答えを待っている** | `push -f`・already pushed・MERGING・SET IDENTITY・detached HEAD・質問バー・未保存の質問 |
| `danger` | `#EF4444` | **今止まっている・失敗した**、および**手元の成果を捨てる** | conflict・git のエラー・Discard everything after it |

**この 3 つに当てはまらない知らせに状態色を使わない。** 読まなくても操作が進むもの
(仕様の説明・静かに失敗しているだけの通知)は `textSecondary`。状態色は出現数が
少ないほど効くので、「一応目立たせておく」で足さない。

`danger` が「もう起きた失敗」と「これから捨てる操作」を兼ねるのは意図的。
どちらも**その場で止まって読ませたい**もので、片方を別の色に割ると赤の意味が薄まる。

### 暗く落とした段(`*Dim`)

**色を暗くすることは、状態を表す経路として認める。** 色相を保ったまま明度だけ
落とすので「何であるか」は変わらず、「どういう状態か」だけが乗る。無効
(§無効)が文字を `textMuted` に落とすのと同じ考え方を、種別色・状態色にも
広げたもの。**枠・アイコン・マークに使う**(文字を暗くするのは無効の合図なので、
`*Dim` を文字色に使わない — 押せないという嘘になる)。

値は微調整しない。各色の出自である Tailwind のランプを**一律 2 段下げる**。

| token | 値 | 元 | ランプ |
|---|---|---|---|
| `accentDim` | `#1D4ED8` | `accent` | blue 500→700 |
| `refTagDim` | `#A21CAF` | `refTag` | fuchsia 500→700 |
| `successDim` | `#166534` | `success` | green 600→800 |
| `warningDim` | `#92400E` | `warning` | amber 600→800 |
| `dangerDim` | `#B91C1C` | `danger` | red 500→700 |

`textSecondary` を 2 段下げると `#475569` = 既存の `borderStrong` になるので足さない。
テキスト段(`textLink` / `textMuted`)も足さない — 文字を暗くする経路は §無効 が既に
1 つ持っており、2 つ目を作ると読み分けられない。

**`*Dim` は自分の元の色との対比でのみ読ませる。同じ場所に 2 つ以上の `*Dim` を
並べない。** 暗くすると彩度が落ちて色同士が寄るためで、実測値がそう言っている
(§ref の種別 と同じ手法 — Machado 2009 severity 1.0 の 1/2/3 型 + CIEDE2000)。
元の色との差は全て floor の **8.8** を大きく超える(最小 12.6 = `dangerDim` × `danger` /
3 型)一方、`*Dim` 同士は `warningDim` × `dangerDim` が **4.0**(2 型)、
`accentDim` × `refTagDim` が **6.9**(1 型)まで寄る。

地に対するコントラストは `bgSurface` で 2.83〜3.19:1 / `bgElevated` で 2.50〜2.82:1。
枠の下限として既に許容している `borderDefault`(1.95:1 / 1.72:1)を上回る。

### ref の種別

グラフのチップとサイドバーの見出しで ref の**種別**を示す色。**状態の 3 段とは
別の軸**なので `warning` / `danger` を流用しない(タグが警告に見えるのがこの事故)。

| token | 値 | 用途 |
|---|---|---|
| `accent` | `#3B82F6` | ローカルブランチ |
| `textSecondary` | `#94A3B8` | リモートブランチ |
| `refTag` | `#D946EF` | タグ(チップ・TAGS 見出しアイコン) |
| `warning` | `#D97706` | detached HEAD マーカー(種別ではなく状態なので状態色。**サイドバーとグラフで同じ色**) |

**種別色が塗るのは枠とアイコンで、ref の名前は塗らない。** チップから読むものは
2 つ(**何であるか** / **何処に在るか**)なので、経路を 1 つずつ割り当てる —
**枠 = 種別、名前の色 = 在処**。サイドバーの行は既にこの読み方で、名前は
`textPrimary`、種別は見出しアイコンの色が持つ。グラフ行で最も読ませたい文字は
ref の名前であり、枠が既に言っていることにその可読性を使わない
(`bgSurface` 上のコントラスト: `accent` 5.5:1 / `refTag` 5.2:1 に対し
`textPrimary` 16.4:1)。

**タグの枠だけは明度でも語る。** ここに無いタグ(リモートにしか無い / ズレている)の枠は
`refTagDim`(§暗く落とした段)。色相は保つので「タグである」は変わらず、乗るのは在処だけ
——**色相 = 種別 / 明度 = 在処**で、経路は 1 つずつのまま。**この二重取りをタグにだけ許すのは、
タグにだけ必要だから。** リモートブランチは枠の色そのものが在処を兼ねており(`textSecondary`)、
名前も `origin/main` と名乗る。タグには名前空間が無く、ズレると同じ裸の名前が 2 行に出るので、
突き合わせる手掛かりが名前の明度しか無かった。

| 名前の色 | 意味 | 出る先 |
|---|---|---|
| `textLink` | **今ここに立っている** | 現在のブランチの名前(左メニューの行・チップ・hover カード・ツールチップ) |
| `textPrimary` | ここに在る | ローカルブランチ・ローカルにも在るタグ |
| `textSecondary` | リモートにしか無い | リモートブランチのチップ・リモートにしか無いタグ |
| `warning` | detached | HEAD マーカーのみ(種別ではなく状態なので名前にも出す) |
| `textMuted` | 行き先にならない(§無効) | hover カードの HEAD マーカー行 |

**現在のブランチは、名前が出る場所すべてで `textLink`。** サイドバーの行だけが
その色で、チップ・カード・ツールチップでは他のブランチと同じに見える、が起きていた。
同じ名前が場所によって「ここ」に見えたり見えなかったりするのは、この列が答えている
問い(何処に在るか)への答えが場所ごとに変わることを意味する。**行き先にならないことを
理由に `textMuted` へ落とさない** — 現在のブランチが押せないのは「使えない」からではなく
「もう立っている」からで、それは在処の話。落とすのは HEAD マーカーだけ(ref ですらない)。

**重なった時は現在のブランチが先頭。** 1 行に複数の ref があるとき、チップが名前を出す
1 件・カード・ツールチップの並びはいずれも **現在のブランチ(detached なら HEAD マーカー)
→ ローカル → リモート → タグ**。並べ替えは core で 1 回だけ行う(`build_label_map`)。

**リモートを `textMuted` まで落とさない。** リモートのみの行にはダブルクリックで
行ける(ローカルを作って移動する)ので、`textMuted` =「押せない」(§無効)は嘘になる。
コントラストも 4.2:1 で、この文字サイズでは低すぎる。
チップ内の `+N` は名前ではなく件数なので `textSecondary`(行の他のメタ情報と同じ)。

`refTag` は Tailwind `fuchsia-500`。CUD 検証(Machado 2009 severity 1.0 の
1 型 / 2 型 / 3 型シミュレーション + CIEDE2000)で、同じ列に並ぶ色との最小差は
**13.4**(`accent` / 2 型)。本書が既に許容している最小差は **8.8**
(`warning` × `danger` / 3 型、`accent` × `textLink` / 3 型)なので、それを上回る。
地(`bgSurface`)に対するコントラストは 5.83:1。
レーン色との最小差は 8.6(lane 6 `#0072B2` / 1 型)だが、レーンは別の列の細線であり、
識別を色だけに依存させない方針(§コミットグラフのレーン色)で担保する。
検討した他の候補(violet / purple / cyan / teal / pink 系)はいずれもこれを下回った。

### 無効(disabled)

**押せないものは押せないように見せる**。無効の合図は文字色を `textMuted` に落とすことで、
背景・枠は変えない(ホバーの重ね色は無効時に出さない)。強調ボタン(Commit / Save)は
面のアクセントも `accentMuted` へ落とし、「今押すもの」に見えない状態にする。

**ただし右クリックのメニューは無効行を持たない** — 選べない行はそもそも出さない
(§メニュー)。無効の色が出るのは、画面に居続けるもの(ボタン・入力欄・アプリメニュー)
だけで、右クリックしたものに合わせて組み立てる一覧には出ない。

実装はウィンドウの `palette` 1 箇所で足りる — コントロールは自分の状態に合う色グループ
(`active` / `inactive` / `disabled`)を自動で引く。ただし**グループを付けずに代入した色は
全グループへ入り、バインディングとしてグループ側の代入より後に確定して上書きする**(実測)。
状態で変わる役割は 3 グループ全てに書き、変わらない役割だけをグループ無しで書く。
`inactive`(ウィンドウ非アクティブ)は `active` と同じ色にする — 焦点の有無は見せない。

disabled グループの割り当て:

| palette の役割 | token | 効く先 |
|---|---|---|
| `text` | `textMuted` | メニュー項目・入力欄 |
| `windowText` | `textMuted` | チェックボックスのラベル |
| `buttonText` | `textMuted` | ボタン・ツールボタン |
| `brightText` | `textMuted` | 強調ボタンのアイコン |
| `highlightedText` | `textMuted` | 選択面の上の文字 |
| `highlight` | `accentMuted` | 強調ボタンの面 |

`contentItem` を自前で書いたコントロール(`ActionButton` 等)は palette を経由しないので、
同じ規則(`enabled ? textPrimary : textMuted`)を自分で書く。

**選ばれていないことを無効の色で言わない。** 2 択の片方(Tree / Paths の切替など)は、
選ばれていない側こそ**押す先**なので `textMuted` に落とすと嘘になる。色相を保って 1 段
落とす(`accent` × `accentDim`、§暗く落とした段)—— 並ぶのは元色と自分の Dim の 1 組だけなので、
「同じ場所に 2 つ以上の `*Dim` を並べない」にも当たらない。

### git / diff 専用

| token | 値 | 用途 |
|---|---|---|
| `diffAddedFg` | `#4ADE80` | 追加行の文字 |
| `diffAddedBg` | `#052E16` | 追加行の背景 |
| `diffRemovedFg` | `#F87171` | 削除行の文字 |
| `diffRemovedBg` | `#450A0A` | 削除行の背景 |
| `diffHunkHeaderFg` | `#94A3B8` | `@@` 行の文字 |
| `diffHunkHeaderBg` | `#0F172A` | `@@` 行の背景 |
| `statusStaged` | `#16A34A` | staged |
| `statusUnstaged` | `#D97706` | unstaged |
| `statusUntracked` | `#64748B` | untracked |
| `statusConflict` | `#EF4444` | conflict |

変更種別(ファイル行のアイコン)は**種別軸**であって状態の 3 段ではない —
追加 = 緑 / 削除 = 赤 / 移動 = 青 と同じ並びに、変更 = 琥珀が入る。
`statusUnstaged` は値としては `warning` と同じだが**別トークン**で、
QML からは必ず `statusUnstaged` を参照する(`warning` を流用しない)。
値が同じことは意図した重複で、意味の重複ではない。
`statusConflict` と `danger` も同様の関係(conflict は状態でもあるので値が一致する)。

### シンタックスハイライト(P5 実装)

自前のトークン配色は**定義しない**。syntect が読む TextMate テーマ
(`.tmTheme`、MIT 系ライセンスのもの)を P5 で選定して同梱し、
トークン前景色はテーマに委ねる。背景・行ハイライトは本書の `bg` 系・
diff 系トークンを維持する(テーマ側の背景色は使わない)。

### コミットグラフのレーン色

`graphLane` は下記 8 色の配列。レーン番号を要素数で剰余して循環させる。
**Okabe-Ito パレット**(色覚多様性対応の標準的なカテゴリカル配色)を採用し、
黒のみダーク背景で不可視のため明灰 `#DDDDDD` に置換している。

`#56B4E9` / `#E69F00` / `#009E73` / `#CC79A7` / `#F0E442` / `#D55E00` / `#0072B2` / `#DDDDDD`

色覚差への配慮を色選定(Okabe-Ito)と冗長化の両面で行う: レーンの識別を
色だけに依存させない(位置・接続線の形状でも判別できること)。

## タイポグラフィ

段は 5 つのみ。`lineHeight` は 4 の倍数に揃えてある(縦グリッドを崩さないため)。

| token | pixelSize | lineHeight | 用途 |
|---|---|---|---|
| `fontXs` | 11 | 16 | 最小段(予備。通常は使わない) |
| `fontSm` | 12 | 16 | 補助メタ(author / 日時 / ハッシュ / diff 行番号)・バッジ・ペイン/セクション見出し |
| `fontMd` | 14 | 20 | 既定の UI テキスト・一覧 / グラフ行の本文・diff 本文(等幅) |
| `fontLg` | 16 | 24 | 画面を占める状態メッセージの見出し・コミット subject の入力欄・字 1 つで立つボタン(`+`) |
| `fontXl` | 20 | 28 | アプリ名(空の窓 / git ゲート)・ダイアログのタイトル |

- ウェイトは `Font.Normal` と `Font.DemiBold` の 2 つのみ。他は使わない
- **ダイアログのタイトルは `fontXl` で揃える** — 大きさを選ばない。
  タイトルが名詞か文かで段を変えると、同じ殻・同じ padding に載ったものが
  二群に割れ、表を引いてもどちらが正しいか決まらなくなる
- `fontFamilyUi` = `["Yu Gothic UI", "Hiragino Sans", "Noto Sans CJK JP", "Noto Sans JP", "Noto Sans", "DejaVu Sans"]`
- `fontFamilyMono` = `["Cascadia Mono", "Consolas", "Menlo", "Noto Sans Mono CJK JP", "Noto Sans Mono", "DejaVu Sans Mono"]`

**UI 家族は「各 OS が同梱する、日本語を持つファミリ」を名指しする**(2026-08-08 決定)。
QML の font 値型にフォールバック列は書けないため、名指しした家族に無い文字は OS の
**ロケール依存**フォールバックへ落ちる — そこで漢字が中国語字形に化ける(どの Windows にも
JP と CN の両フォントが同梱されており、非 JP ロケールでは CN 側が選ばれ得る)。名指しの
家族自身が和文を持っていれば、そこに**到達しない**。ユーザーデータ(コミット・パス・
ブランチ名)はどのラベルにも現れるので、家族を「UI 用 / データ用」に分けることもしない。

- 解決先: Windows = `Yu Gothic UI`(全エディションの base 同梱。**Meiryo は optional の
  supplemental なので使わない**。欧文は Segoe UI 系 — 14px の文で実測 +1.5%)/
  macOS = `Hiragino Sans` / Ubuntu デスクトップ = `Noto Sans CJK JP`(fonts-noto-cjk)
- `SF Pro Text` / `SF Mono` を書かない — 素の macOS に無く(開発者向け配布・Terminal 同梱のみ)、
  常に空振りする。チェーン全滅時は空文字 = **Qt 既定**へ落ちる(macOS では San Francisco)
- 等幅の主収容物は ASCII(ハッシュ・チップ・コマンド・コード)なので Latin 品質を優先する。
  等幅内の和文はフォールバック容認(JP ロケール機では JP 字形になる。非 JP ロケールでの
  実挙動確認は P5 — Windows の base に JP 等幅は MS Gothic しか無く、diff 全体へは受容不能)。
  Ubuntu だけは `Noto Sans Mono CJK JP` が名指しで和文を持つ

## 余白

4px グリッド。通常のステップは 8、高密度な行の内側のみ 4 を使う。

| token | 値 | 用途 |
|---|---|---|
| `spaceXs` | 4 | 行内の詰め(アイコンとラベルの間など) |
| `spaceSm` | 8 | 既定の要素間 |
| `spaceMd` | 12 | グループ間 |
| `spaceLg` | 16 | ペイン内側の余白 |
| `spaceXl` | 24 | 大区画の分離 |
| `spaceXxl` | 32 | ダイアログ内側の余白 |

**印が自分で持っている余白は、隣の詰めに数える。** 目が測るのは箱の縁ではなくインクで、
`NavIcon` の印は箱と実インクの差だけ既に空いている(`iconLg` の箱に立つ印なら
`(iconLg − 印の段) / 2`、`close` はそこからさらに `spaceXs` 内側に描かれる)。**その分を
引かずにトークンを足すと二重に空く** — 語と印の間だけが、同じ箱の左右の余白より広くなる
(タブの `✕` で実測 13px 対 9px)。**印の隣は spacing を置かず**、箱の側は
`spaceSm − 印が持つ余白` を書く。**印の段を変えたらこの引き算も動く**(タブの `✕` を
`iconMd` → `iconSm` に落とした時、箱の側は `spaceSm − 8` = 0 になった — 0 が正で、
インクはその時ちょうど反対側の語と釣り合う)。

**余りの出る箱を作らない。** 箱を「中身 + 左右の余白」で採るなら、中身に渡す幅も
その 2 つを引いた値にする。合わないぶんはレイアウトが配りきれずに**最後の要素の後ろ**
= 右の余白へ落ち、どこにも書いていない値がそこだけを広げる。

| `laneInset` | 4(=spaceXs) | レーン左端の内側余白(チップ側余白と対称) |
| `nodeIcon` | 20(=iconLg) | コミットノード(identicon)径 |
| `laneStroke` | 2 | レーン線幅 |

| `wheelRows` | 6 | ホイール1ノッチのスクロール行数 |

| `labelColW` | 152 | チップ列の既定幅(仕切りドラッグで可変) |
| `graphDefaultLanes` | 12 | グラフ列の既定レーン数(超過は横スクロール) |
| `messageMinW` | 160 | subject 列に必ず残す幅 = 窓が狭い時にグラフ列を止める側の上限(もう一方は最大レーン数) |
| `detailsAvatar` | 40 | コミット詳細のアバター径 |

| `tailFade` | 0.45 | 読み込み窓の切れ目(footer)でレーンを引き継いで描く不透明度 |

グラフのノードは 3 種。コミットは identicon の円、WIP は点線の空円、**stash は
STASHES セクションと同じアーカイブ箱のアイコンのみ**(輪郭で囲まない — 囲うと
点線が二重になって読みにくい)。stash アイコンは足元のリーシュを避けて描く。

**リーシュのレーンは実履歴と共有しない**。同じコミットへ向かう実エッジがあっても
リーシュのレーンには合流させず、別レーンを開く(合流させるとリーシュの残り全体が
実線になり、stash が実履歴からぶら下がって見える)。リーシュは根元から行き先まで
点線のまま。

**読み込み窓の切れ目は footer が言う**: レーンを `tailFade` の不透明度で 1 行分だけ
走らせ(「まだ続く」が読める最小)、subject の列に読み込み範囲の 1 文を置く。文は
`textSecondary` — 窓はグラフの仕様であって対処の要る状態ではない(§状態)。

**グラフ列は最も広い所のレーンまで**。既定は `graphDefaultLanes` 本ぶんで、仕切りは
**そのリポジトリの最大レーン数ぶんまで**広げられる。最後のレーンより先は必ず空白で、
その幅は subject 列から取り上げたもの — 描くものが無い所に列を割かない。窓が狭くて
**`messageMinW` が subject 列に残らない**時はそちらが先に止める(上限は 2 つのうち
狭い方)。**細い履歴のリポジトリでは列が内容の幅で止まる**ので、仕切りは広げる側へは
動かない。**レーンが 1 本なら幅は 1 通りしかない**。その時は**調整の縦線を出さず、
カーソルの右下に禁止の輪を添える** — 掴める線が出ないことと、それでも手が届いた所で
「ここは動かない」と答えることは対で、無反応は壊れて見える(§長押し と同じ理由)。
**カーソルそのものは差し替えない**。仕切りのカーソル(OS が描く split の形)を
出したまま、**添える輪だけを描く** — 矢印まで自前で描くと、線の太さも縁の付き方も
OS のカーソルと揃わず、隣の列の仕切りと**別の道具**に見える(2026-08-09 に報告)。
**輪は白(`textPrimary`)の細い添え物**で、OS の禁止カーソル(赤い標識)は使わない —
この状態は警告ではなく、その列に伸びしろが無いというだけ。輪は `iconMd` を
`spaceXs` ずらして置く — **カーソルが空けている右下の角に食い込ませる**
(OS の合図付きカーソルはどれもその近さで、離すと「カーソルが着けている物」ではなく
別の印に見える)。
2 本以上あれば線もカーソルも普通の仕切りで、狭める側は常に動いて、溢れたぶんは
横へ送る(§グラフを横へ送る)。**チップ列とグラフ列の幅は `state.toml` に憶える**
(他のペイン幅と同じ 1 組 — §レイアウト初期値)。

## 進行中・長押しの定数

| 定数 | 値 | 用途 |
|---|---|---|
| `spinMs` | 1000 | 通信中インジケータの 1 回転 |
| `holdMs` | 500 | 長押しで確定する操作の押下時間 |
| `holdFillMin` | 4(=spaceXs) | 長押しの塗りの最小可視幅 |
| `holdBackMs` | 150 | 途中で離した時に塗りが 0 へ戻る時間 |
| `opticalDrop` | 1 | 語の隣に置く印を下げる量(下記) |
| `menuMinW` | 160 | メニューの最小幅(長押しの塗りが進捗に読める長さ) |
| `tipDelayMs` | 600 | hover ツールチップの表示遅延。**全箇所この 1 値** — 場所ごとに速い遅いを作ると、同じ所作への返事が席で変わる |
| `hoverKeepMs` | 150 | hover で開いたものを**閉じる前に待つ**時間。開く側(`tipDelayMs`)とは別の値 — 開くのは意図の確認、閉じるのは**手が次の的へ渡り切るのを待つ**ためで、必要な長さが違う。`Qt.callLater` では足りない(2026-08-09 実測): 線からその線が開いたカードへ歩く時、2 つの hover は**別のフレームで**変わり、callLater はその間に走ってカードを閉じる。値は同種の実装の帯の中(照合 2026-08-09: Qt Quick Controls のサブメニュー開き 225ms / KDE Plasma のツールチップ閉じ猶予 200ms / Qt Creator 300ms — 後 2 者はどちらも「カードへの Enter が閉じを取り消す」= この対と同じ機構。**Qt 純正 `ToolTip` は自分への hover を明示的に切っている**(`setHoverEnabled(false)`、QTBUG-63644)ので、hover できるカードを Popup で自作するのは KDE / Qt Creator と同じ結論) |

- git が**ネットワークに出ている間**は、そのボタンを**押せない見た目へ落として中央で
  リングを回す** — 言葉は消える。進捗率は出さない
  (git の進捗は人間向け出力で、機械可読形式のみをパースする規約に反する)
- **リングと枠は、そのボタンが待つ前に着ていた色の 1 段下**(§暗く落とした段)。
  灰色に均さない — 通信中でも「これは失敗が続いている fetch」「これは相手の履歴を
  上書きする push」であることは変わらず、待っている間だけ灰色になると、**帰ってきた
  瞬間に色が戻る**。色相を保って暗くすれば「何であるか」は据え置きで「今は触れない」
  だけが乗る。**枠を持たないボタンだけは `borderDefault` を借りて枠を出す** —
  言葉が消えた後、待ちが始まったことを言うものが他に無い
- **`enabled` は落とさない。** 落とすとフォーカスが外れる — 押し切った直後に通信が
  始まる force push では、キーボードで長押しした人のフォーカスが成功した瞬間に飛ぶ。
  暗くして押下を無視すれば見た目も所作も無効と同じになる
- 回転は `RotationAnimator`(レンダースレッド)で行う。GUI スレッドがモデルの drain で
  詰まっても止まらない
- **自動化中(`PG_SHOT_DIR` 指定時)は静止させる**。回っているものを撮ると
  スクリーンショットが毎回違う画像になる
- **回るリングと長押しの印は同じボタンの上で入れ替わり、同時には出ない** — 押し切って
  から通信が始まるので、丸が 2 つの意味を同時に持つ瞬間が無い
- **ボタンでない席では、言葉を消さずリングを語の隣に置く**(`CONFLICTS` 見出しの右で
  外部ツールの終了を待つ間 = `Waiting for <tool>`)。押下を無効化する相手が居ないので
  「暗くして押せない見た目へ落とす」は当たらず、**どのツールを待っているかは言葉でしか
  言えない**ので言葉も残す。色は隣のラベルと同じ `textSecondary` — 待ちは失敗ではない
  ので、見出しの `danger` もその 1 段下も取らない
- **待ちに `…` を付けない。** 進行中を言うのはリングの仕事で、`…` はメニュー行の
  「質問が立つ」(§長押し の語彙)専用に取っておく。**点が増えていくアニメーションも
  採らない** — 同じ意味に語彙が 2 つ増えるうえ、テキスト変更は GUI スレッドで動くので
  **リングがレンダースレッドに置かれている理由(詰まっても止まらない)を捨てることになる**。
  幅が毎秒変わって行が組み直される問題も付く

長押しは**押している間ずっと意思が要る**ことを使う確定手段。惰性のクリックでは起きない。
`holdMs` の間押し続けると発火し、途中で離せば何も起きない。
**押したまま枠の外へ出ても取り下げ**(離すのと同じ)— 押してから気が変わった時の
逃げ道は 2 つある。

`holdMs` に求めるのは **「誤クリック 1 発では実行されない」だけ**。押している間の
意思の継続を測る道具ではないので、長くすれば安全になるものでもない — 毎回払う
コストだけが増える。普段のクリックの押下時間は 100ms 前後なので、その 5 倍を
またぐ **500** で目的は足りる(Android の long press timeout と GTK の
`gtk-long-press-time` も同じ 500 = 「これはタップではない」の線)。

Qt の `mousePressAndHoldInterval` 既定は 800 だが、あれは**クリックと長押しを
見分ける**ための閾値。長押しボタンはクリックを一切報告しない(下記)ので
見分ける相手がおらず、この 800 はここには当たらない。

見た目は 3 つで 1 組:

1. **印**(`HoldIcon`)— 語の**手前**に置く輪。静止時は 12 時へ半径が 1 本立った
   「0 のゲージ」で、押している間その扇形が時計回りに満ちる。NavIcon と同じ 16 グリッドで、
   **線幅は `iconStroke` をグリッド比で縮める**(印は `iconSm` の席に立つ —
   絶対値のままでは小さな輪に太い線が乗る。座標だけ縮めて線を縮めない NavIcon とは
   ここだけ意図して違う)。
   色は隣の語と同じ(塗りの上では語と一緒に `textOnAccent` へ上がる)。
   **これが「長押しである」を言う唯一の場所**で、語は操作だけを名乗る
2. **枠**とその枠を**左から満たす塗り**。枠と塗りは同じ警告色で、
   「枠が満ちきったら実行される」ことがそのまま進捗になる
3. **手を離した時の戻り** — 途中で離すと塗りと扇形が `holdBackMs` かけて 0 へ戻る

塗りは**幅 0 から始めず `holdFillMin` を下限にする**。比例のままだと最初の 1 割が
1px 未満の帯になり、押したのに始まっていないように見えて、体感の長押し時間が
実測より伸びる。**印の扇形には下限を置かない** — 隣で塗りが `holdFillMin` から
立ち上がるので、最初の数フレームを印が 1 人で背負う場面が無い。
**フォーカスリングは枠の外側**に描く — 枠の色は「何を失うか」を
言っている最中なので、フォーカスがそれを塗り替えてはならない。

**途中で離した press には必ず返事をする。** 長押しボタンはクリックを一切報告しないので、
返事が無いと**押した人には壊れて見える**。押し切った時は戻さず 0 へ落とす — 既に
実行されていて、言うことは残っていない。

**印は行の中心から `opticalDrop` だけ下げる。** 幾何的な中央に置くと語より上に見える —
理由は 2 つ重なっていて、(1) `Delete` のようなディセンダの無い語はインクがベースラインで
止まり、その下のディセンダ用の余白が空いたままなので**インクの重心が行の中心より下**に来る、
(2) 静止時の印は 12 時に立つ針の分だけ**上に重い**。合計で 1px 強なので 1px 戻す。
code チップのある行が「ずれていないように見える」のは錯覚ではなく、目がグリフではなく
**チップの地(行に対して幾何的に中央の四角)**と比べるため — 比べる相手が違うだけで、
グリフに対しては同じだけずれている。

長押しを使ってよい条件:

- **幅は普段の文言を基準に固定**し、状態が変わってもツールバーの並びを動かさない —
  狙っていたボタンが押す瞬間に別の位置へ移るのは事故のもと。
  文言は**その箱に収まる短さ**にする(`push -f`)。字を縮めたりアイコンを外したりして
  長い語を押し込まない — 長押しであることは印が言い、失うものは hover の
  ツールチップに書けば足りる。**印はそのボタンのアイコンの席に入るが、アイコンを
  追い出さない** — 2 つを**分数の形**に組む(どちらも 1 段小さく `iconSm`、間に `/`、
  それぞれ中心線から上下へずらす)。追い出すと、`push -f` が押上げの矢印を失って
  「何をするボタンか」を一目で言えなくなる。席の幅は素のアイコンと合成の広い方で
  固定し、状態で動かさない
- **メニュー行の印は語の手前に単独で立つ**(合成する相手のアイコンが無い)
- **通常操作と同じボタンに同居させない**。同じ状態でクリックとも長押しとも解釈される
  ボタンを作らない(押しっぱなしで別の操作に化けるのは事故)。
  長押しボタンは**クリックを一切報告しない** — 途中で手放した時も、押し切った時も、
  そのボタンの「通常の操作」へ落ちてはならない
- **印は行ではなく「その時そこで失うもの」に付く**。同じ行が状態で長押しにも
  クリックにもなってよい(`--skip` = §進行中の操作から出る / drop =
  §履歴を合流させる)。**ただし答えは行が現れる前に手元にあること** — 出てから
  印が付くと、席(`AppMenu.holdColW`)が全行を字下げし直して的が動く
- **失うものをその場に出す**。何が起きるか 1 行で言えない操作は長押しに降ろさない。
  **文字を持てない的は長押しにしない** — diff の行頭に出していた `×`(1 行だけ捨てる)を
  やめて hunk 単位に揃えたのはこれが理由で、素のアイコンには「何を失うか」を書く場所が無い。
  ステージは失うものが無いので**行単位のまま**残る(同じ場所の `+` は長押しではない)
- **文言は操作だけを名乗り、所作は印が言う。** `Hold to <動詞>` も `<動詞> — hold` も
  置かない — 前者は右クリックメニューに並ぶ破壊的な行が**全部同じ 2 語で始まって**
  見分けが付かなくなり(メニューは先頭の語で読む)、後者は 1 行に 1 つしかない
  「失うもの」の席を所作が食う。行は `Discard` / `Delete` /
  `Discard everything after it` と名乗り、動詞だけでは足りない時に警告タグ
  (`AppMenuItem.note`)を後ろへ足す(`not merged` / `both sides`)。
  **`…` との差が語彙になる** — 無印 = 即実行 / `…` = 質問が立つ / 印 = 押し切る
- **メニューでは印の席を全行が空ける**(`AppMenu.holdColW`)。1 行でも長押しがあれば
  その menu の全行が同じだけ字下げされ、**語の先頭は揃ったまま**になる。
  長押しの無いメニューは席を持たない。**席は印より狭く(`iconMd - 2 * spaceXs`)、
  印は両端からはみ出す** — 左は行のパディングへ、右は語との隙間へ。コードチップの地と
  同じ作法で、印はカードの端に寄り、語が払う字下げは印 1 個分より小さくなる
- **枠を持てる場所にだけ枠を出す。** ツールバーのボタンは枠 + 枠を満たす塗り、
  メニューの行と**他の語が並ぶ見出しの中のボタン**(diff の `Discard hunk`)は枠なしで
  地を端から端まで塗る(`ActionButton.holdTone`)。並んだ語の 1 つだけを囲む枠は
  外れた箱に見える
- **押している間メニューは開いたまま**(押下をメニュー行の手前で受け取る。行の
  `triggered` が飛ぶとメニューはその場で閉じ、長押しが成立しない)
- **語から所作が消えた分は `Accessible.description`(`Hold to activate`)が引き受ける。**
  印は見える人にしか届かず、代わりになるものが他に無い
- **代替は「フォーカス → Space または Enter を長押し」の 1 つに統一する。**
  場面ごとにメニューやダイアログの抜け道を用意しない — 抜け道が場面ごとに違うと、
  ポインタを使わない人は毎回それを探すことになる。長押しを持つものは
  **タブ順に入れる**(持たないものは入れない)。質問バーのピルは**開いた時点で
  フォーカスを受け取る**ので、タブで探す必要すらない
- **キーの自動リピートは押下・解放の両方で捨てる。** 押しっぱなしのキーは全ての
  プラットフォームで press を繰り返し、一部では release も繰り返す。どちらの縁でも
  塗りが 0 から張り直され、**押し続けている限り永久に完走しない**

## レイアウト初期値(P1 基準)

| 値 | 用途 |
|---|---|
| 1440×900 | 初期ウィンドウ |
| 640 | ダイアログの幅と git ゲートの文面幅(いずれも上限 — 狭い窓では窓幅 − `spaceXxl` × 2) |
| 260(min 180) | サイドバー幅 |
| min 420 | 中央(グラフ/diff)最小幅 |
| 400(min 300) | 右ペイン幅 |
| 180(min 3 文字 + `…`) | タブタイトルの幅。**下限だけ px ではなく字数**(§ウィンドウの縁) |
| 160 | 幅を固定する入力欄(検索ボックス・設定の数値入力・質問バーの行き先と名前) |
| 240 | ツールバーのボタン文言の最大幅(超過は省略) |
| 120 | Description 枠の最大高 |
| 42 | diff 行番号列幅(片側) |
| 280(min 120) | コマンドログの高さ |
| min 200 | コマンドログを開いた時の三ペインの最小高 |

- **タブタイトルの下限は表に px を持たない。** 「頭 3 文字 + `…` が出る所」= フォントの
  平均文字送り × 3 + 省略記号の幅を実行時に引く。**3 は寸法ではなく字数**なので、
  3 OS で UI フォントが違っても・拡大率が変わっても同じ意味のまま効く(px で書くと
  どちらかで 1 文字も出ない)。**実測値は環境ごとに違うのが正**(Windows / Segoe UI /
  `fontMd` で 56px = タブ 84px)
- **入力欄は原則、置かれた場所いっぱいに広げる**(ダイアログ内は `fillWidth`)。
  幅を固定するのは中身の長さが決まっているものだけで、その値は上表の 1 つを共有する。
  **中身に合わせて細くしない** — 数字 2 桁・ハッシュ 7 桁と欄ごとに詰めていくと、
  画面ごとに違う幅が増えるだけで、読みやすさは変わらない

## ウィンドウの縁(chrome)

**タブ行が OS のタイトルバーを兼ねる。** chrome は `toolbarHeight` 40 + 仕切り
`splitterWidth` 4 の 44px で、その上に別の帯を積まない。消えるのは「アクティブな
タブが既に名乗っているリポジトリ名を、もう一度 1 行使って書いている帯」なので、
情報は 1 つも減らない。

- **窓ボタンはアプリが描く。** OS に描かせると**高さも hover もアイコンも指定できない** —
  実測で 32px 固定・40px の帯の中で 4px ずれ、hover は OS の色、最大化しても
  最大化アイコンのまま(復元アイコンに変わらない)。Chrome も同じ結論で自前に
  している
- **帯の両端は同じ組み方**: 左の ☰ も右の 3 つも `railWidth` × 帯の全高のセル。
  ☰ は畳んだ左メニューと同じ縦線にアイコンが乗る。**印は ☰ が `iconLg`・窓ボタンが
  `iconMd`** — 窓ボタンの印はアプリの印より小さいのが世の作法で、揃えると帯の中で
  いちばん目立つ
- **hover は他のボタンと同じ `bgHover`。✕ だけ `danger`**(印は `textOnAccent` へ
  反転)。赤い閉じるボタンは、外すと house style ではなく不具合に読まれる作法
- **並びは `>_` / fetch / push → 区切り 1 本 → 窓ボタン**。区切りは `borderDefault` の
  `borderWidth` × `iconMd`(帯の端までは伸ばさない — 下の仕切りと二重に見える)。
  間隔は**押せる箱どうしで揃える**(実測 8px と 7px)
- **右端はクライアント領域の端ではない。** そこに密着させると窓ボタンの数 px が
  画面外へ出る(実測 4.5px)ので `spaceXs` を空ける
- **帯を掴む所作はアプリが持つ**: 空きのドラッグで移動・ダブルクリックで最大化
  (保存する窓の形と同じ経路)・右クリックで OS の窓メニュー。**掴める空きは
  `railWidth` × 2 を必ず残す** — タブが伸びて消える空きは、掴もうと思える場所ではない
- **タブは溢れる前にその空きの手前で止まり、そこから縮む。縮みきったら横スクロールする**
  — 縮むのは**長い名前から**で、既に短い名前のタブは最後まで動かない。溢れた分を
  等分すると、`ui` のタブまで巻き添えで細くなり、削れる余地が無いものから幅を取り上げる
  ことになる。**譲る側は同じ幅で揃う**(残りを配り直した結果がその 1 つの値なので、
  揃うのは意匠ではなく計算の帰結)。**下限はタブタイトルの表の値**で、そこから先は
  もう名前を名乗れないので幅ではなくスクロールで捌く
- **最大化した窓のフレームは画面より大きいが、内側は寄せない。** 実測(2026-08-09):
  作業領域 1920×1032 に対してフレームは 1936×1048(四方 8px はみ出す)が、
  **クライアント領域は 0,0..1920,1032 = 作業領域そのまま**。はみ出す 8px は
  OS の不可視リサイズ縁 = 非クライアントなので、**アプリが描く画素は最大化中も
  画面の外に出ない**。帯も窓ボタンもクライアント領域の端まで使う — 寄せると
  「中身が左へ 8px ズレて右が足りない」形になる
- **最大化中は窓の縁(枠線と、その内側の帯)を描かない。** 縁が塗っているのは
  その不可視リサイズ縁なので、最大化するとアプリの色の帯が**隣のモニタに**現れる
  (実測 2026-08-09: 両端 8px が `bgElevated`)。最大化した窓の縁は画面の縁 =
  描いても誰にも見えないので、描かないことで失うものは無い
- **兼ねるかはプラットフォームを名指しで決める。** 窓の生成時に読まれる設定なので
  「効いたか見てから決める」ができず、閉じるボタンの無い窓は取り返しがつかない。
  兼ねない側は OS のタイトルバー + 2 段に落ちる(= このアプリが元々持っていた形)

## QML 実装ルール

- 全ての値は `Theme`(QML singleton)経由で参照する。QML に数値・色・フォント名のリテラルを直書きしない
- ペインの先頭は `headerHeight` の帯(ヘッダ・フィルタ入力)とし、内容はその**直下**から始める。
  ヘッダを持たないグラフは `headerHeight − graphRowHeight` の上余白を置き、最上部で 1 行目の
  **下端**を隣接ペインの帯の下端に揃える。最上行の hover / 選択ハイライトとヒット領域は
  この上余白ごと塗り広げる(帯と同厚の一続きのハイライトにし、上に地の隙間を残さない)
- 例外は**枠付きカードで始まるペイン内容**(コミットメッセージ枠 = COMMIT 詳細 / WIP 編集):
  カード自身が枠を持つため帯に接すると 2 本の境界線が癒着して見える。上下は帯との間に
  `spaceXs` を置く — **カード内の行間と同じ値**にして、帯 → 各枠 → 帯を一定の刻みで並べる
  (上下だけ `spaceSm` にすると内側 4px / 外側 8px でリズムが崩れる)。左右は `spaceSm` =
  ペインの内寸で、カードの縁が帯のラベルの開始位置に揃う。一覧・グラフのように枠を持たない
  内容は上記どおり直下から始める
- グラフの末尾には `spaceSm` の下余白を置く。最下行がペイン下端に接すると「読み込みの終わり」
  ではなく「見切れ」に見えるため、レーンが縁に届く前に途切れるようにする。**空行に見える量は
  取らない** — 途切れが分かる最小限に留める
- サイドバーの各セクションの末尾は `borderWidth` の地の隙間で閉じる。次のセクション見出しの
  帯と最終行を分けるだけの役目なので、境界線と同じ太さで足りる。`spaceXs` 以上を取ると
  セクションに属する空行に見え、セクションが 5 つ縦に並ぶ分だけ隙間が目立つ
- サイドバーのセクションは**上から詰めて並べ、余った高さは最後のセクションの下に地として残す**。
  どのセクションにも自分の行数を超える高さを持たせない — 閉じたセクションは見出し 1 行なので、
  上のセクションが余りを抱えると**その見出しだけがペインの最下段へ送られる**(「閉じた時だけ
  下に張り付く」)。高さが足りない時は、行が入り切らないセクション同士で等分し、行数の少ない
  セクションは丸ごと出したままにする
- **当たり判定は塗りより大きくてよい。ただし帯や窓の端に接するものだけ**。端に密着した
  セルは、ポインタを振り切れば当たる的になる(最大化した窓では画面の端 = 無限の的)。
  塗りまで端まで広げると、隣り合う別種のもの(タブとアプリメニュー)が同じ絵になるので、
  **広げるのは判定だけ**にする。端に接しないものは判定と塗りを一致させる
- `font.pointSize` 禁止 → `font.pixelSize`。pointSize は OS ごとの logicalDpi 基準差で実寸がずれる
- `font.family` には `Theme.uiFamily` / `Theme.monoFamily` 以外を書かない。QML の font 値型に
  `families`(配列)は**無い**ので、§タイポグラフィのチェーンは Theme が `Qt.fontFamilies()` と
  照合して 1 家族に解決する(空文字 = Qt 既定)。どちらも post-write hook が機械検査する
- **折り返す・複数行になるテキスト**は行高を `lineHeightMode: Text.FixedHeight` + `lineHeight` トークンで固定する(1 行のラベルは行側の高さトークンが余白を決めるので指定しない)
- `ListView` / `TableView` の delegate 高さは行高トークンの定数(一覧 = `Theme.rowHeight`、コミットグラフ = `Theme.graphRowHeight`)。可変高にしない(10 万行での性能予算に直撃する)
- スクロールは端で**ハードに止める**(`boundsBehavior: Flickable.StopAtBounds`)。行き過ぎてから戻るラバーバンドは指で慣性を投げるタッチ操作向けの「端に着いた」合図であり、1 ノッチ単位で動くホイール主体のデスクトップでは「まだ先がある」の誤読を生むだけ。`ListView` / `Flickable` は直接指定し、内部の Flickable を隠す `ScrollView` は `Component.onCompleted` で設定する
- `Qt.lighter()` / `Qt.darker()` / `Qt.rgba()` で中間色を作らない。ホバー・押下は `bgHover` / `bgPressed` の重ね色で表現する
- アニメーション時間は 120ms(短)と 200ms(標準)の 2 値のみ
- ドロップシャドウ・ブラーを使わない。階層は背景色と境界線で表す(描画コスト回避を兼ねる)
- **1 つの印は 1 つの意味しか持たない。** 山形は数で分ける — **1 つ(`chevron`)= 一覧が開く**
  (ドロップダウン。見出しの `▾` と同じ「開くと中身が出る」の系列)/ **2 つ(`chevrons`)=
  ペインの端を動かす**(左メニューを畳む / 戻す)。**`»` をドロップダウンに使わない** —
  慣習でも畳み・端送りの記号で、同じ窓の中で意味が割れる
- **印は描く。文字のグリフを流用しない。** 3 OS でフォントの持ち物が違ううえ、グリフは
  ベースラインに乗るので同じ席に置いた描画の印と高さも太さも揃わない。**入れ替わる席なら
  なおさら**(ドロップダウンの山は読み込み中に回るリングと同じ 16 グリッドの席を共有する)

## メニュー(右クリック・アプリメニュー)

**メニューはダイアログと同じ「浮いた面」として描く** — `bgElevated` の地に
`borderDefault` の枠、角は `radiusMd`。地だけで浮かせない: ペイン(`bgSurface`)と
`bgElevated` の差は小さく、グラフの上に開いたメニューは枠が無いと縁が読めない。

**置くのは、そこにしか入口が無いものだけ。** 所作(ダブルクリック・2 回目の
クリック)で届くものも、画面に常設のボタンがあるものも重ねない — メニューは
開くまで中身が見えない導線なので、行が増えるほど**そこにしか無い 1 行**が
探しにくくなる。行を選べば右のペインがその行の全てを出す(ハッシュの
`Copy full hash`・stash の `Apply` / `Pop`)ので、**右クリックはそこに無いもの
= 削除に取っておく**。

- 行の文字は `fontMd`(グラフのコミット subject・メッセージ本文と同じ段)、
  行高は一覧と同じ `rowHeight`。メニューだけ大きく見せない
- **幅は最も広い行に合わせる**。上限はウィンドウ幅 − `spaceXxl` × 2 で、
  そこへ届いた行だけ末尾を省略し、hover でツールチップに全文を出す
- **文言は幅と無関係に §用語 の基準だけで選ぶ** — 収まらないから削るのも、
  収まるから伸ばすのもしない。行が自分で示しているもの(右クリックした行の
  コミット)は文言で言い直さない
- **言い直さない結果、行がコマンドだけで終わることがある**(`cherry-pick` / `revert` /
  `drop`)。メニューはクリックした行に括り付いていて全行がそれに効くので、
  `this commit` は**どの行でも同じことを言う = 行を選ぶ材料にならない**。文に残すのは
  **人が指していないもの**だけ — 相手のブランチ(`merge` into main)、向きが要る時の
  両端(`rebase` main onto it)、行き先(`squash` into parent)。実測: コミット行の
  メニューで 425px → 357px
- **同じ規則を右クリックのメニュー全部に通す** — ref 行は `Switch` / `merge` into
  \<current\> / `rebase` \<current\> onto it / `Delete…`、ファイル行は `stash` /
  `Discard` / `Copy path`。**入口が違っても同じ操作は同じ文**になる(§履歴を合流
  させる)。**件数だけはタグへ逃がす**(`3 files`)— 文に入れると 1 件と複数で行の
  形が変わり、隣の行と読み比べられなくなる
- **右クリックのメニューには選べない行を置かない**(灰色にするのではなく消す)。
  メニューは右クリックしたものに合わせて組み立てる導線で、開くまで中身が見えない
  — 押せない行を並べても、探している**そこにしか無い 1 行**を隠すだけになる。
  **アプリメニュー(ハンバーガー)は逆に、行を減らさず無効にする**: こちらは固定の
  一覧で、並びそのものが「このアプリに何ができるか」を教えるので、未実装の行
  (`Clone repository…`)も席を保つ。無効行の見せ方は §無効
- **出す行が 1 つも無いメニューは開かない。** 空のカードは答えではない。当たるのは
  現在のブランチの行(できることが 1 つも無い)と、書き込みが走っている間で、
  そこで何も出ないのはフォルダ行・WORKTREES 行と同じ形(§左メニューの所作)
- **中身は開いた瞬間に決め、開いている間は動かさない。** 条件は生きている
  (タイマの fetch だけでも「書き込み中」になり、背景の refresh も同じ)ので、
  放っておくとポインタの下で行が出入りする = 押すつもりの無かった行を押す
- カードの内側余白は `spaceXs` — 角の丸みが選択行の帯に食い込まない最小値
- 区切りは `borderSubtle` の 1px 線、上下に `spaceXs`。**区切りは自分で出入りを
  決める**: すぐ上の group に行が残っていて、かつ下にまだ行がある時だけ引く。
  これで端に残る線も、行が消えた group を挟んだ二重線も出ない

## 可否・警告の出し場所

**ポップアップでなければ成立しない UI でない限り、可否の警告・確認は操作している場所の近くに出す。**
ウィンドウを覆うダイアログは、判断の材料そのもの(編集中のテキスト・対象の行)を隠し、
視線を操作から引き剥がす。「近く」とは**その操作の対象が見えている枠の中**を指す。

- **表示の切り替えで足りるならダイアログを出さない**。編集中のテキストについての質問なら
  編集枠の中で聞く(保存行を質問に差し替える — `DetailsPane.asking`)。理由を伝えるだけで
  足りるものは、その場の 1 行(警告色)か hover のツールチップで済ませる
- **確認は画面側にしか無い。** core は discard / clean / `stash drop` / `branch -D` /
  リモートブランチの削除を、頼まれたとおりそのまま実行する(尋ねる仕組みを持たない)。
  聞くかどうかは全部ここの決定で決まる
- **確認を出すのは取り返しがつかないものだけ。** 日常操作(stage / commit / switch /
  fetch / 通常 push)は一切尋ねない — 毎回出る確認は「読まずに押すもの」になり、
  本当に危ない場面での効き目まで削る。何を失うかは操作ごとに違うので、
  **文言は操作側が渡す**

### 立っている質問は 1 か所で聞く(質問バー)

**立っている質問は、対象の行が並ぶ一覧の上端から降りてくるバーで聞く。** 見出し(`fontMd` の
DemiBold・状態色)+ 失うものの 1 行(`fontSm` の `textSecondary`)+ 同意のピル
(状態色の枠)+ `✕`。地は `bgElevated`、下端に状態色の 1px 線。開閉は 200ms。

- **一覧はバーの分だけ下へずらす**(覆わない)。判断の材料は対象の行そのものなので、
  質問がそれを隠しては意味が無い
- **バーが立つのはグラフだけ**(ref についての質問 = Move here / リモートの改名)。
  **1 つの名指しできるものを捨てる**操作 — ファイルの変更・hunk・stash・タグ・
  リモートブランチ・`reset --hard` — はバーを降ろさず、**手が既に居る場所**
  (右クリックで開いたメニューの行、その hunk 自身の見出しのボタン)を長押しする。
  ウィンドウの端から機構を降ろすのは、対象が「行 1 つ」で済まない時だけ
- **対象の行には印を付ける**(行の左端に `laneStroke` の縦線 + `bgHover` の地)。
  **言葉はバーに 1 度だけ**書き、行は「どの行の話か」だけ答える
- 同意はピルだけ。**Escape・`✕`・他の場所のクリックで取り下げ**、答えるまで何も起きない
- **取り返しがつかない質問はピルを長押しにする**(§進行中・長押しの定数)。
  残っているのは Move here とリモートの改名の 2 つで、ピルは動詞だけを名乗り
  (`Move` / `Rename`)、押し方は語の手前の印が言う — メニューの行と同じ 1 形
- **クリックのピルは `clicked` で受けない。** Qt は press-and-hold のタイマ
  (800ms)が鳴った後の `clicked` を出さないので、長押しを教わった人が
  押し続けると**無反応**になる。「ピルの中で離した」で受ける
- **同じ問いは常にここで聞く。** 以前はグラフ行のチップ列を質問ストリップに
  差し替えていたが、チップ列は `labelColW` しか無く、短くした文言でも切れて読めない。
  出し先が場面ごとに変わると「出た時に何を意味するのか」も読めなくなる
- 行がウィンドウ外でも成立する(印が付かないだけ)ので、**ダイアログの代役は要らない**。
  ポインタを使わない人向けの代役も要らない — ピルは開いた時点でフォーカスを持ち、
  Space / Enter で答えられる(§進行中・長押しの定数)
- 質問を出している間は、**まだ何も起きていないことを画面でも示す**(選択・ハイライトを動かさない)。
  答えて初めて動く
- ポップアップを使ってよいのは、**ウィンドウ横断で置き場所が無いもの**
  (identity の入力・設定・リモートの登録・**開けなかったフォルダの報せ**)だけ。
  **質問を出すためには使わない** —
  「答えるまで先へ進ませない」形はどこにも要らなかった(未コミット変更を
  抱えた移動が最後の 1 つで、尋ねるのをやめて消えた)。
  **汎用の確認ダイアログは持たない** — 質問はどれも、その質問が指すリストの上に立つ
- **開けなかったフォルダだけは例外側**(§リポジトリを開く)。これは画面に出ている
  ものについての質問ではなく、**バーが立つ相手がそもそも無い** — そのフォルダは
  タブにならず、来た道のピッカーは既に閉じている。求めているのは同意ではなく、
  「開けなかった」と「もう一度選べる」の 2 つを渡すこと
  取り返しがつかない操作でも、**その場で意思を示せる形(長押し)があるならそちらを採る**
  — force push はボタンの長押しで取る(§相手の履歴を置き換える)
- **長押しはもう 1 つ、「アプリが勝手に止めたものを動かし直す」時にも使う**
  (auto fetch の再開 = §リモートから取り込む)。失うものは無いが、止まったのは
  アプリの判断であって利用者の意思ではないので、**戻すのは利用者の意思でなければ
  ならない** — クリック 1 発で戻せると、なぜ止まっていたのかを読まないまま
  同じ状態へ戻る。長押しはここでは「壊れるから確かめる」ではなく
  「読んだ上で戻すと言え」を取っている
- 出し場所を変えても**文言は同じ基準**で選ぶ(下記の用語表)

### git が言ったことを読む場所(コマンドログ)

**発行した生 git コマンドは下部パネルに出す。既定は非表示、ツールバーの `>_` で開く。**
別ウィンドウにしない — ログの値打ちは「今押したものが何を走らせたか」の対応にあり、
別ウィンドウはそれを壊す。ログはタブごとなので、入口もタブごとの状態が並ぶ
ツールバー右側に置く(ウィンドウの持ち物である下端の縁ではない)。

- **失敗すると自分で開き、閉じるまで開いたままにする**。次の成功で閉じない —
  読む前に消える。開くのは**利用者が頼んだ操作**の失敗と、**連続する fetch 失敗の
  1 回目だけ**。ポーリングの失敗では開かず、2 回目以降の fetch 失敗でも開かない
  (同じ知らせで、オフラインのマシンでは毎分飛び出す。§リモートから取り込む)
- **開く判断は「操作」の答えで下し、コマンド 1 本の終了コードでは下さない。**
  1 つの操作が複数の git を撃つ時(移動の stash → switch → pop)、途中の非ゼロは
  操作の失敗ではない — **着地して初めて失敗かどうかが決まる**。コマンド側は
  `answers_by_code()` で自分から開かないようにし、開けるのは書き込みの答えだけ
  (`RepoPage.absorbWriteResult`)。**同じ終了コードが場面で意味を変えるもの**
  (`stash pop` の exit 1 = 「conflict して着地した」と「何もしなかった」)は
  この形でしか正しく出せない
- **その失敗を質問に化けさせた時は開かない**(`branch -d` の拒否 → `Delete <branch>
  anyway?`)。バーが既に何が起きたかを言っているので、ログは同じ話を二度し、
  そのうえグラフを押し上げる。行は記録されているので、読みたければ `>_` で開く
- `>_` は直近の状態も兼ねる: 通常 `textMuted` / 実行中 `accent` /
  直近が失敗 `danger` + 枠 / 開いている間 `bgSelected`
- **exit 0 は書かない**。常に 0 なら情報量が無く、失敗だけが目立つべき
- **終了コードで答える問い合わせは失敗として扱わない**(`merge-base --is-ancestor`
  の exit 1 は「いいえ」)。行は残すが**コードは書かない**(exit 0 と同じ — 答えは
  情報量が無く、失敗だけが目立つべき)。**ログも自分から開かない** — 答えを
  受け取っただけで下部パネルが飛び出すのは、質問に化けた失敗と同じ理由で邪魔。
  `GitCommand::answers_by_code()` で印を付ける
- git の出力は**加工せず**そのまま出す。失敗行の下に展開し、行の左端に `danger` の帯を引く(失敗 = §状態)
- **帯に出す 1 行は 1 行に収める**(`maximumLineCount: 1`)。git の文言は複数行で、
  省略(`elide`)は最後の 1 行を詰めるだけなので、上限を置かないと帯が伸びて
  **下の行の上に文字が重なる**(実測)
- 入力欄(任意コマンドを打てる端末)は作らない — スコープ外(要望.md)

## 用語(UI 文言)

### アプリ名

**UI に出すアプリ名は `Platitude GG`。** 窓のタイトル・空ウィンドウの見出し・
git 不在時の見出し・**もう 1 つ開いていた時の見出し**・`About` 行・文中で自分を
指す時(identity / settings の説明文)は全てこの綴り。コード表記(等幅チップ)は
着せない — コマンドではないため。

**もう 1 つ開いていた時は、その窓が言うのは 1 文だけ**(`Platitude GG is already
open. Its window is the one to use.` §長さ)。下に**設定の置き場所**を 1 行
(`fontSm` の `textSecondary`・等幅)— 開発ビルドと本物は画面上で他に見分けが
付かないので、**どちらが塞いでいるか**を言えるのはこの行だけ。出口は `Close`
の 1 個(アクセントは着せない)。

`platitude-gg` はリポジトリ名 = **機械が読む綴り**で、crate / バイナリ /
設定ディレクトリ名(`settings::DIR_NAME`)に加えて **Qt の `application_name`
もこちら**。あれは表示ではなく識別子で(このアプリで Qt 自身が文言を持つ窓は
1 つも無い)、読むのは `QStandardPaths` の連結先と X11 の WM_CLASS の class 名
= どちらも綴りをそのまま使う。**表示名を機械が読む場所へ入れない** — 得るものが
無く、`.desktop` との照合を落とす。

**内部で実行する git コマンドと、UI に出す語は意図的に分ける。**
内部は最新 git の適切なコマンドを選ぶ(`switch` / `restore` 等)。
UI 文言はコマンド名に引きずられず、その操作が**何をするか**を最も適切に表す語を選ぶ。

理由: 「単なる git ラッパー」は*挙動*の話であって、*語彙*まで git に合わせる意味はない。
`checkout` はレジ・ホテルの連想が先に立ち、git 内部でも「ブランチ移動」と
「ファイル復元」の二役を持つ多義語。git 自身が 2.23 で `switch` / `restore` に
分割したのは、まさにこの多義性を解消するため。

### git 用語のコード表記

**右クリックメニューの行では、git 用語のまま採った語(Stash / Cherry-pick)を
コマンドの綴りのまま出す** — 小文字・等幅(fontFamilyMono)・淡い地
(bgHover、radiusSm)のチップ(`AppMenuItem.code`)。語頭を大文字にしない —
大文字始まりは文の語彙の身なりで、コマンド名にそれを着せると英語として
読むのか綴りとして読むのかが揺れる。チップの語は翻訳しない(語っているのは
コマンドそのもの)。文の残り("into main")は通常表記・翻訳対象のまま。

**チップの中の語間は詰める**(`wordSpacing` を spaceXs 分)。等幅の空白はチップが
自分の両端に持つ空気よりずっと広く、そのままだと `push -f` の `-f` が `push` から
離れて**1 つの地の上に 2 語**に見える。コマンドとフラグは 1 つの言い分なので、
間の空きは端の空きと同じ程度に収める。

チップの地は語の左右へ spaceXs だけ張り出すが、**張り出しは余白の側に
食い込ませ、語そのものを動かさない** — 語頭は他の行の語頭と揃い、続く語までの
距離も通常の語間のまま(語間の半分が地、半分が空白)。枠のために文字を退かせない。

**フラグのダッシュは font に任せず spaceXs の罫で引く**(太さは borderWidth =
等幅 font のダッシュの実測値と同じ)。等幅のダッシュは 7px の罫が 8px のセルを
ほぼ埋めており、**字を選び直しても縮まない**(U+002D / 2010 / 2011 / 2212 の 4 つとも
同じ 7px。Cascadia Mono 実測)。ボタンで最長の言い分である `push -f` は、この
2 セル(空白 + ダッシュ)のせいで右端に印の立つ場所が無くなる。引いた罫なら
長さも前後の空気も選べる。**測る側(共有の箱)は font のままにする** — 箱は
ツールバーを動かさないためのもので、罫の長さを変えるたびにボタンの幅が
動いてはならない。

**失敗の印(`!`)は語のすぐ後ろに置く。** 基準は語の送り幅の末尾で、チップの地が
自分の端に持つ空気がそのまま印との間になる(実測 3px)。離すほど「このボタンの
話」ではなく「ツールバーの話」に見える。**フラグを持つ語の後ろだけ半ギャップ
内側へ入れる**(実測 1px)— そこが最長の言い分で、右端の余裕がいちばん薄いため。

コード表記の場は**メニューの行と、ツールバーの fetch / push ボタン**。
メニューは `Delete` や `Discard everything after it` のような文と混ざって並ぶ場所で、
そこに紛れたコマンド名だけが問題を起こす。ツールバーの 2 つは事情が逆で、
**ラベルがコマンドそのもの**(`fetch` / `push` / `push -f`)—— この 2 つは
git のコマンドと 1 対 1 で、言い換えても同じものを指す。チップはそれが
コマンドだと言い、`push -f` のフラグも同じ地の上に載る。

**同じボタンでも、コマンドでない状態は通常表記のまま**(fetch が止まった時の
`Resume` / 初回の `Publish`)。どちらもコマンドと 1 対 1 でない —— `Resume` が
戻すのは自動 fetch であって 1 回の `fetch` ではなく、`Publish` は
`push --set-upstream` が起きることそのものではない(ブランチが向こうに
できる、が起きること)。**チップの有無が「これは git のコマンドか」を語る**ので、
コマンドでないものに着せない。

**interactive rebase の todo 動詞は、コマンドと同じに扱う**(`squash` / `drop`)。
`git squash` というコマンドは無いが、綴りは git がその操作に与えた名前そのもので、
対応も 1 対 1(内部は `rebase -i` のその 1 行)。**コミット行のメニューは全行が
コマンドで始まる**ので、ここだけ言い換えると、動詞の列を上から読む目にその行の席が
無くなる —— 言い換えた語は単体では読めても、列の中では行方が知れない。

その他の単独ラベル(WIP ペインのカードの Stash… / 詳細ペインの Apply / Pop)は
見出しであって文でもコマンドでもないので、通常表記(語頭大文字)のまま。

**サブメニューを開く親行も、コマンド名が語ならチップで言える**(`AppMenu.titleCode`
→ delegate が作る親行に乗る)。reset のサブメニューはこれで `reset` `<branch>` here
と名乗り、モードの行にはフラグだけが残る(§ブランチを過去のコミットへ戻す)。

**メニュー内のチップは 1 本の列を共有する**(`AppMenu.codeColW` = いちばん広い
チップに合わせ、文の頭を揃える)。フラグ 3 つのように同じ形の行が並ぶ時、文の頭が
揃わなければ表として読めない。**文が続かない行のチップも同じ列に座る**(§メニュー
「行がコマンドだけで終わることがある」)— 座らせないと、いちばん長いコマンドが
文の頭を追い越して列が崩れる(`cherry-pick` が `into main` の頭より右で終わる)。
地はどの行でも語の実幅だけを塗り、列の余り分は空白のままにする。

### 長さ

**画面に出す文は、数語拾えば伝わる長さで書く。** 読ませる前提の説明文を UI に置かない
— 操作の途中で段落を読む人はいないので、長い文は「読まれない」ではなく
**「そこに何か書いてある」だけの模様**になり、本当に効く 1 行の効き目まで削る。

- 質問・警告は **見出し 1 行 + 失うもの 1 行**。因果や手順の説明を足さない
  (例: `Move main here?` / `Commits only main has stop being reachable.`)
- 2 文目を書きたくなったら、それは 1 文目が本質を言えていない合図
- 詳しい事情は git の出力(コマンドログ)に出ているので、UI 文言で代弁しない
- **冠詞は、特定の既存物を指す文にだけ残す。** その行が**これから選ぶ種類**を名乗って
  いるなら落とす — `Create branch here?` / `Stage file` / `Stage hunk`。**画面に在るものを
  名指しして何をするかを言う文**では残す — `Amend the last commit` /
  `Stage the whole file at once` / `Discard everything after it`。
  短くするために削るのではなく、**指しているものが在るかどうか**で決まる。
  **落とせるのは動詞の直接目的語の位置だけ** — 前置詞句の中は限定詞を要求するので
  `Edit in merge editor` は壊れる。埋まる値を指したいなら**山括弧のプレースホルダ**に
  する(`Edit in <merge editor>…`)

### hover のツールチップ

**結論を先頭に、1 行で書く。** ツールチップは読ませる場所ではなく、
一目で受け取らせる場所 — マウスを止めている間しか出ておらず、
読み下している間は操作が止まる。

- **1 文・1 行**(表示幅で折り返さない長さ)。2 文に割れたら 1 文目を捨てる
- **結論から**書く。押せない理由なら「なぜ押せないか」ではなく
  **何が足りないか**(`Nothing to push — origin/main is up to date`)、
  操作なら**何が起きるか**(`Hold to overwrite origin/main, …`)
- **状況説明・因果の説明を書かない**。「〜なので〜できない」の前半は落とす
- ラベルの言い換えで終わらせない。ラベルに入らなかった 1 点
  (対象の広さ・失うもの・時点)だけを足す
- 数を出す時は時点を添える(§リモートへ送る)が、**括弧で短く**

**足すものが 1 つも無い的には、何も出さない。** 上の 4 条を全部満たそうとして
何も残らなかったなら、それは「短く書け」ではなく「出すな」の答え。グラフの
WIP 行(未コミット)がその形で、行の hover が運ぶ 4 つ(author・日時・
メッセージ全文・co-author。§author の hover / §co-author の表示)をどれも
持たない —— コミットではないので author も日時も無く、メッセージは生成した
文字列、件数は行のラベルが既に出している。内訳を読ませたいなら hover ではなく
**行そのものか、クリックで開くペイン**(GitKraken / GitLens も行に出す)。
**ダブルクリック・右クリックと同じ答え**(§グラフ行のダブルクリック /
§グラフ行の右クリック の表)で、この行は 3 所作すべてに「コミットではない」の
1 つを理由に何も返さない。

**hover で現れるものは、hover されている当のものをリサイズしてはいけない。**
的が手の下で動けば hover は外れ、出したものはその瞬間に消える。2026-08-09 に
2 度踏んだ: co-author カードの行を hover した時だけアドレスを足したら、行の幅と
高さが変わって**自分を開いた手から逃げた**(2 人目以降へ渡ることもできない)。
出すものは**最初から席を持たせる**か、**当のものの外**へ出す。

**hover で開いたものの幅は、開く位置から測る。** ペインの幅ではない —— カードは
ペインの途中から始まるので、そこから右に残っている分しか使えない。測らないと
`Popup` が**位置だけ**をウィンドウ内へ寄せ、幅は切らないまま端に張り付く
(同日、アドレスが 62 文字の co-author で踏んだ)。名前もアドレスも長さの上限が
無い(アドレスは 254 文字まで許される)ので、**必ず省略できる形にする**。

**行を覆う `MouseArea` の下に hover は届かない。** 後から宣言した全面の
`MouseArea` は、内側の `MouseArea` も `Control` の `hovered` も一度も立たせない
(`HoverHandler` へ替えても同じ。`qmltestrunner` + `mouseMove` で実測)。行の中の
小さな的に付けたツールチップは**書いてあっても出ない**ので、区画ごとに違う
ことを言いたいなら、**覆っている `MouseArea` に「どの区画に居るか」を報告させる**
(`GraphRowDelegate.noteChipHover` がその形)。

**1 つのポインタが開けるものは 1 つ。** 手は 1 本しかないので、hover で出るものが
2 つ同時に出ていれば、それは片方が誰にも頼まれずに出ているということ。重なりの
見た目が悪いという話ではない —— **後から出た方が前に立って、先に出ていた方への
道を塞ぐ**(グラフ行のカードは手の下に開くので、チップの一覧がまさにそこにある)。
**どちらが残るかは「より個別のものを指しているか」で決める**: グラフ行のチップを
指す手にはチップの一覧を出し、行のカードは引っ込める —— 行のカードはどの行にも
在るが、一覧はそのチップにしか無い。譲る側は**待たずにその場で消す**(閉じ待ちの
150ms のあいだ重なって見える)。

**hover で開いたものは、そこからさらに開かない。** preview が 2 枚目のポップアップを
生やすと、preview がペインの顔をし始める —— 手は開いた物の中を歩き回ることになり、
**閉じ待ちの配線が入れ子の数だけ増える**(どちらの中に居るかを 2 か所で数える)。
確かめる場所は右のペインで、そこへは 1 クリックで着く。だから**グラフ行のカードは
何も開かない**(§co-author の表示)。カードを開いてよいのはペインと一覧 ——
**居座っているものだけ**が、次を開く側になれる。

**閉じ待ちのあいだ、ポインタはどこにも居ないことがある。** `Popup` は下の行から
hover を奪う一方、`HoverHandler` を `contentItem` に置くと padding の帯は自分でも
拾わない —— 帯の上では**チップも行も一覧も「自分の上には居ない」と答える**ので、
待たずに閉じる実装は必ずそこで閉じる(2026-08-09、チップの一覧へ降りる手が毎回
弾かれるとして報告。qmltestrunner の `mouseMove` で実測)。**行が光ったのに消える
なら、それは「乗っていない」と答えているのが行を光らせた当人ではない**という形
—— 実装側の条件は §hover のツールチップ の罠一覧(`.claude/rules/app-ui.md`)。

**hover で出すものは、通りすがりでは開かない。** 小さな的が並ぶ列を横切る手は
その全部の上を通るので、乗った瞬間に開く作りは**触れた分だけ出しては引っ込める**
—— 読む人にはただの点滅で、しかも自分が何をしたから出たのかが分からない。
**待ちは他の hover と同じ**(§進行中・長押しの定数 の `tipDelayMs`)。
**並びの中に無い的は即時でよい**(詳細ペインの下線・レールのセル)——
そこに乗る手は横切る手ではない。

**出ているものの的へ戻る手は待たせない。** 開く前の待ちは「通りすがりか、
狙ったのか」の確認で、既に開いているものにその問いは無い —— 一覧へ降りた手が
開けた的へ戻り着いたら、そのまま保つ。閉じ猶予で消して開き待ちで出し直すのは、
読む人には点滅で、**開いたものの中と縁を行き来する普通の読み方を罰する**。
**隣の的への即時の移し替えは不採用**(KDE のタスクバーのツールチップはそうするが、
ここでは一覧から出る手の通り道に別の行のチップが並ぶ —— 出るつもりの手に
別の一覧が出る)。

**開けるのは的、保つのはその的が属する区画。** 16px の的に乗るのと、乗り続けるのは
別の難しさ —— 着いたばかりの手はまだ止まっておらず、十数 px は流れる(実測: 着地の
8ms 後に 15px)。**出したものを保つ範囲は、開けた的より広く取る**(チップなら
チップ列、行の印ならその行)。**逆はしない**: 広い範囲で開くと、通り抜けただけの
手にも出てしまう。

### ブランチ・コミットへの移動

| 場面 | UI 文言 | 内部コマンド |
|---|---|---|
| ローカルブランチへ移動 | **Switch**(右クリックの行。名前は行が出しているので言わない = §メニュー) | `git switch` |
| リモートブランチから作って移動 | **Switch**(新規ローカル作成は暗黙) | `git switch -c --track` |
| ローカルブランチをここへ動かして移動 | **Move `<branch>` here**(確認あり) | `git switch -C` |
| 任意コミット / タグへ移動 | **Create branch here?**(入力欄のプレースホルダ) | `git switch -c <name> <oid>` |
| 現在ブランチの表示 | **On `<branch>`** | — |

**この GUI からは detached HEAD にならない。** 行き先は必ずブランチで、
ブランチの無いコミットやタグを指した時は「そこにブランチを作る」入力欄に化ける
(§グラフ行のダブルクリック)。detach は「続きが書けない」状態 — 次のコミットが
どのブランチにも乗らず、離れた瞬間に画面から辿れなくなる。抜け方を知っている人は
コマンドラインで detach でき、知らない人はメニューの 1 行で連れて行かれる。
**その 1 行を置かない**(`CheckoutTarget` に detach する行き先そのものが無い)。

**ただし detached HEAD の表示と操作は保つ。** git 自身が置いていく状態だからで
(bisect 中・rebase の中断・コマンドラインの `checkout <tag>`)、開いた時にそこに
居ることがある。HEAD チップは `warning` 色、サイドバーは **DETACHED HEAD** を出し、
読み取り・stage・commit・別のブランチへの移動はそのまま働く。**抜ける道は 2 つ** —
普通の switch と、その場にブランチを作る入力欄。ブランチが要る操作
(push / `Move <branch> here`)だけが無効になり、無効な理由はその場に出る(§無効)。
右クリックのメニューでは、ブランチが要る行(merge / rebase / reset)は**無効ではなく
消える**(§メニュー) — 残るのは cherry-pick / revert / 削除の側だけになる。

他プロダクトの用例(2026-08 時点):
GitHub Desktop = "Switch branch" / VS Code = "Checkout to..." /
GitKraken・Fork・SourceTree・Sublime Merge = "Checkout" /
Tower = "Checkout" と "Switch To" の併用。

「Checkout」が多数派だが、それは各製品が古くから使ってきた語の継承であって
分かりやすさで選ばれた語ではない。本プロダクトは **Switch** を採る。

### グラフ行のダブルクリック

**行き先は「その行のチップに出ている名前」**。チップの先頭レコード
(HEAD → ローカル → リモート → タグ → 名前順で並ぶ)がそのまま行き先になるので、
画面に出ている文字と着地点が食い違わない。行に複数の ref があっても、
規則を覚える必要がない — 見えているものが行き先。

| 行が持つもの | ダブルクリック | 内部 |
|---|---|---|
| 現在のブランチ | 何もしない | — |
| ローカルブランチ | そこへ移動 | `switch <name>` |
| リモートのみ・同名ローカル無し | 尋ねずに移動(ローカル作成は暗黙) | `switch -c --track` |
| リモートのみ・同名ローカルが別の行 | **Move `<branch>` here?** を尋ねてから移動 | `switch -C` |
| タグのみ / ref 無し | チップ列がブランチ名の入力欄になる | `switch -c <name> <oid>` |
| WIP 行 / stash 行 | 何もしない | — |

**タグでは detach しない。** タグは動かない目印なので移動すれば必ず detached HEAD
になる。それは「続きが書けない」状態で、黙って作ると次のコミットが宙に浮く —
取り返しはつくが、取り返し方を知らない人が最も踏む罠。§ブランチ・コミットへの移動
のとおり detach はどこからも行き先にせず、ダブルクリックにはその行でいちばん
要るもの、つまり**ブランチを作る**を割り当てる。GitKraken も近い判断で、タグの
ダブルクリックは checkout ではなくジャンプ、checkout は右クリックの
「Checkout this commit」/「Create branch here」に置いている
— 本プロダクトはそこから前者も落として後者だけを残す。

`Move <branch> here` だけ確認を出す。**ローカルにしか無いコミットが指されなくなる**
唯一の経路だから(reflog には残るが、この画面からは辿れない)。他は switch で戻せる。
確認は質問バーで出し、行き先の行に印が付く(§可否・警告の出し場所)。
**ピルは `Move` の長押し** — 指されなくなるものがある側なので、
クリック 1 回では取らない(§可否・警告の出し場所)。

**ただし「指されなくなるものがある」かどうかは git に訊いてから決める。**
遅れているだけのブランチを追いつかせる(fast-forward)のが日常の大半で、
そこでは失うものが無い — 質問の文言(`Commits only <branch> has`)が
存在しないものを指すことになるし、**何も捨てない switch に長押しを出すのは
邪魔なだけ**。`merge-base --is-ancestor <local> <remote>` が通れば黙って移動し、
通らなかった時だけ質問を立てる(`session::checkout_moving_branch`)。

**チップは 1 行に 1 つ、ブランチを出す。** 名前を出すのは先頭 1 件で、順は
HEAD → ローカル → リモート → タグ。同じコミットがブランチの先端でもあり
リリースタグでもある時、チップに出るのは**ブランチ**で、タグは `+N` に入る。
チップ列は「この行はどこへ行けるか」を答える場所であり、行けるのはブランチだけ
だから — タグはそこに並べる相手ではなく、カードで読ませる。**ブランチとタグで
列を分けない**(分ければどちらの名前も半分の幅しか持てず、両方が読めなくなる)。

**ブランチと、その雲バッジが指しているリモートは 1 つのチップに畳む。** `main` の
隣で `origin/main` を数えるのは、バッジが 1 回言ったことを 2 回言うだけ。畳む相手は
「そのブランチのリモート」1 つ — 設定された upstream、無ければ**同名のリモートが
1 つだけの時**のそれ。**一致しなければ畳まない**(upstream が `origin/main` なら
`fork/main` は残る。upstream が無く同名候補が 2 つ以上ある時はどれも残す —
バッジがどれを指しているか決まらないものを黙って消さない)。
**畳めるのは両者が同じコミットに居る時だけ**なので、ズレていればリモートは元どおり
別の行にチップを持ち、分岐が隠れることはない。畳まれたリモートはサイドバーの
REMOTES で数えられる。結果として `+N` は実質**タグの件数**になる。

**重なったチップは hover で展開する。** 集約チップ(`main +2`)は先頭 1 件しか
名前を出せないので、hover で下にカードを開き、1 行 1 ref にしてクリックで
選べるようにする。**タグだけの行も同じ** — 行き先にならないことと、名前が
読めないことは別の話。並びはチップと同じ順(ブランチが先・タグが後ろ)。
**待ち時間は置かない** — 展開するのは重なったチップだけで、
それ以外の行はいくら通り過ぎても何も起きないので、誤爆する余地が無い。
代わりに**ポインタが離れたら閉じる**(チップとカードのどちらにも乗っていない時)。
カードの意匠は §メニュー と同じ(`bgElevated` の地・`borderDefault` の枠・
`rowHeight` の行)。`textMuted` に落とすのは HEAD マーカーだけ(§無効)。
**現在のブランチとタグは落とさない** — 行けないのは同じでも、それは
「使えない」ではなく「もう立っている」「印である」から(§ref の種別)。
色とバッジは保ったまま、hover の反応とクリックだけ外す。

**リモートに在るかどうかは、ブランチもタグも同じバッジで示す。** 無表示 =
ここにしか無い / 雲(`textSecondary`)= リモートにも在る / 緑の PR アイコン
(`success`)= PR 中(ブランチのみ)。**1 スロットに 1 つだけ**で、二つ並べない。
グラフのチップとサイドバーの行で同じ形・同じ色を使う — 同じ問い(これはここに
しか無いのか)に、置かれた場所で違う答え方をしない。

**タグの在処もブランチと同じ 2 軸で読ませる** — 枠は `refTag` のまま、名前の色が
在処、雲バッジがリモートの有無。タグにはリモート側の名前空間が無い(fetch した
タグはそのまま `refs/tags/` に入る)ので、`origin/` のような接頭辞では言えない。

| タグの状態 | 名前 | バッジ | 出る行 |
|---|---|---|---|
| ローカルのみ | `textPrimary` | 無表示 | そのコミットの行 |
| 両方に在り、同じコミット | `textPrimary` | 雲 | その行(チップは 1 つ) |
| リモートのみ | `textSecondary` | 雲 | そのコミットがローカルに在る行。無ければサイドバーの TAGS だけ |
| ズレ(同名で別のコミット) | ローカル側 `textPrimary` / リモート側 `textSecondary` | 雲 | **2 つの行に同じ名前で出る** |

**ズレは「同じ名前が 2 行に見える」ことで示し、専用のバッジも警告色も足さない** —
状態バッジは 3 値(無表示 / 雲 / PR)のまま。ズレは fetch では解消しない
(ローカルに同名タグが在れば git は上書きしない)ので、放置されても見え続ける
必要がある。リモート側のコミットがローカルに無ければローカルの行だけが出る。
データ接続は P4(`ls-remote --tags`)、それまで `PG_FAKE_REMOTE_TAGS` は
雲バッジだけをプレビューする。

**入力欄はチップ列の中に出す**(§可否・警告の出し場所: 表示の切り替えで足りるなら
ダイアログを出さない)。プレースホルダが `Create branch here?` で、Enter で作って
移動、Escape と他行のクリックで閉じる。**捨てても失うのは打ち直す数秒だけなので
尋ねない** — 編集中のコミットメッセージ(`DetailsPane.asking`)とは重みが違う。

### グラフ行の右クリック

**行が何であるかでメニューが変わる。** グラフには 3 種の行があり(§グラフ・
インタラクション定数)、コミットに効く操作が他の 2 種に効くわけではない。

| 行 | 出るもの |
|---|---|
| コミット | **`cherry-pick`** / **`revert`** / **`merge`** into \<current\> / **`rebase`** \<current\> onto it(§履歴を合流させる)/ **`squash`** into parent / **`drop`** / **`reset` `<branch>` here ▸**(§ブランチを過去のコミットへ戻す) |
| stash | **Delete** だけ |
| WIP(未コミット) | 出さない(コミットではない) |

**`cherry-pick`** は git 用語のまま採り、コード表記で出す(§git 用語のコード表記。
Stash と同じ扱い)。1 語で言い当てる言い換えが無く、説明で書くと §長さ に反する。
特に `Copy` は本アプリではクリップボードへの複写(`Copy path` / `Copy command` 等)の
語なので、`Copy this commit …` の形は同じ語に二つの意味を持たせる。

**stash 行に出すのは削除だけ。** stash はどのブランチの履歴でもないので、
コミット行の操作はどれも当たらない(cherry-pick も、そこへブランチを動かすことも)。
戻す操作(`Apply` / `Pop`)は**右クリックがその行を選ぶ**ことで右のペインに出るので、
メニューには重ねない(§メニュー)。所作も文言も左メニューの `Delete` と同じ —
同じ問いを、置かれた場所で違う聞き方にしない。

### グラフを横へ送る

レーンが列に収まらない時、横へ送る手は 3 つ(仕切りを広げるのは別 — §グラフ列は
最も広い所のレーンまで)。

| 所作 | 効く範囲 |
|---|---|
| レーンの上を左ドラッグ | レーン列の上だけ(掴んだものを動かす所作なので、掴める場所が範囲) |
| ホイールの横成分(チルト・タッチパッド) | グラフのどこでも(横へ送る意思がその入力自体に書いてある) |
| 中クリックの自動スクロールで横に流す | **レーン列の上で中クリックした時だけ** |

**中クリックの横移動を、どこで押したかで決める。** 縦の自動スクロールは
グラフのどこで押しても効く(送りたいのは履歴で、subject を読みながら押す方が自然)
— が、**横は押した場所がレーン列の中だった時だけ**。subject 列は上下に読む文章の
列で、そこで押した人が求めているのは縦送りだけなので、手のわずかな横ぶれで
レーンが読んでいる下から滑っていくのは事故にしかならない。レーンの上で押したなら、
横はまさに意図の側にある。**判定は押した 1 点で、その後ポインタがどの列へ出ても
変わらない**(移動中に範囲が入れ替わるのは、掴んだものが手の中で変わるのと同じ)。

**どちらの形かはカーソルが言う。** 縦横に動く時は `SizeAllCursor`、縦だけの時は
`SizeVerCursor` — 出ない方向へ流しても何も起きないことを、無反応ではなく
形で先に伝える。アンカーの印(輪 + 中心の点)は両方で同じ。

**横スクロールバーは、グラフにポインタが居る間だけ出す。** 場所はレーン列の
下端いっぱい(グラフには帯が無いので、下端が余白を持たない唯一の縁)。
**常時出さない** — バーは最下行のレーンの上に乗るので、誰も横へ送るつもりが
無い間まで履歴の 1 行を隠す。**レーン列だけでなくグラフのどこに乗っても出す**:
バーは「この列はまだ横に続く」という report でもあり、それを読むためだけに
ポインタをレーンの上へ運ばせない。**ドラッグ中はポインタがペインを出ても出したまま**
(掴んでいる最中に消える的は掴めない)。

### リポジトリを開く

**選んだフォルダは、開けると分かってからタブになる。** ピッカーが受理した所で
`git rev-parse` を 1 本撃ち、答えを見てからタブを作る。開けなかったフォルダは
タブにならない —— そのページには読むものが 1 つも無く、パスだけが次の起動へ
持ち越される。

**待ちの姿は持たない。** 答えは 30〜36ms で返る(Windows warm・非リポジトリ /
bare / 8 階層下のいずれも実測)ので、ピッカーが閉じてから答えまでは 1〜2 フレーム。
遅い共有ドライブの形は手元で測れないので P5-確認事項へ。

**開けなかった時に何を出すかは「どの道で来たか」が決め、文言は種別が決める。**
この 2 つは直交していて、3 × 2 の 6 通りが出る。

| | ピッカーが受理した | それ以外の道 |
|---|---|---|
| **置き場所** | ダイアログ(§可否・警告の出し場所 の例外) | タブの中の画面 |
| **行動** | `Cancel` / `Choose again…` | `Close tab` |

「それ以外の道」= 前回のタブの復元・worktree 行・コマンドライン。**人が今フォルダを
選んだ結果ではない**ので、ダイアログを出さない —— 起動直後に立つモーダルは、
読む前に答えられる。

**文言は 3 つで、どちらの画面も同じものを言う**(実装は `Words.openFailure`。
2 つ目の写しは 2 つ目の答えになる)。

| 種別 | 見出し | 2 行目 | 3 行目 |
|---|---|---|---|
| リポジトリが無い | `Not a git repository` | パス | — |
| bare | `A bare repository has nothing to show` | パス | — |
| git が答えられなかった | `Could not open this folder` | パス | **git の文言**(`danger`) |

- **見出しは 1 行で、その下に言い直しを置かない**(§長さ)。git が親ディレクトリに
  ついて言うことは「リポジトリが無い」が既に含んでいる
- **パスは 3 つとも同じ席**(見出しの直下)。ピッカーは閉じており、タブは葉しか
  名乗らないので、**そのフォルダを名指しできるのはこの行だけ**。`ElideMiddle` で
  末尾を残す(見分けが付くのは葉の側)
- **赤は git の文言だけ**。アプリが書いた文を赤くしない —— 赤は「git がこう答えた」の
  合図で、git が使えない時の画面(§アプリ名 の「git 不在時の見出し」が立つ所)も
  自分の文は普通の色・git の文言だけ `danger` で出す。**種別の判定も git の文言を
  読まない**(core が `plain` / `bare` / `other` を返す)
- **3 つ目に専用の扱いを作らない。** 「答えが出なかったから開けない」ことは他の
  2 つと同じくらい開けないので、置き場所も行動も分けない
- **ボタンは `Choose again…`**、`Choose another…` ではない。`another` は「そのフォルダが
  間違っていた」という主張で、3 つ目ではそれを言えない(git が答えられなかっただけで、
  リポジトリかもしれない)。1・2 つ目では**見出しが既にそれを言っている**ので
  言い直す必要が無い。3 つとも約束するのは「ピッカーがもう一度出る」の 1 つ
- **`Choose again…` はさっき選んだフォルダの親から開く。** 探していたリポジトリは
  たいていその隣に在る —— ピッカーが開いているリポジトリの隣から始まるのと同じ
  理由で、同じ 1 か所が決める(`urlpath::picker_folder_url`)
- **取り下げは 1 形。** `Cancel` / Escape / 開き直したピッカーの取り下げ、どれも
  **入る前と同じ画面**へ着地する(タブは増えても減ってもいない)。**ピッカーの取り下げで
  ダイアログへ戻さない** —— 戻すと `Cancel` が「1 つ前へ」の意味を持ち、輪から抜ける道が
  Escape だけになる。タブが 1 つも無ければ空の窓に `Open repository…` が立っている
- **同じフォルダをもう一度受理しても、文言も回数も変えない**(「またですか」を言わない)

### タブの所作

| 所作 | 効果 |
|---|---|
| 左クリック | そのタブへ移る |
| 中クリック | **そのタブを閉じる** |

**閉じる的はタブ全体で、`✕` はその中に立っている印。** 中クリックはタブのどこで
押しても効き、`✕` の上で押した時も同じ — 印は「ここは閉じられる」と言う役で、
的そのものは行の幅ぶん在る。**16px の印を狙わせないための所作なので、狙わせて
しまえば残るのはボタンが 2 つあることだけ**になる。

**`✕` が出るのは前に居るタブと、手の下のタブだけ。** 印を全タブに並べると、押しに
来られていない席が全部「押してくれ」と言っている状態になり、読みたいのは名前の方
なのに目が先に印の列を数える。**席は空けたまま**にする(消すのではなく落とす)—
幅が変わるタブは、閉じに来た手の下で的をずらす(§hover のツールチップ「hover で
出すものが、hover されている当のものをリサイズしない」)。

**名前は全タブで `textPrimary`、`✕` は 1 段下**(`iconMd` ではなく `iconSm`・色は
`textSecondary`)。タブが在るのは名前を読ませるためで、印はそこから出る道でしかない。
**前に居るのがどれかは席が言う**(`bgSelected` の地・下端の `accent` の線・DemiBold)
ので、文字を暗くして順位を付ける必要が無い。

**閉じるのは離した時**(素のクリックと同じ)。押してから的の外へ逃がせば何も
起きない — 確認を挟まない操作から、取り消す手まで取り上げない。

**長押しにしない。** 閉じて失うものはリポジトリの側に無く、開き直す手は `+` の
1 つ先にある。同じことをする `✕` が素のクリックである以上、2 つ目の所作にだけ
押し切りを課す理由も無い(§長押し = 印の有無が語彙)。

**中ボタンの意味がアプリの中で 2 つに割れているのは正しい。** グラフの上では
自動スクロール(§グラフを横へ送る)、タブの上では閉じる — 押した場所が意味を
決める形で、ブラウザもエディタもそう割っている。

**同じリポジトリは 2 枚のタブにならない。** 既に開いているものを開こうとしたら、
新しいタブを立てずに**そのタブへ移る**。1 つのリポジトリに 2 つの席があると、
どちらを見ているかが分からないまま片方で書き、もう片方の一覧が置いていかれる
——同じ木を 2 つのポーリングが読み、2 本の履歴を描く分の代償も付く。

**黙って何もしない、にはしない。** 頼んだ人はそのリポジトリを見に行きたいので、
無反応は要求を落としたようにしか見えない。**移った先が答え**で、質問もバーも
出さない(尋ねる余地が無い = §長押し の「日常操作は尋ねない」と同じ理由)。

**入口ごとに判定を書かない。** 開く道はフォルダピッカー・WORKTREES 行・起動時の
引数と複数あり、そのどれも同じ 1 つの問いを持つ。**「もう開いているか」に答える
場所は 1 つ**(実装は [.claude/rules/app-ui.md](../.claude/rules/app-ui.md))。

### 左メニューの所作

**行き先はダブルクリック、名前は「間を空けた 2 回目のクリック」。** グラフ行と同じ
規則を左メニューにも通す — 同じ問い(この行はどこへ行くのか)に、置かれた場所で違う
答え方をしない。

| セクション | 単クリック | ダブルクリック | 間を空けた 2 回目 | 右クリック |
|---|---|---|---|---|
| BRANCHES(他のローカル) | その ref のコミットへジャンプ | **Switch** | **改名** | Switch / Delete…(拒まれたら `Delete anyway`) |
| BRANCHES(現在のブランチ) | ジャンプ | 何もしない(既にそこ) | **改名** | 無し(Switch も Delete… も当たらない = メニューを出さない) |
| フォルダ行 | 開閉 | 何もしない | 無し | 無し |
| REMOTES | ジャンプ | **Switch**(同名ローカル無し = 作って移動 / 有り = `Move <branch> here?`) | **改名**(§リモートブランチの改名) | Switch / `push --delete` Delete |
| WORKTREES | 行を取るだけ | **別タブで開く** | 無し | 無し |
| STASHES | 中身を詳細ペインに出す | 何もしない | **改名** | Delete |
| TAGS | ジャンプ | **`Create branch here?` の入力欄**(detach しない) | **改名** | Delete |

**所作で届くものを右クリックに重ねない。** 改名もタグからのブランチ作成も行の上で
1 クリックの距離にあるので、メニューには置かない — メニューの行数は、**そこにしか
入口が無いもの**(削除)のために取っておく(§メニュー)。ハッシュのコピーも同じ
理由で置かない: 行をクリックすれば右のペインがそのコミットを出し、`Copy full hash`
がそこにある。

- **2 回目のクリックも普通のクリックとして働く**(行き先へもう一度飛ぶ)。改名の入力欄が
  出るのはその上に重ねてで、意図せず開いても Escape・他所のクリックで消える
- **判定はダブルクリック間隔だけ**(Explorer と同じ、上限は置かない)。間隔の内側に
  入った 2 回目は「ダブルクリックの片割れ」なので、普通のクリックとしても数えない
- **直前にクリックした行を `bgSelected` で示す**。2 回目の狙いどころが見えないと
  この所作は成立せず、WORKTREES のように飛び先の無い行のクリックが空振りに見える

**入力欄は行の名前の位置に出す**(§可否・警告の出し場所: 表示の切り替えで足りるなら
ダイアログを出さない)。フルネームを入れて全選択で開き、Enter で確定、Escape と
他所のクリックで取り消す。**尋ねない** — 捨てても失うのは打ち直す数秒。

- **編集するのはフルネーム**(`feature/login`)。末尾だけを出すと、打ち直した名前が
  黙ってフォルダの外へ出る
- **確定できない名前は Enter が効かない**。枠が警告色に変わり、理由は入力欄の
  ツールチップに 1 行(§長さ)。**規則は git のもの**(`check-ref-format`)を写すだけで、
  独自の禁止を足さない — 端末で作れた名前を GUI が拒むのは嘘になる。stash の名前は
  ref ではなく reflog の 1 行なので、規則は「1 行・空でない」だけ
- 同名のまま確定したら何もせずに閉じる。既存の名前と衝突したら git がそのまま拒む
  (force は使わない — 黙って上書きすると相手のブランチ・タグが消える)

**git に無い改名は作り直しで通す。** タグは `git tag <new> <old>` → `git tag -d <old>`
(同じオブジェクトを指すので注釈・署名・tagger はそのまま)、stash は書き直した
コミットを `git stash store` → 古い方を drop(**一覧の先頭へ移動する** — 一覧は
reflog で、reflog は先頭にしか伸びない)。どちらも確認は出さない: 指す先は失われず、
消えるのは古い名前だけ。

**削除は「git が拒むかどうか」で分ける。**

| 対象 | 実行 | 確認 |
|---|---|---|
| ローカルブランチ | `git branch -d` | **尋ねずに実行**(行は `Delete…`)。git が拒んだら**メニューは閉じず、その行が `Delete anyway` + `not merged` タグに化ける** — 長押しで `-D` |
| タグ | `git tag -d` | メニューの行を**長押し**(`Delete`)— git は何も拒まない |
| stash | `git stash drop` | 同上(`Delete`) |
| リモートブランチ | `git push <remote> --delete` | 同上。`push --delete` のチップと行の色だけが違う(§リモートブランチを消す) |

この表は**左メニューだけの決まりではない**。同じ行はグラフの stash 行の右クリックにも
出る(§グラフ行の右クリック)ので、実行も確認も文言もここが正本。

**ブランチだけクリックなのは、`-d` が何も失わないから。** git が拒む時だけ失うものが
あるので、そこで初めて長押しを課す。毎回長押しにすると、日常の後始末が全部
確認付きになり、本当に危ない `-D` の重みまで薄れる。**現在のブランチの削除は出さない**
(git が拒むだけの操作をメニューに残さない)。

**答えが返る場所は、訊いた場所と同じにする。** `-d` の結果は非同期に返るので、
この行のクリックだけは**メニューを開いたまま**にして、そこへ答えを落とす
(§長押し)。グラフの上へバーを降ろすと、手はメニューを閉じて別の場所へ移動させられる。

**行が言うのは git が言ったことだけ。** 拒否は「コミットが誰からも辿れなくなる」を
意味しない — git は upstream があればそちらを基準にするので、**HEAD にマージ済みでも
未 push なら拒否**され、逆に**HEAD に未マージでも push 済みなら通る**(実測)。
到達性を語る文言は嘘になるので置かない。事前判定も足さない: 一致させるには
git の upstream 優先規則をアプリに複製することになる。

### 左メニューを畳む

**畳んだ左メニューは背骨だけ残す** — セクションごとに 1 セル、アイコンが何かを言い、
その**真下の数字が幾つあるかを言う**。セルは `railWidth` の正方、幅もその 1 枚分。
文字を縦に流したり、アイコンを小さくして語を残したりはしない(畳む理由は幅で、
44 に収まる語は無い)。

**畳む席と戻す席は同じ 1 つ。** ペインの帯の末尾に `headerHeight` 角のブロックを置き、
地は `bgElevated`・左辺に `borderSubtle` の仕切り、**ブロック全体がボタン**(当たりは
帯の全高)。畳むと帯はそのブロックだけになる。**印は描いた二重山形**(`chevrons`)で、
向きだけが違う — 畳む = 左、戻す = 右。**文字で置かない**: ギリシャ引用符は小文字の帯に
乗るので行ボックスを中央に揃えるとインクが下がり、三角は UI フォント本体に無く 3 OS で
別の形になる。**寸法はセクションのアイコンと同じ**(`iconLg` + `iconStroke`)— 畳んだ
レールでは真下に並ぶので、細い字だと弱く見える。

| 所作 | 結果 |
|---|---|
| 帯のブロック | 畳む / 戻す(戻り先は**畳む直前の幅**。`レイアウト初期値` は最初の 1 回だけ) |
| セルを hover | **そのセクションだけ**をレールの右へ開く(下記) |
| セルをクリック | 開いているそのセクションを閉じる。**戻さない**(下記) |
| 中身が 0 のセル | **何も起きない**。hover でも開かず、クリックも効かない(下記) |
| diff を開く | 自動で畳む(下記) |
| 一覧を戻す | 開いていた diff を閉じてグラフへ(下記) |

**hover で開くのは 1 セクションだけで、レールに密着させる。** 見出しの帯 + その
セクションの行そのもの(所作も右クリックも展開時と同じ)。**間に地を挟まない** —
ポインタが下りていく途中で両方から外れると閉じてしまう。閉じるのは**セルとリストの
両方からポインタが出た時**で、判定は 1 巡待ってから行う(グラフのチップとカードと同じ)。
**どちらへ退いても閉じる** — 上のブロックへ、下の隣のセルへ、右のリストへ、どこへ抜けたかで
残り方が変わってはいけない(セルは「自分から出た」ではなく**どのセルから出たか**を言う。
言わないと、開いたセクションを引き取る相手が居るのかどうかが判らず居座る)。
**開いたリストから出る時も同じで、こちらはリスト自身が言う** — セルへ戻る道はセルが見ているが、
**右の diff やグラフへ抜ける道・上下の端から出る道はどのセルにも見えない**。片方しか言わないと、
リストの中まで入った人だけが閉じられない一覧を抱える(**畳んでいる時ほど起きる** — 畳む理由は
大抵 diff で、リストは畳んだ幅の外側 = diff の上に開くので、出口の大半が diff 側にある)。
**行から改名を始めた時はリストを開いてから**入力欄を出す — 入力欄はキーボードを要求し、
キーボードを取った hover のリストはもうポインタのものではない(離れれば打ちかけの名前ごと
消える)。

**開く位置はそのセルの上端で、そこから下へしか伸びない。** 行数がペインの高さを
超えるセクション(タグを数千本打つリポジトリでは常に)を「入るだけ出す」と、
上端から下端までの帯になって**開いた元のセルとどこも揃わない** — 指した印は下の方に
あるのに一覧は画面の一番上から始まり、ポインタは自分が開けたものを探しに行くことに
なる。下端で頭打ちにし、入り切らない行はその中でスクロールさせる。
**下にあるセクションほど席が狭くなるのは承知の上で採る**: 畳んだレールで覗くのは
「目当ての 1 本を探しに行く」ではなく「何が居るかを見る」所作なので、
一度に見える行数より、見え始めが自分の印と揃っていることの方が効く。

**セルのクリックは開いたセクションを閉じるだけで、一覧を戻さない。** ポインタは既に
そのセルに居るので、**開いたものを手で消す最短の席はそこ**(もう一度押せば開く — hover は
できない。ポインタが動いていないので何も変わらない)。**戻す所作をここに置かない** — 畳んで
いるのは大抵 diff を開いているからで、一覧を戻す所作は**その diff を閉じる**(下記)。
覗くつもりのクリックが読んでいたファイルを畳んでしまう。戻す席は帯のブロック 1 つで足りる。

**中身が 0 のセルは開かない。** 開いても行が無く、行が無ければそこから出来ることも無い —
見出しの帯だけが出てくるのは、数字が既に言ったことをもう一度言うために画面を取ることになる。
セルは**居なくならず、0 を数えたまま無効になる**(§無効: 印と数字を `textMuted` へ落とし、
地と枠はそのまま、**hover の重ね色を出さない**)— 数えられるものは 0 でも数える価値があり、
消してしまうと「無い」と「そんなセクションは無い」が同じ見た目になる。**`*Dim` ではなく
`textMuted`** — 落としているのは種別ではなく可否で、暗くした種別色は「押せない」を言わない
(§暗く落とした段)。**別のセクションが開いている時に 0 のセルへポインタが乗ったら、
開いていた方は閉じる** — 開いたままだと、そのリストが今ポインタの下にあるセルのものに見える。

**タグをグラフに出すかの切り替えは目**(`eye` / `eye-off`)。旗ではない — 旗は
コミットに付ける目印で、それは**タグ自身が既にやっていること**。切り替えているのは
「見るかどうか」なので可視性の語彙(レイヤー一覧の目)から採る。出ている = 開いた目、
出ていない = 斜線の入った目 + `refTagDim`(**色の 2 段だけにしない** — アイコンの大きさでは
状態として読めない)。**畳んだ間はレールの TAGS セルのアイコンの右上に同じ目が乗り**、
出ていない時は**乗らない**(この大きさで斜線は潰れる)。切り替えそのものは hover で開いた
見出しにある。

**diff を開いている間は畳む。** ファイルの中身に使える幅と行数を増やすためで、
**ref の一覧はその画面でファイルについて何も言わない**唯一のもの。閉じたら
**diff が畳んだ分だけ**を戻す — 自分で畳んでいた人は畳んだままにする(手が触れた
時点でその判断は手のものになる)。

**一覧と diff は同時に画面を持たない。** 畳んだ一覧を戻す所作は、開いている diff を
閉じてグラフへ返す — 一覧を呼び戻すこと自体が「読み終わった」の合図であり、戻ってきた
一覧が語るのはグラフに並ぶものだから。**戻す経路はすべて同じ**(帯のブロックと、改名の
入力欄がリストを呼び戻す時)で、例外は作らない — 例外があると「どの開き方なら diff が
残るか」を覚える羽目になる。**hover の peek と、それを閉じるセルのクリックは対象外**:
畳んだままなので diff は 1px も失わない。閉じた diff は覚えない(もう一度読むならファイル行
から開き直す)。

### 未コミット変更がある状態での移動

**持っていく。何も尋ねない。**
移動はまず `git switch` をそのまま実行する — 邪魔にならない変更は git が
運び、邪魔になる場合は**何も変えずに拒否**する。拒否された時は、手で打つのと
同じ順番で回り直す:

```
stash push -u  →  switch  →  stash pop --index
```

**問いを立てない。**拒否の時点でリポジトリは無傷で、この 3 手の着地は
どれも**画面に出るもの**(移動先の作業ツリー / conflict の付いたファイル行)か
**stash が戻せるもの**しかない。失うものが無い所に確認を挟むと、本当に危ない
場面での確認の効き目まで削る(§可否・警告の出し場所)。

着地は 3 通りで、**どれも専用の表示を持たない** — 手で 3 つのコマンドを打った
人が見るものと同じものを見る:

| pop の結果 | 画面 |
|---|---|
| きれいに戻った | 移動先に居て、変更もそこに在る。stash は消える |
| conflict した | conflict の付いたファイル行(§conflict の ours / theirs)。**stash は残る** |
| 未追跡が置いていかれた | 追跡分は運ばれ、置いていかれた分は stash に残る。git の文言がコマンドログに出る |

**conflict した時に stash が残るのは git の仕様**で、それを説明する文言は
どこにも置かない — STASHES の件数が増えているのが見えており、コマンドログの
`The stash entry is kept in case you need it again.` が git 自身の言葉で
言っている。**画面に既に在るものを言い直さない**(§長さ)。

**「置いていく」の選択肢は持たない。** 置いていきたい人は先に stash を取る
(WIP ペインの `Stash…`)。移動の側に選択肢を積むと、日常の移動が毎回二択に
なる。

`switch --merge` は使わない。stash 経由が二つの点で勝るため:

- **staged / unstaged の区別が残る**(`--index`)。`switch --merge` は index に
  何か staged があると衝突ファイルでなくても拒否するので、事前に index を
  空にするしかない
- **conflict した時に stash が残る** = 戻る手段がある。`switch --merge` の
  conflict は成功(exit 0)として着地し、マーカーを残したまま abort する merge も
  無い

staged 側が衝突して `pop --index` が丸ごと拒否された場合のみ `--index` 無しで
やり直す — この時だけ区別が失われる。

**tree が空になっても拒否されたら、そこで止めて戻す**(`--skip-worktree` の
ファイル等、stash が越えられないもの)。stash を pop で戻し、git の最初の
拒否文をそのまま出す。

### 未コミット変更がある状態で履歴を書き換える

**持っていく。何も尋ねない。****履歴を書き換える操作は全部同じ形**
— ブランチ単位の `rebase` onto も、`squash` / drop(と先端以外の
メッセージ編集)も、git は作業ツリーが汚れていると**何も触らずに拒否する**。
移動と同じ順番で回り直す:

```
rebase  →  stash push -u  →  rebase  →  stash pop --index
```

**まず素のまま撃つ。**「汚れているか」をアプリが先に判定しない — 判定の
規則は git のもので、写すと必ずずれる(§可否・警告の出し場所と同じ理由で
`branch -d` の判定を持たないのと揃える)。**未追跡ファイルは邪魔にならない**
ので、それしか無い木では 1 コマンドで済み stash は取られない。**拒否の文言は
素の rebase と `rebase --interactive` で同一**(実測)なので、この 3 手は
どちらの書き換えにも 1 つで足りる。

**`--autostash` は使わない。決め手は 1 つだけ** — git の autostash は素の
`stash apply` で戻すので、**staged だった分が全部 unstaged で返る**。
`--index` を渡す口は無く、設定でも変えられない。これは
§未コミット変更がある状態での移動 で `switch --merge` を捨てたのと同じ理由で、
**同じアプリの中で「この書き換えなら staging が残り、あの書き換えなら消える」を
作らない**。**渡す口自体を持たない**(`RebaseOptions` に autostash のフィールドが
無い)ので、この不変条件は約束ではなく構造が守る。

**捨てているものも書いておく**(実測。**autostash が劣るのはこの 1 点だけではない、の逆**):

- **autostash は `--continue` / `--abort` の後に git が自分で戻す** —
  こちらの stash は止まった時に残り、**戻すのは人**。**これは意図した差で、
  「止めた stash を覚えておいて操作の後に自動で戻す」は足さない**。止まった
  書き換えは人がまだ決着を付けていない状態で、そこへアプリが黙って作業ツリーを
  書き戻す方が危うい — conflict を解決し終えた直後にもう 1 回 conflict を
  落としに行くことにもなる。失われてはいない(STASHES とグラフの stash 行が
  画面に出ている)。**autostash へ倒す話でもない**
- 止まっている間、autostash は **porcelain から見えない**(`stash list` は空・
  `refs/stash` 無し)。ただし `.git/rebase-merge/autostash` は**普通のコミットの
  oid** で `git stash show` も効くので、**見せられないのではなく作れば見える**。
  不可視は理由として軽い
- **gc では消えない**(`gc.pruneExpire=now` + `gc --prune=now` を撃っても生き残り、
  その後の `--abort` が復元する)。fsck は `dangling commit` と言うが実害は無い

着地は 3 通りで、**どれも専用の表示を持たない**(移動の表と同じ考え):

| 書き換えの結果 | 画面 |
|---|---|
| 通って、きれいに戻った | 書き換えた履歴と、そこに在る変更。stash は消える |
| 通って、戻す時に conflict した | conflict の付いたファイル行(§conflict の ours / theirs)。**stash は残る** |
| 途中で止まった | 進行中の操作のバッジと出口カード(§進行中の操作から出る)。**作業は stash に入ったまま**で、STASHES とグラフの stash 行がそこに在ることを言う |

**止まった時に戻さないのは git がそうさせないから** — unmerged のある
index へ git は書かず、`pop` は何もせずに「conflict した」と報告する。
戻すのは操作が終わってからで、それは**同じ 3 コマンドを手で打った人が
居る場所と同じ**。

**拒否はコマンドログを開かない**(§git が言ったことを読む場所)— アプリが
回り直す合図であって失敗ではないから。**止まった時は開く**: ログを持ち上げる
のは書き込みの答えの側で(終了コードで答えるコマンドは自分では持ち上げない)、
その答えには git が止まった時の文言が入っている。

### ブランチを過去のコミットへ戻す

コミット行の右クリックメニューにサブメニューとして出す。

| 場面 | UI 文言 | 内部コマンド |
|---|---|---|
| 現在ブランチを移動(サブメニューの親行) | `reset` **`<branch>` here** | `git reset` |
| 変更を staged のまま残す | `--soft` **Keep everything, staged** | `--soft` |
| 変更を unstaged にして残す | `--mixed` **Keep everything, unstaged** | `--mixed` |
| 変更を捨てる(長押し行) | `--hard` **Discard everything after it** | `--hard` |

`reset` は git 内部でも「ブランチ移動」と「index からの取り消し」の二役を持ち、
後者は本書で既に **Unstage** と呼んでいる。移動側はコマンド名そのものを
親行の動詞に置く — `reset` のチップに `<branch>` here が続く読み
(§git 用語のコード表記)。コマンド名を言うのは親行の 1 度だけで、
各行に残るのは**フラグのチップ**(`--soft` / `--mixed` / `--hard`)と、
**残るのか捨てるのか**で言い分ける文。`reset --soft` を知っている手には
行とコマンドの対応が一目で付き、知らない目には文だけで足りる — チップは
文の一部ではなく、行の隣に置かれたコマンドそのものである。

「to this commit」ではなく「here」なのは、指しているコミットがメニューを開いた
その行だから — 行が自分で示しているものを文言で言い直さない。メニューは行に幅を
合わせるので(§メニュー)、短さのために語を削る必要は無い。

出す条件(いずれかを欠いたら、サブメニューごと出さない = それを開く行も消える):

- ブランチ上にいる(detached HEAD には動かすブランチが無い)
- 進行中の操作が無い — `--soft` は merge 中に拒否され、`--mixed` / `--hard` は
  黙って `MERGE_HEAD` を捨てて merge を中断する。抜け道は Continue / Abort
- 対象が stash 行でない(stash はどのブランチの履歴でもない)
- 対象が現在ブランチの先端でない(移動にならない)

同意は **`--hard` だけ、その行そのものの長押し**(§長押し) — stash の削除と
同じ判断で、グラフへ降りる質問バーは 1 行の問いには機構が過剰、長押しは手が
既に居る場所で同じことを言う。行の言葉が所作(Hold)と失うもの(everything
after it)を一度に言い、色は触れる前から `danger`。soft / mixed はファイルの
中身を 1 バイトも捨てない(ブランチが動くだけで、コミットし直せば元に戻る)。
`--hard` が未追跡ファイルに触れない旨の 1 行はバーと共に退いた — メニューの行は
§長さ の内に収まる分だけを言う。

### 変更を退避する(stash)

| 場面 | UI 文言 | 内部コマンド |
|---|---|---|
| 作業ツリー全体を退避 | **Stash…**(WIP ペインに開くオプションカード) | `git stash push` |
| 1 ファイルだけ退避(ファイル行の右クリック) | **`stash`**(コード表記。行はチップで終わり、複数選択時はタグが件数を言う = §メニュー) | `git stash push -- <path>` |
| 未追跡も含める | **Include files git is not tracking yet** | `--include-untracked` |
| index はそのまま残す | **Leave the staged changes staged** | `--keep-index` |
| index の分だけ退避 | **Only the staged changes** | `--staged` |
| 退避したものを戻す | **Apply**(残す) / **Pop**(消す) | `stash apply` / `stash pop` |
| 退避したものを捨てる(行の右クリック) | **Delete**(長押し) | `git stash drop` |

**Stash** は git 用語のまま採る。「退避」に当たる短い英語(Shelve / Park)は
どれも他ツールの独自語で、STASHES セクション・stash 行・switch 時の説明文が
既に同じ語を使っている以上、ここだけ言い換えると同じものが二つの名前を持つ。

「未追跡も含める」は**既定でオン** — 新しいファイルだけ置き去りにされるのが
stash で最も驚かれる挙動で、switch 時の自動 stash も `-u` で揃えている。

**「Only the staged changes」は、同じファイルが index と作業ツリーの両方で
変更されている間は無効化**して理由を添える(git は stash エントリを作った上で
作業ツリーの除去に失敗し、エントリだけ増やして終わる — 実測)。
「未追跡も含める」との併用も git が拒否するので同時に無効化する。

退避には確認を出さない。stash は何も捨てず、退避したものは STASHES に見える。
**捨てる時だけ長押しで取る** — 中身は他のどこにも残らない(§左メニューの所作 の削除表)。
その行は**左メニューの stash 行とグラフの stash 行のどちらからも**同じ言葉で出る。
`Apply` / `Pop` を右クリックに重ねないのは、行を選べば右のペインに出るため
(§メニュー)。

**conflict した `Pop` は失敗として出さない。** 戻す作業自体は済んでいて、
残っているのは settle するだけ — そして git はこの時エントリを消さないので、
**着地は `Apply` と同じ**(変更は作業ツリーに在り、戻る手段も一覧に在る)。
画面は conflict の付いたファイル行で、それ以上は何も言わない。

判定は**終了コードではなく作業ツリー**で行う。`stash pop` は「conflict した」と
「何もしなかった」を同じ非ゼロで返すため。ただし**元から conflict していた木は
除く** — git は unmerged なファイルがある index へは戻さず丸ごと拒否するので、
後に残っている conflict は元のものであって、戻せた証拠にならない(実測)。

### リモートから取り込む(fetch)

**fetch について言うことは全部 Fetch ボタンの上で言う。** 別のインジケータを隣に
置かない — 同じ 3 状態(走っている / 失敗した / 止まった)を 2 箇所が語ると、
読む人の目を 2 度動かすだけで情報は増えない。

| 状態 | 見た目 | 押せるか |
|---|---|---|
| 通常 | **`fetch`**(コード表記) | ○ |
| 取り込み中(手動・タイマーどちらも) | 語が消えて中央のリング。**リングと枠は上の 3 状態それぞれの色の 1 段下**(§進行中) | ×(耳も塞ぐ。`enabled` は落とさない) |
| 1〜2 回続けて失敗 | **`fetch`** + チップの右端の後ろに `!`、`warning` の文字と枠 | ○ |
| 3 回続けて失敗 | **Resume**(通常表記・チップ無し)+ `danger` の文字と枠、`!` は消える | 長押しのみ |

**数えるのは「連続して失敗した fetch」で、誰が頼んだかは問わない。** ボタンが
語っているのは取り込みそのものの調子であって、タイマーの調子ではない。
**成功が 1 回入れば数は 0 に戻る**(手動の成功でも戻る — でなければ、押して通った
ボタンが「前回失敗」を出し続けることになる)。

**3 回で auto fetch を仮に止める。** ネットワークが戻らない機械が毎分手を伸ばし
続けるのを止めるため。**止まったことは操作しないと解除されない**ので、これは
§状態 の `danger`(今止まっている)に当たる。**語は `Resume`** — 止まっていたものを
続きから戻す、が起きることそのもの。`sync` 系の語は使わない(この製品は pull を
持たないのに、他の GUI では sync が pull+push を指す)。**この状態だけチップが
外れる**のは、戻すのが自動 fetch であって 1 回の `fetch` ではないから
(§git 用語のコード表記)。

**auto fetch が設定で off の時は赤へ行かない。** 止めるものが無いので何も止まって
おらず、ボタンが差し出せる新しい手も無い。何回失敗しても黄のまま。

**最初の失敗だけコマンドログを開く**(§git が言ったことを読む場所)。2 回目以降は
同じ知らせで、オフラインの機械では毎分パネルが飛び出すことになる。

**fetch と push は同じ幅の箱に入れる。** 隣り合っていて、互いに関係なく語が変わる
(`fetch` ⇄ Resume / `push` ⇄ `push -f` ⇄ Publish)ので、箱を共有しないと片方の
状態変化がもう片方を横へずらす。箱は**両者の全状態の最長**で測り、
**等幅と通常表記が混ざる**ので、どちらの書体で測ったものが勝ったかも一緒に持つ。

### リモートへ送る(push)

**押す前に、送れるかどうかを出す。** ahead / behind は最後の fetch 時点の比較なので
**「送れない」方向にしか信用できない** — 0 でも拒否されうるが、behind > 0 なら
通常 push はまず通らない。ツールバーのボタンは次の状態で見た目を変える。

| 状態 | 条件 | UI 文言 | 押せるか |
|---|---|---|---|
| 初回 | upstream 無し、または追跡 ref がまだ無い | **`push`** | ○(質問が立つ —— §はじめてリモートへ送る) |
| 送れる | ahead > 0 かつ behind = 0 | **`push`**(コード表記) | ○ |
| 送るものが無い | ahead = 0 かつ behind = 0 | **`push`** | ×(理由はツールチップ) |
| 遅れているだけ | ahead = 0 かつ behind > 0 | **`push`** | ×(送る中身が無い) |
| 分かれた | ahead > 0 かつ behind > 0 | **`push -f`**(警告色・警告色の枠) | 長押しのみ |
| 対象なし | detached / ブランチ無し | **`push`** | × |

**ラベルは全状態でコマンド。** 初回を `Publish` と呼び分けない —— 初回を分けている
のはコマンドではなく「行き先を誰も知らない」ことで、それは開く質問が言う
(§はじめてリモートへ送る)。無効の状態でもチップの地は残る
(§無効 —— 落とすのは文字色だけ)。

**リモートが 1 つも無いリポジトリは「対象なし」ではなく「初回」。** 質問がリモートを
作れるので、押せない理由が無い。

**ボタンに数は出さない。** 何コミット先行しているかはサイドバーの `↑N ↓M` と
このボタンのツールチップにあり、ラベルに入れると桁数のぶんだけ幅が変わって
ツールバーの並びが動く。**全状態が同じ幅**(fetch 側と共有する箱 —— §リモートから取り込む)。

数を出す時は**いつ時点のものかを述べる**(`(as of the last fetch)`)。
古い数字を確定情報として読ませない。文にせず括弧で足す(§hover のツールチップ)。

**送れなかったことはボタンが憶えている。** git が push を拒んだら、上の表のどの状態に
居ても **`warning` の文字と枠 + 語の後ろに `!`** を重ねる —— fetch が 1〜2 回続けて
失敗した時と同じ形(§リモートから取り込む)。git の言葉はそのままツールチップの
末尾に足す。**赤へは行かない。** fetch の `Resume` は「アプリが止めた自動の仕掛けを
戻す」段だが、push は誰も勝手には送らないので、止まっているものも差し出せる新しい手も
無い。

**憶えるのは押したブランチについてだけ**で、**そのブランチへ送れた時に消える**
(通った押下が「前回は駄目だった」を出し続けない —— §リモートから取り込む と同じ理由)。
別のブランチへ移れば印は出ない: 拒否の多くは `fetch first` のようにそのブランチと
向こうとの関係の話で、隣のブランチには当てはまらない。**分かれた状態でも `!` は出す**
—— 枠の警告色が言っているのは「分かれている」で、「送れなかった」はそれとは別の知らせ。

### はじめてリモートへ送る(publish)

**行き先を推測しない。** upstream の無いブランチは、どのリモートへ・どの名前で送るかが
どこにも書かれていない。既定のリモートに同じ名前で送るのは推測であって、
**推測が当たらなかった時に取り返す手が無い**(向こうにブランチができ、PR が付き、
それを消すのはこちらからは 2 手目の削除しかない)。だから押した時に**訊く**。

**質問は他の質問と同じバーに立つ**(§立っている質問は 1 か所で聞く)。これを立てる
経路は 3 つある —— ツールバーの `push` / グラフ行 / REMOTES 行 —— ので、
**誰が呼んだかで出る場所が変わると読めなくなる**。

| 場面 | UI 文言 |
|---|---|
| 見出し | **Send `<branch>` where?** |
| 行き先 | 設定済みリモートのドロップダウン。最終行が **Add remote…** |
| 名前 | ブランチ名を入れた入力欄(既定は手元と同じ名前) |
| 同意のピル | **Send** |

- **これは同意ではなく情報を求める質問**なので、**警告色を着ない**(3 つ目の中間色 =
  `accent`)。既存の質問が全部「何かを失う」ものだったので状態色しか無かった
- **バーは常に 1 行。** 行き先の選択と向こうでの名前だけが並ぶ
- **行き先はチップ列ではなくドロップダウン。** fork 運用のリポジトリは複数のリモートを
  持ち、チップは本数だけ横へ伸びてブランチ名を枠の外へ押し出す。リストなら何本あっても
  コントロール 1 つ分の幅で済む
- **リモートの登録はこのバーではなくダイアログ**(§リモートを書き留める)。
  ここへ name + URL を入れると、**リモート自身の名前と URL だけが 2 行目に落ちて
  ブランチ名が行き先の隣に残る** = 括りが逆になる(実測して差し替えた)

#### リモートが 1 つも無い時

**押した時点でダイアログが開く。** 行き先の一覧が **Add remote… の 1 行しか持たない**
状態でバーだけ立てても、選べるものが無い所で「選べ」と言うことになる。**質問は裏で
普通に立ち**(見出しもブランチ名の欄もそのまま)、ダイアログを閉じれば続きに戻る ——
**開き方が違うだけで、最終行を押した時と同じ 1 つの経路**。

- **バーを飛ばしてダイアログだけにしない。** リモートを書き留めることは push ではない
  ので、**書き留めた後に「どのブランチをどの名前で送るか」は依然として未回答**。
  質問が裏に立っているから、Add の直後に**そのリモートを選んだ状態**で続きへ戻れる
- **取り下げても行き止まりにしない。** Cancel / Escape で戻る先は空の行き先を持つバーで、
  最終行を押せば同じダイアログがもう一度開く

#### 相手が答えない時

**「訊けなかった」は「無い」ではない。** URL の誤り・認証・オフラインで `ls-remote` が
届かないことがある。届かなかった時に「無い」と読むのは、**git が拒まないものを
拒むと仮定する**ことなので、**長押しへ倒す**(警告色 + 1 行は
`<remote> did not answer — it may already have that branch.`)。送ること自体は
止めない —— 向こうが本当に何を持っているかは push だけが知っている。

**この読みの失敗ではコマンドログを開かない**(§git が言ったことを読む場所 の
「質問に化けた失敗」と同じ理由 —— バーが既に言っている)。

### リモートを書き留める(remote add / set-url)

**リモートの登録はダイアログ。** これは画面に出ているものについての質問ではなく
**リポジトリの設定**で、§可否・警告の出し場所 がポップアップを許している
「identity の入力・設定」と同じ側にある。呼んだ質問はバーに立ったまま待ち、
**登録されたリモートを選んだ状態で続きに戻る**。

| 場面 | UI 文言 |
|---|---|
| 見出し(追加) | **Add remote** |
| 見出し(URL の訂正) | **Where `<remote>` is** |
| 説明 | Paste the URL of the repository on your host. |
| ボタン | **Add** / **Save** |

- **見出しに冠詞を置かない**(§長さ)。これから作る種類を名乗っているだけで、
  指せる remote はまだ無い。**コード表記も着せない** —— `remote` は名詞であって
  コマンドではなく、チップの有無が「これは git のコマンドか」を語る規則
  (§git 用語のコード表記)がその 1 語で緩む。UI の他の 8 か所も素の英文のまま
- **ドロップダウンの最終行はこの見出しと同じ語**(`Add remote…`)。同じダイアログを
  開く 2 つの入口が違う名前を名乗らない
- **説明は 1 行で、頼むことだけを書く。** 「まず作れ」とは言わない ——
  `the repository on your host` の定冠詞が「向こうに既に在る」を前提として運ぶので、
  順序を命令しなくても前提は伝わる。**`git remote add` が何も contact しないことは
  画面で言わない**(§長さ の因果の説明)—— 誤った URL が判るのは push の時で、
  そこでは push ボタンが黄 + `!` と言い、git の言葉はコマンドログに出ている。
  **この 1 文は追加と訂正で共有する**ので、訂正に来た人へ「作れ」と言う文にはできない
  (そちらは向こうに在るから直しに来ている)
- **リポジトリを作る機能は持たない。** git にリポジトリ作成は無く、public / private は
  git のどこにも無い概念で、それを指定できるのは forge API だけ([要望.md](要望.md) スコープ外)。
  **URL を貼らせる**のが git 縛りでの答え —— forge の Web で作り、URL を持ってくる
- **`git remote add` はネットワークに触らない。** 届かない URL も exit 0 で登録される
  ので、URL の誤りは**後続の push でしか判らない**(実測)。その時**リモートは残す** ——
  残っているものを直すのが復帰で、消してやり直しではない
- **同じダイアログが URL の訂正を兼ねる。** 足すのと直すのは「どちらの欄が既に
  埋まっているか」しか違わない。**名前は訂正では触れない**(改名は左メニューの仕事で、
  両方をここでやると 1 枚が 2 枚になる)
- **既にある名前は入力欄で言う。** git 自身も拒む(exit 3)が、**その拒否はダイアログが
  閉じた後に届く** —— 画面に結び付く先が無くなってから出る文言は読めない
- **名前を `origin` で埋めるのは、リモートが 1 本も無い時だけ**(編集は自由)。clone が
  最初の 1 本に付けていた名前で、ぶつかる相手も居ない。**1 本でもあれば埋めない** ——
  2 本目の名前は当てられるものではなく、prefill は「取られている名前」か「勝手な発明」の
  どちらかにしかならない。**埋めない時は焦点も名前欄に置く**(打つ場所が URL ではない)
- **`origin` としての特別扱いは、その名前を実際に持つリモートに付く。** 既定の行き先は
  一覧から `origin` を名前で引き(無ければ先頭)、prefill を書き換えた人には当たらない
  —— **prefill は特別扱いを配らない**
- **placeholder も同じ規則に従う。** 既に `origin` が在る時は薄い `origin` すら出さない
  —— **Add が必ず拒む名前を提案することになる**。代わりの 2 本目を発明もしない

**プレースホルダは「常に埋まる欄」では死んだ文字列になる。** 名前欄は prefill が
必ず入っていた間ずっと placeholder が一度も出ず、埋めない場合を作った時に**はじめて
画面に出た**。**出さない前提の値をコードに残さない**(出る様になった時に誰も見直さない)。

#### 向こうに既にある名前

**git はこれを拒まない。** 早送りできる限り通常 push は成功し、他人のブランチが
黙って動き、こちらがそれを追跡し始める(実測)。手元の `-d` と違って
「そこにしか無いコミット」を数える材料が無いので、**拒否の代わりを長押しが務める**
(§相手の履歴を置き換える と同じ理由)。

- **弾かない。** 既存のブランチへ足すのは正当な操作(別のマシンから同じブランチを
  続ける / 他人のブランチに乗る)。リモートブランチの**改名**が弾くのは、あちらが
  「新しい名前を作る」と言い切っている操作だから —— ここは違う
- 判定は**リモートに訊く**(`ls-remote --heads <remote> refs/heads/<name>`)。
  最後の fetch 時点の情報ではなく今の答えが要る。**打鍵ごとには訊かない**(打ち終わりから
  350ms)—— ネットワークへ行くボタンを押したのであって、1 文字ごとに行く約束はしていない
- **`refs/heads/` を付けたフルパスで訊く。** 素の名前は ref の**末尾**に一致するので、
  `topic` が `refs/heads/feature/topic` に当たる(実測)
- 答えが返るまで**ピルは押せない**(語だけ落として枠は残す = §無効)。返ってから
  文言・色・所作の 3 つが同時に変わる:

| 答え | 失うものの 1 行 | ピル |
|---|---|---|
| まだ無い | **`<remote>/<name>` does not exist yet; this makes it.** | クリック・中間色 |
| もう在る | **`<remote>/<name>` already exists — your commits go on top of it.** | 長押し・警告色 |

### 相手の履歴を置き換える(force push)

**確認はダイアログではなく長押しで取る**(§進行中・長押しの定数)。分かれた状態でのみ
ボタンが長押しを受け付け、クリックでは何も起きない — 同じ状態で通常 push は成立しないので、
1 つのボタンが 2 つの意味を持つことはない。ラベルは **`push -f`**、文字も枠も警告色で、
「押し続けると `<upstream>` を上書きする」ことと失うコミット数はツールチップで述べる。
`-f` は git 自身の印で、フラグもコマンドの一部として同じチップの地に載る
(§git 用語のコード表記)。

ダイアログを外せる理由は「危険が減ったから」ではなく、**lease が効いているから**。
force は常に `--force-with-lease=<branch>:<画面に出ていた oid>` で撃つので、
**見ていない状態は原理的に壊せない**(相手が動いていれば git が `stale info` で拒む)。
ダイアログに残っていた仕事は「何を失うか告げる」ことだけで、それは behind の数
= 相手が失うコミット数として出せる。

ポインタ以外の導線は**ボタンにタブで入り、Space または Enter を長押し**する
(§進行中・長押しの定数 — 全ての長押しで同じ)。**ここに右クリックの確認ダイアログを
戻さない** — 抜け道が 1 箇所だけ別の作法になり、他の長押しには同じものが無くなる。

### リモートブランチの改名

**git にリモートの改名は無い。** 新しい名前を push して古い名前を消す 2 手で作るので、
**forge から見れば「作成」と「削除」**であり、旧名に付いていたもの(PR・保護ルール)は
付いてこない。**これは手元に取り返しの手が無い書き込み**(もう 1 つは
§リモートブランチを消す — 2 手目そのもの)なので、
確認は force push と同じく**長押しで取る**(§相手の履歴を置き換える と同じ理由)。

| 場面 | UI 文言 | 内部コマンド |
|---|---|---|
| リモートの改名(質問バーの見出し) | **Rename `<remote>/<old>` to `<remote>/<new>`?** | `push <remote> refs/remotes/<remote>/<old>:refs/heads/<new>` |
| 失うものの 1 行 | **The old branch is deleted, not moved.** | `push <remote> --delete <old>` |
| 同意のピル | **Rename**(長押し) | 上の 2 手 + `branch --set-upstream-to` |

- **入口は 2 つ、質問は 1 つ**。REMOTES 行の「間を空けた 2 回目のクリック」で直接、
  または**ローカルブランチの改名の続き**として — upstream があるブランチを改名すると、
  手元の改名が済んだ後に同じバーが降りてくる。手元の改名自体は尋ねない(§左メニューの所作)
- **押すのは追跡 ref であってローカルブランチではない。** 訊かれたのは名前のことなので、
  先へ進んでいるローカルのコミットを一緒に publish しない
- **forge の rename と違う理由は hover のツールチップに置く**(§長押し)。
  バーの 1 行は失うもの(`The old branch is deleted, not moved.`)で埋まっていて、
  「向こうから見れば作成 + 削除で PR は付いてこない」まで載せる場所が無い
- **既にリモートに在る名前は入力欄で弾く。** 存在する名前への通常 push は
  早送りできてしまえば**成功として通る** — git は拒まないので、ここだけは
  「git が知っているから任せる」が成り立たない
- ポインタ以外の導線は他の長押しと同じ(§進行中・長押しの定数)

### リモートブランチを消す

**メニューの行そのものを長押しする** — stash の削除・hard reset と同じ
「手が既に居る場所」の判断(§長押し)。対象は 1 つで、右クリックで開いた行が
それを名指ししているので、グラフの上へバーを降ろす機械仕掛けは要らない。
**git は何も拒まない**(ローカルの `-d` と違い、`push --delete` は
「そのブランチにしか無いコミット」を数えない — 数える材料が手元に無い)ので、
その拒否の代わりを長押しが務める。

| 場面 | UI 文言 | 内部コマンド |
|---|---|---|
| REMOTES 行の右クリック | `push --delete` **Delete** | `push <remote> --delete <branch>` |

- **文言は stash の削除と同じ `Delete`。** 同じ問いを、置かれた場所で
  違う聞き方にしない(§左メニューの所作 の削除表)
- **2 つを分けるのはコードのチップ**(§git 用語のコード表記)。この行だけが
  この機械の外へ出るコマンドを撃つので、git の綴りをそのまま出す
- **行は warning 色**(stash の danger ではない)。捨てるのは手元の作業ではなく、
  届く先がこの機械の外という話だから(§状態)
- **独自の禁止を足さない。** 現在のブランチの upstream でも、リモートの既定ブランチでも
  行は出す — 拒むかどうかを知っているのは**向こうの git** で、拒まれればその文言が出る

### 履歴を合流させる(merge / rebase / revert)

**現在のブランチが必ず文の主語**になる — 変わるのはそれで、右クリックした行は
「どこから持ってくるか / どこへ乗せるか」でしかない。

**文は、その行が自分で示していないものだけを言う**(§メニュー)。**入口が変わっても
文は同じ** — グラフ行でも左メニューの ref 行でも、クリックした側は行が出しているので
言い直さず、名乗るのは現在のブランチだけ。

| 行 | 文 | 出る場所 | 内部コマンド |
|---|---|---|---|
| merge | `merge` into \<current\> | グラフ行 / ref 行 | `git merge <rev>` |
| rebase | `rebase` \<current\> onto it | グラフ行 / ref 行 | `git rebase <rev>` |
| revert | `revert` | グラフ行 | `git revert <rev>` |
| squash | `squash` into parent | グラフ行 | `rebase -i`(その行だけ `squash`) |
| drop | `drop` | グラフ行 | `rebase -i`(その行だけ `drop`) |

- **`merge` / `rebase` / `revert` は git 用語のまま採り、コード表記で出す**
  (§git 用語のコード表記。`cherry-pick` と同じ 1 経路)
- **入口は 3 つ**: 左メニューのブランチ行 / リモートブランチ行 / グラフ行の右クリック。
  merge はタグ行にも出す(固定点を取り込むのは有効)。**rebase はタグ行に出さない**
- **revert は cherry-pick の対**(こちらへ写す / こちらで打ち消す)。同じ場所に並べる
- **merge / rebase / revert はクリック**。前 2 つはコミットを足すだけ、rebase は
  ローカルの履歴書き換えで switch / reset で戻せる(§長押し「ローカルの履歴書き換えは
  尋ねない」)
- **`squash` はクリック**。畳んだ先のコミットに中身は残り、戻す道も switch / reset で
  あるので、取り去る `drop` と所作を揃えない。push 済みなら `already pushed` のタグ
  (§長押し「ローカルの履歴書き換えは尋ねない」)
- **`squash` の文は畳む側を言わず、行き先だけを言う**(`into parent`)。右クリック
  した行が畳む側なので、`reset` の `here` と同じ省き方 — この行だけが**人が指して
  いない 2 つ目のコミット**を文で紹介する必要がある。**行き先の名は `parent`** —
  同じクリックが埋める詳細ペインの `←` リンクが既にそう呼んでいる
  (`Go to parent commit`)ので、語を新しく増やさない
- **drop だけ印を持ちうる**。グラフ行のメニューで**コミットを取り去る唯一の行**で、
  他は足す(merge / revert / cherry-pick)か内容を残したまま書き換える(rebase / `squash`)。
  **`squash` の行の隣に置く** — どちらもそのコミットの居場所を書き換える。
  **範囲に merge があれば core が拒む**(平坦化を黙ってやらない。`squash` と同じ)
- **印は「実行後にグラフから消えるものがあるか」で出入りする**(§長押し。
  `--skip` と同じ、状態で変わる形):

| 今のブランチの先端を | drop | 理由 |
|---|---|---|
| このブランチしか掴んでいない | **長押し** | 書き換えた後は reflog しか届かない(hard reset・stash 削除と同じ立ち位置) |
| 他の ref か stash も掴んでいる | **クリック** | 古い列はグラフに残り、cherry-pick 1 回で戻せる |

  **見るのは先端であってその行ではない。** drop が書き換えるのは
  \<row\>..HEAD で、範囲に merge は無い(core が拒む)から全部が先端の祖先 —
  先端を掴むものは範囲の全部を掴み、掴むものが無ければ先端そのものが落ちる。
  **push 済みのコミットを落としても、上に未 push が乗っていれば長押し** —
  巻き添えになる側が reflog 行きだから。逆に**送り終わったブランチでは
  どのコミットの drop もクリック**になる(`origin/<name>` が先端に居る)
- **リモートは触らないので、向こうから消す同意はここでは取らない** — 消すには
  force push が要り、そちらが自分の長押しを持っている(§相手の履歴を置き換える)。
  同じ 1 操作に門を 2 つ置かない
- **数える相手はグラフが描く tip と同じ**(ローカルブランチ / リモート追跡 ref /
  stash / 先端にちょうど乗っているタグ)。**先端より先に居るタグだけ数えない** —
  実測で walk の 6 倍のコストがタグに乗る([ci/baseline/head-reach-windows-x64.md](../ci/baseline/head-reach-windows-x64.md))。
  取りこぼしは**印が出る側**へ倒れる
- **答えはブランチの性質なので、メニューを開く前に手元にある。** 開いた後に印が
  現れると `AppMenu.holdColW` が全行を字下げし直し、手が既に降りている
  (§長押し「押す瞬間に別の位置へ移るのは事故のもと」)
- **行の色も印と一緒に落ちる。** 失うものが無い時に `danger` を着せない(§状態)
- **rebase は書き換え警告を添える** — `<row>..HEAD` を `publish::state_of()` へ渡し、
  1 件でも push 済みなら `rewrites pushed commits` のタグ(§長さ: 尋ねずに言う)。
  **published は最後の fetch 時点の情報でしかない**
- **出す条件**: ブランチの上に居て(detached では出さない)・進行中の操作が無く・
  行き先が今のブランチ / 今のコミットでないこと。これは reset の条件と同じ形

**既定のフラグ**: rebase が足すのは **`--update-refs` だけ**(積んだブランチが
置き去りにならないため)。**`--autostash` は使わない** — 未コミット変更は
§未コミット変更がある状態で履歴を書き換える の 3 手で運ぶ。この操作だけ
autostash に任せていた頃は、**同じ木で `rebase` onto なら staging が消え
`squash` なら残る**が同居していた。merge は既定のまま(`--no-ff` / `--ff-only` /
`--squash` はブリッジが引数で受けるが、呼ぶ導線をまだ持たない)。

### 進行中の操作から出る

merge / rebase / cherry-pick / revert が途中で止まった時の出口。
**バッジが「今どうなっているか」を言い、出口は WIP ペインに立つ。**

- **バッジ(ツールバー)は状態だけを言う。** 進行中の操作名と、rebase なら進捗
  (`REBASING 1/2`)。**押せない** — 状態の表示であって操作の入口ではない
- **名乗るのは 1 つだけ。** git のフラグを並べない — rebase が pick で止まると
  `CHERRY_PICK_HEAD` も残るので、並べると 1 つの rebase が
  `REBASING · CHERRY-PICKING` を名乗る。**どれが「今の操作」かは core が答える**
  (`integrate::InProgress::from_state`。continue / abort が効く先と同じ答え)。
  bisect だけは併走するので `·` で連ねてよい
- **出口は commit ボタンの真下に、枠付きカードとして立つ**(`OpExitRow`)。
  **押して出すのではなく居座り**、ファイル一覧はその分だけ下へ寄る — 操作が
  止まっている間これはペインの主題であって、一覧を覆う一時的な何かではない
- **理由**: commit ボタンの席は元から「これを終わらせる」場所で、merge の
  `--continue` は実際にコミットを作る。同じ席の続きに出口が並ぶ
- **行はメニューの行そのもの**(チップ = git のフラグ・文 = 何をするか・
  長押しの印。§git 用語のコード表記 / §長押し)。reset のサブメニューを覚えた手が
  そのまま読める。`MenuItem` は Menu の中でしかレイアウトされないので写しを持つ
- **`--skip` / `--quit` を出すかは操作が step するかで決める**(merge だけ出さない)。
  **進捗の件数で代用しない** — 件数を書くのは rebase だけで、step する cherry-pick が
  merge に見える
- **`--continue` は conflict が残っている間だけ暗い**(git が拒むため)

**長押しの印は「その行が何を失うか」に従う**(§長押し)。`--skip` は状態で変わる
(もう 1 つは drop = §履歴を合流させる):

| 状態 | `--skip` | 理由 |
|---|---|---|
| conflict 中 / 解決して staged | 長押し | そのコミットの中身を道連れにし、後は reflog にしか残らない(hard reset と同じ立ち位置) |
| 空になって停止(木がきれい) | クリック + `nothing in it` | git 自身が「空だ」と言って `--skip` を名指ししている。失うものが無い |

**「一致しているから飛ばす」は git が勝手に片付ける** — upstream と 1 バイト違わない
コミットは rebase を止めずに落ち、素の rebase では衝突を upstream 側へ寄せて解決しても
`--continue` が黙って通る(`--empty` の既定が `drop`)。**人が `--skip` を見るのは
interactive rebase が `--empty=stop` で止まった時**(このアプリが squash / reword /
drop で使う経路)。いずれも実測 — `integrate_integration.rs`。

**判定の限界**: 「空で停止」は *conflict 0 + staged 0 + unstaged 0* で見分けている。
**フル interactive rebase の `edit` 停止も木がきれい**なので、それが入る時は
「なぜ止まったか」を core が答える必要がある(P3-確認事項)。

### conflict の ours / theirs

**片側を採る行は、両側をブランチ名で呼ぶ。** `ours` / `theirs` を出さない。

- 「今ここに在る側を残す」= `Keep <branch>'s version`
- 「入ってくる側を採る」= `Take <branch>'s version`

**rebase では 2 つの意味が反転する**(再生されるコミット側が `theirs`、着地する
upstream 側が `ours`)。**その反転は core が吸収する** — `conflict::sides()` が
操作ごとに正しい名前を返すので、**UI は反転を知らないし、読む人も知らなくてよい**。
merge でも rebase でも行は「どのブランチの版か」を言うだけになる。

**名前が取れない側は言葉で埋める**(`this branch` / `the incoming side`)。
どのブランチからも到達できないコミットの cherry-pick では git が名前を持たない。

**どちらもクリック**(長押しにしない)。conflict 中のファイルには確定した版が無く、
失うものがまだ無い — もう片方はこの操作を continue するまで 1 クリック先に在る。

**メニューは光っている行すべてに効く**(§その他の操作と同じ。git 実行は 1 回)。

### conflict の種別

**種別の文言は「両側が何をしたか」を言う。** 「Conflicted」では
どちらの手を選べばよいか判らない。git の 2 文字コードから引く:

| コード | 文言 |
|---|---|
| `UU` | Both changed it |
| `AA` | Both added it |
| `DD` | Both deleted it |
| `DU` | Deleted on \<ours\>, changed on \<theirs\> |
| `UD` | Changed on \<ours\>, deleted on \<theirs\> |
| `AU` | Added on \<ours\> only |
| `UA` | Added on \<theirs\> only |

片側だけの話をする行は**その側をブランチ名で呼ぶ**(上記と同じ 1 経路)。
**バケツ名を後ろに足さない** — 文が既に conflict のことしか語っていない。

**この文を出す場所は diff ペインだけ**(行を持たない `DU` / `UD` / `AU` / `UA`
で出る 1 文)。**ファイル行の衝突アイコンには付けない** — 行全体を覆う
`MouseArea` がその上に在るので、アイコンに乗せた hover は一度も届かない
(§hover のツールチップ)。アイコン側でも言いたくなったら、覆っている
`MouseArea` に「どの区画に居るか」を報告させる形になる。

### conflict の diff

**conflict 中のファイルの diff は、両側と同時に比べた 1 枚**(git の combined diff)。
作業ツリーのファイルがそのまま出るので、git が書いたマーカー行も本文として並ぶ。

**行の色は git 自身の規則に従う** —— どこかの列に `+` があれば `diffAddedFg`、`-` があれば
`diffRemovedFg`、全部空白なら素(`color.ui=always` で実測)。**その色は「どちら側か」を
言えない** —— ours 由来の行も theirs 由来の行も、相手側に無いという同じ理由で緑になる。

**どちら側かは行頭の帯が言い、色はグラフのレーン色を借りる。** 帯は `spaceXs` 幅で、
そのブランチがグラフで着ている色(`Theme.graphLane` のレーン色)そのもの。**diff 専用の
対色を作らない** —— ブランチの色は既にグラフが決めており、2 つ目の色体系を持つと
同じブランチが場所によって違う色になる。**ペイン先頭の 1 行が色と名前を結ぶ**
(小さな色見本 + ブランチ名、`fontSm` / `textSecondary`)。

**借りられない側は補うが、2 つが同じ色になることは無い。** グラフはウィンドウ
(`--max-count`)なので窓の外のブランチには色が無く、パレットは 8 色で巡回するので
離れた 2 本が同色になりうる。**ここで黙ると、色が一番要る場面で色が消える**ので補う:

| 状態 | 決め方 |
|---|---|
| 両側に色があり、違う | そのまま |
| 両側に色があり、同じ | **ours を保護し theirs を 1 つずらす**(§conflict の ours / theirs で ours = 既に在る側) |
| 片側に色が無い | 在る側はそのまま・無い側は**ブランチ名から引く**(衝突すれば同じくずらす) |
| 両側に色が無い | 両方とも名前から引く(同上) |

**「名前から引く」は乱数ではない。** 同じ conflict を開き直すたびに色が変わると
ノイズになり、ヘッドレスの PNG も毎回変わって目視での Done 判定が成立しない。
名前の FNV-1a を同じパレットへ落とす(識別アイコンの色と同じ手)。

**名前が無い側にも色は出す。** 帯が言うのは「2 つのうちどちらか」で、名前の話は
先頭の 1 行がしている(そこは `this branch` / `the incoming side` で埋まる)。

**行番号は左 = ours・右 = 作業ツリー。** theirs 由来の行は左が空く。

**分ける道具は出さない。** combined diff は patch ではなく `git apply` が受け付けないので、
`Stage hunk` / `Discard hunk` / 行の `+` は当たる先が無い。残るのはヘッダの
`Mark resolved` 1 語で、**新規ファイルと同じ形**(§diff の中のステージ)。
core 側の floor は `stage::refuse_combined`。

**片側しか残っていない conflict は diff を持てない。** `DU` / `UD` / `AU` / `UA` は
index に片側の版しか入らないので比べる相手が無く、git は patch の代わりに
`* Unmerged path <path>` の 1 行だけを出す。**ペインは種別の 1 文だけを出す**
(`textMuted`。文言は §conflict の種別 の表と同一 —— ファイル行のアイコン hover と
**同じ 1 か所**から取る)。**「diff がありません」と言わない** —— 種別の文が既に理由を
言っている。

### conflict を外部ツールへ渡す

**内蔵の conflict エディタは持たない**(要望.md スコープ外)。設定済みのツールを
開けるようにするだけで、**無ければ利用者が自分で直す**前提に立つ。

- **入口は片側採用の 2 行の直後の 1 行**。どれも「この衝突をどう解くか」の行で、
  区切りの上に並ぶ。設定済みなら `Edit in <tool>`、**未設定なら同じ文のまま
  スロットが空く** = `Edit in <merge editor>…`(git のヘルプと同じ山括弧の
  プレースホルダ)。**行は状態で書き換わるのではなく、埋まるか空くかだけ**が変わる。
  `…` は「押すと質問が立つ」の語彙のまま(§長押し)で、山括弧が「何が入るのか」を言う。
  **前置詞句に裸の名詞を置かないための形でもある** — 冠詞の規則(§長さ)は動詞の直接
  目的語の話で、`Edit in merge editor` は英語として壊れる。
  **`Open in` にしない** — 上 2 行が「このファイルがどうなるか」を言うのに、そこだけ
  「窓がどうなるか」へ主語が移る。**`Open` はこのアプリではリポジトリ / タブの語**でも
  ある(`Open repository` / `Open %1 in a new tab`)ので、同じ語が 2 つの意味を持つ。
  **ツール名にコード表記のチップを着せない** — 同じメニューの `stash` が「これはコマンド」
  の意味でチップを着ており、config の値に同じ形を与えると印が 2 つの意味を持つ
  (§git 用語のコード表記 の「コマンドと 1 対 1 の時だけ」)。
  **暗くしない** — `textMuted` は「押せない」の合図(§無効)で、未設定はむしろ押してほしい
  状態。差を語るのは色ではなく**先頭の動詞**(`Edit in` / `Choose`)で、`not set` のような
  タグも足さない(行が既に示していることを言い直さない = §メニュー)。
  **語は飛んだ先のラベルと揃える**(設定の `Merge editor`)
- **ツールの変更はメニューに置かず設定へ。** メニューは開くまで中身が見えない導線で、
  滅多に使わない行が 1 本増えるコストを毎回全員が払う(§メニュー)。**行の中で設定
  したい項目が 2 つ目に達したら**、その時点で行末の副アクションを作り既存分ごと移す
  — 1 項目のために機構を新設しないだけで、形が否定されたわけではない
- **待ちは `CONFLICTS` 見出しの右**(他のバケツで `Stage all` が座る席)。
  **`Waiting for <tool>` + 回るリング**で、**`…` は付けない** — 進行中を言うのは
  リングの仕事(§進行中・長押しの定数)。**点が増える演出も採らない**(同じ意味に語彙が
  2 つ増え、テキスト変更は GUI スレッドで動く = リングをレンダースレッドに置いた理由を
  捨てる)。**押せるものは置かない**: 止められるのは `git mergetool` だけで、それが
  起動したエディタは生き残り、後片付けもされない
- **解決の着地点は 1 つ。** ツールが直せば git 自身が `git add` まで済ませ、外部
  エディタで直して戻った人は行の `+` を押す。**「解決済みにする」専用の行は置かない**
- **設定は git の持ち物だと言う。** どちらも保存されるが置き場所が違う —
  fetch 間隔はアプリが自分のファイルに書き、これは git が覚えて同じ計算機の
  他の git からも見える。説明の 1 行がその差を引き受ける
- **受け付ける条件は「GUI かどうか」ではない。** 満たすべきはマージツールの約束
  (`$LOCAL` / `$REMOTE` / `$BASE` を受け取り `$MERGED` を書く)だけで、**与えていない
  コンソールを要求しないこと**が唯一の制約(`CREATE_NO_WINDOW`)。窓を持つツールでも、
  窓を持たないスクリプトでも通る — 落ちるのは端末に描く vimdiff 系だけ。
  **文言でツールを「windowed」と言わない**
- **候補は出すが、フィールドは自由入力のまま**(`AppCombo`)。打てる名前は候補より
  常に広いので、一覧は**打つ手間を省く近道**であって値の定義ではない。
  **既定を推測して提案することはしない** — 無ければ自分で直す、が前提
- **候補は 2 波で届き、遅い方を待たせない。** 自前定義(`mergetool.<名前>.cmd`)は
  数十 ms、git が同梱定義を総当たりして「入っているか」を見る `--tool-help` は
  **Windows で約 8 秒**(レジストリと Program Files の走査)。速い方を先に出し、
  **遅い方が出ている間は矢印の席でリングを回す** — 空の一覧に矢印だけが立っていると
  「無い」と読めるが、本当は「まだ」だから
- **候補が届いても入力欄の値は動かさない。** ComboBox は model が差し替わると
  `currentIndex` を先頭へ寄せて文字列を道連れにするので、8 秒後に着いた一覧が
  設定済みの名前を書き換えてしまう。**値を動かしてよいのは人だけ**
  (行の選択と `textEdited`。焦点やポップアップの開閉では判別できない)
- **端末に描くツールは候補から外す**(§conflict を外部ツールへ渡す の条件)。
  判定は git 自身が説明文に付ける印で、**外し損ねるより外し過ぎる方を採る** —
  打てば通るので取り返しがつく。**自前定義は絞らない**(書いた人が選んだもの)

### その他の操作

| 場面 | UI 文言 | 内部コマンド |
|---|---|---|
| 変更を index へ | **Stage** | `git add` |
| index から戻す | **Unstage** | `git restore --staged` |
| 変更を捨てる(ファイル行の右クリック) | **Discard**(長押し) | `git restore --worktree` |
| 未追跡ファイルを消す(同じ 1 行・同じ文言 + タグ `the file goes`) | 同上 | `git clean -f -d` |
| staged 側も含めて捨てる(staged 行の同じ 1 行 + タグ `both sides`) | 同上 | `git restore --staged --worktree` |
| hunk を捨てる(diff の hunk 見出し) | **Discard hunk**(長押しボタン) | `git apply --reverse`(`--cached` 無し) |
| amend で著者を引き継ぐ | **Make me the author** | `commit --amend --reset-author` |
| 進行中操作の継続 | **Continue** / **Abort** / **Skip** | `--continue` / `--abort` / `--skip` |

**staged の帯は 0 でも立つ。** 行が 1 つも無いバケツは見出しを持たないので、何も
ステージしていない間、ペインは**ステージした先がどこか**を一度も言わない
(`Commit changes (0 staged)` はその 0 を数えるだけで、0 が置かれる場所は画面に無い)。
`STAGED FILES (0)` を一覧の末尾に立てたままにして、最初の `+` で帯が手の下から
生えないようにする。**空の帯の `Unstage all` は無効**(§無効 — 画面に居続けるものは
席を空けず、そこで押せないと言う)。**unstaged 側は立てない** — そちらは一覧の先頭で、
無ければ staged の帯が上へ詰むだけ = 席は動かない。**作業ツリーがきれいな時も立てない**
(一覧が丸ごと空で、`(0)` が何の見出しにもならない)。

**捨てる行は 1 つで、どの行で開いたかが中身を決める。** conflict 以外のどの行にも
同じ `Discard` を出す — 読み手の意図はいつも「このファイルに起きたことを
無かったことにする」で、未追跡ファイルは**その存在自体が変更**なので、消えるのが
正しい取り消しになる。**文言も同じ**で、変えるのは**行末の警告タグだけ**:

| 開いた行 | タグ | 何が起きるか |
|---|---|---|
| unstaged | 無し | ディスク側だけ。**staged 分は残る** |
| untracked | `the file goes` | ファイルごと消える |
| staged | `both sides` | 両側とも HEAD へ。新規追加はファイルごと消え、リネームは元の名前へ戻る |

**部分ステージの切り分けは 2 行そのものが担う** — 同じファイルが unstaged と staged に
1 行ずつ出るので、「staged 分は残す」も「まとめて捨てる」も**どちらの行で開くか**で選べる。
リネーム行は**元の名前も一緒に渡す**(片方だけ restore すると相手側が staged の削除として
残る — 実測)。行が示しているファイル名は言い直さない。

**同意は行そのものの長押しで取る**(§長押し)。質問バーは出さない — 対象は右クリックした
その行 1 つで、失うものは行の言葉とタグに収まる。**捨てる中身を先に見たいなら、
順序が逆になるだけ**: 行を左クリックすれば中央がその diff になり、読んでから
右クリックして長押しする。

**複数行はまとめて選べる。** WIP のファイル一覧は、素のクリック = その行 1 つ、
**Ctrl クリック = 出し入れ**、**Shift クリック = 直前の行からの範囲**。選ばれた行は
`bgSelected`。**選択を増やすクリックは diff を動かさない**(読む行を選んでいるのではなく、
操作の対象を選んでいる)。右クリックが選択の外に落ちたら、その行だけが選択になる —
**メニューは常に「光っている行」に効く**(`stash` / `Copy paths` / `Discard`)。
複数選ばれている時はタグが件数を言う(`3 files`)— 行ごとに違う話を 1 つのタグへ
押し込まない。**数えるのは書き込みが触るファイル**(`RepoPage.menuFileCount` =
`chosenRows()` の本数)で、**光っている行の数ではない** — フォルダ行も選べるが
このメニューのどの行もフォルダには効かないので、鍵の数を出すと**誰も触らない
1 件をタグが数える**ことになる。

**行末の `+` / `−` も同じ範囲に効く。** メニューだけが選択を見て、行末の印は 1 行しか
動かさない、という割れ方をしない。効くのは**押した印と同じ側の行だけ**(`+` は staged で
ない行を index へ、`−` は staged の行を戻す)—— 混ざった選択で、行けない向きの行まで
動かさないため。**選択に入っていない行の印は、その行だけに効く**。

**その範囲は押す前に見える。** 印にポインタが乗ると、**一緒に動く行の印も同時に出る**
(件数を言う場所が行末には無いので、代わりに動く行そのものが名乗る)。

**まとめても git の実行はバケツごとに 1 回**(unstaged / 未追跡 / staged で最大 3 回)。
パスはブリッジへ 1 件ずつ渡してから 1 回の書き込みで消費する(`beginPaths` / `addPath`
→ 書き込みスロットが取り出す)— git のパスは NUL 以外のどのバイトも含み得るので、
1 本の文字列に詰める区切りが無い。

**もっと細かい切り分けは diff の中にあるが、捨てる側は hunk で止める。** hunk 見出しの
`Stage hunk` の隣が `Discard hunk`(**unstaged 側だけ** — staged 側は隣のボタンで
戻してから捨てる)。質問バーは出さない: ボタンはその hunk 自身の見出しに載っているので、
何を失うかは立っている場所が言っている。`--cached` を付けないので index は一切動かない
= ここでも「staged 分は残す」が保たれる。

**見出しの中の 2 つは同じ形をした語で、枠を持たない。** `Discard hunk` はツールバーの
長押しボタン(枠 + 枠を満たす塗り)ではなく**メニューの held row と同じ形** — 印 +
`danger` の語で、押している間は地が端から端まで塗られる。見出しは他の語が並ぶ行なので、
1 語だけを囲む枠は外れた箱に見える。`Stage hunk` / `Unstage hunk` は**ファイル行の
`+` / `−` と同じ色の対**(`diffAddedFg` / `diffRemovedFg`)— 同じ操作を一覧と見出しで
違う声で呼ばない。**その色を出す条件は §diff の中のステージ**。

**行単位はステージだけ**(行の `+` / `−` と、選んだ行を数える見出しの語)。
**捨てる方は行単位を持たない** — 素の `×` には失うものを書く場所が無く、文字を
持てない的を長押しにはしない(§長押し)。1 行だけ戻したいなら、その行以外を
ステージしてから hunk を捨てる。**選択があっても `Discard hunk` は hunk のまま** —
語の席はできたので `Discard 3 lines` は作れるが、出すかどうかは未決定。

**conflict 中の path には出さない**(git が restore を拒む)。
**追跡済みファイルをディスクから消す導線は持たない**(他ツールはこれを
「delete file」として出す)— それは取り消しではなく新しい変更で、消したいなら
消してからステージすればよく、`git rm` は取り消せる操作の側にいない。

### diff の中のステージ

**ステージは 4 段あり、語尾がスコープを名乗る**: `Stage all`(バケツの帯)/
`Stage file`(diff ペインのヘッダ)/ `Stage hunk`(hunk 見出し)/
`Stage this line`(行の四角のツールチップ)。

**常設の色語は `Stage file` の 1 つだけ。** diff ペインのヘッダの語は対の色
(`diffAddedFg` / `diffRemovedFg`)を **`fontMd`** で持つ —— ペイン見出しの `fontSm` より
1 段上。hunk 見出しの 2 語は **`fontSm`**(スコープの大小を大きさでも保つ —
ファイルの語より 1 段下)で、**休息時 `textSecondary`・ポインタが乗った見出しだけ
本来の色**。

理由は数。1 ファイルの hunk 数は**中央値 2 / p90 8 / 最大 25**、同時に画面へ出る
hunk 見出しは**中央値 2 / p90 3 / 最大 4**(実測 52 ファイル)。全部を色付きで灯すと、
**ファイル 1 件をステージする語 1 つ**より**hunk の語 2〜4 つ**の方が強くなり、
スコープの大小と目に入る強さが逆になる。色は「今どれが主役か」を言う軸として使う。

**休息時は `textSecondary`。** これは `diffHunkHeaderFg`(`@@` の文字色)と同じ値なので、
見出しは `@@` から語まで 1 本の灰色の行になる。**`*Dim` は使わない**(§暗く落とした段 —
文字を暗くするのは無効の合図)。実測でも 2 段下げた赤 `#DC2626` は地 `#0F172A` に対して
**3.70:1** で、`textMuted`(無効)の **3.75:1** と同じ明るさに落ちる。`textSecondary` は
6.96:1 で、hover しなくても何が置いてあるか読める。

**長押しの印は色を変えても残る**ので、灰色でも `Discard hunk` が押し切る方だと分かる。

**ポインタが乗った見出しは、その hunk の行すべてを `bgHover` で照らす。** 語が色を変えるだけでは
`@@` とボタンの間が地のままで、行が 1 本につながって見えない。hunk 全体を照らせば
**ボタンが何を持っていくか**が同時に出る。照らすのは**見出しに乗った時だけ** —— 行に
乗っているのは読んでいるのであって、hunk を狙っているのではない。

**行の印は `+` / `−` で、枠を持たない。** 色は対のまま(`diffAddedFg` / `diffRemovedFg`)で、
**言うのは書き込みの向き**であって行が何をしたかではない —— 追加行も削除行も、
unstaged 側では同じ `+` でステージされる。地はポインタが連れてくる `bgHover` だけ
(枠を付けるとこの大きさでは「外れた箱」に見える)。

**行は 1 クリックで 1 行ずつ選ぶ。** 選ばれた行は**行頭の `accent` の帯**(`spaceXs` 幅)+
`bgHover` で示す —— diff の地は追加 / 削除の色が持っているので、選択を塗りで示さない。
**選択のある hunk の見出しは、語が `Stage 3 lines` / `Stage 1 line` に変わり、
ポインタが無くても本来の色で灯る**(選択は立っている状態なので、語も立ったままにする)。
変更行以外をクリックすると選択は下りる。**書き込みは選択ごとに 1 回**(パスの集合と
同じ形でブリッジへ渡す)—— 1 行ずつ撃つと、その都度 diff が作り直されて残りの行が動く。

**新規ファイルの diff は分けられないので、分ける道具を出さない。** リポジトリが初めて
見るファイル(未追跡 / 追加してステージ済み)は **hunk が 1 つ・全行が追加**なので、
`Stage hunk` はヘッダの `Stage file` を 1 段小さい声で言い直したもの、行の `+` はそれを
行数ぶん繰り返したものにしかならない。**hunk 見出しの 2 語(`Stage hunk` / `Discard hunk`)も
行の `+` も出さず**、ポインタが乗っても行は照らさない(狙う先が無い所で光る地は、無い
offer を出す)。残るのは**ヘッダの `Stage file` 1 語**で、これがそのまま**この diff で
できることの全部**になる。ステージ済み側も同じ(`Unstage file` だけ)。

**削除されたファイルは新規ではない。** 全行が `−` でも、その行は**古い側に在る** —— 一部
だけをステージする意味があるので、道具は出したままにする。判定は「新しい側があって古い側が
無い」(`encode::is_new_file`)。

**diff の作り直しで画面を飛ばさない。** 同じファイルを読み直す時は**古い行を消さずに
待つ**(消すと往復の間ペインが空になり、長い diff では更新ではなく点滅に見える)。
読み終わったら**元の位置へ戻す**(`Metrics.anchorDelayMs` 待ってから —— 行が届いた
フレームではまだレイアウト前で `contentHeight` が古い)。

**読んでいた側が空になったら diff を閉じる。** unstaged / staged / 未追跡は**別々の
diff**(`git diff` / `git diff --cached` / 全追加として描く)で、ステージしたものは
未ステージ側から消える。最後の 1 つが向こうへ渡ると、残るのは空の枠に生きた
`Stage file` が載った状態 —— 立っている理由が消えているので閉じる(左メニューが
戻ると diff が閉じるのと同じ規則)。**閉じるのは書き込みの後の読み直しだけ**で、
最初から中身の無いファイルを開いた時ではない。画像・バイナリは**行が 0 でも中身
なので閉じない**。

**ペインヘッダは下端を `borderSubtle` の 1px で閉じる**(全ペイン共通)。`bgElevated` と
`diffHunkHeaderBg` は**同じ値**なので、hunk 見出しで始まる diff ではヘッダと見出しの
境目が消え、`Stage file` と `Stage hunk` が 1 つの箱に同居して見える。左メニューの帯は
元からこの hairline で閉じている(入力欄のフォーカス時だけ `borderFocus`)。

**Make me the author** は、HEAD の author が現在の identity と違う時だけ
amend パネルに出す。git は committer だけを書き換えて author を残すので、
他人のコミット(や別 identity で書いた自分のコミット)を amend した時にしか
選ぶ意味が無い。付けると author date も now になる。

### コミットメッセージの 2 つの枠

**summary は `textPrimary`、description は静止 `textSecondary`・打っている間だけ
`textPrimary`。** 枠は 4 つ(詳細ペインの reword と WIP の commit 欄が summary /
description を 1 対ずつ)で、どれも同じ規則。段差はメッセージ自身の階層 —— 一覧でも
グラフでも先に読まれるのは subject の方で、本文はその下に付く。

**caret の入った枠は落とさない。** `textSecondary` は本書が「今読ませたい所ではない」に
割り当てている段(§テキスト)で、**打鍵している当の文字がそこに居ると、書いたそばから
薄い = 無効の枠に見える**。summary が状態によらず `textPrimary` なのと、打っている間の
description が同じ値になるのは同じ理由 —— 手が居る所がそのペインで最も明るい。

**上げる条件は「打てる状態でフォーカスがある」。** stash と現在の履歴の外のコミットは
枠が読み取り専用で、そこに立つ caret は選択のためのもの = 何を打っても入らない。
フォーカスだけを条件にすると、**書けない枠が「書けます」の色になる**。

### 署名の表示

**「署名状態」は別の 2 つで、出す場所も分ける** — 既にあるコミットの**検証結果**と、
これから作るコミットが署名されるかの**設定**。

**検証結果は詳細ペインの author カード、名前の真右**(枠なし・`fontSm`)。
**名前にくっつける** — 名前を `Layout.maximumWidth: implicitWidth` で頭打ちにし、
余りは印の先の `Item` が取る。付けないと名前が余白を全部取って**印がハッシュの
隣まで飛び**、どちらの持ち物か読めなくなる(2026-08-08 に報告)。名前が長い時は
**名前が縮んで印が残る**(印は席を譲らない)。

**日付の隣ではない** — その行は co-author が使う(§co-author の表示)。名前の行は
`wrongwrong` のような 1 語しか使っておらず余りがあるのに対し、日付の行に 3 つ目を
足すと**左カラムの実寸 244px を日付・署名・co-author で奪い合い、後から入った
co-author が切れる**(実測: 日付 98 + co-author 101 = 207px で余り 37px、そこへ
`✓ Verified` の 59px は入らない)。

**git の 8 つの答えを 3 段に畳む。形は 2 つ、色が 3 つ**:

| 出るもの | `%G?` | 色 |
|---|---|---|
| ✓(語なし) | `G` | `success` |
| ✓(語なし) | `E` / `U` / `X` / `Y` / `R` | `textSecondary` |
| ! `Bad signature` | `B` | `danger` |
| 何も出さない | `N` | — |

**通った署名は印だけ、壊れた署名だけが言葉を持つ。** 常に出る側を最小にし、
**`Bad signature` だけが行の中で大きい**というズレは意図的 — あれはエラーメッセージで、
1 行に 1 つだけ大きいものがあるのは読み手にとって正しい重み付けになる。

**形が「署名が在る」を、色が「誰が保証したか」を言う**(経路を 1 つずつ =
§ref の種別 と同じ割り当て)。同じチェックでも、`success` は git が保証した署名、
`textSecondary` は**読めたが判定できない**署名。**緑は検証済みに取っておく** —
SSH は `allowedSigners` 未設定だと全ての署名が後者に落ちるので、そこを緑にすると
**設定していない人の画面では全部が「検証済み」に見える**。git の言い分
(鍵が切れている / 誰も保証していない等)は hover の 1 行が言う。
**灰色のチェックは無効の合図ではない**(§無効 が落とすのは文字で、これは印)。
**無署名は無表示** — 普通の状態に印を付けない(状態バッジと同じ規則)。
**署名の有無を `%G?` だけで判定しない**(SSH は allowedSigners 未設定だと
無署名と同じ `N` を返す。core が `cat-file` で見分ける)。

**検証は詳細と別に投げる**(gpg / ssh-keygen が動くので詳細ペインの 100ms 予算に
乗らない)。答えは**どのコミットの話かを名乗り**、選択中のものと一致した時だけ読む。
初期状態が無表示なので遅れて出てもチラつかない。**答えは持ち回らない** — 選択が
動けば捨て、同じ行へ戻ってくれば投げ直す(外部プロセス 1 回分で、詳細の表示は待たない)。

**設定は commit 欄の予告** — Amend チェックの行の右端に `will be signed`
(`textSecondary`。事実であって警告ではない)。**根拠は `commit.gpgsign` だけ**で、
`tag.gpgsign` を混ぜない(コミットの話をしている場所なので)。**値打ちは
「押すと pinentry が出るかもしれない」を先に言うこと** — 署名鍵の passphrase は
アプリが受け取らない(gpg-agent / ssh-agent へ委譲)ので、そこで止まる理由が
画面のどこにも無いと死因が判らない。同じ席に立つ `already pushed` が優先する
(1 つしか入らない席で、警告が事実に勝つ)。

**署名の有無でツールバーにバッジを出さない** — あそこは対処が要る状態の席で、
正常に効いている設定を常時出すと本当の警告が薄まる。

### アバターを与える

**著者の顔は「与えられた画像」か「名前から生成した identicon」のどちらか**で、
**どちらも同じ円・同じ輪**を着る。一覧が顔の列として読めることが条件で、
誰か 1 人に画像を与えた途端に列が揃わなくなる、が最悪。

**画像は取りに行かない**(§絶対制約)。gravatar 相当のサービスが無い代わりに、
**利用者が自分のディスクから選んだ 1 枚を取り込む**。これが identicon の役目を
肩代わりする唯一の経路。

**取り込んだ 1 枚はその場で作り直す**(`platitude-core::picture`)。**中央の正方を
切って 1 辺 256px の PNG にし、保管庫が持つのはそれだけ**(元のファイルは読むだけ)。
写真そのものを抱えると 1 人あたり数十 MB が常駐し、顔は 20px と 40px でしか描かれない
——実測は [ci/baseline/avatar-shrink-windows-x64.md](../ci/baseline/avatar-shrink-windows-x64.md)。
**正方に切るのは意匠の要請でもある**: 顔は円にクリップされるので、切らなければ
4:3 の写真が円の中で横に潰れる。**切る位置は常に中央で、選ばせない**(設定カードの
中だけで完結する — §設定の入口は 1 つ)。**受け取るのは png / jpeg**(判定は中身で、
拡張子ではない)。**アニメーションは持たない** —— GIF を受けても静止画にしかならず、
それは GitHub のアバターと同じ振る舞いなので、受けずに png / jpeg と言う方が正直。

**鍵はアドレス**(小文字化 + `.mailmap` 適用)。名前は変わるし被るし、
1 つのリポジトリの中で 3 通りに綴られる。**同一人物の名寄せは `.mailmap` に委譲**
し、自前で持たない — git が既に持っている答えを 2 つに増やさない。

**出る場所は 3 つ**: 詳細ペインの author カード(`detailsAvatar` = 40)/
設定カードの一覧(`iconLg` = 20)/ **グラフの全ノード**(`nodeIcon` = 20)。
「与えたのに出ない場所がある」を作らない。

**設定の入口は 1 つ、行き方が 2 つ。** 画像の割り当て・差し替え・削除は
**設定カードの Avatars 一覧の中だけ**で完結する。もう 1 つの行き方は
**詳細ペインの顔そのもの**で、ポインタが乗ると**ペンのバッジ**が立ち、押すと
**設定カードがその人を名指しした状態で開く**(入力欄に `Name <address>` が入り、
フォーカスは `Choose image…`)。**間にメニューを挟まない** — 押した先で
できることは一覧の中に全部あり、途中の 1 行はただの停止。

**バッジは顔の正方形の右下角にフラッシュ**(`iconSm + 2×borderWidth` = 14 の丸に
`iconSm` のペン)。**位置はこれが上限**で、隠れる量を減らすレバーは寸法だけ
(実測の被覆率: 18px = 15.4% / 16px = 11.2% / **14px = 7.5%**)。
**顔に author が無い行には出さない**(WIP 行・未読の行)。

**一覧は表**(§レイアウト初期値と同じ考え): 顔 / 名前 / アドレス / `Remove` の
4 列で、**名前の列は全行で幅を共有**する(`AppMenu.codeColW` と同じ形)。
名前の長さが揃わなくてもアドレスの開始 x が揃う。

**`Remove` は長押し**(§長押し)。書き込みが即時で、取り消す Save も Cancel も
無いのが理由。**ポインタが乗っていない行では `dangerDim`、乗った行で `danger`**
—— 消さずに暗く落とすのは、N 人ぶんの赤い語が縦に並ぶと
**状態色は出現数が少ないほど効く**(§状態)が壊れるため。列の席は常に確保して、
ポインタが横切ってもアドレスの省略位置が動かないようにする。

**設定カードのボタンは `OK` 1 つ。** 画像は名前を指した瞬間に書かれるので、
Save が残りの 2 つだけを支配するのは**カードの半分についてしか本当でない**。
入力欄は**編集が終わった時点**(フォーカスが外れる / Enter / 一覧から選ぶ)で
書き、**Escape と `OK` は同じ出口**。Cancel が無い以上「破棄」が意味を持てる
操作が存在しない。

### co-author の表示

**コミットが誰かを併記していたら、詳細ペインの日付の隣に出す** —
`<日付>` `<identicon>` `<名前>` `+N`。identicon は `iconMd`、名前と `+N` は
`fontSm` の `textSecondary`(日付と同じ = その行はメタ情報)。
**居なければ何も出ない**(普通の状態に印を付けない = 状態バッジと同じ規則)。

**author の下でも横でもなく、日付の行に置くのは、それが事実だから。**
commit object が持つ author は 1 人で、残りは**メッセージ末尾の
`Co-authored-by` trailer** = 本文中の申告にすぎない。名前の行に
`<author> + <co-author>` と並べると git が持たない「著者 2 人」を名乗ることになり、
専用の行を立てると**このリポジトリでは 96% のコミットに常設の行が増える**。

実測(2026-08-08、この 2 リポジトリで):

| | platitude-gg | sealed-class-enumizer |
|---|---|---|
| co-author を持つコミット | 345 / 361 = **95.6%** | 247 / 322 = 76.7% |
| 1 コミットあたりの人数 | **0 か 1 人のみ**(2 人以上は 0 件) | 同左 |

**`+N` に畳んで先頭 1 件だけ名前を出す**のはグラフのチップと同じ語彙で、
**人数が増えても行の幅が動かない**。全員は hover で開くカードに出る
(`CoAuthorCard` = `RefListPopup` と同じ地・枠・行高)。**カードには
アドレスを添える** — 同名の別人を見分ける手掛かりがそれしか無く、author 名の
hover が `<email>` を出しているのと揃う。**この形は詳細ペインだけのもの**
(グラフ行の hover カードは下記)。

**グラフ行の hover カードでは、同じ人たちをコンマで書き並べる** —
`<日付>` `<名前>, <名前>, <名前>`。`fontSm` の `textSecondary` は同じで、
**顔も `+N` も下線も無く、何も開かない**。本当に確かめる場所は右のペインで、
preview が 2 枚目のポップアップを生やすと preview がペインの顔をし始める。

**同じ記録を 2 通りに書くのは、置かれる部屋が違うから。** ペインの日付行は
実寸 ~230px で全員は書けず、そこでの顔は **author のアバターと対**になって
顔の列に見える。hover カードには画像が 1 つも無く(author も日付も文字)、
**顔はカードで唯一の色相**になる — 実測(1440×900、3 人のコミット):
カード全体のインク 5,222px のうち色は identicon の 94px だけで、それが
4 行のうち最も重要でない行に乗る。1 人の行で比べると **1,041px(うち色 94)→
870px(色 0)**、行の幅も **207px → 187px**。

人数の実測(2026-08-09、ローカル 5 リポジトリ = 145,969 コミット):

| 人数 | 件数 | credit されたコミット中 |
|---|---|---|
| 1 人 | 1,238 | **97.6%** |
| 2 人 | 28 | 2.2% |
| 3 人 | 2 | 0.16% |
| 4 人以上 | **0** | 0% |

**コンマ列の実在最長は 49 字**(kotlin の
`Roman, Abduqodiri Qurbonzoda, alexander-gorshenev`)。`+N` が言っていた人数は
**溢れた時だけ言えなくなる**が、4 人以上は 1 件も無く、全員を名乗るのはペインの
仕事なので受け入れる。

**幅はメッセージが決め、credit 行は残りを取って省略する。** カードの幅を
決めるのは subject / body / author の 3 行(いずれも上限はペインの半分)で、
**credit 行は自分の幅をその計算に入れない** — 人数の多いコミットだけカードが
横に伸びると、preview が中身で形を変えることになる。**床だけは持つ**:
「名前が必要とする幅、ただし `messageMinW` まで」で、短い subject の
カードでも 1 人は名乗れ、既に足りている時に空白は増えない。

**ペインの下線は静止 `borderStrong` / ポインタが乗ったら `textSecondary`。**
常時引くのは「ここは開ける」を hover 前に言うため(だから開かない hover カードの
方には引かない)、静止で 1 段落とすのは日付と競らせないため。
`borderStrong` は §暗く落とした段 が「`textSecondary` を 2 段下げると
`#475569` = 既存の `borderStrong` になるので足さない」と既に名指ししている値で、
**トークンは 1 つも増えていない**。上げ先が名前と同じ値になるのは
ハッシュのプレートが hover で下線を出すのと同じ所作。**線は identicon から
`+N` までを 1 本で通す**(ハッシュとコピーアイコンが 1 本を共有するのと同じ =
2 つで 1 つの的)。

**trailer 行は Description 枠から外さない。** あの枠は reword の編集器で、
外すと**枠の中身と保存されるメッセージが食い違い**、そこから co-author を
消すことも直すこともできなくなる。見た目の差が出るのは**本文が 1 行も無い
コミットだけ**(実測 25 / 363 = 6.9%)で、本文があれば最短のものでも
折り返しで枠(120px = 実質 5 行)が埋まり、末尾の trailer はどちらにせよ
画面に出ない。

**co-author に mailmap は効かない。** author / committer は `%aN` / `%aE` で
名寄せされるが(§アバターを与える)、trailer は git がそのまま返す文字列なので、
**同じ人が author の時とで綴りが割れうる**。identicon も別の絵になる。
git が持っていない答えなので、当面はそう見えることを受け入れる。

### author の hover

**author の名前に乗ったら、名前の直下にカードを開く。**中身は顔・名前・アドレスの
1 ブロックで、**`CoAuthorCard` の行と同じ形**(同じ地・枠・行高・同じ字下げ)。
ペインは人を 2 通りに書かない。**本体はアドレス** — 同名の別人を見分ける手掛かりは
それしか無く、co-author カードがアドレスを添えるのと同じ理由(§co-author の表示)。
**名前を書き直すのは省略の巻き戻し**でもある(ペイン側は実寸 ~230px で elide する)。

**ツールチップをやめた**。`ToolTip` は文字列しか置けないので顔が入らず、出る位置は
style が決め(名前の**上**に出て Description 枠を覆っていた)、**地は Fusion 既定 =
ダークテーマの外の色**。カードは §hover のツールチップ の 4 つの罠(位置・
`HoverHandler` を `background` へ・`hoverKeepMs` の閉じ待ち・自分をリサイズしない)を
co-author と同じ実装で満たす。

**committer は、author と別人の時だけ 2 つ目のブロックとして出す**
(普通の状態に印を付けない = §状態)。**別人かはアドレスで決める**(§アバターを
与える と同じ鍵。mailmap 適用後の綴りが届く)。**この 1 行を落とすと、誰が置いたかは
アプリのどこにも出なくなる** — 珍しい状態ではない(2026-08-09 実測):

| リポジトリ | コミット | 別人が置いた | 後から置かれた | どちらもない |
|---|---|---|---|---|
| JetBrains/kotlin | 138,915 | **47.5%** | **89.9%** | 6.7% |
| kotlinx.coroutines | 3,110 | 47.5% | 34.3% | 31.4% |
| jackson-module-kotlin | 3,188 | 16.8% | 9.2% | 74.9% |
| sealed-class-enumizer | 322 | 11.5% | 9.6% | 79.2% |
| platitude-gg | 383 | 0% | 23.2% | 76.8% |

別人の 1 位はどのリポジトリも `GitHub <noreply@github.com>`(web の merge / squash)、
2 位以下は patch を取り込んだメンテナ本人。

**時刻は、人か時刻のどちらかが食い違ったら 2 つ揃えて出す** —
`authored <日時>` / `committed <日時>` を `fontSm` の `textSecondary` で、
アドレスの下に。**片方だけにしない**: 日付行が出しているのは author の時刻で、
**カードはその行を覆って開く**ので、比べる相手が画面から消える。
**語の幅は 2 つで共有**して日時の頭を揃える(`AppMenu.codeColW` と同じ手)。
同じ人が後から置いた時(amend / rebase)は**1 人のブロックに 2 行**が付く。

**語は git のものをそのまま小文字で**(`authored` / `committed`)。行の tag
(`not merged` / `both sides`)と同じメタの声で、`Author:` のようなラベルは置かない
—— ラベルは名前が既に言っている。

**下線は静止 `borderStrong` / ポインタが乗ったら `textPrimary`** — co-author の行と
同じ語彙(§co-author の表示)で、上げ先が名前自身の色になるのも同じ規則。
**平常時に増えるインクはこの 1px だけ**。

**相対時刻(`3 days ago`)を混ぜない** — 日付行が絶対時刻なので、同じカードに
物差しを 2 本持ち込むことになる。**author 側のタイムゾーンは未決**(core は epoch
しか持っていない = `%at`。出すなら core の読みごと変える。P3-確認事項)。

## アプリアイコン

OS に出る顔。**本書のトークンだけで構成し、アイコン専用の色を作らない**。

| 部位 | token | 値 |
|---|---|---|
| 地(タイル) | `bgElevated` | `#0F172A` |
| 縁 | `borderStrong` | `#475569` |
| 幹のレーン | `accent` | `#3B82F6` |
| 枝のレーン | `graphLane[1]` | `#E69F00` |

図は**窓を開いた時に見えるもの** = 2 本のレーンが分岐して合流する形。実体は
`crates/platitude-app/assets/` の 2 ファイルで、**サイズで使い分ける**。

| サイズ | ファイル | 中身 |
|---|---|---|
| 16〜20px | `platitude-16.svg` | 同じ図を、線を太らせ・ノードの比を詰めて描いたもの |
| 24px 以上 | `platitude.svg` | 幹 + 枝 + コミットノード 3 つ |

**切り替えは目で決めていない。** マスターの縁は `3/64` なので 21px 未満で 1
デバイスピクセルを割り、線は 16px で 1.25px まで痩せる。小サイズ版はそのぶん
太らせる(`1.8/16` = マスターの 1.44 倍)。

**それでもノードは落とさない。** 一度落として線の丸端で代用したところ、幹が
ただの棒になり**別のアイコンとして読まれた**(実際にそう見えて差し戻した)。
比を詰めて残す — 線の 2.1 倍(マスターは 2.2 倍)。

**重なりは幹が上。** 枝を後に描くと合流点で幹が 2 つに切れ、それが 16px で
最も強く出る。両サイズとも枝 → 幹 の順で描く。

**縁は意匠ではなく可視性の要件。** 地の `bgElevated` は Windows のダークタスクバーに
対して **1.10:1**、Ubuntu の Dock に対して **1.04:1** で、縁が無いと輪郭がその地に
溶ける(`bgBase` でも 1.24 / 1.08)。`borderStrong` が **2.15 / 2.46** を持つ。逆に
**明るいタスクバーを持たせるのは暗い地の方**(**16.09:1**)で、線だけのアイコンは
そちら側で沈む(`accent` 単色で 3.31)。**地と縁の両方を持つ**のはこのため。

**枝に `warning` / `danger` / `refTag` を使わない。** それらは UI の中で状態と種別を
名乗っており、看板に恒常的に出すと意味が薄まる。`graphLane` は本書の中で何も名乗って
いない識別色なので席が空いており、しかも視認性は上(`#E69F00` が暗地 **7.23** に対し
`warning` は **5.11**)。

**外部の意匠を持ち込まない。** git の公式ロゴ(CC BY 3.0 = 帰属表示が付いてくる)も、
他の git クライアントの形も使わない。線とノードは `NavIcon` の `branch` を引き直した
もの。

**3 OS ぶん焼いてある**(`crates/platitude-app/assets/` の PNG 10 サイズ・`.ico`・
`.icns`、`packaging/` の `.desktop` と `Info.plist`)。**動いているのは Windows だけ**で、
mac / Linux はバンドルとパッケージを組む段で繋がる — 手順と未決事項は
[P5-確認事項.md](P5-確認事項.md)。
