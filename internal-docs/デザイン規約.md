# platitude-gg デザイン規約

UI の色・タイポグラフィ・寸法の**正本**。QML を書く前に読み、必要な値を表から選ぶ。

本書の目的は見た目の理想を語ることではなく、**実装時に数値を考える余地を無くすこと**。
「12px と 13px のどちらが良いか」「余白をあと 2px 詰めるか」を検討してはならない。表から引いて終わりにする。

## 絶対ルール

- 値は本書の表にあるものだけを使う。**表に無い数値・色・フォント名を QML に書かない**
- 微調整目的で中間値(1px 刻み・中間色)を新設しない。ズレて見えるなら「グリッド外の値が混ざっている」のが原因なので、そちらを直す
- 見た目を詰めるためにビルド・スクリーンショットの往復をしない。表どおりに書いた時点で完了とする
- 表で表現できない要求に当たったら、その場で値を発明せず**人間に確認する**(本書へのトークン追加として扱う)
- 用途が近いトークンの流用より、正しい用途のトークンを使うことを優先する。それでも該当が無ければ上記の確認へ

### 状態

段は 3 つ。**分ける軸は「取り返しがつくか」ではなく「波及するか / 止まっているか」**。
このアプリに取り返しのつかない操作はほとんど無い(force push は常に lease 付き、
reset も switch で戻せる)ので、可否で切ると `danger` を使う操作が無くなってしまう。

| token | 値 | いつ使うか | 例 |
|---|---|---|---|
| `success` | `#16A34A` | 成功・ahead | staged・PR あり |
| `warning` | `#D97706` | 次のいずれか — **自分の外へ波及する**(他人が持っている履歴・リモートが変わる)/ **進行中で対処が要る** / **答えを待っている** | Push -f・already pushed・MERGING・SET IDENTITY・detached HEAD・質問バー・未保存の質問 |
| `danger` | `#EF4444` | **今止まっている・失敗した**、および**手元の成果を捨てる** | conflict・git のエラー・Discard everything after it |

**この 3 つに当てはまらない知らせに状態色を使わない。** 読まなくても操作が進むもの
(仕様の説明・静かに失敗しているだけの通知)は `textSecondary`。状態色は出現数が
少ないほど効くので、「一応目立たせておく」で足さない。

`danger` が「もう起きた失敗」と「これから捨てる操作」を兼ねるのは意図的。
どちらも**その場で止まって読ませたい**もので、片方を別の色に割ると赤の意味が薄まる。

### ref の種別

グラフのチップとサイドバーの見出しで ref の**種別**を示す色。**状態の 3 段とは
別の軸**なので `warning` / `danger` を流用しない(タグが警告に見えるのがこの事故)。

| token | 値 | 用途 |
|---|---|---|
| `accent` | `#3B82F6` | ローカルブランチ |
| `textSecondary` | `#94A3B8` | リモートブランチ |
| `refTag` | `#D946EF` | タグ(チップ・TAGS 見出しアイコン) |
| `warning` | `#D97706` | detached HEAD マーカー(種別ではなく状態なので状態色。**サイドバーとグラフで同じ色**) |

**種別色が塗るのは枠とアイコンで、ref の名前は塗らない。** チップから読むものは
2 つ(**何であるか** / **何処に在るか**)なので、経路を 1 つずつ割り当てる —
**枠 = 種別、名前の色 = 在処**。サイドバーの行は既にこの読み方で、名前は
`textPrimary`、種別は見出しアイコンの色が持つ。グラフ行で最も読ませたい文字は
ref の名前であり、枠が既に言っていることにその可読性を使わない
(`bgSurface` 上のコントラスト: `accent` 5.5:1 / `refTag` 5.2:1 に対し
`textPrimary` 16.4:1)。

| 名前の色 | 意味 | 出る先 |
|---|---|---|
| `textLink` | **今ここに立っている** | 現在のブランチの名前(左メニューの行・チップ・hover カード・ツールチップ) |
| `textPrimary` | ここに在る | ローカルブランチ・ローカルにも在るタグ |
| `textSecondary` | リモートにしか無い | リモートブランチのチップ・リモートにしか無いタグ |
| `warning` | detached | HEAD マーカーのみ(種別ではなく状態なので名前にも出す) |
| `textMuted` | 行き先にならない(§無効) | hover カードの HEAD マーカー行 |

**現在のブランチは、名前が出る場所すべてで `textLink`。** サイドバーの行だけが
その色で、チップ・カード・ツールチップでは他のブランチと同じに見える、が起きていた。
同じ名前が場所によって「ここ」に見えたり見えなかったりするのは、この列が答えている
問い(何処に在るか)への答えが場所ごとに変わることを意味する。**行き先にならないことを
理由に `textMuted` へ落とさない** — 現在のブランチが押せないのは「使えない」からではなく
「もう立っている」からで、それは在処の話。落とすのは HEAD マーカーだけ(ref ですらない)。

**重なった時は現在のブランチが先頭。** 1 行に複数の ref があるとき、チップが名前を出す
1 件・カード・ツールチップの並びはいずれも **現在のブランチ(detached なら HEAD マーカー)
→ ローカル → リモート → タグ**。並べ替えは core で 1 回だけ行う(`build_label_map`)。

**リモートを `textMuted` まで落とさない。** リモートのみの行にはダブルクリックで
行ける(ローカルを作って移動する)ので、`textMuted` =「押せない」(§無効)は嘘になる。
コントラストも 4.2:1 で、この文字サイズでは低すぎる。
チップ内の `+N` は名前ではなく件数なので `textSecondary`(行の他のメタ情報と同じ)。

`refTag` は Tailwind `fuchsia-500`。CUD 検証(Machado 2009 severity 1.0 の
1 型 / 2 型 / 3 型シミュレーション + CIEDE2000)で、同じ列に並ぶ色との最小差は
**13.4**(`accent` / 2 型)。本書が既に許容している最小差は **8.8**
(`warning` × `danger` / 3 型、`accent` × `textLink` / 3 型)なので、それを上回る。
地(`bgSurface`)に対するコントラストは 5.83:1。
レーン色との最小差は 8.6(lane 6 `#0072B2` / 1 型)だが、レーンは別の列の細線であり、
識別を色だけに依存させない方針(§コミットグラフのレーン色)で担保する。
検討した他の候補(violet / purple / cyan / teal / pink 系)はいずれもこれを下回った。

### 無効(disabled)

**押せないものは押せないように見せる**。無効の合図は文字色を `textMuted` に落とすことで、
背景・枠は変えない(ホバーの重ね色は無効時に出さない)。強調ボタン(Commit / Save)は
面のアクセントも `accentMuted` へ落とし、「今押すもの」に見えない状態にする。

実装はウィンドウの `palette` 1 箇所で足りる — コントロールは自分の状態に合う色グループ
(`active` / `inactive` / `disabled`)を自動で引く。ただし**グループを付けずに代入した色は
全グループへ入り、バインディングとしてグループ側の代入より後に確定して上書きする**(実測)。
状態で変わる役割は 3 グループ全てに書き、変わらない役割だけをグループ無しで書く。
`inactive`(ウィンドウ非アクティブ)は `active` と同じ色にする — 焦点の有無は見せない。

disabled グループの割り当て:

| palette の役割 | token | 効く先 |
|---|---|---|
| `text` | `textMuted` | メニュー項目・入力欄 |
| `windowText` | `textMuted` | チェックボックスのラベル |
| `buttonText` | `textMuted` | ボタン・ツールボタン |
| `brightText` | `textMuted` | 強調ボタンのアイコン |
| `highlightedText` | `textMuted` | 選択面の上の文字 |
| `highlight` | `accentMuted` | 強調ボタンの面 |

`contentItem` を自前で書いたコントロール(`ActionButton` 等)は palette を経由しないので、
同じ規則(`enabled ? textPrimary : textMuted`)を自分で書く。

| token | 値 | 用途 |
|---|---|---|
| `diffAddedFg` | `#4ADE80` | 追加行の文字 |
| `diffAddedBg` | `#052E16` | 追加行の背景 |
| `diffRemovedFg` | `#F87171` | 削除行の文字 |
| `diffRemovedBg` | `#450A0A` | 削除行の背景 |
| `diffHunkHeaderFg` | `#94A3B8` | `@@` 行の文字 |
| `diffHunkHeaderBg` | `#0F172A` | `@@` 行の背景 |
| `statusStaged` | `#16A34A` | staged |
| `statusUnstaged` | `#D97706` | unstaged |
| `statusUntracked` | `#64748B` | untracked |
| `statusConflict` | `#EF4444` | conflict |

変更種別(ファイル行のアイコン)は**種別軸**であって状態の 3 段ではない —
追加 = 緑 / 削除 = 赤 / 移動 = 青 と同じ並びに、変更 = 琥珀が入る。
`statusUnstaged` は値としては `warning` と同じだが**別トークン**で、
QML からは必ず `statusUnstaged` を参照する(`warning` を流用しない)。
値が同じことは意図した重複で、意味の重複ではない。
`statusConflict` と `danger` も同様の関係(conflict は状態でもあるので値が一致する)。

### シンタックスハイライト(P5 実装)

自前のトークン配色は**定義しない**。syntect が読む TextMate テーマ
(`.tmTheme`、MIT 系ライセンスのもの)を P5 で選定して同梱し、
トークン前景色はテーマに委ねる。背景・行ハイライトは本書の `bg` 系・
diff 系トークンを維持する(テーマ側の背景色は使わない)。

### コミットグラフのレーン色

`graphLane` は下記 8 色の配列。レーン番号を要素数で剰余して循環させる。
**Okabe-Ito パレット**(色覚多様性対応の標準的なカテゴリカル配色)を採用し、
黒のみダーク背景で不可視のため明灰 `#DDDDDD` に置換している。

`#56B4E9` / `#E69F00` / `#009E73` / `#CC79A7` / `#F0E442` / `#D55E00` / `#0072B2` / `#DDDDDD`

色覚差への配慮を色選定(Okabe-Ito)と冗長化の両面で行う: レーンの識別を
色だけに依存させない(位置・接続線の形状でも判別できること)。

## 進行中・長押しの定数

| 定数 | 値 | 用途 |
|---|---|---|
| `spinMs` | 1000 | 通信中インジケータの 1 回転 |
| `holdMs` | 800 | 長押しで確定する操作の押下時間 |

- git が**ネットワークに出ている間**は、押したボタン自身のアイコンを回す。
  進捗率は出さない — git の進捗は人間向け出力で、機械可読形式のみをパースする規約に反する
- 回転は `RotationAnimator`(レンダースレッド)で行う。GUI スレッドがモデルの drain で
  詰まっても止まらない
- **自動化中(`PG_SHOT_DIR` 指定時)は静止させる**。回っているものを撮ると
  スクリーンショットが毎回違う画像になる

長押しは**押している間ずっと意思が要る**ことを使う確定手段。惰性のクリックでは起きない。
`holdMs` の間押し続けると発火し、途中で離せば何も起きない。

見た目は**枠と、その枠を左から満たす塗り**。枠と塗りは同じ警告色で、
「枠が満ちきったら実行される」ことがそのまま進捗になる。塗っている間はラベルを
`textOnAccent` に上げる(塗りの上と地の上を文字が跨ぐため)。

長押しを使ってよい条件:

- **幅は普段の文言を基準に固定**し、状態が変わってもツールバーの並びを動かさない —
  狙っていたボタンが押す瞬間に別の位置へ移るのは事故のもと。
  文言は**その箱に収まる短さ**にする(`Push -f`)。字を縮めたりアイコンを外したりして
  長い語を押し込まない — 長押しであることと失うものは hover のツールチップに書けば足りる
- **通常操作と同じボタンに同居させない**。同じ状態でクリックとも長押しとも解釈される
  ボタンを作らない(押しっぱなしで別の操作に化けるのは事故)。
  長押しボタンは**クリックを一切報告しない** — 途中で手放した時も、押し切った時も、
  そのボタンの「通常の操作」へ落ちてはならない
- **失うものをその場に出す**。何が起きるか言えない場面では長押しに降ろさず確認ダイアログへ戻す
- **キーボード・メニュー経由の代替を残す**。押し続けられない人の唯一の導線にしない

## QML 実装ルール

- 全ての値は `Theme`(QML singleton)経由で参照する。QML に数値・色・フォント名のリテラルを直書きしない
- ペインの先頭は `headerHeight` の帯(ヘッダ・フィルタ入力)とし、内容はその**直下**から始める。
  ヘッダを持たないグラフは `headerHeight − graphRowHeight` の上余白を置き、最上部で 1 行目の
  **下端**を隣接ペインの帯の下端に揃える。最上行の hover / 選択ハイライトとヒット領域は
  この上余白ごと塗り広げる(帯と同厚の一続きのハイライトにし、上に地の隙間を残さない)
- 例外は**枠付きカードで始まるペイン内容**(コミットメッセージ枠 = COMMIT 詳細 / WIP 編集):
  カード自身が枠を持つため帯に接すると 2 本の境界線が癒着して見える。上下は帯との間に
  `spaceXs` を置く — **カード内の行間と同じ値**にして、帯 → 各枠 → 帯を一定の刻みで並べる
  (上下だけ `spaceSm` にすると内側 4px / 外側 8px でリズムが崩れる)。左右は `spaceSm` =
  ペインの内寸で、カードの縁が帯のラベルの開始位置に揃う。一覧・グラフのように枠を持たない
  内容は上記どおり直下から始める
- グラフの末尾には `spaceSm` の下余白を置く。最下行がペイン下端に接すると「読み込みの終わり」
  ではなく「見切れ」に見えるため、レーンが縁に届く前に途切れるようにする。**空行に見える量は
  取らない** — 途切れが分かる最小限に留める
- サイドバーの各セクションの末尾は `borderWidth` の地の隙間で閉じる。次のセクション見出しの
  帯と最終行を分けるだけの役目なので、境界線と同じ太さで足りる。`spaceXs` 以上を取ると
  セクションに属する空行に見え、セクションが 5 つ縦に並ぶ分だけ隙間が目立つ
- `font.pointSize` 禁止 → `font.pixelSize`。pointSize は OS ごとの logicalDpi 基準差で実寸がずれる
- `font.family`(単一文字列)禁止 → `font.families`(配列)。単一文字列は CSS 的なフォールバックをしない
- 行高は `lineHeightMode: Text.FixedHeight` + `lineHeight` トークンで固定する
- `ListView` / `TableView` の delegate 高さは行高トークンの定数(一覧 = `Theme.rowHeight`、コミットグラフ = `Theme.graphRowHeight`)。可変高にしない(10 万行での性能予算に直撃する)
- スクロールは端で**ハードに止める**(`boundsBehavior: Flickable.StopAtBounds`)。行き過ぎてから戻るラバーバンドは指で慣性を投げるタッチ操作向けの「端に着いた」合図であり、1 ノッチ単位で動くホイール主体のデスクトップでは「まだ先がある」の誤読を生むだけ。`ListView` / `Flickable` は直接指定し、内部の Flickable を隠す `ScrollView` は `Component.onCompleted` で設定する
- `Qt.lighter()` / `Qt.darker()` / `Qt.rgba()` で中間色を作らない。ホバー・押下は `bgHover` / `bgPressed` の重ね色で表現する
- アニメーション時間は 120ms(短)と 200ms(標準)の 2 値のみ
- ドロップシャドウ・ブラーを使わない。階層は背景色と境界線で表す(描画コスト回避を兼ねる)

## メニュー(右クリック・アプリメニュー)

**メニューはダイアログと同じ「浮いた面」として描く** — `bgElevated` の地に
`borderDefault` の枠、角は `radiusMd`。地だけで浮かせない: ペイン(`bgSurface`)と
`bgElevated` の差は小さく、グラフの上に開いたメニューは枠が無いと縁が読めない。

**置くのは、そこにしか入口が無いものだけ。** 所作(ダブルクリック・2 回目の
クリック)で届くものも、画面に常設のボタンがあるものも重ねない — メニューは
開くまで中身が見えない導線なので、行が増えるほど**そこにしか無い 1 行**が
探しにくくなる。行を選べば右のペインがその行の全てを出す(ハッシュの
`Copy full hash`・stash の `Apply` / `Pop`)ので、**右クリックはそこに無いもの
= 削除に取っておく**。

- 行の文字は `fontMd`(グラフのコミット subject・メッセージ本文と同じ段)、
  行高は一覧と同じ `rowHeight`。メニューだけ大きく見せない
- **幅は最も広い行に合わせる**。上限はウィンドウ幅 − `spaceXxl` × 2 で、
  そこへ届いた行だけ末尾を省略し、hover でツールチップに全文を出す
- **文言は幅と無関係に §用語 の基準だけで選ぶ** — 収まらないから削るのも、
  収まるから伸ばすのもしない。行が自分で示しているもの(右クリックした行の
  コミット)は文言で言い直さない
- 無効行は文字色を `textMuted` に落とす(§無効。自前 `contentItem` は palette を通らない)
- カードの内側余白は `spaceXs` — 角の丸みが選択行の帯に食い込まない最小値
- 区切りは `borderSubtle` の 1px 線、上下に `spaceXs`

## 可否・警告の出し場所

**ポップアップでなければ成立しない UI でない限り、可否の警告・確認は操作している場所の近くに出す。**
ウィンドウを覆うダイアログは、判断の材料そのもの(編集中のテキスト・対象の行)を隠し、
視線を操作から引き剥がす。「近く」とは**その操作の対象が見えている枠の中**を指す。

- **表示の切り替えで足りるならダイアログを出さない**。編集中のテキストについての質問なら
  編集枠の中で聞く(保存行を質問に差し替える — `DetailsPane.asking`)。理由を伝えるだけで
  足りるものは、その場の 1 行(警告色)か hover のツールチップで済ませる

### 立っている質問は 1 か所で聞く(質問バー)

**立っている質問は、対象の行が並ぶ一覧の上端から降りてくるバーで聞く。** 見出し(`fontMd` の
DemiBold・状態色)+ 失うものの 1 行(`fontSm` の `textSecondary`)+ 同意のピル
(状態色の枠)+ `✕`。地は `bgElevated`、下端に状態色の 1px 線。開閉は 200ms。

- **一覧はバーの分だけ下へずらす**(覆わない)。判断の材料は対象の行そのものなので、
  質問がそれを隠しては意味が無い
- **バーが立つ一覧は 2 つ**: グラフ(ref・コミットについての質問)と、WIP ペインの
  ファイル一覧(ファイルについての質問。編集枠と一覧の間に立つ)。見た目も所作も
  同じ 1 つの実装で、**立つのは同時に 1 つだけ**
- **対象の行には印を付ける**(行の左端に `laneStroke` の縦線 + `bgHover` の地)。
  **言葉はバーに 1 度だけ**書き、行は「どの行の話か」だけ答える
- 同意はピルのクリックだけ。**Escape・`✕`・他の場所のクリックで取り下げ**、
  答えるまで何も起きない
- **見に行くクリックだけは取り下げない**: WIP のファイル行をクリックすると中央が
  その diff になる = **何を捨てるのかを確かめる経路**なので、質問は立ったまま待つ。
  行がバケツを移る操作(ステージ切替・Stage all)と一覧から離れる操作は取り下げる
- **同じ問いは常にここで聞く。** 以前はグラフ行のチップ列を質問ストリップに
  差し替えていたが、チップ列は `labelColW` しか無く、短くした文言でも切れて読めない。
  出し先が場面ごとに変わると「出た時に何を意味するのか」も読めなくなる
- 行がウィンドウ外でも成立する(印が付かないだけ)ので、**ダイアログの代役は要らない**。
  `Main.qml` の `root.confirm()` が残るのは、押し続けられない人向けの
  force push メニュー経路だけ
- 質問を出している間は、**まだ何も起きていないことを画面でも示す**(選択・ハイライトを動かさない)。
  答えて初めて動く
- ポップアップを使ってよいのは、**答えるまで先へ進ませてはならない**ものと、
  ウィンドウ横断で置き場所が無いもの(identity の入力・設定・タブを跨ぐ確認)だけ。
  取り返しがつかない操作でも、**その場で意思を示せる形(長押し)があるならそちらを採る**
  — force push はボタンの長押しで取る(§相手の履歴を置き換える)
- 出し場所を変えても**文言は同じ基準**で選ぶ(下記の用語表)

### git が言ったことを読む場所(コマンドログ)

**発行した生 git コマンドは下部パネルに出す。既定は非表示、ツールバーの `>_` で開く。**
別ウィンドウにしない — ログの値打ちは「今押したものが何を走らせたか」の対応にあり、
別ウィンドウはそれを壊す。ログはタブごとなので、入口もタブごとの状態が並ぶ
ツールバー右側に置く(ウィンドウの持ち物である下端の縁ではない)。

- **失敗すると自分で開き、閉じるまで開いたままにする**。次の成功で閉じない —
  読む前に消える。開くのは**利用者が頼んだ操作**の失敗だけで、ポーリングと
  auto fetch の失敗では開かない(オフラインのマシンで毎分飛び出す)
- **その失敗を質問に化けさせた時は開かない**(`branch -d` の拒否 → `Delete <branch>
  anyway?`)。バーが既に何が起きたかを言っているので、ログは同じ話を二度し、
  そのうえグラフを押し上げる。行は記録されているので、読みたければ `>_` で開く
- `>_` は直近の状態も兼ねる: 通常 `textMuted` / 実行中 `accent` /
  直近が失敗 `danger` + 枠 / 開いている間 `bgSelected`
- **exit 0 は書かない**。常に 0 なら情報量が無く、失敗だけが目立つべき
- git の出力は**加工せず**そのまま出す。失敗行の下に展開し、行の左端に警告色の帯を引く
- 入力欄(任意コマンドを打てる端末)は作らない — スコープ外(要望.md)

## 用語(UI 文言)

**内部で実行する git コマンドと、UI に出す語は意図的に分ける。**
内部は最新 git の適切なコマンドを選ぶ(`switch` / `restore` 等)。
UI 文言はコマンド名に引きずられず、その操作が**何をするか**を最も適切に表す語を選ぶ。

理由: 「単なる git ラッパー」は*挙動*の話であって、*語彙*まで git に合わせる意味はない。
`checkout` はレジ・ホテルの連想が先に立ち、git 内部でも「ブランチ移動」と
「ファイル復元」の二役を持つ多義語。git 自身が 2.23 で `switch` / `restore` に
分割したのは、まさにこの多義性を解消するため。

### 長さ

**画面に出す文は、数語拾えば伝わる長さで書く。** 読ませる前提の説明文を UI に置かない
— 操作の途中で段落を読む人はいないので、長い文は「読まれない」ではなく
**「そこに何か書いてある」だけの模様**になり、本当に効く 1 行の効き目まで削る。

- 質問・警告は **見出し 1 行 + 失うもの 1 行**。因果や手順の説明を足さない
  (例: `Move main here?` / `Commits only main has stop being reachable.`)
- 2 文目を書きたくなったら、それは 1 文目が本質を言えていない合図
- 詳しい事情は git の出力(コマンドログ)に出ているので、UI 文言で代弁しない

### hover のツールチップ

**結論を先頭に、1 行で書く。** ツールチップは読ませる場所ではなく、
一目で受け取らせる場所 — マウスを止めている間しか出ておらず、
読み下している間は操作が止まる。

- **1 文・1 行**(表示幅で折り返さない長さ)。2 文に割れたら 1 文目を捨てる
- **結論から**書く。押せない理由なら「なぜ押せないか」ではなく
  **何が足りないか**(`Nothing to push — origin/main is up to date`)、
  操作なら**何が起きるか**(`Hold to overwrite origin/main, …`)
- **状況説明・因果の説明を書かない**。「〜なので〜できない」の前半は落とす
- ラベルの言い換えで終わらせない。ラベルに入らなかった 1 点
  (対象の広さ・失うもの・時点)だけを足す
- 数を出す時は時点を添える(§リモートへ送る)が、**括弧で短く**

### ブランチ・コミットへの移動

| 場面 | UI 文言 | 内部コマンド |
|---|---|---|
| ローカルブランチへ移動 | **Switch to `<branch>`** | `git switch` |
| リモートブランチから作って移動 | **Switch to `<branch>`**(新規ローカル作成は暗黙) | `git switch -c --track` |
| 任意コミット / タグへ移動 | **Switch to Commit**(+ detached バッジ) | `git switch --detach` |
| ローカルブランチをここへ動かして移動 | **Move `<branch>` here**(確認あり) | `git switch -C` |
| コミットにブランチを作って移動 | **Create branch here?**(入力欄のプレースホルダ) | `git switch -c <name> <oid>` |
| 現在ブランチの表示 | **On `<branch>`** | — |

他プロダクトの用例(2026-08 時点):
GitHub Desktop = "Switch branch" / VS Code = "Checkout to..." /
GitKraken・Fork・SourceTree・Sublime Merge = "Checkout" /
Tower = "Checkout" と "Switch To" の併用。

「Checkout」が多数派だが、それは各製品が古くから使ってきた語の継承であって
分かりやすさで選ばれた語ではない。本プロダクトは **Switch** を採る。

### グラフ行のダブルクリック

**行き先は「その行のチップに出ている名前」**。チップの先頭レコード
(HEAD → ローカル → リモート → タグ → 名前順で並ぶ)がそのまま行き先になるので、
画面に出ている文字と着地点が食い違わない。行に複数の ref があっても、
規則を覚える必要がない — 見えているものが行き先。

| 行が持つもの | ダブルクリック | 内部 |
|---|---|---|
| 現在のブランチ | 何もしない | — |
| ローカルブランチ | そこへ移動 | `switch <name>` |
| リモートのみ・同名ローカル無し | 尋ねずに移動(ローカル作成は暗黙) | `switch -c --track` |
| リモートのみ・同名ローカルが別の行 | **Move `<branch>` here?** を尋ねてから移動 | `switch -C` |
| タグのみ / ref 無し | チップ列がブランチ名の入力欄になる | `switch -c <name> <oid>` |
| WIP 行 / stash 行 | 何もしない | — |

**タグでは detach しない。** タグは動かない目印なので移動すれば必ず detached HEAD
になる。それは「続きが書けない」状態で、黙って作ると次のコミットが宙に浮く —
取り返しはつくが、取り返し方を知らない人が最も踏む罠。§用語 のとおり detach は
**明示的な選択**(コミットメニューの Switch to Commit)に留め、ダブルクリックには
その行でいちばん要るもの、つまり**ブランチを作る**を割り当てる。
GitKraken も同じ判断で、タグのダブルクリックは checkout ではなくジャンプ、
checkout は右クリックの「Checkout this commit」/「Create branch here」に置いている。

`Move <branch> here` だけ確認を出す。**ローカルにしか無いコミットが指されなくなる**
唯一の経路だから(reflog には残るが、この画面からは辿れない)。他は switch で戻せる。
確認は質問バーで出し、行き先の行に印が付く(§可否・警告の出し場所)。
**捨てるものが無い(fast-forward に過ぎない)場合も同じように尋ねる** — 出す出さないが
状況で変わる確認は、出た時に何を意味するのかが読めなくなる。

**チップは 1 行に 1 つ、ブランチを出す。** 名前を出すのは先頭 1 件で、順は
HEAD → ローカル → リモート → タグ。同じコミットがブランチの先端でもあり
リリースタグでもある時、チップに出るのは**ブランチ**で、タグは `+N` に入る。
チップ列は「この行はどこへ行けるか」を答える場所であり、行けるのはブランチだけ
だから — タグはそこに並べる相手ではなく、カードで読ませる。**ブランチとタグで
列を分けない**(分ければどちらの名前も半分の幅しか持てず、両方が読めなくなる)。

**ブランチと、その雲バッジが指しているリモートは 1 つのチップに畳む。** `main` の
隣で `origin/main` を数えるのは、バッジが 1 回言ったことを 2 回言うだけ。畳む相手は
「そのブランチのリモート」1 つ — 設定された upstream、無ければ**同名のリモートが
1 つだけの時**のそれ。**一致しなければ畳まない**(upstream が `origin/main` なら
`fork/main` は残る。upstream が無く同名候補が 2 つ以上ある時はどれも残す —
バッジがどれを指しているか決まらないものを黙って消さない)。
**畳めるのは両者が同じコミットに居る時だけ**なので、ズレていればリモートは元どおり
別の行にチップを持ち、分岐が隠れることはない。畳まれたリモートはサイドバーの
REMOTES で数えられる。結果として `+N` は実質**タグの件数**になる。

**重なったチップは hover で展開する。** 集約チップ(`main +2`)は先頭 1 件しか
名前を出せないので、hover で下にカードを開き、1 行 1 ref にしてクリックで
選べるようにする。**タグだけの行も同じ** — 行き先にならないことと、名前が
読めないことは別の話。並びはチップと同じ順(ブランチが先・タグが後ろ)。
**待ち時間は置かない** — 展開するのは重なったチップだけで、
それ以外の行はいくら通り過ぎても何も起きないので、誤爆する余地が無い。
代わりに**ポインタが離れたら閉じる**(チップとカードのどちらにも乗っていない時)。
カードの意匠は §メニュー と同じ(`bgElevated` の地・`borderDefault` の枠・
`rowHeight` の行)。`textMuted` に落とすのは HEAD マーカーだけ(§無効)。
**現在のブランチとタグは落とさない** — 行けないのは同じでも、それは
「使えない」ではなく「もう立っている」「印である」から(§ref の種別)。
色とバッジは保ったまま、hover の反応とクリックだけ外す。

**リモートに在るかどうかは、ブランチもタグも同じバッジで示す。** 無表示 =
ここにしか無い / 雲(`textSecondary`)= リモートにも在る / 緑の PR アイコン
(`success`)= PR 中(ブランチのみ)。**1 スロットに 1 つだけ**で、二つ並べない。
グラフのチップとサイドバーの行で同じ形・同じ色を使う — 同じ問い(これはここに
しか無いのか)に、置かれた場所で違う答え方をしない。

**タグの在処もブランチと同じ 2 軸で読ませる** — 枠は `refTag` のまま、名前の色が
在処、雲バッジがリモートの有無。タグにはリモート側の名前空間が無い(fetch した
タグはそのまま `refs/tags/` に入る)ので、`origin/` のような接頭辞では言えない。

| タグの状態 | 名前 | バッジ | 出る行 |
|---|---|---|---|
| ローカルのみ | `textPrimary` | 無表示 | そのコミットの行 |
| 両方に在り、同じコミット | `textPrimary` | 雲 | その行(チップは 1 つ) |
| リモートのみ | `textSecondary` | 雲 | そのコミットがローカルに在る行。無ければサイドバーの TAGS だけ |
| ズレ(同名で別のコミット) | ローカル側 `textPrimary` / リモート側 `textSecondary` | 雲 | **2 つの行に同じ名前で出る** |

**ズレは「同じ名前が 2 行に見える」ことで示し、専用のバッジも警告色も足さない** —
状態バッジは 3 値(無表示 / 雲 / PR)のまま。ズレは fetch では解消しない
(ローカルに同名タグが在れば git は上書きしない)ので、放置されても見え続ける
必要がある。リモート側のコミットがローカルに無ければローカルの行だけが出る。
データ接続は P4(`ls-remote --tags`)、それまで `PG_FAKE_REMOTE_TAGS` は
雲バッジだけをプレビューする。

**入力欄はチップ列の中に出す**(§可否・警告の出し場所: 表示の切り替えで足りるなら
ダイアログを出さない)。プレースホルダが `Create branch here?` で、Enter で作って
移動、Escape と他行のクリックで閉じる。**捨てても失うのは打ち直す数秒だけなので
尋ねない** — 編集中のコミットメッセージ(`DetailsPane.asking`)とは重みが違う。

### グラフ行の右クリック

**行が何であるかでメニューが変わる。** グラフには 3 種の行があり(§グラフ・
インタラクション定数)、コミットに効く操作が他の 2 種に効くわけではない。

| 行 | 出るもの |
|---|---|
| コミット | Copy this commit onto the current branch / Switch to this commit / Fold into the commit before it / **Move `<branch>` here ▸**(§ブランチを過去のコミットへ戻す) |
| stash | **Delete…** だけ |
| WIP(未コミット) | 出さない(コミットではない) |

**stash 行に出すのは削除だけ。** stash はどのブランチの履歴でもないので、
コミット行の操作はどれも当たらない(cherry-pick も、そこへブランチを動かすことも)。
戻す操作(`Apply` / `Pop`)は**右クリックがその行を選ぶ**ことで右のペインに出るので、
メニューには重ねない(§メニュー)。確認と文言は左メニューの `Delete…` と同じ —
同じ問いを、置かれた場所で違う聞き方にしない。

### 左メニューの所作

**行き先はダブルクリック、名前は「間を空けた 2 回目のクリック」。** グラフ行と同じ
規則を左メニューにも通す — 同じ問い(この行はどこへ行くのか)に、置かれた場所で違う
答え方をしない。

| セクション | 単クリック | ダブルクリック | 間を空けた 2 回目 | 右クリック |
|---|---|---|---|---|
| BRANCHES(他のローカル) | その ref のコミットへジャンプ | **Switch to `<branch>`** | **改名** | Switch / Delete… |
| BRANCHES(現在のブランチ) | ジャンプ | 何もしない(既にそこ) | **改名** | 同上(Switch と Delete… は無効) |
| フォルダ行 | 開閉 | 何もしない | 無し | 無し |
| REMOTES | ジャンプ | **Switch**(同名ローカル無し = 作って移動 / 有り = `Move <branch> here?`) | 無し(リモートに改名は無い) | Switch |
| WORKTREES | 行を取るだけ | **別タブで開く** | 無し | 無し |
| STASHES | 中身を詳細ペインに出す | 何もしない | **改名** | Delete… |
| TAGS | ジャンプ | **`Create branch here?` の入力欄**(detach しない) | **改名** | Delete… |

**所作で届くものを右クリックに重ねない。** 改名もタグからのブランチ作成も行の上で
1 クリックの距離にあるので、メニューには置かない — メニューの行数は、**そこにしか
入口が無いもの**(削除)のために取っておく(§メニュー)。ハッシュのコピーも同じ
理由で置かない: 行をクリックすれば右のペインがそのコミットを出し、`Copy full hash`
がそこにある。

- **2 回目のクリックも普通のクリックとして働く**(行き先へもう一度飛ぶ)。改名の入力欄が
  出るのはその上に重ねてで、意図せず開いても Escape・他所のクリックで消える
- **判定はダブルクリック間隔だけ**(Explorer と同じ、上限は置かない)。間隔の内側に
  入った 2 回目は「ダブルクリックの片割れ」なので、普通のクリックとしても数えない
- **直前にクリックした行を `bgSelected` で示す**。2 回目の狙いどころが見えないと
  この所作は成立せず、WORKTREES のように飛び先の無い行のクリックが空振りに見える

**入力欄は行の名前の位置に出す**(§可否・警告の出し場所: 表示の切り替えで足りるなら
ダイアログを出さない)。フルネームを入れて全選択で開き、Enter で確定、Escape と
他所のクリックで取り消す。**尋ねない** — 捨てても失うのは打ち直す数秒。

- **編集するのはフルネーム**(`feature/login`)。末尾だけを出すと、打ち直した名前が
  黙ってフォルダの外へ出る
- **確定できない名前は Enter が効かない**。枠が警告色に変わり、理由は入力欄の
  ツールチップに 1 行(§長さ)。**規則は git のもの**(`check-ref-format`)を写すだけで、
  独自の禁止を足さない — 端末で作れた名前を GUI が拒むのは嘘になる。stash の名前は
  ref ではなく reflog の 1 行なので、規則は「1 行・空でない」だけ
- 同名のまま確定したら何もせずに閉じる。既存の名前と衝突したら git がそのまま拒む
  (force は使わない — 黙って上書きすると相手のブランチ・タグが消える)

**git に無い改名は作り直しで通す。** タグは `git tag <new> <old>` → `git tag -d <old>`
(同じオブジェクトを指すので注釈・署名・tagger はそのまま)、stash は書き直した
コミットを `git stash store` → 古い方を drop(**一覧の先頭へ移動する** — 一覧は
reflog で、reflog は先頭にしか伸びない)。どちらも確認は出さない: 指す先は失われず、
消えるのは古い名前だけ。

**削除は「git が拒むかどうか」で分ける。**

| 対象 | 実行 | 確認 |
|---|---|---|
| ローカルブランチ | `git branch -d` | **尋ねずに実行**。git が拒んだら(そのブランチにしか無いコミットがある)**その時に** `Delete <branch> anyway?` を質問バーで聞き、答えれば `-D` |
| タグ | `git tag -d` | **先に聞く**(`What only this tag reaches stops being reachable.`)— git は何も拒まない |
| stash | `git stash drop` | **先に聞く**(`What it holds is kept nowhere else.`)— 同上 |

この表は**左メニューだけの決まりではない**。同じ `Delete…` はグラフの stash 行の
右クリックにも出る(§グラフ行の右クリック)ので、実行も確認も文言もここが正本。

ブランチだけ順序が違うのは、**git 自身が「取り返しがつくか」を知っている**から
(マージ済みなら名前が消えるだけ)。毎回聞くと、日常の後始末が全部確認付きになり、
本当に危ない `-D` の確認まで読まれなくなる。**現在のブランチの削除は出さない**
(git が拒むだけの操作をメニューに残さない)。

### 未コミット変更がある状態での移動

**なるべく持っていく。尋ねるのは git が運べないと言った時だけ。**
移動はまず `git switch` をそのまま実行する — 邪魔にならない変更は git が
運び、邪魔になる場合は**何も変えずに拒否**する。日常の移動で毎回ダイアログを
出さないための順序であり、拒否の時点でリポジトリは無傷なので、後から尋ねて
選ばせられる。

拒否された時だけ次を出す:

| 選択肢 | UI 文言 | 挙動 |
|---|---|---|
| 置いていく(既定) | **Leave my changes on `<current>`** | `stash push -u` → switch |
| 持っていく | **Bring my changes to `<target>`** | `stash push -u` → switch → `stash pop --index` |

どちらも stash を経由し、**移動先で戻すかどうか**だけが違う。
「置いていく」を既定にする(強調表示・先頭)。

`switch --merge` は使わない。stash 経由が二つの点で勝るため:

- **staged / unstaged の区別が残る**(`--index`)。`switch --merge` は index に
  何か staged があると衝突ファイルでなくても拒否するので、事前に index を
  空にするしかない
- **conflict した時に stash が残る** = 戻る手段がある。`switch --merge` の
  conflict は成功(exit 0)として着地し、マーカーを残したまま abort する merge も
  無い

conflict 時は stash が残るので、ボタンの説明文で「STASHES にも残る」と述べる
(ユーザーには stash が増えて見えるため。安全網だと分かる言い方にする)。
staged 側が衝突して `pop --index` が丸ごと拒否された場合のみ `--index` 無しで
やり直す — この時だけ区別が失われる。

未追跡ファイルが移動先の追跡ファイルと衝突している場合はどの方法でも運べない
(git は記録していないファイルを上書きせず、stash からも戻せない)。この場合は
「持っていく」を出さない。

### ブランチを過去のコミットへ戻す

コミット行の右クリックメニューにサブメニューとして出す。

| 場面 | UI 文言 | 内部コマンド |
|---|---|---|
| 現在ブランチを移動(サブメニュー) | **Move `<branch>` here** | `git reset` |
| 変更を staged のまま残す | **Keep everything, staged** | `--soft` |
| 変更を unstaged にして残す | **Keep everything, unstaged** | `--mixed` |
| 変更を捨てる | **Discard everything after it** | `--hard` |

`reset` は git 内部でも「ブランチ移動」と「index からの取り消し」の二役を持ち、
後者は本書で既に **Unstage** と呼んでいる。移動側は*何が動くか*(ブランチ)を
主語にした **Move** を採る。モード名(soft / mixed / hard)は出さず、
**残るのか捨てるのか**で言い分ける。

「to this commit」ではなく「here」なのは、指しているコミットがメニューを開いた
その行だから — 行が自分で示しているものを文言で言い直さない。メニューは行に幅を
合わせるので(§メニュー)、短さのために語を削る必要は無い。

出す条件(いずれかを欠いたら無効化):

- ブランチ上にいる(detached HEAD には動かすブランチが無い)
- 進行中の操作が無い — `--soft` は merge 中に拒否され、`--mixed` / `--hard` は
  黙って `MERGE_HEAD` を捨てて merge を中断する。抜け道は Continue / Abort
- 対象が stash 行でない(stash はどのブランチの履歴でもない)
- 対象が現在ブランチの先端でない(移動にならない)

確認は **`--hard` だけ** — 質問バーで聞き、メニューを開いた行に印が付く
(§可否・警告の出し場所)。soft / mixed はファイルの中身を 1 バイトも
捨てない(ブランチが動くだけで、コミットし直せば元に戻る)。`--hard` は未追跡
ファイルには触れないので、その 1 行でそう述べる。

### 変更を退避する(stash)

| 場面 | UI 文言 | 内部コマンド |
|---|---|---|
| 作業ツリー全体を退避 | **Stash…**(WIP ペインに開くオプションカード) | `git stash push` |
| 1 ファイルだけ退避(ファイル行の右クリック) | **Stash this file** | `git stash push -- <path>` |
| 未追跡も含める | **Include files git is not tracking yet** | `--include-untracked` |
| index はそのまま残す | **Leave the staged changes staged** | `--keep-index` |
| index の分だけ退避 | **Only the staged changes** | `--staged` |
| 退避したものを戻す | **Apply**(残す) / **Pop**(消す) | `stash apply` / `stash pop` |
| 退避したものを捨てる(行の右クリック) | **Delete…** | `git stash drop` |

**Stash** は git 用語のまま採る。「退避」に当たる短い英語(Shelve / Park)は
どれも他ツールの独自語で、STASHES セクション・stash 行・switch 時の説明文が
既に同じ語を使っている以上、ここだけ言い換えると同じものが二つの名前を持つ。

「未追跡も含める」は**既定でオン** — 新しいファイルだけ置き去りにされるのが
stash で最も驚かれる挙動で、switch 時の自動 stash も `-u` で揃えている。

**「Only the staged changes」は、同じファイルが index と作業ツリーの両方で
変更されている間は無効化**して理由を添える(git は stash エントリを作った上で
作業ツリーの除去に失敗し、エントリだけ増やして終わる — 実測)。
「未追跡も含める」との併用も git が拒否するので同時に無効化する。

退避には確認を出さない。stash は何も捨てず、退避したものは STASHES に見える。
**捨てる時だけ先に聞く** — 中身は他のどこにも残らないので(§左メニューの所作 の削除表)。
`Delete…` は**左メニューの stash 行とグラフの stash 行のどちらからも**同じ言葉で
出る。`Apply` / `Pop` を右クリックに重ねないのは、行を選べば右のペインに出るため
(§メニュー)。

### リモートへ送る(push)

**押す前に、送れるかどうかを出す。** ahead / behind は最後の fetch 時点の比較なので
**「送れない」方向にしか信用できない** — 0 でも拒否されうるが、behind > 0 なら
通常 push はまず通らない。ツールバーのボタンは次の状態で見た目を変える。

| 状態 | 条件 | UI 文言 | 押せるか |
|---|---|---|---|
| 初回 | upstream 無し、または追跡 ref がまだ無い | **Publish** | ○ |
| 送れる | ahead > 0 かつ behind = 0 | **Push** | ○ |
| 送るものが無い | ahead = 0 かつ behind = 0 | **Push** | ×(理由はツールチップ) |
| 遅れているだけ | ahead = 0 かつ behind > 0 | **Push** | ×(送る中身が無い) |
| 分かれた | ahead > 0 かつ behind > 0 | **Push -f**(警告色・警告色の枠) | 長押しのみ |
| 対象なし | detached / ブランチ無し / リモート無し | **Push** | × |

**ボタンに数は出さない。** 何コミット先行しているかはサイドバーの `↑N ↓M` と
このボタンのツールチップにあり、ラベルに入れると桁数のぶんだけ幅が変わって
ツールバーの並びが動く。**全状態が同じ幅**(最長の文言 `Push -f` に揃える)。

数を出す時は**いつ時点のものかを述べる**(`(as of the last fetch)`)。
古い数字を確定情報として読ませない。文にせず括弧で足す(§hover のツールチップ)。

### 相手の履歴を置き換える(force push)

**確認はダイアログではなく長押しで取る**(§進行中・長押しの定数)。分かれた状態でのみ
ボタンが長押しを受け付け、クリックでは何も起きない — 同じ状態で通常 push は成立しないので、
1 つのボタンが 2 つの意味を持つことはない。ラベルは **Push -f**、文字も枠も警告色で、
「押し続けると `<upstream>` を上書きする」ことと失うコミット数はツールチップで述べる。
`-f` は git 自身の印で、**普段の文言の箱に収まる**唯一の長さ。用語表の原則
(コマンド名に引きずられない)より、ツールバーの並びを動かさないことを優先した例外。

ダイアログを外せる理由は「危険が減ったから」ではなく、**lease が効いているから**。
force は常に `--force-with-lease=<branch>:<画面に出ていた oid>` で撃つので、
**見ていない状態は原理的に壊せない**(相手が動いていれば git が `stale info` で拒む)。
ダイアログに残っていた仕事は「何を失うか告げる」ことだけで、それは behind の数
= 相手が失うコミット数として出せる。

右クリックの **Force push…**(確認ダイアログ経由)は残す。長押しは押し続けられる人の
近道であって、唯一の導線にはしない。

### その他の操作

| 場面 | UI 文言 | 内部コマンド |
|---|---|---|
| 変更を index へ | **Stage** | `git add` |
| index から戻す | **Unstage** | `git restore --staged` |
| 変更を捨てる(ファイル行の右クリック) | **Discard changes…** → 質問 **Discard changes?** / 同意 **Hold to discard** | `git restore --worktree` |
| 未追跡ファイルを消す(同じ 1 行・同じ文言) | 同上 | `git clean -f -d` |
| amend で著者を引き継ぐ | **Make me the author** | `commit --amend --reset-author` |
| 進行中操作の継続 | **Continue** / **Abort** / **Skip** | `--continue` / `--abort` / `--skip` |

**捨てる行は 1 つで、中身だけ分ける。** unstaged の行にも未追跡の行にも同じ
`Discard changes…` を出す — 読み手の意図はどちらも「このファイルに起きたことを
無かったことにする」で、未追跡ファイルは**その存在自体が変更**なので、消えるのが
正しい取り消しになる。**質問も同じ文言**(`Discard changes?` / 同意は
`Hold to discard`)で、行の種別で変えるのは**失うものの 1 行だけ**
(`Kept nowhere else.` / `The file goes — git never recorded it.`)。
行が示しているファイル名は言い直さない。末尾の `…` は `Delete…` と同じ意味 —
**先に質問が出る**ことを言う。

**同意は長押しで取る**(§相手の履歴を置き換える と同じ理由 — 取り返しがつかず、
その場で意思を示せる)。ピルは `holdMs` 押し続けている間だけ枠が左から塗り潰され、
途中で離せば何も起きない。**押し続けられない人向けの代替導線は未定**
([P2-確認事項.md](P2-確認事項.md) §E)。

**捨てられるのは index の外だけ。** staged の行に出さないのは Unstage が行の上で
1 クリックだからで、conflict 中の path は git が restore を拒む。
**追跡済みファイルをディスクから消す導線は持たない**(他ツールはこれを
「delete file」として出す)— それは取り消しではなく新しい変更で、消したいなら
消してからステージすればよく、`git rm` は取り消せる操作の側にいない。

**Make me the author** は、HEAD の author が現在の identity と違う時だけ
amend パネルに出す。git は committer だけを書き換えて author を残すので、
他人のコミット(や別 identity で書いた自分のコミット)を amend した時にしか
選ぶ意味が無い。付けると author date も now になる。
