## 配線する時に効く決定

### A. 破壊的操作の確認ダイアログ方針(**決定済み**)

core 側は確認を一切しない(`discard` / `clean` / `stash drop` / `branch -D` /
リモートブランチ削除はそのまま実行する)ので、方針は UI 側にある。

**方針: 取り返しがつかないものだけ確認する。** 日常操作(stage / commit / switch /
fetch / 通常 push)は一切尋ねない — 毎回出る確認は「読まずに押すもの」になり、
本当に危ない場面での効き目まで削る。

確認を出す操作:

| 操作 | 失うもの | 状況 |
|---|---|---|
| discard(unstaged 破棄) | 作業内容 | 配線済(ファイル行の `Discard changes…`) |
| clean(untracked 削除) | ファイルそのもの | 配線済(同じ 1 行。未追跡の行で開いた時) |
| discard(staged も含めて HEAD へ) | staged と作業ツリーの両方 | 配線済(同じ 1 行。staged の行で開いた時) |
| stash drop | stash 1 件 | 配線済(左メニュー / グラフの stash 行、どちらも `Delete…`) |
| branch -D(未マージ) | ブランチの指す先 | 配線済(`-d` が拒まれた時だけ聞く) |
| tag -d | タグにしか届かないコミット | 配線済(左メニューの `Delete…`) |
| リモートブランチ削除 | リモートの ref | UI 未配線 |

確認は**対象が見えている場所で聞く**のが基本(グラフ / WIP のファイル一覧 = その一覧の
上に立つ質問バー + 行の印、編集テキスト = 保存行の差し替え)。文言は操作側が渡す(何を失うかは操作ごとに
違うため)。`Main.qml` の `root.confirm(heading, detail, acceptText, action)` は
force push のメニュー経路専用で、新しい確認の置き場所ではない。

### B. 未マージブランチ削除の導線(**決定済み**)

削除は常に `-d` で試し、**失敗したら「未マージです。強制削除しますか」を出す**。
事前判定(`branch::is_merged_into`)はメニュー文言を変えたい場合の予備として残す。

## 未決定(要判断)

### C. 複数選択の一括操作

パスはブリッジを 1 件ずつ渡す(git のパスは NUL 以外どの文字も含み得るため、
1 本の文字列に詰める安全な区切り文字が無い)。
複数ファイルをまとめて stage する UI を作る場合、QML から N 回呼ぶ形になる。
セッションが直列化するので競合はしないが、N 回の git 実行になる。
一括が必要なら「選択集合を Rust 側に保持するモデル」を足す判断が要る。

### D. 数値入力欄の幅

設定ダイアログの分数入力に `160`(デザイン規約のレイアウト表にある唯一の
「入力欄の幅」＝検索ボックス)を流用した。分数には広い。
小さい数値入力用のトークンを足すかは要判断。

### E. 長押しの代替導線

質問バーの同意を長押しにした操作(ファイルの discard / clean・リモートブランチの改名)には、
**押し続けられない人向けの代替が無い**。規約 §長押し は「キーボード・メニュー経由の
代替を残す」を条件に挙げており、force push はダイアログ経由の `Force push…` が
それに当たる。候補は (a) バーが立っている間の Enter / Space、(b) メニューに
ダイアログ経由の行を足す、(c) 長押しをやめる。**(a) は入力欄のフォーカスと衝突する**
(コミットメッセージ枠が Enter を取る)ので、そのまま採れない。

## 既知の制限

- **改名した stash は一覧の先頭へ動く（許容・ユーザー判断）**: git に stash の改名は
  無いので、書き直したコミットを `stash store` して古い方を drop する。一覧は reflog
  であり **reflog は先頭にしか伸びない**ので、途中へ書き戻す方法が無い。
  他の stash の順序は変わらない。
- **末尾改行が無いファイルへの行追加を部分ステージできない（許容）**: 最終行に改行が
  無い場合、その後ろへ行を足す変更は「最終行に改行を足す」変更と不可分で、追加行だけを
  選んだ patch は unified diff として表現できない（pre-image と食い違い git が
  `patch does not apply` で拒否する）。**前提となる行を自動で選択に足す回避策は入れない**
  — 選んでいない行を黙って index に入れる方が害が大きい。最終行を**選ばず残すだけ**の
  ケースは、`\ No newline` マーカーが降格した context 行へ引き継がれるので通る。
- **untracked ディレクトリ**: `status -uall` で新規ディレクトリの中身をファイル単位に展開する。
  中の 1 ファイルだけを部分ステージできる代わりに、そのディレクトリの全ファイルを
  discard すると空のディレクトリがディスクに残る（git は空ディレクトリを追跡しないので
  status は clean のまま）。
- **ブリッジへ出さない core 機能**: `--allow-empty` と `hunk_count`。空コミットを発行する
  導線は持たない（Commit は staged が 1 件以上ある時だけ通る。amend を除く）。
  hunk 数は diff 行モデルから UI 側で数えられる。
- **設定の永続化が無い**（P4）: auto fetch の間隔（既定 1 分）は起動ごとに既定へ戻る。
  設定ダイアログにその旨を表示している。
- **ネットワークタイムアウトに UI が無い**: ブリッジの `setNetworkTimeout` は在るが
  QML から呼ぶ経路が無く、実質 `remote::DEFAULT_NETWORK_TIMEOUT`（180 秒）固定。
  設定ダイアログに出すかは永続化（P4）と同時に決める。
- **署名の UI 表示**: `identity::verify_commit()` で署名状態を取れるが、
  コミット詳細への表示は未実装（P5 の diff 強化と同時が自然）。
  `signingActive` / `signingFormat` はブリッジに出してある。
